# 让Agent自我进化：无需重置的持续优化框架

**日期**: 2026-05-13

---

论文 : Continual Harness: Online Adaptation for Self-Improving Foundation Agents链接 : https://arxiv.org/abs/2605.09998现在的 AI Agent 框架（如 Claude Code 或 OpenHands）已经相当成熟，但一旦进入需要长期记忆和复杂状态管理的“具身智能”或长程 RPG 游戏领域，这些框架往往显得捉襟见肘。这篇论文提出的 Continual Harness 解决了一个核心痛点： 如何让 Agent 在不重置环境的情况下，边玩边学，边玩边改自己的“大脑配置”？
### 问题与动机：为什么“重置”是种浪费？
在传统的 Prompt 优化（如 GEPA）或强化学习实验中，为了评估一次改进的效果，通常需要一个完整的 Episode（回合）结束后进行重置（Reset）。这种做法有两个致命缺陷：
- 积累断层：每一次重置都让之前积累的经验归零，Agent 无法利用长周期内的深层失败模式。
- 工程瓶颈：对于某些物理仿真或高成本环境，频繁重置不仅昂贵，甚至不可行。
论文团队通过 Gemini Plays Pokémon (GPP) 项目发现，如果允许人类介入优化 Agent 的“操作台”（Harness，即工具、记忆、规划逻辑的集合），Agent 能完成多个复杂的宝可梦游戏。他们想做的，是把这种“人肉优化”自动化，并且实现 Reset-Free（无重置） 的在线适应。
### 方法拆解：动态编辑“操作系统”
Continual Harness 的核心 Insight 是： 将 Agent 的 Harness（系统提示词、子智能体、技能库、记忆）视为一个可被实时 CRUD（增删改查）编辑的状态对象。
#### 1. 双层循环架构- 内层循环（执行）：Agent 基于当前 Harness HtH_t​ 和环境状态 sts_t​ 采取行动 ata_t​。
- 外层循环（优化）：每隔 FF 步，一个专门的 Refiner（优化器） 会读取最近的轨迹数据 τ\tau，识别失败模式（如死循环、工具调用失败），然后对 Harness 的四个组件进行就地更新：
System Prompt pp：重写指令，针对当前失败调整策略。
- Sub-agents GG：创建新的专用子模块，或删除无效模块。
- Skills KK：将成功的操作序列固化为可复用的技能（如路径规划算法）。
- Memory MM：更新事实知识，遗忘过时信息。
#### 2. 为什么这样设计？
传统方法只优化 Prompt，而 Continual Harness 优化的是 整个 Agent 的架构 。它允许 Agent 在运行中“发明”新的子智能体来处理复杂任务（如宝可梦中的战斗策略），并将这些新发明的代码/逻辑直接注入到运行环境中。这种 In-Context Learning（上下文学习） 与 Code Execution（代码执行） 的结合，使得 Agent 能够自我迭代。
### 关键结果：效果显著，但有门槛论文在 Pokémon Red 和 Emerald 上进行了大量实验，主要对比了极简基线（ HminH_{min} ​ ）和手工专家版 Harness（ HexpertH_{expert} ​ ）。

- 能力依赖：在较小模型（Flash-Lite）上，该方法失效（完成率仅 3-13%），说明该方法需要足够强的基础模型来执行复杂的自我编辑指令。
- 技能进化：在 24 小时运行中，Agent 自我生成的导航技能逐渐逼近 Dijkstra 算法的最优路径，证明了技能库的自我进化能力。
### 工程启示：从“提示词工程”到“架构工程”
- Harness 是动态资产：不要只把 Prompt 当作静态配置。在长周期任务中，Harness 应该包含可执行的代码、动态生成的子模块和长期记忆。
- 在线微调的闭环：论文进一步展示了 Co-Learning（协同学习） 循环：用前沿模型（Teacher）对开源模型（Student，如 Gemma-4）的轨迹进行重标记，并通过 Soft SFT 更新模型权重。关键在于，这个训练过程也是 Reset-Free 的，模型在同一个游戏存档中不断变强。
- 失败驱动优化：Refiner 的核心任务是识别“失败签名”。在实际工程中，构建一个能准确诊断 Agent 失败原因（是迷路？还是战斗策略错误？）的评估机制，比单纯的奖励模型更重要。
### 局限与展望- 能力地板：如果基础模型太弱（如 Flash-Lite），Refiner 无法有效利用 Harness 组件，优化反而会增加开销。
- 收敛性未证：虽然观察到持续的里程碑进步，但尚未证明该方法在理论上会收敛到最优解。
- 教师依赖：当前的协同学习依赖前沿模型作为 Teacher 进行重标记，如何完全去依赖教师模型，实现全自监督的持续进化，仍是开放问题。
总的来说，Continual Harness 为构建“自我进化”的 Agent 提供了一条可行的技术路径： 让 Agent 拥有修改自身“操作系统”的权限，并在运行中持续打补丁。
