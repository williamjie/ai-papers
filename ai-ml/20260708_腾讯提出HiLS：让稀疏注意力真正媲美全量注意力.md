# ⭐⭐½ 腾讯提出HiLS：让稀疏注意力真正媲美全量注意力

**日期**: 2026-07-08

---

论文 : Hierarchical Sparse Attention Done Right: Toward Infinite Context Modeling链接 : https://arxiv.org/abs/2607.02980长上下文建模一直是 LLM 的工程痛点。全量注意力（Full Attention）计算复杂度高且难以外推，而现有的块稀疏注意力（Chunk-wise Sparse Attention）虽然快，但检索精度太差，导致模型“漏看”关键信息。
腾讯混元团队最新发布的 HiLS-Attention （Hierarchical Landmark Sparse Attention）试图打破这个僵局。它的核心主张很直接：通过端到端学习，让稀疏注意力的性能不仅追平，甚至在某些长文本任务上超越全量注意力。
### 为什么现有的稀疏注意力不行？
传统方法通常使用非参数化的摘要（如均值池化 Mean-Pooling）来代表一个 Chunk 的重要性。
核心 Insight ：均值池化在 Logit 分布均匀时有效，但在“大海捞针”场景下，往往只有一个 Token 的 Logit 极高。此时均值会严重稀释信号，导致模型选错 Chunk。
HiLS 指出，现有的稀疏方法无法通过语言建模损失（LM Loss）直接优化 Chunk 的选择过程，导致检索不准。
### HiLS 的核心设计：分层与可微HiLS 的设计非常巧妙，主要解决两个问题：如何高效估算 Chunk 质量？如何让这个过程可学习？
-基于泰勒展开的线性代理：
全量注意力的 Chunk 质量是 LogSumExp 函数。HiLS 证明，可以通过对 Query 和 Chunk 摘要 Key 的点积进行一阶泰勒展开，得到一个线性代理分数。这个分数由两部分组成：相关性项（Query ⋅\cdot Summary Key）和偏置项（熵）。
-Landmark Token 与端到端学习：
每个 Chunk 末尾添加一个特殊的 Landmark Token，其 Query 向量用于生成该 Chunk 的摘要 Key。
关键突破：HiLS 将注意力分解为“Chunk 间”和“Chunk 内”两层 Softmax。Chunk 间的代理分数直接参与前向传播计算权重。这意味着，LM Loss 的梯度可以直接回传到 Landmark Token 的参数中，让模型学会“哪些 Chunk 对预测下一个词更有用”。
-硬件友好的 Kernel 设计：
相邻 Query 往往检索高度重叠的 Chunk。HiLS 将多个相邻 Query 打包（Batching），一次性加载并计算 Union 后的 KV Cache。这不仅提高了 Tensor Core 利用率，还减少了内存访问次数。在 128K 上下文中，解码速度比全量注意力快 15.7x。
### 实验结果：不仅快，而且准论文在 345M 和 7B 参数规模的模型上进行了详尽对比。数据非常有说服力。
1. 长上下文外推能力（RULER Benchmark）
在仅训练 8K 上下文的情况下，HiLS 展现了惊人的外推能力：
模型 8K (In-Domain) 512K Extrapolation 4M Extrapolation Full-Attn (RoPE) 100% 0% - NSA (SOTA Sparse) 49% 0% - HiLS-Attn 100% 95% 89%注：数据来自 Table 2，Single-NIAH 任务。HiLS 在 512K 长度下仍保持 95% 的准确率，而全量注意力直接归零。
2. 推理延迟对比（7B 模型）
在 Olmo3 7B 模型上，转换到 HiLS 后：
- 128K 上下文：解码延迟降低 15.7x。
- 256K 上下文：解码延迟降低 9.3x。
- 性能保持：在 LongBench-v1 等短/中上下文任务上，HiLS 的性能与全量注意力基本持平（Overall Score: 59.4 vs 59.3）。
3. 压缩带来的意外增益在一个变量跟踪（Variable Tracking）任务中，HiLS 比全量注意力提升了高达 50% 的准确率。
反直觉发现 ：全量注意力中，无关 Token 也会获得微小的非零权重，随着上下文变长，这些“噪声”累积会稀释有用信号。HiLS 的压缩机制反而起到了去噪作用，保留了更纯净的语义信号。
### 工程启示与落地建议-低成本迁移：
你不需要从头训练。论文显示，只需对现有全量模型进行轻量级继续预训练（Continual Pretraining），冻结主干参数，仅训练 Landmark Token Embedding 和低秩适配器（<1% 参数量），用 50B Token 即可转换完成。
-位置编码替换：
在使用 HiLS 时，建议将 RoPE 替换为 HoPE（Hybrid Position Encoding）。实验表明，HoPE 能显著提升 HiLS 在长上下文下的 PPL 和外推能力。
-适用场景：
对于需要处理超长文档、代码库或 Agent 历史记录的本地部署场景，HiLS 是目前最具潜力的方案之一。它打破了“稀疏即降智”的魔咒，实现了效率与性能的双赢。
### 局限与展望尽管 HiLS 表现优异，但仍有一些工程细节需注意：
- Landmark Token 开销：虽然参数极少，但引入特殊 Token 需要修改模型结构。论文也提供了一种共享 Learnable Query 的无 Landmark 变体，但外推能力会显著下降。
- GQA 适配：在分组查询注意力（GQA）中，HiLS 需要在 Group 级别聚合 Chunk 分数，这增加了一定的实现复杂度。
总体而言，HiLS-Attention 为无限上下文建模提供了一条可行且高效的路径。对于追求极致长文本处理能力的工程师来说，这是一个值得深入研究的架构方向。
