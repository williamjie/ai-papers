# ⭐⭐½ LoMo：用局部模态替换破解VLM的载体敏感症

**日期**: 2026-05-29

---

论文 : LoMo: Local Modality Substitution for Deeper Vision-Language Fusion链接 : https://arxiv.org/abs/2605.30265现在的 VLM 有个很尴尬的毛病：你把文字问题直接截图扔给它，它的智商就像被砍了一半。这篇论文不仅指出了这个“载体敏感”问题，还给了一个极其轻量、零推理开销的微调数据增强方案——LoMo。
核心洞察是： 现有的训练数据里，文本和图像的角色是割裂的（文本是指令，图像是素材）。模型根本没学会“文字”和“文字的像素渲染版”在语义上是等价的。
### 痛点：为什么 VLM 怕截图？
理想情况下，把一段文本转换成图片，模型的理解能力应该不变。但现实很骨感。论文展示了令人震惊的**载体敏感（Carrier Sensitivity）**现象：
- 将标准文本问题渲染为图像后，主流模型的准确率普遍暴跌。
- LLaVA-OneVision-1.5-8B 在 MMMU 上掉了 9.25%。
- Qwen3.5-9B 在 MathVista 上掉了 10.09%。
更深层的原因在于 跨载体模态间隙 。作者发现，文本与其渲染图像之间的余弦距离越大，准确率下降越严重。这说明模型在内部表示层，根本没把“这段文字”和“这张写着同样文字的图片”对齐。
### 方法拆解：LoMo 的三招LoMo 不需要改模型架构，也不增加推理成本，它纯粹是在 数据层面 做文章。它的核心逻辑是： 局部模态替换 。
具体流程分三步走：
-结构感知跨度定位（Structure-Aware Span Localization）
不是随机切文本，而是基于语义结构。
- 对于长文本，它会识别出中间的三分之一作为目标。
- 关键点：它会把公式和 LaTeX 命令视为原子单元，确保切割边界不会切断数学表达式。
-视觉渲染（Visual Rendering）
把选中的文本片段转换成图片。
- 包含数学公式的走 LaTeX 渲染器，纯文本走标准渲染器。
- 这步操作把原本的 Text 变成了 Image。
-感知失真（Perceptual Distortion）
为了让模型更鲁棒，给渲染后的图片加噪声：旋转、模糊、阴影或波浪形变。
- 模拟真实世界中的拍照、扫描瑕疵。
最终效果： 原本的纯文本提示 A + B + C 变成了交错序列 A [Image of B] C 。模型为了回答正确，必须同时理解前后的文字上下文和中间的图像内容，从而被迫建立跨模态的对齐。
### 关键结果：数据不会撒谎LoMo 在 13个 多模态基准测试上全面碾压标准 SFT（监督微调）。以下是核心数据对比：
模型 评估协议 平均提升 (Avg. Gain) 亮点指标提升 LLaVA-OneVision-1.5-8B 标准评估 +2.67 MM-IFEval: +3.21, CountBench: +8.15 Qwen3.5-9B 标准评估 +2.82 DocVQA: +6.10, MM-IFEval: +5.49⚠️ 最反直觉的发现：
在“渲染评估”（即把问题全变成图片）下，LoMo 的优势被放大了数倍。
- LLaVA-8B 平均提升 +18.86 分。
- Qwen3.5-9B 平均提升 +11.92 分。
这说明 LoMo 不仅提升了常规性能，更彻底治愈了“载体敏感症”，让模型在面对纯视觉指令时依然保持高智商。
内部表征分析：
- 模态集成率 (MIR)：LoMo 比标准 SFT 低 0.122，说明文本和视觉特征的分布间隙更小。
- 成对跨模态距离：标准 SFT 训练后距离反而变大（0.52 -> 0.57），而 LoMo 将其缩小至 0.49。
### 工程启示：怎么用在你的项目里？
- 零成本增强：你不需要修改模型代码，也不需要额外的标注。只需要在现有的 SFT 数据预处理 pipeline 中插入 LoMo 的逻辑即可。
- 最佳实践参数：
重写比例：论文建议 50% 的文本样本进行替换效果最好（100% 反而有收益递减）。
- 位置选择：将图像插入文本的中间部分（Text-Image-Text）效果优于开头或结尾，因为这强制模型进行上下文融合。
- 适用场景：如果你的 Agent 需要处理大量截图、OCR 结果或文档图片，LoMo 是提升鲁棒性的必选项。它能让模型真正学会“看字”，而不是仅仅依赖 Token 匹配。
### 局限与展望- 渲染开销：虽然推理无开销，但训练时的 LaTeX/文本渲染需要额外的 CPU/GPU 资源进行预处理。
- 数据依赖性：LoMo 主要作用于文本到图像的转换，对于纯视觉推理（如物体识别）的提升相对有限，其核心价值在于“语义载体”的对齐。
总之，LoMo 是一个典型的“小改动大收益”的工作。它提醒我们： 多模态融合的深度，往往取决于数据构造的细腻程度，而非仅仅是模型规模的堆砌。
