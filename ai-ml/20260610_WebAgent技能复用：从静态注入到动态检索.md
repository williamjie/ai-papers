论文 : Online Skill Learning for Web Agents via State-Grounded Dynamic Retrieval链接 : https://arxiv.org/abs/2606.04391做 Web Agent 的都知道，让大模型“记住”以前怎么操作浏览器是个痛点。
现在的在线技能学习（Online Skill Learning）大多还是“静态”思维：任务开始前检索一次技能，然后全程死磕。但这不符合网页交互的真实逻辑——页面状态在变，需要的操作也在变。
这篇来自佐治亚大学等机构的工作 SGDR，核心洞察很直接： 技能检索必须跟随页面状态动态发生 。它把 Web Agent 的技能复用从“任务级一次性注入”升级为了“步骤级动态匹配”。
### 为什么现有方案不够用？
现有的在线技能学习方法（如 AWM、ASI）主要存在两个致命缺陷：
- 粒度不匹配：要么存完整轨迹，太具体导致无法迁移；要么存单步动作，太琐碎失去抽象价值。
- 检索时机僵化：基于初始指令检索的技能，在任务执行到中间页面时往往失效。比如一个“填写表单”的技能，如果在首页就被注入，到了详情页就毫无用处，甚至干扰判断。
SGDR 认为，技能应该像代码库里的函数一样，根据当前上下文（Current State）按需调用，而不是在程序启动时就全部加载。
### 核心设计：滑动窗口与双模检索SGDR 的设计非常工程化，主要解决了“存什么”和“怎么找”两个问题。
1. 滑动窗口提取（Sliding-Window Extraction）
论文没有简单地把整个任务轨迹存为技能，而是用滑动窗口切割成功轨迹。
- 直觉：网页操作往往由多个原子动作组成局部子程序（如“打开设置->点击地址栏”）。
- 实现：使用长度为 2-5 的窗口提取片段，并通过 LLM 验证其可复用性。只有当替换掉原始动作后任务依然成功，该技能才会入库。这保证了技能的“中间粒度”——既不是整个任务，也不是单个点击。
2. 状态感知的动态检索（State-Grounded Dynamic Retrieval）
这是最核心的创新。在每一步决策时，SGDR 不仅看任务目标（Goal），还看当前页面状态（State）。
- 双重信号：检索分数 = α×Cosine(Goal,Skill)+(1−α)×Cosine(State,Skill)\alpha \times \text{Cosine}(Goal, Skill) + (1-\alpha) \times \text{Cosine}(State, Skill)Cosine(Goal,Skill)+(1−α)×Cosine(State,Skill)。
- MMR 重排：为了避免检索到一堆相似的冗余技能，引入了最大边际相关性（MMR）进行去重，确保注入的技能多样性。
⚠️ 反直觉发现 ：实验表明，仅依赖任务目标或仅依赖当前状态都不是最优解。 α=0.5\alpha=0.5 0.5 时效果最好，说明“目标导向”和“状态适配”必须平衡。

### 工程启示- 技能库需要“中间粒度”：不要试图让 Agent 记住整个工作流，也不要只记单步操作。提取 2-5 步的局部子程序是性价比最高的选择。
- 检索必须动态化：静态注入技能在长尾任务中极易失效。将当前页面的 DOM 摘要或截图作为检索 Query 的一部分，能显著提高匹配精度。
- 去重很重要：简单的 Top-K 检索会导致语义冗余。引入 MMR 等多样性惩罚机制，能让 Agent 看到更多样化的操作选项，避免陷入局部最优。
### 局限与展望论文也坦诚了局限性：SGDR 在 GitLab 这类强依赖持久化状态（如 Fork、Merge Request）的任务上表现一般。因为局部技能难以捕捉全局的仓库前置条件。此外，目前仅验证了非参数化的技能积累，未来结合模型微调（Fine-Tuning）可能会带来更强的长期记忆能力。
总体而言，SGDR 为 Web Agent 的技能复用提供了一个更贴合实际交互逻辑的范式： 不要一次性给答案，而是在每一步提供正确的工具。
