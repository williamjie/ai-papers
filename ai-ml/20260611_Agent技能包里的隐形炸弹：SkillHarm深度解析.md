论文 : SkillHarm: Lifecycle-Aware Skill-Based Attacks via Automated Construction链接 : https://arxiv.org/abs/2606.02540Agent 技能（Skills）正成为工作流的核心，但它们也是最大的安全盲区。这篇来自俄亥俄州立大学与 Amazon AGI 的论文揭示了一个残酷事实：当前的 Agent 对恶意技能包几乎毫无抵抗力。
现有的安全研究大多停留在“单次任务执行”层面。攻击者注入一个坏技能，Agent 跑一次任务，失败即止。但这忽略了技能的 生命周期（Lifecycle） ——技能是持久化的，会被跨会话复用，甚至会在执行中被静默篡改。SkillHarm 正是为了填补这个空白而生。
### 核心洞察：从“单次中毒”到“生命周期攻击”
论文提出了两种极具工程现实意义的攻击场景，彻底改变了我们对 Agent 安全的认知：
- 固定载荷投毒（Fixed-Payload Poisoning, FPP）：这是传统模式。技能包里预埋了恶意代码或指令，Agent 只要调用该技能，就会在单次任务中触发危害。
- 自变异投毒（Self-Mutating Poisoning, SMP）：这是本文的杀手锏。初始执行看似无害，但技能包内部包含一个“变异钩子”。它在第一次运行时静默修改了自身的持久化文件。当 Agent 在后续任务中再次复用该技能时，真正的危害才爆发。
这种设计直击痛点：**时间解耦（Temporal Decoupling）**让攻击意图变得极难察觉。Agent 很难将当前任务的安全隐患与几分钟前执行的一个“良性”操作联系起来。
### 自动化构建：用代码 Agent 对抗代码 Agent为了大规模生成这些攻击样本，作者开发了 AutoSkillHarm 。这不是简单的模板填充，而是一个由自然语言驱动的代码 Agent 流水线。
- 目标选择：基于基线轨迹分析，只选择 Agent 真正会读取或执行的技能文件（曝光率 r≥0.30r \ge 0.300.30）。
- 攻击设计：使用 Claude Code (Opus 4.7) 作为设计师，将抽象的风险类型转化为具体的对抗目标，并编写确定性的评估器。
- 质量过滤：通过独立的审查 Agent 剔除无效或过于明显的攻击样本。
最终生成了 879 个攻击样本，覆盖 71 个技能和 12 种风险类型。这种自动化方法解决了手工构造成本高、覆盖面窄的问题。
### 实验结果：防线全面溃败数据不会撒谎。在测试的六种主流 Agent 配置中，结果令人震惊：

⚠️ 反直觉发现：失败不等于安全许多攻击看似“失败”，并非因为 Agent 识破了恶意，而是因为它根本没去读那个被投毒的文件（例如自己写了代码而不是遵循技能指引）。一旦条件限定为“Agent 确实接触了载荷”（cASR），成功率飙升高达 32.1% 。这意味着，随着 Agent 使用技能能力的增强，潜在的安全风险反而在急剧上升。
此外，防御手段形同虚设：
- 技能扫描器：最强的配置也仅能检测出 55.6% (FPP) 和 68.8% (SMP) 的攻击。
- 防御性系统提示：添加警告提示后，几乎所有配置的 ASR 仍高于 70%。
### 工程启示与局限对于正在构建 Agent 应用的工程师来说，这篇论文敲响了警钟：
- 不要信任第三方技能：Agent 对技能的“隐式信任”是致命弱点。必须引入运行时护栏（Runtime Guardrails），而不仅仅是提示词层面的警告。
- 关注持久化状态：SMP 攻击表明，跨会话的状态复用是新的攻击面。需要监控技能包在执行前后的完整性变化。
- 模型与框架的协同安全：实验显示，Claude Code 的低 ASR 部分归功于其安全的框架设计，而不仅仅是模型本身的安全对齐。安全是“模型+框架”堆栈的属性。
当然，SkillHarm 也有局限。它主要关注代码执行和数据泄露类风险，对于更隐蔽的社会工程学攻击覆盖不足。且自动化构建依赖强大的编码 Agent，可能无法覆盖所有边缘情况。但即便如此，它已足以证明：在当前的 Agent 生态中，技能包就是最大的特洛伊木马。
