# ⭐⭐ TerminalWorld：用真实录屏反向构建 Agent 评测基准

**日期**: 2026-05-22

---

论文 : TerminalWorld: Benchmarking Agents on Real-World Terminal Tasks链接 : https://arxiv.org/abs/2605.22535现在的终端 Agent（Terminal Agent）评测大多像“做题”，而这篇论文指出，真正的挑战在于“干活”。现有基准如 Terminal-Bench 依赖专家手工编写题目，容易偏向对抗性谜题，偏离了开发者日常的真实工作流。TerminalWorld 提出了一种全新的思路： 直接逆向工程真实的终端录屏 ，将其转化为可执行的评测任务。这种方法不仅保证了数据的真实性（Authentic by Construction），还实现了随着开发者实践演进而自动扩展的能力。
### 为什么现有方案不够用？
目前的评测基准主要存在两个痛点：
- 缺乏真实性：专家倾向于编写高难度的“脑筋急转弯”来拉开分数差距，但这与日常开发中重复、琐碎但依赖复杂环境的任务大相径庭。
- 扩展性差：手动维护基准无法跟上工具链的快速迭代。
TerminalWorld 的核心 Insight 是： Asciinema 平台上数百万份自愿分享的终端录屏，本质上是一个自策展、经人类验证且持续增长的“真实开发者工作流语料库”。 只要能把这些嘈杂的录屏清洗成标准任务，就能得到最接地气的评测集。
### 方法拆解：从噪点录屏到标准化任务将原始录屏转化为评测任务并非简单复制粘贴，论文设计了一套四步自动化引擎来解决三个核心难题：
-意图提取与噪声清洗录屏包含拼写错误、重试和冗长的系统输出。团队利用 LLM（如 Claude Sonnet）从转录文本中提取两个关键工件：
结果导向的指令（Outcome-oriented Instruction）：描述最终状态而非具体步骤，防止泄露解题路径。
- 干净的参考脚本（Reference Solution）：剔除无效命令后的核心执行流。
-环境逆向工程录屏只记录命令，不记录依赖环境。这是最大的难点。团队使用 LLM Agent（如 Claude Code）根据参考脚本推断所需的 Docker 镜像、系统包和运行时。关键设计在于“执行反馈循环”：Agent 构建 Docker 镜像并运行参考脚本，若失败则解析错误日志修复 Dockerfile，直到脚本成功退出（Exit code 0）。这消除了幻觉依赖，确保环境可复现。
-测试套件生成与校准仅有指令和脚本还不够，需要自动判断 Agent 是否做对了。团队设计了基于三次试验的 refinement loop：
AllPassing Trial：运行参考解，所有测试必须通过（防假阴性）。
- Nop Trial：什么都不做，所有测试必须失败（防假阳性/空状态）。
- Partial Trial：运行截断的不完整解，至少一个测试失败（确保测试能区分部分正确与完全正确）。
这套流程从 80,870 份原始录屏中筛选出 1,530 个经过验证的任务 ，涵盖 18 个真实类别，涉及 1,280 个唯一命令 ，其中 91% 的命令在 Terminal-Bench 中从未出现。
### 关键结果：SOTA 模型依然挣扎论文在人工审核的 TERMINALWORLD-VERIFIED（200 题子集） 上进行了全面评测，结果令人深思：
模型 Pass Rate (%) Avg. Cost ($) $/Pass Claude Opus 4.7 62.5 16.7 0.51 Gemini 3.1 Pro 55.0 10.6 0.52 GPT-5.5 53.5 14.8 0.94 Kimi K2.6 57.5 16.9 0.15 GLM 5.1 57.0 15.5 0.16核心发现：
- 效率悖论（Efficiency Paradox）：资源消耗与成功率呈负相关。GPT-5.5 和 MiniMax M2.7 消耗了最多的 Token 和 Turn，但 Pass Rate 反而较低。失败尝试平均消耗成功尝试 3.3 倍的 Token 和 1.4 倍的时间。这说明在开放动作空间中，盲目探索无法解决问题，需要更强的规划能力。
- 框架影响性价比而非上限：对于同一模型（如 Claude Opus 4.7），不同 Agent 框架（Terminus-2, OpenHands 等）的 Pass Rate 差异不大，但成本差异显著。Terminus-2 和 mini-SWE-agent 以更低的 Token 消耗达到了相似效果。
- 与现有基准脱节：TerminalWorld 得分与 Terminal-Bench 得分的相关系数仅为 Pearson r = 0.20。在 Terminal-Bench 上表现优异的模型，在真实工作流中可能并不突出。
### 工程启示- 评测需要“脏数据”：人工清洗的基准过于理想化。TerminalWorld 证明，利用真实用户行为数据（如录屏、日志）逆向构建评测集，能更有效地暴露 Agent 在处理非标准环境、复杂依赖时的弱点。
- Agent 设计应降低探索摩擦：实验显示，复杂的编排框架并未显著提升能力上限，反而增加了成本。未来的终端 Agent 应聚焦于如何快速发现有效路径，减少无意义的试错。
- 关注长尾命令：TerminalWorld 覆盖了 k3d、terraform、ansible 等大量基础设施工具。这表明通用 LLM 在专用 CLI 工具的使用上仍有巨大盲区，针对特定领域的指令微调（SFT）或检索增强生成（RAG）可能是突破口。
### 局限与展望目前 TerminalWorld 仅覆盖纯 CLI 工作流，不包含 TUI/GUI 交互（如 vim、nano）。此外，自动化逆向过程虽然高效，但仍依赖 LLM 进行环境推断，对于极度依赖特定硬件或私有网络的录屏仍无法复现。随着 Asciinema 数据的积累，该基准有望持续迭代，成为衡量终端 Agent 真实能力的黄金标准。
