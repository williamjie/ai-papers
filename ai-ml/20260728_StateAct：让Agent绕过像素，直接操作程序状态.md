**日期**: 2026-07-28

论文 : StateAct: Program State, before Pixels, for Long-Horizon Computer-Use Agents链接 : https://arxiv.org/abs/2607.22798现在的 GUI Agent 都在卷视觉感知：谁看图更准、谁点击坐标更稳。但 Salesforce AI Research 这篇论文泼了盆冷水： 截图只是程序状态的有损渲染 。对于长周期任务，盯着像素看不仅效率低，还会因为信息丢失导致误差累积。StateAct 的核心主张很激进：把 Agent 的交互主通道从“屏幕”切换到“代码/状态”，视觉交互仅作为兜底手段。
### 为什么“看图”是瓶颈？
传统 Computer-Use Agents (CUA) 的工作流是：截图 →\rightarrow 识别 UI →\rightarrow 点击/输入。这在短任务中还行，但在长周期任务（如处理几百步的 Excel 或日历同步）中面临两个致命问题：
- 渲染是有损且非单射的。屏幕上的“1,240”可能是一个公式 =SUM(B2:B6)，也可能只是一个硬编码的数字。截图无法区分这两者，但这对后续计算至关重要。
- 误差累积。每一步基于像素的判断都有微小误差，几百步下来，Agent 早就偏离了目标状态。更糟糕的是，截图无法可靠地验证最终结果（比如文件是否真的保存到了指定路径）。
StateAct 的核心 Insight 是： 桌面任务的交付物是程序状态（State），而不是屏幕截图（Pixels） 。既然目标是修改状态，为什么不直接操作状态？
### 方法拆解：State-First 架构StateAct 并没有完全抛弃视觉，而是重构了 Agent 的决策层级：
- 主 Agent (Main Agent)：只读/写程序状态。它的动作空间是 Bash、Python、文件编辑器等。它不控制鼠标键盘，而是直接读取 Excel 文件的底层数据、查询 DOM 结构或操作数据库。
- GUI 子代理 (GUI Subagent)：仅处理不可编码的视觉交互。只有当主 Agent 发现某个任务无法通过代码路径解决（如拖拽画布元素、关闭非脚本化弹窗）时，才会调用这个专门的视觉专家。
- 独立验证门 (Finish Gate)：一个“盲审”机制。它不看主 Agent 的执行日志，只检查最终持久化的文件/状态是否符合任务要求。这避免了 LLM 常见的“自圆其说”偏差。
关键设计直觉 ：主 Agent 保持“扁平化”，不引入复杂的递归层级。通过上下文压缩和外部计划清单来维持长周期记忆，而不是靠深层嵌套的代理通信。
### 实验结果：降本增效的双重胜利在 OSWorld 2.0 基准测试（108 个长周期任务）上，StateAct 配合 Claude Opus 4.8 的表现令人印象深刻：
指标 StateAct (Ours) Opus 4.8 参考基线 提升幅度 二元成功率 26.9% 20.6% +6.3 pts 部分成功率 61.6% 54.8% +6.8 pts 单任务成本 ~$7.8 ~$72.0 降低 ~9x- 消融实验验证：如果去掉“状态优先”动作（退化为纯 GUI），部分成功率跌至 51.3%，甚至低于基线。这证明核心增益来自观察通道的改变，而非 Agent 架构的复杂度。
- 视觉子代理的使用率极低：在 108 个任务中，仅有 28 个任务调用了 GUI 子代理，且仅占主 Agent 步骤的 1.1%。这意味着绝大多数操作都可以通过代码高效完成。
### 工程启示与局限对工程师的建议：
- 优先寻找 API/状态接口：在构建自动化 Agent 时，不要默认使用 UI 自动化（如 Selenium/PyAutoGUI）。先检查目标应用是否有文件存储、数据库或 DOM 可访问性。直接操作数据比模拟点击更稳健、更快。
- 分离“执行”与“验证”：不要让同一个 LLM 实例既干活又自检。引入独立的、基于状态的验证器（Finish Gate）能显著减少幻觉导致的错误提交。
- 视觉作为最后手段：将视觉识别模块视为“兜底专家”，仅在代码路径失效时调用，这能大幅降低 Token 消耗和延迟。
局限性与边界：
- 推理能力仍是瓶颈：StateAct 解决了感知问题，但无法解决逻辑错误。论文分析显示，剩余失败案例中 38/79 源于 Agent 的推理错误（如算错数、误解指令），这是状态访问无法弥补的。
- 视觉强依赖任务表现不佳：对于图像编辑、布局调整等“所见即所得”的任务，StateAct 的优势不明显，因为这些任务的交付物本身就是像素。
总结 ：StateAct 证明了在长周期计算机使用中， “思考”比“看见”更重要 。通过将交互锚定在程序状态上，我们不仅提高了准确率，还实现了数量级的成本降低。这是 Agent 从“模拟人类操作员”向“智能系统管理员”演进的关键一步。
