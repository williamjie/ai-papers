# ⭐⭐⭐½ LLM打标签翻车记：CVE映射ATT&CK的陷阱与真相

**日期**: 2026-07-29

论文 : Mapping CVEs to MITRE ATT&CK Techniques: A Curated Gold-Set Classifier and the Limits of LLM-Assisted Label Expansion链接 : https://arxiv.org/abs/2607.25572安全工程师常面临一个痛点：如何将成千上万的 CVE 漏洞映射到 MITRE ATT&CK 战术框架？手动标注太慢，自动推导太脏。这篇来自 CIRCL 的论文不仅给出了一个高性能的监督微调（Supervised Fine-Tuning, SFT）方案，更通过三次“翻车”实验，揭示了 LLM 辅助数据增强的残酷真相： 在低质量标签下，数据量越大，模型表现越差。
### 现有方案的致命缺陷目前主流做法是利用 CWE→CAPEC→ATT&CK 的链条进行确定性推导。作者直接量化了这种方法的噪音：在 39,156 个 CVE 中，平均每个漏洞被贴上 13.3 个标签，中位数高达 8 个。更离谱的是，由于表扩展（Table Expansion）机制，像 T1574.007（路径劫持）这样的通用技巧竟然覆盖了 53% 的 CVE。
这种推导反映的是映射表的结构，而非真实的攻击行为。训练在这种数据上，模型学会的不是“漏洞如何被利用”，而是“如何复现表格的错误”。因此，作者坚决弃用自动标签，转而构建了一个仅包含 1,207 条专家标注的“黄金数据集”（Gold Set）。
### 方法拆解：小而美的监督学习作者的核心直觉是： 标签质量 > 数据规模 。
他们使用 RoBERTa-base 进行多标签分类，采用二元交叉熵损失（BCEWithLogitsLoss），将每个 ATT&CK 技巧视为独立的 0/1 决策。为了应对长尾分布，他们对稀有技巧的权重进行了逆向比例调整，并将子技巧合并到父技巧以简化词汇表（最终保留 57 个父技巧）。
这种设计不仅提升了准确率，还兼顾了工程落地：模型推理只需一次前向传播，无需生成文本，可在 CPU 或小型 GPU 上低延迟运行，适合本地部署。
### 关键结果：LLM 增强的幻象与破灭实验部分极具戏剧性，揭示了评估噪声对结论的致命干扰：
- 基线对比：监督模型大幅超越零样本语义相似度基线（SMET-style）。Recall@5 从 0.322 提升至 0.686，MRR 从 0.397 提升至 0.620。
- LLM 标签质量：使用 Qwen-122B 进行标注，与专家标注的 Micro-F1 仅为 0.392（低于模型自身预测水平 0.407）。
- 三次反转的实验：
第一次（单种子）：加入 LLM 标签后，Recall@5 下降 0.050。结论：LLM 有害。
- 第二次（五种子平均）：Recall@5 提升 0.030。结论：LLM 有益。
- 第三次（独立复现+缩放测试）：真相大白。之前的“提升”是因为基线模型在验证集选择上运气不好（评估噪声）。在修正后的协议下，加入 LLM 标签没有任何可靠增益。更糟的是，当加入 984 条 LLM 标签时，Macro-F1（稀有技巧覆盖率）下降了 0.04。

### 工程启示这篇论文给 AI 安全落地敲响了警钟：
- 不要盲目相信 LLM 生成的训练数据：LLM 与专家的一致性仅为 39%，这种噪音在大规模引入时会稀释稀有技巧的信号，导致模型“平庸化”。
- 警惕评估噪声：在小数据集上，基于测试集选择最佳检查点（Checkpoint）会引入巨大的方差。作者修正协议后，Micro-F1 的标准差从 0.016 降至 0.006。工程实践中务必使用独立的验证集进行模型选择。
- 高质量小数据集优于低质量大数据集：对于 CVE-ATT&CK 映射这类专业任务，专家标注的 1,200 条数据足以训练出高性能模型，强行用 LLM 扩充只会适得其反。
⚠️ 核心结论 ：在标签质量受限的场景下，分类器是“标签质量绑定”（Label-quality bound），而非“数据量绑定”（Data bound）。LLM 标注若不能达到专家水平，越多越毒。
