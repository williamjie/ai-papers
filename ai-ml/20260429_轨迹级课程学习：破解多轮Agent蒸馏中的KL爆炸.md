# 轨迹级课程学习：破解多轮Agent蒸馏中的KL爆炸

**日期**: 2026-04-29

---

论文 : TCOD: Exploring Temporal Curriculum in On-Policy Distillation for Multi-turn Autonomous Agents链接 : https://arxiv.org/abs/2604.24005多轮Agent的蒸馏，不能直接把单回合的方法照搬过来。
这是读完这篇论文最直接的结论。On-policy distillation (OPD) 在数学问答这类单回合任务上已经证明有效——让学生在自己生成的轨迹上模仿教师的 token 分布，用 KL 散度做监督信号。但一旦放到多轮交互环境（ALFWorld、WebShop），这套玩法就崩了。
## 问题：为什么 vanilla OPD 在多轮场景会失稳？
论文提出的核心发现叫 Trajectory-Level KL Instability（轨迹级KL不稳定性） 。关键现象有两个：
- KL 持续攀升，成功率塌陷：随着训练步数增加，KL 散度不降反升，成功率跌到接近零- 初始值过高：收敛后 KL 虽然下降，但初始值太夸张了——学生和教师之间的 KL 初始能达到 ~1000，而收敛后只剩 ~60，这意味着训练初期梯度完全不可信Figure 2d 把机制说得很清楚： 每轮的误差会 compounding（累积） 。学生第 1 步错了，这个错误状态会进入历史，影响第 2 步；第 2 步再错，影响第 3 步……后果就是学生逐渐”漂”到教师从未见过的状态分布，教师在这些状态上分配的概率很低，KL 散度自然飙升。
Table 2 的数据更直观：Qwen2.5-3B 学生用 vanilla OPD 在 ALFWorld 上，成功率只有 13.06% ；而教师（Qwen2.5-7B-RL）能达到 65.72% 。差距不是一点半点。
## 核心 insight：控制轨迹深度，让教师监督始终靠谱关键洞察是： 教师只在”自己熟悉的区域”内才是可靠的监督源 。一旦学生跑到太远的地方，教师的分布就开始模糊，KL 信号就废了。
TCOD 的解法很直觉： 不要一开始就把完整长轨迹丢给学生 。用 curriculum（课程学习）控制暴露的轨迹深度，从短到长逐步推进。
具体有两个变体：
### TCOD-F2B（Forward-to-Backward）
学生从短轨迹开始学，逐步增加到完整任务。公式：
L = Σ_{t=0}^{k-1} DKL(π_φ(a_t|h_t) || π_θ(a_t|h_t))
k 从 kstart 开始，每 η 步增加 1，直到最大步数 T_max。
### TCOD-B2F（Backward-to-Forward）
这个更聪明： 教师先Navigator 。从预收集的成功轨迹中，教师执行前面的 L-k 步，把环境推到”距离成功只剩 k 步”的状态，学生再从这儿开始执行剩下的 k 步。
L = Σ_{t=L-k}^{L-1} DKL(π_φ(a_t|h_t) || π_θ(a_t|h_t))
这样学生始终在教师”照看”过的区域优化，避免了早期累积错误。
核心设计直觉 ：
- F2B：让学生先学”容易的短任务”，逐步延长思考链条- B2B：让学生直接从”快成功”的状态开始，避免在起点就犯错- 两者都用 stop-gradient 确保教师动作不参与梯度，只负责定位## 关键结果：不只是好一点，而是质变Q1: 能否缓解 KL 不稳定性并提升性能？

## 工程启示：你的本地模型蒸馏可以怎么用？
- 多轮任务不要照搬单回合蒸馏：如果你在蒸馏一个 Agent，不要假设”学生跟着教师rollout就能学好”——误差累积会毁掉一切- 从短到长是安全策略：无论是 F2B 还是 B2F，核心都是控制暴露的轨迹深度。对长 horizon 任务，先让学生掌握局部决策，再逐步扩展视野- B2F 的”教师导航”模式值得借鉴：预收集一些成功轨迹，教师执行前缀把环境推到”快成功”状态，学生只优化剩余部分。这特别适合稀疏 reward 环境——学生始终在 reward 密度高的区域学习- 训练动态需要监控：Figure 2a 显示 KL 和成功率是反向运动的——如果看到 KL 上升的同时成功率下降，说明 curriculum 可能推进太快，该减慢 η 了## 局限与后续方向论文在 Discussion 部分提到几个点：
- train-test mismatch：B2F 训练时学生从教师导航的状态开始，测试时要从头开始。论文用渐进减少教师前缀的方式缓解，但这是一个需要小心处理的分布偏移问题- 教师质量决定上限：Table 2 vs Table 3 的对比显示，领域适配的教师（ALFWorld 上 RL fine-tuned 的 Qwen2.5-7B）能让学生略微超越自己（+0.7点）；但通用教师（Qwen3-30B）学生只能接近，无法超越——说明教师的 domain 覆盖能力比模型规模更重要- 效率分析还可以更深：论文只给了总训练时间对比，没细说 rollout 效率与最终性能的 trade-off## 总结TCOD 的价值在于 把一个多轮 Agent 蒸馏的”不稳定任务”，转化成了一个”可控的课程学习任务” 。核心操作只是控制轨迹长度，但效果拔群：小模型成功率的绝对提升超过 16%，甚至能在教师都失败的困难任务上超越教师。
对于实际做 Agent蒸馏的工程师，这条路径很清晰： 别让学生一开始就面对完整长任务，用 curriculum 逐步增加决策长度，让教师的监督信号始终落在其可靠区域内。 简单、有效、训练还更快。
