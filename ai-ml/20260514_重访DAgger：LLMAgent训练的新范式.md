# 重访 DAgger：LLM Agent 训练的新范式

**日期**: 2026-05-14

---

论文 : Revisiting DAgger in the Era of LLM-Agents链接 : https://arxiv.org/abs/2605.12913在长程交互（Long-horizon）的 LLM Agent 场景中，一个早期的微小错误往往会导致后续状态分布彻底偏离，最终让整条轨迹崩盘。这篇来自佐治亚理工和苏黎世联邦理工的论文，重新拾起了经典算法 Dataset Aggregation (DAgger)，并证明了它在现代大模型 Agent 训练中的巨大价值。对于正在构建代码生成、Web 浏览等复杂 Agent 的工程团队来说，这是一篇极具参考价值的“避坑指南”。
## 现有方案的结构性痛点目前训练多轮 LLM Agent 的主流方法主要有两类，但都存在明显的结构性缺陷：
- 监督微调（Supervised Fine-Tuning, SFT）：直接模仿专家轨迹。优点是标签密集，缺点是存在严重的协变量偏移（Covariate Shift）。因为模型只在专家状态上训练，一旦部署时出现误差，状态分布就会迅速发散，导致性能断崖式下跌。
- 基于验证奖励的强化学习（RLVR）：如 GRPO。优点是数据来自模型自己的真实交互（On-policy），避免了分布偏移；缺点是奖励信号极其稀疏，且计算成本高，容易出现信用分配难题。
- 在线蒸馏（On-policy Distillation, OPD）：试图结合两者，但在冷启动阶段表现糟糕。弱学生模型早期的 Rollout 经常失败，导致教师模型只能监督那些“错误的片段”，无法提供有效反馈。此外，OPD 需要教师模型的 Logits，无法使用黑盒 API（如 GPT-4）。
论文的核心洞察在于： DAgger 恰好能同时解决协变量偏移、冷启动失败和黑盒兼容性问题。
## 方法拆解：Teacher-Interleaved RolloutsDAgger 的核心思想是：在迭代训练中，使用“学生-教师混合策略”生成数据，并在这些 学生实际可能遇到的状态 上进行监督学习。
论文提出了两种具体的 Rollout 策略：
- DAgger-style Rollout（回合级混合）：
在每个 Turn，以概率 βi\beta_i​ 选择教师动作，以 1−βi1-\beta_iβi​ 选择学生动作。βi\beta_i​ 随训练迭代逐渐衰减。这意味着早期主要靠教师“带路”，后期逐渐让学生独立决策。
- AggreVaTe-style Rollout（轨迹级混合）：
学生生成前缀轨迹，随后教师接管完成剩余部分。这保证了即使学生早期犯错，也能通过教师的介入获得成功的完整轨迹进行监督。
关键设计直觉 ：
无论哪种策略， 标签始终来自教师 （Expert Labels），但 状态分布来自混合策略 。这样既保留了 SFT 的密集监督信号，又通过混合采样让模型接触到部署时的真实状态分布，从而缓解协变量偏移。同时，由于早期有教师介入，避免了 OPD 的冷启动灾难；且只需查询教师动作（Action），无需 Logits，完美兼容黑盒教师。
## 关键结果：小模型打爆大模型？
实验在 SWE-Gym 数据集上进行，使用 Qwen3-4B 和 Qwen3-8B 作为学生，Qwen3-Coder-30B 作为教师。结果令人印象深刻：
模型规模 方法 SWE-Gym Holdout SWE-Bench Verified 4B OPD (最强基线) 16.0% 23.4% 4B DAgger-style 17.0% 27.3% 8B OPD (最强基线) 16.0% 26.2% 8B DAgger-style 19.0% 29.8%几个值得注意的细节 ：
- 4B 模型超越 8B 竞品：4B 的 DAgger 模型在 SWE-Bench Verified 上达到 27.3%，超过了公开最强的 8B 系统（SkyRL-Agent-8B-v0 为 9.4%）。
- 8B 模型逼近 32B 水平：8B DAgger 模型达到 29.8%，超过了 SWE-Gym-32B（20.6%），仅落后于更强的 32B 系统约 5 个百分点。
- 训练更稳定：在有效样本量增加时，SFT 的性能会出现波动甚至下降（受协变量偏移影响），而 DAgger 表现出更平滑、稳定的增益曲线。
## 工程启示- 不要迷信 SFT：对于长程 Agent 任务，纯 SFT 极易陷入协变量偏移的陷阱。引入 On-policy 的状态覆盖至关重要。
- 黑盒教师也是好老师：你不需要教师模型的 Logits 或内部梯度。只要教师能给出动作（Action），就可以通过简单的模仿学习进行蒸馏。这大大降低了对强大白盒模型的依赖。
- 冷启动很重要：在训练初期，完全依赖学生自生成数据（如 OPD）风险极高。通过 Teacher-Interleaved 策略，让教师在早期“托底”，能显著提升训练初期的效率和稳定性。
- 失败模式的转变：分析显示，DAgger 训练后的模型，失败原因从“语法错误”、“工具使用错误”转向了“上下文溢出”和“定位错误”。这意味着模型已经学会了基本的交互规范，瓶颈转移到了更高级的规划和长上下文管理上，这是模型能力质的提升。
## 局限与展望尽管效果显著，DAgger 依然受限于长上下文容量。论文指出，剩余的主要失败模式是 Context Overflow，这暗示了未来需要结合更高效的上下文管理机制。此外，DAgger 的计算成本介于 SFT 和 RL 之间，虽然比 RL 低，但仍高于 SFT，需要在样本效率和计算资源之间做权衡。
总的来说，这篇论文重新证明了经典算法在新时代的生命力。对于构建复杂 Agent 的团队，DAgger 提供了一种比 SFT 更稳健、比 RL 更高效的训练路径。
