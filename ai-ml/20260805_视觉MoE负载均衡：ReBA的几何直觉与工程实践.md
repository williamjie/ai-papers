论文 : Relax Within, Balance Across: Geometry-Guided Load Balancing for Vision-Language Mixture-of-Experts链接 : https://arxiv.org/abs/2608.00574在部署多模态大模型时，MoE（Mixture-of-Experts）架构的负载均衡是个老大难问题。这篇论文揭示了一个被长期忽视的陷阱：标准的 Token 级辅助损失在多模态场景下其实是在“耍流氓”，它掩盖了真正的负载失衡，只在特定数据分布下碰巧平衡。
## 痛点：标准辅助损失的“虚假繁荣”
现有的 Switch Transformer 架构使用标准的 Token 级辅助损失（Std-Aux）来平衡专家负载。但在视觉-语言模型中，Batch 里的图像和文本 Token 比例是动态变化的（受分辨率、切片数影响）。
论文通过实验发现了一个惊人的事实：在 Split-Qwen3VL-4B 模型上，同一个训练好的 Router，随着图像分辨率变化，其负载不均衡度（RMS-CV）会发生超过 5 倍 的剧烈波动。
⚠️ 反直觉发现 : Std-Aux 并不是没起作用，而是它在“作弊”。它让图像和文本产生了巨大的、方向相反的负载偏差，两者在特定 Token 比例下恰好抵消。一旦输入分布改变（比如高分辨率导致图像 Token 激增），这种抵消就会失效，导致严重的负载倾斜。
## 核心 Insight：ReBA 的几何直觉为了解决这个问题，作者提出了 ReBA (Relax Within, Balance Across) 。其设计逻辑完全基于对 Router 输入空间几何结构的观察：
- 模态边界（Modality Boundary）：图像和文本在 Router 的输入空间中占据完全不同的区域。因此，必须将图像和文本的负载均衡目标彻底解耦，分别计算 Loss，防止它们互相抵消错误。
- 图像边界（Image Boundary）：同一张图像的视觉 Token 在路由上高度相关，而不同图像之间则有明显差异。因此，ReBA 不统计单个 Token，而是以单张图像为实例进行负载均衡。
简单来说，ReBA 的逻辑是：“图片内部怎么分我不干涉（Relax Within），但不同图片和文本整体必须平衡（Balance Across）”。这种设计不仅消除了模态间的误差抵消，还避免了长图因 Token 多而获得过大的优化权重。
## 关键结果：更稳的负载，持平的性能论文在四个 Split-MoE 骨干网络（基于 Qwen3-VL, InternVL3 等）上进行了验证，数据非常扎实：
- 负载稳定性：ReBA 将负载曲线的曲率降低了 96.3%。这意味着无论输入是纯文本还是高分辨率大图，负载均衡度都保持在一个极窄的低值区间内。
- 消除模态抵消：在 Split-Qwen3VL-4B 上，图像与文本负载的皮尔逊相关系数从 -0.949（强负相关，即互相抵消）改善至 -0.166。平均 L1 间隙从 0.798 降至 0.137。
- 性能持平：在 POPE、MMBench 等主流基准测试中，ReBA 的平均任务准确率与 Std-Aux 基本持平（差异在 ±0.6 以内），但负载方差显著降低。

## 工程启示与局限对于正在落地多模态 MoE 的工程团队来说，这篇论文的启发是明确的： 不要盲目信任全局的负载均衡指标 。如果你的模型在处理高分辨率图像或复杂 Agent 任务时出现推理延迟抖动，很可能就是遇到了这种“模态互补”导致的负载崩溃。
ReBA 的实现成本极低，不需要增加新的 Router 参数，只需修改辅助损失的统计聚合方式（从 Token 级改为 Image/Text 实例级）。其计算复杂度仅为 O(∣M∣N)O(|M|N) ，几乎可以忽略不计。
不过，该方法目前主要验证于 Split-MoE（稠密转稀疏）架构。虽然论文在原生 MoE 模型（如 Qwen3-VL-MoE-30B）上也观察到了类似的几何特征，但在原生稀疏训练中的长期效果仍需更多社区验证。
