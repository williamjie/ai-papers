### 痛点：为什么现有的 Agent 不会“白手起家”？
目前的代码 Agent（如 SWE-agent）大多是在“修补匠”模式下训练的。它们面对的是已经存在的代码库，任务是修 Bug 或加功能。这种模式有个致命缺陷： Agent 永远依赖已有代码的上下文 。
一旦要求 Agent 从零开始（From Scratch），情况就变了。它必须经历完整的软件生命周期：从文档中推断需求、设计架构、编写代码、调试错误，直到最终构建成功。在 ProgramBench 基准测试中，即便是 GPT-5.5 这样的顶级模型，完全解决此类任务的比例也不到 1%。现有的训练数据缺乏这种“全生命周期”的长程推理轨迹，导致小模型在面对复杂工程时往往半途而废。
### 核心 Insight：制造“信息真空”来逼迫模型思考MindForge 的核心创新在于构建了一个**源码隔离（Source-Free）**的训练环境。
- 环境构建：他们自动化地将开源命令行程序转化为 Docker 镜像。关键点在于，Agent 在环境中看不到任何源代码，只能看到一个编译好的参考可执行文件和公开的文档（README/man page）。
- 强制逆向思维：因为无法直接复制粘贴代码，Agent 必须通过运行参考程序、观察输入输出来“黑盒”推断功能规格。这迫使模型学习真正的工程推理，而不是简单的模式匹配。
- 轨迹清洗：使用 GLM-5.2 作为教师模型生成轨迹后，MindForge 引入了独特的“推理重写机制”。如果教师模型在长程运行中犯了工具调用错误，系统不会简单删除该步骤，而是让模型自我修复后续的推理逻辑，确保训练数据的连贯性和高质量。
⚠️ 反直觉发现 ：通常我们认为更长的轨迹意味着更多的噪声。但 MindForge 数据显示，经过微调的模型虽然平均回合数翻倍（从 344 增至 735），但其 命令失败率反而从 10.98% 降到了 9.35% 。这说明长程训练教会了模型更稳健的工程纪律，而非盲目试错。

### 工程启示：如何训练你的“全能”代码 Agent？
- 全生命周期数据至关重要：不要只收集“最终 Patch”。要收集从需求分析、架构设计到调试的完整轨迹。MindForge 数据显示，99.1% 的优质轨迹都包含“规格探索”阶段，这是小模型最缺乏的能力。
- 隔离训练提升鲁棒性：尝试在训练中隐藏部分源码或参考实现，迫使模型通过执行反馈来学习。这种“黑盒测试”式的训练能显著提升模型的调试能力。
- 长上下文微调的价值：MindForge 的轨迹平均长度达 181.6 轮，峰值 token 数高达 272K。这表明，对于复杂工程任务，模型需要更长的注意力窗口来维持逻辑一致性。
### 局限与展望尽管效果显著，该方法目前主要局限于**命令行工具（CLI）**的重构，且依赖强大的教师模型（GLM-5.2）生成初始轨迹。此外，环境构建过程计算成本高昂，每个程序都需要经过复杂的编译验证和源码泄露检查。未来，如何将这种“源码隔离”范式扩展到更复杂的 GUI 应用或微服务架构，将是下一步的关键挑战。
