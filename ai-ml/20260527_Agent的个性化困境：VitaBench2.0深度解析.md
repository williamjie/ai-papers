论文 : VitaBench 2.0: Evaluating Personalized and Proactive Agents in Long-Term User Interactions链接 : https://arxiv.org/abs/2605.27141现在的 LLM Agent 在写代码、做数学题上已经相当成熟，但一旦进入真实的“长期陪伴”场景，它们往往显得像个失忆的机器人。美团联合新加坡国立大学发布的 VitaBench 2.0，精准地戳破了这个泡沫：即使是最强的模型，在处理碎片化交互中的用户偏好时，依然表现糟糕。这篇论文不仅提供了一个新的评测基准，更揭示了当前 Agent 系统在“个性化”和“主动性”上的根本性缺陷。
### 为什么现有的 Benchmark 不够用？
现有的 Agent 评测（如 WebVoyager, GAIA 等）大多关注“推理能力”和“工具调用”。在这些任务中，用户意图是明确的，上下文是自包含的。但在真实生活中，用户很少直接说“我讨厌辣”，而是通过搜索“低脂饮食”、浏览“清淡餐厅”等行为间接表达。
VitaBench 2.0 的核心洞察在于： 个性化不是静态的知识检索，而是动态的偏好推断与更新。 它模拟了长期交互场景，要求 Agent 从碎片化的对话和行为日志中，提取隐含偏好（Preference Extraction），并在后续决策中利用这些偏好（Preference Utilization），甚至当用户行为改变时及时更新记忆（Preference Updating）。
### 方法拆解：如何模拟真实的“懂你”？
VitaBench 2.0 的设计非常贴近工程现实，主要体现在三个维度：
- 碎片化交互历史：任务不再是单次查询，而是时间序列。Agent 需要在任务间隙处理新的交互记录（如搜索历史、对话片段），从中区分“信号”与“噪声”。例如，用户搜了“减肥食谱”，Agent 需要推断出“健康饮食”偏好，而不是仅仅记住这个关键词。
- 可扩展的记忆接口：为了公平对比，论文定义了标准的 UPDATE 和 RETRIEVE 接口。这允许我们插入不同的记忆架构，比如基于 RAG 的向量检索，或者由 Agent 自主控制的 Agentic Memory（决定存什么、删什么）。
- 主动性（Proactiveness）评估：这是最大的亮点。很多 Agent 在信息不足时会强行回答或瞎猜。VitaBench 2.0 设置了“缺失信息”任务，要求 Agent 识别出自己不知道什么，并主动向用户提问或探索环境。这模拟了真正智能助手的“追问”能力。
### 关键结果：SOTA 模型依然很弱实验结果令人沮丧，但也极具参考价值。论文评测了包括 GPT-4o, Claude Opus, DeepSeek-V4-Pro 等在内的顶尖模型。
模型类别 Avg@4 (Full Context) Passˆ4 (Full Context) DeepSeek-V4-Pro 0.658 0.207 Claude Opus-4.6 0.664 0.198 GPT-4o-mini 0.229 0.008即使在拥有完整上下文（Full Context）的理想情况下，最强模型的 Avg@4 也仅在 0.65 左右，而要求四次独立运行全部成功的 Passˆ4 更是低至 0.20 上下。这意味着什么？意味着即便给了所有信息，模型依然很难稳定地做出符合用户偏好的决策。
更有趣的是对“思考模式”（Thinking Mode）的分析。通常我们认为让模型多思考能提升性能，但在 VitaBench 2.0 上，开启 Thinking 模式的提升并不显著，甚至在某些场景下效率更低。这说明 个性化瓶颈不在于推理深度，而在于偏好提取和长期一致性 。
### 记忆机制的悖论工程上我们常依赖 RAG 或向量数据库来解决长上下文问题。但 VitaBench 2.0 发现，引入记忆机制后，模型性能反而下降。
- RAG Memory：基于相似度的检索往往召回无关信息，导致干扰。
- Agentic Memory：让模型自己决定存什么，虽然更灵活，但模型经常“记错”或“遗忘”关键偏好，导致误差累积。
随着任务序列的推进（从第 1 个任务到第 10 个任务），性能呈现明显的下降趋势。这揭示了当前 Agent 在长期交互中的致命伤： 信息丢失与错误传播 。早期的微小推断错误，会在后续任务中被放大，最终导致完全偏离用户意图。
### 工程启示：我们该如何构建个性化 Agent？
- 不要迷信 RAG：简单的向量检索无法处理复杂的偏好逻辑（如“心情好时喜欢游泳，心情差时喜欢看书”）。需要更结构化的用户画像管理。
- 重视“追问”机制：在信息缺失时，强制 Agent 输出澄清问题而非盲目行动，能显著提升用户体验和任务成功率。
- 偏好是动态的：系统设计必须支持偏好的增、删、改。静态的用户 Profile 在长期交互中会迅速失效。
- 推理增强并非万能：针对个性化场景，可能需要专门的微调数据或奖励模型（Reward Modeling），而不仅仅是依赖更强的基座模型或更长的思考链。
VitaBench 2.0 告诉我们，真正的个性化 Agent 之路还很长。当前的 SOTA 模型更像是一个聪明的执行者，而非一个懂你的伙伴。对于工程师而言，关注记忆架构的设计和主动交互逻辑的实现，比单纯堆砌模型参数更有价值。
