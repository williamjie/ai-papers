# 只算前向传播，也能给训练数据打分

**日期**: 2026-04-28

---

论文 : For-Value: Efficient Forward-Only Data Valuation for finetuning LLMs and VLMs链接 : https://arxiv.org/abs/2508.10180一句话说：这篇论文干掉了数据估值里最贵的梯度计算，从此给百万条训练样本打分不用再一遍遍跑反向传播。
## 背景：数据估值到底在估什么？
大模型微调（SFT）时，数据质量决定效果。但训练集里混着低质量样本——要么标注错了，要么跟任务不相关。你得知道 哪个样本贡献大，哪个是噪音 ，这就是数据估值（Data Valuation）。
传统方案主要分两类：
- Influence Functions（Koh & Liang, 2017）：算 Hessian 矩阵逆，代价 O(d³) 起步，13B 参数模型根本玩不转- TracIn 系列（Pruthi et al., 2020）：靠梯度相似度，但要存所有 checkpoint 的梯度，内存爆炸DataInf（Kwon et al., 2024）和 HyperInf（Zhou et al., 2024）已经做了近似优化，但骨子里还是在算梯度—— 每张卡一次只能处理一个样本 ，没法批量并行。
简单说，现有方案都是 “反向往复跑” 的思路：先跑前向得到损失，再反传梯度看”如果去掉这个样本损失会怎么变”。问题在于，LLM 动辄几十亿参数，每轮微调都来一遍，时间成本直接起飞。
## 核心洞察：最后一层梯度就能搞定？
这篇论文的关键观察很直觉：** bottlenect 在最后一层**。
预训练好的 LLM/VLM 已经具备了强大的表征能力。微调时，大部分参数基本冻结（尤其是早期层），真正”学习”的主要是最后一层和 LoRA 模块。论文里有个 unconstrained feature assumption ：假设模型能产出与架构细节解耦的隐层表示——意思是Transformer堆那么多层，最后出来的 h 已经够你用，不依赖细枝末节。
基于这个假设，作者证明了： 训练样本 (xi, yi) 对验证样本 (xv, yv) 的影响，可以用最后一层梯度表示成一个闭式表达式 。这个表达式只依赖于两个东西：
- 两个样本在最后一层的隐层表示 h（前向传播可得）
- 两个样本在各自序列上的 token 级预测误差 α（也是前向传播可得）
预测误差 α 定义为：α = e_y - π(·|context)，也就是 one-hot 标签和模型预测分布的差。 这玩意儿天然就是 soft 的标签权重——模型已经很确定的 token，误差就小，权重低；模型懵圈的 token，误差大，权重大 。
所以最终的数据价值分数（Eq. (1)）是：
score(xi → xv) = Σ_{k∈yv} Σ_{k’∈yi} α_{xv,k} · α_{yi,k’} · ⟨h_{xv,<k}, h_{yi,<k’}⟩双重对齐 ：既要隐层表示对齐（⟨h,h⟩），也要预测误差对齐（α·α）。想象力丰富点：你在 xv 上犯错的点，如果恰好 yi 也在同样位置犯错，那 yi 对 xv 就有价值——同病相怜嘛。
## 工程化落地：怎么把这个公式跑起来？
光有公式不够，还得能在大规模数据上跑。论文的核心工程技巧就两点：
### 1. 词汇表裁剪（V̂ 截断）
公式里 α 的维度是整个词表 |V|（通常几万），直接外积 O(|V|·d) 太贵。但实际中， 概率质量高度集中 ——一个样本的预测分布主要落在它自己序列出现的 token 上。
所以只保留 样本关联词表 V̂ = V(x,y) ∪ V(xv,yv)，把复杂度从 O(|V|·d) 降到 O(|V̂|·d)。批量计算时，V̂ 还可以进一步收缩成 in-batch vocabulary ——这一批样本共用的词，进一步压缩计算量。
### 2. 批处理友好算法流程就四步：
- 一次前向跑完整个 batch 的 (xi,yi) 和 (xv,yv)，缓存每步的 h 和 π(·)
- 提取样本关联词表 V̂- 计算 α = e - π(·)（只在 V̂ 上）
- 按 Eq.(2) 做稀疏矩阵乘法，得到每个训练样本的分数全程无反向 ，batch size 想设多大设多大，GPU 利用率直接拉满。

## 消融实验：α 项真的有用吗？
论文做了关键消融：把预测误差权重 α 直接置为 1。这时候公式退化成 纯隐层表示相似度 （Emb 基线）。结果：
- 在 LLM 任务上，Emb 的 AUC 掉到 0.546–0.854，Recall 更惨，只有 0.148–0.563- 加入 α 后，各项指标全线上涨结论： 不能简单拿句子向量做相似度 。因为 LLM 训练是自回归的，不同位置的 token 重要性不同。α 项就是那个”我在哪些 token 上没把握”的 mask，它给高不确定性 token 更高权重—— 这才是自回归模型数据估值的正确姿势 。
## 工程启示：这对你的项目意味着什么？
如果你是：
- 本地部署微调：面对几百 GB 数据不知道怎么选，For-Value 一次前向 pass 就能给出排序，选 top-k 就行。对 70B 模型，72B 也只要几百秒（图 4a），而 HyperINF 在 32B 就要 6 小时。
- 数据清洗：发现标注错误，用 For-Value 快速给样本打分，低分样本直接进待审查队列。论文在猫狗分类（50% 错误率）上 Recall 达到 0.999，说明效果稳定。
- 多模态任务：结合视觉和文本的 VLM，同样适用。图 2 的 pipeline 直接套用，不需要为图像额外设计特征。
- 评估集设计：估值质量依赖验证集 (Dval) 的代表性。如果你没有独立的验证集，估值可能偏倚。论文假设 t=0（初始化时刻）做估值，相当于”从零开始看每个样本的边际贡献”，这个设定在微调初期最有效。
## 局限与未来方向论文自己也承认三点限制：
- 仅适用于微调阶段：预训练阶段的数据估值不适用，因为那时 unconstrained feature assumption 不成立——模型还在学习基础表征。
- 静态估值：没考虑训练过程中数据价值的动态变化。可能某个样本早期有用，后期就冗余了。扩展成阶段感知的数据选择，留给后续研究。
- 依赖验证集质量：Dval 如果跟训练集分布不一致，估值会偏。实践中要保证验证集能代表目标任务。
## 总结For-Value 的核心贡献是把数据估值从 “昂贵的二阶问题” 变成了 “廉价的一阶问题” 。理论基础是： 在预训练模型足够强大的前提下，最后一层的梯度足以捕捉数据影响 。工程实现上，用词汇裁剪和批处理把前向估值压到极致。
结果： 在影响力识别、错误标签检测、微调数据选择三项任务上，效果持平或超越梯度方法，速度快 5–6 倍 。对于任何需要从大规模数据里挑高价值样本的场景，这是一个简单、有效、能跑满 GPU 的实用方案。
