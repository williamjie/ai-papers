论文 : SkillJack: Persistent Skill Backdoors in Self-Evolving Agents链接 : https://arxiv.org/abs/2608.03509自进化 Agent（Self-Evolving Agents）正在从“无状态任务解决者”向“具备长期记忆与技能复用的智能体”演进。这种能力跃迁令人兴奋，但腾讯朱雀实验室的最新研究揭示了一个隐蔽且致命的风险：攻击者可以通过污染原始交互记录，让 Agent 自行将恶意行为编译为持久化的“技能”，从而绕过常规的安全检测。
### 为什么现有的防御体系失效了？
传统的 Agent 安全研究主要集中在记忆投毒（Memory Poisoning）或间接提示注入上。这些攻击通常依赖于 poisoned records 在后续任务中被检索并作为上下文（Context）使用。一旦我们删除了原始记录，或者加强了检索时的过滤，攻击往往就会失效。
然而，SkillJack 指出了一个新的攻击面： 经验到技能的转化管道（Experience-to-Skill Pipeline） 。
当 Agent 将历史交互提炼为可复用的技能时，它不仅仅是在存储数据，而是在进行“行为编译”。论文的核心洞察在于，这个编译过程本身就是一个天然的“漂白剂”。攻击者只需在经验层注入看似合法但包含恶意逻辑的记录，Agent 的自动化提取机制就会将其转化为结构化的技能。由于技能是独立存储且经过抽象处理的，它既脱离了原始上下文，又获得了更低的检测率。
### 核心方法：如何利用“功能框架”绕过检测？
SkillJack 的攻击成功依赖于一个关键设计： 变换鲁棒载荷（Transformation-Resilient Payloads） 。
如果直接注入包含明显恶意词汇的轨迹，提取器通常会将其过滤或标记为异常。因此，攻击者采用“功能框架”策略：
- 伪装意图：使用看似合法的业务术语（如“备份”、“归档”）来包装恶意动作（如数据外传、权限提升）。
- 利用抽象机制：Agent 在提取技能时，会压缩和抽象原始轨迹。这种抽象过程无意中抹去了原始记录中的敏感语境，只保留了核心的执行逻辑。
论文形式化了这一过程，指出攻击者只需影响经验层（Experience Layer），无需直接访问技能库。一旦管道接受了污染记录并提取出技能，系统自身就将对抗性影响转移到了一个独立存储的、更难以追踪的工件中。
### 实验结果：数据不会撒谎研究团队在两个代表性的自进化系统 SkillX 和 Anything2Skill (A2S) 上进行了评估，使用了包含 150 条轨迹的数据集。结果令人警醒：

此外，技能的持久性远超预期：
- 跨层提升：在 SkillX 中，植入的技能在攻击导向任务中的成功率为 56.2%；在 A2S 中高达 89.2%。
- 持久隔离：即使删除了原始的污染轨迹，80.0% 的攻击仍能通过已生成的技能触发。这说明传统的“清理内存”手段对技能库无效。
### 工程启示：如何构建防御？
这篇论文对 Agent 系统的工程落地提出了严峻挑战，也指明了防御方向：
-全生命周期溯源（Provenance-Aware Lifecycle）
不能假设对原始记录的安全检查能传递到衍生技能。必须建立从轨迹到技能的元数据关联。当删除或隔离某条源记录时，应自动触发对其衍生技能的审查或移除。
-行为级监控优于静态审查论文发现，仅靠提取时的 LLM 安全审查（Detection Rate ~10-40%）效果有限。相比之下，运行时基于行为签名的监控（Runtime Monitoring）在 SkillX 测试中实现了 0% 的触发率。但要注意，防御层之间可能存在干扰（Defense Coordination Hypothesis），上游过滤可能改变下游路由的行为分布，导致原本有效的规则失效。
-警惕元数据欺骗消融实验显示，LLM 裁判高度依赖技能的名称和描述等表面元数据。当仅展示代码内容时，检测率显著上升（SkillX 从 10% 升至 36.7%）。这意味着攻击者可以通过编写良性的技能文档来“洗白”恶意代码。防御系统需要更深层的代码语义分析，而非仅仅依赖自然语言描述。
### 局限与展望目前的研究基于 DeepSeek-v4-flash 单一模型，且成功标准主要基于路由层面的代理检测（Proxy Detectors），而非真实的外部服务执行。此外，防御实验样本量较小，属于探索性研究。
对于工程师而言，SkillJack 是一个明确的警告： 不要信任 Agent 自行生成的“知识” 。在引入自进化能力时，必须将技能库视为一个需要独立审计、隔离和溯源的高风险存储区，而不是简单的缓存。随着 Agent 自主能力的增强，攻击面正从“上下文”向“核心逻辑”渗透，防御体系也必须随之进化。
