# ⭐⭐⭐½ SKT：用验证合成数据让 Agent 学会调用技能

**日期**: 2026-08-04

---

论文 : SKT: Skill-Use Training at Scale via Verified Synthetic Data Generation链接 : https://arxiv.org/abs/2608.02287Agent 时代，光有“技能库”没用，模型得真会调用。这篇来自上海人工智能实验室的 SKT 论文，直接解决了“有技能不会用”的工程痛点。它不靠复杂的强化学习，而是通过一套严密的合成数据流水线，让模型在监督微调（Supervised Fine-Tuning, SFT）中真正掌握技能的识别、协调与执行。
### 为什么现有方案不够好？
目前社区已有超过 60 万个公开 Agent Skills，但大多数 LLM 面对这些技能时依然“手足无措”。
现有研究主要聚焦于技能的检索（如何找到它）、内化（把它塞进上下文或权重）或自我进化。然而， 拥有技能并不等于能使用技能 。模型需要理解何时调用、如何遵循约束、以及如何协调多个技能解决复杂任务。这是一个被严重低估的基础能力缺口。
### SKT 的核心直觉：验证即训练SKT 的核心 Insight 非常朴素但极具工程价值： 高质量的执行轨迹比原始指令更有价值，而质量必须通过严格的自动化验证来保证。
它构建了一个三阶段流水线：
- 技能策展：从公开库中筛选可执行、可客观检查的技能，并组合成单技能或多技能（最多 3 个）配置。
- 任务合成与验证：这是关键。生成的任务包必须通过规则验证（文件路径、评估器定义）、Agent 语义验证（指令清晰、无答案泄露），以及难度控制。如果强模型能轻易破解，任务会被打回重修。
- 轨迹收集与过滤：由强教师模型执行任务，仅保留那些成功且忠实使用每一个指定技能的轨迹。
⚠️ 关键设计 ：SKT 不仅要求结果正确，还通过 LLM 验证器检查“每个技能是否在指导动作前被咨询”、“是否影响了具体决策”。这确保了数据中包含了真正的“技能使用逻辑”，而非巧合的正确答案。
### 实验结果：提升显著且可迁移论文在 Qwen3.5-9B 和 Gemma 4 E4B-IT 上进行了全参数 SFT，并在多个基准上测试。数据非常硬核：
模型 Harness SkillsBench (Original → SKT) SkillEval (Original → SKT) Qwen3.5-9B OpenCode 5.80 → 15.79 (+9.99) 55.24 → 72.48 (+17.24) Qwen3.5-9B DeepAgents 4.94 → 13.62 (+8.68) 51.62 → 70.53 (+18.91) Gemma 4 E4B-IT OpenCode 7.08 → 10.28 (+3.20) 61.01 → 72.85 (+11.84)
几个值得注意的发现：
- 验证的重要性：如果跳过验证步骤，直接用原始合成数据微调，性能反而下降（SkillsBench 下降 1.9 分，AgentSkillOS 下降 19.5 分）。这证明了“脏数据”对技能学习的破坏性。
- 跨框架迁移：在 OpenCode 上训练的模型，在 DeepAgents 上评估也能获得显著增益（保留约 50%-58% 的收益）。这意味着学到的“技能使用逻辑”具有通用性，不完全绑定于特定的 Agent 框架。
- 混合训练更优：混合两个 Harness 的数据训练出的单一 Checkpoint，性能接近甚至略优于针对特定 Harness 训练的 Specialist 模型。这对工程部署极具吸引力——只需维护一个模型即可适配多种环境。
### 工程启示与局限对于正在构建 Agent 应用的工程师，SKT 提供了明确的指导：
- 不要只喂指令：要喂完整的、经过验证的执行轨迹（Trajectory）。
- 数据质量 > 数据数量：引入严格的自动化验证环节（规则+LLM）是提升微调效果的关键。
- 多技能协调需专门训练：实验显示，SKT 在双技能任务上提升最大（+16.77 分），说明模型在处理复杂工作流时最需要这种监督信号。
当然，该方法依赖强教师模型生成初始轨迹，且目前主要验证了代码和工具调用场景。但在 Agent 技能生态日益庞大的今天，SKT 提供了一条低成本、可规模化提升模型“动手能力”的可行路径。
