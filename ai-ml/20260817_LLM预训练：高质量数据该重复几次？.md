# ⭐⭐⭐⭐ LLM预训练：高质量数据该重复几次？

**日期**: 2026-08-17

---

论文 : Scaling Domain Data Repetition in LLM Pretraining链接 : https://arxiv.org/abs/2608.14071LLM 训练中，通用 Web 数据管够，但代码、数学等高质量领域数据稀缺。为了不让这些“精华”被海量垃圾数据稀释，我们通常会重复使用它们。但重复多少次最好？太多会过拟合，太少学不会。这篇来自清华和字节跳动 Seed 的论文，给出了一个反直觉且极具工程价值的结论。
### 痛点：固定 TPP 下的数据稀释随着模型参数规模 NN 增加，为了保持计算最优（Compute-Optimal），训练 Token 总量 DD 也必须按比例增加，即维持固定的 Tokens-per-Parameter (TPP) 比率。
这就导致了一个不对称问题：
- 通用数据：Web 文本几乎无限，可以轻松扩展。
- 领域数据：高质量代码、数学数据有限，难以同比例扩展。
如果领域数据的绝对量不变，其在训练混合中的占比就会随着模型变大而急剧下降。一旦低于某个临界阈值，模型甚至无法习得该领域的知识。因此， 重复（Repetition） 成了对抗稀释的唯一手段。
### 核心 Insight：TPP 固定时，大模型能容忍更多重复过去很多研究认为，模型越大越容易过拟合，所以应该减少数据重复。但这通常是在 固定总训练 Token 数 的前提下得出的结论。
本文指出，在实际 LLM 缩放中，我们更关心的是 固定 TPP 。在这个设定下，结论完全反转：
⚠️ 反直觉发现 ：在固定 TPP 的情况下，随着模型规模增大，领域数据的最优重复次数反而 轻微增加 。
这意味着，你在小代理模型（Proxy Model）上测试出的“不过拟合”的重复次数，直接套用到更大的目标模型上是安全的，甚至可能保守了。这为工程上的超参迁移提供了理论依据。
### 方法拆解：寻找最优重复次数的决定因素作者设计了严格的控制变量实验，考察四个高质量领域（Code, Math, Wiki, Medical），在固定 TPP 下，扫描不同的唯一数据比例 α\alpha 和重复次数 ee 。
他们发现，决定最优重复次数 e∗e^* 的因素主要有两个，且权重差异巨大：
-域的最终验证损失（强负相关）：
相关性系数高达 -0.944。
- 验证损失越低（模型学得越好、数据噪声越少），能承受的重复次数越多。
- 验证损失越高（数据难学或噪声大），稍微多重复几次就会过拟合。
-模型规模（弱正相关）：
相关性系数为 0.400。
- 符合前文所述的“固定 TPP 下，大模型可容忍更多重复”的趋势。
-唯一数据量（几乎无关）：
相关性系数仅为 0.018。
- 无论你手里有 1% 还是 5% 的唯一高质量数据，最优重复次数基本不变。这极大地简化了调参流程：你不需要为了预估重复次数而去凑特定比例的数据。
### 关键结果与对比影响因素 相关系数 (Pearson) 工程启示 域验证损失 -0.944 核心指标 。Loss 低的域（如 Math）可重复 ~5 次；Loss 高的域需减少重复。 模型规模 0.400 固定 TPP 下，大模型比小模型更“耐造”，可适度增加重复。 唯一数据量 0.018 忽略此项。在代理模型上测出的 e∗e^* 可直接迁移，无需匹配相同的数据比例。
此外，论文还对比了不同域对重复的敏感度：
- Math：相对鲁棒，重复 4 次以内性能下降很小，可部分替代新增的唯一数据。
- Wiki：非常敏感，重复超过 2 次后验证损失急剧上升，无法用重复替代新数据。
### 工程启示：如何配置你的训练食谱？
对于正在构建或微调 LLM 的工程师，这篇论文提供了一套低成本的调参策略：
-小模型代理测试：
不要直接在大模型上扫超参。用一个较小规模的模型（保持相同的 TPP），对目标领域数据进行重复次数扫描。
-以 Loss 为锚点：
观察代理模型在该领域的最终验证损失。如果 Loss 很低，大胆增加重复次数（如 Math 域可试到 5 次）；如果 Loss 较高或下降缓慢，保守一点（如 Wiki 域控制在 2 次以内）。
-忽略数据比例差异：
代理模型测试时，随意取一个代表性的唯一数据子集即可。最优重复次数对唯一数据的绝对量不敏感。
-注意学习率调度：
论文补充实验显示，学习率衰减越早，模型越容易过拟合（容忍的重复次数越少）。如果计划使用早期 Decay 的学习率策略，需相应降低重复次数。
### 局限与展望目前的研究主要聚焦于 单一领域 的重复。在实际预训练中，我们往往同时混合 Code、Math、Science 等多个高质量域。多个域之间的交互效应（Interaction Effects）尚未被充分研究。此外，论文基于线性回归的理论推导解释了现象，但 LLM 的非线性特性可能带来更复杂的动态，未来需要更精细的量化缩放法则。
总之，这是一篇将“数据重复”这一老话题讲出新深度的佳作。它纠正了以往对模型规模与过拟合关系的片面理解，并给出了可落地的调参指南。下次当你纠结代码数据该跑几个 Epoch 时，不妨先看看它的验证 Loss。
