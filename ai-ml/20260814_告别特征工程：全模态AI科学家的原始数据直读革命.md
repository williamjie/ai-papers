论文 : OmniScientist: An Omni-Modal Omni-Discipline AI Scientist链接 : https://arxiv.org/abs/2608.13558现在的 AI Agent 已经能写代码、跑实验，甚至生成论文初稿。但大多数系统有个致命缺陷：它们只看“总结好的数据”，不看“原始证据”。
OmniScientist 提出了一个反直觉的观点： 真正的科学发现，藏在那些被预处理丢弃的空间、时间和跨通道关系中。
## 痛点：为什么“喂给 Agent 特征”是死路？
现有的 AI 科学家系统（如之前的 AutoML 或科研 Agent）通常接收文本、标签或预计算的特征向量。
这种设计看似高效，实则 阉割了科学发现的源头 。
⚠️ 核心洞察 ：一个无序的特征向量会抹杀时间序列的顺序；一段文字摘要会丢失病理图像的局部形态。Agent 在研究开始前，就继承了人类预设的偏见，导致它无法发现异常，也无法提出新颖假设。
OmniScientist 认为，如果 Agent 不能直接“看”到原始数据（Raw Evidence），它就永远只是一个高级的数据分析工具，而不是科学家。
## 方法拆解：从“工作流覆盖”到“证据感知”
OmniScientist 的核心架构由一个**感知层（Perception Layer）**和三个自主代理组成： 构思（Ideation）、实验（Experiment）和撰写（Writeup） 。
### 1. 全模态感知层：不只是看图系统将科学证据分为四类家族，并直接处理原始文件：
- 感知类：图像、视频、光谱、音频、3D 结构。
- 符号类：公式、序列、知识图谱。
- 定量统计类：表格、分布曲线。
- 过程动态类：轨迹、模拟步骤。
设计直觉 ：Agent 优先提取原生数值特征（如 FFT 峰值），仅在空间结构关键时才渲染视觉图表。这种“按需感知”平衡了计算成本与信息完整性。
### 2. 确定性管道 + 代码强制检查这是工程落地的关键。LLM 容易幻觉，所以 OmniScientist 用代码锁死流程：
- 新颖性筛查：自动搜索文献，若发现已有研究，自动将“首次探索”降级为“未充分探索”。
- 严谨性检查（Rigour Check）：强制多重比较校正，防止 p-hacking。所有测试必须记录在案，包括失败的尝试。
- 反 HARKing：禁止在结果出来后倒推假设。所有声明必须追溯到执行记录中的具体数字和图表。
## 关键结果：原始数据直读的碾压性优势论文在 36 个真实数据集上进行了测试，涵盖物理、生命、工程等领域。
评估维度 OmniScientist (全感知) Blind Variant (仅预计算特征) 胜出率 综合论文得分 6.3 / 10 较低 - 多模态 grounding 显著提升 缺失 85% 科学意义 高 低 85% 头对头判断胜率 - - 85%反直觉发现 ：在地震学案例中，Agent 通过直接观察原始波形，发现 21.7% (163/750) 被标记为“噪声”的数据实际上是真实的信号爆发。如果只看预计算特征，这些发现根本不存在。
在材料科学中，通过直接读取表格中的成分分布，系统发现了随机 k-fold 交叉验证低估了外推误差（Leave-one-family-out RMSE 高出 3.1–7.0 倍 ）。
## 工程启示：Agent 开发的范式转移对于正在构建垂直领域 Agent 的工程师，这篇论文提供了三个重要指导：
- 不要过早抽象数据：如果你的 Agent 需要处理复杂决策，给它原始文件（PDF、CSV、Image），而不是清洗后的 JSON。让模型自己决定提取什么特征。
- 用代码做护栏，用 LLM 做推理：LLM 负责发散思维（提出假设），确定性代码负责收敛验证（检查统计显著性、数据泄露）。这种混合架构比纯 Prompt 工程更可靠。
- 跨学科复用核心引擎：OmniScientist 的核心管道不随领域变化。扩展新领域只需编写一个新的 Specification 文件，无需重写代码。这意味着你可以构建一个通用的“科研 Agent 底座”。
## 局限与展望虽然系统完成了 36 个案例的全流程，但主要依赖现有的 Foundation Model 能力。
- 计算成本：全模态感知和多次迭代调试带来高昂的 Token 消耗。
- 物理实验限制：目前仅限于可计算验证的实验，无法直接操控湿实验室设备（尽管架构上预留了接口）。
OmniScientist 证明了： 给 AI 科学家“眼睛”，它才能看到人类没看到的真相。

挑刺:
- 骨干模型未指明导致分数误导：博文 “关键结果” 表格中写 “综合论文得分 6.3 / 10”，但原文表 3 中 6.3 是 Sonnet 5 骨干的总体分，其他骨干（如 GPT‑5.6 为 5.6，Qwen3.5‑27B 为 5.1）差异明显。博文未注明具体骨干，易让读者误以为这是系统在所有配置下的通用分数。
- 盲变体分数缺失，仅用“较低”概括：原文图 7 给出了盲变体在各维度的具体分数（例如 MM‑grounding 约 2.3，OmniScientist 约 5.1），博文表格中 “Blind Variant” 列仅写 “较低”“缺失”，未给出任何数值，降低了对比的精确性。
- 遗漏关键检查条件：博文只提及了新颖性筛查、严谨性检查和反 HARKing，但原文表 14 列出了 20 余条代码强制条件（如 claim check 中的 traceability、guarded revision、forbidden claims 等），且实验阶段最频繁的拒绝原因是 “demotion”（非显著分析留在论文中）。这些工程细节的遗漏使读者无法全面理解系统的鲁棒性来源。
