# 用代码重构房间：从俯视图到可执行3D场景

**日期**: 2026-05-19

---

论文 : Code-as-Room: Generating 3D Rooms from Top-Down View Images via Agentic Code Synthesis链接 : https://arxiv.org/abs/2605.18451在室内设计、VR 开发和具身智能（Embodied AI）领域，手动搭建 3D 房间不仅耗时，还极度依赖专业建模技能。虽然大语言模型（LLM）在文本驱动的场景生成上表现不错，但文本无法精确描述空间布局；而现有的图像驱动 Agent 往往因为缺乏结构化约束，容易陷入死循环或生成结果不稳定。这篇论文提出的 Code-as-Room (CaR) 框架，通过将 3D 房间表示为可执行的 Blender 代码，并利用多阶段 Agent 流程，解决了从俯视图到完整 3D 场景的稳定生成问题。
### 痛点：为什么直接让 LLM 画图不行？
现有方案主要有两个致命缺陷：
- 文本描述的局限性：文本难以精确指定物体数量、精确位置和朝向，导致生成的 3D 房间与用户预期偏差大。
- Agent 的不稳定性：之前的工作（如 VIGA）尝试用代码生成 3D 场景，但在处理复杂的俯视图时，Agent 经常陷入无限循环，导致生成失败或空间细节丢失。
### 核心方法：结构化执行 HarnessCaR 的核心 Insight 是： 不要试图一次性生成整个场景，而是要将任务分解为“粗到细”（Coarse-to-Fine）的多阶段流水线，并通过跨阶段记忆（Cross-Stage Memory）保持上下文一致性。
整个流程分为五个阶段，由一个结构化的执行 Harness 编排：
- 图像结构化解析：首先从俯视图提取场景元素（主要家具、小配件、门窗墙壁），并构建场景图（Scene Graph），明确空间关系。
- 布局代码生成：生成主要家具的粗略布局代码。这里引入了视觉反馈循环（Vision-feedback Loop）：Agent 生成代码 -> 渲染成俯视图 -> VLM 作为 Critic 评估 -> 修正代码。这个过程最多迭代 5 次，直到布局合理。
- 对象级代码生成：基于固定的布局，为每个物体生成详细的几何形状、材质和纹理代码。对于复杂小物体，采用检索现有资产的方式补充。
- 室内装饰代码生成：最后添加灯光、渲染设置和后处理修正，确保场景光照自然且无几何错误。
关键技术直觉 ：
- 跨阶段记忆模块：这是解决 LLM “上下文遗忘”的关键。每个阶段的输出都被存储为类型化的记忆条目，下游阶段只读取相关的记忆视图，既保证了信息传递，又减少了 Prompt 噪声。
- 代码即场景：输出不是黑盒的网格数据，而是可编辑、可执行的 Blender Python 代码。这意味着生成的房间可以直接在 Blender 中打开和修改，极大地提升了工程实用性。
### 实验结果：结构化流程的威力论文构建了一个专门的基准测试，包含 41 个不同复杂度的房间场景，从视觉理解、空间推理到代码生成质量进行全面评估。

消融实验表明：
- 记忆模块至关重要：移除跨阶段记忆后，布局 IoU 从 73.2% 暴跌至 58.0%，证明记忆对于维持长流程中的空间一致性不可或缺。
- 反馈迭代次数需平衡：视觉反馈迭代 5 次效果最佳，增加到 10 次反而导致布局漂移（Layout IoU 下降），说明过度修正会引入噪声。
### 工程启示- Agent 设计范式：对于复杂的多步骤任务，简单的“生成-评估”循环不够，需要引入结构化记忆和分阶段执行。将大任务拆解为子任务，并明确每个阶段的数据输入输出，能显著提升稳定性。
- 代码作为中间表示：在 3D 内容生成中，使用代码（如 Blender Python API）作为中间表示，比直接生成网格或神经辐射场（NeRF）更具可解释性和可编辑性，适合工业级应用。
- 视觉反馈的价值：在布局生成中引入渲染后的视觉反馈，能有效纠正 LLM 的空间推理错误。但需注意迭代次数的控制，避免过拟合或漂移。
### 局限与展望目前 CaR 主要处理俯视图，对于任意视角的输入支持有限。此外，许多真实世界物体难以用程序化代码精确生成，仍需依赖资产检索。未来方向包括探索视频生成模型作为神经渲染器，以提升场景的视觉真实感。
