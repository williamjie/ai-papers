论文 : ASPIRE: Agentic /Skills Discovery for Robotics链接 : https://arxiv.org/abs/2607.00272现有的“代码即策略”（Code-as-Policy）框架虽然让机器人行为变得可解释，但调试起来依然像在黑盒里摸索。ASPIRE 的核心突破在于：它不只是生成代码，而是通过 细粒度多模态轨迹日志 和 进化搜索 ，构建了一个能自我诊断、修复并积累通用技能库的持续学习系统。这意味着机器人不再是每次任务都从零开始，而是像人类工程师一样，从过往失败中提取经验，实现能力的复利增长。
### 痛点：现有 Agent 为什么“智障”？
目前的机器人编程 Agent 面临两个致命瓶颈：
- 反馈太粗糙：大多数系统只给任务级成败（Success/Fail）。当抓取失败时，Agent 无法区分是视觉定位错了、路径规划撞了墙，还是末端执行器打滑。没有细粒度证据，调试就是盲目试错。
- 经验不累积：解决完一个任务，学到的修复策略就丢了。面对第 100 个任务时，Agent 依然像新手一样毫无经验。
### 方法拆解：从“黑盒执行”到“白盒调试”
ASPIRE 的设计直觉非常清晰： 把软件工程的 Debug 流程引入机器人控制 。它由三个核心组件构成闭环：
1. 细粒度执行引擎（Execution Engine）
这是 ASPIRE 的“眼睛”。传统方法只给最终结果，而 ASPIRE 为每个原语调用（感知、规划、控制）记录多模态轨迹。
- 关键 Insight：不要扔给 Agent 完整视频流，而是提供原子操作前后的关键帧 + 状态覆盖层 + API 返回值。
- 案例：在 BEHAVIOR-1K 任务中，机器人找不到收音机。引擎日志显示 navigate_to_pose 返回 PLANNING_ERROR。Agent 通过检查日志发现目标点落在桌子碰撞缓冲区内。于是它没有去改视觉提示词，而是编写了一个“多角度接近”（Multi-Angle Approach）的修复代码，尝试从侧面绕过障碍物。这种基于证据的定位比盲目重试高效得多。
2. 技能库（Skill Library）
这是 ASPIRE 的“大脑”。它将验证过的修复模式蒸馏为可复用的 In-Context Guidance。
- 存储内容：不是完整任务代码，而是原子级的启发式规则。例如：“当规划器因碰撞缓冲报错时，尝试旋转接近向量 45°/90°/180°”。
- 价值：未来遇到类似场景，Agent 直接检索该技能，无需重新推理。
3. 进化搜索（Evolutionary Search）
这是 ASPIRE 的“探索力”。单一轨迹调试容易陷入局部最优（反复修补同一个错误策略）。
- 机制：每轮生成 KK 个候选程序，基于上一轮表现最好的程序和剩余失败模式进行变异。这确保了 Agent 会尝试根本性的策略改变，而不仅是修修补补。
### 关键结果：数据不会撒谎ASPIRE 在多个基准测试中展现了压倒性优势，特别是在长尾和泛化场景下。
数据集 指标 ASPIRE 最强基线 (CaP-Agent0 / π\pi 0.5) 提升幅度 LIBERO-Pro Object Perturbation Success ~98% ~21% +77% Robosuite Bimanual Handover Success 92% 20% +72% BEHAVIOR-1K Long-horizon Task Success 88% 56% +32% LIBERO-Pro Long Zero-shot Transfer (Unseen) 31% 4% +27%⚠️ 反直觉发现 ：在零样本迁移到未见过的长 horizon 任务（LIBERO-Pro Long）时，ASPIRE 凭借从短任务积累的技能库，达到了 31% 的成功率。相比之下，依赖测试时推理和重试的基线方法仅停留在 4%。这证明了 结构化的技能复用远比临场推理更可靠 。
在 Sim-to-Real 实验中，使用仿真中发现的技能作为上下文引导，真机调试所需的 Token 数量大幅减少。例如“拉开抽屉”任务，无技能引导时完全失败（0/20），引入技能后成功率提升至 11/20，且总 Token 消耗从 334M 降至 81M。
### 工程启示：如何落地？
- 日志即资产：在构建机器人 Agent 时，不要只记录动作序列。必须结构化地记录每个原语调用的输入、输出、错误码和关键帧。这些是后续自动调试的燃料。
- 技能原子化：不要把“倒水”作为一个整体技能。应该拆解为“识别杯口”、“调整抓取角度”、“防洒漏控制”等原子修复策略。原子化程度越高，跨任务复用率越高。
- 引入多样性搜索：不要只让 LLM 基于上一次错误进行修改。保留一组候选程序进行并行演化，能有效避免陷入死胡同。
### 局限与展望ASPIRE 目前仍依赖强大的 Frontier LLM（Claude Opus 4.6）和昂贵的仿真/真机 rollout 成本。此外，技能库缺乏自动清理机制，随着规模扩大可能出现冗余或过时条目。未来的方向包括：更高效的记忆管理、对更小模型的适配，以及实现完全自主的真机闭环重置与验证。
