论文 : LocateAnything: Fast and High-Quality Vision-Language Grounding with Parallel Box Decoding链接 : https://arxiv.org/abs/2605.27365如果你正在把视觉语言模型（VLM）落地到机器人或GUI Agent上， 推理延迟 绝对是绕不开的痛点。现在的VLM大多把定位任务当成“填空题”——一个个生成坐标Token，这导致生成一个框要串行跑好几步。NVIDIA团队这篇 LocateAnything 直接掀了桌子：既然框的四个坐标是强耦合的几何整体，为什么要拆开卖？通过 并行框解码（Parallel Box Decoding, PBD） ，他们在保持甚至提升精度的同时，把推理吞吐量拉高了2.5倍。
### 痛点：串行生成的“结构性幻觉”与延迟现有主流方案（如 Qwen-VL, Rex-Omni）通常采用 Next-Token Prediction (NTP) 范式。
- 序列化损耗：无论是把坐标转成文本数字（“1”, “0”, “2”…）还是量化Token，本质上都是把2D几何结构强行拍扁成1D序列。
- 推理瓶颈：生成一个框需要串行解码多个Token，延迟随坐标位数线性增加。
- 结构不匹配：之前的多Token预测（MTP）尝试并行生成，但往往随机切分Token块。这会导致模型学到跨框边界的虚假相关性（比如把物体A的x坐标和物体B的y坐标拼在一起），产生严重的结构性幻觉。
### 核心洞察：把“框”当作原子单元LocateAnything 的核心直觉非常工程化： 对齐数据结构与计算单元 。
他们提出了 Parallel Box Decoding (PBD) ，在训练和推理时，不再预测单个坐标Token，而是将 整个边界框（Bounding Box）视为一个不可分割的原子块（Atomic Block） 。
- 训练策略：采用双格式联合训练。输入序列同时包含 NTP 格式（保持因果推理能力）和 MTP 格式（用于并行解码）。
- 注意力掩码设计：这是关键。在同一个Box块内部，Token之间使用双向注意力（Bidirectional Attention），让模型能同时看到所有坐标从而理解几何约束；而在不同Box块之间，严格保持因果注意力，防止未来信息泄露。
- 推理模式：提供三种按需模式：
Fast Mode (MTP)：全并行，吞吐量最高，适合端侧设备。
- Slow Mode (NTP)：全串行，精度最稳，适合离线标注。
- Hybrid Mode：默认推荐。平时用 Fast Mode 狂奔，一旦检测到格式错误或空间歧义（如置信度<0.7且Top-5概率分散），立即回退到 NTP 重解码当前块。这种“自动降级”机制完美平衡了速度与鲁棒性。
### 关键结果：又快又好在 NVIDIA H100 GPU 上的实测数据非常漂亮，LocateAnything-3B 模型不仅快，精度还碾压了同量级甚至更大参数的基线模型。
吞吐量对比（Boxes Per Second, BPS）：
- LocateAnything (Hybrid): 12.7 BPS- Rex-Omni (Quantized): 5.0 BPS- Qwen3-VL-4B/8B: ~1.0 - 1.1 BPS结论 ：比量化基线快 2.5倍 ，比文本生成基线快 10倍以上 。
精度对比（COCO & LVIS Mean F1）：
- LocAnything-3B: COCO 58.7, LVIS 62.3- Rex-Omni-3B: COCO 56.9, LVIS 58.5- Qwen3-VL-8B: COCO 50.7, LVIS 45.7在密集目标检测（Dense200）和GUI定位（ScreenSpot-Pro）上，LocateAnything 同样取得了 SOTA 或接近 SOTA 的成绩。特别是在 ScreenSpot-Pro 上，其平均 F1 达到 60.3 ，超过了参数量大得多的 GUI-Owl-32B (58.0)。
### 工程启示- 结构化输出优于文本流：对于检测、定位这类强几何约束任务，强行让 LLM 像写文章一样生成坐标是低效的。将几何单元（Box/Point）原子化，能显著降低解码步数并提升一致性。
- 混合解码是生产环境的最佳实践：纯并行解码在复杂场景下容易出错（如格式混乱），纯串行太慢。LocateAnything 的 Hybrid Mode 思路值得借鉴：默认走高速通道，异常时自动切换高精度通道。
- 数据规模决定上限：该模型基于 1.38亿 条查询、7.85亿 个标注框的大数据集训练。如果你也想微调类似模型，注意构建涵盖检测、GUI、OCR、布局的多任务混合数据集。
### 局限与展望虽然 Hybrid Mode 解决了大部分稳定性问题，但在极端密集且规则排列的场景（如货架商品）中，并行解码仍可能出现空间边界模糊。此外，该方法目前主要优化了 Bounding Box，对于更复杂的 Polygon 或 Keypoints 的并行解码适配还需要进一步探索。但对于大多数 Agent 落地场景，这已经是一个极具性价比的升级方案。
