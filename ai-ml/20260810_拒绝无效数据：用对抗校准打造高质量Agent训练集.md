# ⭐⭐ 拒绝无效数据：用对抗校准打造高质量 Agent 训练集

**日期**: 2026-08-10

---

论文 : CalibForge: Adversarial Solver Calibration for Scaling Learnable Terminal Tasks链接 : https://arxiv.org/abs/2608.06352现在的终端 Agent 训练面临一个尴尬的现实：数据量虽然大，但有效数据极少。
大多数合成任务要么太简单，模型看一眼就过；要么太难，根本无解。这两种情况对模型学习都毫无帮助。
CalibForge 提出了一种“对抗求解器校准”机制，核心逻辑很直接：只有当任务处于“强模型能解、弱模型难解”的区间时，才被视为高质量训练数据。
## 痛点：可执行不等于可学习现有的终端任务合成系统（如 TermiGen, CLI-Gym）主要解决的是“可行性”问题。
它们确保任务环境能跑通、验证脚本能执行。但这只是底线。
对于模型训练而言，我们真正需要的是“挑战性”。如果所有模型都能轻松通过，数据就是浪费；如果全都不行，数据就是噪音。
如何量化这种“恰到好处”的难度？CalibForge 的答案是：看求解器的行为分歧。
## 核心 Insight：利用求解器分歧定位“可学习区”
论文没有引入复杂的奖励模型或人工标注，而是巧妙地利用了现有 LLM 的能力差异作为标尺。
系统构建了一个“作者-求解器”的对抗循环：
-多求解器校准（Multi-Solver Calibration）：
让多个不同能力的模型同时尝试解题。
保留标准：必须出现分歧。即至少有一个模型通过，且至少有一个模型失败。
直觉：如果全过，说明太简单；如果全挂，说明有 Bug 或太难。只有分歧存在，才证明任务处于能力边界附近。
-对比求解器校准（Contrastive Solver Calibration）：
指定一个强模型和一个弱模型。
保留标准：强模型必须通过，弱模型必须失败。
直觉：这直接定义了“可学习区间”。弱模型的失败轨迹包含了有价值的错误模式，而强模型的成功轨迹提供了正确的解题路径。
⚠️ 反直觉发现 ：在初步验证通过的任务中，仅有 19% 天然满足对比校准条件。
这意味着，绝大多数“看似正常”的任务，其难度分布并不符合学习需求。
经过多轮对抗修订后，这一比例提升至 96%。这证明了“校准”不仅仅是过滤，更是主动重塑任务难度的过程。
## 关键结果：少而精的数据带来显著增益CalibForge 最终构建了 5,431 个经过严格校准的任务。虽然数量不多，但效果惊人。

在全量数据（5,431 tasks）上，CalibForge-30B-A3B 达到了 32.58% 的准确率，比最强基线高出 6.36 个百分点。
更令人印象深刻的是其泛化能力。在完全分布外（OOD）的软件工程基准测试中：
- SWE-bench Pro：提升 27.68 个百分点（从 16.64% 到 44.32%，基于 Qwen3.5-35B-A3B）。
- Doc2Repo：提升 30.04 个百分点（从 18.73% 到 48.77%，基于 Qwen3.5-35B-A3B）。
这表明，通过校准获得的“解题思维”具有极强的迁移性，不仅仅局限于终端命令操作。
## 工程启示：数据质量 > 数据数量这篇论文给工程实践提了个醒：盲目堆砌合成数据是低效的。
- 引入对抗机制：在生成训练数据时，不要只检查“能否运行”，要检查“谁难住了”。利用模型能力的差异性来筛选数据，成本极低但收益巨大。
- 关注轨迹深度而非长度：实验显示，CalibForge 生成的轨迹交互步数中位数仅为 21 步（低于 CLI-Gym 的 28 步），但其触发的“思考 Token”数量更高（5.3k vs 4.0k）。这说明高质量数据更侧重于推理深度，而非机械式的试错。
- 动态修订优于静态过滤：不要直接丢弃不符合难度的任务。像 CalibForge 那样，利用求解器的失败反馈去反向修改任务描述或环境，往往能挖掘出更具挑战性的变体。
## 局限与展望CalibForge 目前依赖于强大的作者模型（DeepSeek-V4-Pro）和多个求解器模型，计算成本较高。
此外，校准过程可能需要多达 50 轮迭代，对于大规模数据合成来说，延迟是一个实际问题。
未来，如何降低校准的计算开销，以及如何将这种“难度感知”机制扩展到非终端类的通用任务中，是值得探索的方向。
