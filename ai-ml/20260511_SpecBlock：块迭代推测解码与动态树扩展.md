# SpecBlock：块迭代推测解码与动态树扩展

**日期**: 2026-05-11

---

论文 : SpecBlock: Block-Iterative Speculative Decoding with Dynamic Tree Drafting链接 : https://arxiv.org/abs/2605.07243在大语言模型（LLM）推理中，推测解码（Speculative Decoding）已成为突破显存带宽瓶颈的关键技术。然而，现有的草案模型（Drafter）设计往往陷入“串行慢”与“并行乱”的两难境地。SpecBlock 这篇论文提出了一种**块迭代（Block-Iterative）**的架构，巧妙地在保持路径依赖性和降低计算成本之间找到了平衡点，实测在 Llama-3.1-8B 上相比 SOTA 基线 EAGLE-3 提升了 8–13% 的速度。
### 现有方案的痛点：串行 vs 并行要理解 SpecBlock 的价值，得先看看它想解决什么。目前的草案模型主要分两派：
- 自回归草案器（如 EAGLE-3）：像 EAGLE-3 这样，每一层深度都需要调用一次小模型。虽然路径依赖性强，接受长度（Accepted Length, τ\tau）很高（Llama-3.1-8B 上 τ=5.89\tau=5.895.89），但代价是草稿成本占比高达 31%。因为每次调用都要加载权重，串行调用累积的延迟非常可观。
- 并行草案器（如 Medusa, ParallelSpec）：一次性预测多个未来位置，草稿成本极低（仅 6–9%），但由于各位置独立预测，缺乏路径间的连贯性，导致很多路径在验证时被拒绝，接受长度被限制在 2–3 左右。
SpecBlock 的核心 Insight 是： 能不能既像并行那样一次出多个 token，又像自回归那样保持路径依赖？
### 方法拆解：块迭代与层级移位SpecBlock 的设计非常精妙，它引入了“块（Block）”的概念。每次前向传播生成 KK 个连续位置（Block Size K=4K=4 4 ），然后通过迭代扩展树。
#### 1. 层级移位（Layer-wise Shift）：解决依赖丢失在单个 Block 内部，虽然使用了因果注意力，但随着 Prefix 增长，注意力权重会被稀释，导致深层位置的准确性下降。
SpecBlock 引入了一个 层级移位机制 ：在每一层 Decoder 中，显式地将位置 k−1k-1 1 的隐藏状态（Hidden State）拼接并投影到位置 kk 。
h~t,k(ℓ)=Wshift[ht,k(ℓ),ht,k−1(ℓ)]\tilde{h}_{t,k}^{(\ell)} = W_{shift} [ h_{t,k}^{(\ell)}, h_{t,k-1}^{(\ell)} ] ~ t , k ( ℓ ) ​ = W s hi f t ​ [ h t , k ( ℓ ) ​ , h t , k − 1 ( ℓ ) ​ ]这相当于在单次前向中模拟了自回归的状态传递，既保留了计算并行性，又恢复了路径依赖性。消融实验显示，去掉这个机制，平均速度提升从 3.21×3.21\times 跌至 2.95×2.95\times ， τ\tau 从 4.41 跌至 4.02。
#### 2. 排名引导的树扩展（Rank-Guided Tree Expansion）
传统的树结构通常使用固定的 top-k 分支。SpecBlock 训练了一个共训练的 排名头（Rank Head） ，预测目标 Token 在草案分布中的排名桶（Bucket）。
- 自信的位置：排名靠前，分支少，节省验证预算。
- 不确定的位置：排名靠后，分支多，扩大恢复窗口。
这种动态分配让验证器（Verifier）的预算花在了刀刃上。
#### 3. 有效前缀课程学习（Valid-Prefix Curriculum Learning）
训练时，SpecBlock 不能像自回归模型那样使用 Ground-Truth 前缀进行 Teacher Forcing，因为 Block 内的位置是并行生成的。如果前一个 Token 预测错误，后续位置基于错误前缀的监督信号是无效的。
因此，SpecBlock 设计了 有效前缀掩码 ：一旦路径中某个位置预测错误，该路径后续位置的 Loss 直接被 Mask 掉，不再参与训练。这防止了错误前缀干扰模型学习。
#### 4. 成本感知的部署时适应（Cost-Aware Adaptation）
小模型容易受到部署时数据分布漂移的影响。SpecBlock 利用验证器产生的免费反馈信号（拒绝位置的目标分布），通过一个 Bandit 算法决定是否更新模型。
- 只更新 Head：如果内部表示尚可，只更新 LM Head 和 Rank Head，成本极低。
- 全量更新：仅当预期吞吐量增益超过更新成本时才进行。
实验显示，这种自适应机制在长流式查询中能进一步将速度提升扩展到 11–19%。

### 工程启示- 状态传递比注意力更鲁棒：在处理长序列依赖时，显式的状态移位（Shift）可能比依赖注意力权重的隐式传递更有效，尤其是在并行生成场景下。
- 动态树结构优于固定树：根据模型的不确定性动态调整分支宽度，比固定的 top-k 更能优化验证器的计算预算。
- 低成本在线适应是趋势：对于部署在小模型上的 Drafters，利用验证反馈进行 Head-only 的轻量级更新，是应对数据分布漂移的高性价比方案。
### 局限与展望SpecBlock 目前主要验证在 8B 和 32B 模型上，且依赖 NVIDIA A100 等高性能 GPU。对于更小的端侧设备，其额外的移位操作和 Rank Head 是否会造成不可接受的延迟，仍有待验证。此外，自适应机制在短查询（如 HumanEval 的 164 个 prompt）中因无法摊销更新成本而效果不明显，这在实时性要求极高的场景中可能需要更精细的策略。
