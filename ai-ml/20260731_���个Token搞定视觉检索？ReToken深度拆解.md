论文 : ReToken: One Token to Improve Vision-Language Models for Visual Retrieval链接 : https://arxiv.org/abs/2607.28627处理长视频或多图场景时，VLM（Vision-Language Model）往往面临“顾此失彼”的困境：全量加载显存爆炸，随机采样又容易漏掉关键帧。ReToken 提出了一种极简方案——仅增加一个可学习 Embedding Token，就能让冻结权重的 VLM 精准定位相关视觉信息。
这种“轻量级外挂”思路对工程落地极具吸引力，因为它不需要昂贵的全模型微调（Full Fine-Tuning），且能直接复用现有的 KV Cache 机制。
### 为什么现有的 Attention 检索不行？
直觉上，我们常认为 LLM 的 Attention Score 反映了 Token 的重要性，因此可以用它来做视觉检索。但 ReToken 的作者发现，在 VLM 中这个假设是错的。
⚠️ 反直觉发现 ：在 QAEgo4DTest-MC 数据集上，基于 Attention（Query-Key）分数的检索 Recall@1 仅为 5.1%。相比之下，利用 Value 空间进行匹配，Recall@1 可提升至 78.0%。
原因在于，Attention 权重主要服务于“聚合机制”，而非“内容表征”。Value 向量才真正承载了被传播的视觉语义内容。此外，直接使用问题文本的平均 Query 向量作为检索探针会引入大量噪声，导致检索信号微弱。
### ReToken 的核心设计直觉ReToken 的设计非常巧妙，它只做了两件事：
- 引入单一检索 Token：在问题末尾追加一个可学习的 Embedding XrX_r​。这个 Token 不生成文本，而是作为一个“探针”，专门用于计算与视觉特征的相似度。
- Value 空间匹配：不再使用 Query-Key 内积，而是计算 ReToken 投影后的向量与每一帧平均 Value 向量之间的余弦相似度。
这种设计避开了直接依赖问题文本带来的噪声干扰，通过数据驱动的方式让 XrX_r ​ 学会如何“抓取”关键视觉特征。更重要的是，它只在最后一层进行检索评分，并通过两阶段推理（先检索再生成）来解耦检索与生成任务。
### 实验效果：小而美ReToken 在多个基准测试中表现优异，尤其是在长上下文场景下。以下是基于 Qwen3VL-8B 的关键数据对比：
数据集 任务类型 基线性能 ReToken 性能 提升幅度 Visual Haystacks (C=50) 多图检索 58.6% 72.0% +13.4% Visual Haystacks (C=100) 多图检索 55.7% 67.7% +12.0% LVBench 长视频理解 (>1小时) 40.6% 48.6% +8.0%值得注意的是，ReToken 仅在多图 QA 数据集上进行训练，却能零样本（Zero-shot）迁移到长达数小时的视频理解任务中。在 LVBench 上，它比均匀采样策略高出 8 个百分点，证明了其检索能力的泛化性。
### 工程启示与落地建议对于工程师而言，ReToken 提供了几个实用的指导：
- KV Cache 复用：ReToken 采用“编码一次，多次检索”的策略。视频只需编码一次并存储 KV Cache，后续每个问题仅需极低的检索开销（约 0.5 秒/问）。这在多轮对话或 Agent 场景中能显著降低延迟。
- 轻量级微调：默认设置下，VLM 权重完全冻结，仅训练 ReToken 和一个投影矩阵。这意味着你可以在单张 H100 上快速适配特定领域的检索需求，无需担心灾难性遗忘。
- 两阶段推理：虽然引入了两次前向传播，但由于第二次传播仅针对少量关键帧，整体计算量远小于全量处理。在资源受限环境下，这是一种高性价比的精度换取方案。
### 局限与展望ReToken 并非万能药。论文指出，当关键信息分散在整个视频中（如总结类任务）时，其效果反而不如均匀采样（-5.2%）。它更擅长“实体识别”和“关键信息检索”这类局部证据明确的任务。
此外，虽然 ReToken 提升了检索精度，但它依赖于预填充的 KV Cache。对于超长视频，Cache 的管理和显存占用仍是工程挑战。不过，结合滑动窗口编码策略，这一问题在单卡 H100 上已得到初步解决。
总的来说，ReToken 用极低的成本证明了：有时候，你不需要更复杂的架构，只需要一个更聪明的“探针”。
