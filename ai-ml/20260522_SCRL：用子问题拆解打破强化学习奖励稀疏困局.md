论文 : From Reasoning Chains to Verifiable Subproblems: Curriculum Reinforcement Learning Enables Credit Assignment for LLM Reasoning链接 : https://arxiv.org/abs/2605.22074如果你正在用 GRPO 等基于可验证奖励的强化学习（RLVR）训练数学推理模型，你一定遇到过这个绝望场景：面对难题，模型生成的所有 rollout 全错，奖励信号归零，梯度消失，模型原地踏步。这篇来自清华大学的论文提出了 SCRL（Subproblem Curriculum Reinforcement Learning），通过“子问题拆解”和“细粒度信用分配”，让模型能从失败的尝试中汲取有效信号。这不仅是理论上的优雅，更是工程上解决 RLVR 效率瓶颈的一剂猛药。
### 为什么现有的 RLVR 在难题上失效？
RLVR 的核心优势在于无需人工标注奖励，只要答案对就给分。但在高难度推理任务（如 AIME、IMO）中，这种“全有或全无”的稀疏奖励机制暴露了致命缺陷：
- 梯度死区：当模型解出难题的概率极低时，同一组采样（Group）内的所有 rollout 往往全部失败。由于 GRPO 等算法在组内归一化优势函数（Advantage），全错意味着优势为 0，模型学不到任何东西。
- 信用分配粗糙：即使有一个接近正确的答案，传统的样本级信用分配也会将整个长序列的奖励平均分摊给每个 token。这意味着，一个只答对第一步就卡住的回答，和一个答对前三步才卡住的回答，获得的梯度信号几乎没有区别。
现有的改进方案要么依赖监督微调（SFT）模仿专家轨迹，导致分布偏移；要么提供固定提示（Hint），让模型只需补全后半段，削弱了其自主探索能力。SCRL 的核心洞察在于： 既然整题太难，那就把难题拆解成一系列可验证的子问题，让模型在解决子问题的过程中获得密集的、细粒度的反馈。
### SCRL 方法拆解：从“整题”到“子问题序列”
SCRL 的设计非常精巧，它并没有改变模型的底层架构，而是重构了训练数据的组织和奖励计算方式。
1. 构建可验证的子问题课程（Curriculum）
利用外部强模型（如 DeepSeek-V3.2）或参考解答，将一道难题拆解为 KK 个子问题 s(1),…,s(K)s^{(1)}, \dots, s^{(K)} , … , s ( K ) 。这些子问题满足三个关键特性：
- 难度递增：从易到难，最后一个子问题即为原题。
- 相互关联且独立：前一个子问题的结果是后一个的基础，但每个子问题本身是完整的、可独立验证的。
- 结构化输出：模型在一次 rollout 中按顺序回答所有子问题，并使用 <p1>...</p1> 等标签明确标记每个答案的边界。
2. 进度感知奖励修正（Progress-Aware Correction）
这是防止“奖励黑客”的关键。如果模型答对了第 3、4 个子问题，但第 2 个错了，SCRL 不会奖励第 3、4 步，而是将奖励截断为 [1, 1, 0, 0] 。只有连续解出的前缀才算数。这迫使模型必须扎实地走好每一步，而不是靠运气蒙对后面。
3. 子问题级归一化与细粒度信用分配传统 GRPO 计算整个样本的优势函数 AiA_i ​ 。SCRL 则在每个子问题位置 jj 独立计算优势函数 Ai(j)A_i^{(j)} ( j ) ​ ：
Ai(j)=Ri(j)−mean({Rk(j)})std({Rk(j)})A_i^{(j)} = \frac{R_i^{(j)} - \text{mean}(\{R_k^{(j)}\})}{\text{std}(\{R_k^{(j)}\})} ( j ) ​ = std ({ R k ( j ) ​ }) R i ( j ) ​ − mean ({ R k ( j ) ​ }) ​这意味着，模型在第 2 个子问题上表现得好坏，只与同组其他样本在第 2 个子问题上的表现对比，不受第 1 或第 3 步的影响。随后，这个优势值被精确分配给 <p2> 标签内的 token。这种 子问题级归一化 实现了真正的细粒度信用分配，无需额外的奖励模型。
4. 混合组训练（Mixed-Group Training）
为了避免模型只适应“子问题格式”而忽略原题，SCRL 采用混合训练：每组采样中，一半是子问题课程 rollout，另一半是原始问题 rollout。两者共享同一个优化目标，确保能力迁移。

### 工程启示与局限对工程师的建议：
- 无需额外奖励模型：SCRL 最大的工程价值在于它完全基于可验证的最终答案，不需要训练复杂的 Process Reward Model (PRM)，部署和维护成本极低。
- 适用于边界难题：如果你的模型在中等难度题目上已经收敛，但在竞赛级难题上停滞不前，引入 SCRL 的子问题拆解机制是提升上限的有效手段。
- 提示词工程的重要性：虽然子问题生成器不需要极强，但确保子问题的“可验证性”和“独立性”是关键。建议在预处理阶段加入简单的格式校验。
局限与展望：
SCRL 依赖于将难题拆解为线性序列的子问题。对于某些非线性的、需要多路径探索的复杂推理任务，这种线性课程可能无法完全覆盖所有关键推理路径。此外，子问题生成的离线开销虽然可控，但在大规模训练中仍需考虑计算成本。
总的来说，SCRL 提供了一种优雅的思路： 通过结构化拆解将稀疏奖励转化为密集信号 。它证明了在不引入额外监督信号的前提下，仅靠巧妙的奖励分配机制，就能显著提升 LLM 的硬推理能力。

挑刺:
- 进度感知修正举例错误：博文写道“如果模型答对了第 3、4 个子问题，但第 2 个错了，SCRL 不会奖励第 3、4 步，而是将奖励截断为 [1,1,0,0]”。
原文示例为 (1,1,0,1) 修正为 (1,1,0,0)（见 §3.2.1）。博文的假设情况（第 2 错、第 3 对）对应的原始向量应为 (1,0,1,1)，按规则应截断为 (1,0,0,0)，而非 [1,1,0,0]。该错误可能使读者对修正逻辑产生混淆。
- 遗漏对外部 LLM 依赖这一关键约束：博文在“局限与展望”中只提到“子问题生成的离线开销可控”，未强调原文明确指出的“subproblem construction relies on an external LLM, which introduces additional preprocessing cost”（§G）。实际工程中，外部生成器的质量、成本和可复现性会直接影响 SCRL 的落地难度，这是比“线性课程”更本质的局限。
- 子问题生成过程中“参考解”的角色描述不准确：博文说“利用外部强模型（如 DeepSeek-V3.2）或参考解答，将一道难题拆解为 K 个子问题”。
原文明确说明“Given a reference solution, an external LLM derives K verifiable subproblems from the reasoning chain”（§3.2），参考解是输入给 LLM 的素材，而非替代 LLM 的生成方式。博文将“或参考解答”并列可能让人误解为可以直接用参考解答作为子问题，忽略了 LLM 是核心生成器这一条件。
