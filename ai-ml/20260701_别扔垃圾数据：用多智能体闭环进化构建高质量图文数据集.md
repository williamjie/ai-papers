# ⭐⭐⭐⭐ 别扔垃圾数据：用多智能体闭环进化构建高质量图文数据集

**日期**: 2026-07-01

论文 : DataEvolver: Self-Evolving Multi-Agent Data Construction for Text-Rich Image Generation链接 : https://arxiv.org/abs/2606.31537做文本丰富图像生成（Text-Rich Image Generation）的同学都知道，数据质量是命门。
现有的主流做法太粗暴：爬取、过滤、冻结。被拒绝的样本直接进垃圾桶，哪怕它们包含了 OCR 错误、语义错位等极具价值的失败信号。
DataEvolver 这篇论文的核心洞察非常犀利： 不要把构建过程看作一次性清洗，而要看作一个反馈驱动的策略进化系统。
它提出了一套自进化的多智能体框架，把“垃圾数据”变成了指导下一轮采集的“导航图”。
### 痛点：静态流水线的死胡同传统的数据流水线（Crawl–Filter–Freeze）有个致命缺陷： 缺乏记忆与反思 。
第一轮过滤掉的样本，往往揭示了检索查询不可靠、语义覆盖不足或特定字体渲染失败等问题。
但在静态管线中，这些信息随着样本被丢弃而消失。第二轮采集时，系统会重复同样的错误，陷入低效循环。
### 方法拆解：四个 Agent 的闭环进化DataEvolver 将数据构建重构为一个迭代策略优化过程，由四个智能体组成闭环：
- Retriever（检索者）：根据当前策略生成结构化查询模板，从外部源获取候选图像。
- Verifier（验证者）：这是固定的“裁判”。它评估图像质量、OCR 准确率和语义一致性，产出通过集和详细的拒绝原因统计。
- Critic（批评家）：这是核心创新点。它不只记录分数，而是将本轮的失败模式（如大量重复、特定布局 OCR 失败）总结为自然语言形式的“语义反馈”。
- Generator（生成者）：针对覆盖不足的长尾区域，利用 Critic 的反馈进行定向合成补全。
关键直觉 ：Critic 将数值统计转化为可执行的策略更新指令。例如，如果某轮因重复率高被拒，Critic 会指示下一轮增加查询多样性；如果特定字体识别率低，则调整生成提示词。
### 实验结果：碾压式提升在同等数据预算下，DataEvolver 构建的数据集显著优于静态基线（AnyWord, MARIO）。
以下是 PixArt-α 模型在 0.75M 数据规模下的核心指标对比：
基准测试 方法 OCR-F1 (↑) 相对最强基线提升 TextScenesHQ AnyWord 0.63 - MARIO 4.56 - DataEvolver 8.45 +85.3% LongTextBench AnyWord 0.54 - MARIO 6.71 - DataEvolver 9.08 +35.3%⚠️ 反直觉发现 ：移除 Critic 模块会导致性能断崖式下跌。
在 0.1M 规模下，去掉 Critic 后 TextScenesHQ 的 F1 从 1.78 降至 1.01。这证明单纯的质量过滤不够，必须将失败模式转化为策略反馈才能避免重复犯错。
此外，该框架的优势可迁移至 Show-o2 模型，证明其价值在于数据构建本身，而非特定下游模型。
### 工程启示：如何落地？
- 重视“负样本”价值：在微调（SFT）或预训练数据清洗中，不要只保留 Pass 的数据。记录 Fail 的原因分布，定期分析这些模式以优化采集策略。
- 引入 LLM 作为策略层：利用大语言模型（如 Qwen3.5-4B）作为 Critic，将结构化的错误日志转化为自然语言的优化建议，比硬编码规则更灵活。
- 闭环迭代优于单次清洗：建立“采集-验证-反思-再采集”的循环机制。即使每次只改进一点点，累积效应也能显著提升长尾场景的覆盖率。
### 局限与展望该方法依赖 Verifier 的可靠性，如果 OCR 或语义评分本身有噪声，可能会误导 Critic 产生错误的策略更新。
此外，目前主要聚焦于文本丰富图像生成，未来可拓展至更广泛的多模态数据构建场景。
对于工程师而言，DataEvolver 提供了一个清晰的范式： 数据构建不是静态的预处理，而是一个动态的、可进化的系统工程。
