# 终结2bit量化崩溃：KronQ引入梯度协方差

**日期**: 2026-07-13

---

论文 : KronQ: LLM Quantization via Kronecker-Factored Hessian链接 : https://arxiv.org/abs/2607.07964当我们将大模型压缩到 2-bit 时，GPTQ 等主流方案往往会彻底崩溃。这篇论文不仅修复了这个问题，还揭示了现有量化方法长期忽视的一个关键维度：输出侧的梯度信息。
### 痛点：被遗忘的输出侧敏感度目前的后训练量化（Post-Training Quantization, PTQ）主流方案，如 GPTQ 和 GPTAQ，核心逻辑都基于一个假设：所有输出通道对重建误差的贡献是均等的。
它们仅利用输入激活的协方差矩阵 HXH_X ​ 作为 Hessian 的代理。这在数学上等同于假设输出侧梯度协方差 HGH_G ​ 为单位矩阵。
直觉偏差 ：这种假设在低比特量化下极其危险。论文 Figure 1(a) 显示，LLaMA-2 中 Q、K、V 投影的输出通道梯度幅度差异高达数个数量级。忽略这种异构性，直接导致极端离群值无法被有效抑制，最终引发量化发散。
### 核心 Insight：双向非相干处理KronQ 的核心突破在于引入了 Kronecker 分解近似（K-FAC），将 Hessian 分解为 H≈HX⊗HGH \approx H_X \otimes H_G H X ​ ⊗ H G ​ 。它没有直接修改昂贵的求解器，而是巧妙地利用 HGH_G ​ 做了两件事：
-双向非相干处理（Bidirectional Incoherence Processing）
传统方法仅对输入维度进行旋转以分散权重能量。KronQ 创新性地引入输出侧缩放矩阵 SGS_G​，基于梯度协方差对角线元素对权重行进行重缩放。
这极大地降低了权重在输入和输出两个方向上的变异系数（CV）。论文 Figure 2(b) 数据显示，双向处理后，LLaMA-2 的 CVoutCV_{out}​ 从 0.51 降至 0.34，使得量化误差分布更加均匀。
-混合精度分配的新标尺在 Transformer 中，Q、K、V 共享相同的输入激活，导致基于 HXH_X​ 的敏感度评分完全相同。KronQ 提出使用联合迹 tr(HG)⋅tr(HX)tr(H_G) \cdot tr(H_X)​)⋅tr(HX​) 作为敏感度指标。由于 Q/K/V 接收不同的下游梯度，HGH_G​ 成功打破了这种“退化”，实现了更精细的比特分配。
### 关键结果：2-bit 量化的救星在极端压缩场景下，KronQ 的表现具有压倒性优势。以下是 LLaMA-3-70B 在 WikiText-2 上的困惑度（PPL）对比：
模型 精度 GPTQ GPTAQ KronQ LLaMA-3-70B W3 27.49 399.46 4.41 LLaMA-3-70B W2 >2000 (发散) NaN (发散) 7.93在 LLaMA-2-7B 的 2-bit Group Quantization (g=128) 测试中，GPTQ 的 PPL 飙升至 274.00，而 KronQ 仅录得 7.61。
此外，在更难的推理基准 LiveCodeBench 上，KronQ 在 DeepSeek-R1-Distill-Llama-8B (W4) 上的准确率从 GPTAQ 的 16.3% 提升至 37.3% ，几乎翻倍。
### 工程启示：低成本的高收益对于工程师而言，KronQ 的最大吸引力在于其 零推理开销 。
虽然校准阶段需要一次反向传播来计算 HGH_G ​ ，并增加约 8-11 秒/层的预处理时间，但在实际的列式 OBS 更新中， HGH_G ​ 会在代数上被消去。这意味着：
- 无需修改推理内核：最终部署的模型结构与 GPTQ 完全兼容。
- 内存友好：HGH_G​ 仅在预处理时占用额外显存，量化完成后即可释放，峰值内存仅比 GPTAQ 略高。
### 局限与展望尽管效果显著，KronQ 仍依赖校准数据集的质量。如果校准数据无法覆盖模型的真实分布， HGH_G ​ 的估计将产生偏差。此外，目前主要验证于 LLaMA 系列，在其他架构（如 MoE）上的泛化性仍需社区进一步验证。
总体而言，如果你正在尝试部署 2-bit 或 3-bit 的大参数模型，KronQ 是目前解决量化崩溃最优雅的数学解法之一。
