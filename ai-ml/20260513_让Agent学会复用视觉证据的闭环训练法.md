# 让Agent学会复用视觉证据的闭环训练法

**日期**: 2026-05-13

---

论文 : Towards On-Policy Data Evolution for Visual-Native Multimodal Deep Search Agents链接 : https://arxiv.org/abs/2605.10832多模态大模型（MLLM）正在从“看图说话”走向“深度搜索”。但在构建具备工具调用能力的多模态 Agent 时，我们往往忽略了两个致命缺陷：一是工具产生的中间图片被视为“一次性消耗品”，无法被后续步骤复用；二是训练数据依靠静态配方生成，无法跟随模型能力的提升而进化。这篇论文针对这两个痛点，提出了 Visual-Native Agent Harness 和 On-policy Data Evolution (ODE) ，在 Qwen3-VL 上跑出了超越 Gemini-2.5 Pro 的成绩。
## 为什么现有的 Agent 架构不够用？
在当前的多模态深度搜索流程中，模型需要连续使用搜索、浏览、图像变换等工具。然而，现有系统通常将视觉推理绑定在原始任务图片上。当模型通过 zoom_in 或 visual_search 获得一张新的局部图或搜索结果图时，这张图往往只能作为当前的观察（Observation），而不能作为下一个工具的输入参数。
这种设计导致视觉证据无法像文本证据那样在轨迹中累积和传递。模型很难利用“上一步搜到的图”去“再放大看细节”，更别提利用它去进行二次搜索了。这正是传统 Agent 在处理复杂视觉推理任务时的主要瓶颈。
## 核心拆解：图像银行与闭环进化论文的核心贡献在于从 交互空间（Workspace） 和 数据构建（Data Construction） 两个维度进行了协同设计。
### 1. Visual-Native Agent Harness：让图片成为“一等公民”
这是方法的基础设施层。论文引入了一种 Image Bank Reference Protocol（图像银行引用协议） 。
- 核心机制：系统维护一个全局的图像银行。无论是初始任务图，还是任何工具（如 Web Search, Zoom In, Rotation）返回的图片，都会被注册为可寻址的引用，格式为 <image:N>。
- 设计直觉：后续的任意工具调用都可以直接消费这些引用。例如，模型可以先对 <image:0> 执行 zoom_in 得到 <image:1>，然后对 <image:1> 执行 visual_search 得到 <image:2>。
- 价值：这将多模态搜索从“单图交互”变成了“链式视觉工作流”，使得中间视觉证据可以在不同工具间流转和复用。
### 2. On-policy Data Evolution (ODE)：像调参一样调数据这是方法论的创新层。传统的合成数据（Synthetic Data）通常是一次性生成的，而 ODE 将数据构建视为一个 闭环优化过程 。
- Forward Curation（正向构建）：通过种子提议、网页探索、图谱组织和任务策展四个阶段生成候选任务。
- Backward Optimization（反向优化）：这是 ODE 的灵魂。
Rollout：让当前的策略模型（Policy Model）在 Harness 中执行这些任务。
- Trace Analysis：使用 Rubric（评分标准）分析轨迹。对于 监督微调（Supervised Fine-Tuning, SFT），关注轨迹是否具备高质量的教学示范意义（如工具使用质量、步骤合理性）；对于 强化学习（Reinforcement Learning, RL），关注任务是否处于当前策略的“学习前沿”（难度匹配、学习效用）。
- Configuration Update：根据评分反馈，动态调整下一轮数据生成的配置（如增加难例比例、调整探索广度）。
这种机制确保了生成的数据始终针对模型当前的能力短板，避免了“数据过易”或“难度错配”的问题。
## 关键结果：不仅仅是刷榜在 8 个多模态深度搜索基准测试中，ODE 展现了显著的提升效果：
- Qwen3-VL-8B：平均分从 24.9% 提升至 39.0%。
- Qwen3-VL-30B：平均分从 30.6% 提升至 41.5%。
- 对比 SOTA：在标准的 Agent Workflow 设置下，ODE 训练的 8B 模型（39.0%）超越了 Gemini-2.5 Pro（37.9%）。
消融实验揭示了两个关键洞察：
- 图像复用至关重要：在 HLE-VL 和 MMSearch+ 等需要迭代视觉细化的任务上，启用图像银行引用协议带来了最大的性能增益（如 HLE-VL 提升 +2.9%）。
- 进化优于静态合成：与使用固定配方生成的静态数据相比，ODE 生成的 SFT 数据包含更多中间视觉证据和工具链多样性；生成的 RL 数据更能精准匹配策略的学习前沿，带来更稳定的性能提升。
## 工程启示- 重构 Agent 的状态管理：在构建多模态 Agent 时，不要将工具输出视为瞬态数据。建立全局的“视觉状态池”，允许后续步骤引用历史图像，能显著提升复杂推理能力。
- 数据生成需具备“自我感知”能力：静态的数据集很快会过时。引入基于 Rollout 反馈的数据进化机制，让数据生成器根据模型的实时表现动态调整难度和内容分布，是提升 Agent 训练效率的关键。
- SFT 与 RL 的数据侧重不同：SFT 数据应追求“示范质量”（如何正确使用工具），而 RL 数据应追求“难度校准”（挑战模型当前边界）。ODE 通过不同的 Rubric 分别优化这两者，值得借鉴。
## 局限与展望尽管 ODE 效果显著，但其依赖大量的 Rollout 评估来计算 Rubric 分数，这带来了较高的计算开销。此外，当前的 Rubric 设计主要依赖 LLM Judge，其一致性和准确性仍有优化空间。未来，如何降低数据进化的成本，以及探索更自动化的 Rubric 学习机制，将是这一方向的重要演进路径。
