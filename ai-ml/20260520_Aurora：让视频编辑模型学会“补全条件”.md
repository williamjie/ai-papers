# Aurora：让视频编辑模型学会“补全条件”

**日期**: 2026-05-20

---

论文 : Aurora: Unified Video Editing with a Tool-Using Agent链接 : https://arxiv.org/abs/2605.18748现在的统一视频编辑模型（Unified Video Editing Models）越来越强，能同时处理文本、源视频和参考图。但工程落地时有个尴尬： 模型假设用户给出的指令是“完美”的 。如果你只说“把背景换成安迪的房间”，而不提供《玩具总动员》的参考图，模型只能瞎猜；如果你说“去掉那个路人”，却不给掩码（Mask），模型可能连路人在哪都找不到。
Aurora 这篇论文的核心洞察非常务实： 视频编辑的瓶颈不在生成模型，而在“条件构建”（Condition Construction） 。与其让扩散模型去理解模糊的自然语言，不如在前面加一个带工具的 VLM Agent，把模糊指令翻译成模型能听懂的完整条件包。
### 痛点：统一模型的“输入幻觉”
现有的 UniVideo、Kiwi-Edit 等模型，虽然权重统一，但要求用户输入结构化条件：
- 文本指令：必须精准。
- 参考图像：指定视觉特征（如特定的品牌 Logo、艺术风格）。
- 空间掩码：指定编辑区域。
现实中的用户请求往往是**欠规范（Underspecified）**的。
- 视觉欠规范：提到“Burberry 格纹围巾”，但没给图。
- 文本欠规范：说“把蓝色物品换成更快的车”，没明确具体车型。
Aurora 认为，与其让扩散模型在噪声中猜测这些缺失信息，不如在生成前，由一个 Agent 把缺失的条件“补全”。
### 方法拆解：Agent 是“翻译官”，DiT 是“执行者”
Aurora 的架构分为两部分，职责分离得非常干净：
#### 1. 工具增强型 VLM Agent（规划层）
基于 Qwen3-VL-8B-Instruct + LoRA 微调。它不生成视频，只生成一个 四字段编辑计划（Edit Plan） ：
- y' (Rewritten Instruction)：重写后的标准指令。
- c (Task Label)：任务类型（替换、移除等）。
- q (Image Search Query)：如果需要参考图，生成搜索关键词。
- m (Mask Phrase)：如果需要掩码，生成定位短语。
关键设计直觉 ：
- 解耦条件构建与生成：Agent 负责“想清楚要什么”，DiT 负责“画出来”。
- 工具调用：Agent 触发 Serper API 搜索参考图，或调用 GroundingDINO + SAM 生成掩码。这些工具的输出被转化为标准的参考图像格式，统一喂给下游模型。
- 训练策略：先用监督微调（SFT）教 Agent 输出 JSON 计划，再用 DPO（直接偏好优化）处理边界情况（比如：源视频里已经有实体了，还去搜图就是错的；风格迁移不需要搜图等）。
#### 2. 统一视频扩散 Transformer（执行层）
基于 Wan2.2-TI2V-5B 改造。它接收 Agent 打包好的“统一条件元组” (y′,Vsrc,R+)(y', V_{src}, R^+) , V sr c ​ , R + ) 。
- 多模态上下文编码器：冻结的 Qwen3.5-4B 将文本、源帧、参考图编码为 Cross-Attention Token。
- 零步长调制（Zero-timestep Modulation）：这是一个巧妙的技巧。在 DiT 中，噪声 Token 随时间步变化，但源视频和参考图的 Token 保持固定（调制因子设为 0）。这确保了参考信息的稳定性，避免在去噪过程中丢失参考特征。
### 关键结果：Agent 带来的巨大提升论文构建了 AgentEdit-Bench ，专门测试欠规范指令下的编辑能力。结果非常有说服力：

- 最受益任务：IP 替换和 IP 添加。因为这两类任务极度依赖参考图，Agent 的搜图能力直接解决了“没图不能画”的问题。
- Agent 的可迁移性：论文还测试了将 Aurora Agent 搭配其他模型（UniVideo, Kiwi-Edit）。在 EditVerse-Bench 上，UniVideo 加上 Agent 后从 6.12 提升到 6.48。这说明 Agent 的价值是通用的，它可以作为现有编辑模型的“外挂大脑”。
### 工程启示- “补全”比“理解”更重要：对于多模态生成任务，前端加一个负责补全缺失条件的 Agent，比单纯增大生成模型参数更高效。
- 工具链标准化：Aurora 将掩码生成、图片搜索都转化为“参考图像”这一统一格式输入给 DiT。这种输入标准化极大降低了下游模型的复杂度（不需要专门处理 Mask 分支）。
- DPO 在 Agent 规划中的价值：SFT 只能教 Agent 输出格式，DPO 才能教 Agent 判断“什么时候不该搜图”、“什么时候不需要掩码”。这种偏好对齐对减少 Agent 的幻觉调用至关重要。
### 局限与展望- 动态物体插入困难：目前的 5B 模型在处理大幅度运动的物体插入时仍显吃力，这受限于骨干网络的运动建模能力。
- 离线对齐：目前 Agent 仅使用离线 DPO，未来可能结合在线 RL（如 GRPO），根据最终视频质量反馈来优化 Agent 的规划策略。
Aurora 展示了一个清晰的工程路径： 不要指望一个模型搞定所有事，用 Agent 把脏活累活（找图、定位、重写指令）干好，让生成模型专心画画。
