# ⭐⭐⭐ 告别静态基准：EvoBrowseComp 自动合成新鲜考题

**日期**: 2026-06-12

---

论文 : EvoBrowseComp: Benchmarking Search Agents on Evolving Knowledge链接 : https://arxiv.org/abs/2606.13120现在的搜索 Agent 评测有个致命伤：题目太旧，模型靠“死记硬背”就能拿高分。
当基准测试（Benchmark）变成公开数据集，大语言模型（LLM）在预训练阶段就会把这些答案“吞”下去。这就导致我们在评测 BrowseComp 等静态数据集时，看到的往往不是模型的检索能力，而是它的记忆力。
腾讯微信 AI 团队发布的 EvoBrowseComp 试图解决这个问题：它不依赖人工标注，而是用一套自动化框架，从实时互联网中挖掘新鲜知识，动态生成高难度考题。
这对工程界的意义在于，我们终于有了一个能持续进化、防止数据泄露的“压力测试场”。
### 为什么静态基准会失效？
传统评测如 BrowseComp 或 GAIA，其题目和答案在发布那一刻就固定了。随着模型预训练语料的不断扩张，这些静态知识不可避免地会进入模型的参数中。
Anthropic 甚至明确指出，BrowseComp 的答案已经泄露到公共数据中，导致该基准被污染。模型可以通过参数记忆（Parametric Memorization）直接回忆答案，完全绕过真正的网页浏览和多跳推理。
我们需要一种机制，让题目始终跑在模型预训练截止时间之后，或者至少包含大量未被广泛收录的新鲜事实。
### 核心设计：三 Agent 协作合成EvoBrowseComp 的核心创新在于其全自动的数据合成流水线。它没有使用昂贵的人工标注，而是设计了三个协同工作的 Agent，形成一个闭环反馈系统。
-QA 合成 Agent（生产者）
它是执行者。从种子实体出发，通过搜索和访问网页工具，收集实时信息并构建候选问答对。关键在于，它被要求优先寻找“新鲜知识”（即特定时间点之后出现的信息）。
-信息过滤 Agent（质检员）
这是防止作弊的关键。它对收集到的证据进行两重筛选：
可信度：通过多源交叉验证，剔除谣言或不可靠来源。
- 流行度：如果某个非新鲜知识过于热门（比如“2008年北京奥运会”），模型很可能已经记住它，这类知识会被丢弃，以防止模型走捷径。
-高层引导 Agent（架构师）
这是最巧妙的部分。它将问题结构化为一个推理图（Reasoning Graph）。
使用投影、交集、补集等逻辑操作定义节点关系。
- 检测逻辑冗余和捷径：如果图中存在孤立节点，或者存在绕过复杂路径直接到达答案的“结构性捷径”，它会向合成 Agent 发出指令，要求增加复杂度或消除捷径。
这种设计确保了生成的题目不仅包含新鲜知识，而且在逻辑结构上足够复杂，迫使模型必须进行真正的多跳推理。
### 实验结果：顶尖模型也翻车EvoBrowseComp 包含了 400 个英文和 400 个中文问题。实验结果显示，即使是最强的模型，在这个基准上也表现不佳。

### 工程启示与局限对于构建搜索 Agent 的工程师来说，EvoBrowseComp 提供了两个重要信号：
- 推理效率至关重要：实验发现，DeepSeek-V4-Flash 在最大推理设置下，有超过 75% 的案例超过了工具调用次数限制（Exceed Ratio）。这说明当前模型在复杂检索任务中，往往陷入“过度思考”或无效循环。优化 Agent 的停止策略和上下文管理比单纯堆砌算力更关键。
- 自动化评测是趋势：人工维护基准的成本太高且容易过时。EvoBrowseComp 展示的三 Agent 框架可以复用到其他领域，用于自动生成特定领域的测试用例。
不过，该方法也有局限。高度依赖实时网页检索意味着数据生成的稳定性受网络环境影响较大。此外，虽然过滤了热门知识，但对于某些极度垂直或小众的新兴领域，可能仍难以找到足够的种子实体来构建复杂的推理图。
总体而言，EvoBrowseComp 为搜索 Agent 的评测树立了一个新的标杆：不仅要考得难，还要考得“新”。
