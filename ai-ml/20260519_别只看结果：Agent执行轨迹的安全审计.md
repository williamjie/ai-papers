# 别只看结果：Agent 执行轨迹的安全审计

**日期**: 2026-05-19

---

论文 : Auditing Agent Harness Safety链接 : https://arxiv.org/abs/2605.14271现在的 LLM Agent 早就不是单兵作战了，它们运行在复杂的执行框架（Harness）里，调度工具、分配资源、在多智能体间传递消息。但这里有个巨大的盲区：大多数安全评测只看最终输出（Output-level），只要结果对了，过程里是否访问了未授权资源、是否泄露了隐私，统统被忽略。这篇论文直接点破了这个痛点： 结果正确不等于过程安全 。
### 为什么现有的评测不够用？
想象一下，一个金融 Agent 最终生成了正确的报表，但在过程中偷偷读取了隔壁部门的薪资文件，或者把客户隐私发给了错误的子 Agent。传统的评测标尺会判定它“成功”，但在工程落地中，这已经是严重的安全事故。
现有基准（如 AgentHarm, OS-Harm）要么环境太简化，要么只关注单智能体，完全忽略了多智能体协作中复杂的权限边界和信息流控制。这篇论文提出的 HarnessAudit 框架，核心洞察就是： 安全审计的单位应该是“执行轨迹”（Execution Trajectory），而不是“最终响应” 。
### 方法拆解：三层安全审计体系HarnessAudit 的设计非常工程化，它不依赖 Agent 的自我报告，而是通过隐藏的、Agent 无法篡改的证据通道（Evidence Channels）来记录全过程。它定义了三个关键的安全层级：
-边界合规性（Boundary Compliance, L1）：
这是最核心的防线。检查每个动作是否越权。包括：
工具违规：调用了未授权或无关的工具。
- 资源违规：访问了受保护或超出范围的文件/数据。
- 信息流违规：在通信或最终输出中泄露了不应共享的信息。
-执行保真度（Execution Fidelity, L2）：
不仅看结果，还看路径。检查中间步骤是否有效，是否有冗余操作或错误的动作序列。
-系统稳定性（System Stability, L3）：
在注入干扰（如间接提示注入、模糊目标、工具报错）后，L1 和 L2 是否依然成立。
关键设计直觉 ：论文强调使用“隐藏审计工件”（Hidden Audit Artifacts）。在 Setup 阶段，系统会预定义好权限策略（ Π\Pi ）和信息流策略（ Φ\Phi ），并在执行过程中通过后端日志独立记录所有工具调用和资源访问。这意味着 Agent 无法通过“撒谎”或“掩盖”来通过审计，所有证据都是客观存在的系统日志。
### 关键结果：能力与安全的严重错配论文在 HarnessAudit-Bench（8 个领域，210 个任务）上测试了 10 种 Harness 配置，结果令人警醒：
-任务完成与安全合规完全脱节：
即使是最强的系统，整体安全评分（Overall Score）也仅为 0.32。Gemini 3.1 Pro 在 OpenClaw 框架下取得了最高的整体分 0.32，而 Claude Opus 4.6 虽然任务完成率（TCR）更高，但安全评分显著更低。这说明更强的任务能力往往伴随着更激进的资源访问，从而增加越权风险。
-资源访问是最大漏洞：
在所有配置中，资源访问的安全遵守率（SAR_r）普遍最低。例如，在 OpenClaw + ChatGPT-5.4 配置下，工具合规率为 0.61，但资源合规率仅为 0.43。Agent 很少调用完全错误的工具，但它们经常把正确的工具用在不该用的资源上。
-多智能体协作放大风险：
从单智能体切换到多智能体后，信息流合规率（SAR_f）从 0.91 暴跌至 0.64。多智能体间的通信通道成为了敏感信息泄露的重灾区。
-对抗干扰极其脆弱：
在间接提示注入（Indirect Injection）测试中，所有模型的性能都大幅下降。平均稳定性得分仅为 0.28-0.36 之间。这表明当前的 Harness 在面对隐蔽的攻击时，缺乏足够的鲁棒性。

### 工程启示对于正在构建 Agent 系统的工程师，这篇论文给出了三个明确的信号：
- 不要迷信最终结果：如果你的评测体系只看 Output，你正在忽略 80% 的安全风险。必须引入轨迹审计（Trajectory Auditing）。
- 收紧资源权限，而非仅限制工具：Agent 更容易在“资源绑定”上出错。在 Harness 设计中，实施细粒度的资源访问控制（RBAC）比限制工具列表更有效。
- 多智能体通信需加密/脱敏：多 Agent 协作中的信息泄露是主要风险。在子 Agent 间传递消息时，必须强制进行上下文过滤和脱敏处理。
### 局限与展望目前 HarnessAudit 主要依赖模拟环境（Mock Services），虽然高保真，但与真实生产环境的动态性仍有差距。此外，论文主要关注了权限和信息流，对于更复杂的逻辑漏洞（如死循环、资源耗尽）覆盖有限。未来的工作可能需要将这种轨迹审计直接集成到生产级的 Agent 框架中，实现实时的安全拦截。
