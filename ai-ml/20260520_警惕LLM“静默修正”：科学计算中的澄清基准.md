# 警惕LLM“静默修正”：科学计算中的澄清基准

**日期**: 2026-05-20

---

论文 : SCICONVBENCH: Benchmarking LLMs on Multi-Turn Clarification for Task Formulation in Computational Science链接 : https://arxiv.org/abs/2605.18630在构建科学计算 Agent 时，我们往往痴迷于代码生成的准确率或工具调用的成功率，却忽略了一个更上游、更致命的环节： 任务定义本身 。如果用户输入的需求存在缺失或矛盾，LLM 是会主动追问澄清，还是为了“显得聪明”而直接脑补一个看似合理的解？这篇来自 RPI 和 PNNL 的论文抛出了一个令人不安的结论：当前最强的模型在解决科学任务模糊性时，存在严重的“静默修正”（Silent Resolution）倾向。这不仅是交互体验问题，更是科学可重复性的风险点。
### 痛点：从“解题”到“审题”的范式转移现有的科学 LLM 基准（如 SciCode, ScienceAgentBench）大多假设输入是一个定义良好的科学问题。但在实际工程中，科学家的请求往往是模糊的。例如，“模拟圆柱绕流”这个指令，如果没有雷诺数（Reynolds Number），流场是完全不同的物理图景。
论文通过一个典型案例展示了后果：如果模型不澄清雷诺数，它可能会“静默地”假设一个低雷诺数工况，运行出无涡旋脱落的层流结果。虽然代码跑通了，但物理上是错的，且完全偏离了用户可能想要的湍流研究意图。这种**上游失败模式（Upstream Failure Mode）**在现有基准中几乎不可见，因为现有评测只看最终代码是否执行成功，而不看任务定义是否经过对话确认。
### 方法拆解：SciConvBench 的设计直觉SciConvBench 的核心创新不在于数据规模，而在于 评测维度的解耦 。它覆盖了流体力学、固体力学、材料科学和偏微分方程（PDE）四个领域，包含 1142 个实例。其设计精髓在于将“任务公式化”拆解为两个独立能力：
- 消歧（Disambiguation）：识别缺失信息并主动询问。
- 不一致性解决（Inconsistency Resolution）：检测并纠正用户输入中自相矛盾的条件。
更重要的是，它引入了 基于对话的 grounding 评估 。传统评测只看最终输出（Final Specification）是否正确，而 SciConvBench 区分了：
- 最终解决率（FRR）：最终给出的任务定义是否正确。
- 对话接地解决率（CGRR）：是否正确且通过对话明确澄清了所有问题。
- 静默解决率（SRR）：最终答案正确，但未在对话中明确澄清（即模型偷偷脑补）。
这种设计直接暴露了 LLM 的“黑盒推理”行为：模型可能猜对了，但它没有让用户知情，这在科学协作中是不可接受的。
### 关键结果：强模型也“静默”
实验结果揭示了当前前沿模型（GPT-5.2, Gemini 2.5 Pro 等）在科学澄清任务上的真实短板：
-通用基准 vs. 科学基准的巨大落差：
在通用澄清基准 CLAMBER 上，Gemini 2.5 Pro 的解决率高达 86.1%。但在 SciConvBench 的消歧任务中，同一模型的性能暴跌至 18.2%（流体力学领域）。这说明科学领域的澄清难度远超通用问答，需要深厚的领域知识来识别“什么信息是缺失的”。
-静默修正普遍存在：
所有模型都表现出非零的 FRR-CGRR 差距。平均而言，消歧任务的差距为 8.2 个百分点，而不一致性解决任务的差距高达 14.7 个百分点。
极端案例：Claude Sonnet 4.6 在 PDE 不一致性任务中，FRR 为 31.5%，但 CGRR 为 0.0%。这意味着它所有的“正确”解答都是静默完成的，完全没有通过对话与用户确认冲突点。
-能力分离现象：
GPT-5.2 在消歧任务上最强（CGRR 52.7%），擅长挖掘缺失信息。
- Gemini 2.5 Pro 在不一致性解决上最强（CGRR 82.7%），擅长发现矛盾。
这表明“提问”和“纠错”是两种可分离的科学对话技能。
-领域差异：
流体力学是消歧的瓶颈，最佳 CGRR 仅 29.8%；而 PDE 和材料科学相对较好，分别达到 72.1% 和 68.5%。本体分析显示，“数值求解器选择”和“控制物理假设”是最脆弱的组件，模型经常在此处静默假设。
### 工程启示对于正在构建科学 Agent 的工程师，这篇论文提供了三点直接建议：
- 不要信任“一次性”输出：在科学计算场景中，不要直接使用 LLM 生成的单次任务定义。必须引入多轮澄清机制，强制模型显式列出其假设。
- 评估指标需升级：如果你的基准只检查最终代码是否运行，你正在奖励“正确的猜测”而非“可靠的协作”。引入类似 CGRR 的指标，惩罚那些未经验证的静默修正。
- 领域知识注入：通用 LLM 在科学澄清上表现不佳，因为它们不知道“雷诺数”对流体模拟至关重要。通过 RAG 或微调注入领域本体（Ontology），能显著提升模型识别缺失关键参数的能力。
### 局限与展望SciConvBench 目前依赖 LLM 模拟用户（User Simulator），虽然论文做了鲁棒性测试，但模拟用户的真实性仍有提升空间。此外，基准仅评估到“任务定义”阶段，未涵盖后续的代码执行和结果验证。未来的工作可能需要将澄清、编码和执行串联起来，形成端到端的科学 Agent 评测闭环。
总之，这篇论文提醒我们：在科学计算中， 问对问题比给出答案更难，也更重要 。
