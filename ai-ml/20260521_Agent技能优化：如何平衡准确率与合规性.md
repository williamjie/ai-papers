# ⭐⭐⭐⭐ Agent技能优化：如何平衡准确率与合规性

**日期**: 2026-05-21

---

论文 : MOCHA: Multi-Objective Chebyshev Annealing for Agent Skill Optimization链接 : https://arxiv.org/abs/2605.19330现在的 LLM Agent 开发早就过了“单一大提示词”的时代。为了复用和路由，技能（Skill）被拆解成结构化的自然语言规范：描述字段用于检索匹配，指令主体负责执行逻辑。但在实际工程中，这带来了一个棘手的多目标优化难题： 既要高准确率，又要满足平台硬约束 。
比如 Anthropic 的 SKILL.md 规范，描述字段限制在 1,024 字符，指令主体限制在 5,000 字符。一旦超限就会被截断或拒绝部署。现有的提示词优化工具（如 TextGrad、ProTeGi）大多只盯着准确率看，或者简单地把多个目标加权求和。这种做法在非凸的目标空间中往往会失效——它们要么找不到最优解，要么直接卡在初始状态不动。
Adobe Research 提出的 MOCHA （Multi-Objective Chebyshev Annealing）正是为了解决这个问题。它不追求单一的“最好”，而是通过切比雪夫标量化（Chebyshev Scalarization）和指数退火策略，探索出完整的帕累托前沿（Pareto Front），让开发者根据实际部署需求在准确率和合规性之间做权衡。
### 为什么现有优化器会“卡死”？
论文指出了一个被忽视的工程痛点： 单目标选择策略无法利用多目标反馈 。
在实验中，所有基线方法（TextGrad, ProTeGi, GEPA）都接收了相同的、包含合规性状态的文本反馈。然而，因为它们最终只根据单一标量（如 UCB 分数或贪婪匹配）来选择候选者，它们无法处理那些“准确率提升但合规性下降”的中间状态。
结果非常残酷：在 6 个测试任务中的 4 个（GPQA, HoVer, FEVER, DebugBench），经过 1000 次迭代后， 所有基线方法返回的结果与初始种子技能完全一致 。也就是说，它们花了大量算力，却没有任何进步。
### MOCHA 的核心设计直觉MOCHA 的突破在于它承认了优化的多目标本质，并设计了两个阶段来导航解空间：
-切比雪夫标量化（Chebyshev Scalarization）：
传统的线性加权会漏掉非凸区域的帕累托最优解。MOCHA 使用切比雪夫范数（L∞L_\infty​）来评估候选技能与理想点的最大加权偏差。这保证了算法能覆盖整个帕累托前沿，包括那些线性方法够不到的“凹陷”区域。
-探索与利用的退火切换（Annealing）：
早期（探索）：使用超体积贡献（Hypervolume Contribution, HVC）作为接受准则。只要候选者能扩大帕累托前沿的范围，无论方向如何，都被允许进入候选池。这确保了多样性。
- 后期（利用）：随着预算消耗，阈值指数衰减，算法切换到严格的切比雪夫接受准则。此时只接受在特定权重方向上改进的候选者，从而精细打磨最优解。
这种设计让 MOCHA 既能“撒网”找到各种权衡点，又能“收网”提升核心指标。

### 工程启示与局限对 Agent 开发的指导意义：
如果你正在构建需要严格遵循格式或长度约束的 Agent 技能库，不要只用单一的准确率指标去优化 Prompt。引入多目标优化视角，特别是处理“非凸”权衡时，能避免优化器陷入局部最优甚至停滞。MOCHA 的思路可以直接复用到其他结构化文本优化场景中。
局限性与边界：
- 低冲突任务收益有限：在 HotpotQA 这种准确率提升不与长度约束冲突的任务上，MOCHA 的优势不明显，甚至略低于 ProTeGi。这说明当目标之间没有张力时，复杂的 MOO 机制可能只是增加了开销。
- 固定退火调度：当前的指数衰减是超参数，未来可能需要自适应调度来应对不同任务的优化难度。
- 平台依赖性：合规性指标绑定在特定的 SKILL.md 规范上，换到不同的 Agent 框架可能需要重新定义约束函数。
总的来说，MOCHA 证明了在离散的自然语言搜索空间中，经典的多目标优化理论（如切比雪夫标量化）依然具有强大的生命力，尤其适合解决现代 Agent 系统中那些“既要又要”的工程难题。
