# ⭐⭐⭐½ RLVR的隐形陷阱：验证器如何重塑模型的“未来可学性”

**日期**: 2026-08-17

论文 : Verifier-Induced Support Reshaping in On-Policy Optimization链接 : https://arxiv.org/abs/2608.00220做模型后训练（Post-training）时，我们常盯着当前任务指标涨没涨。但这篇来自北大和北邮的工作揭示了一个更隐蔽的危机： RLVR 可能在提升当前任务的同时，悄悄“杀死”了未来任务的可学习性。 这对做多阶段 Agent 或持续微调的工程团队是个重大预警。
### 痛点：不是遗忘，是“够不着”
传统的灾难性遗忘（Catastrophic Forgetting）关注的是“学完 A 后 B 还记不记得”。但这篇论文提出了一个新概念： 验证器诱导的支持重塑（Verifier-Induced Support Reshaping） 。
核心区别在于：
- 遗忘是能力丢失，性能下降。
- 支持重塑是能力还在，但在有限采样预算内，成功轨迹变得太罕见，导致后续训练缺乏正样本信号。
简单来说，模型不是“忘了”怎么做数学题，而是它现在倾向于直接给答案（Direct Answer Initiation, DAI），而不是逐步推理（Deliberative Reasoning Initiation, DRI）。当你接着用数学验证器训练时，因为采样到的大多是“直接答案”，验证器无法提供有效的梯度信号。
### 核心机制：第一个 Token 决定了命运论文通过双向实验（Math→IF 和 IF→Math）发现，这种重塑高度集中在 响应的开头几个 Token 。
- 分布偏移极大化：在 AIME 数据集上，第一个 Token 的 JS 散度（Jensen-Shannon Divergence）比内部 Token 高出 9.8x 到 106.7x。
- 路由重排而非新能力学习：RLVR 并没有教模型全新的推理路径，而是重新排序了 Base 模型已有的候选项。Math-RLVR 偏好 DRI（如 “Alright”, “To”），而 IF-RLVR 偏好 DAI（如 “Answer”）。
- 因果性验证：作者通过干预实验证明，如果强制 IF-RLVR 后的模型以 DRI 开头，其 AIME best@32 能恢复 +57.8%。这证实了“开头路由”对数学搜索能力具有因果影响。
### 关键数据：指标背离与联合失效实验在 Qwen3-8B-Base 和 Qwen2.5-Math-7B 上进行，结果令人警惕：
训练阶段 IFEval pass@1 (平均成功率) IFEval best@32 (采样覆盖率) AIME best@32 (数学搜索性) Base Baseline Baseline Baseline Math-RLVR 后 +6.5% -9.8% - IF-RLVR 后 - - 显著下降⚠️ 反直觉发现 ：Math-RLVR 让 IF 的平均成功率（pass@1）提升了，但 best@32 却下降了。这意味着模型在剩下的提示词上要么全对、要么全错，中间的“混合”状态消失了。 对于后续训练来说，“混合”状态才是提供梯度信号的金矿，它的消失意味着学习停滞。
在联合能力测试（MathIF/ReasonIF）中，单任务提升很难转化为“既正确又遵循约束”的联合表现。例如，Math-RLVR 提升了数学正确率（+11.3pp），但指令遵循度几乎没变，联合成功率仅微增 2.4pp。
### 工程启示：如何避免踩坑？
- 监控“支持度”而非仅看分数：在多阶段训练中，不要只看 pass@1。必须监控 best@k（尤其是 k=32）的变化。如果 best@k 下降，说明模型正在极化，未来可学性受损。
- 警惕顺序效应：IF-RLVR 会破坏 Math-RLVR 所需的推理路径。如果业务需要“先懂指令，再强推理”，直接串行训练可能会让数学能力变得难以恢复。
- 缓解手段有限：
KL 约束：增加 KL 系数（如 β=0.12）能保留数学能力，但会牺牲 IF 收益，没有免费午餐。
- DRI 先验 SFT：在 IF-RLVR 前做少量 DRI 风格的 SFT，只能延缓 DAI 的主导地位，无法阻止最终结果。
- 在线策略蒸馏（OPD）：依赖教师模型的状态选择非常敏感，收敛后的 IF 教师反而会导致学生数学能力崩塌（MATH-500 mean@16 从 0.34 跌至 0.09）。
### 局限与展望该研究基于 8B/7B 规模模型和特定基准。虽然指出了“第一个 Token”的关键作用，但尚未提供能同时保留多任务支持度的完美算法。对于工程实践者而言，这篇论文的价值在于 诊断工具 ：它告诉我们，当你的模型在 A 任务上表现变好但在 B 任务上变得“不可教”时，去检查它的 响应开头分布 ，可能比调整学习率更有效。
