# 用 AI 生成 AI 的考场：ClawEnvKit 如何自动化 Agent 评测环境

**日期**: 2026-04-21

---

论文 : ClawEnvKit: Automatic Environment Generation for Claw-Like Agents链接 : https://arxiv.org/abs/2604.18543现在的 Agent 评测有个尴尬的悖论：模型能力飞速迭代，但评测集还是那几张卷。人工出题不仅慢，而且一旦发布就固定了——模型刷多了就泄漏，不刷又测不出真实水平。
马里兰大学等机构提出的 ClawEnvKit 给出了一个反直觉的解法： 既然人工出题累，那就让 AI 出题，再用 AI 阅卷，而且还要保证题目不出错。
他们一口气自动生成了 1,040 个环境，成本只要 80 美元。
## 痛点：手工造环境，造到地老天荒在 ClawEnvKit 之前，主流评测集如 Claw-Eval、ClawArena 等，环境全部是人工编写的。每个环境需要三件事：
- 写任务描述（agent 要干什么）
- 实现验证逻辑（怎么判断 agent 做对了）
- 确保环境可执行（mock 服务、预置数据）
一篇论文估计，人工构建一个任务需要约 2 小时。104 个任务就是 208 个人时。更致命的是，这些环境是 静态 的——发布即固化，无法随模型能力增长而扩展。
ClawEnvKit 的核心洞察是： 你不需要枚举状态空间，只需要声明式地描述 P-M-C 三元组。
## 方法拆解：P-M-C 三元组 + 三 Agent 流水线### 核心设计：声明式环境定义传统 RL 环境用马尔可夫决策过程（MDP）建模，需要显式定义状态空间 S、动作空间 A。但对 LLM Agent 来说，状态空间几乎是无限的——邮件内容、API 返回、对话历史都在变。
ClawEnvKit 做了一个聪明的简化：从 agent 视角看状态是无限的，但从实现者视角看，状态就是几个内存里 mock 数据库的内容。所以不需要定义状态转移，只需要定义三个东西：
组件 符号 含义 任务规范 P ∈ L 自然语言描述 agent 要做什么 交互接口 M = (T, O) 可用工具集合 T + 审计日志 O 评估函数 C = {(ci, wi)} 多个打分项 ci，权重 wi 和为 1这个声明式分离是关键。LLM 不需要理解状态转移语义就能生成合法的 (P, M, C)，但如果要用传统方式写一个正确的 state-based grader，LLM 得理解整个环境的执行语义——这几乎不可能可靠地完成。
### 三 Agent 流水线ClawEnvKit 用三个 LLM 驱动的子模块组成端到端流水线：
1. Parser（解析器）
把自然语言需求转成结构化规范。回答三个问题：agent 要做什么？任务涉及什么对象？必须满足什么约束？这些结构化意图单元是后续所有验证的锚点。
2. Generator（生成器）
干三件事：
- 任务生成：根据服务列表和难度，写出完整的 (P, M, C)，通过 action rotation 和去重保证多样性- 服务生成：如果需要的服务不在库里，自动生成 API、搭建 mock server、测试通过后再入库- Fixture 生成：准备任务所需的预置数据（数据库、图片、文档等）
3. Validator（验证器）
这是保证质量的关键。每个生成环境必须通过三关：
- 格式检查：字段完整、权重和为 1、至少一个安全检查、不自相矛盾- 覆盖检查：Parser 的每个意图单元都必须在任务中找到对应物- 可行性检查：检查反事实任务（比如”获取明天的邮件”）和无法访问的信息任何一关不过就回炉重造。
### 执行与评分生成的环境运行在隔离容器中，无网络访问，mock 服务会向 25% 的 API 调用注入随机错误来测试鲁棒性。
评分引擎分五步：
- 安全门控：任何违规直接归零- 分项评分：15 种检查类型，来源三个——审计日志（agent 做了什么）、输出检查（agent 说了什么）、文件系统检查（agent 创建了 What）
- 完成率：加权汇总- 鲁棒性：从注入错误中恢复的比例- 综合得分：R(σ, E) = safety(σ) × [0.8 · completion + 0.2 · robustness]注意 LLM Judge 的权重上限 55%，确保大部分评分是确定性的。

## 工程启示1. 评测基础设施本身就是竞争力。 NemoClaw 用 SKILL.md + curl 这种”低级”方案干翻了更”高级”的 MCP 集成，说明 agent 的编排策略（planning、tool use pattern）比工具集成本身更关键。
2. 自动生成 ≠ 低质量。 得益于 P-M-C 的声明式设计和 Validator 的三道门控，自动生成环境在连贯性和清晰度上反超人工。结构化的中间表示反而让质量更可预测。
3. 活体评测（Live Evaluation）才是终局。 ClawEnvKit 最性感的特性不是批量生成，而是 按需生成 ——用户用自然语言描述一个场景，系统实时生成可验证环境。这解决了数据泄漏的根本问题：评测集不再是冻结的 artifact，而是持续演化的服务。
## 局限与展望论文没有明说但隐含的局限：
- LLM 依赖：整个流水线依赖 Claude Sonnet 4.6（80 美元成本），如果换用更弱的 LLM 做生成/验证，质量会怎样？
- Mock 服务的真实性：当前环境运行在内存 mock 服务上，与真实 API 的行为差异可能掩盖某些 agent 缺陷- 评估维度：目前主要测 completion/robustness/safety，对 agent 的效率（token 消耗、调用轮数）虽有图 5 但非核心指标总体来看，ClawEnvKit 证明了一件事： 当环境生成从手工劳动变成可编程管道时，评测的规模和频率就不再是瓶颈。 这不只是省人力的事——它让”随模型能力演化”的评测从愿景变成了工程现实。
