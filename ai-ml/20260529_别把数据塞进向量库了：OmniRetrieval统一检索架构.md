# ⭐⭐ 别把数据塞进向量库了：OmniRetrieval 统一检索架构

**日期**: 2026-05-29

---

论文 : OmniRetrieval: Unified Retrieval across Heterogeneous Knowledge Sources链接 : https://arxiv.org/abs/2605.29250现在的 RAG 系统有个通病：为了省事，把 SQL、知识图谱（Knowledge Graph）全转成文本塞进向量库。结果呢？Join 没了，多跳遍历废了，查个复杂问题全靠运气。这篇来自 KAIST 的论文直接掀桌子： 别搞统一表示，保留原生查询能力才是正解。
### 痛点：强行“大一统”带来的信息损失现有方案通常有两种路数：
- 单源孤岛：Text-to-SQL 只管数据库，向量检索只管文档。用户得自己知道去哪查。
- 暴力统一：把所有数据投影到同一个嵌入空间（Embedding Space）。
作者指出，第二种看似优雅，实则致命。当你把结构化数据扁平化为文本或向量时，你丢失了“结构红利”（Structural Affordances）。比如 SQL 的 Join、SPARQL 的三元组匹配、Cypher 的路径遍历，这些操作在向量相似度搜索里根本不存在。更糟糕的是，这种统一会导致“模态偏差”：检索结果往往偏向于形式上相似的数据源，而不是语义上正确的答案。
### 核心 Insight：保留原生接口，上层做路由OmniRetrieval 的核心设计哲学非常清晰： Meet each source on its own terms（在各自的主场上对话）。
它不尝试构建一个万能编码器，而是构建了一个 统一访问层 。流程分三步走：
- 源选择（Source Selection）：利用长上下文 LLM，一次性读取所有数据源的描述符（Schema、本体论、文档摘要），选出最相关的几个候选源。
- 原生查询生成（Native Query Generation）：针对每个选中的源，生成其原生语言查询（SQL/SPARQL/Cypher 或文本）。
- 跨源证据选择（Cross-Source Evidence Selection）：执行所有查询，拿到异构结果（行、三元组、段落），最后由 LLM 判断哪些真正回答了问题。
⚠️ 关键直觉 ：与其在检索前做“有损压缩”，不如在检索后做“无损整合”。因为原生查询引擎已经完成了最复杂的结构推理，LLM 只需要做最后的语义裁决。
### 实验数据：吊打单源基线作者在涵盖 13 个数据集、309 个独立知识库的基准上进行了测试。结果非常硬核：
方法 源选择准确率 检索准确率 LLM-as-a-Judge KB Routing (单源路由) 64.88% 42.07% 60.26% OmniRetrieval (本文) 68.58% 46.62% 69.72% Oracle (完美源选择) 100.00% 62.47% 75.20%数据基于 GPT-5.4 骨干模型，宏观平均几个值得注意的细节：
- 多候选优势：OmniRetrieval 允许选择 Top-K 个源（默认 K=3）。实验显示，K=3 时性能显著提升，且随着模型规模增大（从 2B 到 27B），候选源的多样性增加，准确率随之提升。
- LLM-as-a-Judge 的增益更大：在严格的执行匹配（Execution Match）上，OmniRetrieval 领先 KB Routing 约 4.5%；但在语义等价性评估（Judge）上，领先幅度扩大到近 10%。这说明即使源选择稍有偏差，跨源证据整合也能“救场”，找回语义正确的答案。
- 统一表示的局限：作者做了一个受限实验，将异构数据强行统一嵌入。结果显示，虽然能覆盖一些跨域问题，但性能远低于原生查询方法。这证实了：原子级检索无法替代结构化合成。
### 工程启示：架构设计的取舍- Schema 即上下文：不要试图微调一个模型去“记住”所有 Schema。OmniRetrieval 直接利用 LLM 的长上下文能力，将 Schema 作为 Prompt 的一部分传入。这意味着你的系统可以动态注册新数据源，无需重新训练。
- 延迟 vs 准确率：这种架构的代价是并发执行多个查询。但在企业级场景中，为了获取高准确率的复杂答案，这点延迟通常是可接受的。
- 证据整合是关键：最后的 Evidence Selection 步骤决定了成败。论文建议未来可以通过监督微调（SFT）或强化学习来优化这一步，使其更鲁棒。
### 局限与展望目前 OmniRetrieval 依赖单一共享 LLM 完成所有步骤，可能存在“全能但平庸”的问题。此外，源选择阶段的准确率仍有提升空间（距离 Oracle 还有差距）。未来的方向包括针对特定操作符的专业化模型，以及基于下游答案质量的强化学习优化。
总之，如果你正在构建企业级知识库，别再想着把所有数据都变成向量了。 尊重数据的原生结构，用 LLM 做路由和整合，才是通往通用检索的正确路径。
