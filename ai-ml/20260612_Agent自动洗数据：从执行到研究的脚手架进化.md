# ⭐⭐⭐⭐ Agent自动洗数据：从执行到研究的脚手架进化

**日期**: 2026-06-12

---

论文 : Can Generalist Agents Automate Data Curation?
链接 : https://arxiv.org/abs/2606.04261训练数据的质量直接决定了模型的上限，但“洗数据”往往是最耗时的人工环节。这篇论文抛出了一个极具工程吸引力的问题：能不能让通用代码 Agent 自动完成“提出策略-实施-评估-迭代”的数据清洗闭环？
答案不仅是肯定的，而且揭示了一个反直觉的现象： Agent 能完美执行清洗流程，但如果不加约束，它们只会做低水平的微调。
### 痛点：为什么需要 Agent 洗数据？
在现有的 AI 开发流中，我们自动化了去重、筛选等单点操作，但“该用哪种策略”、“如何组合策略”依然依赖人工直觉。这种迭代搜索过程积累了大量人力成本。
作者提出了 Curation-Bench ，这是一个以 Agent 为中心的基准测试。它固定了模型架构、训练配方和评估套件，只让 Agent 通过命令行接口去探索数据子集。这模拟了真实的工程场景：你不能改代码，只能改数据。
### 方法拆解：从“执行者”到“研究者”的鸿沟论文的核心洞察在于区分了 执行能力（Execution） 和 研究能力（Research） 。
-开放提示（Open-Prompt）模式：
Agent 被赋予完全自由，只需运行标准的 inspect-cur-train-eval 循环。
结果：Agent 表现惊人。在 LLaVA-665K 数据集中选取 10k 样本微调 LLaVA-1.5-7B，Claude Code 达到了 33.7 的平均分，超过了随机选择（31.9）甚至部分人工基线（ICONS 33.3）。
- 缺陷：轨迹分析显示，Agent 陷入了“局部最优”。它们倾向于调整数据源比例、长度阈值等低代价操作，而不是探索全新的策略家族。这是一种“氛围优化”（Vibe Optimization），听起来像在做研究，实际上只是在调参。
-脚手架（Scaffolds）干预：
为了打破僵局，作者引入了不同强度的约束：
轻量级：提供策略列表或论文卡片。效果有限，Agent 只是嘴上说考虑了新策略，代码里还是改比例。
- 重量级（Adapt Papers）：强制要求每次迭代必须引用一个先前的方法，解释其适用性，并将其适配到当前数据集中。
⚠️ 关键发现 ：只有当“方法论适配”成为任务契约的一部分时，Agent 才会真正跳出舒适区。
在重量级脚手架下，Agent 自主组合了 EL2N 风格的高损失样本选择 与 助手损失噪声过滤 。这种混合策略以仅 1/10 的数据量（10k vs 100k），达到了 34.9 的分数，超越了所有非 Agent 基线。

### 工程启示- 不要指望 Agent “自己想”：通用代码 Agent 是优秀的执行者，但不是天生的研究员。如果你只给一个开放指令，它们会走阻力最小的路（改比例、换种子）。
- 强制结构化思考：在自动化数据清洗流水线中，引入“必须引用/适配某种已知算法”的约束，能显著提升最终策略的上限。这不仅是 Prompt Engineering，更是工作流设计。
- 计算力可以花在搜索上：实验显示，增加 Agent 的迭代次数（从 10 次到 50 次），性能仍在提升。在数据稀缺的场景下，用更多的算力去“搜索最佳数据子集”，比盲目增加训练数据更有效。
### 局限与展望目前的实验主要集中在视觉语言模型的指令微调上。对于代码、数学等更专业的领域，或者评估信号更噪声的场景，Agent 的表现可能不同。此外，脚手架的设计本身也需要人工定义，如何自动发现最佳的“脚手架结构”是下一步的方向。
总之，这篇论文告诉我们： Agent 自动化数据清洗不是未来，而是现在。但要想让它产出超越人类专家的结果，你需要给它戴上“方法论”的手铐。
