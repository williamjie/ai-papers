# 自动搜索推理策略：让LLM自己优化推理过程

**日期**: 2026-05-11

---

论文 : LLMs Improving LLMs: Agentic Discovery for Test-Time Scaling链接 : https://arxiv.org/abs/2605.08083在推理成本日益昂贵的今天，如何在有限的 Token 预算下榨干大模型的性能，是工程落地的核心痛点。传统的测试时扩展（Test-Time Scaling, TTS）策略，如自一致性（Self-Consistency）或早期停止，大多依赖研究人员凭直觉手动设计启发式规则。这种方法不仅效率低下，而且很难找到全局最优的计算分配方案。
这篇来自 UMD、Meta 和 Google 等机构合作的文章《LLMs Improving LLMs: Agentic Discovery for Test-Time Scaling》提出了一个颠覆性的思路：不再让人去设计策略，而是构建一个环境，让智能体（Agent）自动搜索出最优的推理控制策略。其核心框架 AutoTTS 仅花费约 40 美元和 160 分钟，就发现了一套在准确率-成本权衡上超越多种人工基线的方法。
## 为什么现有的 TTS 策略不够好？
现有的 TTS 方法（如 Parallel-Probe、ASC、ESC 等）本质上是在一个巨大的“计算分配空间”中手动寻找路径。我们可以把这个空间想象成宽度和深度两个维度：宽度指并行探索多少个推理分支，深度指每个分支延伸多远。
目前的痛点在于：
- 人工设计局限：研究人员手动假设分支、剪枝、停止的规则，并凭直觉调参。这导致大量计算分配空间未被探索。
- 搜索成本极高：如果直接让 LLM 在线搜索最优策略，每次评估都需要调用 LLM 生成推理轨迹，成本高昂到无法承受。
AutoTTS 的核心 Insight 是： 将 TTS 策略设计转化为控制器合成问题，并通过离线回放（Offline Replay）环境来大幅降低搜索成本。
## AutoTTS 方法拆解AutoTTS 的设计巧妙地解决了“搜索空间过大”和“评估成本过高”两个难题。
### 1. 离线回放环境：零额外 LLM 调用为了评估候选策略，AutoTTS 不再实时调用 LLM，而是预先收集推理轨迹。
- 数据预采集：对于每个问题，预先从基座模型采样 N 条独立的推理轨迹，并将每条轨迹分割为固定长度的区间（Interval）。
- 确定性回放：在搜索阶段，控制器只是从预存的数据中“读取”分支前缀和探针信号（Probe Signals）。例如，执行 PROBE 动作只是读取预存的中间答案，执行 BRANCH 只是实例化一个新分支并读取第一层生成结果。
- 效果：这使得候选控制器的评估变得极其廉价且确定，无需任何额外的 LLM 调用。
### 2. Beta 参数化：防止过拟合在初步实验中，作者发现智能体倾向于提出拥有大量超参数（多达 10 个）的复杂控制器。这导致搜索空间过大，智能体容易在搜索集上过拟合，发现一些极端但鲁棒性差的策略（如过度激进的剪枝）。
为此，AutoTTS 引入了 Beta 参数化 ：
- 每个控制器只暴露一个标量超参数 β\beta。
- 所有内部超参数都通过一个单调映射函数由 β\beta 决定。
- 这强制搜索空间降维为一维，防止了智能体发现针对搜索集的特异性阈值，提高了策略的泛化能力。
### 3. 执行轨迹反馈：让 Agent 知道“为什么失败”
仅凭准确率-成本这一标量反馈，智能体很难诊断策略失败的具体原因。AutoTTS 在历史存储中保留了完整的 执行轨迹（Execution Traces） ，记录控制器在每个步骤中如何分配计算（如扩展了哪个分支、剪枝了哪个分支）。这使得探索者 LLM 能够基于细粒度的行为证据，针对性地改进策略。

此外，AutoTTS 发现的策略具有极强的泛化能力：
- 跨模型泛化：在 Qwen3 上发现的策略，在 DeepSeek-R1-Distill-Llama-8B 模型上依然有效（HMMT25 基准下，AutoTTS 准确率达 27.2%，Token 仅 533.9K，优于 SC@64 的 26.7% 和 985.7K）。
- 跨任务泛化：在 GPQA-Diamond（非数学推理任务）上，AutoTTS 同样表现出优异的准确率-成本权衡。
## 工程启示- 环境设计重于策略设计：与其手动调参，不如精心设计一个可回放、反馈丰富的搜索环境。AutoTTS 证明，只要环境构建得当，智能体可以自动发现比人类专家更优的策略。
- 离线回放是低成本搜索的关键：对于需要大量评估的算法搜索，预采集数据并离线回放是极具价值的工程实践。这不仅降低了成本，还提高了搜索过程的确定性。
- 简化搜索空间：通过 Beta 参数化将多维超参数压缩为一维，可以有效防止过拟合，提高搜索效率和泛化能力。
## 局限与展望尽管 AutoTTS 展示了强大的潜力，但仍有一些局限性：
- 搜索集依赖：虽然 Beta 参数化缓解了过拟合，但策略仍在特定搜索集上优化。
- 探针成本假设：实验中将探针（Probe）成本视为零或极低，在实际应用中，如果探针计算成本较高，需要重新调整成本模型。
- 领域特定性：目前主要在数学推理任务上验证，未来需扩展到代码生成、多模态等更复杂领域。
总体而言，AutoTTS 为测试时计算优化提供了一条新的范式： 从人工设计启发式规则，转向自动化、环境驱动的控制器合成。 随着智能体编程能力的提升，这种“让 LLM 优化 LLM”的思路可能会成为未来推理优化的主流方向。
