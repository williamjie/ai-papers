# ⭐⭐⭐ 不靠验证集，Agent 也能自我进化

**日期**: 2026-06-10

---

论文 : Retrospective Harness Optimization: Improving LLM Agents via Self-Preference over Trajectory Rollouts链接 : https://arxiv.org/abs/2606.05922大多数 Agent 优化方法都依赖一个“金标准”：带标签的验证集。但在真实生产环境中，获取高质量标注数据成本极高，甚至不可行。这篇论文提出了 RHO（Retrospective Harness Optimization），一种完全自监督的方法。它让 Agent 仅凭过去的运行轨迹（Trajectories）进行反思和优化，无需任何外部评分信号。
### 痛点：为什么我们需要“回顾性”优化？
现有的 Agent 进化方案（如 Meta-Harness、DSPy 等）通常采用“搜索-评估”循环。Agent 生成新的提示词或工具配置，然后在验证集上运行，根据通过率筛选最优解。
这有两个致命缺陷：
- 数据依赖：你需要一个能代表未来任务分布的标注集。现实中，线上任务千变万化，静态验证集往往失效。
- 计算昂贵：为了找到一个好的配置，可能需要成百上千次 Agent 调用和验证集推理。
RHO 的核心直觉是： Agent 过去的失败轨迹中，已经包含了改进所需的全部信号。 我们不需要外部裁判，Agent 可以自己通过“自我偏好”（Self-Preference）来判断哪种执行路径更好。
### 方法拆解：三步走策略RHO 的流程非常清晰，分为三个阶段，全部由同一个基础模型完成，不引入额外判别器。
1. 核心集选择 (Coreset Selection)
不是所有轨迹都有优化价值。随机选容易漏掉关键错误，只选最难的任务又会导致分布偏差。
作者引入了 确定性点过程 (Determinantal Point Process, DPP) 。这是一种数学方法，能在保证样本多样性的同时，优先选取高难度任务。
- 设计直觉：通过 DPP 权重参数 θ=0.7\theta=0.70.7，平衡“难度”与“多样性”。实验表明，这种组合比单纯按难度排序或随机采样更能覆盖多种失败模式。
2. 组别重演与诊断 (Group Rollout & Diagnosis)
选出 kk 个核心任务后，让 Agent 对每个任务并行运行 GG 次（论文中 G=3G=3 3 ）。这里提取了两个关键信号：
- 自我验证 (Self-validation)：检查单次轨迹内部的逻辑错误，如工具调用失败、假设错误。
- 自我一致性 (Self-consistency)：对比同一任务的多次运行结果。如果多次运行得出不同结论或路径，说明 Agent 在该任务上存在不确定性。
- 洞察：低一致性通常意味着高不确定性。通过分析这些矛盾点，Agent 能生成具体的改进指令（例如：“需要更严格的输入校验”）。
3. 最佳-N 提案 (Best-of-N Harness Proposal)
根据诊断信号，生成 NN 个候选的 Harness 更新方案（包括新的 Prompt、Skills 或 Tools）。
最后，让 Agent 再次运行这些任务，通过 成对自我偏好 （Pairwise Self-Preference）来打分。Agent 比较新轨迹和旧轨迹，选出相对优势最大的那个方案。
### 关键结果：性能飞跃RHO 在三个领域进行了测试：软件工程 (SWE-Bench Pro)、技术工作 (Terminal-Bench 2) 和知识工作 (GAIA-2)。

行为模式改变：
优化后的 Agent 不仅仅��“更聪明”，它的行为模式发生了结构性变化。
- 在 SWE-Bench Pro 中，Agent 的 验证 (Verify) 操作增加了 61%，而编辑操作减少了。这意味着它学会了“先检查再动手”，从而在长周期任务中保持了更高的准确率。
### 工程启示- 无监督优化的可行性：你不需要昂贵的标注数据来优化 Agent。利用线上积累的失败日志，通过 RHO 类似的流程，可以实现低成本的持续迭代。
- Harness 的模块化：RHO 强调对“Harness”（包括 Prompt、Skills、Tools）的整体优化，而不仅仅是调整 Prompt。工程中应将工具代码和提示词视为可独立进化的组件。
- 多样性的重要性：在选取优化样本时，避免只盯着最难的任务。使用 DPP 或类似机制保证样本的分布多样性，能防止 Agent 过拟合于某类特定错误。
### 局限与展望- 环境重置假设：RHO 需要重新运行任务以获取新轨迹。这要求环境是可重置且幂等的。对于一次性、不可逆的真实业务操作（如发送不可撤回的交易），该方法无法直接应用。
- 计算开销：虽然比验证集搜索便宜，但“组别重演”仍然需要多次推理。对于超大规模部署，需权衡优化频率与计算成本。
RHO 展示了一条通往自主进化 Agent 的务实路径：利用自身经验，通过自我反思实现闭环优化。这对于构建长期在线、自适应的智能体系统具有极高的参考价值。
