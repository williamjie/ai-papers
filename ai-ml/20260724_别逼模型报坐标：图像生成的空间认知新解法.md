# ⭐⭐⭐½ 别逼模型报坐标：图像生成的空间认知新解法

**日期**: 2026-07-24

---

论文 : Show, Don’t Tell: Evaluating Spatial Cognition in Generative Pixels Rather Than LLM Text链接 : https://arxiv.org/abs/2607.21072现在的多模态大模型评测有个巨大的盲区：我们习惯让所有模型都“说话”。
但在空间任务中，让一个图像生成模型输出 [x1, y1, x2, y2] 这种坐标字符串，就像强迫画家背诵几何公式。这不仅违背了视觉模型的直觉，更导致我们无法公平地对比文本型 VLM 和像素级生成模型的真实空间能力。
这篇来自浙大 ACES Lab 的论文提出了 ProVisE （Protocolized Visual Evaluation），核心观点很直接： Show, Don’t Tell 。与其让模型把空间判断序列化成文字，不如让它直接在图片上画出来，再通过解析器还原成标准答案。
### 痛点：接口错配导致的能力低估现有的空间基准测试（如 MindCube、SAT）大多为文本输出 VLM 设计。
对于涉及区域、路径或深度的任务，文本模型必须将连续的空间判断压缩为离散的符号。这种“序列化负担”不仅让文本模型难受，更让图像生成模型无路可走——它们生成的视觉标记无法被原始评估器直接打分。
以往的研究常引入一个辅助 VLM 作为“裁判”来读取生成图。但这引入了新的噪声：分数往往反映的是裁判的不确定性，而非生成模型的真实水平。ProVisE 的目标是建立一个**指标兼容（Metric-Compatible）**的测试床，让两种模态在相同的任务语义下公平竞技。
### 方法拆解：协议化视觉评估ProVisE 的设计直觉在于将“回答界面”与“评分规则”解耦。
-视觉协议（Visual Protocols）：这是核心单元。它包含两部分：
引导提示词：约束模型如何在像素空间表达答案（如“用红色掩码标出目标”、“画出导航路径”）。
- 确定性解析器：将生成的图像转换为结构化预测（如坐标、标签、掩码），以便输入原始基准的评分函数。
-智能体构建（Agentic Builder）：手动为每个任务写协议不可扩展。ProVisE 引入一个 Agent，自动分析新基准的任务契约（输入、答案格式、指标），并从预定义的解析组件库中组装生成-解析协议。经过烟雾测试验证后，该协议对所有待测模型冻结共享，防止针对特定模型的过拟合优化。
-SpatialGen-Bench：作者构建了一个包含 470 个样本、14 个子任务的对角线基准。任务涵盖从基础感知（计数、深度）到复杂推理（多跳推理、轨迹规划）的四个能力层级，支持离散选择、点、掩码和连续轨迹等多种答案形式。
### 关键结果：互补而非替代实验对比了 20 个文本回答系统和 11 个视觉回答系统。数据揭示了两种模态在空间认知上的显著差异。

2. 模态优势分布⚠️ 反直觉发现 ：图像生成模型并非在所有视觉任务上都更强。
- 视觉回答的优势区：当答案可以直接作为像素级空间状态外部化时，生成模型表现更好。例如在 深度估计（Depth） 上，视觉回答比文本回答高出 +18.85 分；在 关系验证（Relationship） 上高出 +6.74 分。这是因为深度场和叠加掩码保留了连续的空间结构，无需转化为离散符号。
- 文本回答的优势区：当任务需要超越可见证据的转换时，文本 VLM 占优。在 大小比较（Size）、可行性判断（Feasibility） 和 计数（Counting） 上，文本模型显著领先。这些任务要求组合中间关系或进行离散决策，像素本身只是前提，答案需要经过推理得出。
3. 互补性验证在同一组样本上，GPT Image 2 解决了 GPT-5.4 遗漏的 71 个样本（视觉救援率 37.0%）。这表明视觉成功并非文本成功的子集，两者具有真正的样本级互补性。
4. 解析器敏感性警告如果使用通用的 VLM 作为黑盒解析器替代 ProVisE 的确定性解析器，模型排名会发生剧烈变化（秩相关系数低至 0.31-0.60）。这证明 通用解析器引入了模型依赖的解释偏差 ，不能作为可靠的评估标准。
### 工程启示- 不要强行序列化空间答案：如果你的 Agent 需要处理空间任务（如机器人导航、视觉定位），优先考虑让底层视觉模型输出掩码或关键点，再通过后处理代码解析，而不是让它生成 JSON 坐标。
- 混合架构的价值：鉴于文本和视觉回答的互补性，未来的空间智能体应采用双路策略。对于需要精确推理的任务（如碰撞检测）使用文本 VLM，对于需要连续感知任务（如区域分割、深度感知）使用图像生成模型。
- 评估工具链升级：在评测多模态模型时，必须为不同输出模态设计专用的解析协议。依赖单一通用裁判会导致评估结果失真，无法反映模型的真实空间认知能力。
### 局限与展望ProVisE 目前主要依赖于预定义的解析组件库。对于极度复杂或新颖的空间任务，Agentic Builder 可能需要 fallback 到受限的辅助解析器，这仍保留了一部分主观性。此外，图像生成模型的推理能力（Reasoning）依然薄弱，如何结合文本链式思维与像素级表达，是后续研究的关键方向。
