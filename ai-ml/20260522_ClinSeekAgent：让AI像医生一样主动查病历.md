# ⭐⭐⭐⭐ ClinSeekAgent：让AI像医生一样主动查病历

**日期**: 2026-05-22

---

论文 : ClinSeekAgent: Automating Multimodal Evidence Seeking for Agentic Clinical Reasoning链接 : https://arxiv.org/abs/2605.20176大多数医疗大模型应用还停留在“被动答题”阶段：人类把整理好的病历摘要喂给模型，模型给出诊断。这在实际临床中完全行不通——医生面对的是杂乱无章的电子健康记录（EHR）、海量影像和分散的外部知识库。 ClinSeekAgent 的核心价值在于，它让 AI 从“被投喂者”变成了“主动调查者”，能够自主规划、检索并整合多模态证据。
### 痛点：为什么“被动输入”搞不定临床推理？
现有的医疗 Agent 研究大多假设证据已经经过策展（Curated Input）。但在真实世界中，关键信息往往隐藏在长达数月的原始 EHR 表格深处，或者分布在不同的检查报告中。固定长度的上下文窗口无法覆盖所有潜在相关信号，导致模型在风险预测等长周期任务上表现不佳。ClinSeekAgent 提出的核心 Insight 是： 临床推理的瓶颈不在于“如何思考”，而在于“去哪里找证据” 。
### 方法拆解：把 EHR 变成可编程数据库ClinSeekAgent 并没有发明新的模型架构，而是设计了一套标准化的 多源工具空间（Multi-Source Tool Space） ，包含 20 个具体工具，覆盖三大维度：
- EHR 检索（11 个工具）：这是最关键的创新。它不只是简单的文本搜索，而是允许 Agent 使用 SQL 查询原始数据库。这意味着模型可以像后端工程师一样，动态编写查询语句来提取特定时间窗口内的生命体征或用药记录。
- 医学影像分析（6 个工具）：包括 DICOM 预处理、胸部 X 光分类、报告生成和解剖分割。Agent 不再依赖原生视觉能力去“猜”图像内容，而是调用专业工具获取结构化结论。
- 外部知识检索（3 个浏览器工具）：用于查询最新的医学指南或疾病定义。
设计直觉 ：系统不预设证据检索的顺序。Agent 根据任务需求，自由交错使用 SQL 查询、影像分析和网络搜索。这种开放式的轨迹（Trajectory）模拟了医生“看到异常指标 -> 调阅历史影像 -> 查阅最新文献”的真实工作流。
### 关键结果：主动检索带来显著增益论文构建了 ClinSeek-Bench ，对比了“策展输入（Curated Input）”与“自动化证据搜索（Automated Evidence-Seeking）”两种模式。数据非常有说服力：
1. 文本 EHR 任务：风险预测提升明显在纯文本 EHR 任务中，强 Agent 模型通过主动检索获得了显著增益：
- Claude Opus 4.6：整体 F1 从 60.0 提升至 63.2 (+3.2)。
- MiniMax M2.5：整体 F1 从 43.1 提升至 47.3 (+4.2)。
特别是在风险预测子任务中，优势更为突出。例如，Claude Opus 4.6 在住院死亡率（Mortality Hospital）预测上提升了 +12.5 分，在住院时长（LengthOfStay）预测上提升了 +16.2 分。这是因为风险信号通常稀疏且分散，固定上下文极易遗漏。
2. 多模态任务：跨模态整合威力巨大在多模态基准测试中，主动检索的优势进一步扩大：
- Claude Opus 4.6：整体 F1 从 47.5 飙升至 62.6 (+15.1)。
- Claude Sonnet 4.6：提升了 +6.9。
- Qwen3-VL-235B：提升了 +5.9。
在表型预测（Phenotype）任务中，Claude Opus 4.6 甚至实现了惊人的 +34.0 分提升。这得益于 Agent 能组合使用 CXR 分类器输出、EHR 时间序列数据和外部医学定义，形成完整的证据链。
3. 训练时蒸馏：小模型也能学会“查病历”
论文还验证了该框架作为训练管道的价值。通过监督微调（SFT）将 Claude Opus 4.6 的检索轨迹蒸馏给 Qwen3.5-35B-A3B ，得到了 ClinSeek-35B-A3B：
- 在 AgentEHR-Bench 上，平均 F1 从基线的 22.1 提升至 34.0 (+11.9)。
- 这一成绩超越了所有其他开源基线，并达到了教师模型（36.0）的 94.4%。
### 工程启示：如何落地临床 Agent？
- 工具链比 Prompt 更重要：不要试图让 LLM 直接理解原始 CSV 或 DICOM 文件。构建标准化的 SQL 接口和影像分析 API，让模型通过代码或函数调用获取结构化数据，是提升可靠性的关键。
- 轨迹蒸馏优于答案微调：实验显示，学生模型学到的不仅是正确答案，更是“如何分配工具预算”。ClinSeek-35B-A3B 使用自由 SQL 查询的比例从 2.0% 激增至 12.5%，说明它学会了将 EHR 视为可编程数据库。
- 长周期任务需主动检索：对于住院时长、死亡率等依赖长期稀疏信号的任务，被动输入几乎必然失败。必须引入主动检索机制。
### 局限与展望尽管效果显著，ClinSeekAgent 在“决策制定（Decision Making）”类任务上表现不如风险预测稳定。部分模型在该类别下甚至出现性能下降（如 Qwen3.5-35B-A3B 下降了 7.0 分）。这可能是因为决策任务需要高度聚焦的关键信号，而主动检索容易引入过多噪声或无关信息，干扰模型的最终判断。未来工作需优化检索的精准度与噪声过滤机制。
