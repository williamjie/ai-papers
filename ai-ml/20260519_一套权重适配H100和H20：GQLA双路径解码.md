# 一套权重适配 H100 和 H20：GQLA 双路径解码

**日期**: 2026-05-19

---

论文 : GQLA: Group-Query Latent Attention for Hardware-Adaptive Large Language Model Decoding链接 : https://arxiv.org/abs/2605.15250DeepSeek-V2/V3 引入的 MLA（Multi-head Latent Attention）虽然把 KV Cache 压缩到了极致，但在实际工程落地中暴露了一个尴尬的问题：它太“娇贵”了。这套架构是专门为 NVIDIA H100 这种算力富余的显卡“量体裁衣”的，一旦换到出口受限的 H20 或其他消费级显卡上，不仅性能暴跌，连原本好用的多 Token 预测（Multi-Token Prediction, MTP）都彻底失效。这篇论文提出的 GQLA 方案，核心目标非常务实：用同一套训练好的权重，同时跑赢 H100 和 H20 的硬件极限，无需重新训练，无需手写新 Kernel。
### 为什么 MLA 在 H20 上会“水土不服”？
MLA 的设计直觉非常精妙：它把 Key 和 Value 联合压缩成一个低秩潜变量（Latent），推理时通过“吸收”操作直接对潜变量做注意力计算。这种设计在 H100 上完美契合了算力与带宽的比例（Ridgeline），算术强度约为 242 FLOPs/byte，刚好卡在 H100 的 295 FLOPs/byte 峰值下方，实现了内存带宽的极致利用。
然而，H20 的情况完全不同。受限于出口管制，H20 的算力被削减了约 7 倍，导致其算力/带宽比骤降至约 37 FLOPs/byte。当 MLA 这种高算术强度的算法跑在 H20 上时，它瞬间变成了“计算密集型”任务，算力根本跑不满，带宽却闲置。更糟糕的是，MLA 的结构锁死了“单路径”解码，导致它无法在 H20 上利用 MTP 提升吞吐量，也失去了沿 Head 维度进行张量并行（Tensor Parallelism, TP）的能力。
### GQLA 的核心设计：一套权重，两条路GQLA（Group-Query Latent Attention）并没有推翻 MLA 的低秩压缩思想，而是做了一个极简的结构修改： 将上投影矩阵（Up-projections）按组（Group）索引，而不是按查询头（Query Head）索引。
这个看似微小的改动，让模型权重在代数上同时支持两种推理路径：
- MQA-Absorb 路径（兼容 MLA）：保持 MLA 原有的低秩潜变量计算方式。KV Cache 极小（仅包含潜变量），适合带宽敏感、算力富余的硬件（如 H100）。
- GQA 路径（新增）：在推理时将潜变量扩展为每组的 Key/Value，执行标准的分组查询注意力（Grouped-Query Attention, GQA）。KV Cache 稍大（包含每组的 K/V），但算术强度低，适合算力受限、带宽尚可的硬件（如 H20）。
核心 Insight ：不需要为不同硬件训练不同模型。部署时，运行时（Runtime）根据硬件特性自动选择计算路径。H100 走 MQA-Absorb 路径压榨带宽，H20 走 GQA 路径避免计算瓶颈。
### 关键结果：通吃两种硬件论文通过 Roofline 模型分析和实验验证了 GQLA 的优势。以下是关键数据对比：
硬件 模型/路径 算术强度 (FLOPs/byte) 每步耗时 (µs) 吞吐量 (tok/s) 状态分析 H100 MLA / GQLA (MQA) ~242 2.82 354K 内存受限，完美契合 H100 峰值 H20 MLA (MQA) ~242 15.42 65K 计算受限 ，严重浪费算力 H20 GQLA (GQA, sq=2) ~38.8 9.06 221K 契合 H20 峰值 ，吞吐量提升 3.4 倍注：sq=2 表示使用多 Token 预测。在 H20 上，MLA 开启 MTP 后吞吐量无增益甚至下降，而 GQLA 的 GQA 路径配合 MTP 实现了理论峰值。
在模型转换方面，论文提出了 TransGQLA 方法，可以将预训练好的 GQA 模型（如 LLaMA-3-8B）直接转换为 GQLA 格式。实验显示，经过转换后，KV Cache 在 MQA 路径下压缩至原来的 28.125%（即压缩了 71.875%），且在零样本评估中，平均准确率仅损失约 9.7 分，证明了结构转换的高效性。
### 工程启示与局限对于正在部署大模型推理服务的团队，GQLA 提供了极具价值的参考：
- 硬件自适应：如果你的服务集群混合了 H100 和 H20（或类似算力受限的国产卡），GQLA 这种“一权多路”的设计能显著降低运维复杂度，无需维护两套模型。
- 张量并行恢复：GQLA 的 GQA 路径支持沿 Group 维度的零冗余张量并行（最高 8 路），这在 MLA 中是缺失的，有利于在大卡上扩展吞吐量。
- 稀疏注意力兼容：GQLA 的每组 16 个查询头的设计（hq/g=16）恰好匹配 Tensor Core 的 MMA _tile 尺寸，这意味着它在 H20 上也能高效支持细粒度稀疏注意力（Sparse Attention），而 MLA 在此场景下会被迫退化为低效的 MQA 模式。
当然，该方法也有局限。目前的路径选择是静态的，部署时确定，不支持运行时动态切换（因为涉及 KV Cache 的重新压缩/解压）。此外，虽然转换过程无需从头预训练，但为了恢复因压缩损失的性能，仍需要进行一定规模的继续预训练（Continued Pretraining）。
GQLA 证明了，在追求极致压缩的同时，保留一定的结构灵活性，是应对复杂硬件生态的更优解。对于追求落地效率的工程师来说，这比单纯的“指标刷榜”更具现实意义。
