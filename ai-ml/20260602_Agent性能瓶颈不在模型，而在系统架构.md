# ⭐⭐⭐½ Agent 性能瓶颈不在模型，而在系统架构

**日期**: 2026-06-02

---

论文 : From Model Scaling to System Scaling: Scaling the Harness in Agentic AI链接 : https://arxiv.org/abs/2605.26112我们常陷入一种误区：认为 Agent 跑不通是因为基座模型（Foundation Model）不够强。这篇来自 UC Berkeley 的论文直接泼了一盆冷水：当模型能力跨过某个阈值后，长周期任务的性能瓶颈不再是推理本身，而是包裹模型的“系统架构”。
作者提出了一个核心概念： Scaling the Harness （扩展执行层）。
### 为什么模型变强了，Agent 还是不行？
现有的评估体系大多盯着最终任务的准确率（Success Rate），把记忆管理、工具调用、上下文构建当作次要实现细节。但这掩盖了真相：Agent 的表现是基座模型与周围系统组件交互的产物。
论文指出，一旦将 Agent 嵌入真实环境（终端、浏览器、代码库），其行为不再由模型单独决定，而是由以下六个组件共同定义：
- Reasoning Substrate (R)：基座推理能力。
- Memory Store (M)：记忆存储。
- Context Constructor (C)：上下文构建器。
- Skill Router (S)：技能路由层。
- Orchestration Loop (O)：编排循环。
- Verification & Governance (G)：验证与治理层。
⚠️ 核心洞察 ：模型缩放（Model Scaling）主要提升 R；而系统缩放（System Scaling）提升的是 M, C, S, O, G。在长视野任务中，后者的权重往往超过前者。
### 三大系统级瓶颈拆解论文没有停留在理论层面，而是深入拆解了三个具体的工程痛点：
#### 1. 上下文治理（Context Governance）
痛点 ：上下文窗口变大 ≠\neq = 信息获取变好。
随着 Token 数量增加，模型面临“暴露但无法访问”（Exposure without access）的问题。关键证据被低价值填充物稀释，注意力分散。
工程对策 ：不要只依赖大窗口，要实施 选择策略 。上下文构建应被视为一个策略输出，需权衡语义相关性、紧凑性、可追溯性和刷新频率。
#### 2. 可信记忆（Trustworthy Memory）
痛点 ：陈旧但自信（Stale-but-confident）。
这是最隐蔽的杀手。例如，“数据加载器在 utils/loader.py ”这条记忆在重构前是正确的，重构后它依然被高置信度检索到，导致 Agent 基于错误假设执行破坏性操作。
工程对策 ：信任必须是运行时决策。检索时需加入 陈旧度惩罚 和 置信度门控 ，并将检索内容视为假设，直到通过实时环境验证。
#### 3. 动态技能路由（Dynamic Skill Routing）
痛点 ：自信但未检查（Confident-but-unchecked）。
专用子 Agent 可能返回看似合理的输出，但下游缺乏验证机制。随着技能增多，失败模式从“缺少能力”转变为“存在但未验证”。
工程对策 ：将路由视为学习策略而非固定规则，并为每个技能定义明确的 后置条件检查 。
### 实验对比与基准思考论文通过对比三个具体的 Harness 实现，展示了不同设计优先级的差异：
系统 类型 核心记忆机制 上下文治理策略 Claude Code 生产级商业 持久化文本记忆 + 自动提取 混合策略：前端加载项目指南，JIT 检索实时信息 OpenClaw 社区开源 对话历史 + 向量检索 用户/频道/会话分级管理 CheetahClaws 研究参考 结构化条目（含置信度、时效性） 显式信任轴，用于检索排序和冲突解决反直觉发现 ：在 Anthropic 的内部评估中，多 Agent 系统比单 Agent 系统在广度优先任务上性能提升高达 90.2% 。但进一步分析显示， Token 使用量 alone 解释了 80% 的性能差异 。这说明所谓的“智能涌现”，很大程度上是计算资源分配和并行上下文窗口利用的结果，而非单纯的推理突破。
### 对工程师的启示- 停止盲目追求大模型：如果你的 Agent 在长流程中频繁出错，先检查你的 Context Constructor 是否引入了噪声，或者 Memory 是否包含了未验证的陈旧信息。
- 重视过程指标：不要只看任务是否完成（Outcome Metrics）。要监控轨迹质量、记忆卫生、上下文效率、验证成本。两个都能完成任务的 Agent，如果一个消耗了十倍 Token 且充满重试，它的系统架构是失败的。
- 建立审计追踪：Agent 的进化必须是可审计的。记忆写入、路由变更、工具权限必须留下可检查的痕迹，否则“学习”很容易变成不可控的漂移（Drift）。
### 局限与展望论文承认， Φ(R,M,C,S,O,G)\Phi(R, M, C, S, O, G) 是一个概念框架而非定量模型，各因子并非严格正交。此外，目前缺乏成熟的 Agent 进化标准，如何区分“安全改进”与“危险漂移”仍是开放问题。
总结 ：未来的 Agent 竞争，将是系统架构设计的竞争。谁能在记忆可信度、上下文治理和技能验证上做得更精细，谁就能在长周期任务中胜出。
