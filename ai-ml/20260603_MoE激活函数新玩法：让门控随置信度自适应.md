### 为什么现有的 SwiGLU 不够好？
现代 Transformer 普遍采用 SwiGLU 作为 MLP 的激活函数。其核心是 SiLU 门控： SiLU(z)=z⋅σ(z)SiLU(z) = z \cdot \sigma(z) z ⋅ σ ( z ) 。
传统做法中，SiLU 的形状是固定的（锐度系数 κ=1\kappa=1 1 ）。但在 MoE 模型中，每个 token 被路由到特定专家时，路由器已经计算出了“置信度”（Router Logits）。
作者发现了一个被长期忽视的现象： 路由器权重与专家门控投影向量在训练初期会迅速对齐 。
反直觉发现 ：这种隐式对齐导致高置信度的 token 和 low-confidence 的 token 落在 SiLU 曲线的不同区域。但这只是通过“加法偏移”影响门控，缺乏灵活性。
### 核心方法：κ\kappa-SwiGLU作者提出了 κ\kappa -SwiGLU，核心 insight 是将 SiLU 的锐度系数 κ\kappa 参数化为路由置信度的函数：
κ(x)=ϕ(α⋅se(x)+b)\kappa(x) = \phi(\alpha \cdot s_e(x) + b) ϕ ( α ⋅ s e ​ ( x ) + b )
其中 se(x)s_e(x) ​ ( x ) 是路由 logits。
- 高置信度：κ>1\kappa > 11，门控变“锐”，激活更稀疏、选择性强。
- 低置信度：κ<1\kappa < 11，门控变“平滑”，激活更广泛、包容性强。
这种设计让每个专家能根据输入 token 的“靠谱程度”动态调整自己的处理策略。相比隐式的加法偏移，这种乘法调制提供了更强的表达能力。
### 实验数据：小改动，大收益作者在 FineWeb-Edu 数据集上训练了从 8 层到 28 层的 MoE 模型，使用 CORE 基准测试进行评估。结果非常稳健：

- 消融实验：移除路由置信度相关的缩放项（α\alpha）会导致性能下降，证明“随置信度变化”是核心贡献，而非简单的参数增加。
### 工程落地价值对于工程师而言，这篇论文的价值在于 极低的开销换取稳定的增益 。
- 参数几乎为零：仅增加了每个门控单元的标量参数 α\alpha 和 bb。在 MoE-14L 模型上，活跃参数仅增加 0.02%。
- 计算开销微小：推理吞吐量（TPS）仅下降约 4%，训练吞吐量下降约 3.5%。这完全在可接受范围内。
- 实现简单：无需修改底层算子，只需在前向传播中利用已有的 router logits 进行简单的逐元素运算即可。
### 局限与展望- 规模限制：实验主要在中小规模模型（最大 28 层）上进行，未在千亿参数级前沿模型上验证。
