### 痛点：跨模态显著性错位（Salience Mismatch）
在视频问答中，音频和视频的关键信息往往不在同一时刻出现。
比如裁判吹哨（音频关键）和手势示意（视觉关键），两者时间不同步。如果让音频重要性去指导视频 Token 的保留，或者反过来，极易误删另一模态的关键线索。
核心洞察 ：78.3% 的查询-视频对中，视听显著性相关性极弱。单向引导在高压缩率下会导致关键信息丢失。
### 方法拆解：共享 Query，独立决策OmniScope 的核心设计原则是： Query 是共享语义锚点，但显著性估计必须解耦。
- 视觉评分：使用外部 CLIP 模型计算帧与 Query 的余弦相似度，独立于 LLM 推理。
- 音频评分：利用 LLM 内部 Audio Encoder 输出与 Query Embedding 的相似度，无需额外模型。
- Anchor-Delta 视觉压缩：
Anchor 帧：保留空间信息密度最高的 Token（用 DPC-KNN 算法），捕捉全局语义。
- Delta 帧：保留相对于前一 Anchor 帧变化最大的 Token，捕捉时序增量。
- 这种交替策略平衡了全局覆盖和局部细节，避免高压缩下的信息碎片化。
- 音频合并：在每秒内通过二分软匹配（Bipartite Soft Matching）合并相似 Token，既去重又保持时间连续性。
### 关键结果：又快又好在 Qwen2.5-Omni-7B 上，OmniScope 表现稳健：
- 45% 保留率：平均准确率 +0.30%（相比全量 Token），几乎无损。
- 25% 保留率：平均准确率仅下降 0.35%，而竞品 OmniZip 下降 1.55%。
- 效率提升：25% 保留率下，Prefill 速度提升 3.53x，显存降低超 15%。
