# 重型技能：将深度思考内化为Agent的核心能力

**日期**: 2026-05-06

---

论文 : HeavySkill: Heavy Thinking as the Inner Skill in Agentic Harness链接 : https://arxiv.org/abs/2605.02396在 Agent 框架（如 Claude Code、CodeX）大行其道的今天，我们往往沉迷于复杂的编排逻辑、记忆模块和工具调用。但美团 LongCat 团队提出的 HeavySkill 却泼了一盆冷水：那些看似精妙的系统架构，其核心驱动力其实可以简化为一种更本质的能力—— 重型思考（Heavy Thinking） 。
这篇论文的价值不在于提出了一个新的 Agent 框架，而在于它揭示了一个被忽视的真相： 并行推理 + 顺序审议 不仅是测试时扩展（Test-Time Scaling, TTS）的有效手段，更是一种可以被“内化”为模型技能（Skill）的通用范式。
## 痛点：复杂编排背后的黑盒现有的 Agentic Harness 试图通过 Orchestrator（编排器）协调多个 Sub-agent 来解决复杂任务。这种设计虽然灵活，但极其脆弱且难以解释。我们不知道是编排逻辑赢了，还是模型本身的推理能力赢了。
HeavySkill 的核心 Insight 很直接： 剥离复杂的系统外壳，将 Agent 的行为抽象为两个阶段：
- 并行推理（Parallel Reasoning）：生成多条独立的思维轨迹（Trajectories）。
- 顺序审议（Sequential Deliberation）：对这些轨迹进行聚合、批判和综合，得出最终答案。
这种抽象不仅适用于复杂的 Agent 系统，甚至可以直接作为 LLM 的一个“内在技能”注入上下文窗口，无需修改任何代码。
## 方法拆解：从工作流到可读技能HeavySkill 提供了一套训练-free（Training-free）的框架，但其工程价值在于将这套流程封装成了一个 可读技能文档（Readable Skill） 。
### 1. 双阶段流水线- Phase 1: 并行思考。模型 πθ\pi_\theta​ 根据问题 qq 生成 KK 个独立的推理轨迹 Tπθ(q,K)T_{\pi_\theta}(q, K)​​(q,K)。这里的关键是多样性，鼓励模型从不同策略（如代数vs几何）入手。
- Phase 2: 顺序审议。另一个模型 πϕ\pi_\phi​（或同一模型）接收这些轨迹的序列化缓存（Memory Cache），进行二次推理。这个过程不是简单的投票，而是要求模型“批判性地评估”每个 Thinker 的逻辑，甚至在全错时重新推导。
### 2. 记忆缓存机制为了防止上下文溢出，论文设计了一个 Serialized Memory Cache 。它将多条轨迹压缩并洗牌（Shuffle）后输入给审议模型，防止模型对特定位置产生偏见。
### 3. 技能化封装这是最工程友好的部分。HeavySkill 定义了一个结构化的自然语言文档，包含：
- 激活条件：仅在复杂推理任务时触发，简单查询保持沉默以节省成本。
- 并行协议：指示编排器生成 KK 个独立子代理。
- 输出约束：强制最终输出仅包含答案（如 answer\boxed{answer}​），去除元分析。
这种设计使得 HeavyThinking 可以像插件一样，无缝注入任何支持 Skill 加载的 Agent 框架（如 Claude Code）。
## 关键结果：不仅仅是投票论文在 STEM 领域（AIME25, GPQA-Diamond 等）和通用推理任务上进行了广泛评估。核心对比指标包括：
- M@KM@K：单次生成的平均准确率。
- V@KV@K：多数投票（Majority Voting）准确率。
- HM@KHM@K：Heavy-Mean，即经过审议后的平均准确率。
- HP@KHP@K：Heavy-Pass，即审议后至少有一个答案正确的比例。
数据说话：
模型 (K=16) AIME25 HM@4 AIME25 V@4 GPQA-Diamond HM@4 GPQA-Diamond V@4 GPT-5 Thinking 99.2% 96.7% 87.2% 85.9% Kimi K2 Thinking 99.2% 96.7% 87.5% 88.9% DeepSeek R1-0528 93.3% 90.0% 86.9% 85.9% R1-Distill-Qwen-32B 68.3% 66.7% 45.8% 50.0%关键发现：
- Heavy Thinking 全面优于 Voting：在几乎所有模型和基准上，HM@4HM@4 都显著高于 V@KV@K。例如 GPT-5 Thinking 在 GPQA-Diamond 上，HM@4 达到 87.2%，而投票仅为 85.9%。这说明审议过程能纠正低频率但正确的路径，而投票往往忽略少数派真理。
- 逼近理论上限：对于强模型，HM@KHM@K 非常接近 P@KP@K（Pass@K，即单次推理的理论上限）。这表明审议过程不仅是在“选优”，有时甚至能“合成”出原始轨迹中不存在的正确解（即 HP@K>P@KHP@K > P@KP@K 的情况在部分实验中观察到）。
- 迭代审议的双刃剑：引入迭代（Iterative Deliberation）可以进一步提升 HM@KHM@K，但会显著降低 HP@KHP@K。这意味着多轮审议虽然能细化答案，但也引入了噪声，限制了探索新解空间的能力。
## 工程启示：给 Agent 开发者的三个建议- 不要迷信复杂的编排：如果你的任务主要是逻辑推理，简单的“并行生成 + 顺序审议”可能比复杂的 Multi-Agent 协作更有效且更稳定。
- 审议模型可以“降级”：实验显示，即使使用推理能力较弱的模型（如 Qwen2.5-32B-Instruct）作为审议者，只要其指令遵循能力强，也能显著提升最终结果。这意味着你可以用一个小模型做“裁判”，用大模型做“选手”，实现成本与效果的平衡。
- Skill 化部署是趋势：将 HeavyThinking 封装为 Skill 文档，使其具备可移植性。这意味着你不需要修改底层 Agent 代码，只需注入 Prompt 即可激活这一能力。
## 局限与展望HeavySkill 并非万能。在主观对齐任务（如 Arena-Hard）上，增益有限甚至为负，因为“正确”的定义在主观偏好中变得模糊。此外，迭代审议带来的噪声累积问题仍需解决。
未来，论文指出 RLVR（基于验证的强化学习） 是进一步挖掘这一技能潜力的关键。如果能让模型在训练阶段就学会如何更好地进行并行探索和顺序审议，而不是依赖推理时的计算堆砌，我们将看到真正自进化的 LLM。
