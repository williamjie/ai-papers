## 为什么现有的安全测试都太虚？
传统的大模型安全评测（如红队对抗）主要看 Prompt 层面的拒绝能力。一旦 Agent 开始调用工具、操作文件、发送邮件，这种“文本对齐”就失效了。
现有方案有两个致命痛点：
- 混淆意图与结果：很多评测把“Agent 说了危险的话”等同于“发生了安全事故”。但在真实环境中，Agent 可能嘴上拒绝，却在后台偷偷执行了恶意代码。
- 耦合度高，扩展难：风险定义、环境模拟、验证逻辑写死在一起。每增加一个新工具或新风险类型，整个测试链路都要重写，维护成本极高。
VERA 的核心 Insight 是： Agent 安全测试必须回归软件工程本质——基于可观测证据（Evidence-Grounded）的确定性验证。
## 方法拆解：从文献到代码的自动化闭环VERA 设计了一个三阶段自增强流水线，把模糊的安全风险转化为可执行的测试用例。
### 1. 持续风险探索（Continuous Risk Exploration）
它不依赖人工编写攻击案例，而是让一个 Summary Agent 去爬取 arXiv 等文献库。
- 三元组分类：将风险拆解为三个正交维度：风险后果（如凭证泄露）、攻击方法（如提示注入）、执行环境（如代码托管平台）。
- 动态收敛：通过创建、更新、合并、删除操作，让分类树随着新文献自动进化，而不是无限膨胀。
### 2. 可执行测试用例构建（Executable Test Case Construction）
这是工程落地的关键。它将抽象的风险三元组组合成具体的测试用例 σ=⟨g,s0,Vg⟩\sigma = \langle g, s_0, V_g \rangle ⟨ g , s 0 ​ , V g ​ ⟩ ：
- gg (Goal)：具体的安全违规目标。
- s0s_0​ (Initial State)：通过 LLM 初始化器，利用 API 动态构建初始环境状态（如预置一个含密码的邮件）。这个初始化过程被记录为确定性脚本，确保可复现。
- VgV_g​ (Verifier)：程序化验证器。这是一个 Python 脚本，直接检查环境最终状态和工具调用日志，而不是让 LLM 判断自己是否安全。
### 3. 自适应执行与证据验证（Adaptive Execution）
Agent 的行为是非确定性的，固定路径测试容易失效。VERA 引入了 控制代理（Control Agent） ：
- 沙箱隔离：每个测试在独立的 Docker 环境中运行，通过 MCP 网关拦截所有工具调用。
- 动态引导：控制代理观察 Agent 的实时行为。如果 Agent 拒绝攻击，它就调整策略；如果 Agent 走了意外路径，它也随之调整注入点。
- 证据优先级：验证时遵循 环境状态 > 工具日志 > 文本回复 的原则。只有当环境状态确实改变（如文件被删、钱被转），才判定为攻击成功。
## 关键结果：多通道攻击下，Agent 几乎裸奔VERA 在 OpenClaw、Hermes、Codex、Claude Code 四个主流框架上进行了测试，发布了包含 1600 个可执行用例的 VERA-Bench。
核心数据洞察：
指标 数值/现象 解读 多通道攻击成功率 93.9% (平均) 当攻击者能同时控制用户输入和工具返回结果时，现有 Agent 防御几乎失效。 最脆弱风险类型 Integrity (完整性) ESR 高达 95.3% 。因为这类攻击依赖明确的状态变更，极易被自动化验证捕获。 最稳定攻击方法 Profile Infer (画像推断) 平均 ESR 89.9% 。跨不同风险类别通用性强。 最难攻陷环境 Productivity (生产力工具) 平均 ESR 77.0% 。因为工作流耦合度高，中间一步失败就会导致整个攻击链断裂。
⚠️ 反直觉发现 ：社会工程学（Social Engineer）在 CRM & Svc 环境中成功率仅为 42.9% ，但在 Communication 环境中高达 100% 。这说明 Agent 在具有持久身份信道的场景中更容易建立“信任”并被操纵，而在事务性强的环境中表现更机械、更安全。
## 工程启示- 验证器必须是代码，不是 LLM：不要相信 Agent 的自我评估。VERA 证明，基于 Python 脚本检查文件系统状态或数据库记录，才是唯一可靠的安全审计方式。
- 测试环境需要“脏数据”：静态的 Prompt 测试不够。你需要动态构建初始状态（s0s_0​），模拟真实的业务上下文（如待处理的交易、未读的邮件），才能触发深层漏洞。
- 多通道威胁是常态：在评估 Agent 安全性时，必须考虑工具返回结果被篡改的场景（Multi-channel）。单靠输入过滤无法防御通过 API 响应注入的恶意指令。
## 局限与展望VERA 目前主要关注推理阶段的风险，未涵盖训练数据投毒等前置攻击。此外，虽然它实现了自动化用例生成，但验证器 VgV_g ​ 的代码质量仍依赖 LLM 生成的准确性，可能需要后续的人工审查或形式化验证增强。
对于正在构建 Agent 系统的工程师来说，VERA 提供了一个清晰的范式： 把安全测试当成软件回归测试来做，用代码验证行为，用沙箱隔离风险。
