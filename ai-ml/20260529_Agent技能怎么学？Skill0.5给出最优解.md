# ⭐⭐½ Agent技能怎么学？Skill0.5给出最优解

**日期**: 2026-05-29

---

论文 : Skill0.5: Joint Skill Internalization and Utilization for Out-of-Distribution Generalization in Agentic Reinforcement Learning链接 : https://arxiv.org/abs/2605.28424给 Agent 喂技能（Skills）是提升复杂任务成功率的关键，但现有方案往往陷入“全外部提示”或“全内部微调”的二元对立。这篇来自华东师大与美团 Longcat 团队的论文提出了 Skill0.5，通过动态路由机制，巧妙地实现了通用技能的内部化与特定技能的动态利用，显著提升了分布外（OOD）场景的泛化能力。
### 痛点：非黑即白的技能管理困境在 Agent 强化学习（RL）中，技能通常分为两类： 通用技能 （如元推理、错误恢复）和 任务特定技能 （如具体操作步骤）。
现有方法存在两个极端：
- 全外部化（Full Externalization）：所有技能都作为上下文提示注入 Prompt。这会导致 Context 过长，严重干扰大模型的上下文学习（ICL）能力，且在长程任务中性能急剧下降。
- 全内部化（Full Internalization）：试图将所有技能参数化到模型权重中。这不仅受限于模型容量，还极易引发知识冲突。当遇到未见过的 OOD 任务时，内部化的旧模式会阻碍对新技能的吸收，导致执行幻觉。
核心 Insight 在于： 通用技能应被内化为认知基础，而特定技能应保持动态插拔。 就像人学习一样，先掌握底层逻辑（内化），再根据具体场景调用操作手册（利用）。
### 方法拆解：基于难度感知的三级路由Skill0.5 的核心是一个 难度感知路由器（Difficulty-Aware Router） ，它根据任务在训练中的实时通过率，将任务分流到三个层级，并施加不同的优化策略。
-困难任务（Hard Tasks）：特权蒸馏内化通用技能触发条件：通过率为 0。
- 策略：此时 Agent 缺乏基础推理逻辑。系统引入“特权提示”，包含通用技能作为教师信号。Agent 在此指导下生成成功轨迹，然后通过 Jensen-Shannon 散度（JSD）进行蒸馏，强制学生模型（无通用技能提示）模仿教师的推理步骤。
- 目的：将通用启发式规则压缩进参数，建立认知基石。
-中等任务（Medium Tasks）：标准 GRPO 强化能力触发条件：通过率低于动态阈值 ηt\eta_t​。
- 策略：复用路由阶段的轨迹，使用标准的 Group Relative Policy Optimization (GRPO) 最大化成功率。
- 目的：在已有基础上通过试错提升性能。
-简单任务（Easy Tasks）：反捷径探测确保技能利用触发条件：通过率高于动态阈值 ηt\eta_t​。
- 策略：引入“无技能提示”作为反事实对照，计算“利用增益”（Utilization Gain）。如果 Agent 在没有特定技能时也能成功，说明它在走捷径（死记硬背），系统会通过负向优势惩罚这种行为。
- 目的：防止过拟合，强制 Agent 真正依赖外部检索到的特定技能，从而提升对 OOD 新技能的适应性。
### 关键结果：OOD 泛化能力的显著跃升实验在 ALFWorld 和 WebShop 两个基准上进行，对比了 Prompt-based、Memory-based 及现有的 Skill-based RL 方法（如 SkillRL, SKILL0）。
ALFWorld 表现：
- ID 场景：Skill0.5 达到 94.3% 成功率，相比最强基线 SkillRL (91.4%) 提升 +2.3%。
- OOD 场景：Skill0.5 达到 88.0% 成功率，相比 SkillRL (76.0%) 大幅领先 +12.0%（论文摘要提及 +8.5%，表格数据显示更大优势，此处以表格具体数值为准，整体提升显著）。
- 对比 SKILL0：SKILL0 在 OOD 上仅 46.2%，而 Skill0.5 高达 87.5%（Heat 任务），证明了纯内部化在面对新技能时的僵化。
消融实验洞察：
- Internalize-Only：仅内化通用技能，OOD 性能下降至 52.8%。说明没有特定技能的动态利用，泛化能力受限。
- Utilize-Only：仅利用特定技能，ID/OOD 全面崩盘。说明缺乏通用推理基础，Agent 无法有效解析和执行复杂指令。
⚠️ 反直觉发现 ：在训练后期，简单任务占主导时，如果不进行“反捷径”惩罚，Agent 会迅速过拟合到 ID 任务的特定动作映射上，导致 OOD 性能崩塌。Skill0.5 通过对比优势机制，强行保留了 Agent 对外部技能的依赖路径。
### 工程启示- 技能分层管理：在实际构建 Agent 系统时，不要把所有知识都塞进 Prompt 或微调进模型。将“思维链/元认知”类知识内化（LoRA/全量微调），将“操作手册/API文档”类知识保留为外部检索（RAG）。
- 动态课程学习：利用任务难度作为信号，动态调整训练策略。对于完全不会的任务，优先用蒸馏建立基础；对于已经会但可能走捷径的任务，引入对抗性验证。
- OOD 准备：如果你的 Agent 需要处理不断新增的业务场景（如新电商品类、新家居环境），Skill0.5 的架构能有效避免“旧知识干扰新知识”的问题。
### 局限与展望目前方法主要在文本交互环境（ALFWorld, WebShop）验证。论文指出，未来可扩展到代码生成、多模态环境及更长视距的任务。此外，动态路由的计算开销（需额外 Rollout 评估难度）在实际高频部署中可能需要优化。
