# ⭐⭐½ LLM做科研靠谱吗？SDABench深度评测

**日期**: 2026-07-16

---

论文 : Are LLMs Ready for Scientific Discovery? A Capability-Oriented Benchmark for AI Scientists链接 : https://arxiv.org/abs/2607.11079现在的 LLM Agent 吹得天花乱坠，号称能自动跑实验、写代码、出结论。但作为工程师，我们心里都清楚： 代码能跑通不代表科学逻辑成立 。很多 Benchmark 只盯着“代码执行成功率”，却忽略了最核心的问题——模型是否真的理解了数据背后的科学假设？
这篇来自东南大学和 HKUST 的论文 SDABench 直击痛点。它不再问“你能不能写出这段 Pandas 代码”，而是问“你能不能从数据中推导出正确的因果机制”。这对正在构建科研 Agent 的团队来说，是一记清醒剂。
### 现有评测的致命盲区目前的 DataSciBench、KramaBench 等主流基准，主要评估 计算视角 的能力：特征选择、模型构建、代码执行。
这有两个严重问题：
- 混淆执行与有效性：算出结果 ≠\neq= 结果支持科学假设。
- 掩盖推理断层：一个总分无法区分模型是连基本描述都搞错，还是在复杂的因果推断上栽跟头。
科学分析服务于不同的主张（假设探索、统计推断、机制解释等），每种主张需要不同的假设和验证标准。因此，评测必须围绕**能力（Capability） 而非 操作（Operation）**展开。
### 核心设计：从“跑代码”到“测思维”
SDABench 的核心 Insight 是引用 Leek and Peng (2015) 的六问框架，将科学发现拆解为六种能力：
- 描述性 (Descriptive)：总结现象- 探索性 (Exploratory)：发现潜在模式- 推断性 (Inferential)：量化不确定性下的主张- 预测性 (Predictive)：估计未知状态- 因果性 (Causal)：评估干预的影响- 机制性 (Mechanistic)：解释产生结果的内在过程数据构建的巧思 ：
为了解决真实数据集难以覆盖所有任务类型的问题，作者构建了 SDA-Synth 。通过 LLM 生成语义图（Semantic Graph），定义变量间的代数方程或 ODE 求解器作为“隐藏机制”，再生成带噪声的数据。这样既保证了 Ground Truth 的可编程推导，又控制了变量干扰。
### 关键结果：模型在“装懂”
评测了 15 个主流模型（GPT-5.4, Claude Sonnet 4.6, Llama 3.1 等），发现令人担忧的 能力断层 。
1. 描述强，推理弱模型在处理简单的描述性任务时表现优异（GPT-5.4 达到 94.75%），但在需要假设选择的推断和因果任务上断崖式下跌。
任务类型 GPT-5.4 (OEQ) Llama 3.1-8B (OEQ) 差距分析 描述性 94.75% 10.25% 基础能力差异巨大 推断性 67.25% 3.50% 模型难以处理统计假设 因果性 34.50% 0.50% 核心短板 ：无法建立有效因果链 机制性 47.00% 0.00% 小模型完全无法理解机制⚠️ 反直觉发现 ：多选题（MCQ）并不总是比开放问答（OEQ）好。在某些任务中，提供选项反而诱导模型进行浅层模式匹配，导致性能下降。例如 Kimi K2.5 在预测任务的 MCQ 准确率仅为 25.75%（接近随机猜测），而在 OEQ 中却能正确解答。
2. 错误发生在“后半程”
作者提出了一个五阶段错误分析框架：Scope -> Variable -> Function -> Relationship -> Conclusion。
- 小模型：死在第一步，连变量都选错（Variable Error >30%）。
- 大模型：能选对变量，但死在**函数选择（Function Error）和关系建模（Relationship Error）**上。
这意味着，随着模型规模扩大，早期 grounding 错误减少了，但核心的科学推理瓶颈依然坚固。 GPT-5.4 的主要错误集中在 Function Error，说明它知道看什么数据，但不知道用什么方法处理。
### 工程启示：如何构建靠谱的科研 Agent？
- 不要迷信自动评测分数：如果只测代码执行率，你会误以为模型已经具备科学推理能力。必须引入基于任务类型的能力拆解。
- 微调策略需转变：单纯喂代码数据不够。论文显示，使用“错误类型”作为监督信号进行 LoRA 微调（FT Llama-3.1-8B Error Type），能显著提升 OEQ 准确率至 55.33%。这说明模型需要学习的是分析流程的结构，而不仅仅是语法。
- 警惕 MCQ 的虚假繁荣：在评估 Agent 的科学推理能力时，优先使用开放问答或代码执行验证，多选题容易因干扰项设计不当而产生偏差。
### 局限与展望SDABench 的合成数据虽然可控，但可能无法完全捕捉真实实验中的复杂混淆因素和测量伪影。此外，目前的错误标注只记录第一个失败点，可能会低估级联错误的严重性。
对于工程师而言，这篇论文的价值在于提供了一个 诊断工具 。当你发现 Agent 给出的结论不可信时，不要只盯着代码报错，去检查它是卡在变量选择、方法误用，还是关系建模上。这才是提升 AI Scientist 可靠性的关键路径。
