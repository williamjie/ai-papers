# ⭐⭐⭐½ 漏洞复现 Agent：策略比执行更重要

**日期**: 2026-07-07

---

论文 : Mastermind: Strategy-grounded Learning for Repository-Scale Vulnerability Reproduction链接 : https://arxiv.org/abs/2607.01764现在的 LLM Agent 在写代码、跑命令上已经很强了，但在面对仓库级漏洞复现这种复杂任务时，依然经常“瞎忙活”。这篇论文指出一个反直觉的事实： 瓶颈不在执行能力，而在战略决策。 如果只让模型盲目试错，哪怕给它最强的执行器，效率也极低。
### 痛点：执行力过剩，策略力不足在 CyberGym 基准测试中，作者发现了一个尴尬的现象。使用 GPT-5.5 作为执行器，单次尝试的成功率只有 23.5%。即便采用“最佳 8 选 1”（Best-of-8）的暴力采样策略，成功率也仅提升到 63.0%，且消耗了 1,600 次执行 rollout。
更讽刺的是，即使提供包含补丁差异和源码的 Level 3 全量上下文，成功率也没显著提升。这说明问题不在于模型“看不懂”代码，而在于它 不知道下一步该往哪看 。Agent 浪费了大量资源在无效的路径探索上，缺乏一种能够跨任务复用、且能指导具体执行的“高层策略”。
### 核心 Insight：策略是独立的学习单元Mastermind 的核心贡献在于将“规划（Planning）”与“执行（Acting）”彻底解耦。
关键直觉 ：完整的执行轨迹太长、太噪，不适合直接做强化学习。但“策略”（Strategy）——即一段描述检查哪里、构造什么输入、如何验证的自然语言计划——既紧凑又稳定。它是连接高层推理与底层执行的完美中间层。
作者提出了一个双环框架：
- 体验环（Experience Loop）：维护任务局部的经验库（Curator），记录之前的失败假设和文件位置。这是易变的、任务特定的知识。
- 策略环（Policy Loop）：训练一个可复用的规划器（Planner）。它不直接发 shell 命令，而是生成一段紧凑的策略文本（限制在 2,000 token 以内），指导冻结的执行器去行动。
这种设计的妙处在于： 执行器可以是任何现成的模型（如 GPT-5.5 或 GLM 5.1），只需训练一个轻量级的 Planner，就能提升所有执行器的表现。 这避免了为每个新模型重新微调巨大的执行网络。
### 实验结果：策略质量决定上限作者在 CyberGym 的 200 个 held-out 任务上进行了严格测试，数据非常有说服力：
方法 GPT-5.4 mini 通过率 GPT-5.5 通过率 GLM 5.1 通过率 平均 Rollouts Best-of-8 (独立采样) 43.0% 63.0% 61.0% 1,600 Iterative Improvement (迭代改进) 53.0% 77.0% 67.0% 753 Mastermind 60.0% 84.5% 71.0% 560几个关键发现：
- 策略的因果效应：在固定 GPT-5.4 mini 执行器的情况下，仅将“无策略”替换为“软预言机策略”，M7 通过率就从 23.5% 飙升到 39.5%。这证明策略本身直接决定了结果上限。
- 跨模型迁移：Mastermind 的 Planner 仅在 GPT-5.4 mini 上训练，直接冻结后用于 GPT-5.5 和 GLM 5.1，依然带来了显著增益（GPT-5.5 从 72.5% 提升至 84.5%）。这验证了“策略知识”是独立于具体模型参数的通用能力。
- 效率提升：相比 Best-of-8 的 1,600 次执行，Mastermind 仅需 560 次就达到了更高的通过率。它通过减少无效探索，实现了真正的降本增效。
### 工程启示：如何构建高效的 SE Agent对于正在构建软件工程的 Agent 团队，这篇论文提供了清晰的架构指引：
- 不要试图微调整个执行器：执行器的动作空间太大，RL 训练成本极高且容易破坏原有能力。相反，训练一个专门的“策略生成器”性价比更高。
- 显式管理短期记忆：引入类似 Curator 的模块，专门存储任务本地的失败经验和线索。不要让模型去“回忆”历史对话，而是主动检索并压缩成当前可用的上下文。
- 奖励信号要稀疏但分层：论文使用了基于里程碑（Milestone）的奖励机制。从“定位源码”到“触发崩溃”再到“双构建验证”，每一步都有对应的奖励。这种细粒度的反馈比单纯的最终成功/失败更适合引导长期任务。
### 局限与展望尽管效果显著，Mastermind 仍依赖高质量的执行器基础。如果执行器本身无法准确实现策略中的指令（例如构造错误的 PoC），Planner 的优化也会受阻。此外，目前主要验证在漏洞复现场景，其在通用代码调试或复杂系统重构中的泛化能力仍需进一步探索。
总之，Mastermind 提醒我们：在 Agent 系统中， “想清楚”比“做得快”更重要 。将策略学习从执行轨迹中剥离出来，可能是解决长程、高复杂度软件工程任务的关键路径。
