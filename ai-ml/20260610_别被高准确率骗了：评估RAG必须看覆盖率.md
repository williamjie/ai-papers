# ⭐⭐⭐½ 别被高准确率骗了：评估RAG必须看覆盖率

**日期**: 2026-06-10

---

论文 : Precision Is Not Faithfulness: Coverage-Aware Evaluation of Grounded Generation with a Complete Oracle链接 : https://arxiv.org/abs/2606.09376做 RAG（检索增强生成）或 Agent 开发的工程师，一定被“幻觉率”这个指标折磨过。通常我们只关心模型生成的内容是否准确（Precision），却往往忽略了一个致命盲区：如果模型为了求稳，只回答一句废话，它的准确率就是 100%，但这毫无用处。这篇论文用 F1 赛车数据证明： 只看准确率的评估体系，本质上是在奖励模型的“摆烂”行为。
### 痛点：现有指标为何失效？
目前的无参考忠实度（Reference-free Faithfulness）评估，如 FActScore，核心逻辑是拆解原子主张并验证真伪。这只能衡量 Precision（模型说的都对吗？）。
⚠️ 反直觉发现 ：在缺乏完整事实清单的情况下，模型可以通过“少说”来最大化得分。一个只陈述一个安全事实的模型，和一个详尽分析的模型，在纯 Precision 指标下可能得分相同。这种“奖励弃权”（Rewarding Abstention）的现象，让现有的评估基准失去了区分能力。
### 核心 Insight：引入“完整预言机”
要解决这个问题，必须引入 Recall（覆盖率）。但在开放域任务中，我们不知道“所有相关事实”是什么，因此无法计算 Recall。
作者巧妙选择了 F1 赛车遥测数据 作为测试床。因为赛车策略（进站圈数、轮胎配方、攻防结果）是由确定性的时序数据推导出的，我们可以枚举出每个决策背后 全部 的关键事实。这就构成了一个“完整预言机”（Complete Oracle），使得计算 Recall 成为可能。
### 方法拆解：Verifier-Guided Generation除了评估指标，作者还提出了一种无需参考文本的生成优化方法：
- 结构化验证器：将模型输出拆解为类型化原子主张（如进站圈、轮胎变化）。
- 双向反馈循环：验证器不仅标记错误主张（Fix these），还明确列出未覆盖的关键事实（Add these）。
- 迭代修正：利用这些结构化信号引导模型重新生成，同时提升 Precision 和 Recall。
### 关键结果：排名彻底反转在包含 7253 个决策实例的多语言基准测试中，结果令人震惊。以葡萄牙语为例：
模型 Precision (忠实度) Recall (覆盖率) F1 Score 排名变化 grok-4.3 0.89 (最高) 0.46 (最低) 0.61 Precision第1 ➔ F1倒数第1 gpt-5.5 0.87 0.51 0.65 (最高) Precision第2 ➔ F1第1数据来源：论文 Table 2可以看到，准确率最高的 grok-4.3 实际上覆盖了不到一半的关键事实。一旦引入覆盖率（F1），模型排名完全颠倒。这一现象在英语、西班牙语以及另一个独立领域（NOAA 天气预报）中均得到复现。
此外，针对“是不是提示词没写好”的质疑，作者测试了强制要求覆盖所有事实的 Prompt，结果 Recall 反而从 0.60 降至 0.47。这说明 低覆盖率是模型能力的固有缺陷，而非提示工程的问题 。
### 工程启示- 评估体系升级：如果你的业务场景有明确的结构化数据源（如金融报表、医疗记录），不要只用 LLM-as-a-Judge 看准确率。构建一个“完整预言机”，计算 F1 Score，否则你会误选那些只会说废话的模型。
- 小模型的机会：实验显示，经过微调的 Qwen2.5-3B 在 F1 得分上超越了所有前沿大模型（F1 0.982 vs 最高 0.654）。在垂直领域，专精的小模型 + 结构化验证器可能比通用大模型更具性价比。
- 自修正信号：Verifier-Guided 方法证明，利用确定性数据反馈进行自我修正，可以显著提升生成质量（gpt-5.4-mini Precision 从 0.64 升至 0.88），且无需人工标注参考文本。
### 局限与展望目前的方法依赖于能够枚举事实的领域。对于开放域问答，Recall 的分母难以定义。此外，验证器受限于预定义的 Schema，可能漏掉未建模的因果主张。未来方向包括扩展事实本体论，以及探索在更复杂场景下的覆盖率度量。
