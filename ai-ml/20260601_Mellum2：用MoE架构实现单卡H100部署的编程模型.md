# ⭐⭐⭐½ Mellum2：用 MoE 架构实现单卡 H100 部署的编程模型

**日期**: 2026-06-01

---

论文 : Mellum2 Technical Report链接 : https://arxiv.org/abs/2605.31268JetBrains 发布的 Mellum 2 并非简单的参数堆叠，而是一次针对“边缘推理成本”的精准架构手术。作为 JetBrains IDE 内嵌模型的继任者，它试图解决一个核心矛盾：如何在保持 7B 稠密模型推理速度的前提下，获得超越其的知识广度与代码生成能力。
## 痛点：稠密模型的算力天花板在开源领域，4B-14B 参数的稠密模型（Dense Models）虽然部署成本低，但在复杂代码编辑和多步推理上往往遭遇性能瓶颈。相反，超大规模混合专家模型（Mixture-of-Experts, MoE）虽然能力强，但显存占用和延迟使其难以在消费级硬件或单卡服务器（如 H100）上高效运行。
Mellum 2 的目标很明确：构建一个总参数量约 12B、但每 token 仅激活 2.5B 参数的 MoE 模型。其设计约束只有一个——在单张 H100 GPU 上的推理吞吐量必须匹敌甚至超越 Qwen2.5-7B。
## 架构拆解：为延迟而生的四个关键决策Mellum 2 的架构并非盲目创新，而是基于大量消融实验（Ablation Studies）得出的工程最优解。
-MoE 稀疏度的权衡团队测试了不同数量的激活专家。虽然仅激活 2 个专家能将延迟降低约 1.5 倍，但模型质量严重受损。最终选择 64 个专家中激活 8 个（Top-8），这是在单卡显存限制下，平衡质量与延迟的最佳甜点区。
-极致的 KV Cache 优化在高并发场景下，KV Cache 是主要瓶颈。Mellum 2 采用分组查询注意力（Grouped-Query Attention, GQA），并将 KV Head 数量激降至 4 个。消融实验显示，8 个 KV Head 会导致吞吐量显著下降，而 2 个则影响模型质量。这一设计使其在吞吐量模式下极具竞争力。
-滑动窗口注意力（SWA）的混合策略为了进一步降低长上下文推理成本，模型在每 4 层中的 3 层应用了窗口大小为 1024 的滑动窗口注意力，仅保留 1/4 的层使用全局注意力。这种“局部为主、全局为辅”的策略，使得在处理双倍长度上下文时，延迟仍能与 Qwen2.5-7B 持平。
-多 Token 预测（MTP）的双用设计模型增加了一个额外的 Transformer 层作为 MTP Head，用于预测下一个未来 token。这不仅是辅助预训练目标，更直接充当了推测解码（Speculative Decoding）的草稿模型。实验表明，MTP 仅增加了 7% 的训练时间，却在 HumanEval 上带来了 +10.4 的巨大提升。
反直觉发现 ：在优化器选择上，传统的 AdamW 在大规模 MoE 训练中并非最优。团队采用基于正交化更新的 Muon 优化器 ，配合 Moonlight 配置（额外缩放因子 0.2），在验证集损失上比 AdamW 降低了约 2.5%，且训练稳定性显著优于 Megatron 默认配置。
## 数据策略：三阶段课程学习预训练数据总量达 10.6T tokens，采用“早期网页、后期精选”的三阶段课程：
阶段 Token 量 代码占比 核心目标 Phase 1: Foundation 6.18T 23% 建立基础语言与代码理解，主要使用网页数据 Phase 2: Quality Uplift 2.79T 42% 引入高质量 SFT 数据和合成代码，提升推理能力 Phase 3: Sharpening 1.69T 59% 专注代码与数学，学习率线性衰减至零以固化知识值得注意的是，代码数据在训练中被重复使用了 3 个 epoch。对于 MoE 模型而言，高质量数据的重复暴露能显著促进专家的特化（Specialization），其效果优于单次遍历海量噪声数据。
## 性能表现：以小博大尽管每 token 仅激活 2.5B 参数，Mellum 2 在多项基准测试中超越了同量级甚至更大参数的稠密模型。
- 代码生成：HumanEval pass@1 达到 41.5%，MBPP 达到 62.4%，全面超越 OLMo-3-7B 和 Qwen3.5-4B。
- 复杂推理：在 MMLU-Pro 上得分 59.3%，大幅领先 Qwen2.5-7B (48.6%)；BBH 得分 74.9%，优于 Qwen2.5-7B (69.0%)。
- 数学能力：GSM8K 准确率达 81.7%，与 Qwen2.5-7B (81.9%) 持平。
这些数字证明，通过合理的 MoE 稀疏化和注意力机制优化，可以在不牺牲推理速度的前提下，显著提升模型在垂直领域（如软件工程）的能力上限。
## 工程启示对于希望部署本地编程助手的工程师而言，Mellum 2 提供了极具参考价值的架构范式：
- KV Head 数量对吞吐量的影响被低估了。在资源受限场景下，激进地减少 KV Heads 是提升并发能力的有效手段。
- MoE 并非越稀疏越好。在中小规模模型中，保持适度的激活专家数量（如 Top-8）对于维持推理质量至关重要。
- MTP 是免费的加速红利。集成多 Token 预测不仅提升训练效果，还能无缝支持推测解码，建议在新模型训练中默认启用。
Mellum 2 的开源（Apache 2.0）意味着开发者可以直接获取这一经过工业级验证的架构与数据配方，为构建高效、专用的代码大模型提供了坚实基座。
