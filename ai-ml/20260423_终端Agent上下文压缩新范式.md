# 终端 Agent 上下文压缩新范式

**日期**: 2026-04-23

---

论文 : A Self-Evolving Framework for Efficient Terminal Agents via Observational Context Compression链接 : https://arxiv.org/abs/2604.19572做终端 Agent 的朋友都懂一个痛：每一步命令执行后的原始输出直接塞回上下文，走几十步之后 token 成本呈二次方增长，关键是噪音太多反而把关键信号淹没了。
Manchester 大学等机构这篇 TACO 提出了一套自进化压缩框架，不用训练、即插即用，在 TerminalBench 上稳定提升 1%-4% 准确率，同时减少约 10% 的 token 开销。
## 为什么现有方案不够用终端环境的异质性是核心难点。pip 安装日志、编译 trace、测试输出、错误信息……每种场景的压缩策略完全不同。
现有方案分三类：
- 静态规则：专家手写的启发式规则（论文用了 6 条种子规则 + 200 条人工规则做对比），跨任务泛化差- Prompt 压缩：让 LLM 总结终端输出，效果不稳定- 训练方法：SWE-Pruner 需要额外微调，且只针对 SWE-Bench 场景TACO 的核心 insight 很直接： 既然压缩规则本身也是结构化知识，为什么不让它从交互轨迹里自己长出来，然后在任务之间共享？
## 方法拆解：三层规则进化TACO 的架构分三个层次，像一个不断进化的免疫系统：
### 1. 全局规则池（Global Rule Pool）
跨任务共享的结构化规则库。每条规则包含触发模式、保留模式、移除模式和保守保留边界。新规则初始置信度为 1.0，通过排名分数 Rgs(r)=cgr⋅(nr+1)R_g^s(r) = c_g^r \cdot (n_r + 1) s ​ ( r ) = c g r ​ ⋅ ( n r ​ + 1 ) 排序——置信度乘以使用次数加一。
### 2. 任务级规则选择每个新任务从全局池检索 top-k 条候选规则（论文选 k=30），LLM 根据任务描述筛选和微调后，初始化为当前任务的活跃规则集。
### 3. 任务内在线进化这才是亮点。两条进化路径：
- 新增规则：遇到未被任何规则覆盖的输出，LLM 自动生成新规则- 规则修正：通过隐式反馈检测过度压缩——如果 Agent 后续要求查看完整输出、重复执行相同命令来恢复信息，说明刚才压缩过头了。TACO 会回查触发的规则，压制它并注入更保守的替代版本任务完成后，满足条件的规则（应用次数 >= 1 且置信度 >= 阈值）写回全局池。被投诉的规则置信度清零，直接删除。

## 工程启示几个值得关注的点：
- 即插即用：TACO 适配了 Terminus-2 和 OpenHands 两种框架，接入成本不高- 收敛判据实用：用 Top-30 规则的 Retention（留存率）判断收敛，90% 阈值对应性能波动从 2.0% 降到 1.0%- 批量大小权衡：N=4 是精度和速度的平衡点，完全并行一轮自进化约 4 天- 错误输出不压缩：语法错误、异常堆栈标记为 Critical 直接保留，这个保守策略很务实## 局限- 小模型（<40B）的 token 节省有限，因为它们在复杂任务上提前失败的模式被改变了- 自进化需要多次迭代才能收敛，冷启动阶段的性能波动存在- 规则池的质量依赖 LLM 的生成能力，不同 backbone 的规则质量可能有差异总的来说，TACO 提供了一个思路：终端 Agent 的上下文管理不应该是一成不变的工程 hack，而是可以持续进化的能力。对于实际部署的终端 Agent 系统，这个方向值得跟进。
