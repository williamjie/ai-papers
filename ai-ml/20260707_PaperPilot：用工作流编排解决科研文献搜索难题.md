# ⭐⭐ PaperPilot：用工作流编排解决科研文献搜索难题

**日期**: 2026-07-07

---

论文 : Multi-Turn Agentic Scientific Literature Search via Workflow Induction链接 : https://arxiv.org/abs/2607.00597现在的 AI 科研助手大多有个通病：用户说“找这篇论文的后续工作”，它往往直接扔出一堆关键词搜索结果，或者执行一套固定的检索流水线。
这种“黑盒”式的搜索不仅难以控制，更无法处理模糊意图。PaperPilot 提出了一种新思路：把文献搜索看作**工作流归纳（Workflow Induction）**问题。
它不再依赖隐式的语言推理，而是构建可执行的有向无环图（DAG），并通过多轮对话动态调整这个 DAG。这不仅是检索效果的提升，更是 Agent 可控性的质变。
### 痛点：固定流水线无法应对复杂意图现有系统如 LitLLM、OpenScholar 等，通常采用固定的检索-合成管道。当用户需求涉及“特定方法论的延伸”或“最新基准对比”时，静态管道往往失效。
更关键的是，自然语言反馈（如“太宽泛了”）很难直接转化为检索策略的调整。Agent 往往将其视为额外的查询文本，而非对检索逻辑的修改指令。
PaperPilot 的核心洞察是： 搜索意图是 underspecified 的，需要通过交互来明确；而明确的最好方式，是直接编辑底层的检索工作流。
### 方法拆解：将搜索意图具象为 DAGPaperPilot 定义了一套类型化的操作符库（Toolset），包括关键词搜索、引文扩展、过滤、评分和重排序等。
每个节点对应一个具体算子，边代表中间数据（如论文集合、分数）的流向。这种设计带来了两个关键优势：
- 结构可解释：用户可以看到 Agent 是如何组合“引文追踪”和“时间过滤”的。
- 反馈可落地：当用户说“只看最近两年的”，Agent 直接在 DAG 中插入或修改 year >= 2024 的过滤节点，而不是重新生成整个查询。
为了训练这种能力，作者采用了两阶段监督策略：
- SFT 阶段：使用强教师模型生成的成功轨迹进行模仿学习。
- 偏好优化（DPO）：构造“损坏的工作流”作为负样本（如缺失关键节点、类型不匹配），让模型学会区分正确与错误的 DAG 结构。
### 实验结果：小模型也能打败大系统在保留的测试集上，PaperPilot-9B 的表现令人印象深刻。以下是核心指标对比：
模型/配置 Hit@5 MRR nDCG@10 工作流错误率 Qwen3.5-9B (基线) 58.0% 47.5% 26.8% 9.5% PaperPilot-9B 77.0% 59.4% 32.5% 0%可以看到，经过工作流归纳训练后，Hit@5 提升了近 20 个百分点，且工作流执行错误率从 9.5% 降至 0%。
更值得关注的是成本效益：
- OpenAI DeepResearch 单案例成本约 $6.09，Hit@5 为 72.0%。
- PaperPilot-9B 单案例成本仅 $0.15（甚至更低，取决于具体配置），但在多轮交互下 Hit@5 达到 77.0%，远超昂贵的商业方案。
反直觉发现 ：增加初始候选池规模（从 K=8 增加到 K=20）反而导致检索质量下降。Recall@50 从 0.411 降至 0.374，Hit@5 从 0.705 降至 0.660。这说明在科学文献搜索中，“少而精”的初始筛选比“大而全”更有利于下游的重排序和过滤。
### 工程启示：结构化是 Agent 落地的关键这篇论文对构建垂直领域 Agent 有三个重要指导意义：
- 显式状态优于隐式推理：让模型输出代码或 DAG，比让它直接输出文本结果更容易调试和控制。
- 偏好数据的质量决定上限：通过构造“结构性错误”的负样本进行 DPO 训练，显著提升了工作流的稳定性。这提示我们在微调 Agent 时，不仅要给正确答案，更要教它识别错误的执行路径。
- 多轮交互的价值在于“编辑”：不要为了聊天而聊天，每一轮交互都应转化为对检索策略的具体修改（如添加过滤条件、调整权重）。
### 局限与展望PaperPilot 目前依赖预定义的操作符库，可能无法覆盖所有领域的特殊搜索逻辑。此外，基准测试主要基于计算机科学文献，且使用 LLM 模拟用户反馈，真实场景下的鲁棒性仍需验证。
尽管如此，它将“意图澄清”转化为“工作流编辑”的思路，为构建可控、高效的科研 Agent 提供了一条清晰的路径。对于工程师而言，借鉴其 DAG 编排和结构化微调的方法，或许能显著提升自家检索系统的可用性。
