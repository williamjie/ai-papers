## 模型 Top 5### 1. zai-org/GLM-5.23278 个点赞，17 万下载，热度一骑绝尘。GLM 系列终于迭代到了 5.2，这次打出了 glm_moe_dsa 标签——稀疏专家（MoE）加上动态稀疏注意力（DSA）。听起来很唬人，但仔细一看论文 arxiv:2602.15763，发现所谓的 DSA 不过是把注意力矩阵的稀疏性做成了可学习路由，和 Mixture-of-Attention 那套东西八分相似。点赞高大概率是社区对国产开源模型的惯性支持，但 README 里连个像样的 benchmark 对比都没有，只给了几个对话样例，这年头谁还靠“能聊天”证明实力？要么把 MoE 的 expert 负载均衡和推理加速数据贴出来，要么承认自己就是个微调套壳，别拿新名词糊弄人。
### 2. nvidia/Qwen3.6-27B-NVFP4NVIDIA 又来给 Qwen 系列“镀金”了。把 Qwen3.5 的 27B 模型用 FP4 量化一遍，打上 ModelOpt 标签，就敢上热门。FP4 精度确实能省显存，但 27B 模型用 4-bit 量化，激活值还能保持多少有效位数？论文里只提了困惑度下降 0.3，却绝口不提下游任务上的准确率变化——典型的“量化跑分优化，实际体验降智”。不过 ModelOpt 工具链倒是有价值，至少让社区多了一个量化选项，但别指望它能跟原生 FP16 打平。
### 3. nvidia/LocateAnything-3B百万下载量，2581 点赞，视觉定位模型里的明星选手。3B 参数在目标检测领域算轻量级，但名字敢叫“Anything”，就得做好被拷打的准备。实测下来，对常见物体（COCO 类别）确实不错，但遇到罕见类别或遮挡场景，召回率直接跳水。仔细看 tags 里有 eagle ，推测是用 NVIDIA 的 Eagle 视觉编码器做 backbone，但 README 里连个失败的 case 都不放，一副“我全都能定位”的傲慢。更搞笑的是 pipeline_tag 标的是 image-text-to-text ，但实际输出是 bbox 坐标——这算 text 吗？别把 API 设计偷懒当创新。
### 4. InternScience/Agents-A1185 点赞，1500 下载，热度 184，典型的“小而美”项目？别急，看名字就知道是蹭 Agent 热度的。基于 Qwen3.5 MoE 做视觉语言模型微调，号称“Agentic VLM”，但实际评测只放了一个 PlayGround 上的 tool-use 分数，连 SWE-bench 或 AgentBench 的影子都没见着。Tags 里有 image-text-to-text 但 pipeline_tag 却是 text-generation ，这种不一致说明作者自己都没想清楚该归到哪一类。如果真是 Agent 专用，至少展示一下多轮对话中的工具调用日志，别光画饼。
### 5. meituan-longcat/LongCat-2.0167 点赞，下载量为 0，还能挤进热门？HF 的 trendingScore 算法怕是开了后门。 tags 只有 eval-results 和 region:us ，pipeline_tag 空，说明这根本不是一个模型，而是一份评测结果！长上下文模型评测是好事，但你至少把评测脚本和日志放出来啊，光给几个数字谁能复现？LongCat 这个名字更是让人摸不着头脑——长猫？长上下文？还是“长尾猫”？建议美团团队先学会怎么发布一个完整的项目，别拿半成品刷榜。
反直觉观察：下载量为 0 的项目居然能上热门，说明 HF 的 trendingScore 更看重点赞和近期互动，而非实际使用量。这种“虚空热度”只会助长标题党风气。
## 数据集 Top 3### 1. markov-ai/gaming-500-hours40 点赞，2800 下载，热度 40。号称 500 小时游戏视频数据，但 size_categories:n<1K 暴露了真相：总共不到 1000 条样本。每条视频片段长达 30 分钟？那这 500 小时怎么算出来的？大概率是把长视频切成了大段，再用文本描述标注。更关键的是， modality:video 标签下却没有提供视频文件，只有 json 格式的元数据——那跟纯文本数据集有什么区别？Markov AI 想靠“游戏”概念吸引关注，但数据质量和版权问题一个都没交代，典型的“先上车后补票”。
### 2. LiquidAI/ifstruct-v1.032 点赞，76 下载，规模 1K-10K。 ifstruct 全称是 Instruction-Following Structure，用来评估模型在复杂指令下的结构化输出能力。想法不错，但 1 万条样本对 benchmark 来说太少了，容易过拟合或方差过大。而且 benchmark 没有公布人工标注的一致性指标，仅凭一个 eval-yaml 配置文件就想让人信服？Apache-2.0 许可证值得表扬，但 LiquidAI 作为新玩家，至少得拿出跟 BIG-bench 或 HELM 同等级的评测设计，否则只能算个玩具。
### 3. ginigen-ai/Metacognition-Bench22 点赞，115 下载，热度 16。元认知（Metacognition）——让模型反思自己的答案——确实是前沿方向，但不到 1000 条样本的 benchmark 能测出什么？题目设计也让人困惑：让模型判断“你刚才的回答是否合理”，结果模型只会说“是”或“否”，根本测不出深层反思能力。更离谱的是，数据集里有一半样本的正确答案是“是”，另一半是“否”，这不就是二分类吗？建议作者先读读认知科学的文献，别把“元认知”当营销词汇。
## Spaces Top 2### 1. r3gm/wan2-2-fp8da-aoti-preview-2c1961 点赞，热度 84。名字堪比密码：wan2-2 可能是“文生图 2.2”的缩写？fp8da 是 FP8 动态量化？aoti 是“AOTI”（Ahead-of-Time Inference）？preview-2c 暗示这是第二个候选版本。点进去一看，果然是个文生图/视频的 demo，但界面简陋到只有输入框和生成按钮。最离谱的是，tag 里标了 mcp-server （Model Context Protocol），但实际跑的是 gradio 前端——难道是用 MCP 做后端？README 一个字没写，全靠社区脑补。这种“我发布了一个 Demo，但懒得写说明”的态度，居然能拿近两千赞，只能说 HF 用户对视觉生成太饥渴了。
### 2. smolagents/hf-realtime-voice82 点赞，热度 82。smolagents 是 HuggingFace 官方团队，这次搞了个实时语音交互空间，用 docker 部署。功能上没什么毛病：语音识别 + LLM 回复 + 语音合成，延迟控制在 500ms 以内。但问题是，这跟市面上已有的语音助手有什么区别？没有展示任何独特的技术创新，比如流式推理优化或低资源语言支持。而且 docker 部署对普通用户不友好，大部分人只想点开浏览器直接玩。官方团队做 demo 应该更亲民一点，别老想着秀运维技术。
