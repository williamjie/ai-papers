# 拒绝无效搜索：并行多模态Agent的效率革命

**日期**: 2026-05-11

---

论文 : HyperEyes: Dual-Grained Efficiency-Aware Reinforcement Learning for Parallel Multimodal Search Agents链接 : https://arxiv.org/abs/2605.07177多模态搜索Agent如果还在像人一样“一个接一个”地查资料，那不仅慢，而且贵。这篇来自小红书和剑桥大学的论文提出了 HyperEyes ，核心逻辑只有一个： “搜得更宽，而不是更深”（Search wider, not longer） 。对于包含多个实体的查询，它强制模型在同一轮对话中并行定位并搜索所有目标，彻底告别传统的串行“裁剪-搜索”循环。
### 为什么传统方案不行？
现有的多模态Agent（如 DeepEyes, MMSearch-R1 等）大多遵循 ReAct 范式，即串行调用工具。遇到复杂问题（例如：“图中哪只狗有蹼，但最初不是为游泳培育的？”），传统模型会先裁剪一只狗，搜索，再裁剪另一只，再搜索。
这带来两个致命工程痛点：
- 延迟爆炸：每次工具调用都需要一次模型前向传播和网络往返，串行意味着延迟线性叠加。
- 噪声累积：中间步骤的错误会污染上下文，导致后续推理偏离轨道。
HyperEyes 的直觉很朴素：如果问题可以分解为独立的子检索，为什么要一个个查？它提出将视觉定位（Grounding）和检索（Retrieval）融合为一个原子动作 Unified Grounded Search (UGS) ，允许模型在一个回合内并发处理多个实体。
### 方法拆解：双粒度效率感知强化学习仅仅拥有并行能力是不够的。如果模型缺乏效率激励，它可能会退化为“暴力并行”——一次性发出几十次搜索，虽然快但毫无意义。HyperEyes 的核心贡献在于一套 双粒度效率感知强化学习框架 ，专门解决“如何高效并行”的问题。
#### 1. 宏观层面：TRACE 动态效率参考传统的奖励函数要么只看对错（Accuracy），要么用固定阈值惩罚工具调用。固定阈值太死板：对于简单问题太松，对于复杂多跳问题太紧。
HyperEyes 设计了 TRACE (Tool-use Reference-Adaptive Cost Efficiency) 奖励机制。
- 动态基准：它不预设固定的工具调用次数上限，而是以训练初期在中等难度样本上首次成功的轨迹作为初始参考值 t^c\hat{t}_c^c​。
- 单调收紧：随着训练进行，参考值会根据当前策略在每一轮（Epoch）中找到的最短成功轨迹进行更新：t^c(e+1)=min⁡(t^c(e),tc(e+1))\hat{t}_c^{(e+1)} = \min(\hat{t}_c^{(e)}, t_c^{(e+1)})^c(e+1)​=min(t^c(e)​,tc(e+1)​)。
- 防作弊机制：为了防止模型为了刷分而在单轮内无节制地并行调用（例如一次搜100次），TRACE 同时约束总调用次数 tst_s​，只有当轮次 tct_c​ 和总次数 tst_s​ 都在合理范围内时才给予正奖励。
这种设计相当于给模型设定了一个“不断进化的及格线”，逼迫模型在保持准确率的同时，自发寻找更紧凑的并行路径。
#### 2. 微观层面：OPD 失败轨迹蒸馏RL 奖励通常是稀疏的（只有最后答对或答错）。如果模型在并行搜索中前9步都对，最后一步错了，传统的 RL 会惩罚所有步骤，导致模型不知道哪里错了。
HyperEyes 引入了 On-Policy Distillation (OPD) ，但有一个关键限制： 仅应用于失败的轨迹（Failed Rollouts） 。
- 它使用一个更强的教师模型（Teacher）在 token 级别提供密集的监督信号。
- 通过最小化学生模型与教师模型在失败轨迹上的 KL 散度，学生模型可以学习教师模型在中间推理步骤中的正确模式，而不需要承担教师模型的高推理成本。
- 这解决了信用分配（Credit Assignment）难题：即使最终结果错误，正确的中间推理步骤也能得到正向引导。
#### 3. 数据合成：Progressive Rejection Sampling为了训练这种高效策略，数据至关重要。论文构建了一个 Parallel-Amenable Data Synthesis Pipeline 。
- 通过 Progressive Rejection Sampling (PRS)，模型在逐渐收紧的轮次预算下进行采样，只保留那些在最少轮次内成功的轨迹。
- 这种“优胜劣汰”的数据筛选，确保了冷启动（SFT）阶段模型就内化了“零冗余”的并行行为。
### 关键结果：精度与效率的双赢在六个基准测试上的表现证实了并行搜索的优势。以下是 HyperEyes-30B (RL) 与最强开源竞品 VDR 的对比：
模型 平均准确率 (Avg Acc) 平均工具调用轮次 (Avg Turns) 提升幅度 VDR 54.1% 11.6 - HyperEyes-30B 64.0% 2.2 +9.9% Acc, 5.3x 更少轮次- 精度提升：HyperEyes-30B 比 VDR 高出 9.9 个百分点。
- 效率飞跃：工具调用轮次从 11.6 降至 2.2，减少了 5.3 倍。这意味着在相同时间内，HyperEyes 能处理更多查询，且上下文窗口压力大幅降低。
- 成本感知得分 (CAS)：在 IMEB 基准上，HyperEyes-30B 的 CAS 得分为 0.910，远超第二名 WebWatcher 的 0.059，证明了其在“准确率-成本”权衡上的绝对优势。
此外，HyperEyes-235B 甚至接近了闭源模型 Gemini-3.1-Pro 的表现，同时保持了极低的推理成本。
### 工程启示- 并行是刚需，但需要引导：简单的并行工具调用不会自动带来效率提升，必须通过 RL 显式优化效率奖励。
- 数据质量 > 数据数量：经过严格过滤的 30k 高质量轨迹，效果优于 121k 原始数据。在 Agent 训练中，清洗“冗余步骤”比增加样本量更重要。
- 失败也是学习机会：OPD 仅用于失败轨迹的设计非常巧妙，既利用了强模型的推理能力，又保护了成功轨迹的并行策略不被稀释。
### 局限与展望HyperEyes 目前主要针对多实体并行搜索场景。对于高度依赖严格逻辑链、无法分解的单跳或多跳推理，串行搜索可能仍是必要的。未来的方向可能是混合架构：让模型学会判断何时“并行搜”，何时“串行想”。
