论文 : Decentralized Multi-Agent Systems with Shared Context链接 : https://arxiv.org/abs/2606.10662当前的大模型多智能体系统（Multi-Agent Systems, MAS）大多采用“中央集权”模式：一个主控 Agent 负责拆解任务、分发子任务并汇总结果。这种架构在子任务数量增加时，主控节点极易成为通信和整合的性能瓶颈。斯坦福大学提出的 DeLM 框架，通过引入“共享验证上下文”和“任务队列”，实现了真正的去中心化协调，不仅提升了推理精度，还大幅降低了 Token 成本。
### 痛点：为什么中央协调行不通？
现有的 MAS 框架（如 Claude Code Subagents、AOrchestra）虽然能并行执行子任务，但协调过程依然是串行的。每个子 Agent 的发现必须回传给主控 Agent，由后者决定如何合并并广播给其他子 Agent。这带来了两个致命问题：
- 通信瓶颈：随着 Agent 数量增加，信息交换变成串行队列，进度共享严重滞后。
- 信息失真：主控 Agent 在路由过程中可能稀释、遗漏或扭曲关键细节，导致有用进度丢失。
⚠️ 核心 Insight ：并行执行不等于并行进度共享。DeLM 的核心直觉是将协调从“基于提示的路由”转变为“基于状态的管理”。
### 方法拆解：DeLM 的三大支柱DeLM 不再依赖中央控制器，而是通过以下三个组件实现异步协作：
- 并行 Agent 与任务队列：Agent 从全局任务队列中异步领取子任务，无需等待主控指令。
- 共享验证上下文（Shared Verified Context）：这是 DeLM 的核心通信基质。Agent 读取积累的进度，进行本地推理后，将紧凑且经过验证的更新写回共享上下文。一旦更新被采纳，所有 Agent 均可复用这一状态，无需通过中央节点中转。
- 压缩与准入验证：
分层压缩：采用 原始内容 -> 摘要 (Si) -> 要点 (Gi) 的层级结构。Agent 默认读取轻量级的要点（Gist），仅在需要时按需展开（Unfold）详细证据，类似操作系统的“需求分页”机制。
- 准入验证：更新在写入共享上下文前，必须经过 LLM 验证器检查，确保其有证据支持。这防止了错误信息污染全局状态，误导后续 Agent。

### 工程启示：如何复用这一设计？
DeLM 的成功揭示了多智能体系统设计的几个关键原则：
- 状态优于消息：不要试图通过复杂的消息传递协议来协调 Agent，而是建立一个单一的、可信的全局状态源。
- 失败也是资产：在 DeLM 中，失败的假设（如“修改打印层不影响输出”）被验证后写入共享上下文，后续 Agent 可直接避免重复踩坑，极大提升了搜索效率。
- 按需加载细节：对于长文本或大型代码库，不要一次性加载所有上下文。使用分层摘要和按需展开机制，可以显著降低 Token 消耗并减少噪声干扰。
### 局限与展望尽管 DeLM 表现强劲，但在需要精确行级聚合的任务（如 OOLONG 基准）中，纯对话式 Agent 不如基于代码执行的方法（RLM）。论文指出，DeLM 可作为协调层与程序化推理系统结合，发挥各自优势。未来工作可能集中在优化验证器的效率以及处理更复杂的依赖关系上。
