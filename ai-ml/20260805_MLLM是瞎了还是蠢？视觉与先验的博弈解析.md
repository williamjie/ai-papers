# ⭐⭐⭐½ MLLM是瞎了还是蠢？视觉与先验的博弈解析

**日期**: 2026-08-05

论文 : Seeing or Knowing? Visual Context Sensitivity in Multimodal Large Language Models链接 : https://arxiv.org/abs/2607.26326当 MLLM 面对“五只腿的马”时回答“马有四条腿”，我们常默认它“没看清”。但本文通过严谨的实验拆解揭示：模型其实看见了，只是缺乏一套稳定的机制来在“视觉证据”与“参数先验”之间切换。
这对工程师意义重大。如果瓶颈不在感知而在利用，那么盲目升级 Vision Encoder 可能是徒劳的，我们需要的是更精细的控制手段。
## 问题与动机：感知的幻觉 vs 利用的失败当前 MLLM 的核心痛点在于：当视觉输入与预训练知识冲突时，模型表现极不稳定。
学界通常归咎于 H1（感知失败）：认为 Vision Encoder 丢弃了高频细节，导致信息在传入 LLM 前就已丢失。因此，主流解法是堆叠更强的视觉编码器或混合多模态特征。
然而，作者提出了反直觉的 H2（利用失败）：视觉证据其实完整保留在模型中，但模型缺乏一个可控制的“开关”，无法根据指令决定是信任图像还是信任常识。
⚠️ 关键洞察 ：如果模型连“忽略图像”的指令都无法执行（例如面对红色西瓜仍回答红色而非绿色），那这就不是感知问题，而是控制策略的缺失。
## 方法拆解：从重建到子空间干预为了验证 H2，作者设计了一套严密的诊断流程，核心在于将“看见”与“使用”彻底解耦。
### 1. 生成式探针：证据还在吗？
传统评估混淆了感知与利用。作者采用 图像重建 技术，仅从冻结 MLLM 的最后一层图像 Token 中重建图像。
- 设计直觉：如果重建出的图像保留了反事实属性（如五只腿），说明信息从未丢失。
- 实验设置：使用 Metaquery 框架，连接器仅在真实图像上训练，确保重建结果纯粹来自 MLLM 的表示，而非解码器的先验补全。
### 2. WhatIfVis 基准：双向敏感性测试作者构建了包含 3,049 个样本的 WhatIfVis 基准，涵盖空间、颜色、计数、大小、重量五个维度。
- 核心指标 PairAcc：要求模型在同一个样本上，既能听从“只看图”指令给出视觉答案，又能听从“忽略图”指令给出先验答案。这比单一准确率更能暴露模型的 brittleness（脆弱性）。
### 3. 子空间干预：寻找控制旋钮基于激活补丁（Activation Patching），作者定位了模型内部处理“视觉 vs 先验”权衡的关键层，并发现了一个 一维子空间向量 。
- 技术直觉：通过向残差流注入特定方向的标量值，可以在不修改权重、甚至不提供提示词的情况下，强制模型偏向视觉或先验。
## 关键结果：数字背后的真相实验数据有力地支持了 H2 假设，并揭示了当前 MLLM 的深层缺陷。
### 1. 视觉证据被完整保留在重建实验中，反事实属性（如异常腿数）的保留率极高：
- Gemma-4-E2B-IT: 97.8%- Qwen3.5-4B: 97.8%- Qwen2.5VL-3B: 93.4%结论 ：粗粒度视觉证据在 LLM Backbone 中完好无损。失败源于“用不上”，而非“看不见”。
### 2. 原生模型缺乏控制力在未微调（Vanilla）状态下，模型对指令的遵循极差：
- 宏观 PairAcc: 仅 14.7%。
- 任务差异：颜色等直接感知任务稍好，但涉及推理的重量、计数任务几乎为零。

- 规模效应：随着模型增大，这一差距不仅未缩小，反而扩大（Qwen2.5-VL 从 9.1pp 扩至 20.6pp）。
## 工程启示- 别只盯着 Encoder：如果你的应用需要模型严格遵循图像细节（如 OCR、图表分析），升级 Vision Encoder 收益有限。重点应放在后处理或微调上，以增强“利用”能力。
- 微调是必要手段：原生 MLLM 缺乏稳定的视觉敏感性策略。对于关键任务，使用类似 WhatIfVis 的数据进行 SFT 能显著提升可控性（从 14.7% 提升至 52.7%）。
- 干预向量的潜力：虽然目前子空间干预效果不如 SFT，但它提供了一种“零样本”控制思路。在无法微调的场景下，定位关键层并注入特定向量可能成为未来 Agent 系统的一种轻量级控制手段。
## 局限与展望- 推理任务瓶颈：Count 和 Weight 等需要多跳推理的任务，即使经过 SFT 提升有限。这说明模型不仅缺乏控制开关，还缺乏将视觉线索转化为物理判断的推理能力。
- 架构依赖性：不同架构（Transformer vs Linear Attention）的关键层位置不同，干预向量不具备跨模型通用性。
这篇论文打破了“MLLM 视觉弱是因为编码器差”的迷思，将问题精准定位到 上下文敏感性的控制机制 上。对于追求高可靠性的多模态应用，理解并干预这一机制比单纯堆砌算力更具工程价值。

挑刺:
- 遗漏 PairAcc 的两种评分器区分：原文明确区分 Exact-Match 和 Probability 两种 PairAcc（Section 4.2），且主结果基于概率评分器。博文在“关键结果”表中直接给出 14.7% 等数值，却未注明使用的是概率评分器，读者可能误以为是精确匹配结果。原文中精确匹配下基线仅 8.2%，概率评分器更宽松，这种混淆会影响对模型实际可控性的判断。
- “激活补丁”说明过于简略且顺序有误：博文在“方法拆解 - 子空间干预”中说“基于激活补丁定位了关键层，并发现了一个一维子空间向量”。但原文中激活补丁是在 SFT 模型上先定位关键层（Section 4.4），然后才从这些层学习一维子空间（Section 5）。博文将两步合并，且未提及“先 SFT 再定位”的前提（因为 vanilla 模型满足双意图的样本太少无法补丁），可能让读者误以为子空间可直接从原生模型导出。
- 遗漏“视觉 vs 文本”差距的细粒度定位：博文仅给出文本 43.4% 与图像 14.7% 的差距，但原文进一步拆解出差距几乎全部来自“遵循证据”意图（context intent 差 28.2pp），而“忽略证据”意图（prior intent）仅差 0.6pp（Table 5）。这一细粒度分析对理解“模型能用文本跟随证据却不能用图像”至关重要，博文未提及。
