# ⭐⭐⭐½ 把经验写成代码：HASP 让 Agent 技能可执行

**日期**: 2026-05-21

论文 : Harnessing LLM Agents with Skill Programs链接 : https://arxiv.org/abs/2605.17734Agent 最大的痛点是什么？不是模型不够聪明，而是它太“固执”且缺乏肌肉记忆。现有的 Agent 系统（如 ReAct）通常将过往经验作为文本提示注入 Prompt。这种“建议式”的技能往往被模型忽略，或者因为缺乏明确的触发机制而在关键时刻掉链子。HASP 这篇论文的核心洞察非常犀利：与其让模型去“读”技能，不如把技能变成可执行的 程序函数（Program Functions, PFs） ，直接在推理循环中进行干预。
### 痛点：文本技能是“软约束”
传统方法将经验抽象为文本（例如：“不要过早下结论”），注入到 Prompt 中。这存在两个致命问题：
- 缺乏时效性：文本无法精确指定在哪个状态（State）触发。
- 缺乏强制性：模型可能“听懂了但没做到”，导致中间步骤依然犯错。
HASP 认为，技能不应只是被动指南，而应是主动的 护栏（Guardrails） 。
### 方法拆解：从“建议”到“拦截”
HASP 的核心设计是将技能转化为 Program Functions (PFs) 。每个 PF 包含两个关键接口：
- should_activate：判断当前 Agent 状态和候选动作是否需要干预。
- intervene：如果触发，直接修改下一个动作（Action Override）或注入修正上下文（Context Injection）。
设计直觉 ：
这种设计将“决策”与“修正”解耦。基础策略（Base Policy）负责提出动作，而 PF 作为外部控制层（Harness），在动作执行前进行拦截。例如，当检测到 Agent 试图在未验证证据的情况下输出最终答案时，PF 会直接将其动作重写为“再次搜索”，而不是仅仅在 Prompt 里提醒它“请注意验证”。
HASP 的模块化体现在三个维度：
- 推理时干预：直接修改动作，无需训练。
- 后训练内化：利用 PF 干预产生的结构化日志（原始动作 vs 修正动作），通过监督微调（SFT）、拒绝采样（RS）或在线策略蒸馏（OPD）让模型学会这些技能。
- 自我进化：从失败案例中总结新 PF，经过语法验证和教师审核后加入技能库。
### 关键结果：数据不会撒谎HASP 在无需大规模强化学习的情况下，取得了显著的性能提升。以下是基于 Qwen2.5-7B-Instruct 的关键数据对比：
1. 推理时干预（Training-free）
仅靠 PF 拦截，无需任何模型权重更新，效果已大幅超越基线：
- Web 搜索推理：平均准确率从 ReAct Agent 的 31.2% 提升至 51.0%（+25.0%）。加入辅助教师选择 PF 后，进一步提升至 56.2%。
- 数学推理：平均准确率从 Prompt-Only Skills 的 32.8% 提升至 35.9%。
- 代码生成：平均 pass@1 达到 63.4%，加入教师辅助后达到 68.7%。
2. 后训练内化（Training-based）
将 PF 干预产生的数据用于训练，模型能够“学会”这些技能：
- Web 搜索：结合技能库进化的拒绝采样（HASP-Evolve + RS）达到 60.3%，比基线 Search-R1 高出 30.4%。
- 代码生成：HASP-Evolve + RS 达到 69.9% pass@1，优于大多数基于 GRPO 的基线方法。
3. 机制分析- 干预类型：65.1% 的干预是直接修改动作，34.9% 是注入上下文。这说明直接控制动作比单纯给提示更有效。
- 信号重要性：消融实验显示，PF 评分中的“时机（Timing）”、“模式（Mode）”、“正确性（Correctness）”和“结果（Outcome）”四个信号缺一不可。去除任何一个信号，性能都会下降 7-15 个点。
- 过滤必要性：严格的 PF 过滤（可执行性验证 + 教师审核）至关重要。无过滤的技能库进化会导致性能从 60.3% 暴跌至 36.3%，证明噪声技能会严重干扰 Agent。
### 工程启示- 结构化经验优于文本提示：在构建 Agent 系统时，尝试将高频错误模式转化为可执行的代码逻辑（如正则匹配、状态机检查），而非仅仅依赖 Prompt Engineering。
- 干预即数据：PF 干预过程产生的“原始动作-修正动作”对，是极高质量的监督数据。利用这些数据进行的 SFT 或 RS，比传统的 RLHF 更稳定、更高效。
- 技能库需要“卫生管理”：HASP 证明了技能库的进化必须伴随严格的过滤机制。否则，冗余或错误的技能会迅速污染系统，导致性能倒退。
### 局限与展望HASP 目前依赖人工或教师模型进行 PF 的初始化和审核，自动化程度仍有提升空间。此外，在数学推理任务上，虽然优于基线，但与顶级专用模型仍有差距，说明 PF 在处理纯逻辑推导时的泛化能力有待加强。未来方向可能在于如何实现 PF 的完全自动生成与自验证，进一步降低人工成本。
