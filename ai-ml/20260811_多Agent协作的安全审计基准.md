# ⭐⭐⭐½ 多Agent协作的安全审计基准

**日期**: 2026-08-11

---

论文 : WeClawArena: An Auditable Sandbox and Benchmark for Cross-User Agents Collaboration and Security in Human-Centered Agent Networks链接 : https://arxiv.org/abs/2608.03499当 AI 代理（Agent）从“单兵作战”走向“多用户协作网络”，安全边界变得模糊。这篇论文提出了 WeClawArena，一个针对跨用户代理协作的可审计沙箱和基准测试平台。它填补了现有工具使用基准在“多方所有权”和“攻击溯源”上的空白。
### 痛点：现有基准的盲区现有的 Agent 基准（如 τ\tau -bench, GAIA）主要关注单用户环境下的任务完成率。它们假设代理拥有完整的环境权限，或者在一个共享沙箱中运行。
但在真实场景中，代理代表不同的人类主人工作。每个代理只能访问自己的文件系统、数据库和政策约束。这种“个人工作空间”既是完成任务的工具，也是隐私和权限的边界。
现有方案无法回答三个关键问题：
- 代理能否在信息碎片化且受限于各自工作空间的情况下完成协作？
- 当恶意攻击通过正常的协作通道渗透时，会产生什么危害？
- 我们能否通过运行时证据（Runtime Evidence）审计出是谁、通过哪条消息或工具调用导致了最终的危害？
### 方法拆解：将“工作空间”作为约束面WeClawArena 的核心 Insight 是将**个人工作空间（Personal Workspace）**形式化为任务状态的一部分，而不仅仅是背景环境。
1. 结构化任务定义论文定义了包含人类主人、代理角色、资源、工具和政策的工作空间节点。每个任务实例是一个多部分图结构，要求代理在不跨越工作空间边界的前提下，结合局部信息完成全局目标。
2. 攻击向量与危害表面基准将攻击分为四类危害表面：
- 协作危害：目标劫持、错误共识。
- 安全危害：工具滥用、证据投毒。
- 隐私危害：受保护信息越界泄露。
- 治理危害：无效授权路径、缺失同意书。
每个基础任务（共 124 个）扩展为 5 个变体：1 个良性对照 + 4 种攻击向量变体，总计 620 个场景。这种配对设计允许我们在相同任务背景下，分离评估“任务效用”和“攻击成功率”。
3. 可审计的沙箱运行时沙箱基于 Docker 模拟每个用户的工作空间，并通过网关接口记录所有消息、工具调用、资源操作和决策路径。关键在于，它记录了 有界运行时证据 ，使得事后审计成为可能。
反直觉发现 ：任务成功（Utility）与攻击抵抗（Security）并不完全正相关。代理可能完成了可见任务，但泄露了预算上限或接受了无效授权；反之，代理可能因拒绝恶意输入而失败，但这在安全上是正确的行为。因此，论文将 TSR（任务成功率）和 ASR（攻击成功率）分开评估。
### 关键结果：模型表现分化明显实验覆盖了议价、招标、旅行、SWE-Workspace、临床和交易六个领域。以下是主要模型在所有变体上的任务成功率（TSR）对比：

- 领域异质性：Travel 和 Bargaining 区分了顶级模型与其他模型，而 SWE-Workspace 即使对最强模型（Opus 4.7）也极具挑战，TSR 仅为 34.0%。
- 攻击抵抗差异：在宏观向量攻击抵抗率（1 - ASR）上，Claude Opus 4.7 表现最稳健。开源模型集群的抵抗率普遍较低。
- 危害表面差异：治理（Governance）和安全（Security）维度的攻击成功率最高，而协作（Collaboration）维度的攻击成功率最低。这表明代理在遵循显式权限和工具安全上比在复杂社会共识中更容易出错。
### 工程启示- 分离评估指标：在部署多 Agent 系统时，不要仅看任务完成率。必须引入独立的攻击成功率和审计日志分析，以识别“带毒的成功”。
- 工作空间隔离是基础：模拟真实的生产环境，每个 Agent 应有独立的文件系统、数据库和策略约束。共享沙箱会掩盖真实的权限漏洞。
- 证据链的重要性：WeClawArena 证明了记录完整的运行时轨迹（消息、工具调用、资源变更）对于事后审计至关重要。没有这些证据，无法区分是代理能力不足还是遭受了攻击。
### 局限与展望目前基准依赖于 LLM-as-a-judge 进行攻击成功率的判定，虽然使用了有界证据包，但仍存在主观性风险。此外，SWE-Workspace 等领域的高难度表明，当前模型在复杂代码审查和权限验证方面仍有巨大提升空间。未来工作可探索更细粒度的策略执行引擎，以及针对特定危害表面的防御微调技术。
