# ⭐⭐⭐½ 别堆字数了：扩散模型的文本条件缩放定律

**日期**: 2026-08-03

---

论文 : Scaling Properties of Text Conditioning in Visual Generation链接 : https://arxiv.org/abs/2607.29679现在的文生图模型遇到复杂指令就拉胯，大家第一反应往往是“让 LLM 把 prompt 写得更长、更详细”。
但这篇来自 ByteDance Seed 的论文直接泼了一盆冷水： 单纯增加自然语言（Natural Language, NL）的长度，不仅不能提升生成质量，反而会导致性能下降。
作者通过严谨的控制变量实验发现，真正决定扩散模型训练损失（Diffusion Loss）的，不是 Token 的数量，而是 Prompt 中蕴含的 图像接地信息量（Image-grounded Information） 。
### 痛点：为什么“详细”没用？
在 LLM 时代，我们习惯了“上下文越长，理解越深”。但在文生图中，这个直觉失效了。
作者做了一个固定骨干网络的探针实验（Figure 3）：
- 用同一张参考图，生成不同长度的 NL 描述（从 470 到 2130 tokens）。
- 保持实体和关系不变，只是修辞上更啰嗦。
- 结果发现，重建质量（DINOv3/SigLIP2 相似度）完全停滞。
⚠️ 反直觉结论 ：当 NL 描述超过一定长度后，所有开源模型（Qwen-Image, Hunyuan, FLUX 等）的表现甚至不如它们自己最短的 Caption。
这是因为自然语言存在“信息饱和度”。啰嗦的文字并没有增加新的视觉约束，反而引入了噪声和歧义，导致扩散模型在训练时接收到的监督信号变弱。
### 核心 Insight：结构化即真理既然 NL 不行，作者提出了**结构化 Prompt（Structured Prompt, SP）**方案。
SP 本质上是一个 JSON 格式的 typed schema，将视觉变量拆解为明确的字段：
- 全局字段：场景、风格、光照。
- 元素字段：每个物体的 ID、属性、动作、边界框（BBox）、深度。
- 关系字段：物体间的空间或逻辑关系。
设计直觉 ：扩散模型本质上是像素预测器。JSON 结构强制将“视觉事实”与“自然语言修辞”解耦。每一个新增的字段（如 BBox 坐标）都直接对应图像中的具体像素区域，提供了高信噪比的监督信号。
### 关键发现：文本条件的缩放定律作者定义了两个指标来量化 Caption 的信息量：
- GPG (Grounded Perplexity Gain)：白盒指标，衡量看到图像后，Caption 在 VLM 下的似然增益。
- ED (Effective Detailness)：黑盒指标，基于属性匹配的 F0.5 分数。
通过控制变量训练（固定模型、数据、算力，仅改变 Caption 格式），作者发现了惊人的 线性缩放定律 ：
信息量指标 与收敛 MSE Loss 的关系 相关系数 (r) GPG 近似线性负相关 -0.984 ED 幂律负相关 ( MSE∝ED−0.207MSE \propto ED^{-0.207} E D − 0.207 ) -0.971这意味着： Caption 包含的有效视觉信息越多，扩散模型的训练损失越低。 这种相关性极强，甚至可以用来预测新 Caption 格式的训练效果，无需实际跑训。
### 工程落地：Diffusability × Promptability论文将系统性能拆解为两个因子：
- Diffusability（可扩散性）：Caption 格式暴露信息的能力。通过 SP 结构显著提升。
- Promptability（提示能力）：LLM 从用户简短请求生成完整 SP 的能力。
落地建议 ：
- 训练侧：不要只用 NL Caption 微调。构建包含 BBox、深度、材质等字段的 SP 数据集，能显著降低 Loss。
- 推理侧：使用 LLM 作为 Prompter，将用户意图转换为 SP。作者通过监督微调（SFT）和验证门控的强化学习（Verifier-gated RFT），让 LLM 学会“脑补”合理的视觉细节。
实验显示，该端到端系统在组合性、推理和世界知识基准上，击败了几乎所有开源模型，并接近或超越最强闭源模型。
### 局限与展望- 标注成本：构建高质量的 SP 训练数据需要 VLM 结合专用专家模型（如 Sapiens, SAM2），流水线复杂。
- 模型特异性：目前的缩放定律是在 BAGEL 骨干上校准的，不同架构可能需要重新拟合系数。
### 总结对于工程师而言，这篇论文的价值在于打破了“长 Prompt 等于好效果”的迷思。
如果你想提升文生图模型的指令遵循能力， 不要只调大 LLM 的上下文窗口，而要设计更结构化的中间表示。 让模型看到“坐标”和“材质”，而不是更多的形容词。
