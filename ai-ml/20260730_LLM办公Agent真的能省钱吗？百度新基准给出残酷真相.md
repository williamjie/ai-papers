# ⭐⭐½ LLM办公Agent真的能省钱吗？百度新基准给出残酷真相

**日期**: 2026-07-30

---

论文 : OmegaUse-OfficeVal: Benchmarking LLM Agents on Long-Horizon Office-Suite Tasks with Economic Grounding链接 : https://arxiv.org/abs/2607.27155当我们在谈论“AI替代白领”时，往往陷入一种技术自嗨：模型能打开Excel吗？能生成PPT吗？
这些测试太短、太简单，完全无法反映真实职场中那些耗时两三个小时的复杂文档处理需求。
百度团队发布的 OmegaUse-OfficeVal 基准测试，直接把大语言模型（LLM） Agent 扔进了真实的“长期办公任务”泥潭里，并引入了一个极其硬核的维度： 经济账 。
### 痛点：现有评测都在“耍流氓”
现有的办公自动化评测（如 OfficeBench）大多关注单一操作或合成工作流。它们不问代价，只问对错。
更糟糕的是，通用生产力基准（如 GDPVal）虽然涉及真实任务，但往往不公开完整数据，且缺乏任务级别的经济标注。
这意味着我们根本不知道：让 Agent 花 5的推理成本去解决一个原本只需5 的推理成本去解决一个原本只需 2 人力就能搞定的问题，到底是进步还是退步？
OmegaUse-OfficeVal 的核心 Insight 非常直接： 办公能力的终极评判标准不是“完成率”，而是“性价比” 。
### 方法拆解：用代码算账，而非让模型互评这篇论文最值得工程借鉴的，是其 基于代码的验证协议（Code-based Verification Protocol） 和 经济锚定机制 。
-真实长程任务：
收集了 100 个来自一线从业者的真实需求。平均每个任务需要人类耗时 2.32 小时完成。这不再是“把字体改成宋体”，而是“根据模板重构异常审查报告并添加封面”。
-双重经济信号：
人力时间（Human Labor Time）：通过激励协议，记录至少两名标注员完成任务的最短时间均值。
- 任务价格代理（Task Price Proxy）：结合从业者提供的实际外包报价和专家估算，给出每个任务的市场价值。平均单价约 $6.86。
-拒绝 LLM-as-Judge：
作者敏锐地指出，用前沿模型当裁判是不稳定的。随着模型迭代，昨天的“优秀”今天可能变成“平庸”。
因此，他们将细粒度评分标准转化为可执行代码。每个任务平均有 20.09 个检查项，涵盖可用性和任务完成度。
⚠️ 反直觉发现 ：最高分的模型，未必是性价比最高的。论文引入了“价值加权评估”，揭示出某些模型虽然平均分高，但在高经济价值的复杂任务上表现拉胯。
### 关键结果：便宜，但不好用实验结果相当残酷。尽管所有测试的 LLM Agent（包括 GLM-5.2, Kimi K2.6, DeepSeek-V4-Pro 等）在速度和成本上都碾压人类，但在交付质量上差距巨大。
评估对象 Q Score (满分约30) 平均耗时 平均成本 人类基线 27.79 ~2.32 小时 高 最佳 LLM 17.91 < 10 分钟 极低- 质量鸿沟：最佳模型得分仅为人力的 64%。这意味着 Agent 产出的文档往往需要人类进行大量返工。
- 成本优势：LLM 的成本远低于人类，但前提是你能接受“半成品”。
### 工程启示：别急着替换，先做辅助对于正在构建办公 Agent 的工程师来说，这篇论文有几个明确的指导意义：
-重视“可用性”检查：
论文中的评分标准包含大量“可用性（Usability）”检查项。如果生成的 PPT 打不开、Excel 宏报错，任务直接归零。工程落地时，必须建立严格的文件格式校验层。
-长程任务的规划瓶颈：
2.32 小时的任务意味着数百个交互步骤。当前 LLM 的上下文窗口和推理稳定性仍不足以支撑全程无错执行。**Human-in-the-loop（人在回路）**不仅是安全需求，更是质量刚需。
-经济评估是必要的：
不要只看 Accuracy。引入类似 OmegaUse-OfficeVal 的经济锚定，能帮你识别出哪些任务适合自动化（低成本、高容错），哪些必须保留给人力（高价值、低容错）。
### 局限与展望目前 LLM 在文档排版、复杂图表生成等细节上依然脆弱。论文指出，随着模型能力的提升，未来的重点将从“能否完成”转向“如何以最低成本完成”。
OmegaUse-OfficeVal 开源了全部数据和代码。建议所有从事 Agent 研发的团队，将其作为回归测试的基准集，时刻提醒自己： AI 的目标是创造价值，而不仅仅是生成 Token。
## 📝 AI 点评点评时间：2026-07-30 13:10 ｜ reviewer: DeepSeek V4 Flash核心贡献: 针对现有办公套件基准缺乏长时任务和经济成本评估的问题，OmegaUse-OfficeVal 构建了100个平均需2.32小时人工的真实办公任务，为每个任务标注人力劳动时间和市场价代理，并采用基于代码的验证器实现稳定、可复现的自动化评分。
亮点: 博文精准提炼了原文最突出的工程价值：任务级经济锚定（人力时间+价格代理）使成本效益分析成为可能；基于代码的验证协议避免了LLM-as-Judge的不稳定性；同时强调了“最高分模型未必性价比最高”这一反直觉发现，并给出了“先做辅助、Human-in-the-loop”的务实工程启示，取舍到位。
挑刺:
- 严重数值错误：博文在结果表格中写“Q Score (满分约30)”，但原文Score定义为100个任务归一化分数之和（每个任务最高1分），满分应为100。人类27.79、最佳LLM 17.91，远低于30。该错误导致读者对模型表现产生根本性误解。
- 速度描述不准确：博文称“最佳LLM平均耗时<10分钟”，但原文表3中Qwen3.7-Plus平均0.193小时≈11.6分钟，DeepSeek-V4-Pro平均0.184小时≈11.0分钟，均超过10分钟；且MiniMax M3耗时2.275小时，接近人类。原文未说“所有LLM均小于10分钟”。
- 检查项统计不完整：博文说“每个任务平均有20.09个检查项，涵盖可用性和任务完成度”，但原文表2显示可用性检查项平均2.19个，任务完成检查项20.09个，合计22.28个。20.09仅指任务完成项，未包含可用性项。
总评: ⭐⭐½ 博文整体传达了原文核心思想和经济锚定价值，但存在满分误解这一严重事实错误，以及速度表述不精确，降低了可信度，建议修正后提升至3星。
