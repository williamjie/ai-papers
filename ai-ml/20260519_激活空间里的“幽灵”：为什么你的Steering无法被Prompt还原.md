# 激活空间里的“幽灵”：为什么你的Steering无法被Prompt还原

**日期**: 2026-05-19

---

论文 : Steered LLM Activations are Non-Surjective链接 : https://arxiv.org/abs/2604.09839如果你做过模型可解释性或安全对齐，一定见过 Activation Steering（激活引导）。只需在残差流加个向量，就能让模型闭嘴或开口。但这引发一个直觉陷阱： 既然 Steering 能改行为，那一定存在某个 Prompt 能达到同样效果，只是我们没找到而已。
这篇来自约翰霍普金斯大学的研究直接把这个直觉打碎了。论文证明： Steering 后的激活状态，几乎不可能被任何真实 Prompt 还原。 换句话说，你在激活空间里看到的“成功”，在文本空间里是“幽灵”——根本不存在对应的输入。
### 为什么这很重要？
在 AI 安全领域，Steering 常被用来证明模型对齐很脆弱（比如“加个向量就能绕过拒绝”）。这导致很多团队过度担忧黑盒攻击风险。但论文指出， 白盒可控性（White-box Steerability）不等于黑盒可攻击性（Black-box Exploitability） 。
如果 Steering 把模型推入了一个没有任何 Prompt 能到达的“死胡同”，那这种攻击在实际部署中（用户只能输入文本）就是无效的。混淆两者，会导致安全评估资源严重错配。
### 核心 Insight：满射性（Surjectivity）问题作者将问题形式化为数学上的“满射”问题：
- Prompt 空间：离散的、可数的（即使词表很大，也是有限的组合）。
- 激活空间：连续的、高维的实数空间 Rd\mathbb{R}^d。
直觉解释 ：
想象你在一个巨大的 3D 房间里（激活空间），只有几个特定的点（Prompt 映射点）是“合法的落脚点”。Steering 就像一把无形的力场，把你从合法点推到了房间里的任意位置。因为合法点是离散的，而被推到的位置是连续的， 你几乎必然落在了“非法”区域 。
论文通过三个定理严谨证明了这一点：
- 随机向量：随机加的向量几乎必然导致激活状态无法被任何 Prompt 还原（概率为 0）。
- DOM 向量：常用的“均值差”（Difference-of-Means）提取的 Steering 向量，同样满足这一性质。
- 对抗向量：即使你刻意构造一个向量，让它在当前 token 位置与某个 Prompt 的激活重合，它在下一个 token 位置几乎必然发散。
### 实验验证：SipIt 与 ICL 的失败理论很硬核，实验也很直接。作者在 Llama-3.2-1B、Qwen-2.5-0.5B 等模型上做了两组测试：
1. SipIt 逆向工程（精确匹配）
SipIt 算法可以精确地从自然激活中还原出原始 Prompt。
- 自然激活：L2 距离 ≈0\approx 00，完美还原。
- Steering 激活：算法在第一个 token 就失败了。
- 现象：即使强行投影到最近的 token，还原出的 Prompt 往往还是原始 Prompt 本身，但模型生成的却是标准拒绝回复。这证明 Steering 激活与任何真实 Prompt 的激活都相距甚远。
2. ICL 前缀搜索（行为匹配）
既然精确匹配难，那用 In-Context Learning (ICL) 给大量示例，能不能“逼近” Steering 的效果？
- 结果：随着 ICL 示例数量增加（从 1 到 64 个），虽然攻击成功率（ASR）上升了，但激活状态的 L2 距离反而越来越大。
- 结论：ICL 和 Steering 虽然都能让模型“开口”，但走的内部路径完全不同。ICL 是在合法空间内找路径，Steering 是强行把模型拽出合法空间。

论文还展示了一个有趣的黑盒攻击 “Here” Attack ：强制模型以 “Here” 开头。
- 在 Llama-3.2-1B 上，该攻击成功率高达 96%。
- 相比之下，某些高级安全模型（如 LAT-Llama）能防住 “Here” 攻击，但依然会被白盒 Steering 攻破。
- 这进一步证实：白盒失败不代表黑盒安全，反之亦然。
### 工程启示- 别被 Steering 吓倒：如果你的模型只通过 API 提供服务，Steering 攻击是无法实施的。不要因为它能绕过拒绝，就认定你的模型对用户不安全。
- 评估分离：在安全评测中，必须将白盒可控性和黑盒可攻击性分开报告。混在一起会导致错误的风险感知。
- 可解释性的边界：Steering 证明的是“某个方向控制某种行为”，但这不代表该行为在自然语言中有对应的“开关”。机制解释需谨慎，避免过度解读为“模型内部存在某个具体的 Prompt 逻辑”。
- 防御策略：针对黑盒用户，重点防御 ICL 和 Prompt Injection；针对内部开发/开源场景，才需要考虑激活篡改防护。
### 局限与展望论文主要关注了非思考型（Non-thinking）Chat 模型。对于带有 Chain-of-Thought 或复杂推理步骤的模型，Steering 的提取和应用更复杂，但其非满射性的数学本质可能依然成立。此外，论文未探讨是否可以通过更复杂的非线性变换来“模拟” Steering 效果，但这超出了当前 Prompt 的范畴。
总之，这篇论文给过度依赖白盒工具的安全研究者泼了一盆冷水： 你看到的“漏洞”，可能只是模型在数学空间里的一次“越狱”，而非现实世界中的“破门”。
