# 让Agent从失败中自我进化

**日期**: 2026-05-13

---

论文 : On-Policy Self-Evolution via Failure Trajectories for Agentic Safety Alignment链接 : https://arxiv.org/abs/2605.11882做 Agent 开发的都知道，单纯靠“拒绝回答”来保证安全是下策，往往会把正常任务也拒了（Over-refusal）；但靠人工写修复数据又太贵且覆盖不全。新出的 FATE 框架直接打破了这个僵局：它让 Agent 自己挖掘自己的失败轨迹，自己提出修复方案，再通过多目标验证器筛选出“既安全又能干活”的样本，最后自我迭代。这是一种真正的“从错误中学习”的闭环。
## 痛点：轨迹级安全的“稀疏信号”困境传统的安全对齐（如 RLHF/DPO）大多基于最终回复的标量奖励。但在 Agent 场景下，这远远不够。Agent 是工具调用链，安全失败往往是**轨迹级（Trajectory-level）**的：
- 中间步骤失控：最终回复看起来很安全，但中间已经调用了危险 API 或泄露了敏感信息。
- 过度防御：Agent 为了避责，对任何稍复杂的指令都直接拒绝，导致 Utility（效用）归零。
现有的 off-policy 数据或单一维度的安全奖励，无法解决这种多目标冲突。FATE 的核心洞察是：不要试图用单一分数衡量安全，而是利用“生成-筛选”策略，构建帕累托最优的修复监督信号。
## 方法拆解：FATE 的核心机制FATE（Failure-Trajectory Evolution）是一个 On-policy 的自我进化框架，其流程极具工程美感：
### 1. 失败挖掘与同策略修复（Same-Policy Repair）
不同于使用外部专家数据，FATE 让当前策略 πθt\pi_{\theta_t} ​ ​ 自己在开发集上运行，收集被验证器标记为失败的轨迹。
- 关键点：它用同一个模型针对这些失败轨迹生成 KK 个修复候选项。
- Why：这保证了修复提议与模型当前的“错误分布”局部对齐，避免了外部教师分布偏移的问题。
### 2. 多目标重评分与可行性过滤模型生成的修复并不直接信任。FATE 引入了四个维度的验证器评分：
- Security (zsecz_{sec}​)：是否安全？
- Utility (zutilz_{util}​)：任务是否完成？
- Over-refusal Control (zorz_{or}​)：是否过度拒绝？
- Trajectory Control (zctrlz_{ctrl}​)：工具调用格式是否合法？
只有同时满足效用、非过度拒绝和轨迹有效性阈值的候选项，才会进入下一轮筛选。这步直接过滤掉了那些“虽然安全但完全没干活”的退化样本。
### 3. 帕累托前沿监督构建（Pareto-Front Supervision）
这是最精彩的部分。在多目标优化中，没有一个候选项能同时在所有指标上得分最高。FATE 提取**帕累托前沿（Pareto Front）**上的非支配解，并使用一个平衡得分公式进行 Tie-breaking：
rPF(x,a′)=∑wmzm−λmax⁡wm(1−zm)r_{PF}(x, a') = \sum w_m z_m - \lambda \max w_m (1 - z_m) ​ ( x , a ′ ) = ∑ w m ​ z m ​ − λ max w m ​ ( 1 − z m ​ )
这个公式不仅奖励整体质量，还惩罚最大的短板。这意味着，如果一个修复项在某一项上极差（比如完全拒绝），即使其他项很好，也不会被选中。最终形成的修复回放缓冲区 RtR_t ​ 只包含经过验证的“平衡型”优秀轨迹。
### 4. SFT + PFPO 更新- SFT (Supervised Fine-Tuning)：先在修复缓冲区上进行监督微调，让模型快速内化这些平衡策略。
- PFPO (Pareto-Front Policy Optimization)：随后使用基于帕累托奖励的强化学习进行偏好锐化。对于采样出的组内候选项，计算组内相对优势，优化那些在多目标上表现更优的策略，同时通过 KL 散度约束防止偏离过大。
## 关键结果：安全与效用兼得在 AgentDojo、AgentHarm 和 ATBench 上的实验结果令人印象深刻。以 Qwen3-8B-Instruct 为例，经过 2 轮自我进化后：
指标 AgentDojo (攻击下) 变化 AgentHarm (有害请求) 变化 ASR (攻击成功率) 0.540 -27.2% - - TSR (任务成功率) 0.392 +26.0% - - HCR (有害顺从率) - - 0.125 -59.4% VRR (有效拒绝率) - - 0.812 +65.6% SafeScore 0.870 +62.9% - -- 安全性大幅提升：攻击成功率降低 33.5%（跨模型平均），有害顺从率降低 82.6%。
- 效用未受损：在抵抗攻击的同时，任务成功率不降反升，证明了模型学会了“精准拒绝”而非“盲目拒绝”。
- 泛化能力：在未见过的 ATBench 轨迹诊断任务上，安全诊断准确率提升了 6.5%，说明学到的轨迹级安全知识具有迁移性。
## 工程启示- 失败是金矿：Agent 的失败轨迹不是垃圾，而是最宝贵的监督信号。关键在于如何从“失败”中提取“正确的修复路径”。
- 多目标平衡优于单一奖励：在 Agent 安全中，单纯最大化安全奖励会导致模型变“笨”（过度拒绝）。引入帕累托前沿筛选，能强制模型在安全与效用之间找到最佳平衡点。
- On-policy 自我迭代：Off-policy 数据往往滞后于模型能力。让模型不断挖掘自身的新失败模式并进行针对性修复，比静态数据集微调更具适应性。
## 局限与展望FATE 目前依赖于高质量的验证器（Verifier）来评分。如果验证器本身存在偏差或覆盖不全，修复监督的质量也会受损。此外，多轮迭代虽然稳定，但计算成本随轮数线性增加。未来可能需要探索更高效的验证器压缩或并行化策略，以适配更大规模的 Agent 系统。
