# 从视频到剧本：OmniScript 如何实现长视频的‘全感官’深度理解

**日期**: 2026-04-21

---

论文 : OmniScript: Towards Audio-Visual Script Generation for Long-Form Cinematic Video链接 : https://arxiv.org/abs/2604.11102现在的多模态大模型（MLLMs）看短视频挺溜，问问“视频里有什么”也能答得不错。但如果你扔给它一部 20 分钟的电影，让它写一份专业的、包含场景、动作、台词、表情甚至是背景音乐（BGM）的结构化剧本，现有的模型基本都会“翻车”——要么时间轴对不上，要么角色逻辑全乱套。
腾讯 ARC 实验室最近推出的 OmniScript 专门死磕这个硬骨头。它不只是做视频描述（Captioning），而是试图通过“音-视-文”三位一体的建模，把长视频还原成电影工业级别的结构化剧本。
### 1. 现有方案的痛点：为什么“看懂”不等于“写出剧本”？
目前的视频理解模型主要面临三个“深水区”问题：
- 颗粒度太粗：现有的密集描述（Dense Captioning）往往把动作、对白、环境揉成一团，缺乏层级化（Hierarchical）的结构。
- 长程依赖丢失：电影里的角色可能在第 1 分钟出现，第 10 分钟才再次露面。如果模型没有“记忆”，它就无法维持角色身份的一致性。
- 多模态失调：很多模型只看画面，忽略了音频。但剧本里最关键的信息——对白（Dialogue）、环境音（Audio Cue）和情绪（Expression）——往往是音画同步的，缺了音频，理解力会断崖式下跌。
### 2. 方法拆解：OmniScript 的核心设计直觉OmniScript 的核心不是简单的“堆参数”，而是通过一套精巧的流程解决了 数据、架构、训练 三个维度的难题。
#### A. 数据引擎：带“记忆”的自动化标注（Memory-Augmented Pipeline）
高质量剧本数据极难标注。论文没有选择纯人工，而是设计了一个基于 角色档案管理器（Character Profile Manager, CPM） 的渐进式标注流水线。
核心 Insight ：解决长视频角色重识别（Re-ID）的难点不在于视觉特征，而在于上下文。
- 做法：利用 Gemini-2.5-Pro 配合 CPM 模块。CPM 会存储跨片段的角色信息（比如：张三在第 5 分钟换了件衣服），在处理新片段时，先注入历史档案，再进行情节推理。
- 效果：这避免了模型在长视频中把“换了衣服的张三”误认为“另一个人”，保证了剧本在叙事逻辑上的全局一致性。
#### B. 模型架构：AV-DeepStack 深度融合OmniScript 并没有简单地把音频特征拼在视频特征后面，而是采用了 AV-DeepStack 策略。
核心 Insight ：多模态交互不应该只发生在输入层，而应该“贯穿始终”。
- 设计：在 Qwen3-VL 的基础上，通过残差多模态适配器（Residual Multimodal Adapters），将音频 Token 和视频 Token 在 Transformer 的多个层级中反复进行交互。
- 为什么这么做：这样模型在进行深层语义推理时，能够实时感知音频的细微变化（如 BGM 的节奏变化带动情绪识别），而不是在最后输出时才硬凑。
#### C. 训练策略：从 CoT SFT 到 GRPO 强化学习为了让模型学会写“有逻辑”的剧本，他们分了四步走：
- 模态对齐：先学音频和视觉的对应关系。
- 大规模预训练：在大规模音视频数据上磨练感知力。
- CoT 监督微调（SFT）：这是一个关键设计。模型不是直接蹦剧本，而是先生成一段中间推理过程（Thinking Process），包括情节总结和角色关系图谱，再基于此生成结构化剧本。这种“先思考再输出”的模式显著提升了长文本的逻辑性。
- 基于时序分段奖励的强化学习（RL）：利用 GRPO 算法，引入了一个时序感知奖励机制。它不是看整体相似度，而是把视频切成段，逐一匹配事件的准确性（Precision/Recall），专门惩罚那些“时间点飘了”或“凭空捏造（Hallucination）”的行为。
### 3. 关键结果：小参数也能“打”过大模型实验结果非常硬核，OmniScript（8B 参数）在 5 分钟视频的评测中，表现不仅超过了许多开源巨头，甚至在很多维度上逼近了闭源顶流 Gemini 3-Pro。

### 4. 工程启示：我们在做 Agent 或多模态应用时能学到什么？
- 不要忽视“中间思维链（CoT）”在结构化输出中的作用：如果你的任务输出要求极高的逻辑性（如生成 JSON、剧本、代码），强制模型先生成一段“推理/规划”文本，再输出结果，效果远好于直接生成。
- 记忆管理是长程任务的核心：处理长视频或长文档时，建立一个类似 CPM 的“实体档案库（Entity Profile）”进行检索和动态更新，比单纯堆 Context Window 更有效且省钱。
- 针对特定任务设计“可验证”的奖励函数：在 RL 阶段，如果目标是时间对齐，那么 Reward 就必须是基于时间重叠度（tIoU）或时序分段的，而不是模糊的语义相似度。
### 5. 局限与展望虽然 OmniScript 很强，但论文也暗示了边界：目前模型对极短时间（几毫秒级）的瞬间动作捕捉仍有提升空间，且在处理超长（如 2 小时以上）电影时，如何实现更低成本的推理（Inference Cost）仍是工程上的巨大挑战。
