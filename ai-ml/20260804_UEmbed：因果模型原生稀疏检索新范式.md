# ⭐⭐⭐½ UEmbed：因果模型原生稀疏检索新范式

**日期**: 2026-08-04

---

论文 : UEmbed: Unified Sparse and Dense Multimodal Embeddings链接 : https://arxiv.org/abs/2608.02583现有的学习稀疏检索（Learned Sparse Retrieval, LSR）大多依赖双向编码器（如 BERT），而因果解码器（Decoder-only）因单向注意力机制，无法直接复用传统的 Max-Pooling 策略来生成全局稀疏表示。这导致我们要么牺牲服务效率去改造架构，要么忍受多模态场景下繁琐的跨模态辅助模块。
UEmbed 提出了一种优雅的解法：在因果多模态大语言模型（MLLM）末尾追加 NN 个可学习的特殊 Token，将词表划分为 NN 个不相交子集，让每个 Token 负责预测其对应子集的稀疏权重。这不仅实现了单次前向传播同时输出稠密与稀疏向量，更彻底打破了稀疏检索对双向架构的依赖。
### 核心设计：分治策略破解表示瓶颈因果模型生成稀疏向量的最大痛点是“信息瓶颈”：仅靠 EOS 或 CLS 单个 Token 去投影到数十万维的词表空间，表达能力严重不足。UEmbed 的核心 Insight 是采用**分词表投影（Partitioned Projection）**策略。
具体实现如下：
- 追加特殊 Token：在输入序列末尾添加 N=16N=1616 个可学习特殊 Token。由于因果注意力机制，这些 Token 能“看到”前面的所有输入内容，从而有效总结全局语义。
- 词表聚类划分：利用 K-Means 对压缩后的词表进行语义聚类，划分为 NN 个子集。每个特殊 Token 仅负责预测其分配子集中的非零权重。
- 拼接成完整向量：将 NN 个子集的稀疏向量拼接，形成完整的稀疏表示。
这种设计让每个特殊 Token 成为特定语义子空间的“软专家”，避免了单个 Token 试图同时建模所有无关概念的困境。实验表明，相比随机划分或最大距离划分，基于语义聚类的策略能显著提升检索性能。
### 关键结果：稠密与稀疏的性能平衡UEmbed 在 MMEB-v2 和 BEIR 基准上展现了强大的竞争力，尤其是在公开数据集训练的模型中表现突出。
MMEB-v2 多模态检索表现（Table 1）：
- UEmbed-9B (Dense)：平均得分 71.8，超越 RzenEmbed-V2-7B (71.1) 等开源基线，仅略低于使用专有数据训练的 Qwen3-VL-Embedding-8B。
- UEmbed-9B (Sparse)：平均得分 71.0。
- 关键发现：稀疏与稠密模式的分差控制在 1.0 分以内（例如 9B 模型为 71.8 vs 71.0）。这证明在精心设计的架构下，稀疏检索在多模态领域完全可以媲美稠密检索。
BEIR 文本检索表现（Table 2）：
- UEmbed-9B (Dense)：平均 nDCG@10 为 56.3，优于 GME-7B 和 Qwen3-VL-Embedding-8B。
- UEmbed-9B (Sparse)：平均 nDCG@10 为 55.2，与专业的稀疏模型 Echo-Mistral-SPLADE 持平。
⚠️ 反直觉发现 ：在联合训练中，稠密和稀疏目标并未产生负迁移。消融实验显示，联合训练的 UEmbed 性能几乎等同于单任务专家模型，这意味着我们可以低成本地获得双模态能力。
### 工程启示：Agent 时代的检索利器UEmbed 的价值不仅在于精度，更在于其部署优势：
- 服务兼容性：作为纯因果模型，它可直接兼容 vLLM 等高吞吐推理框架，无需额外的双向编码器服务栈。
- 倒排索引友好：稀疏向量可直接接入标准倒排索引，实现高效的近似最近邻搜索。
- Agent 场景降本：在 BrowseComp-Plus 基准测试中，UEmbed 的稀疏模式比稠密模式显著减少了工具调用的搜索轮次（Avg. Search），同时在保持召回率的情况下降低了成本。这对于依赖高频检索的 Agent 应用至关重要。
### 局限与展望尽管表现优异，UEmbed 仍存在边界：
- 多语言偏差：训练数据偏向中英双语，导致其他语言的稀疏激活能力较弱。
- 异常 Token：大词表下偶尔会激活非标准子词（如 _alt），生产环境可能需要后处理过滤。
- 视频场景差距：在视频检索任务上，稀疏与稠密模式的性能差距略大于文本和图片，这可能源于视频时空信息的高密度特性难以被扁平化的稀疏向量完全捕捉。
UEmbed 证明了因果架构原生支持稀疏检索的可行性，为构建统一、高效的多模态检索系统提供了新的范式。对于追求极致服务效率和 Agent 集成能力的工程师来说，这是一个值得深入探索的方向。
