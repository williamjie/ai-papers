# 多教师协同蒸馏：CoRD 让长推理更高效

**日期**: 2026-05-18

---

论文 : Distilling Long-CoT Reasoning through Collaborative Step-wise Multi-Teacher Decoding链接 : https://arxiv.org/abs/2605.02290大模型推理能力的跃升离不开测试时缩放（Test-time Scaling），但动辄数千 token 的长思维链（Long-CoT）推理成本高昂。对于工程落地而言，如何把这些昂贵的推理能力“蒸馏”到更小的模型中，是降本增效的关键。CoRD 这篇论文提供了一个极佳的工程视角：与其让多个教师模型各自为战生成完整路径再筛选，不如让他们在每一步推理中实时协作，这不仅在数学上更优，在计算效率上也更胜一筹。
## 痛点：现有蒸馏方案的“浪费”与“短视”
目前的推理蒸馏（Reasoning Distillation）主流方案是 S1 和 LIMO 采用的“后处理筛选”（Curation-based）：让多个教师模型各自生成完整的推理轨迹，最后挑选质量最高的。这种做法有两个致命缺陷：
- 算力浪费：大量生成过程被直接丢弃，无法利用中间步骤的互补信息。
- 缺乏动态探索：无法在推理过程中根据上下文动态调整策略，容易陷入局部最优。
相比之下，基于蒙特卡洛树搜索（MCTS）的方法虽然能探索，但在 Long-CoT 场景下搜索空间指数级爆炸，计算成本难以接受。
## 核心设计：CoRD 的三步走策略CoRD（Collaborative Reasoning Decoding）的核心 Insight 是将推理视为一个 逐步协作解码 的过程。它不是一次性生成，而是将推理拆解为离散的“步骤”，在多教师之间进行动态博弈与融合。
### 1. 提示词引导的步骤分割（Prompt-guided Step Segmentation）
不同模型生成的推理格式千差万别，难以对齐。CoRD 通过在 Prompt 中插入显式标记（如 <think> ### Step ），强制模型将推理划分为语义连贯的独立步骤。
- 为什么这么做：传统的换行符分割缺乏语义边界，而前缀标记（如 “wait”）频率不稳定。显式标记确保了跨模型比较的公平性和一致性，是实现多教师协作的基础。
### 2. 预测困惑度评分（Predictive Perplexity Scoring）
在每一步，多个教师模型基于当前前缀提出候选步骤。CoRD 引入一个元证明器（Meta-prover，如 QwQ-32B），计算给定当前推理前缀预测出正确答案的条件概率。
- 直觉：如果一个推理步骤能让模型更“确信”地预测出正确答案，说明该步骤在逻辑上更通向最终解。这比传统的基于过程奖励模型（PRM）的过滤更平滑，能保留那些看似次优但具有长期价值的推理路径。
### 3. 束搜索解码（Beam Search）
为了防止贪心策略导致的“短视”，CoRD 在每一步保留 Top-B 个最有潜力的部分轨迹。
- 效率权衡：相比 MCTS 的全量 rollout，CoRD 的束搜索计算复杂度为 O(TKMB)O(TKMB)，远低于 MCTS 的 O(TKlog⁡(TMB))O(TK \log(TM B))(TMB))。实验显示，CoRD 的耗时仅为 MCTS 的 49.0%，却能达到更高的推理质量。

## 工程启示- 异构教师优于同构教师：实验表明，混合不同架构的教师模型（如 QwQ-32B + Phi4-Reasoning-Plus）能带来更显著的增益。不同模型在推理的不同阶段（如问题理解 vs 结论综合）各有专长，CoRD 能自动捕捉并分配这些专长。
- 预测困惑度是强大的代理指标：在没有完美 PRM 的情况下，利用强模型计算预测困惑度是一种低成本、高质量的筛选手段，适合工程落地。
- 计算效率优先：CoRD 在保持高质量的同时，大幅降低了计算开销。对于需要高频推理的 Agent 应用，这种“逐步协作”范式比暴力 MCTS 更具可行性。
## 局限与展望CoRD 目前主要验证于数学推理任务，虽然在 PubMedQA 等开放域任务上也表现良好，但在更复杂的代码生成或多模态推理中的泛化能力仍需验证。此外，元证明器的选择对结果影响较大，如何降低对最强模型的依赖，是后续优化的方向。
