论文 : SearchSwarm: Towards Delegation Intelligence in Agentic LLMs for Long-Horizon Deep Research链接 : https://arxiv.org/abs/2606.09730在长文本 Agent 任务中，上下文窗口（Context Window）的爆炸式增长是性能瓶颈。蚂蚁集团这篇论文提出了一种优雅的解法：与其被动压缩历史，不如让主模型学会“委派”子任务给独立的子代理。这种“委托智能”不仅解决了显存焦虑，更让轻量级模型在复杂搜索任务中具备了挑战千亿参数大模型的竞争力。
### 痛点：被动截断 vs. 主动规划现有的长上下文管理策略大多是 被动 的。当 token 耗尽时，系统要么丢弃旧历史，要么机械地总结对话。这种做法缺乏前瞻性，往往导致关键线索丢失或逻辑断裂。
SearchSwarm 的核心直觉是： 将“上下文管理”转化为“任务分解” 。主代理（Main Agent）不再亲自执行所有耗时的搜索步骤，而是将子任务委派给拥有独立上下文的子代理（Subagent）。子代理完成后，仅返回精简的报告。这本质上是一种 内容感知的压缩机制 ，由模型自主决定保留什么、丢弃什么。
### 方法拆解：如何训练“甩锅”能力？
仅仅提供工具接口是不够的，模型需要被引导去正确使用它。SearchSwarm 设计了一套精细的 Harness（执行框架） ，通过四个原则塑造行为：
- 鼓励委派：主代理专注于高层协调，将多轮信息收集等“认知浅层但 token 昂贵”的工作交给子代理。
- 全面简报（Comprehensive Briefing）：这是关键 Insight。子代理没有历史记忆，因此主代理必须生成包含任务背景、已知事实、未解之谜的完整简报。这迫使主代理在委派前理清思路，避免子代理盲目搜索。
- 核心判断权保留：子代理只负责证据收集，主代理负责验证结论的一致性并做出最终裁决，防止错误累积。
- 引用驱动的汇报：子代理的报告必须附带内联引用（Inline Citations），确保主代理能追溯来源，增强可信度。
通过这套 Harness 运行大量任务后，作者筛选出高质量的轨迹，使用**监督微调（Supervised Fine-Tuning, SFT）**将这些决策模式内化到模型权重中。

### 工程启示：低成本构建高级 Agent这篇论文对工程落地有直接指导意义：
- 上下文即资源：不要试图塞入所有信息。通过结构化委派，你可以用更小的窗口实现更长的推理链。
- 简报的质量决定上限：在实现 Multi-Agent 系统时，Prompt Engineering 的重点应从“指令”转向“背景同步”。主代理必须学会写高质量的 Brief。
- 数据合成是关键：自然语料中缺乏多代理协作数据。利用强模型生成轨迹并微调弱模型，是提升 Agent 规划能力的捷径。
### 局限与展望尽管效果显著，SearchSwarm 目前仅支持单层委派（Subagent 不能再委派）。此外，训练数据主要基于短答案任务，虽然在开放式研究任务上也有泛化表现（平均提升 14.2 分），但在极度复杂的长文生成场景中仍需进一步验证。
对于希望构建低成本、高性能搜索 Agent 的团队，SearchSwarm 提供的 Harness 设计和 SFT 数据合成策略，是一条值得深入探索的路径。
