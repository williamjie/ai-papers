# ⭐⭐⭐⭐ 告别 Docker：Coding Agent 的零环境验证新范式

**日期**: 2026-07-01

论文 : Dockerless: Environment-Free Program Verifier for Coding Agents链接 : https://arxiv.org/abs/2606.28436训练代码智能体（Coding Agent）时，最大的工程瓶颈往往不是模型本身，而是验证环节。为了判断生成的代码补丁是否正确，传统方案必须为每个仓库构建独立的 Docker 环境并运行测试用例。这不仅耗时巨大，更导致大量缺乏可复现环境的私有或遗留代码库被直接排除在训练数据之外。
上海交通大学与抖音团队提出的 Dockerless 彻底打破了这一僵局。它提出了一种完全无需执行环境的代理式补丁验证器，通过在最小化基础镜像中主动探索代码库来判定补丁正确性。这使得从监督微调（Supervised Fine-Tuning, SFT）到强化学习（Reinforcement Learning, RL）的全流程后训练均可在无环境依赖下完成。
### 痛点：执行验证的“隐形税”
目前的行业标准是执行验证：在隔离环境中运行单元测试，以通过/失败作为奖励信号。然而，构建这些环境的成本极高——需要解析依赖、编写测试脚本和结果解析器。
更致命的是，许多真实世界的代码库根本无法提供可复现的环境或完整的测试套件。这导致现有的环境无关（Environment-Free）验证器只能依赖表面信息打分，缺乏对仓库上下文的深度理解，难以应对复杂的软件工程任务。
### 核心设计：用“证据”代替“执行”
Dockerless 的核心 Insight 在于： 判断补丁是否正确，不需要运行代码，只需要确认补丁是否符合逻辑预期。
它采用了一个两阶段的代理架构：
- 问题生成与探索：模型根据 Issue 描述和参考补丁，生成若干验证问题（例如：“修改后的函数是否被调用？”、“语义是否保持兼容？”）。随后，派遣多个子代理并行通过只读 Shell 工具（如 grep, find）在代码库中搜集证据。
- 基于证据的裁决：模型汇总所有收集到的证据，输出一个二元判定令牌（0 或 1），并将其 logits 转化为连续的正确性分数。
这种设计的精妙之处在于，它用“静态的代码上下文探索”替代了“动态的执行反馈”。通过拒绝采样（Rejection Sampling）训练，只有那些最终判定与真实执行结果一致的轨迹才会被保留用于微调，从而让模型学会如何像资深工程师一样审查代码逻辑。
### 实验结果：精度与效率的双重胜利在验证器评估基准上，Dockerless 的表现令人印象深刻。它在 SWE-bench Verified 上的 AUC 达到 81.0 ，比最强的开源验证器 DeepSWE Verifier 高出 14.3 个点，也优于 GPT-5.4 等前沿 LLM 的零样本判断能力。
更关键的是，基于 Dockerless 构建的全链路无环境后训练管道，其最终模型性能追平了传统的基于环境的训练方案：

### 工程启示：规模化训练的新路径对于致力于构建大规模代码智能体的团队而言，Dockerless 提供了极具价值的工程参考：
- 消除基础设施债务：无需再维护成千上万个仓库的 Docker 镜像和测试脚本，大幅降低运维复杂度。
- 覆盖长尾代码库：那些缺乏测试套件或环境配置的私有企业代码库，现在也可以纳入训练数据池，极大地丰富了模型的见识。
- 延迟可控：虽然 Dockerless 需要多步探索，但其奖励计算时间仅占单次 Rollout 总时间的 7.2%。在 RL 训练中，这相对于 Agent 生成轨迹的时间而言是可以忽略不计的开销。
### 局限与展望尽管效果显著，Dockerless 仍依赖对代码库静态结构的理解。对于高度动态、依赖运行时状态或复杂外部交互的逻辑，纯静态探索可能存在盲区。此外，验证问题的数量（K=2-4）需要仔细调优，过多会导致噪声增加而非精度提升。
总体而言，Dockerless 证明了“智能验证”可以脱离“物理执行”。它为代码智能体从实验室走向大规模工业落地扫清了最后一道基础设施障碍。
