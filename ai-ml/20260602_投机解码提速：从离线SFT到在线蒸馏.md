论文 : Draft-OPD: On-Policy Distillation for Speculative Draft Models链接 : https://arxiv.org/abs/2605.29343如果你在用 EAGLE 或 DFlash 加速推理，这篇论文直接指出了你训练 Draft Model 的瓶颈： 离线数据喂饱了，但在线接受率死活上不去 。
它提出了一种针对投机解码（Speculative Decoding）的在线蒸馏框架，把平均加速比推到了 5x 以上。对于追求极致推理成本优化的工程团队来说，这是目前最实用的后训练方案之一。
### 为什么 SFT 会失效？
主流做法是用目标模型生成的轨迹对 Draft Model 进行监督微调（Supervised Fine-Tuning, SFT）。但作者发现，SFT 很快会进入平台期。
核心矛盾在于 分布错位 ：
- 训练时：Draft Model 学习的是目标模型生成的固定前缀。
- 推理时：Draft Model 面对的是它自己提出的、可能已经偏离目标分布的前缀。
这就好比教练只让你练标准动作，但比赛时你因为失误导致姿势变形，教练却没教过你如何从错误姿势恢复。这种“离线到在线”的错配，限制了接受长度（Accepted Length）的提升。
### 核心 Insight：不仅要稳，还要学错既然要解决分布错位，自然想到策略蒸馏（On-Policy Distillation, OPD）。但直接让 Draft Model 自己生成序列（Rollout）会崩坏，因为它不是独立的自回归模型；如果完全依赖目标模型辅助生成，又丢失了 Draft Model 自己的错误信号。
Draft-OPD 的巧妙之处在于**“借力打力”**：
- 目标辅助 Rollout：利用投机解码过程收集高质量序列，确保训练数据不崩坏。
- 错误位置回放（Error-Position Replay）：记录验证失败的位置作为锚点。从这些锚点重新让 Draft Model 生成，并计算目标模型对这些“错误提议”的概率分布。
- 区分对待：
接受 Token：使用正向 KL 散度，强化一致性。
- 拒绝 Token：使用反向 KL 散度，重点惩罚那些导致验证失败的早期错误。
⚠️ 反直觉发现 ：单纯的“目标辅助 Rollout”如果不回放错误位置，效果反而不如 Draft-OPD。因为丢弃被拒绝的 Token 等于丢掉了最有价值的训练信号——正是这些错误决定了你能加速多少。
### 关键结果：实打实的加速在 Qwen3 系列模型上，Draft-OPD 在相同 FLOPs 预算下，显著优于 EAGLE-3 和 DFlash。

- 在非思考模式（Non-thinking）下，平均接受长度达到 6.33，加速比 5.17×。
在 SGLang 服务引擎上的测试也证实，高并发下吞吐量提升了 6%-17% 。
### 工程启示- SFT 只是热身：不要指望仅靠扩大 SFT 数据集来提升投机解码性能。一旦进入平台期，必须引入在线信号。
- 错误比正确更值钱：在训练 Draft Model 时，重点优化那些被目标模型拒绝的 Token。特别是 Block 开头的错误，权重应更高（论文中使用了指数衰减权重）。
- 兼容性强：该方法基于 DFlash 架构实现，但原理通用。如果你在使用 Medusa 或其他块级猜测解码器，类似的“回放失败路径”策略值得尝试。
### 局限与展望- 长文本覆盖不足：受限于计算资源，训练 Rollout 长度 capped 在 4096 tokens，而评估可达 8192。对于超长推理任务，后期状态的覆盖可能不够。
- 仅针对无损解码：目前假设目标模型验证是完美的。如果未来引入近似验证或损失性解码，该方法可能需要调整。
Draft-OPD 证明了： 让 Draft Model 从自己的“失败”中学习，比死记硬背目标模型的“成功”更有效。 这是投机解码领域从“静态拟合”走向“动态对齐”的重要一步。
