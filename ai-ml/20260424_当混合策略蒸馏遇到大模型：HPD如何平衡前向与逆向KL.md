# 当混合策略蒸馏遇到大模型：HPD如何平衡前向与逆向KL

**日期**: 2026-04-24

---

论文 : Hybrid Policy Distillation for LLMs链接 : https://arxiv.org/abs/2604.20244蒸馏大语言模型不是简单地让学生模仿老师的输出。这篇论文撕开了一个盖子：现有的知识蒸馏（Knowledge Distillation, KD）方法其实是在 前向KL、逆向KL、离轨数据、在轨采样 这四个维度上反复权衡的局部解。作者把这些纠缠的设计轴重新梳理，提出了一个统一的 重加权似然目标 ，并在此基础上孵化出HPD——一个在token层面同时协商前向/逆向KL信号、离轨专家标记与在轨学生采样的混合策略。
## 为什么需要重新思考蒸馏传统的监督微调（Supervised Fine-Tuning, SFT）只给单个标记提供one-hot监督，忽略其他可能正确的输出。而基于KL散度的蒸馏会用老师的完整预测分布提供密集监督，但代价是计算开销。
问题在于： 单纯选一个KL方向不够用 。
- 前向KL（FKLD）：鼓励学生覆盖老师分布的所有模式，但学生容量有限时会”摊大饼”，预测变得过度平滑（over-smoothed）
- 逆向KL（RKLD）：让学生聚焦老师的高概率模式，但学生-老师差距大时梯度方差爆炸，训练不稳定此外还有两个纠缠的设计轴：
- 优化策略：把KL作为loss还是reward，梯度动力学完全不同- 数据策略：离轨数据（off-policy）有外部数据源但存在train-inference不匹配；在轨数据（on-policy）引入分布偏移但计算开销大这些因素不是独立的，它们共同塑造了蒸馏行为。作者指出，如果把所有KL蒸馏目标重写为 重加权似然目标 ，就能统一理解：
[L(\theta) = \min_\theta -\mathbb{E} {(s_t,a_t^*)\sim D} [ w(a_t | s_t) \log q \theta(a_t | s_t) ]]其中权重 ( w(a_t | s_t) ) 编码了KL方向与数据策略的选择。
## HPD的核心洞察：把KL变成token级rewardHPD的聪明之处在于 不直接优化KL散度本身 ，而是用**负K1估计器（negative K1 estimator）**把KL转化成token级别的重加权信号。
K1估计器是蒙特卡洛近似KL散度的最简单方法：
[K1 \approx \frac{1}{N} \sum_{i=1}^{N} q_\theta(a_t^{(i)}|s_t) \left( \log \frac{p(a_t^{(i)}|s_t)}{q_\theta(a_t^{(i)}|s_t)} \right)
]当这个值应用于单个token时，就得到了 局部回报信号 ：
- 正值 → 学生低估了这个token，需要加强（前向KL作用）
- 负值 → 学生高估了这个token，需要压制（逆向KL作用）
### 不对称的token级设计HPD对 专家token （来自老师或离轨真值）和 学生采样token 分别处理：
-专家token ( a_t^ ) 的权重 ( w_t^ )**：
计算逆向KL gap：( k1 = q_\theta(a_t^|s_t) (\log p(a_t^|s_t) - \log q_\theta(a_t^*|s_t)) )
- 如果 ( k1 > 0 )（低估），权重 = ( p(a_t^*|s_t) + k1 ) → 前向KL加强- 如果 ( k1 \leq 0 )（已高估），权重 = ( k1 ) → 逆向KL压制，且屏蔽前向KL信号-学生采样token ( a_t ) 的权重 ( w_t )：
只在高估时（( k1’ < 0 )）生效，权重 = ( k1’ ) → 压制不合理采样- 低平时不加强，避免reinforce噪声token关键设计是 Reinforce操作 ：当学生压制了某个非专家token（( k1’ < 0 )）时， 加倍前向KL权重 （( 2p(a_t^*|s_t) + k1 )）强化专家token，把被压制的概率质量有方向地转移到专家token上。

2. 轻量在轨采样是性价比之王HPD只采样一个学生在当前前缀下最可能的非专家token，就能触发Reinforce逻辑。相比OPD动辄多个rollout，计算开销低得多。用在推理任务（长CoT）上，论文证明 纯离轨就能达到SFT+OPD两阶段的效果 。
3. 初始化决定强化对齐天花板Table 6显示，HPD初始化+DPO在AlpacaEval2达到17.68%，比SFT+DPO的13.67%高4个百分点。工程上意味着： 学生质量越高，后续对齐收益越大 。如果你的SFT基线已经狄拖不动的，可能问题不在DPO而在更早的蒸馏阶段。
## 局限与边界论文没明说但值得思考的几点：
计算代价 ：HPD需要计算老师分布 ( p(a_t|s_t) ) 用于k1估计。长序列下这等于每步额外一次前向，比朴素SFT慢。论文没提具体速度比，但明确说”为生成效率做近似假设”。
依赖老师质量 ：如果老师本身在多模态输出上不稳定，k1估计噪声会很大。论文实验用的都是高能力老师（Qwen2.5-7B, LLaMA3-8B），小老师蒸馏场景效果未知。
没解决离轨数据的根本性 ：HPD用轻量采样缓解train-inference不匹配，但离轨数据本身的质量问题（错误、过时）依然存在。实验用的都是高质合成数据（OpenR1-Math, Ultrafeedback），真实场景可能需要先做数据清洗。
长文本的特殊性 ：数学推理任务里，长CoT的中间步骤错误会传播。HPD在这类任务上有效，是否因为长文本天然提供更丰富的token级信号？对话/代码任务中，效果是否同样显著？论文表格显示对话任务提升幅度相对较小。
## 总结HPD把KL蒸馏从”宏观选择散度类型”的哲学辩论，拉回到”微观token层面设计权重”的工程实践。核心洞见是： 前向KL负责拉学生覆盖老师的正确模式，逆向KL负责压制学生的错误膨胀，Reinforce操作负责定向引导概率流 。
对做模型压缩的工程师来说，这意味着如果你的SFT学生熵坍缩、OPD不稳定、多KL方向不知道咋选——试试HPD的k1阈值mask，它用最简单的条件判断实现了正交视角下的三个目标。效果数字在这摆着： 3B模型76.30分逼近老师，对话任务MT-Bench从13.88冲到14.25 。这在成本敏感的场景里，就是实打实的ROI。
