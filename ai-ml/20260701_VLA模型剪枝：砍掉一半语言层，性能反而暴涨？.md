# ⭐⭐⭐½ VLA模型剪枝：砍掉一半语言层，性能反而暴涨？

**日期**: 2026-07-01

论文 : Drop-Then-Recovery: How Redundant Are Vision-Language-Action Models?
链接 : https://arxiv.org/abs/2606.27755现在的视觉-语言-动作（Vision-Language-Action, VLA）模型有个通病：为了处理复杂的自然语言指令，它们直接继承了庞大的预训练语言模型（LLM）骨干。
但现实很骨感，机器人任务中的指令往往短小且模板化（比如“拿起红色杯子”）。这就引出了一个扎心的问题： 我们真的需要这么巨大的语言模型来干这点简单的活吗？
这篇论文给出了一个反直觉的答案：不仅不需要，砍掉一半的语言层，在同等算力下微调后，性能甚至能反超完整模型。
### 核心洞察：不对称的冗余性作者提出了一种名为 Drop-Then-Recovery (DTR) 的分析协议。逻辑很简单：先物理移除 Transformer 块，然后进行下游任务的微调（Fine-tuning），看模型能否恢复性能。
这里的核心 Insight 在于**“可恢复性”不等于“重要性”**。一个模块可能在零样本推理时至关重要，但在微调阶段，剩余的参数足以通过优化来补偿被移除的功能。
为了决定砍谁，作者设计了 GateProbe 。这是一种基于梯度的敏感度指标，通过在残差连接处引入虚拟门控（Virtual Gate），计算任务损失对每个块的梯度敏感性。这比传统的余弦相似度或参数大小更能预测哪些块在微调后是可以“补回来”的。
### 实验结果：语言层是巨大的浪费实验数据非常具有冲击力。作者在 LIBERO 基准测试上，对 OpenVLA-OFT 和 π0.5 等主流模型进行了测试。
⚠️ 反直觉发现 ：在保持训练算力（FLOPs）不变的情况下，移除一半的语言层，性能不降反升。
具体数据如下表所示（OpenVLA-OFT / LIBERO）：
设置 语言层保留比例 平均成功率 (Avg SR) Baseline (完整模型) 100% 95.0% Drop Half (移除一半) ~50% 98.3% (+3.3%) Keep 2 (仅保留首尾2层) ~6% 95.1% (持平)
相比之下，视觉（Vision）和动作（Action）模块则极其脆弱。移除一半的视觉块会导致性能暴跌至 83.9%，而动作模块几乎无法承受任何结构性移除。
这说明： 当前的 VLA 基准测试对语言理解的压力太小了。 模型不需要深层的语言推理能力就能搞定这些任务，巨大的 LLM 骨干纯属“杀鸡用牛刀”。
### 工程启示：如何构建更高效的 VLA？
对于正在落地机器人应用的工程师来说，这篇论文提供了三个关键指导：
- 架构设计要“量体裁衣”：不要盲目堆叠 LLM 层。未来的 VLA 架构应该大幅缩减语言组件的容量，将算力倾斜给视觉感知和动作规划模块。
- 微调是压缩的关键：简单的零样本剪枝（Zero-shot Pruning）会导致性能严重退化。必须配合下游任务的恢复性微调，才能释放被移除层的冗余潜力。
- 硬件加速更简单：DTR 产生的是标准的密集模型（Dense Model），没有稀疏结构的包袱。这意味着你可以在任何通用硬件上获得直接的推理加速，无需定制算子。
在真实机器人部署中，作者发现虽然激进剪枝（如 Drop-16）在标准环境下表现尚可，但在光照变化或物体扰动等分布外（OOD）场景下，鲁棒性会下降。这提示我们： 冗余的语言层可能在无形中提供了某种物理泛化的“安全垫” 。
### 局限与展望这篇论文也指出了当前评估体系的缺陷：LIBERO 等基准测试过于简单，无法激发深层语言模型的价值。
如果我们要训练真正具备通用能力的机器人助手，我们需要更复杂的、需要组合式语言理解（Compositional Language Understanding）的基准测试。否则，我们只是在用昂贵的算力，去解决一个只需要浅层网络就能搞定的问题。
