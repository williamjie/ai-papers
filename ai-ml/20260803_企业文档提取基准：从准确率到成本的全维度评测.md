论文 : ExtractBench: A Benchmark for Schema-Guided Enterprise Document Extraction链接 : https://arxiv.org/abs/2607.29677现有文档提取评测大多停留在“固定模板”或“短文档”层面，完全脱离企业真实场景。这篇来自 RunLLama 的论文提出了 ExtractBench，首次将 长列表完整性、视觉定位（Grounding）和单页成本 纳入统一评测体系。对于正在构建 RAG 或 Agent 工作流的工程师来说，这是一份极具参考价值的“避坑指南”。
### 为什么现有基准不够用？
企业文档提取的核心痛点不是“读不准字”，而是**“结构对齐”与“长上下文截断”**。
传统基准（如 SROIE）只关注固定字段；新兴的 Schema-Guided 基准往往忽略扫描噪声、手写体或超长表格。更致命的是，它们不测成本。在百万页级处理量下，单页几美分的差异直接决定项目盈亏。ExtractBench 覆盖了 370 份真实企业文档（4,869 页），横跨金融、能源等 8 个领域，并引入了 5 维挑战标签体系。
### 核心设计直觉：分层构建 Ground Truth论文最精彩的部分在于其 可扩展的 Ground Truth 构建管线 。全人工标注在大规模数据下不可行，作者采用了“混合信任”策略：
- 真实文档：利用多个独立提取系统的**共识（Agreement）**作为候选值，争议字段由人类仲裁。这避免了单一模型的偏差。
- 合成长列表：逆向构建。先有数据记录，再由 Coding Agent 生成渲染代码生成 PDF。因为数据是预定义的，Ground Truth 绝对精确，完美解决长列表标注难题。
- 扫描表单：保留人类标注，确保手写和模糊字段的准确性。
这种设计不仅保证了数据质量，还使得评测能够区分“模型幻觉”与“标注歧义”。
### 关键结果：VLM 的长文档崩溃与成本陷阱论文评测了 14 种前沿系统，包括商业 VLM、开源模型、Coding Agent 和专用 API。结果揭示了几个反直觉现象：
1. 长度是 VLM 的致命伤⚠️ 反直觉发现 ：Gemini 3.5 Flash 在短文档上表现优异（87.9%），但在长文档上准确率暴跌至 27.9% 。
大多数商业 VLM 缺乏处理长列表的策略，导致记录截断。相比之下，LlamaExtract Agentic Plus 在短/中长文档上均保持 94%-96% 的高分，显示出更强的上下文管理能力。
2. 质量-成本权衡（Quality-Cost Tradeoff）
Coding Agent（如 Codex GPT-5.5）虽然准确率高（93.6%），但单页成本高达 27.8 ¢ 。而 LlamaExtract Agentic Plus 以 8.1 ¢/page 的成本实现了 95.6% 的准确率，远超前者。

### 工程启示- 不要迷信通用 VLM：对于长文档、密集表格，通用 VLM 极易截断。必须引入专门的提取管线或 Agentic 策略。
- 成本是核心指标：在选型时，务必结合“单页成本”与“召回率”。高准确率若伴随高昂成本，在生产环境中可能不可行。
- 重视 Grounding：如果业务需要人工审核（Human-in-the-loop），必须选择支持 Word-level Box 输出的系统，否则审核效率极低。
### 局限与展望尽管 ExtractBench 覆盖面广，但目前的 Grounding 精度仍有提升空间。此外，评测主要基于静态文档，对于动态交互型表单的支持尚待探索。未来，如何降低专用提取 API 的成本，同时保持高定位精度，将是行业焦点。
