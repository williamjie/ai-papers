# On-Policy 蒸馏：避坑指南与稳定训练法

**日期**: 2026-05-13

---

On-Policy Distillation（OPD，在线策略蒸馏）和 On-Policy Self-Distillation（OPSD，在线自蒸馏）最近在大模型后训练中吵得火热。理论上，让模型用自己的轨迹采样，再用老师模型提供密集的 Token 级监督，既省算力又能融合多老师能力。但现实很骨感：有的实验里效果拔群，有的却直接崩溃。这篇来自 UIUC 和北京大学等机构的工作，通过大量实证研究，把 OPD/OPSD 的“黑盒”拆开了：到底什么时候能用？什么时候会炸？核心故障点在哪？
## 为什么 OPD 会突然“智障”？
很多工程师发现，OPD 在数学推理任务上极不稳定，容易出现长度爆炸、重复输出甚至准确率归零。论文通过细致分析，指出了三个导致崩溃的核心机制。
### 1. 前缀污染：老师被带偏了在 OPD 中，学生模型生成前缀 y<ty_{<t} ​ ，老师模型基于这些前缀继续生成监督信号。问题在于，强老师原本能独立解题，但被强行接在学生生成的错误前缀后，它会进入一个“尴尬”的状态。
论文在 GPQA-Diamond 上做了量化：Qwen3-14B 独立测试准确率为 62.1% ，但一旦接入 Qwen3-1.7B 学生生成的前缀，准确率暴跌至 46.0% 。
这种“局部语义冲突”会导致老师给出高概率的“修正词”（如 “wait”, “but”），试图扭转学生错误的推理路径。学生模型学到的是这种犹豫和修正，而不是正确的推理逻辑，最终导致输出啰嗦且不一致。
### 2. Top-K Reverse KL 的梯度偏差为了节省显存，大家常用 Top-K 截断来计算 Reverse KL 损失。论文指出，未归一化的 Top-K Reverse KL 会引入有偏梯度。

## 什么时候 OPD/OPSD 能成？
OPD/OPSD 并非完全不可用，关键在于任务的 PI 结构：
- 失败场景：数学推理。PI 是实例特定的（答案/过程），不同题目间行为不一致，OPSD 无法收敛到有效策略。
- 成功场景：系统提示内部化（System Prompt Internalization）和风格对齐（Alignment）。PI 是共享的潜在规则（如系统指令、人物设定）。此时，OPSD 能将老师在不同 PI 下的行为压缩为一个通用的、无 PI 的归纳偏置。
在 CharacterBench 和 EmotionBench 上，OPSD 比 GRPO 和 PPO 收敛更快，且在同一采样预算下表现更好（见图 5）。在推理压缩任务中，OPSD 能在不损失准确性的前提下显著缩短响应长度，且比带长度惩罚的 RL 更省样本（见图 6）。

### 2. 用 RLVR 强化老师如果老师本身就在学生分布附近，监督信号会更兼容。论文建议先用 RLVR（如 GRPO）在训练数据上微调老师模型（Qwen3-1.7B-GRPO），使其性能接近更强模型（Qwen3-8B），但分布更贴近学生。
结果显示（图 13），用 Qwen3-1.7B-GRPO 作为老师蒸馏 Qwen3-1.7B 学生，效果显著优于直接用 Qwen3-8B 老师。这说明 分布匹配比绝对能力更重要 。
### 3. SFT 预热稳定输出格式对于小模型（如 1.7B），直接 OPD 可能因为输出乱码（非语义 Unicode）而失效。先用老师生成的轨迹做监督微调（Supervised Fine-Tuning, SFT），可以稳定学生的输出格式和长度分布，确保后续 OPD 阶段老师能提供有效反馈（图 14）。
## 工程启示- 不要盲目上 OPD：如果你的任务是数学推理且 PI 是答案，OPSD 大概率没用。如果是风格对齐或指令跟随，OPSD 是性价比极高的选择。
- 小心 Top-K 实现：务必使用 Stop-Gradient 或归一化的 Top-K 损失，未归一化的 Reverse KL 是稳定性杀手。
- 老师也要“接地气”：用 RL 微调后的老师模型做蒸馏，往往比直接拿最强开源模型效果更好，因为它更懂学生的“语言”。
- 小模型需要 SFT 预热：确保学生在蒸馏前能输出人类可读的文本，否则老师信号无从下手。
这篇论文的价值在于它没有停留在“提新算法”，而是深入到底层梯度机制和分布匹配层面，为工程落地提供了清晰的避坑地图。
