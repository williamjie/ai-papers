论文 : SkillZip: Evaluation-Free Skill Compression for Self-Evolving Agents by Discovering Reusable Structure链接 : https://arxiv.org/abs/2608.11079自我进化（Self-Evolving）Agent 的致命伤是“技能膨胀”。随着迭代轮次增加，Skill 文件往往从几行代码膨胀成数万字的冗余文档。阿里达摩院团队提出的 SkillZip ，提供了一种无需评测（Evaluation-Free）的压缩方案，通过发现可复用结构，让 Agent 既保持聪明又保持轻量。
### 为什么现有的压缩方法不管用？
Agent 在进化过程中，会把成功的步骤、失败的教训不断追加到 Skill 中。这导致同一个规则（如“不要覆盖源文件”）可能在引言、三个工作流分支和示例中重复出现。
传统的 Prompt 压缩通常基于 Token 重要性或困惑度（Perplexity）来剪枝。但这在 Agent 场景下是灾难性的：
- 结构敏感：Skill 不是扁平文本，它包含接口、工作流、工具契约。删除一个看似不重要的“罕见异常处理”，可能导致整个执行逻辑崩溃。
- 未来不可知：通用压缩器针对当前查询优化，但 Skill 必须服务于所有潜在任务。
更主流的方案如 SkillReducer，依赖生成的任务进行反馈循环（Rollouts）。这不仅成本高昂，还导致压缩结果过度拟合于压缩时的评测集，缺乏泛化性。
### 核心 Insight：把 Skill 当作代码重构SkillZip 的核心直觉是： “解释一次，引用多次”（Explain once, reference many） 。
它将 Skill 视为一个类型化的契约（Typed Contract），而非纯文本。其设计背后的 Why 非常清晰：
- 最小描述长度（MDL）原则：压缩的目标不是删除内容，而是找到最短的忠实解释。如果三个分支都包含相同的验证步骤，提取为一个共享函数并调用它，比保留三份副本更短。
- 硬覆盖约束（Hard Coverage Constraint）：这是 SkillZip 的灵魂。它要求压缩后的表示必须覆盖原始解析出的每一个规范性需求。这意味着，即使某个规则只被触发过一次，只要它在契约中，就必须被保留。这从数学上保证了罕见规则（Rare Rules）不会被误删。
### 方法拆解：两步走策略- 结构化提取：使用 LLM 将 Markdown 格式的 Skill 解析为类型化单元（接口、工作流、工具协议、作用域规则等）。无法确定的部分作为“锁定残差”原样保留，确保安全性。
- 确定性优化：在解析出的契约上运行确定性算法。它计算每种复用结构（如提取公共规则、合并相似工作流）带来的 Token 节省。只有当“定义+引用”的成本低于“重复复制”时，才执行压缩。
这种设计将“语义理解”与“结构优化”解耦，使得压缩过程无需反复调用 LLM 进行试错，极大降低了成本。

### 工程启示对于正在构建长程记忆或自我进化 Agent 的团队，SkillZip 提供了两个关键指导：
- 结构化优于文本化：不要直接把 Log 拼接到 Prompt 里。尝试将经验转化为结构化的契约（Contract），这样压缩和维护才有抓手。
- 离线压缩是常态：无需在线实时压缩。在每次 Agent 更新 Skill 后，异步运行一次 SkillZip 即可。其极低的 LLM 调用成本（仅几次结构化提取）使其非常适合生产环境。
### 局限与展望SkillZip 依赖对原始文本的结构化解析。如果原始 Skill 写得极其混乱、缺乏逻辑关联，解析器可能将其全部归为“锁定残差”，导致压缩率下降。此外，该方法目前主要针对文本型 Skill，对于嵌入向量或 LoRA 参数的压缩尚未覆盖。
总体而言，SkillZip 证明了通过严谨的结构分析，我们可以在不牺牲智能的前提下，大幅降低 Agent 的认知负荷。
