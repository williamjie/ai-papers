# 多智能体协同：让推理在测试时自我进化

**日期**: 2026-05-12

---

论文 : TMAS: Scaling Test-Time Compute via Multi-Agent Synergy链接 : https://arxiv.org/abs/2605.10344在推理大模型（Reasoning LLMs）的赛道上，单纯堆砌参数量已经不是唯一的出路，“测试时计算扩展”（Test-Time Scaling, TTS）成为了新的兵家必争之地。但现有的TTS方法往往陷入一个两难境地：要么是多轨迹并行却缺乏有效协同，要么是历史经验噪声太大导致模型在冗余路径上打转。IQuest Research 提出的 TMAS 框架，通过引入多智能体协同（Multi-Agent Synergy）和分层记忆机制，试图解决这一痛点，让模型在推理过程中真正实现“越算越聪明”，而不仅仅是“算得更多”。
### 痛点：并行推理中的“信息孤岛”
早期的 TTS 方法，如 Self-Consistency 或 Tree of Thoughts，虽然通过生成多个候选解来提高准确率，但它们本质上是独立的。即使像 PaCoRe 或 RSE 这样试图聚合历史轨迹的方法，也往往缺乏对“什么该保留、什么该丢弃”的显式判断。
TMAS 的核心洞察在于： 多智能体推理不应是简单的投票或接力，而应是一个结构化的协作过程。 如果多个智能体之间没有明确的信息流动机制，并行生成的轨迹就会变成一个个信息孤岛，有用的中间结论无法复用，错误的探索路径也无法被及时规避。
### 方法拆解：分层记忆与角色分工TMAS 将推理过程解耦为五个专门的角色：Solution Agent（解题）、Verification Agent（验证）、Summary Agent（总结）、Experience Agent（经验提取）和 Guideline Agent（策略指导）。其中，最具工程价值的设计在于其 分层记忆管理（Hierarchical Memory Management） 。
传统方法往往将所有历史信息混为一谈，而 TMAS 将其严格划分为两类：
- 经验库（Experience Bank）：存储低层级的、具体的推理信号。包括经过验证的中间结论、具体的解题技巧以及被验证器指出的错误陷阱。它的作用是“复用”，让后续的智能体能够站在前人的肩膀上，避免重复造轮子或重蹈覆辙。
- 指导库（Guideline Bank）：存储高层级的、抽象的策略洞察。它记录的是之前探索过的解题方向和高阶策略。它的作用不是直接复用，而是“规避”。通过记录已探索的路径，指导库迫使后续的智能体走出舒适区，进行非冗余的探索。
这种设计巧妙地平衡了 Exploitation（利用） 和 Exploration（探索） 。经验库确保了局部最优的累积，而指导库则从全局角度防止模型陷入局部最优或重复无效搜索。
在训练层面，TMAS 并没有使用传统的仅关注最终答案正确率的 RLVR（Reinforcement Learning with Verifiable Rewards），而是设计了一套 混合奖励系统（Hybrid Reward System） ：
- 标准正确性奖励：保底，确保基本推理能力不退化。
- 经验利用奖励：如果模型在提供了经验库的情况下比仅提供历史轨迹时表现更好，给予额外奖励。这激励模型真正去“读”和“用”经验库，而不是把它当背景噪音。
- 新颖策略探索奖励：如果模型给出的解法遵循了指导库中未记录的新策略且答案正确，给予高分奖励；如果重复旧策略且正确，奖励较低；如果重复旧策略且错误，严厉惩罚。
### 关键结果：小模型也能跑出大模型的效果实验在 IMO-AnswerBench-50 和 HLE-Math-100 两个高难度数学基准上进行。使用 Qwen3-30B-A3B-Thinking-2507 作为基座模型，TMAS 在迭代推理中表现出了显著的扩展能力。
模型 基准 迭代次数 TMAS (Pass@1) 最佳基线 (Pass@1) 提升幅度 Qwen3-30B IMO-AnswerBench-50 Iter 19 40.50 39.31 (RSE) +1.19% Qwen3-30B HLE-Math-100 Iter 19 35.38 28.16 (RSE) +7.22%更令人印象深刻的是混合奖励训练的效果。使用较小的 Qwen3-4B 模型，配合 TMAS 和混合奖励 RL 训练后，其性能大幅逼近 30B 模型。在 Iter 19 时，4B 模型在 IMO-AnswerBench-50 上与 30B 模型的差距从 23.44% 缩小至 9.62%（相对减少 59.0%）。这证明了通过有效的测试时计算扩展和专门的 RL 对齐，小模型也能获得超越其参数规模的推理能力。
### 工程启示- 记忆的结构化优于单纯的数据量：在构建 Agent 系统时，不要简单地将历史对话拼接给模型。区分“具体事实/步骤”（经验）和“策略/方向”（指导），能让模型更清晰地理解上下文的权重。
- 奖励函数的精细化设计：简单的对错奖励不足以训练出擅长多步推理的模型。引入对“经验利用”和“策略新颖性”的奖励，可以引导模型学习更复杂的元认知能力。
- 平衡探索与利用：实验显示，探索系数 ϵ\epsilon 在 0.2 左右表现最佳。完全依赖历史（ϵ=0\epsilon=00）会导致陷入局部最优，完全随机探索（ϵ=1.0\epsilon=1.01.0）则效率低下。工程实践中需要精心调优这一超参数。
### 局限与展望TMAS 目前尚未在 GPT-5.5 等前沿模型上验证，且 RL 训练依赖外部模型预构建冷启动数据。未来若能实现动态数据收集，将进一步提升系统的自适应能力。但对于追求极致推理性能的团队来说，TMAS 提供的多智能体协同范式具有极高的参考价值和落地潜力。
