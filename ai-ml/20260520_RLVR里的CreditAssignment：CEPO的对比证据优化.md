# RLVR 里的 Credit Assignment：CEPO 的对比证据优化

**日期**: 2026-05-20

---

论文 : CEPO: RLVR Self-Distillation using Contrastive Evidence Policy Optimization链接 : https://arxiv.org/abs/2605.19436在强化学习可验证奖励（RLVR）训练大模型时，大家最头疼的问题之一往往是“功劳分配”（Credit Assignment）。目前的 GRPO 等方法虽然好用，但有个致命缺陷：只要最终答案对，整条推理链里的每个 Token 都吃一样的奖励。
这就导致模型很难分清哪些是关键的推理步骤，哪些只是无意义的废话（Filler）。这篇论文提出了 CEPO（Contrastive Evidence Policy Optimization） ，通过引入“错误答案”作为对比基准，让模型学会只给关键步骤加分，不仅解决了信息泄露问题，还在数学推理任务上取得了显著的性能提升。
### 痛点：GRPO 的“平均主义”与自蒸馏的“泄露风险”
现有的 RLVR 训练主要面临两个极端：
- GRPO 的粗糙：它给正确轨迹里的所有 Token 分配相同的正优势值。在长链推理中，一个关键的算术错误可能毁掉整段推理，但 GRPO 无法区分这种“决定性步骤”和普通的连接词。
- 自蒸馏的危险：为了让模型自己当老师，之前的方法（如 OPSD、SDPO）会让模型基于正确答案生成教师分布，并最小化学生与教师的 KL 散度。但这会导致信息泄露（Information Leakage）：梯度中包含了词汇表级别的正确答案权重，模型会记住“看到这个问题就输出这个答案”的捷径，而不是学习推理过程。实验显示，OPSD 和 SDPO 在 2B 模型上的准确率甚至低于未训练的基线（34.96% vs 39.73%）。
### CEPO 的核心洞察：用“错误”来定义“正确”
CEPO 的设计直觉非常巧妙。它没有直接让学生模仿正确答案，而是问了一个更尖锐的问题：
“这个 Token 是被正确答案支持，同时被错误答案反对的吗？”
如果答案是肯定的，那它就是一个真正的推理步骤；如果两者都支持或都反对，那它大概率是个废话（Filler）。
技术拆解：
CEPO 引入了两个教师分布：
- PT+P_{T+}​：模型基于正确答案 r+r_+​ 生成的分布。
- PT−P_{T-}​：模型基于错误答案 r−r_-​ 生成的分布（从同一批次中被拒绝的 rollout 中提取，零额外采样成本）。
它定义了一个对比证据增量（Contrastive Evidence Delta）：

这个公式有几个关键设计：
- 消除流畅性混淆（Fluency Confound）：之前的 RLSD 方法分母是学生模型 PSP_S​，这反映了 Token 的基础流畅度。CEPO 用 PT−P_{T-}​ 做分母，直接对比正确与错误的倾向性，消除了常见词带来的干扰。
- 结构安全（Leak-free）：CEPO 只在当前生成的 Token 上计算这个比值，并通过 stop-gradient 切断梯度回传。这意味着正确答案和错误答案只作为标量权重调制优势值，不会改变梯度的方向，从而彻底避免了信息泄露。
- 动态范围更大：实验显示，CEPO 的裁剪率（Clip Rate）比 RLSD 低很多（49.5% vs 71.3%），说明它能提供更精细、动态范围更广的信用分配信号。

### 工程启示- 免费的数据源：CEPO 不需要额外的负样本采集，它直接从训练批次中被拒绝的回答（Rejected Rollouts）中提取错误答案。这意味着你可以直接在现有的 RLVR 训练循环中集成 CEPO，几乎没有额外的计算开销（仅增加一次教师前向传播）。
- 避免盲目自蒸馏：如果你正在尝试让模型模仿自己的正确输出来提升推理能力，请务必小心信息泄露。OPSD 和 SDPO 的失败案例表明，简单的分布匹配在 RLVR 中是危险的。CEPO 提供的对比框架是一个更安全的替代方案。
- 超参数敏感：CEPO 的效果依赖于对比权重的裁剪边界（ϵw\epsilon_w​）。论文建议设置为 0.5，过小会退化为 GRPO，过大会引入噪声。同时，对比信号的强度 λ\lambda 建议在训练初期较高，然后线性衰减到 0，因为对比信用分配的收益主要集中在训练的前 10-25 步。
### 局限与展望CEPO 目前主要在多模态数学推理任务上验证。对于纯文本推理或代码生成任务，其效果仍有待验证。此外，虽然 CEPO 解决了 Token 级别的信用分配，但它仍然依赖于序列级别的可验证奖励。如果未来能结合过程奖励模型（PRM），CEPO 的潜力可能会更大。
总的来说，CEPO 是一个设计优雅、工程友好的改进，它通过引入“错误”的视角，让模型学会了在推理中“去伪存真”。对于正在优化 RLVR 训练流程的工程师来说，这是一个值得尝试的方向。
