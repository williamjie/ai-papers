论文 : Boundary-Aware Context Grounding for A Low-Channel EEG Agent链接 : https://arxiv.org/abs/2606.26519当大语言模型（Large Language Models, LLM）被接入脑电（EEG）分析软件时，我们面临一个尴尬的现实：模型懂脑科学，但不懂你的硬件。它可能会建议你用只有后部电极的设备去计算前额叶不对称性，或者把工程上的质量警告误读为神经学结论。NeuraDock Agent 这篇论文提供了一个极具工程参考价值的解法：通过“边界感知”的上下文 grounding，强行划定 LLM 的能力禁区。
### 痛点：通用模型的“幻觉”是科学软件的安全隐患在低通道 EEG 场景中，空间覆盖稀疏且信号质量多变。通用 LLM 缺乏对特定传感器蒙太奇、当前软件实现版本以及结果字段含义的认知。这种认知缺失会导致严重的类别错误（Category Error）：流畅的模型可能推荐未实现的算法，或将工程标志转化为临床结论。
核心问题不在于事实召回，而在于 边界意识（Boundary Awareness） 。系统必须能区分四个维度的限制：
- 物理边界：传感器能观察到什么？
- 实现边界：当前软件实现了哪些算法？
- 结果边界：确定性输出字段实际报告了什么？
- 科学边界：基于这些观察，哪些推断是合理的？
### 方法拆解：计算与语言的硬隔离NeuraDock Agent 的核心 Insight 是： 不要让 LLM 触碰原始数据，也不要让它生成分析代码。
系统架构将确定性的本地 Python 工作流作为数值真理的唯一来源。LLM 仅作为一个受限的解释和规划层。具体设计包含三个关键机制：
- 白名单式载荷投影：LLM 接收的并非完整结果对象，而是经过严格过滤的紧凑摘要。原始 EEG、每样本数组、全功率谱密度（PSD）向量均被排除。
- 版本化上下文包：上下文包含硬件配置、审查过的工作流注册表、结果字段定义、实现边界及科学限制。每个 LLM 调用都记录上下文版本的 SHA256 哈希，确保可追溯性。
- 失败隔离：LLM 服务是可选的。如果 LLM 调用失败（如 HTTP 400 或连接拒绝），本地工作流生成的 results.json 和报告依然有效。计算正确性与语言服务可用性被彻底解耦。
### 关键结果：边界意识显著提升安全性作者在自建的 36 个案例、4 种上下文消融、2 个模型（qwen3.7-max, kimi-k2.6）的基准测试中，验证了该架构的有效性。以下是核心数据对比：

此外，系统测试显示，12 次录音在 10 次重复中产生了完全相同的结构化结果哈希值，证明了底层计算的高度确定性。
### 工程启示：如何构建可信的科学 Agent这篇论文为工程师提供了几个直接可用的指导原则：
- 最小化数据暴露：通过白名单机制，不仅保护了隐私（原始 EEG 不离开本地），还迫使 LLM 关注结构化特征而非噪声。
- 显式声明限制：在 Context 中明确列出“不支持什么”比只告诉它“支持什么”更重要。例如，明确指出后部电极无法计算前额叶指标。
- 容错设计：LLM 只是解释层，核心业务逻辑必须独立于 LLM 存在。当 LLM 挂了，系统依然能输出报告。
### 局限与展望尽管边界分类准确率大幅提升，但仍有约 33% 的响应未达到“严格安全”标准。错误主要集中在条件边界的处理上：模型倾向于将需要保留意见的请求简化为支持或拒绝，或者在多约束编排任务中遗漏必要的事实细节。
此外，该研究未建立临床有效性或绝对认知负荷指数。它解决的是系统层面的可靠性问题，而非算法本身的生物学解释力。对于希望将 LLM 集成到垂直领域科学软件中的团队而言，这种“硬隔离+上下文 grounding”的架构模式值得借鉴。
