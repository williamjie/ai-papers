# ⭐⭐⭐½ 先答后想：CopT 推理新范式

**日期**: 2026-05-20

---

论文 : CopT: Contrastive On-Policy Thinking with Continuous Spaces for General and Agentic Reasoning链接 : https://arxiv.org/abs/2605.20075如果你正在为推理模型（Reasoning Model）高昂的 Token 消耗和延迟头疼，这篇论文值得你停下来读一读。它提出了一种反直觉的推理范式： 先给答案，再决定要不要反思 。这种方法在不需要任何额外训练的情况下，显著提升了模型的推理效率。
### 为什么传统的 CoT 效率低下？
主流的思维链（Chain-of-Thought, CoT）遵循“先思考，后回答”的逻辑。但研究者发现，模型往往存在“表演性推理”（Performative Reasoning）：即便内心早已确定答案，模型仍会机械地生成冗长的中间步骤。这不仅增加了延迟，还无谓地消耗了算力。
CopT 的核心洞察在于：对于许多简单或中等难度的问题，模型在生成初始草稿答案时，其实已经掌握了足够的信息。与其强制模型“想清楚再说”，不如让它“先说再说”，然后根据答案的可信度，动态决定是否触发后续的反思过程。
### 方法拆解：用连续空间做“置信度裁判”
CopT 的架构非常简洁，主要由两个阶段组成：
- 草稿答案阶段（Draft Answer）：模型直接输出答案，不进行显式的中间推理。
- 策略性反思阶段（On-Policy Thinking）：这是 CopT 的精髓。模型如何判断草稿答案是否可信？它引入了**连续嵌入（Continuous Embeddings）**作为推理时的验证器。
核心机制：对比反向 KL 散度CopT 计算一个序列级的反向 KL（Reverse KL）估计量 κa\kappa_a ​ 。它对比的是：
- 离散输入下的支持度：模型在标准离散 Token 输入下，生成当前答案的概率。
- 连续输入下的支持度：将输入替换为缓存的连续嵌入（保留了下一步 Token 分布的不确定性信息），重新计算生成同一答案的概率。
直觉解释 ：
如果草稿答案是可靠的，那么即使输入中包含了更多的不确定性信息（连续嵌入），模型对该答案的信心（概率）不应发生剧烈变化。反之，如果 κa\kappa_a ​ 很大，说明引入不确定性后，模型对该答案的支持度大幅下降，意味着答案可能不可靠。
一旦 κa\kappa_a ​ 超过阈值 τa\tau_a ​ ，CopT 会触发反思。在反思过程中，CopT 还会使用第二个估计量 κr\kappa_r ​ 动态控制草稿答案的可见性：如果当前反思块不稳定，就隐藏草稿答案，防止错误信息误导后续推理。
### 关键结果：提速与提效兼顾实验在数学、代码和智能体（Agentic）任务上进行了广泛验证，使用 Qwen3 和 Qwen3.5 系列模型。数据表明，CopT 在保持甚至提升准确率的同时，大幅降低了 Token 消耗。

在 BFCL v4 和 ZebraArena 任务中，CopT 同样表现优异。例如在 Qwen3.5-35B 模型上，CopT 在 BFCL v4 上 Token 减少了 44.7% ，且在多轮对话的 ZebraArena 大难度任务中，准确率提升了 23.03% 。
### 工程启示- 零训练成本：CopT 是一个推理时（Inference-time）的插件，无需对模型进行监督微调（SFT）或强化学习（RL）。你可以直接将其集成到现有的推理服务中。
- 动态成本控制：通过调节阈值 τa\tau_a​，你可以精确控制模型的“思考深度”。对于高价值任务，调低阈值以追求极致准确率；对于日常简单任务，调高阈值以追求极致速度。
- 可读性保留：与 Latent CoT 不同，CopT 的反思过程仍然是显式的自然语言，便于人类调试和理解。
### 局限与展望虽然 CopT 效果显著，但它依赖于模型本身具备较强的“直觉”能力。对于极难且需要深度探索的问题，初始草稿答案的质量可能过低，导致反思过程难以收敛。此外，连续嵌入的计算虽然并行化，但仍带来了一定的额外计算开销。未来，如何更精细地自动化调节阈值，以及将其扩展到多模态推理，将是值得关注的方向。
