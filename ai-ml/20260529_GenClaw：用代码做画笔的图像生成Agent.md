**日期**: 2026-05-29

论文 : GenClaw: Code-Driven Agentic Image Generation链接 : https://arxiv.org/abs/2605.30248现在的文生图 Agent 大多在“瞎猜”。它们本质上只是高级 Prompt 优化器，通过反复修改文本提示词来微调像素。一旦遇到需要精确计数、复杂排版或物理逻辑的任务，这种基于自然语言的模糊指令就会彻底失效。
GenClaw 提出了一个反直觉的解法：让 LLM 像人类画家一样，先用代码画草图，再用扩散模型上色。
### 痛点：为什么 Prompt 优化走不通？
现有的图像生成 Agent（如 GenAgent, Mind-Brush）陷入了一个死循环：它们把 Agent 当作“提示词重写器”。
自然语言在描述空间坐标、物体数量和层级遮挡时存在天然的歧义性。比如“三个红色的球在左边”，模型很难精确锁定“三个”和“左边”的绝对位置。最终，Agent 只能依赖底端黑盒模型的随机采样，这本质上是在玩概率彩票，而非工程化构建。
### 核心 Insight：代码即画布（Code-as-Canvas）
GenClaw 的核心直觉在于 解耦 。它将图像生成拆解为人类创作的三个阶段：构思、草图、上色。
- 认知层（Think）：LLM 负责搜索、推理和知识补全，将模糊意图转化为结构化记录。
- 执行层（Sketch）：这是关键创新。Agent 使用 SVG、HTML 或 Three.js 等代码作为“数字画笔”，直接构建可执行的视觉骨架。代码具有确定性，能精确控制坐标、层级和数量。
- 渲染层（Color）：现有的文生图模型不再负责构图，而是专注于补充纹理、光照和真实感。
⚠️ 关键设计 ：代码不是最终产物，而是中间表示。纯代码无法生成照片级细节，但能完美解决结构控制问题；扩散模型擅长细节但缺乏逻辑。两者结合，各取所长。
### 实验数据：确定性结构的威力在 GenEval++ 基准测试中，GenClaw 展示了其对复杂指令的掌控力。

在长文本渲染（LongText-Bench）上，GenClaw 更是实现了降维打击：
- 英文长文本：0.989（对比 GPT-Image-1 的 0.956）
- 中文长文本：0.988（对比 GPT-Image-1 的 0.619）
通过将文字渲染交给 HTML/SVG 层，GenClaw 彻底解决了扩散模型“乱写汉字”的通病。
### 工程启示：Agent 的新范式这篇论文对工程师的最大启发在于： 不要试图用自然语言去约束像素，要用结构化数据去约束结构。
在实际落地中，我们可以借鉴 GenClaw 的架构：
- 中间件思维：在 LLM 和图像模型之间插入一个“代码渲染器”。对于海报、UI 设计或信息图，优先使用 HTML/CSS 生成布局。
- 可追溯性：由于引入了代码中间层，当生成失败时，我们可以精准定位是知识检索错误、代码逻辑错误还是渲染风格问题，而非面对黑盒束手无策。
- 分层编辑：利用 JSONL 格式管理图层，使得局部修改（如移动物体、替换文字）变得精确且可控，避免了全局重绘带来的不一致性。
### 局限与展望GenClaw 目前仍依赖强大的 LLM 来生成正确的代码草图。如果 LLM 的代码能力不足，或者任务涉及极度复杂的非结构化自然场景（如森林、人群），纯代码描述的代价会急剧上升。此外，代码到像素的风格迁移仍需高质量的底端模型支持。
但这无疑是图像生成从“随机艺术”走向“工程构建”的重要一步。未来，随着 Code Agent 能力的增强，这种“代码驱动视觉”的范式可能会成为复杂内容生成的标准答案。
