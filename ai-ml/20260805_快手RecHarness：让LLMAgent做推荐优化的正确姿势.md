论文 : RecHarness: A Bandit-Routed Agentic Harness for Self-Evolving Recommender Systems链接 : https://arxiv.org/abs/2607.29241把 LLM 直接扔给模型优化任务，往往是一场灾难。LLM 容易在巨大的搜索空间里“瞎逛”，试错成本极高且缺乏系统性。快手这篇论文提供了一个极佳的工程范式： 用经典的多臂老虎机（Multi-Armed Bandit）算法来约束 LLM 的探索方向 ，既保留了大模型的代码生成能力，又解决了盲目搜索的效率问题。
### 为什么纯 LLM 优化推荐模型行不通？
推荐系统的迭代不是单次实验，而是连续的过程。现有的 MLE Agent（如 AIDE、AIRA）通常把反馈压缩成标量分数进行剪枝，或者让 LLM 自由决定下一步改哪里。
⚠️ 核心痛点 ：LLM 缺乏可靠的探索机制。在有限的算力预算下，让 LLM 自由选择修改方向会导致搜索极不稳定，成功率低，且难以从失败日志中提取有效信号。
RecHarness 的核心洞察是： 将“选方向”和“写代码”解耦 。用数学上的 Thompson Sampling 决定“往哪改”，用 LLM 的推理能力决定“具体怎么改”。
### 方法拆解：Bandit + LLM 的双层架构RecHarness 的设计非常精妙，它构建了一个三层控制流程：
- 定义优化臂（Arms）：人类专家预先定义修改维度，如学习率、Dropout、Embedding 维度、Loss 函数等。这些臂分为两类：
局部臂（Local Arms）：微调现有结构，用于在当前盆地内收敛。
- 跳跃臂（Jump Arms）：结构性大改（如更换编码器），用于跳出局部最优。
- Bandit 路由（Thompson Sampling）：
系统维护每个臂的后验分布 Beta(α,β)\text{Beta}(\alpha, \beta)(α,β)。
- 每轮根据采样概率选择要探索的臂。这解决了“探索-利用”困境，确保算力集中在历史上表现好的方向，同时保留对新方向的探索概率。
- 关键细节：成功判定不仅是比 Baseline 好，还要比同组其他候选好，且不低于历史最佳（Incumbent）。
- LLM 生成与 Experiment Skill：
LLM 不决定方向，只根据选中的臂生成具体代码。
- 引入 Experiment Skill：一个动态更新的文本记忆库，记录成功模式、失败原因和训练日志。这相当于给 LLM 提供了“上下文梯度”，让它知道哪些坑不要踩。
💡 反直觉设计 ：当局部优化停滞时（改进率低于阈值 τ\tau ），系统会自动激活“跳跃臂”。这种 Basin-aware 机制避免了 Agent 在低效微调中无限循环。

- 结构化探索优于自由生成：不要让 LLM 凭空想象怎么改模型。定义好修改维度（Arms），用算法分配算力，效率更高。
- 记忆是关键：Experiment Skill 的设计表明，LLM 需要“经验教训”的文本摘要，而不仅仅是分数反馈。将失败日志转化为“避免规则”能显著减少无效尝试。
- 混合反馈信号：标量分数用于路由决策，文本日志用于代码生成。两者分工明确，互不干扰。
局限与思考：
- 依赖人工定义 Arms：目前仍需要专家预设修改维度。如果完全开放空间，Bandit 的维度灾难问题依然存在。
- 计算成本：虽然比纯 LLM 搜索高效，但每轮仍需训练验证模型。对于超大规模模型，单次 Trial 的成本可能成为瓶颈。
RecHarness 展示了一条务实的路径： LLM 不是万能的自动调参器，而是被算法精心编排的代码生成器。 这种“算法控盘 + LLM 执行”的模式，值得所有从事 AutoML 和 Agent 开发的工程师借鉴。

挑刺：
- Thompson sampling选择规则表述不准确：博文说“每轮根据采样概率选择要探索的臂”，但原文实际是“selects the arms with the largest samples”（采样后取最大值，公式13）。原文明确写“RecHarness samples θ̃_a from each available arm’s Beta posterior … selects the arms with the largest samples”。博文“根据采样概率选择”易被误解为按概率随机抽选，与Thompson sampling的经典实现（采样后取最优）有偏差。
- 跳臂激活条件过度简化：博文称“当局部优化停滞时，系统会自动激活‘跳跃臂’”。原文公式16显示，当改进率低于阈值时，允许跳跃臂参与选择（At = Alocal ∪ Ajump），而非强制激活或必然选择跳跃臂。博文“自动激活”可能让读者误以为系统直接执行跳跃，忽略了它只是放开参与资格。
- 成功信号定义遗漏关键归一化步骤：博文说“成功判定不仅是比Baseline好，还要比同组其他候选好”，但原文成功信号rt(a)要求归一化改进bt(a) > 0（公式10），而bt(a)是经过组内均值和标准差归一化后的相对值（公式9）。博文“比同组其他候选好”不够精确，实际是优于同组平均，且必须同时满足候选有效且不低于历史最优。这一归一化设计是避免不同臂之间尺度差异的关键，博文未提及。
总评：⭐⭐⭐½ 博文准确传达了RecHarness的核心思路和工程价值，但Thompson sampling选择规则和跳臂激活条件的表述存在细微不精确，成功信号的关键归一化步骤被遗漏；整体作为技术博客质量良好，但严谨性上略有折扣。
