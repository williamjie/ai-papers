# ⭐⭐⭐⭐ 疾病感知的药物生成：DrugGen-2 深度解析

**日期**: 2026-07-10

---

论文 : DrugGen 2: A disease-aware language model for enhancing drug discovery链接 : https://arxiv.org/abs/2607.08404在 AI 制药领域，我们常犯一个错误：只盯着靶点蛋白，却忽略了疾病本身的复杂性。同一靶点在不同病理状态下表现迥异，而 DrugGen-2 试图通过引入“疾病本体”上下文，解决这一长期被忽视的工程痛点。这篇论文不仅展示了如何微调 LLM 进行分子生成，更提供了一种将领域知识（MeSH 本体）结构化注入模型的有效范式。
### 为什么需要“疾病感知”？
传统的生成式药物设计通常以靶点蛋白序列或通用分子属性为条件。这种方法的致命缺陷在于它剥离了临床语境。例如，PPARγ 在 2 型糖尿病中发挥有益的代谢作用，但在结肠癌中却可能因与 Wnt/β-catenin 通路的相互作用而产生截然不同的后果。
如果模型不知道“这是糖尿病肾病（DN）”，它就无法区分这种细微的病理差异。DrugGen-2 的核心洞察在于： 药物设计不应仅是“靶点-配体”的二元匹配，而应是“疾病-靶点-配体”的三元协同。
### 方法拆解：从 SFT 到 GRPO 的双重进化DrugGen-2 基于预训练的 GPT-2 架构（具体为 DrugGPT），采用了经典的“监督微调 + 强化学习”两阶段策略，但其奖励函数的设计极具巧思。
-数据构建与输入格式：
作者构建了包含已批准药物、靶点和疾病关联的数据集。关键在于输入格式的设计，模型接收的是 MeSH DAG（疾病本体有向无环图） + 蛋白质序列 + SMILES 的组合。通过引入 <D>（疾病）、<P>（蛋白）、<L>（配体）特殊标记，强制模型学习三者间的语义对齐。
-监督微调（SFT）：
在 13,908 条经过清洗的 MeSH-序列-SMILES 字符串上进行微调。这一步让模型掌握基本的化学语法和疾病-靶点关联模式。
-强化学习优化（GRPO）：
这是本文的工程亮点。作者使用了组相对策略优化（Group Relative Policy Optimization, GRPO），而非传统的 PPO。
Why GRPO? GRPO 无需训练独立的价值网络（Value Network），而是利用组内统计量计算优势函数。这在显存受限的本地部署中极具优势，同时保持了强大的生成性能。
- 奖励函数设计：
结合亲和力：使用 PLAPT 模型预测结合能，无效结构直接归零。
- 新颖性：二进制奖励，若生成的分子存在于已批准药物库中则得 0 分，否则得 1 分。
- 多样性：批次内去重，防止模型陷入“复读机”模式（Reward Hacking）。
### 关键结果：碾压基线的性能表现作者在糖尿病肾病相关的五个关键靶点（ACE, PPARγ, NOS3, PAI-1, TGF-β1）上进行了评估。数据非常硬核，直接对比了 DrugGPT 和 DrugGen 两个基线模型。

### 工程启示：如何落地这类模型？
对于工程师而言，DrugGen-2 提供了几个可复用的最佳实践：
- 本体知识结构化注入：不要只扔文本给 LLM。将疾病、靶点等关系映射为 MeSH DAG 等结构化标识符，能显著提升模型对复杂逻辑的理解能力。
- GRPO 的性价比：在资源有限的情况下，GRPO 是 PPO 的优秀替代品。它通过组内对比消除价值网络的开销，特别适合需要频繁迭代奖励函数的生成任务。
- 多目标奖励平衡：单纯追求结合能会导致模型生成毒性或不可合成的分子。DrugGen-2 通过引入“新颖性”和“批次多样性”奖励，有效防止了模式崩溃（Mode Collapse）。
### 局限与展望尽管结果亮眼，但模型仍有边界。首先，蛋白质序列被截断为 768 tokens，这可能丢失远端结构域对变构调节的关键信息。其次，PLAPT 预测和 GLIDE 对接仍是体外计算，缺乏体内药效验证。未来工作需引入 ADMET（吸收、分布、代谢、排泄、毒性）预测作为奖励函数的一部分，以进一步缩小从“生成”到“临床候选”的差距。
DrugGen-2 证明了，当我们将 LLM 从单纯的序列预测器升级为“语境感知的设计师”时，AI 制药的潜力将被真正释放。

挑刺:
- 博文在“方法拆解-数据构建与输入格式”中写道：“模型接收的是 MeSH DAG（疾病本体有向无环图） + 蛋白质序列 + SMILES 的组合。” 这容易让读者误以为SMILES也是输入条件，而原文中生成阶段模型仅以MeSH DAG和蛋白质序列为条件，SMILES是生成目标。原文4.2节明确训练时输入格式为 <|startoftext|> + <D> + <MeSH DAG> + <P> + <Sequence> + <L> + <SMILES> + <|endoftext|>，但生成时只提供 <|startoftext|> + <D> + MeSH DAG + <P> + Sequence + <L> 作为前缀。博文未区分训练与生成，表述不够精确。
