# 物理可控视频生成新思路：PhyCo教你用物理属性地图控制AI

**日期**: 2026-05-01

---

论文 : PhyCo: Learning Controllable Physical Priors for Generative Motion链接 : https://arxiv.org/abs/2604.28169简单说，这篇论文解决了一个很实际的问题：现在的视频生成模型画得越来越真，但物理规律一塌糊涂——物体该弹不弹、该滑不滑、软的东西硬得像块石头。
PhyCo的思路很直接： 既然训练数据里没告诉模型物理怎么走，那我自己造一批带物理标签的数据，教模型理解摩擦、弹力、变形和外力这四大物理属性，并且实现像素级的连续控制 。
关键数字亮一下：10万+模拟视频、4类核心物理属性、Physics-IQ基准44.1分（比SVD-XT高6.3分）、用户偏好度90.9%（摩擦力控制）。这是一篇有清晰问题定义、可复现数据集、两阶段训练框架、实测数据扎实的工作。
## 问题与动机：物理控制为什么难？
视频扩散模型（比如Cosmos-Predict2、SVD-XT）的痛点很明显：
- 物理一致性差：碰撞没反弹、软体不变形、重力下坠速度随意- 缺乏细粒度控制：想调整”这个球弹得高一点”或者”那个布摩擦小一点”？没门- 现有方案有硬伤：
显式模拟方案（PhysGen、PhysDreamer）：推理时要跑物理引擎+几何重建，速度慢、扩展性差- 隐式控制方案（VLIPP、PhysCtrl）：只能做轨迹规划，没法控制”材料属性”本身最接近的工作是Force Prompting，但它只做单一的”力方向”控制，而且没有像素对齐的物理属性地图。
PhyCo的目标很明确： 把物理属性变成像ControlNet那样可插拔的条件输入，让模型学会”看地图生成视频” 。
## 方法拆解：物理先验怎么”学”进去？
### 核心 InsightPhyCo的突破口是： 物理属性必须”像素对齐”且”解耦表示” 。
推理过程是这样的：
- 如果只用文本描述（“一个高摩擦的球”），模型根本不知道”高摩擦”在像素层面意味着什么- 如果只用轨迹控制（“球往左弹”），模型还是不知道材料本身的属性- 解法：给模型一张”物理属性地图”——每个像素点标注该位置的摩擦系数、恢复系数、变形参数、外力方向和大小然后让模型学会： 给定初始帧 + 物理属性地图 → 生成符合物理规律的视频 。
### 关键设计#### 1. 数据集设计：10万+高质量物理模拟PhyCo的数据集（100K+视频）基于Kubric + PyBullet + Blender构建，覆盖6个核心场景：
- 砖块在平面上滑动（摩擦）
- 球撞墙反弹（恢复系数）
- 球垂直弹跳（恢复系数+重力）
- 软球坠落（变形）
- 物体撞击软体（变形+碰撞）
- 多个球在桌上碰撞（综合交互）
每个场景会系统性地扰动4类物理参数：
- 摩擦系数 μ（friction）
- 恢复系数 e（restitution，0~1）
- Neo-Hookean变形参数（dμ, dλ, dγ）
- 外力大小 F 和方向 ϕ设计哲学很重要 ：场景要”视觉干净”但”物理丰富”。太复杂（多物体、杂乱场景）会让预训练模型学不过来，反而引入噪声。
#### 2. 物理监督微调：ControlNet Inject物理属性架构方面，PhyCo基于Cosmos-Predict2-2B，用ControlNet注入条件。有趣的是： 只微调ControlNet层，base model完全冻结 ——保护预训练的视觉表征，避免灾难性遗忘。
物理属性地图的编码方式很讲究：
物理属性p ∈ R^K×H×W 分解成3个语义组：
1. 摩擦μ + 恢复系数e + 常量通道2. 变形参数(dμ, dλ, dγ)
3. 外力大小F + 方向(cos ϕ, sin ϕ)
每组独立tokenizer（Cosmos tokenizer τ），然后线性投影到DiT输入维度。 分开处理是为了让模型能组合不同属性 （比如摩擦+外力同时生效）。
损失函数就是标准的扩散score matching，但只用物理场景数据训练。
#### 3. VLM奖励优化：让大模型当”物理考官”
纯监督微调有个问题：模型学会了拟合训练数据的分布，但 对未见过的属性组合可能泛化不好 。比如训练时只见过”高摩擦+小外力”，测试时给”低摩擦+大外力”可能就崩。
PhyCo的解法是： 用VLM给生成的视频打分，把分数变成可微的奖励信号 。
关键设计点：
-为什么不用noise prediction的直接反馈？
论文说：部分去噪后的结果还是模糊的，而且已经隐含了条件所给的轨迹信息，无法反映模型真实推理时的行为。
-方案：做N步（实验用10步）denoising rollout，从初始帧+条件生成完整视频，再丢给VLM问问题。
-VLM怎么用：微调Qwen2.5-VL-3B（200步，85%准确率），构造物理问答对：
“物体运动方向是否在蓝色扇形区域内？“（测方向）
- “变形程度是否大于阈值X？“（测变形）
- “反弹高度是否高于Y？“（测恢复系数）
-奖励计算：对每个问题，比较VLM输出”是”和”否”的logits差值，用binary cross-entropy作为损失，end-to-end回传到ControlNet。
为什么不联合训练score matching？
论文做了实验： 只用VLM loss微调ControlNet更稳定 。联合训练时score matching的梯度会和reward梯度打架，反而降低物理对齐度。

## 工程启示：我们能从中抄什么作业？
### 1. 物理可控生成的新范式传统思路：文本→轨迹→视频PhyCo思路： 物理属性地图→视频 （文本作为辅助）
这意味着： 物理属性是第一类公民，不是事后解释 。对机器人仿真、自动驾驶场景生成、特效制作来说，这是更实用的控制粒度。
### 2. 模拟数据的高效利用策略PhyCo的数据构建哲学值得抄：
- 场景少而精：6个核心场景，覆盖主要物理 regime- 属性系统扰动：不是随机乱放物体，而是控制单一变量- 视觉丰富性：50种HDRI环境 + 多种材质纹理，避免模型学到”模拟器作弊”
如果要做自己的可控生成， 先问自己：我的控制维度能在视觉上清晰区分吗？ 做不到就别做。
### 3. VLM作为reward model的可行性论文证明了： 针对特定领域微调VLM，可以构造高质量的可微奖励 。
关键点：
- VLM不是直接当生成器用，而是当critic- 问题设计成binary QA，便于计算logit差值- rollout N步（10步）再评估，避免模糊结果这启发我们： 对于任何”主观评价”的生成任务（比如代码正确性、安全合规性、风格强度），都可以用VLM构造reward，端到端优化生成模型 。
### 4. 训练策略的取舍- 冻结base model：保护视觉知识，加速收敛- 分阶段训练：先监督微调学基础物理，再reward优化强化对齐- 只训ControlNet：如果control任务与主任务解耦，这是性价比最高的方案### 5. 局限性（论文自己也承认）
- 物理属性种类有限：目前只覆盖4种，没做流体、刚性 fracture、热传导等- 场景单一物体为主：多物体交互复杂时性能下降（这也是为什么训练数据故意控制复杂度）
- 模拟到真实的gap：虽然泛化不错，但真实世界的材料属性更连续、更复杂## 局限与后续方向论文结尾提了几个方向：
- 更丰富的物理属性：比如密度、热导率、电导率- 多物体交互场景：现在是单/双物体为主- 与3D重建结合：从单图重建几何+物理属性，再生成动态- 实时交互式编辑：像NeRF那样实时调物理参数看反馈个人判断 ：PhyCo最直接的落地场景是：
- 自动驾驶corner case生成：调摩擦系数生成不同路况下的车辆动力学- 影视特效预演：导演说”这个爆炸威力小一点”，直接改力大小参数- 机器人仿真训练：生成带真实物理响应的操作视频，预训练视觉策略## 写在最后PhyCo的贡献不在算法多复杂，而在 问题定义清晰、数据构建扎实、训练策略务实 。
它没有追求SOTA的PSNR/SSIM，而是专注解决一个工程痛点： 我想控制视频里物体的物理行为，但现在的模型做不到 。
方法上，它把ControlNet的思路从”外观条件”扩展到”物理条件”，用VLM reward解决模拟数据与真实偏好的gap——这两招都是可以复用到其他可控生成任务的。
如果你要做 可控视频生成 ，PhyCo的框架值得参考：
- 先定义清楚你的控制维度在视觉上是否可区分- 构建系统扰动的模拟数据（或标注数据）
- 用ControlNet解耦注入条件- 必要时用VLM reward对齐主观偏好数据是10万+高质量模拟视频，算力是Cosmos-Predict2-2B + Qwen2.5-VL-3B的微调——这个成本对NEC Labs、CMU、UCSD级别的研究团队可行，但对小团队是挑战。不过思路是通的： 物理可控 = 像素对齐的条件表示 + 针对性数据 + 领域专家反馈（VLM） 。
