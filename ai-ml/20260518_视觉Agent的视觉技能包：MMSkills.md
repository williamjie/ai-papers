# 视觉Agent的视觉技能包：MMSkills

**日期**: 2026-05-18

---

论文 : MMSkills: Towards Multimodal Skills for General Visual Agents链接 : https://arxiv.org/abs/2605.13527做 GUI Agent 的同学一定遇到过这个痛点：模型明明“知道”怎么操作，但在具体界面上就是找不到按钮，或者分不清当前状态是“进行中”还是“已完成”。现有的技能复用（Skill Reuse）方案大多把经验压缩成文本提示或代码，这对纯文本模型够用，但对视觉 Agent 来说， 程序性知识（Procedural Knowledge）本质上是多模态的 。
这篇来自上海交通大学和小红书的论文 MMSkills，提出了一套完整的框架，把“文本流程”、“状态判断卡”和“多视角关键帧”打包，让 Agent 在运行时能像人一样，既懂步骤，又懂看图。
### 痛点：为什么纯文本技能包救不了视觉 Agent？
传统的技能包（如 Prompt、Code）假设所有状态都能被语言充分抽象。但在视觉交互中，这种假设经常崩塌：
- 状态识别缺失：Desktop Agent 知道要创建图表，但不知道弹窗还没准备好；Game Agent 知道要过关，但分不清进度条满没满。
- 上下文过载与锚定效应：如果直接把带截图的技能包塞进主上下文，不仅 Token 爆炸，模型还容易被参考截图“锚定”，对着参考图规划，而不是看当前屏幕。
### 核心设计：MMSkill 的三个组件MMSkills 的核心 Insight 是将技能定义为 State-Conditioned Procedure（状态条件化流程） 。一个完整的 MMSkill 包含三部分：
- 文本流程（Textual Procedure）：描述可复用的动作模式。
- 运行时状态卡（Runtime State Cards）：这是精华。它不是图片描述，而是决策节点。包含：
when_to_use / when_not_to_use：明确触发条件。
- visible_cues / verification_cue：告诉 Agent 看哪里，怎么验证。
- 多视角关键帧（Multi-view Keyframes）：包含全屏（全局上下文）、Focus Crop（局部细节）、Before/After（状态变迁）。注意，这些是参考证据，不是坐标。
### 生成与使用：自动化流水线与分支加载怎么生成？ 论文提出一个 Agentic Generator，利用非测试轨迹数据，通过任务聚类、流程归纳、视觉接地（Visual Grounding）和元技能审计，自动从交互数据中提取技能包。
怎么用？分支加载（Branch Loading） 。这是工程上的亮点。
- 传统做法：直接把技能包插入主 Agent 上下文。
- MMSkills 做法：主 Agent 遇到潜在技能时，开启一个临时分支（Temporary Branch）。
Stage 1：分支根据当前屏幕，筛选出相关的状态卡和关键帧视图（比如只加载 Focus Crop）。
- Stage 2：分支对齐证据，返回结构化的决策支持（如：适用性判断、子目标、下一步计划、禁忌操作）。
- 主 Agent 只接收这个精简的“指导意见”，而不是原始图片。这既避免了上下文污染，又防止了视觉锚定。
### 实验数据：不仅是准确率，更是行为矫正在 OSWorld 和 VAB-Minecraft 等基准上，MMSkills 带来了显著增益。
OSWorld 整体成功率提升（Table 1）：
- Gemini 3.1 Pro: 44.08% (No Skill) → 50.11% (MMSkills)
- Qwen3-VL-235B: 21.34% → 39.17% (提升近 20 个百分点，效果惊人)
- Qwen3-VL-8B-Instruct: 10.78% → 25.40% (小模型收益巨大)
行为层面的改变（Figure 4 & Table 3）：
- 路径更短：Qwen3-VL-235B 的平均步骤从 15.22 步降至 9.87 步。
- 减少无效探索：Qwen3-VL-235B 的点击（Click）占比从 75.8% 降至 63.7%，键盘输入和 DONE 操作增加。
- 抑制重复：精确重复动作率从 21.8% 降至 6.2%。
这说明 MMSkills 不仅仅是“给答案”，它通过状态卡和视觉证据，约束了 Agent 的搜索空间，让它从“盲目试错”转向“状态感知的执行”。
### 工程启示- 多模态技能是刚需：对于视觉 Agent，纯文本 Prompt 已经到瓶颈了。必须引入视觉证据来辅助状态判断。
- 分支加载是通用范式：在处理复杂外部知识库时，直接注入上下文往往适得其反。通过一个轻量级的“咨询分支”进行证据筛选和蒸馏，能显著降低主模型的认知负荷。
- 小模型也能飞：Qwen3-VL-8B 的巨大提升表明，外部程序性知识可以弥补小模型内部先验的不足。这在端侧部署或低成本场景下非常有价值。
### 局限与展望- 生成依赖轨迹覆盖：技能包的质量取决于源轨迹的丰富度，冷门场景可能无技能可用。
- 推理成本：分支加载引入了额外的 LLM 调用，虽然优化了主路径，但整体 Token 消耗可能增加。
- 泛化边界：目前主要在 GUI 和简单游戏验证，在具身智能或高安全要求场景下，还需要更强的在线修复机制。
MMSkills 为视觉 Agent 的技能复用提供了一条清晰的路径： 把“怎么做”和“怎么看”解耦再重组，用分支加载实现渐进式披露。 值得所有做 Agent 的工程师深入研读。
