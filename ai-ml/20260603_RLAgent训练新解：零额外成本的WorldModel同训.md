# ⭐⭐½ RL Agent训练新解：零额外成本的World Model同训

**日期**: 2026-06-03

论文 : Policy and World Modeling Co-Training for Language Agents链接 : https://arxiv.org/abs/2606.02388RL 强化学习（Reinforcement Learning, RL）虽然能让 LLM Agent 学会“怎么做”，但往往忽略了“做了之后环境会变成什么样”。这种对世界动态认知的缺失，导致 Agent 在长程任务中容易因不可逆操作或延迟失败而崩溃。这篇论文提出了一种极具工程价值的思路：无需额外训练模拟器，直接在现有的 RL rollout（轨迹）数据上挖掘信号，让 Policy 和 World Model 在同一模型内联合优化。
### 痛点：RL 的“盲目”与 WM 的“昂贵”
标准 RL 通过奖励最大化来优化动作选择，但它并不关心动作对环境状态的具体影响。这就像蒙眼走路，只知道哪条路能拿到糖，却不懂路况变化。
现有的 World Modeling（世界建模）方案通常很“重”：要么训练一个独立的模拟器模型，要么在推理时增加规划步骤。这不仅增加了训练成本，还破坏了 RL 训练的一致性。作者敏锐地指出： On-policy RL 的 rollout 数据本身就包含了世界建模的监督信号 。每一次交互 (历史, 动作) -> 下一观察 ，本质上就是一个预测任务。
### 核心 Insight：从“废料”中提取黄金PaW（Policy and World modeling Co-Training）的核心在于 零额外开销 。它不改变推理范式，也不增加环境交互次数，而是复用了 RL 训练过程中已经生成的轨迹数据。
为了让这个辅助目标有效且稳定，作者设计了三个关键组件：
-动作熵筛选（Action-Entropy Data Selection）
并非所有过渡都有学习价值。高确定性、重复性的动作（如机械点击）产生的观察变化很小，信息量低。PaW 计算动作的 token 级熵，只保留前 α\alpha（默认 0.75）高熵的动作对应的观察作为 WM 训练数据。这确保了模型关注那些真正改变环境状态的“关键决策点”。
-截断 MAE 损失（Clipped MAE Loss）
这是论文最反直觉的设计。传统的交叉熵（Cross-Entropy, CE）损失对低概率 token 的梯度放大效应极强（1/p1/p）。在 Agent 环境中，观察往往包含大量随机噪声（如 ID、动态字符串），CE 会导致模型过度拟合这些无关细节。
PaW 改用 MAE 损失，并引入置信度截断：当模型对某个 token 预测概率超过阈值 ρ\rho（默认 0.2）时，停止优化该 token。这迫使模型忽略已掌握的简单部分，专注于学习真正难以预测的环境动态。
-奖励自适应平衡（Reward-Adaptive Balancing）
WM 损失不能喧宾夺主。PaW 根据 rollout group 的平均回报动态调整 WM 损失的权重 λWM\lambda_{WM}​。表现差的轨迹组获得更高的 WM 权重，以获取更密集的环境反馈；表现好的组则降低权重，专注于策略微调。
### 关键结果：显著且稳定的提升实验覆盖了 ALFWorld（具身交互）、WebShop（网页购物）和搜索增强 QA 三大基准。PaW 在不同模型规模和 RL 算法上均表现出一致的提升。

消融实验进一步验证了设计的有效性：
- 去掉自适应系数（固定 λ=1\lambda=11），ALFWorld 性能从 77.9% 降至 75.5%。
- 用标准 CE 损失替换 Clipped MAE，WebShop 性能大幅下跌至 57.2%（相比 68.6%）。
### 工程启示：低成本高性能的落地方案对于实际部署 Agent 的团队，PaW 提供了极具吸引力的优化路径：
- 推理零负担：训练时虽然增加了 WM 损失计算，但推理时完全不需要调用额外的 World Model 或进行模拟规划。Agent 的行为接口和标准 RL 模型完全一致。
- 极低的训练开销：由于复用了已有的 rollout 数据且无需额外前向传播（仅利用已计算的分布），PaW 带来的额外计算开销仅为 ~2%（时间增加 10.7s/step，显存增加 2.4GB）。
- 通用性强：该方法与具体的 RL 算法（GRPO, GIGPO, PPO, RLOO）解耦，可以无缝集成到现有的 Agent 训练流水线中。
### 局限与展望PaW 目前仅使用单步观察预测，未显式建模长程依赖或多步累积误差。此外，直接使用原始 rollout 可能导致重复轨迹偏差。未来方向包括扩展至多步世界建模以及引入去重采样机制。
总体而言，这是一篇将“理论洞察”转化为“工程实效”的典范论文。它提醒我们：在追求复杂架构之前，先好好审视手中已有的数据信号。
