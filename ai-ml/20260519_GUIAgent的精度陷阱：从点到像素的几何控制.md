# GUI Agent 的精度陷阱：从点到像素的几何控制

**日期**: 2026-05-19

---

论文 : PAGER: Bridging the Semantic-Execution Gap in Point-Precise Geometric GUI Control链接 : https://arxiv.org/abs/2605.15963现在的 GUI Agent 大多活在“宽容区”里：点击按钮，只要落在按钮范围内，系统就判定成功。这种“区域容忍”范式掩盖了一个致命缺陷——当任务需要 像素级精度 时，现有的多模态大模型（VLM）彻底失效。这篇论文通过几何作图这一极端场景，揭示了语义理解与执行精度之间的巨大鸿沟，并提出了解决方案。
### 痛点：语义对了，动作废了在常规 GUI 任务中，点击“搜索框”和点击“搜索框边缘”效果一样。但在几何作图（如 GeoGebra）中，目标是一个连续画布上的 点 。
论文定义了一个新概念： 精度敏感型 GUI 任务（Precision-sensitive GUI Tasks） 。这类任务有两个核心难点：
- 点级精度：成功标准从“落在区域内”变为“距离目标点误差小于 ϵ\epsilon”。
- 误差级联：几何对象存在拓扑依赖。第一步点的坐标偏差 ΔC\Delta C，会通过依赖雅可比矩阵 JJ 传递到后续所有对象，导致最终图形结构崩塌。
实验数据触目惊心：最强的通用闭源模型（如 Gemini-3.1-Pro）动作类型准确率高达 89.18% ，但任务成功率仅为 5.82% 。这就是所谓的“语义-执行鸿沟”：模型知道要画什么，但手抖得画不出来。
### PAGER 方法拆解：规划与执行的解耦PAGER 的核心 Insight 是将“画什么”（规划）和“怎么画”（执行）彻底分离，并针对性地解决执行层的精度问题。
-拓扑感知的规划模块（Planning）
设计直觉：几何作图是有先后顺序的（先有点，才有连线）。模型首先构建一个构造图，识别对象间的依赖关系，生成拓扑排序的子任务列表。这避免了模型试图在不存在的基础上操作。
-像素级执行模块（Execution）
像素接地监督微调（Pixel-grounded SFT）：这是基础。将几何坐标投影到屏幕像素，建立“工具-坐标-参数”的动作语法。这一步让模型学会“怎么点击”和“怎么输入参数”。
- 精度对齐强化学习（Precision-aligned RL）：这是关键。SFT 存在暴露偏差（Teacher-forcing 导致推理时误差累积）。RL 阶段引入了状态条件几何反馈：
动作类型奖励：确保操作逻辑正确。
- 参数精度奖励：核心创新。直接优化坐标、半径等连续参数的准确性，使用指数衰减惩罚函数 exp⁡[−δ/σp]\exp[-\delta/\sigma_p]​] 来约束像素偏差。
- 几何有效性奖励：最终渲染图形与参考图形的几何距离。
### 关键结果：4.1 倍的提升在 PAGE Bench（4,906 道几何题，224K+ 像素级动作）上，PAGER 的表现证明了“精度对齐”的有效性：
模型类别 代表模型 动作准确率 任务成功率 (Task) 步骤成功率 (Step) 通用 VLM Gemini-3.1-Pro 89.18% 5.82% 66.66% GUI 专用 Agent UI-TARS 47.08% 0.00% 8.38% PAGER (Ours) Qwen3-VL-8B 82.62% 23.78% 62.20%- 对比通用模型：PAGER 的任务成功率是 Gemini-3.1-Pro 的 4.1 倍。虽然动作准确率略低（因为更关注像素而非语义），但执行质量远超后者。
- 对比 GUI Agent：传统 GUI Agent（如 UI-TARS）步骤成功率不足 9%，因为它们的 grounding 机制是为“区域”设计的，无法处理连续画布的点级操作。PAGER 将其提升至 62.20%。
消融实验进一步证实：仅靠 SFT，任务成功率仅为 4.48%；加上参数精度奖励后，跃升至 23.78%。这说明 连续空间的参数控制 是瓶颈所在。
### 工程启示- GUI Agent 的边界：如果你的业务涉及 CAD、绘图、科学可视化等需要精确坐标的操作，通用的“点击区域”Agent 方案行不通。必须引入像素级监督和几何校验。
- RL 的精细化奖励设计：不要只给“成功/失败”的稀疏奖励。对于连续控制任务，需要设计过程级奖励（如参数偏差惩罚），才能有效缓解误差累积。
- 数据构造的重要性：PAGE Bench 通过 GeoGebra 回放生成像素级标注，这种“执行闭环”的数据构造思路，可复用到其他需要高精度的 GUI 场景。
### 局限与展望目前 PAGER 仅针对 GeoGebra 风格的平面几何。扩展到更复杂的 CAD 或 3D 建模，需要更复杂的动作语法和环境适配器。此外，依赖几何验证器进行 RL 训练，在缺乏明确数学规则的非结构化界面中难以直接应用。
但这篇论文明确指出了一个方向： GUI Agent 的下半场，是精度之战。
