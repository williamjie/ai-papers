# LIDO：直接在特征空间做3D激光雷达异常分割

**日期**: 2026-04-28

---

论文 : Learning to Identify Out-of-Distribution Objects for 3D LiDAR Anomaly Segmentation链接 : https://arxiv.org/abs/2604.23604不知道你有没有遇到过这种情况——自动驾驶系统在训练时没见过Construction Vehicle（施工车辆），结果在路上把它识别成”一堆杂乱的点”？这就是 out-of-distribution (OoD) 物体检测 的问题。传统的语义分割只会给每个点贴已知类别的标签，但现实世界可不会乖乖按你的分类集来。
这篇CVPR 2026论文提出的LIDO方法， 核心思路很直接：不在预测层面做后处理，直接在整个特征空间里建模”已知世界”的分布 ，让未知物体自己”暴露”。
## 为什么需要新方法现有的3D LiDAR异常分割方案，说白了都是”2D方案的搬运工”：
- Mask4Former3D + 各种后处理：最大logit、MC dropout、模型集成- 要么依赖未标注区域作为异常——但训练时这些区域其实已经被当成”void”类了- Deep Ensemble效果最好，但需要3个模型并行，参数暴增3倍（118.8M vs 39.6M），推理耗时861ms vs 单模型168ms而且数据集也是个大问题。唯一的公开数据集STU用的是128-beam激光雷达， 分辨率太高导致与常见的64/32-beam训练数据之间存在巨大的domain gap 。简单说，模型在”高清画面”里认不出的东西，在”标清画面”里可能连长什么样都不知道。
## 核心设计：双分支特征空间建模LIDO的架构见Fig.2，主干用MinkowskiNet提取点特征，然后分两条路走：
### 语义头：构建”纯净”的类原型传统的类原型（class prototype）就是简单平均。但这里有个 insight ：不是所有点都配当原型—— 模型自己都没信心的点，肯定不具代表性 。
所以用了 confidence-weighted prototype （Eq.2）：
CP_c = Σ(κ_p · fp) / Σ(κ_p)
其中 κ_p = max(fp) 是预测前的最大激活值，相当于模型说”我有XX把握这是某类”。 只让高置信度的点说话 ，这样原型才真正反映类别的本质特征。
训练时，这个原型会变成 锚点 ，通过Prototype Loss（Eq.3）把同类点往原型拉：
L_prot = (1/N) Σ_c Σ_p∈X_c (1 - ⟨CP_c^(e-1), f_p⟩)
相当于每轮训练前，把上一轮学好的原型扔出来说：“你们这些同类的点，特征向量尽量往这靠”。
### 对比头：把异常”挤”出特征球这部分受到Objectosphere Loss的启发，但做了关键改动。 原始方法依赖未标注区域学习异常特征，但LIDO在训练时见都没见过异常样本 。
那怎么做？思路是： 把inlier类特征往球面上推，让球心区域空出来 。
用了两招：
- 对比损失L_cont（Eq.6）：对齐类均值f̄_c与原型CP_c^(e-1)，同时推开其他类- Objectosphere损失L_obj（Eq.7）：对inlier点，如果特征范数‖f’‖²小于阈值r=5.0，就把它往外推；异常点（推理时才用）则不管关键设计直觉 ：不学习”异常长什么样”，而是学习”已知类不应该长什么样”—— 特征空间里留出一片”真空地带”，异常点掉进去就暴露了 。
## 推理：两个视角打分最终异常分数是语义头与对比头的 均匀混合 （Eq.14）：
s_n = 0.5 · (s_n^sem + s_n^cont)
- s_sem（Eq.11-12）：从语义头来，看1 - max_c(⟨f_n, CP_c⟩) + 熵。点特征离所有原型都远 + 模型分类不确定性高 → 嫌疑变大- s_cont（Eq.13）：从对比头来，看max(0, 1 - ‖f_n'‖²/r)。特征范数越小（越靠近球心），异常概率越高这两个分数互补：一个基于 语义相似性 ，一个基于 特征几何分布 。

## 工程启示-特征空间正则化比后处理更优雅与其预测完再加一堆阈值、集成、dropout，不如在训练时就让特征分布自己说话。LIDO证明了特征范数与类原型的几何关系，本身就是异常检测的信号。
-异常检测可以完全不依赖异常样本通过Objectosphere Loss把inlier特征”挤”到球面，球心自然成为异常区。这为数据稀缺场景提供了新思路——我们其实只需要”正常”数据长什么样。
-数据增强的物理真实性很重要论文插入合成物体时，用了Lambertian反射模型计算强度值（Eq.15），比CARLA那种简单按距离计算更真实。这说明：合成数据要仿真到物理层面，模型才能真正学会区分。
-轻量级设计有实际意义21.7M参数、38ms推理，意味着可以在车载芯片（如Orin）上实时跑，同时还能保留资源给其他模块。模型集成方案在嵌入式场景基本没戏。
-语义与异常任务可以共享主干但分支优化双头设计既做语义分割（mIoU仍保持在61%左右，Table 7），又做异常检测，一鱼两吃。这对需要同时输出”已知类标签+未知物警报”的系统很友好。
## 局限与边界论文自己也承认问题：
- AP值仍然偏低（STU上27.53%）。主要原因：LiDAR数据类别极度不平衡（road点 vs 行人点），加上语义分割模型本身的不确定性（如把路边停的车误分为road）
- 低分辨率数据表现下降：nuScenes（32-beam）上AUROC仅89.33%，比高分辨率数据差一截- 稀疏远处点难处理：远距离点特征稀疏，容易被误判为异常- 跨域泛化未充分验证：虽然做了多分辨率数据集，但不同城市/天气/传感器的domain shift仍是挑战未来方向提到了 cross-domain anomaly detection 和 不确定性建模 ，这确实是下一个关键点——如果连”已知类”都认不准，异常检测无从谈起。
## 总结LIDO的价值在于： 它把3D LiDAR异常分割从”2D方案的append模式”，推进到了”特征空间原生设计”的阶段 。通过类原型+对比学习+Objectosphere的三重约束，在未见异常样本的情况下，让特征分布自己区分”已知”与”未知”。
更重要的是，它 不光是算法创新，还带了一套真实可用的数据集构建流程 ——从物理反射模型到几何对齐，解决了”没数据”这个根本问题。效率上，21.7M参数跑出38ms，已经踩在实时部署的门槛上。
对于要做自动驾驶感知、机器人环境理解的朋友，这套思路值得参考： 与其依赖后处理，不如在特征层面就做好”已知/未知”的分离 。
