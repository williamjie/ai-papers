# 扩散+大语言模型，多模态理解生成终于统一了

**日期**: 2026-04-23

---

论文 : LLaDA2.0-Uni: Unifying Multimodal Understanding and Generation with Diffusion Large Language Model链接 : https://arxiv.org/abs/2604.20796现在做多模态，基本是两条腿走路——理解用 VLM，生成用扩散模型或自回归模型。两边模型不互通，训练数据不共享，推理管线也各搞各的。
LLaDA2.0-Uni 干了件有意思的事：用离散扩散大语言模型（dLLM）把理解、生成、推理全塞进一个原生统一的框架里。不是拼积木，是真·端到端统一。
## 现有方案为什么不够好先说痛点。
当前多模态工作流基本分三块：
- 理解：CLIP + LLM 的 VLM 架构，比如 GPT-4V、Qwen-VL。效果好，但只管”看懂”，不管”画出来”。
- 生成：Stable Diffusion、Flux 这类扩散模型，或者 CogVideo 这种自回归生成。只管”画出来”，理解能力极弱。
- 编辑/交互：通常需要额外接 ControlNet、InstructPix2Pix 等模块，模型之间数据不共享。
结果是什么？你要做一个”看图→理解→推理→生成新图”的完整链路，至少调三个模型，管线又长又慢，数据还互相隔离。
更致命的是，理解模型和生成模型用的是完全不同的表示空间——VLM 用离散 token 做文本理解，扩散模型用连续噪声做图像生成，两边根本不在一个语言里对话。
## LLaDA2.0-Uni 的核心思路这篇论文的核心直觉很简单但很有效： 如果文本和图像都用离散 token 表示，那它们就能在同一个模型里被统一处理。
具体怎么做的？三个关键组件：
### 1. 全语义离散 Tokenizer传统方法里，图像的 tokenization 往往丢失语义（比如 VQGAN 重建的图像细节好但语义模糊）。LLaDA2.0-Uni 用的是 SigLIP-VQ 做视觉离散化——SigLIP 本身就是强语义对齐的视觉编码器，用它做向量量化，得到的离散 token 自带强语义信息。
这意味着什么？意味着图像 token 和文本 token 在语义空间上是可比对的。模型不需要专门学”怎么把像素翻译成文字”，因为翻译已经在 tokenization 阶段完成了。
### 2. MoE 架构的离散扩散 LLM 骨干这是整个架构的心脏。
离散扩散（Discrete Diffusion）和传统扩散不一样——传统扩散操作的是连续潜变量，而离散扩散操作的是离散 token 序列。本质上，它把扩散过程变成了 token 级别的掩码预测。
LLaDA2.0-Uni 在这个基础上加了 MoE（Mixture of Experts）——多个专家网络共享输入，每个 token 只路由到少数专家处理。这样做有两个好处：
- 推理效率：参数量可以做得很大，但每次只激活一部分，实际计算量可控- 能力分区：不同专家可以天然地 specialize 于不同类型的任务（理解、生成、推理）
更妙的是， 文本和图像在骨干网络里走的是同一套流程 ——都是 block-level masked diffusion。不管输入是文字还是图片，模型做的都是同一件事：逐步预测被 mask 的 token。
### 3. 扩散解码器骨干网络输出的是离散视觉 token，要变成可见图片，需要一个解码器把它们重建回高保真图像。这个解码器做了 few-step distillation（少步蒸馏）——把原本需要几十步的扩散过程压缩到几步内完成。
## 推理效率：不只是并行解码论文在效率上做了两件实事：
- 前缀感知优化（Prefix-aware optimization）：在骨干网络推理时，利用已生成/已理解部分的前缀信息，加速后续 token 的预测。这在对长序列处理时特别有效——你不需要每次都从头算。
- 解码器少步蒸馏：扩散解码从几十步压缩到 few-step，大幅缩短生成时间。
这两招组合起来，意味着整个系统的推理速度不只是”并行解码”那么简单，而是从架构层面做了端到端的效率优化。
## 训练数据与流程论文强调了两个容易被忽视但很关键的工程细节：
- 精心策划的大规模数据：不是简单堆数据量，而是 carefully curated——数据质量、多样性、覆盖度都经过设计- 定制化多阶段训练流程（Multi-stage training）：不是一次性端到端训练，而是分阶段逐步推进，每个阶段有明确目标这种训练策略在工程上非常重要——直接端到端训练统一模型，往往会出现理解能力强但生成弱（或反过来）的失衡问题。多阶段训练给了模型”先学会理解、再学会生成、最后学会统一”的时间。
## 效果怎么样？
论文的核心结论：
- 多模态理解：性能匹配专门的 VLM 模型。注意，不是”接近”，是”匹配”——一个同时做理解和生成的模型，理解能力不输纯理解模型。
- 图像生成与编辑：同样表现强劲。
- 原生支持交错式生成与推理（Interleaved generation and reasoning）：这是真正区别于”拼接方案”的地方——模型可以在生成图像的过程中穿插文本推理，也可以在理解文本的过程中穿插图像生成。
## 工程启示这篇论文对实际开发有什么指导意义？
1. 统一表示是统一能力的前提。 SigLIP-VQ 的选择不是偶然的——强语义对齐的离散化是整个架构成立的基础。如果你在做多模态统一工作，先问自己：我的 token 表示在语义空间里对齐了吗？
2. 扩散+LLM 的路线值得跟进。 过去大家觉得扩散模型和 LLM 是两条平行线，但 dLLM 证明了离散扩散可以在 LLM 的范式下工作。MoE + 离散扩散的组合，可能成为下一代多模态基座模型的标准配置。
3. 少步蒸馏是扩散落地的关键。 扩散模型一直被推理速度慢卡脖子，few-step distillation 是目前最实用的加速方案之一。如果你的项目要用扩散做生成，这个方向值得深入研究。
4. 多阶段训练比端到端更可靠。 统一模型如果直接端到端训练，很容易顾此失彼。分阶段、有目标的训练流程，在工程上更可控、更可调试。
## 局限与展望论文没有详细讨论的几点：
- 推理成本：MoE 架构虽然推理时激活参数量可控，但总参数量可能很大，部署成本如何？
- 训练数据需求：精心策划的大规模数据意味着什么成本？小规模团队能否复现？
- 长上下文能力：prefix-aware optimization 对超长文本/图像序列的效果如何？论文未深入展开不过，代码和模型已经开源在 GitHub 上，这些问题的答案很快就能在实践中找到。
总的来说，LLaDA2.0-Uni 不是又一个”把 A 和 B 拼在一起”的论文。它从表示层就开始统一，从架构层就设计了一体化流程，训练层也做了针对性优化。这是目前我看过的最认真在做”统一多模态”的工作之一。
