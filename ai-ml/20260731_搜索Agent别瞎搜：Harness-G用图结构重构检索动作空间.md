# ⭐⭐⭐½ 搜索Agent别瞎搜：Harness-G用图结构重构检索动作空间

**日期**: 2026-07-31

---

论文 : Harness-G: A Graph-Structured Harness for Search Agents链接 : https://arxiv.org/abs/2607.27652现在的 RAG Agent 训练有个隐蔽的大坑： 模型在“假装”探索。
我们常以为让 LLM 自由生成搜索词（Free-form Query）能带来多样性，但 Harness-G 指出，这其实导致了 检索等价坍缩（Retrieval-Equivalence Collapse） 。表面看查询字符串千变万化，实际上拿回来的证据集高度重叠。对于基于组相对优化（如 GRPO）的强化学习来说，这意味着梯度信号消失，模型学不到真正的检索策略。
## 痛点：自由查询是 RL 优化的毒药在 Search-R1 等主流方案中，策略网络生成自然语言查询，环境返回文档。作者发现了一个反直觉的现象：
⚠️ 幻觉探索（Illusory Exploration） ：训练初期，同一问题的 rollout 组内，查询形式多样性很高，但检索结果等价类迅速坍缩。到第 30 步时，超过 90% 的组内轨迹获取了几乎相同的证据。
这导致两个致命问题：
- 优势函数消失：如果拿到的证据一样，最终答案大概率一样，组内奖励差异趋零，RL 无法区分哪个检索动作更好。
- 信用分配混淆：即使答案不同，差异往往来自推理或生成阶段，而非检索质量。强行把结果好坏归因于之前的查询词，信噪比极低。
现有的改进方案（如 IGPO、StepSearch）试图通过更细粒度的奖励信号来修补，但都没动“动作空间”这个根本。Harness-G 认为： 问题不在奖励怎么算，而在动作怎么定义。
## 核心 Insight：把检索变成图上的有限状态选择Harness-G 的核心直觉是： 将开放式的文本生成，重构为封闭式的图导航。
### 1. 离线构建三元图论文不依赖 LLM 提取关系（避免幻觉和成本），而是用程序化方式从语料库构建 段落-句子-实体（Paragraph-Sentence-Entity） 三元图。
- 句子节点：最小证据单元。
- 实体节点：跨句、跨文档的跳板。
- 边：基于表面匹配和共现，无需语义理解。
### 2. 在线菜单式交互（Action Menu）
策略网络不再生成查询串，而是从环境提供的有限菜单中选择动作 ID：
- Select(s)：采纳当前可见的某个句子作为证据。
- Lookup(e)：针对某个实体发起检索，环境自动构建确定性查询。
- Answer：终止并生成答案。
这种设计带来了三个关键性质：
- 有限性（Finiteness）：动作空间有界，易于探索。
- 可验证性（Verifiability）：无效动作直接过滤，无需事后惩罚。
- 可预览性（Previewability）：环境可以零成本模拟执行某个动作后的状态，为信用分配提供基础。
### 3. 结构化非短视信用（SNC）
利用“可预览性”，Harness-G 引入了 SNC 机制，无需额外 rollout 即可计算步级奖励：
- 前沿相对优势（Frontier-relative Advantage）：用冻结的回答器评分当前动作带来的边际增益，并减去同一状态下其他备选动作的平均增益。这解决了“选A比选B好多少”的问题。
- 启用信用传播（Enablement Credit）：多跳检索中，早期找到关键实体可能没立即得分，但为后续步骤铺路。SNC 沿依赖图反向传播下游增益，奖励那些“搭桥”的动作。
## 实验结果：小模型收益巨大在六个 QA 基准测试上，Harness-G 表现强劲，尤其在多跳推理任务中优势明显。
模型规模 基线 (Graph-R1) Harness-G 提升幅度 1.5B Avg F1: 40.09 Avg F1: 50.83 +10.74 3B Avg F1: 55.24 (注: 原文对比值为Graph-R1的51.26? 不，原文Table 1显示Graph-R1 3B在2Wiki为57.56, Harness-G为65.53) Avg F1: 59.24 (综合平均) +3.98注：具体到数据集，Qwen2.5-3B 在 2Wiki 上从 Graph-R1 的 57.56 提升至 65.53（+7.97），HotpotQA 从 56.75 提升至 65.87（+9.12）。
消融实验揭示真相：
- 仅将接口改为菜单（无 SNC），F1 提升超过 17 点。
- 加上 SNC 后，多跳任务进一步显著提升。
- 零优势组率：Search-R1 训练后期大量轨迹陷入“全对”或“全错”的零优势状态；Harness-G 保持了更高的检索多样性，零优势组率稳定在 23% 左右，说明模型仍在有效学习。
## 工程启示与局限### 为什么你应该关注 Harness-G？
- 小模型友好：1.5B 模型的提升幅度（+10.74）远大于 3B 模型（+3.98）。结构化动作空间降低了小模型的决策复杂度，使其能更好地利用外部知识。
- 零 API 成本构建图谱：不同于 GraphRAG 需要 LLM 提取实体关系，Harness-G 的图构建是程序化的（NER + 规则），成本低且无幻觉风险。
- 无需额外 Rollout 的信用分配：SNC 利用环境预览计算优势，避免了 Tree-GRPO 等方法昂贵的树状展开开销，每步仅增加 9-11% 的时间。
### 局限与边界- 仅限文本域：目前方法基于文本图谱，扩展到多模态（如图像、表格）需要重新设计图结构和动作空间。
- 依赖预构建图谱：虽然构建成本低，但仍需离线处理语料库，不适合完全动态的 Web 实时搜索场景（除非结合在线索引）。
Harness-G 提醒我们： 在 Agent 训练中，动作空间的定义往往比奖励函数的微调更重要。 当自由生成导致信噪比崩溃时，退回到结构化、有限状态的选择，可能是更稳健的工程路径。

亮点: 1. 博文准确地提炼了“检索等价坍缩”这一核心发现，并用“模型在‘假装’探索”的生动比喻解释了 GRPO 优势消失的机制，抓住了原文最关键的洞察。2. 博文对 Harness-G 的三个关键性质（有限性、可验证性、可预览性）的概括清晰到位，并正确指出 SNC 无需额外 rollout 即可提供步级奖励，体现了对方法精髓的理解。
挑刺: 1. 事实数字错误 ：博文在实验结果表格中将 Harness-G (3B) 的平均 F1 写为 “59.24”，但原文 Table 1 明确显示该值为 55.24 （原文：”Harness-G … 55.24”）。这一错误直接改变了模型性能的量化描述，属于严重的数据引用偏差。
2. 表述不严谨 ：博文称“到第 30 步时，超过 90% 的组内轨迹获取了几乎相同的证据”。原文 Figure 1a 精确描述为 “fraction of rollout groups spanning multiple retrieval-equivalence classes falls … to below 10%”，即跨多个等价类的组占比低于 10%，而非“超过 90% 的组内轨迹”证据相同。虽然意思相近，但博文的表述可能被误解为组内轨迹个体层面的重合度。
3. 省略关键条件 ：博文在介绍 SNC 的前沿相对优势时，仅说“减去同一状态下其他备选动作的平均增益”。原文明确指出该平均值是 从类型分层、去重、有容量上限 (Kf=4) 的前沿集合 Ft 中计算 ，而非所有备选动作。省略这一约束可能让读者误以为计算成本较高或覆盖所有动作。
