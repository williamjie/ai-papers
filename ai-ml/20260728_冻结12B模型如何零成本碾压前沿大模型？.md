论文 : A Frozen 12B Beats Frontier Models on Verified Work: 100% Accuracy, 0 Tokens, Bit-Exact, Forever链接 : https://arxiv.org/abs/2607.23806当前 LLM 工程实践存在一个巨大的结构性浪费：我们每次调用前沿模型 API，都在为早已解决的问题重新支付推理成本。这篇来自 Corbenic AI 的行业报告揭示了一个反直觉的事实：通过“冻结模型+持久化验证记忆”，一个 12B 参数的小模型在已验证任务上，能以零 Token、毫秒级延迟、比特级确定性输出，全面击败前沿大模型。
## 现有方案的痛点主流提升模型能力的路径是重新训练或微调（Fine-Tuning）。这带来三个致命工程缺陷：
- 昂贵：每次改进都意味着巨大的 GPU 算力消耗。
- 不透明：新权重的行为变化需要重新审计，难以追踪。
- 不可重复：同一问题多次提问，输出往往不同，无法满足审计、合规或确定性计算的需求。
更严重的是，当前的 API 调用模式本质上是“过度参数化的非确定性执行引擎”。即使问题是老生常谈，模型依然会进行完整的生成过程，产生数千 Token 的中间推理，且结果每次都有细微差异。
## 核心 Insight：推导与执行的解耦Galahad 系统的核心直觉非常清晰： 将“问题的求解推导”与“具体实例的执行”彻底解耦 。
传统 RAG 或语义缓存（Semantic Cache）依赖近似匹配，这在需要精确验证的场景下是灾难性的。Galahad 提出了一种新的契约：
- 模型冻结：权重永不改变，不进行任何微调。
- 独立验证：解决方案在存储前必须通过独立于答案密钥的验证步骤（如形式化证明、一致性检查）。
- 精确复用：一旦某个问题族被解决并验证，后续所有该族的实例都从内存中直接执行，零生成 Token。
⚠️ 关键设计差异 ：这不是简单的缓存。缓存存储的是“答案”，而 Galahad 存储的是“经过验证的参数化方法”。当输入参数变化时，系统重新计算答案，但无需模型重新推理。
## 关键结果：数据不说谎论文在 9 个问题族、180 个全新实例上进行了测试，结果极具冲击力：
指标 前沿大模型 (API) Galahad (冻结 12B) 准确率 依赖单次生成稳定性 100% (180/180) 边际 Token 成本 每次查询数百至数千 Token 0 Token 延迟 秒级 (多轮生成+执行) 6-23 ms 确定性 非确定性 (随机性存在) 比特级精确 (Bit-Exact) 能耗 每次查询独立耗电 ~36 mWh/次 (相当于 LED 灯亮 13 秒)
架构无关性验证 ：
该记忆层与模型解耦。在 Gemma-4-12B、Qwen3-14B、DeepSeek-Coder-V2-Lite 和 Phi-4 四种不同架构（密集型与 MoE）上，结果完全一致。这意味着知识资产不绑定于任何特定厂商的模型迭代周期。
精确检索 vs 近似检索 ：
在一个包含 4,500 项验证知识的存储库中，传统的近似相似度检索（向量检索）错误匹配率高达 94.3% 。而 Galahad 使用的精确内容寻址（Exact Content Addressing）实现了 0 次碰撞 。这证明对于可验证的执行知识，近似匹配不是“降级”，而是“灾难性失败”。
## 工程启示- 重新定义“智能”的边界：在可验证、重复性高的工作流中（如代码生成、数学计算、结构化提取），前沿模型的边际价值极低。小模型 + 高质量验证记忆的组合，在成本、速度和确定性上具有绝对优势。
- 打破 API 依赖：一旦建立了验证知识库，系统对底层模型的依赖大幅降低。你可以随时替换更便宜、更快的基础模型，而无需重新训练或担心能力退化。
- 长上下文的真正解决方案：该系统在单张 46GB GPU 上维持了 600 万 Token 的可移动窗口，且内存占用平坦（仅增加 263MB）。相比之下，vLLM 在 30,399 Token 处报错，SGLang 在 ~32,000 Token 后静默截断。这为处理超长文档或复杂上下文提供了新的工程思路。
## 局限与展望该系统目前主要适用于 可验证、执行绑定型 的任务。对于需要从零开始进行开放式创造性推理的“冷启动”场景，前沿大模型依然占据优势。此外，知识组合的上限目前测试为 9 个小项或 14,134 Token 的合并上下文，更大规模的跨领域复杂推理仍需进一步探索。
