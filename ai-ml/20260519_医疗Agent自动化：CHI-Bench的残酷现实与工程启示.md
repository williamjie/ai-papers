# 医疗Agent自动化：CHI-Bench的残酷现实与工程启示

**日期**: 2026-05-19

---

论文 : CHI-Bench: Can AI Agents Automate End-to-End, Long-Horizon, Policy-Rich Healthcare Workflows?
链接 : https://arxiv.org/abs/2605.16679别再被 SWE-Bench 上 90% 的通过率迷了眼。当 Agent 走出代码沙盒，进入充满规则、角色切换和不可逆操作的真实企业级工作流时，能力瞬间崩塌。这篇论文揭示了一个残酷现实：当前最强的 AI Agent 在医疗行政自动化任务上的通过率仅为 28%，一旦进入长时程多任务并发模式，成功率直接跌至 3.8%。
### 现有方案的痛点：不仅是“懂医学”，更是“懂流程”
现有的医疗 AI 评测（如 MedQA, HealthBench）主要考察静态的医学知识或短期问答。但真实的医疗工作流（如医保预授权 Prior Authorization、利用管理 Utilization Management）是 政策密集（Policy-dense） 、**多角色协同（Multi-role composition） 且 不可逆（Irreversible）**的。
Agent 不仅要查病历，还要在 1,279 篇操作手册中检索保险条款，扮演护士、医生、协调员等不同角色，并进行多轮对话。一旦提交申请，状态机不可回退。这种长时程、高容错率极低的环境，是现有基准完全无法覆盖的“深水区”。
### 方法拆解：高保真模拟与“入职手册”设计CHI-Bench 的核心洞察在于： Agent 的失败往往不是因为不懂医学，而是因为不熟悉复杂的企业级规则引擎。
为此，作者构建了 χ\chi -World 引擎，模拟了 20 个医疗应用，通过 87 个 MCP 工具暴露接口。其设计亮点在于引入了**“受管护理操作手册”（Managed-Care Operations Handbook）**技能库：
- Wiki 式技能结构：将 1,279 个 Markdown 文档组织成类似新员工入职指南的 Wiki 结构。顶层路由到具体角色（如 PA 专员、UM 审核员），再深入具体操作流程。
- 分层验证器：采用“确定性合约 + 基于规则的 LLM 裁判”双重验证。只有当底层状态机一致且裁判判定合理时，才算通过。这种设计模拟了真实世界中“系统报错”与“人工复核”并存的严苛环境。
### 关键结果：前沿模型集体翻车实验覆盖了 30 种 Agent/模型组合，结果令人警惕：

- 端到端双 Agent 互搏：当 Provider 和 Payer 两端均由 Agent 驱动时，通过率归零（0%）。
- 失败模式：35.4% 源于临床推理错误，23.3% 是因为未完成工作流（如忘记提交），15.6% 是因为 Agent 陷入死循环或超时放弃。
### 工程启示：RAG 的边界与成本控制- 技能库的双刃剑效应：移除领域手册（-Domain）会导致 UM 任务通过率从 32.0% 降至 17.3%；但奇怪的是，在 PA 任务中，完全移除手册（-Both）反而比只保留部分手册表现更好。这表明过大的上下文可能引发 Agent 的“过度验证”和“拒绝行动”（Over-verification），导致其因不确定而放弃提交。
- MCP 优于 CLI：将 MCP 工具转换为 CLI 命令后，UM 任务通过率下降 6.7%。对于复杂的企业级工作流，结构化工具接口比自然语言命令行更可靠。
- 性价比之选：虽然 Claude Code + Opus 4.6 性能最强，但 OAI Agents + GLM-5.1 以极低的成本（$0.27）取得了不错的性价比，适合对容错率有一定要求的场景。
### 局限与展望CHI-Bench 证明了当前 Agent 在长时程、多角色切换任务上的脆弱性。未来的突破点可能不在于模型参数的堆砌，而在于 工作流编排的鲁棒性 和 状态管理的显式化 。对于工程师而言，不要指望 Agent 能完美处理端到端的行政工作流，但在单一角色、短链路的子任务中，它们已经是高效的辅助工具。
