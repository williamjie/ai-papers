**日期**: 2026-07-08

论文 : CanvasAgent: Enabling Complex Image Creation and Editing via Visual Tool Orchestration链接 : https://arxiv.org/abs/2607.05465现在的多模态大模型（MLLM）大多还停留在“看图说话”或“单步修图”的阶段。但真实的工程需求往往复杂得多：用户可能要求先定位物体、再抠图、接着替换背景，最后还要调整光影并锐化。这种长链条、状态依赖的任务，靠单一扩散模型或简单的 Prompt 根本搞不定。
CanvasAgent 的出现，正是为了解决这个“视觉工具编排”的空白。它不再把 Agent 当作被动观察者，而是将其训练为主动操纵视觉状态的“导演”，通过协调 11 种异构视觉工具（如生成、分割、OCR、超分等）来完成复杂工作流。
### 痛点：为什么现有方案不够用？
现有的多模态工具使用研究主要优化的是感知、搜索或特定领域的编辑。它们缺乏大规模的可执行图像创建轨迹监督。
具体来说，复杂图像创作有三个关键特性让传统方法失效：
- 长视距（Long-horizon）：后续操作严重依赖前一步产生的视觉资产。
- 视觉接地（Visually grounded）：Agent 必须在每次工具调用后检查中间结果，而不是假设成功。
- 状态保持（Stateful）：多张图片、掩码、裁剪区域共存，Agent 必须准确引用正确的资产 ID。
这本质上是一个轨迹学习问题，而非简单的指令到图像映射。
### 方法拆解：SFT + GRPO 的两阶段训练CanvasAgent 的核心在于其两阶段训练框架和精心设计的混合奖励函数。
1. 数据构造：CanvasCraft 数据集作者构建了包含 140K 条完全标注的可执行轨迹（CanvasCraft-SFT）和 10K 个强化学习任务规范（CanvasCraft-RL）。
- SFT 阶段：学习合法的 JSON 工具调用格式、参数生成以及跨工具依赖关系。这是为了稳定后续的 RL 训练，避免无效调用。
- RL 阶段：使用 GRPO（Group Relative Policy Optimization）在弱监督下探索更优的工具顺序和策略。
2. 核心 Insight：混合奖励函数（Hybrid Reward）
单纯的最终图像质量评估不足以指导过程优化。CanvasAgent 设计了一个结合结果与过程的奖励公式：
R(τ)=0.3⋅Ralign+0.1⋅Raes+0.2⋅Rtraj+0.4⋅RruleR(\tau) = 0.3 \cdot R_{align} + 0.1 \cdot R_{aes} + 0.2 \cdot R_{traj} + 0.4 \cdot R_{rule} 0.3 ⋅ R a l i g n ​ + 0.1 ⋅ R a es ​ + 0.2 ⋅ R t r aj ​ + 0.4 ⋅ R r u l e ​- 结果分（Outcome）：使用 LLM-as-judge 评估图像与提示词的对齐度以及美学质量。
- 过程分（Process）：
轨迹分：评估任务分解是否合理，工具选择是否恰当。
- 规则分：硬性约束，包括格式合法性、参数有效性、资产引用正确性以及效率惩罚（防止无意义的冗余调用）。
这种设计强制 Agent 不仅关注“图好不好看”，还要关注“步骤对不对”和“执行快不快”。
### 关键结果：RL 带来了质的飞跃在 CanvasCraft-RL 评估集（250个样本）上的表现令人印象深刻。以下是核心数据对比：

### 工程启示：如何落地复杂视觉 Agent？
- 状态管理是关键：CanvasAgent 显式维护图像资产引用（Asset References）。在工程中，你的 Agent 框架必须能追踪每一步输出的中间文件 ID，并在后续步骤中正确传递这些 ID，否则长链条任务必然崩溃。
- 奖励函数要细化：不要只给最终结果打分。对于多步工作流，必须引入过程约束（如格式检查、资产有效性验证），否则 RL 容易陷入“刷分”陷阱，生成大量无效但格式正确的调用。
- SFT 是 RL 的基石：直接从零开始做 RL 会导致探索不稳定（对齐度降至 0.472）。先用高质量轨迹做 SFT 初始化，再进行 GRPO 优化，是目前最稳健的路径。
### 局限与展望尽管 CanvasAgent 展现了强大的编排能力，但它依赖于预定义的 11 种工具集。对于超出该集合的新兴视觉操作（如特定的风格迁移或复杂的物理模拟），模型可能无法泛化。此外，LLM-as-judge 的主观性仍可能影响奖励信号的准确性。未来方向可能包括动态工具发现以及更细粒度的中间状态验证机制。
