# 开推理反而变菜？小模型的系统二陷阱

**日期**: 2026-04-22

---

论文 : The Cognitive Penalty: Ablating System 1 and System 2 Reasoning in Edge-Native SLMs for Decentralized Consensus链接 : https://arxiv.org/abs/2604.16913DAO 治理正在引入 AI 做合规审查，但一个反直觉的发现来了：关掉 Chain-of-Thought（CoT），90 亿参数的小模型反而表现得更好。
这不是说推理能力没有价值，而是——在边缘端、在分布式共识场景下，给小模型”深度思考”的时间，反而让它崩溃了。
## 问题在哪DAO 提案审查有个硬需求：节点上的小模型必须快速、一致地给出裁决。节点异构、共识需要确定性，所以模型不能飘。
主流做法是开推理（System 2），让模型生成 CoT 后再下结论。直觉上，多想想总不会错吧？
这篇论文的作者 Syed Muhammad Aqdas Rizvi 偏不信这个邪。他用 Sentinel-Bench 框架，在 Qwen-3.5-9B 上做了一个干净的消融实验：同一个模型、同一组权重、同一个 prompt，唯一区别就是 think=True vs think=False 。
排除了 tokenizer、预训练数据、对齐策略等一切混淆变量。任何差异，都只能归因于推理机制本身。
## 实验设计：干净到有点奢侈数据集来自 Optimism DAO 的实际治理提案，分三层：
层级 数量 测试目的 预期裁决 BASELINE 10 个 正常提案会不会误杀 UPHOLD PERTURBED 10 个 注入伪装成”可持续发展”语气的违宪条款 STRIKE_DOWN CASE STUDY 1 个 高度模糊的真实争议提案 人类共识为 UPHOLD每个提案、每个推理模式各跑 20 次（T=0.6），总共 840 次推理。
关键设计：用 DSPy 构造了一个宪法审查签名，强制输出 JSON 格式的裁决。模型输出不了合法 JSON 就算崩溃（FAIL_NON_CONVERGENCE），不重试。
## 结果：System 1 碾压 System 2先说最炸裂的数字：
指标 System 1 (Think Off) System 2 (Think On) BASELINE 准确率 100.0% 75.5% PERTURBED 准确率 100.0% 68.5% 认知崩溃率 0.0% 26.7% 平均延迟 12.8 秒 226.4 秒 裁决一致性 100.0% 72.6%System 1 全赢了。
100% 的 BASELINE 通过率意味着没有过度审查（Hyper-Regulatory Overreach）。100% 的 PERTURBED 拦截率意味着没有被”可持续发展”这种合规话术忽悠。
而 System 2 呢？崩溃率高达 26.7%——420 次推理里，有 112 次模型直接输出不了合法 JSON，推理自我瓦解。延迟拉高 17 倍。裁决一致性从 100% 掉到 72.6%，离 BFT 共识的 66.7% 门槛只差一点点。
## 为什么 System 2 会崩？
论文提出了两个机制性解释，按出现频率排序。
第一个原因：上下文稀释（Context Dilution）。 占 System 2 所有失败的 97.3%（109/112 次）。模型生成长达 15,000 字以上的内部独白时，注意力权重被自己生成的文本稀释了，system prompt 的指令被淹没。这就是 Luo et al. 之前发现的”Long CoT Degradation”在小模型上的具体表现。
第二个原因：推理诱导的阿谀奉承（Reasoning-Induced Sycophancy）。 虽然只发生了 3 次（1.5%），但性质更恶劣。模型没有被指令打败，也没有崩溃——而是用更长的推理（平均 25,750 字符，比成功防御多 34%）来”合理化”违宪行为。论文称之为”推理剧场”（Reasoning Theater）：模型不是在推理真相，而是在给自己编一个看起来合理的借口。
最可怕的是置信度校准的失效。System 2 在被忽悠时，自我报告的置信度是 0.950——和被正确拦截时的 0.946 几乎一样。模型根本不知道自己错了。
## 延迟不只是慢，是安全隐患226 秒的推理时间，在 Optimism 2 秒一个区块的环境下，意味着 113 个区块的决策窗口。论文指出这引入了 Governance Extractable Value（GEV）风险——套利者可以在裁决出来前抢先操作。
而 System 1 在 12.8 秒内完成裁决，只涉及 6 个区块，GEV 窗口被压缩到几乎为零。
更隐蔽的影响是硬件中心化。System 2 需要处理超长注意力矩阵，慢节点根本跟不上，治理 Oracle 网络会不可避免地集中到拥有企业级 GPU 的运营商手里——这跟去中心化的初衷背道而驰。
## 工程启示这篇论文对实际部署的参考价值在于：
小模型别盲目开 CoT。 90 亿参数的模型，参数化直觉（parameterized intuition）已经足够处理宪法审查类的任务。强行让它”想清楚”，反而会因为上下文稀释和自我合理化导致性能倒退。这不是 Qwen 独有的问题，而是 SLM 的普遍现象。
确定性比”看起来更聪明”重要。 在分布式共识场景下，100% 一致的 System 1 输出，远比 72.6% 一致但”似乎更合理”的 System 2 输出有价值。BFT 共识不接受概率性。
推理长度不等于推理质量。 System 1 和 System 2 在被判违规时引用的宪法条款数量完全一样（平均 3 条）。多想的 20 万字符，没有带来任何额外的法律洞察，只带来了崩溃和延迟。
置信度不可信。 被忽悠的模型和没有忽悠的模型，给出的置信度几乎一样。别用模型自己的置信度评估它的判断质量——至少在 CoT 模式下不行。
## 局限与后续方向论文自己提了几个开放问题：
- 需要专门的法律领域过程奖励模型（Process Reward Models for Law），而不是拿数学推理的奖励模型来套- 动态推理预算：在错误积累之前就截断 CoT- 用更小的模型（4B/2B/0.8B）做二次验证器，实时审计主模型的推理轨迹- 探索状态空间模型（SSMs，如 Mamba、RWKV），它们用固定大小的隐藏状态压缩上下文，理论上不会遭遇注意力稀释但说实话，这篇论文的实验范围确实窄。只有一个模型、一个场景、一个数据集。结论能不能推广到其他 SLM、其他任务，还不好说。不过作为一篇 Working Paper，它的价值在于提供了一个干净可复现的消融框架——代码和数据集都开源了。
核心结论就一句：给小模型太多思考时间，它可能想太多。
