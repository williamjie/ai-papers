**日期**: 2026-08-17

论文 : Beyond Final Scores: A Systematic Evaluation of Agents for Long-Horizon AI Research and Development链接 : https://arxiv.org/abs/2608.13417做 Agent 开发的工程师都知道，现在的评测榜单太“虚”了。一个 Agent 跑完长程任务，只给一个最终分数（Final Score），这就像考试只看总分，不管你是蒙对的还是真懂的，也不管你中间踩了多少坑。美团和 UCAS 的这篇新工作直接撕开了这个黑盒：他们提出了一套过程评估框架，揭示了当前顶尖模型在自动化研发中更像“工程优化器”而非“自主研究者”的本质。
### 为什么只看 Final Score 会误导人？
现有评测的核心痛点在于 信息丢失 。
同一个最终分数，可能来自两种完全不同的路径：
- 高效探索：早期就找到了正确方向，稳步提升。
- 盲目试错：前期毫无进展，后期靠运气撞大运。
更致命的是，传统评测忽略了 经验复用（Experience Reuse） 。Agent 在长程任务中积累的上下文、笔记和失败教训，是它进化的核心动力。如果评测把每次运行都视为独立事件，就无法判断 Agent 是否真的具备“学习能力”。
### 核心洞察：拆解研发闭环的三大能力作者没有引入复杂的 LLM Judge，而是设计了基于规则（Rule-based）的三个过程指标，精准定位瓶颈：
- 方案构建（Solution Framing, C1）：Agent 提出的方向是否有效？通过追踪运行过程中的最高分（Running Best Score）来衡量。
- 执行能力（Execution, C2）：想法能否落地？检查代码是否可运行、构建是否失败。
- 反馈控制（Feedback Control, C3）：面对回归（Regression）时，能否守住成果并快速恢复？
核心直觉 ：这三个维度相互独立。一个模型可能方向感极差（C1 低），但执行力极强（C2 高）；或者执行稳健，但一旦出错就一蹶不振（C3 低）。只有拆解开来，才能知道该优化模型的哪一部分。
### 关键结果：数据背后的真相作者在 7 个前沿模型、36 个长程任务上进行了大规模评测（约 10 万美元推理成本），发现了一些反直觉的现象：
1. 可靠性比峰值性能更能拉开差距在 avg@3 （三次运行平均分）上，最强与最弱模型的差距高达 0.237 ；而在 best@3 （最佳单次成绩）上，差距仅为 0.122 。
⚠️ 反直觉发现 ：低端模型也能偶尔跑出高端模型的成绩，但缺乏稳定性。这意味着当前 Agent 的瓶颈不在“上限”，而在“下限”。
2. 相似分数，截然不同的能力画像GPT-5.5 和 Gemini-3.1-Pro 的最终得分非常接近（0.663 vs 0.652），且方案构建能力相同（C1=0.555）。但拆解后：
- GPT-5.5：执行极强（C2=0.958），但反馈控制弱（C3=0.858），容易在迭代中丢失进展。
- Gemini-3.1-Pro：执行稍弱（C2=0.889），但反馈控制强（C3=0.920），善于守住成果。
3. 经验复用是双刃剑，甚至能改变排名通过对比“有历史经验”和“清空记忆”两种情况，作者发现：
- 任务内：经验通常有益，但 LongCat-2.0 对经验的依赖度最高（增益 +0.145），说明其独立推理能力较弱。
- 跨任务：经验迁移效果极不稳定。DeepSeek-V4-Pro 借助经验提升了 0.093 分，而 Gemini-3.1-Pro 反而下降了 0.017 分。
这意味着，初始排名靠后的模型，通过有效的经验管理，有可能在长程工作中反超领先者。
4. “创新”极其稀缺尽管执行分数普遍较高（平均 >0.88），但在人工审查中，仅有 3/252 的最佳方案被认定为具有方法论上的真正新颖性。绝大多数 Agent 只是在组合或微调现有技术，而非发明新算法。
### 工程启示：如何构建更好的 Agent 系统？
- 优化推理时策略（Inference-time Compute）：既然 best@3 和 avg@3 差距大，通过增加采样次数、选择最佳输出（Best-of-N）可以显著提升生产环境的稳定性。
- 重视 Harness 设计：原生工具链（Native Harness）比通用共享框架更能提升运行稳定性。不要低估工程环境对 Agent 表现的放大作用。
- 经验管理需去噪：简单的上下文保留可能导致“锚定效应”或误导。未来的 Agent 系统需要更智能的记忆筛选机制，而非简单地追加日志。
### 局限与展望该研究主要关注代码和系统优化任务，对于纯理论推导或创意生成的覆盖较少。此外，评估成本高昂（$100k+），限制了大规模迭代。但无论如何，这篇论文提供了一个可复现的诊断框架，提醒我们： 在追求 Agent “更聪明”之前，先让它“更稳定”、“更靠谱”。
