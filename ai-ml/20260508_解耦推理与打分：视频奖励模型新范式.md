# 解耦推理与打分：视频奖励模型新范式

**日期**: 2026-05-08

---

论文 : Think, then Score: Decoupled Reasoning and Scoring for Video Reward Modeling链接 : https://arxiv.org/abs/2605.05922在视频生成模型的后训练（Post-training）和测试时扩展（Test-time Scaling）中，视频奖励模型（Video Reward Model, RM）的质量直接决定了生成效果的天花板。然而，现有的 RM 范式陷入了一个尴尬的“二选一”困境：要么稳定但缺乏泛化能力，要么能推理但训练极不稳定。快手 Kling 团队提出的 DeScore 通过“先思考，后打分”的解耦范式，巧妙地将两者优势结合，不仅提升了泛化性，还大幅改善了训练稳定性。
## 现有方案的痛点：鱼与熊掌不可兼得？
目前的视频奖励模型主要分为两派，各有致命缺陷：
-判别式（Discriminative）RM：直接从多模态大语言模型（MLLM）的特征中回归标量奖励。
优点：使用 Bradley-Terry (BT) Loss 优化，收敛稳定。
- 缺点：缺乏显式的推理过程（CoT），容易陷入“捷径学习”（Shortcut Learning）。为了获得良好的泛化能力，往往需要海量数据堆砌，数据效率极低。
-生成式（Generative）RM：通过自回归生成包含 Chain-of-Thought (CoT) 的文本序列来输出奖励。
优点：显式的 CoT 提供了细粒度的语义监督，让模型理解“为什么好”，泛化能力显著强于判别式。
- 缺点：推理和打分耦合在同一个自回归采样链中。这导致两个严重问题：
信用分配困难：很难判断最终得分低是因为中间推理错了，还是最后打分错了。
- 高方差梯度：依赖强化学习（如 GRPO）优化整个序列，梯度方差随序列长度增加，导致训练剧烈波动，极难收敛。
核心 Insight ：为什么我们不能让模型“认真思考”以获得泛化能力，同时用“稳定回归”来打分以获得训练稳定性？
## 方法拆解：DeScore 的解耦艺术DeScore 的核心设计哲学是 解耦（Decoupling） 。它不再让一个自回归头既做推理又做打分，而是将过程拆分为两步：
- Think（思考）：MLLM 首先生成详细的 CoT 推理过程。
- Score（打分）：引入一个可学习的查询 token（[Reward]）和一个独立的回归头（Regression Head）。这个查询 token 聚合视频、文本 Prompt 以及生成的 CoT 信息，最终输出一个标量奖励。
### 关键技术直觉- 随机掩码机制（Random Masking）：在冷启动阶段，DeScore 以一定概率随机 Mask 掉 CoT。这强迫评分模块不能只依赖 CoT，必须同时理解原始的多模态视觉特征。这种设计增强了鲁棒性，防止模型过度依赖推理文本而忽略视频本身的视觉证据。
- 双目标强化学习（Dual-Objective RL）：这是解决训练不稳定的关键。
GRPO Loss：仅用于优化 CoT 的推理质量。
- 辅助 BT Loss：用于校准最终的标量奖励。
- 这种设计将“推理优化”与“奖励校准”分离。即使推理过程有波动，标量奖励依然通过稳定的 BT Loss 获得直接梯度，避免了 GRPO 高方差对最终得分的污染。

## 工程启示- 奖励建模不必“全自回归”：对于需要高精度标量输出的任务（如 RLHF 中的 Reward Model），尝试将“推理过程”与“数值输出”解耦。引入可学习的 Query Token 和回归头，可以显著降低训练方差。
- CoT 是泛化的钥匙，但需要保护：在训练中加入 Random Masking 是防止模型“偷懒”或“过拟合推理文本”的有效手段，迫使模型回归多模态本源。
- 双目标优化是 RL 的稳定器：在强化学习阶段，如果同时优化推理和最终得分，务必考虑引入辅助的监督损失（如 BT Loss）来校准最终输出，避免梯度冲突。
## 局限与展望DeScore 目前依赖于预训练的 CoT 数据进行冷启动，且在 RL 阶段需要同时维护 GRPO 和 BT Loss，增加了实现复杂度。未来工作可能探索更自动化的 CoT 生成策略，或进一步简化双目标优化的超参数调优难度。
总体而言，DeScore 为视频奖励模型提供了一条清晰且高效的工程落地路径，特别是在数据稀缺且要求高泛化性的场景中，具有极高的实用价值。
