# ⭐⭐⭐ 固定GPU预算下突破200万Token RL训练

**日期**: 2026-07-17

---

论文 : LongStraw: Long-Context RL Beyond 2M Tokens under a Fixed GPU Budget链接 : https://arxiv.org/abs/2607.14952长上下文推理（Long-Context Inference）已经卷到了百万 Token 级别，但强化学习（Reinforcement Learning, RL）后训练还卡在 256K 甚至更低。
这中间的巨大鸿沟，让 AI Agent 在部署时只能靠“长度泛化”硬撑，效果并不理想。
这篇来自 MindLab 的论文 LongStraw 给出了一个极具工程野心的解法：在不增加 GPU 数量的前提下，把 RL 训练的上下文窗口硬推到 200 万 Token 以上。
### 为什么长上下文 RL 这么难？
推理和训练对显存的占用逻辑完全不同。
推理时，Prefill 阶段算完 Prompt 的 KV Cache 存起来就行，前向图（Forward Graph）可以直接丢弃。
但 GRPO（Group Relative Policy Optimization）这类 RL 算法要求对同一个长 Prompt 下的多个回复（Responses）分别打分并反向传播。
这意味着你需要同时保留：长 Prompt 的激活值、多个短回复的前向图、以及所有的梯度状态。
显存消耗是二次方级别的，传统方案只能靠堆显卡（Scale-Out），比如用几百张 A100 跑 Ring Attention。
但大多数团队没有这种预算。LongStraw 的核心洞察在于： 训练图的“生命周期”才是瓶颈，而不是单纯的稀疏性。
### 核心设计：捕获一次，串行回放LongStraw 的设计哲学非常朴素且暴力： 把长 Prompt 和短回复彻底解耦。
- 无梯度捕获（No-Grad Capture）：首先对共享的长 Prompt 进行一次无前向图记录的前向传播。只保留模型架构所需的“条件状态”（如 RNN 状态或 KV Pages），其余激活值立即释放。
- 串行回放（Serial Replay）：在自动微分（Autograd）开启的情况下，逐个加载短回复分支。利用之前捕获的状态进行前向计算，算完梯度后立即释放该分支的图。
- 梯度累积：所有回复分支的梯度累加到同一个 Adapter 上，最后统一调用优化器更新参数。
⚠️ 关键 Trade-off ：这种设计用“额外的回放时间”换取了“极低的显存占用”。它把同时活跃的激活值从 Prompt + G*Response 压缩到了仅 Max(Response) 。
### 架构感知的状态管理不同模型架构需要保留的状态截然不同，LongStraw 做了精细化的适配：
- Qwen3.6-27B（混合架构）：包含 48 层 GDN（循环网络）和 16 层全注意力。GDN 只需要固定大小的循环状态；全注意力层则需要保留 KV Pages。LongStraw 将这些状态压缩在 GPU 上，通过 CP8（Context Parallelism 8）分片管理。
- GLM-5.2（MoE + MLA/DSA）：采用多潜伏头注意力（MLA）和稀疏注意力索引（DSA）。由于 MoE 的显存开销巨大，LongStraw 将 Prompt 状态移至 CPU 内存，仅在回放某一层时将其 Stage 到 GPU。
这种“物理所有权”的管理，避免了传统 Checkpointing 在 MoE 场景下因 Router 和 Expert 调度带来的显存碎片问题。
### 实验结果：固定预算下的极限测试论文在有限的硬件上展示了惊人的执行能力：
模型 硬件配置 上下文长度 关键指标 Qwen3.6-27B 8x H20 GPUs 2.1M Tokens Group Size 从 2 增至 8，峰值显存仅增加 0.21 GB Qwen3.6-27B 8x H20 GPUs 4.46M Tokens 压力测试上限，验证执行包络线 GLM-5.2 32x H20 GPUs 2.1M Tokens 完成全部 78 层的端到端执行路径验证注意，这里强调的是“执行容量（Execution Capacity）”。论文诚实地指出，当前的实现尚未完成分布式梯度的完全一致性校验（如 K/V Adapter 的梯度同步），因此这是一个系统工程上的可行性证明，而非完整的训练正确性验证。
### 工程启示与局限对工程师而言，LongStraw 的价值在于它揭示了 显存优化的新维度 ：
- 状态生命周期管理：不要试图优化所有激活值，只保留“未来依赖”的状态。
- CPU-GPU 协同：对于超大规模上下文，利用 CPU 内存作为 KV Cache 的缓冲区是可行的，前提是回放策略足够高效。
- 固定预算思维：在无法无限扩展集群时，通过算法-系统协同设计（Architecture-Aware Execution）可以突破硬件墙。
当然，局限性也很明显： 梯度截断 。由于 Prompt 状态被 Detached，反向传播无法流经长 Prompt 部分。这意味着模型无法通过 RL 直接优化对长上下文的理解能力，只能优化回复部分的策略。
这为后续研究留下了明确的方向：如何在保持低显存的同时，恢复长上下文梯度的完整性？
