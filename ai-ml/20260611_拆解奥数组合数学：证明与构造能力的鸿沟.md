# ⭐⭐⭐⭐ 拆解奥数组合数学：证明与构造能力的鸿沟

**日期**: 2026-06-11

---

论文 : ComBench: A Benchmark for Rigorous Proof Reasoning and Constructive Realization in Olympiad-Level Combinatorics链接 : https://arxiv.org/abs/2606.10479大模型在数学竞赛题上的表现正在逼近人类精英水平，但组合数学（Combinatorics）依然是那块最难啃的骨头。
这篇论文提出了 ComBench 基准测试，核心洞察非常犀利： “写出严谨的证明”和“给出可执行的构造”是两种截然不同的能力。
现有的评测大多只看最终答案或自然语言证明的质量。但这在组合数学中是不够的。比如 IMO 2025 P6，模型可能证明了某个数值是最优解，但如果它无法给出具体的铺砖方案（Witness），这个证明在工程上就是不可用的。ComBench 通过引入确定性代码验证器，强行将这两者解耦。
### 为什么需要这种新评测？
传统的数学基准（如 GSM8K、MATH）主要依赖答案匹配或基于 LLM 的评分。对于组合数学中的“存在性”问题，模型往往擅长论证“存在”，却拙于“构造”。
自然语言描述的构造方案难以被机器可靠地验证。ComBench 的设计直觉是：让模型输出一个具体的离散对象（如着色图、矩阵、策略），然后用 Python 代码进行确定性校验。这不仅评估了推理的严谨性，更评估了将抽象数学转化为具体可执行对象的“实现能力”。
### 方法拆解：Verifier-Gated 评分机制ComBench 包含 100 道奥数级组合数学题，分为两类：
- 分析导向（Analysis-centric）：侧重严谨的数学论证。
- 构造导向（Construction-centric）：要求提供具体的见证对象（Witness）。
其核心创新在于 Verifier-Gated Scoring 规则：
- 模型首先获得一个基于量表的证明分数（0/1/6/7 分制）。
- 如果题目需要构造，模型还需输出代码可解析的构造结果。
- 关键逻辑：如果构造验证失败，高分证明会被降级（7→6，6→1）。这意味着，即使你的证明写得再漂亮，如果造不出具体的例子，你的分数也会大打折扣。
这种设计迫使模型不能只停留在“口嗨”层面，必须完成从存在性论证到具体实例化的闭环。
### 关键结果：能力解耦的证据实验结果显示，即便是最强的前沿模型，在 ComBench 上也远未饱和。GPT-5.5 的总体平均分仅为 65.4%，Best@4 为 75.3%。
更有趣的是不同模型在不同能力上的表现差异：
模型 分析导向 Avg (%) 构造导向 Best@4 (%) GPT-5.5 62.4 77.7 Gemini-3.1-Pro 56.1 78.3 Kimi-K2.6 43.5 83.7⚠️ 反直觉发现 ：Kimi-K2.6 在分析导向的证明评分上显著弱于 GPT-5.5，但在构造导向的 Best@4 上却以 83.7% 的成绩反超所有模型。
这直接证明了“严谨证明推理”和“构造性实现”是正交的能力。有些模型擅长写漂亮的数学文章，有些模型则更擅长生成符合全局约束的具体结构。
在子类别分析中，“存在与构造”类问题对所有模型都是最难的。相比之下，计数（Counting）和图论（Graph Theory）问题得分较高，说明模型在处理局部结构枚举时表现更好，但在需要全局规划的存在性问题上依然薄弱。
错误分析显示，41.2% 的低分证明是因为“缺失核心机制”（Missing Core Mechanism），另有 20.0% 是“搞错了数学目标”。这说明模型的失败并非仅仅因为格式错误，而是深层的全局规划能力不足。
### 工程启示对于从事 Agent 开发或数学推理模型微调的工程师来说，这篇论文有几个重要启示：
- 不要迷信自然语言证明：在需要具体输出的场景（如代码生成、策略制定），必须引入确定性验证器（Deterministic Verifier）。LLM 自评分数往往存在幻觉，只有代码跑通才是硬道理。
- 构造能力需单独训练：如果你的应用场景涉及生成满足复杂约束的对象（如排班、布局、图着色），需要针对性地增强模型的“见证合成”能力，而不仅仅是提高其逻辑推理的流畅度。
- 评估体系升级：在评测数学或逻辑类模型时，采用“证明+构造”的双轨制评估能更真实地反映模型的可用性。
### 局限与展望ComBench 目前仅覆盖了组合数学领域，且验证器依赖于预先形式化的构造目标。如果模型给出了一个数学上正确但格式不符合预设的构造，可能会被误判为失败。此外，它并未涵盖代数、几何等其他奥数分支。
尽管如此，ComBench 清晰地划定了一条界线：当前的 LLM 在“理解”和“执行”之间仍有巨大鸿沟。填补这一鸿沟，可能是下一代数学模型突破的关键。
