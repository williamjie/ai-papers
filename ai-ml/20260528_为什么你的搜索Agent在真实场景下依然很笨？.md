论文 : VibeSearchBench: Benchmarking Long-horizon Proactive Search in the Wild链接 : https://arxiv.org/abs/2605.27882现有的搜索基准测试（如 BrowseComp）大多像是在做“填空题”：用户给出一个包含所有约束条件的完整查询，Agent 只要按图索骥找到答案即可。但在真实的工程落地中，用户的意图往往是模糊的、动态变化的，且无法一次性表述清楚。这篇来自小红书 Dots Studio 和 UniPat AI 的论文 VibeSearchBench 直击这一痛点，提出了“VibeSearch”范式，并揭示了当前最强模型在长程主动搜索任务上的巨大能力缺口。
### 为什么现有基准测试失效了？
作者指出了现有基准测试与真实用户行为之间的三个核心错位：
- 过度指定的查询（Over-specified Queries）：现有测试将所有限制条件打包进 Prompt，Agent 无需主动挖掘意图。
- 单轮交互（Single-turn Interaction）：缺乏多轮对话机制，跳过了最难的“意图澄清”环节。
- 固定 Schema 评估：真实世界的知识关系是复杂的图结构，而现有测试往往要求输出固定的表格或列表，这迫使 Agent 去适应格式而非理解内容。
### VibeSearchBench 的核心设计直觉VibeSearchBench 的设计核心在于模拟**双向收敛（Bidirectional Convergence）**的过程。它不是让 Agent 一次性给出答案，而是通过以下机制构建了一个更真实的交互环境：
-渐进式披露用户模拟器（Progressive-disclosure User Simulator）：
这是该 Benchmark 最巧妙的部分。用户 Persona 被设计为包含 KK 个阶段的信息需求。Agent 必须通过主动提问或提供部分结果来触发特定的“条件（Trigger Condition）”，才能解锁用户的下一层需求。如果 Agent 只是被动等待，交互就会陷入死循环。这迫使 Agent 具备主动意图 elicitation 的能力。
-无 Schema 的知识图谱评估（Schema-free Graph Evaluation）：
真实知识是网状的，而非线性的。Ground Truth 被构建为一个有向图 G∗=(V∗,E∗)G^* = (V^*, E^*)=(V∗,E∗)。Agent 的输出也是一个预测图 G^\hat{G}^。评估通过 LLM-as-Judge 进行图谱匹配，允许实体别名、关系同义词等语义等价表达。这种细粒度的三元组（Triplet）级 P/R/F1 计算，能更客观地反映 Agent 对复杂知识结构的构建能力。
### 实验结果：顶级模型也“翻车”了作者在 ReAct 和 OpenClaw 两种框架下测试了 7 个前沿模型。结果令人震惊： 即使是表现最好的 Claude Opus 4.6，其平均 F1 分数仅为 30.30 。这意味着在复杂的长程搜索中，Agent 依然只能捕获不到三分之一的有效信息。

- 资源消耗与性能不相关：GPT-5.4 消耗了最多的 Token 和工具调用次数，但 F1 最低。原因是其冗长的输出触发了频繁的上下文压缩（Context Compression），导致之前检索到的关键信息被丢弃，陷入“溢出 -> 遗忘 -> 重复搜索”的恶性循环。
- 主动性与性能正相关：Claude Opus 4.6 在 ReAct 下每轮用户回复平均执行 8.26 次 Agent 内部步骤，这种高主动性（Proactiveness）与其最高 F1 直接相关。相比之下，Gemini 的比值仅为 2.84，表现为被动等待，导致覆盖率严重不足。
- 架构增强无效：消融实验显示，OpenClaw 框架中的子代理协作（Sub-agent）、本地记忆（Local Memory）和终身记忆（Life-long Memory）均未能带来显著的 F1 提升。这表明当前的瓶颈在于模型本身的长上下文推理和意图建模能力，而非外部架构的堆砌。
### 工程启示对于正在构建搜索 Agent 的工程师来说，这篇论文给出了三个明确的信号：
- 重视上下文管理：在长程任务中，简单的截断或总结会导致灾难性的信息丢失。需要更智能的上下文压缩策略，或者设计能够容忍信息碎片化的检索机制。
- 培养“提问”能力：不要只训练 Agent 回答已知问题。需要在微调数据中加入大量的多轮澄清对话，让模型学会在信息不足时主动询问用户偏好（如“您对哪个年代的电影感兴趣？”）。
- 结构化输出的陷阱：强制要求输出 JSON 或固定表格可能会限制模型的探索空间。尝试使用更灵活的图结构或自由文本作为中间态，最后再统一格式化，可能有助于提高召回率。
### 局限与展望VibeSearchBench 目前仅包含 200 个任务，虽然覆盖了 20 个领域，但规模尚小。此外，评估依赖 LLM-as-Judge，尽管论文验证了其与人类专家的高度一致性（>98.5%），但在极端边缘案例下的主观性仍需警惕。未来，随着模型长窗口能力的提升，如何平衡“探索深度”与“上下文开销”，将是搜索 Agent 落地的核心挑战。
