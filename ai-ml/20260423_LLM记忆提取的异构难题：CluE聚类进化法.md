# LLM 记忆提取的异构难题：CluE 聚类进化法

**日期**: 2026-04-23

---

论文 : Self-Evolving LLM Memory Extraction Across Heterogeneous Tasks链接 : https://arxiv.org/abs/2604.11610做 Agent 或者持久化 AI 助手的人都知道一个痛点：模型得记住东西，但不同场景下”值得记的东西”完全不同。闲聊要记用户偏好，debug 要记操作步骤，解数学题要记推理链条。一篇 prompt 想通吃？几乎不可能。
这篇论文把这个直觉形式化了，造了一个 18 个数据集的异构基准 BEHEMOTH，然后证明了一个事实： 现有那些自进化 prompt 优化的框架（GEPA、ACE、MemEvolve），在面对异构任务时会翻车。 它们要么顾此失彼，要么把反馈信号稀释成一锅粥。
## 问题：为什么”一个 prompt 走天下”行不通现有记忆提取系统大概分两派：
- 个性化派：Mem0 提取偏好、日期、关系，构建实体图- 经验派：ReasoningBank 提炼成功策略和失败教训问题在于，真实世界的 AI 助手不可能只活在单一场景里。论文用 BEHEMOTH 基准验证了这个直觉——18 个数据集，分三档：个性化（5 个）、问题解决（7 个）、Agent 任务（6 个）。
静态 prompt 的实验结果很说明问题：
Prompt 个性化 MA 问题解决 MA Agent MA 总 MA 相对增益 No Memory 34.15% 46.52% 30.36% 37.84% — Simple 58.76% 48.76% 32.46% 46.00% 基准 Mem0 73.31% 45.97% 31.62% 48.48% +5.79% ReasoningBank 50.67% 50.72% 32.12% 44.51% +0.45% OpenMemory 57.39% 50.47% 34.93% 47.14% +4.74% Survey 62.05% 49.86% 33.58% 47.69% +4.83%Mem0 在个性化任务上碾压（73.31%），但问题解决和 Agent 任务几乎没提升。ReasoningBank 反过来，在 Agent 任务上 +2.49%，个性化反而跌了 10.78%。

## 现有自进化框架的困境既然静态不行，那就让 prompt 自己进化。但 GEPA、ACE、MemEvolve 这些框架都是为同构任务设计的，搬到异构场景就遇到一个两难：
- 更新太频繁：不同类别的样本把 prompt 往不同方向拉，导致过拟合- 更新太慢：异构反馈混在一起，细粒度的洞察被平均掉了实验结果印证了这个分析：
方法 个性化 RG 问题解决 RG Agent RG 总 RG GEPA -2.16% +2.86% +14.08% +5.06% ACE -4.38% +8.04% +4.93% +3.56% MemEvolve +10.76% +1.17% -3.25% +2.11% CluE +12.34% +8.39% +7.22% +9.04%GEPA 在 Agent 任务上猛涨 +14.08%，但个性化跌了 2.16%。MemEvolve 个性化涨了 10.76%，Agent 却跌了 3.25%。典型的”拆东墙补西墙”。
只有 CluE 在三个类别上全部正增长，总体相对增益 +9.04%，稳赢。
## CluE 的核心设计：聚类之后再说进化CluE（Cluster-based Evolution）的设计直觉很简单： 先把相似的提取场景聚在一起，分别分析，最后再综合。 四步走：
-摘要（Summarization）：每个样本生成一个提取场景摘要——要提什么类型的信息（操作步骤、用户偏好、推理链），难点在哪（长上下文、隐含信息、多轮推理）。关键是抽象掉表面细节，关注提取相关的属性。
-聚类（Clustering）：按提取场景分组，不管原始数据集是什么。比如”从长对话中提取程序性知识”可能同时包含 Agent 轨迹和数学解题步骤。聚类标签是动态的——可以新建、合并、拆分。
-聚类级分析（Cluster-based Analysis）：每个簇独立分析成功模式和失败模式。不同场景的建议互不干扰。
-跨簇提案（Cross-cluster Proposal）：把各簇分析喂给 Proposer，提取跨簇的通用原则，整理簇特定的结构化指南，冲突建议按记忆类别限定作用域。
这个设计的核心 insight 是： 异构问题的解法不是”更大更通用的 prompt”，而是”结构化地容纳多样性”。 CluE 生成的 prompt 包含完整的记忆分类体系（事实数据、用户偏好等），每个类别有定义和指南，同时保留跨域通用原则。
对比一下各方法进化出的 prompt 结构差异：
- GEPA：受限于固定上下文长度，每次只能看小 batch，严重偏向最近看到的样本（实验里是 AlfWorld），prompt 里塞满了领域特定的例子- MemEvolve：分析大 batch 但不分簇，异构信号互相抵消，最终 prompt 只有”禁止条款”，没有记忆分类体系- CluE：936 token，结构化的记忆分类 + 每类指南 + 通用原则## 泛化能力和持续场景分布外测试（3 个 hold-out 数据集）：

## 工程启示这篇论文对实际做 Agent 和持久化助手的人有几个直接指导：
- 不要指望一个 prompt 解决所有记忆提取问题。如果你的产品跨多个场景，静态 prompt 注定顾此失彼- 自进化 prompt 优化在异构场景下需要聚类意识。直接拿混合数据跑 GEPA 或 MemEvolve，效果可能不如预期——甚至会退化- 记忆分类体系比”禁止条款”更有用。MemEvolve 进化出来的 prompt 只有 penalty clause，而 CluE 的分类体系在泛化和持续场景中都表现更好- 更强的种子 prompt 不一定更好。从 Survey prompt（整体 MA 47.69%）开始进化时，GEPA 完全找不到改进，ACE 和 MemEvolve 反而产生负增益。CluE 仍然 +6.54%——聚类分析能保护已有优势的同时发现改进空间代码和数据已开源： https://github.com/ayyyq/heterogeneous-memory-extraction## 局限论文自己也提了几点：BEHEMOTH 虽然覆盖 18 个数据集，但真实部署的场景更复杂、交互历史更长。当前只关注记忆提取这一环，存储、检索、管理的全生命周期泛化仍是开放问题。
