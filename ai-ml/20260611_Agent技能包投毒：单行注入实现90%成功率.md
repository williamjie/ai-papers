论文 : POISE: Position-Aware Undetectable Skill Injection on LLM Agents链接 : https://arxiv.org/abs/2606.07943LLM Agent 正在快速普及，而“技能包”（Skill）作为扩展 Agent 能力的模块化文件，正成为新的供应链攻击面。这篇论文揭示了一个令人不安的事实：通过精心设计的单行注入，攻击者可以在不破坏用户任务的前提下，让 Agent 静默执行恶意代码，且现有静态扫描手段几乎完全失效。
### 痛点：可靠性与隐蔽性的死结现有的技能投毒攻击面临一个两难选择：
- YAML 头部注入：可靠但显眼。因为元数据位于文件顶部，任何异常的命令都会引起人类或扫描器的警觉。
- 正文随机注入：隐蔽但不可靠。将恶意命令散落在正文中，容易因上下文不匹配而被 Agent 自身识别为“不符合当前任务”从而跳过。
真正的威胁在于“隐形执行”：如果注入导致用户任务失败，用户就会检查技能包。因此，成功的攻击必须同时满足两个条件： 恶意载荷被执行 且 用户任务正常通过验证 。这就是论文提出的核心指标——攻击成功率（Attack Success Rate, ASR）。
### POISE：位置感知的单行注入艺术POISE 的核心洞察非常精妙： 不要散播恶意代码，而是将其压缩为一条看似无害的“前置步骤” 。
其设计逻辑包含三个关键步骤：
- 脚本间接化：将所有恶意行为封装在外部辅助脚本中，技能文件只保留一行调用命令。这利用了 Agent 通常不审查被调用脚本内容的盲区。
- 位置感知（Position-Aware）：不再随机插入，而是选择结构中天然允许额外指令的位置，如“编号步骤列表”或“安装/设置代码块”。这些位置本身就具备执行 Shell 命令的语境。
- 上下文融合：使用 LLM 生成符合周围语气的文本，将恶意调用伪装成常规的环境检查或依赖验证（例如：“运行脚本以确认环境合法性”）。
这种设计使得注入点既在 Agent 的执行路径上（保证可靠性），又在语义上合理（保证隐蔽性）。
### 实验数据：压倒性的优势论文在 Skill-Inject 和 SkillsBench 两个基准上进行了测试，结果令人震惊。以下是基于 codex+gpt-5.2 的主要对比数据：
方法 触发率 (Trigger) 验证通过率 (Verifier) 攻击成功率 (ASR) POISE 90.7% 97.3% 89.3% 随机位置基线 (B@k=2) 62.7% 94.7% 61.3% 仅 YAML 注入 89.3% 96.0% 86.7%关键发现 ：POISE 的 ASR 比随机位置基线高出 28.0 个百分点 。更重要的是，其任务验证通过率（97.3%）与干净技能包（96.0%）几乎无差别，这意味着用户完全感知不到异常。
在隐蔽性方面，论文测试了四种 LLM 静态扫描器。结果显示，这些扫描器对干净技能包的误报率高达 57%-92% 。相比之下，POISE 注入的技能包中，仅有 5.6% 被额外标记为高风险。这意味着攻击者可以轻易隐藏在巨大的噪音中。
### 工程启示：防御的脆弱性这篇论文对 Agent 安全架构提出了严峻挑战：
- 静态扫描已失效：由于合法技能包本身就包含 Shell 命令，区分“恶意调用”和“正常设置”在语义上极其困难。依赖 LLM 作为静态扫描器会产生极高的误报率，导致防御形同虚设。
- 信任边界模糊：Agent 默认信任技能包中的祈使句指令。论文指出，这是一种协议层面的缺陷——系统未区分“应执行的指令”和“仅供参考的文档”。
- 低成本防御建议：论文提出了一种轻量级防御——在任务开始前插入“不信任提示语”（Distrust Prompting），告知 Agent 技能包来自第三方且不可信。实验显示，这一简单措施可将攻击成功率降至 0%，且仅造成约 5 个点的任务性能损耗。
### 局限与展望目前研究主要基于受控的沙盒环境，真实世界中的技能市场分布、多样性可能影响攻击效果。此外，防御手段目前依赖于提示工程（Prompt Engineering），随着 Agent 厂商对底层信任机制的加固（如显式标记可执行内容），此类攻击的效果可能会减弱。
对于开发者而言，最直接的教训是： 不要盲目信任第三方技能包 。在集成外部技能时，必须引入运行时验证或显式的权限隔离，而非仅仅依赖静态扫描。
