论文 : minWM: A Full-Stack Open-Source Framework for Real-Time Interactive Video World Models链接 : https://arxiv.org/abs/2605.30263现在的视频大模型（如 Wan2.1、HunyuanVideo）画质已经卷到头了，但离真正的“世界模型”还差最后一公里：交互性。
大多数现有方案只能离线生成一段固定视频，无法根据用户实时的相机轨迹进行因果推演（Causal Rollout）。minWM 的出现，填补了从“高质量离线生成”到“低延迟交互式世界模型”之间的工程鸿沟。它不是一个单一的 SOTA 模型，而是一套完整的、可复现的工业级流水线。
### 为什么现有的视频模型不能直接做交互？
核心痛点在于 因果性 和 延迟 。
传统的扩散模型是双向（Bidirectional）的，生成第 tt 帧时能看到前后所有帧的信息。这保证了画质，但破坏了因果律——在真实世界中，你只能根据过去的动作预测未来，不能“偷看”下一秒。
此外，多步扩散模型的推理速度太慢。如果要实现实时交互（例如 VR 或游戏），首帧延迟必须极低。minWM 的目标很明确：把现有的双向 T2V/TI2V 基座模型，通过一套标准化的蒸馏流程，转化为支持相机控制、低延迟的自回归（Autoregressive, AR）世界模型。
### 方法拆解：两阶段“手术”
minWM 的核心设计直觉是 分而治之 。它没有重新训练一个庞大的端到端模型，而是将任务拆分为两个正交的模块： 可控性注入 和 加速蒸馏 。
#### 1. 相机控制注入：PRoPE 的巧妙应用要让模型理解“镜头往左移”，必须把相机参数（内参 KiK_i ​ 和外参 Tic→wT_{i}^{c \to w} c → w ​ ）编码进注意力机制。
minWM 采用了 PRoPE（Cameras as Relative Positional Encoding）方案。其核心 insight 在于 相对性 。它不直接注入绝对坐标，而是构建一个块对角变换矩阵 DtPRoPED_t^{\text{PRoPE}} PRoPE ​ ，注入到自注意力的 Query/Key/Value 中。
这样，Token t1t_1 ​ 和 t2t_2 ​ 之间的注意力权重，显式地依赖于它们的相对投影变换：
Pi(t1)Pi(t2)−1P_{i(t_1)} P_{i(t_2)}^{-1} ​ ) ​ P i ( t 2 ​ ) − 1 ​这种设计极其优雅，它既编码了相机内参（焦距等）的变化，也编码了姿态（Pose）的相对运动，同时保留了原始扩散模型的生成结构，无需修改骨干网络架构。
#### 2. 加速蒸馏：Causal Forcing++ 流水线有了可控的双向模型，下一步是把它变成“快且因果”的 AR 模型。minWM 集成了 Causal Forcing 和 Causal Forcing++ 流程，分为三步走：
- Stage 1: AR 扩散训练。通过 Teacher Forcing，将双向模型微调为 AR 扩散模型。此时模型具备了因果生成能力，但仍是多步去噪，速度慢且存在暴露偏差（Exposure Bias）。
- Stage 2: 少步初始化。这是提速的关键。minWM 支持两种路径：
Causal ODE：离线生成大量 PF-ODE 轨迹进行蒸馏。效果好但存储开销大。
- Causal CD (一致性蒸馏)：理论等价于 ODE，但无需离线数据生成，直接在训练时通过 EMA 模型计算梯度。这是工程上的巨大优化，省去了繁琐的数据预处理。
- Stage 3: 非对称 DMD。由于 AR Teacher 的质量不如原始双向模型，直接蒸馏会导致画质下降。minWM 最后使用非对称分布匹配蒸馏（Asymmetric DMD），以高质量的双向模型为“真实分布”参考，对少步 AR 学生模型进行后训练对齐。这一步确保了速度提升的同时，画质不崩盘。

### 工程启示：数据质量 > 模型规模这篇论文最宝贵的部分不是算法本身，而是那些 踩坑总结出的工程直觉 。
⚠️ 反直觉发现 ：直接使用带有感知估计相机位姿的数据集（如 SpatialVid），模型根本学不会相机控制。
作者发现，感知算法估算的相机轨迹存在噪声和不一致性，导致模型无法建立准确的“动作-视觉”因果映射。
解决方案 ：必须使用 Ground-Truth 级别的轨迹 。
- 3D 重建+重渲染：从 DL3DV 数据集重建场景，沿预设轨迹渲染视频。
- 世界模型生成：利用已有的 WorldPlay 模型，基于 OpenVid 图像生成带有精确相机控制指令的视频。
此外，关于训练超参数的 ablation 也极具参考价值：
- 训练步数：HY1.5 模型在 1k-2k 步时完全不可控，5k 步开始响应，8k 步才达到强可控性。
- Batch Size：Wan2.1 模型若 Batch Size < 4，几乎无法学习相机控制；Batch Size = 16 时效果稳定。
### 局限与展望minWM 目前主要聚焦于 相机控制 。对于更复杂的交互（如人物姿态 Pose、物体操作 Object Manipulation），框架尚未覆盖。此外，虽然首帧延迟极低，但长视频生成的累积误差（Error Accumulation）仍是 AR 模型的通病，需要后续在记忆机制上做进一步优化。
总的来说，minWM 为工程师提供了一条从“玩具模型”到“可用产品”的清晰路径。如果你想构建自己的交互式视频 Agent，这套代码和调参经验比任何 SOTA 论文都更有价值。
