论文 : What Should Agents Say? Action-state Communication for Efficient Multi-Agent Systems链接 : https://arxiv.org/abs/2606.05304在多智能体系统（Multi-Agent Systems, MAS）的工程落地中，Token 成本往往是阻碍规模化应用的最大痛点。这篇来自新加坡科技设计大学的研究直击要害：Agent 之间到底该传什么？作者发现，现有的“自由发挥”式通信不仅浪费算力，还严重拖慢推理效率。
### 痛点：Agent 之间的“废话文学”
目前的 MAS 架构（如角色分工、辩论机制）大多关注“谁在什么时候说话”，却忽视了“说了什么”。默认情况下，Agent 会将包含完整思维链（Chain-of-Thought）、冗余解释甚至自我对话的原始输出直接追加到共享历史中。
这导致两个严重后果：
- 上下文窗口爆炸：下游 Agent 必须重复读取上游所有冗长的中间过程。
- 信息噪声大：关键的动作指令和状态更新被淹没在海量的自然语言描述中。
作者对比了五种常见通信策略（全量转发、精简生成、仅结论、简短总结、仅产物），发现 没有一种固定策略在所有拓扑结构中都是最优的 。例如，“仅结论”在顺序管道中有效，但在需要证据交互的场景下会因为缺乏上下文而失效。
### 核心 Insight：公私分离的通信协议基于上述观察，作者提出了 PACT（Protocolized Action-state Communication and Transmission） 。其核心直觉非常工程化： 将 Agent 的“私人计算”与“公共通信”严格解耦。
PACT 不改变 Agent 内部的推理逻辑，而是在消息进入共享历史前，通过一个投影函数将其压缩为紧凑的 Action-State（动作-状态） 记录。这条记录仅包含三个关键字段：
- ACTION：发送者做了什么，或要求接收者做什么。
- STATE：支撑该动作的证据、观察结果或工具反馈。
- RESULT：下游可直接复用的产物（如检索到的事实、修正后的代码）。
这种设计确保了共享历史中只保留“对后续动作有直接贡献”的信息，而将中间的推导过程留在 Agent 的私有上下文中。
### 关键结果：省钱且更强实验在两个典型 MAS 设置（证据分割交互、顺序管道）及真实编码框架（OpenHands, SWE-agent）上进行，使用 Qwen3 系列模型。数据表明，PACT 显著改善了性能-成本前沿。
1. 控制环境下的效率提升在 HotpotQA 和 AIME 等基准测试中，PACT 相比基线方法平均减少了 38.7% 的 Token 消耗，同时保持或提升了任务准确率。

2. 真实编码框架的落地效果PACT 被移植到 OpenHands 和 SWE-agent 中，作为轻量级的代理钩子（Proxy Hook）运行：
- OpenHands：在 SWE-bench Verified 上，解决率从 19.40% 提升至 23.00% (+3.6 pp)，同时每个解决的实例消耗 Token 减少 10.3%。
- SWE-agent：输入 Token 大幅削减 50.4%（从 314.6M 降至 156.0M），解决率基本持平，每解决一个问题的成本降低 47%。
### 工程启示与局限对于正在构建 Agent 应用的工程师，PACT 提供了明确的优化方向：
- 结构化通信优于自然语言：不要指望 LLM 能自动提炼重点，显式定义 Action、State、Result 字段能大幅降低下游解析成本。
- 中间件层介入：PACT 实现为一个代理钩子，无需修改底层 Agent 代码即可生效，适合现有系统的低成本改造。
局限性 ：目前 PACT 主要验证于共享历史为主要成本来源的场景。对于短交互或动态路由的网络，其收益可能有限。此外，如何自动确定哪些信息属于“必要状态”而非“冗余细节”，仍是未来需要探索的方向。
总之，这篇论文提醒我们：在多智能体协作中， “说什么”比“怎么说”更影响系统效能 。通过协议化通信，我们可以在不牺牲智能的前提下，实现成本的指数级优化。
