# ⭐⭐⭐½ Agent技能持续进化：决策历史的价值

**日期**: 2026-07-01

---

论文 : SkillHone: A Harness for Continual Agent Skill Evolution Through Persistent Decision History链接 : https://arxiv.org/abs/2606.08671现在的 Agent 技能（Skill）优化大多停留在“单次迭代”层面。跑完一轮，拿到个更好的 Prompt 或脚本就完事了。但这有个致命问题：下次再优化时，Agent 往往忘了上次为什么改、试过什么失败方案。
SkillHone 这篇论文的核心洞察非常工程化： 不要只保留最终产物（Artifact），要保留决策历史（Decision History）。
### 痛点：只有结果没有过程现有的 Skill 生成方法（如 Skill-Creator）或反思优化方法（如 GEPA、Hermes-SE），本质上都是“黑盒进化”。它们把技能看作一个静态文件，每次优化都从零开始评估。
这就导致了一个严重的“上下文丢失”问题。如图 1 所示，当环境变化（比如 API 限流、网页改版）时，新的 Agent 可能会重复尝试之前已经证明无效的修复方案，甚至引入旧的 Bug。因为之前的诊断理由、被拒绝的备选方案、以及评估证据都随着那次运行的结束而消失了。
### 核心设计：持久化的决策记录SkillHone 引入了一个“持久化决策历史”机制。它不仅仅保存 SKILL.md 的版本差异（Diff），而是将每次迭代打包成一个结构化的决策记录 hth_t ​ ：
- 诊断 (qtq_t​)：发现了什么问题？
- 修订提案 (rtr_t​)：打算怎么改？
- 评估证据 (ete_t​)：修改后效果如何？（注意：这里是脱敏后的报告）
- 结果 (oto_t​)：接受、拒绝还是推迟？
这种设计的精妙之处在于 角色分离与权限隔离 。SkillHone 将子 Agent 分为“优化团队”和“评估团队”。
- 优化侧：只能看到脱敏后的评估报告和过往决策历史，不能直接访问原始测试数据（Probes）或验证器。
- 评估侧：可以运行技能并查看详细 Trace，但不能修改技能仓库。
这种隔离防止了 Agent 对测试集过拟合（Memorization），同时通过“脱敏报告”传递反馈。更重要的是，后来的优化 Agent 可以查阅历史：“哦，这个 Bug 上周修过一次，当时试了方案 A 失败了，原因是 X，所以这次我直接避开方案 A。”
### 实验表现：碾压基线论文在深度研究（Deep Research）场景下进行了测试，因为这类任务最依赖技能的组织能力和容错机制。
1. 公开基准测试 (GAIA & WebWalkerQA-EN)
在“原始开放网络”设置下（即没有预集成的商业搜索栈），SkillHone 的表现令人印象深刻：
系统 GAIA Avg. WebWalkerQA-EN Avg. Existing-Skills (直接加载) 41.7% 50.2% Skill-Creator 44.1% 52.6% Hermes-SE 50.4% 53.0% SkillHone (Ours) 64.6% 66.4%- SkillHone 在 GAIA 上比 Hermes-SE 高出 14.2 分，比直接加载现有技能高出 22.9 分。
- 甚至在没有商业搜索加持的情况下，它也比拥有商业检索支持的 Deep-Research Agent 高出 15.8 分（GAIA）。
2. 消融实验：决策历史是关键为了验证核心组件的价值，论文做了消融实验：
- 无决策历史 (w/o decision history)：GAIA 得分从 64.6% 跌至 51.2%（下降 13.4 分）。
- 无角色分离 (w/o role separation)：GAIA 得分跌至 58.2%（下降 6.4 分）。
⚠️ 关键发现 ：决策历史带来的增益远大于角色分离。这说明“记住为什么这么改”比“谁在改”更重要。
3. 跨模型迁移能力SkillHone 优化的技能包可以直接迁移到 Claude Sonnet 4.6 上，无需重新优化。在 GAIA 上，迁移后的得分达到 72.4% ，远超其他基线。这证明 SkillHone 学到的是通用的任务流程（Procedure），而非针对某个特定模型的拟合。
4. 内部部署实测在腾讯内部的工具中介分析场景中，SkillHone 对 7 种常见技能进行了优化，平均准确率提升了 18.8 个百分点。其中计数、聚合和结构解析类任务的提升尤为显著（+20%~30%）。
### 工程启示这篇论文给 Agent 开发者的最大启发是： 把 Agent 的进化过程当作软件工程来管理。
传统的 Prompt 优化往往是一次性的“调参”。但在实际生产中，Agent 需要长期维护。SkillHone 提出的“Issue-PR-Merge”式的工作流（见附录 B），实际上是将 Git 的版本控制理念引入了 Agent 技能的生命周期管理。
- 不要丢弃失败案例：被拒绝的修订方案包含了宝贵的负向知识。
- 结构化反馈：评估侧返回的不应只是一个分数，而应是包含故障模式分析的脱敏报告。
- 权限隔离：优化者和测试者必须分离，以防止作弊和过拟合。
### 局限与展望目前 SkillHone 主要关注单一技能的独立进化。在多技能相互依赖、共享资源冲突的场景下，如何协调多个技能的协同进化，仍是未解之谜。此外，决策历史的长度随着迭代增加会迅速膨胀，如何高效检索和利用长历史也是一个工程挑战。
总之，SkillHone 展示了一条从“一次性生成”走向“持续维护”的 Agent 技能演进路径。对于构建长期运行的生产级 Agent 系统而言，保留“决策记忆”可能比单纯追求单次优化的精度更有价值。
