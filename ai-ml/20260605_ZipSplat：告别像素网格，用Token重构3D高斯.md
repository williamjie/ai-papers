# ⭐⭐⭐½ ZipSplat：告别像素网格，用 Token 重构 3D 高斯

**日期**: 2026-06-05

---

论文 : ZipSplat: Fewer Gaussians, Better Splats链接 : https://arxiv.org/abs/2606.05102现在的 Feed-Forward 3D Gaussian Splatting（前馈式 3D 高斯溅射）有一个巨大的工程痛点：模型把“像素”和“高斯点”强行绑定。
这意味着无论场景是一面空白的墙，还是纹理复杂的雕塑，只要占据相同的像素面积，就会生成相同数量的高斯点。
这种“像素对齐（Pixel-aligned）”的设计导致冗余极高，且内存占用完全取决于相机分辨率，而非场景本身的几何复杂度。
ZipSplat 的核心直觉非常直接：把 3D 重建从 2D 像素网格中解放出来，改用“场景 Token”来驱动高斯点的生成。
它不再沿着射线逐像素预测，而是提取视觉特征后通过聚类压缩，让模型只在几何复杂的地方密集分布高斯点。
这种设计不仅大幅减少了计算量，还解决了多视角重叠导致的重复预测问题。
### 核心方法拆解：从“像素”到“Token”的跃迁ZipSplat 的工作流可以分为三个关键步骤，彻底重构了高斯点的生成逻辑：
-特征提取与聚类压缩模型首先利用预训练的多视图骨干网络（如 DA3）提取密集视觉 Token。
接着在特征空间进行 K-Means 聚类，将冗余的视觉 Token 压缩为紧凑的场景 Token。
设计亮点：这种聚类是在推理阶段动态进行的。通过调整压缩率 rr，你可以像调节旋钮一样，在同一个训练好的模型上连续切换“高保真”或“轻量化”模式，无需重新训练。
-注意力机制与解码聚类虽然高效但会丢失细节，因此 ZipSplat 使用交叉注意力和自注意力层，让场景 Token 回溯原始视觉信息以恢复细节。
最后，一个轻量级的 MLP 将每个 Token 解码为一组（默认 32 个）具有自由 3D 位置的高斯点。
-无约束的 3D 放置这是最反直觉的设计：高斯点不再被限制在相机射线上，而是直接在 3D 空间中自由定位。
为了防止模型“放飞自我”，作者引入了单向 Chamfer Loss（几何监督损失），将游离的高斯点拉向真实场景表面，同时结合耦合初始化策略确保训练稳定。

### 工程启示与落地建议对于正在构建实时 3D 重建系统的工程师，ZipSplat 提供了两个极具价值的思路：
-动态质量调节（Quality-Efficiency Trade-off）
由于压缩率 rr 是推理参数，你可以在同一模型上实现“自适应渲染”。
在算力受限的边缘设备上，调低 rr 以获取流畅帧率；在云端则调高 rr 追求极致画质。这种灵活性是传统像素对齐方法无法提供的。
-打破分辨率枷锁如果你的应用场景涉及不同分辨率的相机输入（如手机与无人机混合），ZipSplat 的 Token 机制能更好地统一表征，避免因分辨率差异导致的内存爆炸或细节丢失。
### 局限与展望尽管 ZipSplat 表现出色，但仍存在边界：
- 极端压缩失效：当压缩率极低（如 r=0.1r=0.10.1）时，模型可能无法覆盖整个场景，导致渲染空洞。
- 高频色彩细节：在稀疏视角下，由于像素对齐方法能直接复制输入颜色，ZipSplat 在 LPIPS 指标上略逊一筹，因为它需要从聚合 Token 中预测色彩。
总的来说，ZipSplat 证明了 3D 重建不需要被 2D 像素网格束缚。通过引入 Token 化和自由 3D 放置，它在保持甚至提升画质的同时，极大地降低了存储和计算开销。这是迈向高效、通用 3D 生成模型的重要一步。
