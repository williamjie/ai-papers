论文 : EvoPolicyGym: Evaluating Autonomous Policy Evolution in Interactive Environments链接 : https://arxiv.org/abs/2607.02440现在的 Coding Agent 已经能写代码、调工具了，但“通过反馈迭代优化策略”的能力到底强不强？现有评测要么只看最终分数（掩盖了瞎试的过程），要么搞成开放式软件工程任务（变量太多无法归因）。
这篇论文提出了 EvoPolicyGym ，一个专门评估 Agent 在有限交互预算下，如何通过环境反馈自主进化可执行策略的基准测试。它不看你最后赢没赢，而是看你怎么赢。
### 痛点：为什么现有评测不够用？
现有的 Agent 评测存在两个极端：
- 静态补丁类（如 SWE-bench）：只看最终代码是否通过单元测试，忽略了软件演进中的多轮调试和质量退化。
- 开放式工程类：任务规格不断演变，难以隔离出 Agent 纯粹的“策略优化”能力。
我们需要一个受控环境，让 Agent 在固定预算下反复提交策略、获取反馈、修改代码。 EvoPolicyGym 的核心 insight 是：将“策略进化过程”本身作为评估对象，而不仅仅是任务执行结果。
### 方法拆解：受限预算下的进化博弈EvoPolicyGym 的设计非常克制且精准：
- 固定预算：每个环境仅给 128 个 Episode 的交互预算。这迫使 Agent 必须权衡“探索”与“利用”，不能无脑试错。
- 严格隔离：Agent 只能看到训练集的反馈，验证集和测试集对 Agent 完全隐藏。最终得分取决于隐藏验证集选出的最佳 Checkpoint 在测试集上的表现。
- 轨迹诊断：不仅记录最终分数，还记录完整的“执行-反馈-修订”轨迹。
这种设计剥离了外部因素，直接考察 Agent 将稀疏的行为证据转化为鲁棒策略改进的能力。
### 关键结果：GPT-5.5 统治力与任务类型差异在 Core16 基准（涵盖 Gym/Box2D, MuJoCo, MiniGrid, Robotics/Driving）上，各模型表现分化明显：

### 深度洞察：结构合成 vs 参数微调论文最精彩的部分在于对进化机制的拆解。作者将任务分为两类：
- 结构主导型（Synthesis-dominant）：如 MiniGrid、CarRacing，需要构建感知、记忆或规划模块。
- 调参主导型（Tuning-dominant）：如 MuJoCo 控制，只需调整增益和阈值。
数据揭示了关键差异：
- 在结构主导任务中，GPT-5.5 和 Claude Opus 4.7 的“结构编辑”成功率高达 41% 和 48%。
- 相比之下，MiniMax-M3 和 DeepSeek-V4-Pro 的结构编辑成功率仅为 10% 和 3%，大部分时间在无效地重构代码。
- 在调参任务中，所有模型差距缩小，说明一旦控制架构正确，微调相对容易。
结论 ：强 Agent 的核心壁垒不在于调参，而在于能否发现并构建出适配任务的计算结构（如视觉状态提取、搜索逻辑）。复杂代码本身不是目的，任务适配的机制才是关键。
### 工程启示- 评估需看轨迹：不要只看最终分数。分析 Agent 的“预算消耗曲线”和“编辑类型”，能更真实地反映其推理效率。
- 结构优先于参数：在构建自主进化系统时，应鼓励 Agent 先建立正确的控制流和数据流结构，再进行参数优化。盲目调参是低效的。
- Harness 很重要：GPT-5.5 配合 Codex Harness 表现最佳，说明工具链对策略进化的影响不可忽视。
### 局限与展望目前基准仅覆盖了 16 个经典 RL 环境，虽然适配器支持更多环境（如 BrowserGym），但尚未全面验证。未来可探索更复杂的长期依赖任务和更开放的工程场景。
总之，EvoPolicyGym 为理解 Agent 的“自我改进”能力提供了一把手术刀。它告诉我们：真正的智能进化，是结构创新与预算管理的艺术。
