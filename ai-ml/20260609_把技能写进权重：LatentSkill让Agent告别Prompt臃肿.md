# ⭐⭐⭐½ 把技能写进权重：LatentSkill让Agent告别Prompt臃肿

**日期**: 2026-06-09

论文 : LatentSkill: From In-Context Textual Skills to In-Weight Latent Skills for LLM Agents链接 : https://arxiv.org/abs/2606.06087现在的 Agent 系统有个尴尬的痛点：为了让模型“记住”复杂技能，我们通常把大段的操作指南塞进 Prompt。这不仅让上下文窗口迅速膨胀，还导致每次决策都要重复支付昂贵的 Prefill 成本。更糟糕的是，明文暴露的技能文本容易受到提示词注入攻击。LatentSkill 提出了一种极客式的解法：别在 Prompt 里写技能了，把它编译成 LoRA 权重，直接“注射”进模型参数空间。
### 痛点：Prompt 里的技能是“一次性消耗品”
现有方案如 In-Context Skill，本质上是把技能文档当作静态文本检索并插入 Prompt。随着交互轮次增加，同样的技能描述被反复加载，造成严重的 Token 浪费。虽然也有通过全量微调（Fine-tuning）将知识固化进模型的方法，但这破坏了技能的模块化特性——你无法在推理时动态卸载或组合特定技能。LatentSkill 的核心洞察在于： 技能不应该只是文本，而应该是可插拔的参数增量。
### 方法拆解：Hypernetwork 充当“技能编译器”
LatentSkill 的设计非常巧妙，它引入了一个基于 Transformer 的 Hypernetwork（超网络）作为“技能编译器”。
- 编译阶段：给定一段文本形式的技能描述 ss，编译器通过单次前向传播生成一组 LoRA 权重 Δs\Delta_s​。这个过程冻结了主干 LLM 的参数，只训练编译器。
- 推理阶段：在 Agent 执行任务时，不再将技能文本放入 Prompt，而是将生成的 LoRA 挂载到主干模型上。公式表达为 W′=W+αrBsAsW' = W + \frac{\alpha}{r} B_s A_s=W+rα​Bs​As​，其中 α\alpha 控制注入强度。
这种设计的精妙之处在于解耦了“技能定义”与“技能执行”。编译器在预训练阶段学习将程序化文本映射为有效的权重扰动，而在监督微调（SFT）阶段，它利用教师轨迹数据确保生成的 LoRA 能稳定引导多步决策。这意味着，你可以像管理插件一样管理技能：加载、卸载、甚至算术组合，而无需重新训练主干模型。
### 关键结果：效率与性能的双赢论文在 ALFWorld（具身智能）和 Search-QA（搜索增强问答）两个基准上进行了严格测试，对比基线包括 Vanilla、Few-shot、Reflexion 以及直接插入技能的 In-Context Skill。
性能提升显著：
- ALFWorld：LatentSkill 在 Seen 和 Unseen 分割集上的平均成功率分别比 In-Context Skill 高出 21.4 和 13.4 个百分点。特别是在复杂的 Pick2 任务（未见样本）上，达到了 70.6%，远超第二名 41.2 个点。
- Search-QA：平均 Exact Match (EM) 分数达到 35.6，优于所有基线方法。
成本大幅降低：
- Token 节省：在 ALFWorld 上，Prefill Token 开销减少了 64.1%；在 Search-QA 上，技能相关的 Token 开销降低了 72.2%。
- 交互更短：在 Seen 分割集上，平均每集步骤数从 Vanilla 的 35.0 步降至 28.4 步。这说明权重化的技能不仅省 Token，还能让 Agent 更快找到正确路径。
⚠️ 反直觉发现：技能权重具有几何结构论文通过 MDS 可视化发现，不同领域的技能 LoRA 在权重空间中形成了清晰的聚类（如代码、金融、写作技能各自成团）。这意味着编译器学到的不是随机噪声，而是有语义结构的程序化知识表示。
### 工程启示：可控性与安全性LatentSkill 带来的最大工程价值在于 可控性 。通过调节注入系数 α\alpha ，我们可以精确控制技能的影响强度。实验显示，性能随 α\alpha 呈倒 U 型曲线（最优值通常在 0.5-0.6 之间），这比 In-Context Skill 的“全有或全无”要灵活得多。
此外，安全性得到显著提升。在面对 Hijack（提示词劫持）攻击时，In-Context Skill 的成功率从 52.9% 暴跌至 8.57% ，而 LatentSkill 仍保持 38.6% 的鲁棒性。因为技能不再以明文形式存在于 Prompt 中，恶意指令难以直接覆盖或提取它。
### 局限与展望尽管前景广阔，LatentSkill 目前仍有边界。首先，它依赖于预先训练好的编译器，新领域的冷启动需要大量数据支持。其次，技能组合（Composition）要求语义对齐，简单的 LoRA 相加会导致共享组件过度放大，必须通过细粒度的组件分解来实现有效融合。未来，随着编译器泛化能力的提升，我们或许能看到一个真正的“技能商店”，用户只需下载几个 MB 的 LoRA 文件，即可让 Agent 瞬间掌握新技能。
