# ⭐⭐⭐ Agent自进化：从Prompt到模型的工程全景

**日期**: 2026-07-16

---

论文 : Self-Improvements in Modern Agentic Systems: A Survey链接 : https://arxiv.org/abs/2607.13104现在的 Agent 系统大多还是“一次性”的。你调好 Prompt，配好工具，上线后它就僵化了。遇到新任务？改代码。遇到新数据？重训练。这种静态架构在动态环境中极其脆弱。这篇综述提出了一套统一的视角： Agent 的自我进化（Self-Improvement） 。它不只是让模型变聪明，而是让系统具备从经验中自动迭代的能力。对于工程师来说，这意味着我们不再需要手动维护每一个 Agent 版本，而是可以构建一个能“自我修复”和“自我增强”的生产系统。
### 为什么现有方案不够用？
早期的 Agent 研究往往把重点放在基础模型（Foundation Model, FM）的微调上。但微调成本高、周期长，且容易引发灾难性遗忘。另一方面，单纯的 Prompt 优化虽然快，但缺乏长期记忆和结构化知识的积累。现有的综述通常将这两者割裂开来讨论，导致工程师难以找到一个统一的框架来权衡“改参数”还是“改结构”。
这篇论文的核心洞察在于： 现代 Agent 是一个由基础模型（认知核心）和操作脚手架（Scaffold）组成的复合系统。 自我进化不应局限于某一部分，而应被视为一个整体的自适应过程。
### 方法拆解：双路径进化框架论文提出了一个清晰的双路径分类法，这对工程落地极具指导意义：
-基础模型改进（Foundation Model Improvement）
核心逻辑：通过更新模型参数 θt→θt+1\theta_t \to \theta_{t+1}​→θt+1​ 来实现长期、稳定的能力固化。
- 驱动信号：
内在生成演示（Intrinsic Generative Demonstrations）：如 Self-Instruct，让模型自己生成训练数据。
- 内在评估反馈（Intrinsic Evaluative Feedback）：如 Constitutional AI，利用模型自身的判断力进行对齐和优化。
- 外在探索经验（Extrinsic Exploratory Experience）：通过与真实或模拟环境交互获得的奖励信号，结合 RLHF 或 RLVR 进行更新。
- 工程价值：适合需要长期积累、通用能力增强的场景，但计算开销大。
-脚手架改进（Scaffolding Improvement）
核心逻辑：不改变模型参数，而是更新非参数的结构组件 Σt→Σt+1\Sigma_t \to \Sigma_{t+1}​→Σt+1​。这包括 Prompt、记忆（Memory）、工具（Tools）和控制逻辑。
- 关键优势：速度快、可逆性强、成本低。
- 细分领域：
Prompt 优化：从标量反馈优化（如 OPRO）到文本梯度优化（如 TextGrad），甚至基于种群的进化（如 GPTSwarm）。
- 记忆演化：不仅存储数据，还优化记忆的结构（如图结构、向量空间）和处理方式（如遗忘机制）。
- 工具治理：动态路由工具选择、迭代式工具 refinement，甚至自主创建新工具。
⚠️ 关键 Insight ：脚手架改进是“快思考”，模型改进是“慢思考”。高效的 Agent 系统应该结合两者：用脚手架快速适应短期变化，用模型微调固化长期收益。
### 工程启示：如何落地？
- 优先优化脚手架：在资源有限的情况下，不要急着微调模型。先尝试使用 TextGrad 或 OPRO 等技术自动优化 Prompt。这些方法无需训练数据，只需任务反馈即可迭代，ROI 极高。
- 构建可进化的记忆系统：传统的 RAG 是静态的。论文建议引入“记忆处理”机制，如主动遗忘无关信息、动态重组知识结构（如图数据库）。这能让 Agent 在长周期任务中保持上下文的相关性。
- 工具链的动态化：不要硬编码工具调用逻辑。采用动态工具路由（Dynamic Tool Routing），让 Agent 根据当前状态自动选择或组合工具。甚至可以让 Agent 自主编写简单的脚本作为新工具，形成闭环。
### 局限与挑战尽管框架很完美，但论文也指出了当前的痛点：
- 评估困难：如何衡量“自我改进”的有效性？现有的基准测试（如 SWE-bench, WebArena）多针对静态性能，缺乏对进化过程的度量。
- 安全风险：自我进化的 Agent 可能产生不可控的行为漂移（Drift）。需要引入更强的约束机制和人类在环（Human-in-the-loop）的监督。
- 术语混乱：领域内存在大量重叠概念（如 self-correction, meta-prompting），增加了工程复现的难度。
### 总结这篇综述为 Agent 系统的设计提供了一个宏观的蓝图。 不要试图一次性构建完美的 Agent，而要构建一个能自我完善的系统。 对于工程师而言，理解“模型”与“脚手架”的分工，是迈向下一代智能系统的关键一步。从静态配置转向动态进化，不仅是技术的升级，更是开发范式的转变。
