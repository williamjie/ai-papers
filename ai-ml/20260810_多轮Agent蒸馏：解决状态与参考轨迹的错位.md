# ⭐⭐⭐½ 多轮 Agent 蒸馏：解决状态与参考轨迹的错位

**日期**: 2026-08-10

---

论文 : When Privileged Guidance Misaligns: State-Matched Routing and Contextualized Self-Distillation for Multi-Turn Agents链接 : https://arxiv.org/abs/2608.05219在多轮交互 Agent 的训练中，直接使用“成功轨迹”作为参考进行在线策略蒸馏（On-Policy Distillation, OPD）是提升性能的常见手段。但本文揭示了一个被长期忽视的致命缺陷：当学生 Agent 的执行路径偏离参考轨迹时，生硬地套用参考轨迹会导致严重的“状态-参考错位”，反而降低模型表现。
### 痛点：成功的参考不等于当前的指南现有的特权在线蒸馏方法（如 FullPath-SD）通常假设：只要参考轨迹在任务层面是成功的，它就可以在任何时刻指导学生的决策。
然而，在多轮交互中，Agent 的状态（位置、库存、页面等）是动态变化的。如果学生因为之前的操作不同，到达了参考轨迹未曾覆盖的状态，此时强行让教师模型基于参考轨迹进行打分，就会产生误导。
反直觉发现 ：即使参考轨迹在任务上是完全正确的，如果它与学生当前的执行状态不兼容，它会显著降低正确动作的概率。例如，参考轨迹从搜索结果页点击商品 A，而学生当前在商品 B 的详情页，此时“返回搜索”是正确操作，但参考轨迹会错误地抑制这一动作。
### 方法拆解：SMRC-SD 的核心直觉为了解决这个问题，作者提出了 状态匹配路由与上下文自蒸馏（State-Matched Routing and Contextualized Self-Distillation, SMRC-SD） 。其核心设计逻辑非常清晰：
-状态签名重构：
由于环境内部状态通常不可见，作者通过历史交互和可执行动作，手工构建了紧凑的“状态签名”。这不仅是简单的文本匹配，而是基于任务进度的结构化检查。
-状态匹配路由（State-Matched Routing）：
这是最关键的一步。在每一轮，系统会检查学生当前的状态签名是否与参考轨迹中的某个状态兼容。
如果匹配：说明参考轨迹在此处具有局部有效性，允许进行自蒸馏。
- 如果不匹配：切断参考信号的注入，仅保留基础的 GRPO 奖励信号。这避免了错误指导的干扰。
-上下文自蒸馏（Contextualized Self-Distillation）：
对于匹配的回合，教师模型看到的不是整个参考轨迹，而是由三部分组成的上下文：完整路径、当前状态摘要、以及基于匹配位置推导出的候选动作。这种设计将全局计划与局部执行解耦，确保指导信号是“落地”的。
### 关键结果：显著的性能提升实验在 ALFWorld（具身智能）和 WebShop（网页交互）两个基准上展开，使用 Qwen3-1.7B 模型。数据说话：

### 工程启示：如何用好“特权信息”
这篇论文对实际落地 Agent 微调有几个重要指导意义：
- 不要盲目信任参考轨迹：在强化学习或蒸馏过程中，参考数据（Reference）的价值是条件性的。必须验证其与学生当前状态的兼容性，否则“好数据”会变成“坏信号”。
- 稀疏监督优于噪声监督：SMRC-SD 仅在匹配状态应用蒸馏，这意味着大部分回合只使用 GRPO 奖励。这表明，高质量的稀疏监督比全量但可能包含噪声的监督更有效。
- 状态抽象的重要性：虽然论文使用了手工规则进行状态匹配，但这提示我们在工程实践中，需要建立一套机制来量化 Agent 的“执行进度”，以便更精准地检索和利用历史经验。
### 局限与展望SMRC-SD 目前依赖于环境特定的适配器来构建状态签名，这在通用性上有所限制。未来如何自动化地学习这种状态兼容性判断，或者将其扩展到更复杂的开放域交互场景，是值得探索的方向。但对于当前基于轨迹的 Agent 训练而言，SMRC-SD 提供了一个极具价值的基线改进思路。
