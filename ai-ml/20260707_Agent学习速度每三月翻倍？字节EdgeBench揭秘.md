论文 : EdgeBench: Unveiling Scaling Laws of Learning from Real-World Environments链接 : https://arxiv.org/abs/2607.05155我们习惯了预训练（Pretraining）的缩放定律，知道参数量和算力如何线性提升能力。但在部署后，Agent 在真实环境中通过试错“自学”的能力，一直是个黑盒。这篇来自字节跳动 Seed 实验室的工作，首次揭示了 Agent 环境学习的精确数学规律。
### 痛点：短视评测掩盖了真实学习力现有的 Agent 评测大多像“限时考试”，只给几分钟或几小时。这种设置测的是模型记住了多少知识，而不是它能否从反馈中进化。
现实世界的问题——比如修复一个包含十万行代码的生产系统，或者推导一个形式化数学定理——往往需要数天甚至数周的迭代。如果评测窗口太短，Agent 还没来得及通过错误调整策略就结束了。我们需要一个能容纳“长时间试错”的基准，才能看清 Agent 真正的学习曲线。
### 方法拆解：EdgeBench 的设计直觉EdgeBench 的核心创新在于构建了一个包含 134 个真实世界任务、且每个任务至少运行 12 小时的评测集。这不仅仅是时间长，更关键的是它模拟了真实工作的 双环反馈机制 ：
- 内环（Inner Loop）：Agent 可以在本地无限次运行测试、查看报错、调试代码。这是快速探索的空间。
- 外环（Outer Loop）：只有当 Agent 主动提交成果时，才会触发权威裁判（Judge）的评估，返回分数或详细反馈。
这种设计迫使 Agent 不能靠瞎猜得分，必须学会利用内环的快速反馈来优化策略，再通过外环验证成果。任务覆盖科学发现、软件工程、组合优化等六大领域，且人类专家平均需要 57.2 小时才能完成单个任务，确保了足够的难度上限。
### 关键结果：惊人的对数 Sigmoid 定律论文最震撼的发现是，Agent 在环境中的学习曲线并非杂乱无章，而是完美符合**对数 Sigmoid（Log-Sigmoid）**函数。

此外，论文还发现了一个惊人的行业趋势： Agent 的学习速度大约每三个月翻倍 。通过对比 2025 年 9 月以来的模型发布数据，前沿模型在固定 2 小时交互预算下的性能增益呈指数增长。
### 工程启示：给 Agent 开发者的建议- 不要过早放弃：由于学习曲线是 Sigmoid 型的，初期进步可能缓慢（tmidt_{mid}​ 之前）。如果你的 Agent 在前 1-2 小时表现平平，不代表它没戏，关键在于它能否利用后续时间突破瓶颈。
- 反馈质量决定上限：外环的权威反馈（Judge）是防止过拟合本地测试的关键。在设计 Agent 工作流时，务必引入独立的、基于隐藏用例的评估环节，而不仅仅是单元测试通过。
- 持续上下文优于重启：实验表明，连续的经验积累（Continuous experience）远胜于独立重启。保持长上下文窗口（如 Claude Code 的 1M 窗口）能让 Agent 更好地保留之前的调试教训。
### 局限与展望该定律依赖于任务图的“前沿扩展”假设，即解锁的新知识能带动相邻知识点。如果任务存在强瓶颈或结构非分形，该规律可能失效。此外，目前主要关注了文本和代码类任务，视觉 GUI 操作因难以分离感知与推理能力而被排除在外。
随着 Agent 逐渐接管复杂工作流，理解其“自学”的缩放定律，将比单纯堆砌参数更重要。EdgeBench 为我们提供了一把尺子，去衡量 Agent 在真实世界中成长的速率。
