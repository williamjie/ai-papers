论文 : LiveBrowseComp: Are Search Agents Searching, or Just Verifying What They Already Know?
链接 : https://arxiv.org/abs/2605.28721如果你正在开发基于 LLM 的搜索 Agent，这篇论文可能会让你后背发凉。它揭示了一个残酷的现实：我们在 BrowseComp 等静态基准上看到的“卓越表现”，很大程度上是模型在利用内部记忆进行“事后诸葛亮”式的验证，而非真正的证据驱动发现。当面对完全未知的领域时，现有的搜索 Agent 往往直接崩溃。
## 痛点：静态基准的“作弊”红利随着 LLM 参数量激增，其参数化知识（Parametric Knowledge）覆盖了越来越多的长尾事实。现有的搜索基准（如 BrowseComp、GAIA）是静态的，这意味着随着模型迭代，原本需要搜索才能解决的问题，逐渐变成了模型“背下来”的题目。
这就导致了一个评估偏差：我们混淆了**“模型已经知道什么” 与 “模型能搜到什么”**。如果 Agent 只是把网络当作确认内部假设的工具，那么一旦遇到超出其训练数据边界的新知识，它的搜索策略就会失效。
## 方法拆解：如何剥离“记忆作弊”？
论文作者提出了一个核心概念： 内在知识依赖（Intrinsic Knowledge Dependence, IKD） 。为了验证这一点并解决评估难题，他们设计了 LiveBrowseComp，这是一个专门用于压制 IKD 的动态基准。
其设计直觉非常硬核，主要通过三个维度构建“防火墙”：
- 时间窗口限制：所有问题必须依赖基准构建前 90天内 发布的事实。这直接绕过了当前主流模型的训练数据截止线。
- 长尾过滤（Long-tail Filtering）：排除全球性重大新闻（如奥运会、大选），只保留小众但可验证的事实（如特定 CVE 漏洞细节、冷门电影票房）。防止模型通过强化学习或微调吸收热点信息。
- 人类难度校准：确保问题对人类搜索者来说具有相当的挑战性，且答案唯一稳定。
## 关键结果：当记忆失效时，Agent 有多弱？
论文通过一系列诊断实验和 LiveBrowseComp 的实测，给出了令人震惊的数据对比。

## 工程启示：如何构建真正的搜索 Agent？
- 警惕“验证陷阱”：如果你的 Agent 在测试集上表现完美，先做个闭卷测试。如果闭卷分数超过 20%，你的评估可能已经失效。
- 强化证据驱动而非假设驱动：目前的 Agent 倾向于先生成假设再搜索验证。工程上应强制要求 Agent 在生成最终答案前，必须引用具体的检索片段，并抑制其在无证据支持时坚持原有假设的倾向。
- 动态评估常态化：对于生产环境的搜索 Agent，静态基准只能作为基线。必须引入类似 LiveBrowseComp 的近期数据测试，以监控模型在面对新知识时的真实检索能力，防止因模型更新导致的“记忆依赖”退化。
## 局限与展望LiveBrowseComp 目前仅包含 335 个问题，且主要依赖人工标注，扩展成本较高。此外，90天的时间窗口对于某些快速迭代的领域可能仍然不够短。未来，如何实现低成本的动态基准自动化生成，以及如何设计能真正从“假设驱动”转向“探索驱动”的 Agent 架构，是接下来的关键方向。
