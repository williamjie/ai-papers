# Agent 进化：不靠奖励信号也能自主探索

**日期**: 2026-04-21

---

论文 : Training LLM Agents for Spontaneous, Reward-Free Self-Evolution via World Knowledge Exploration链接 : https://arxiv.org/abs/2604.18131我们通常认为 Agent 的“自我进化”是靠 RLHF 或者强化学习反馈来的。但腾讯这篇论文直接掀了桌子： 真正的进化不需要外部奖励信号 。
它让 Agent 在没有任何任务指令、也没有外部奖惩的情况下，自发地去探索一个陌生环境，并总结出一份“世界知识（World Knowledge）”。这份知识不仅让模型在当下更好用，甚至还能跨模型传递——14B 的小模型装上这份知识，能干掉没有知识的 2B 级大模型。
### 痛点：现有的“进化”都是假的你看现在的 Agent 框架，要么是靠人类写好的提示词（Prompt），要么是靠预设好的奖励函数（Reward Function）。
- 经验驱动（Experience-Driven）：人类出题，Agent 答题，人类给分。这叫什么进化？这叫“做题家”。
- 对抗驱动（Adversarial Evolution）：一个 Agent 出题，另一个 Agent 解题。虽然不用人出题了，但还得人搭这套对抗的流水线。
这俩方案的共同死穴是： 只要断了人类的指令或奖励，Agent 就原地懵圈。 它们缺乏一种“原生智能”——就像人到了一个新城市，不需要老师教也能摸索出地铁怎么坐。
这篇论文提出的 Meta-Learning-Driven Evolution ，就是要打破这个枷锁。
### 核心拆解： outcome-based reward 机制既然推理（Inference）阶段不能给奖励，那怎么训练？
论文的设计非常精妙。它把 Agent 的生命周期拆成了两步：
- 原生进化阶段（Native Evolution）：Agent 进入一个陌生环境（比如一个复杂的网站），自发地去浏览、探索。
- 知识增强执行阶段（Knowledge-Enhanced Execution）：拿到一个具体任务后，利用刚才探索总结出的“世界知识”来完成任务。
那么问题来了： 怎么判断 Agent 探索得好不好？
如果给任务，Agent 就会为了完成任务而探索，这就失去了“自发”的意义。
于是论文提出了一个 Outcome-Based Reward 机制。简单来说：
你总结出来的知识（World Knowledge, KK ）到底好不好，不看你在探索阶段表现咋样，而是看你带着这份知识去解决 未来可能出现的任务 时，成功率提升了多少。
公式很简单：
Revolve(K)=Success(TE∣K)−Success(TE∣∅)R_{evolve}(K) = Success(T_E | K) - Success(T_E | \emptyset) ​ ( K ) = S u ccess ( T E ​ ∣ K ) − S u ccess ( T E ​ ∣∅ )
这就逼着 Agent 去思考：哪些信息是真正有价值的？哪些只是噪音？它不再是为了“探索”而探索，而是为了“提炼高价值信息”而探索。
### 训练套路：SFT + RFT 双管齐下光有奖励机制不够，还得有训练手段。论文用了两招：
-监督微调（Supervised Fine-Tuning, SFT）：
先用一个大佬（Gemini-2.5-Pro）当老师，去各个网站逛一圈，总结出高质量的“世界知识”。然后让 Qwen3-30B 模仿老师的探索轨迹。这一步是为了让模型学会“怎么逛”。
-强化拒绝采样（Rejection-based Fine-Tuning, RFT）：
模仿完了，还得自己练。让 Qwen3-30B 自己去探索，生成多个版本的“世界知识”，然后用上面的奖励公式打分。选得分最高的那个进行微调。
注意：这里没用传统的 PPO 或 GRPO，因为奖励计算太慢了（要跑辅助 Agent 验证），所以用了 RFT。
### 关键结果：14B 干翻未辅助的 Gemini实验结果非常硬核，咱们直接看数据：

### 工程启示-世界知识（World Knowledge）是个好东西：
它本质上是一个 Markdown 文件，记录环境的逻辑结构。你可以把它看作 Agent 的“本地地图”。对于复杂系统（如代码库、内部 Wiki），让 Agent 先花点时间“读地图”，能大幅减少无效交互步骤（实验显示效率提升 17%）。
-不要迷信 Prompt 工程：
直接 Prompt 基础模型去总结知识，效果往往很差（Prompt-only Base 只有 19.50%，甚至不如不总结）。必须经过 SFT + RFT 的训练，模型才能学会过滤噪音，提炼出真正有用的信息。
-小模型有大作为：
如果你资源有限，跑不起超大模型，不如先让大模型去探索环境，提取出高质量的“世界知识”，然后喂给小模型。这是一种极具性价比的性能提升手段。
### 局限与展望当然，这玩意儿也不是万能药。论文里有个**敏感性分析（图 5）**很有意思：
- 知识太短（4k tokens 以下），信息不够，模型瞎猜。
- 知识适中（8k-16k），效果最好。
- 知识太长（超过 32k），反而开始干扰模型，准确率下降。
这说明： 知识的密度比长度重要。 未来怎么让 Agent 自动压缩知识，去掉冗余，可能是下一个研究热点。
总的来说，这篇论文给 Agent 开发指了一条新路：别光盯着怎么优化奖励函数，多想想怎么让 Agent 学会“自主学习环境”。毕竟，在真实世界里，没人会一直给你打分。
