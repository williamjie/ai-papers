**日期**: 2026-08-11

---

论文 : DCAS: Decoupling CLI Agent Scaffolding to Internalize Planning across Scaffolds链接 : https://arxiv.org/abs/2608.06113现在的 CLI Agent 生态有个尴尬现象：模型在 OpenHands 上微调得飞起，换个框架（如 Claude Code 或 mini-swe-agent）就原地崩盘。
这篇论文不仅指出了病灶—— 规划结构（Planning Structure） ，还给出了一套工程化解法，让模型学会“通用规划”，从而在不同框架间自由迁移。
## 为什么你的 Agent 换个壳就不行了？
大多数开源 Agent 轨迹数据都来自 OpenHands。这导致模型在微调（SFT）时，不仅学会了写代码，还潜意识里记住了 OpenHands 特有的交互习惯。
作者通过对比实验发现， 未微调的基座模型在不同框架间表现差异很小，但微调后的模型差异巨大 。
这意味着：跨框架性能下降不是模型能力不足，而是 微调过程“安装”了特定框架的规划惯例 。
⚠️ 核心洞察 ：规划分为两种—— 显式规划 （执行前的独立计划步骤）和 隐式规划 （循环中的工具调用顺序、子任务分解节奏）。不同框架对这两者的定义截然不同，微调模型往往只适配了训练时的“混合口味”。
## DCAS：不修改代码的拦截层为了验证这个假设并收集数据，作者设计了 DCAS (Decoupling CLI Agent Scaffolding) 。
这是一个后端替换拦截层，它像代理一样路由 API 流量，允许任意 CLI 框架对接任意后端模型，且 无需修改框架源码 。
这使得我们可以：
- 在 Claude Code 框架下收集高质量轨迹，同时使用开源模型作为后端。
- 将同一模型部署到不同框架进行公平评估。
## 关键实验：规划到底值多少钱？
### RQ1: 显式规划的质量杠杆作者固定执行模型（Qwen3-Coder-30B），仅改变计划来源，测试对 SWE-bench Verified 的影响：
计划来源 Pass@1 (%) 提升幅度 无计划 (Baseline) 42.8% - 模型自规划 48.2% +5.4% Qwen3-480B 规划 49.2% +6.4% Claude Sonnet 4.5 规划 57.8% +15.0%结论 ：高质量的外部计划能带来高达 15% 的性能提升，这个增益远超跨框架掉分幅度。说明 规划是高性能 Agent 的核心瓶颈 。
### RQ2: 规划是可以被“内化”的作者利用 DCAS 收集了 576 条包含显式规划的高质量轨迹，并构建了两种微调数据集：
- PlanOnly: 仅包含规划阶段数据。
- Plan+Exec: 包含规划及后续执行全过程。
微调 Qwen3-Coder-30B 后的结果令人惊讶：
微调变体 无计划 Pass@1 自规划 Pass@1 解读 PlanOnly 53.8% (+11.0%) 53.2% 仅学回了 隐式规划 惯例，无需显式计划步骤也能提升。 Plan+Exec 52.8% (+10.0%) 55.8% (+13.0%) 同时掌握 显式与隐式规划 ，自规划效果最佳。
💡 反直觉发现 ：仅用规划数据微调（PlanOnly），模型在没有显式计划步骤的情况下，性能依然大幅提升。这证明模型学会了更优的“思维节奏”和工具调用策略，而不仅仅是学会写一个 Plan 文档。
### RQ3: 学到的能力能迁移吗？
这是最关键的工程验证。将仅在 Claude Code (v2.0) 上微调的 Plan+Exec 模型，部署到从未见过的环境：
- Claude Code v2.1 (新版本): Pass@1 达到 57.2%，甚至优于训练版本。
- OpenCode (开源框架): Pass@1 从基线的 46.0% 提升至 49.4%。
- mini-swe-agent (极简框架): Pass@1 从基线的 35.4% 提升至 42.4%。
结论 ：规划能力是一种 结构性技能 ，而非对特定框架的机械记忆。它具备极强的跨框架泛化能力。
## 给工程师的建议- 不要只收集执行轨迹：如果你的 Agent 微调数据缺乏高质量的“思考-计划”分离过程，模型只会学会模仿特定框架的调用格式，无法举一反三。
- 显式规划值得投入：即使你的框架不支持独立的 Plan 阶段，在训练数据中引入显式规划步骤（Plan+Exec），也能显著提升模型的隐式推理质量。
- 关注“隐式惯例”：工具调用的粒度、探索与执行的切换时机，这些隐式结构对性能的影响可能比代码生成本身更大。
这篇论文为构建 框架无关的通用 Agent 基座 提供了清晰的路径：通过解耦框架与模型，收集富含规划信号的数据，将“规划”从框架特性转化为模型能力。
