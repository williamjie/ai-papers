论文 : FORT-Searcher: Synthesizing Shortcut-Resistant Search Tasks for Training Deep Search Agents链接 : https://arxiv.org/abs/2606.12087做 Agent 训练的工程师都知道一个痛点：你花了大力气构造的多跳检索任务，模型往往“一眼看穿”，直接调用内部知识给出答案。
这种“假搜索”让训练数据失去了监督价值。这篇论文直击要害，提出了一套**防捷径（Shortcut-Resistant）**的数据合成框架 FORT，并仅凭纯监督微调（Supervised Fine-Tuning, SFT）就刷爆了同类开源榜单。
### 为什么现有的搜索数据“太水”？
传统做法认为，只要增加知识图谱的跳数或复杂度，任务就难了。但作者指出一个反直觉的事实： 结构复杂 ≠\neq = 搜索困难 。
如果题目中不小心泄露了一个关键实体名（Exposed Constants），或者某个单一线索就能唯一锁定答案（Single-clue Selectivity），模型就会走“捷径”，跳过真正的证据链推理。
⚠️ 核心洞察 ：任务的真实难度不由你设计的“预期路径”决定，而由模型能找到的**最便宜识别路径（Cheapest Identifying Route）**决定。
作者定义了四种具体的捷径风险：
- 证据共覆盖：一条搜索结果同时验证了多个线索。
- 单线索选择性：一个线索就足以缩小候选集到唯一答案。
- 暴露常量：题目直接给出了本应通过搜索发现的中间实体名。
- 先验知识绑定：模型在检索前就已从参数记忆中知道答案。
### FORT 框架：把“防作弊”写进合成流程FORT 不是简单的数据生成器，而是一个对抗式的合成流水线。它通过四个阶段严格控制上述风险：
- 长尾根实体选择：专门挑选没有英文维基百科页面的冷门实体。这直接打击了“先验知识绑定”，强迫模型必须去搜，因为它大概率没见过。
- 循环结构初始化：避免使用线性链式结构，而是预挖掘 Wikidata 中的环状子图。这让题目描述关系时更自然，且不容易直接暴露下游实体的名称。
- 多源证据分散：强制从不同来源（网页、数据库、学术库）收集事实，并构造“衍生事实”。目的是防止单条搜索结果覆盖所有线索，增加检索步数。
- 对抗式精炼：这是最精彩的一步。用强搜索 Agent 去试探生成的草稿题目。如果发现模型走捷径（如过早命中答案），就自动修复题目——比如模糊化具体数值、隐藏中间实体名。
### 实验结果：SFT 也能打爆 RL？
通常认为训练深度搜索 Agent 需要复杂的强化学习（RL）。但 FORT-Searcher 证明了： 只要数据够“硬”，纯 SFT 就够了。

### 工程启示与局限这篇论文对 Agent 开发者的最大价值在于 数据质量的重新定义 。
- 别只看长度，要看“命中时间”：评估搜索数据时，不要只看检索步数（Step Count），要看答案首次出现在证据中的时机。如果模型第一步就搜到了答案，后面的步骤都是噪音。
- 对抗式生成是必选项：静态规则无法穷尽所有捷径。引入一个强 Agent 作为“裁判”来自动修复题目，是提升数据难度的有效手段。
- SFT 的潜力被低估了：在高质量、防捷径的数据上，SFT 足以让模型学会复杂的规划策略，无需立即投入昂贵的 RL 训练。
当然，FORT 目前依赖 Wikidata 和外部 API 构建证据图，这在通用垂直领域（如医疗、法律）的落地成本较高。但它的“防捷径”思想完全可迁移。
