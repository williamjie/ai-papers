论文 : ClaimDiff-RL: Fine-Grained Caption Reinforcement Learning through Visual Claim Comparison链接 : https://arxiv.org/abs/2605.20278在多模态大模型（LMM）的强化学习（Reinforcement Learning, RL）中，我们常陷入一个尴尬境地：为了降低幻觉率，模型学会了“少说为妙”。一旦给出整体评分（Holistic Score），模型发现只要不说错，哪怕漏掉大量关键细节也能拿高分。这篇来自 CUHK 和 MiniMax 的论文 ClaimDiff-RL 直击痛点，提出了一种基于“视觉声明差异”的细粒度奖励机制，让模型在保持事实准确的同时，不再因为害怕犯错而变得保守寡言。
### 为什么整体评分会害了模型？
现有的图像描述（Captioning）RL 方法大多依赖整体标量奖励。无论是传统的 CIDEr/SPICE 指标，还是基于 LLM/Judge 的整体打分，都存在严重的 粒度问题 。
当 Judge 给一个长文本描述打出一个 7/10 分时，这个分数混合了太多信息：
- 模型是否编造了不存在的物体（幻觉）？
- 模型是否遗漏了显著特征（缺失事实）？
- 模型是否只是用更安全的简短句子规避了风险？
实验表明，整体奖励会导致 保守性欠描述（Conservative Under-captioning） 。模型通过减少输出长度来降低出错概率，从而在奖励上“作弊”。这就导致了幻觉率下降，但信息覆盖率也大幅暴跌的恶性循环。
### 核心 Insight：把“差异”变成奖励单元ClaimDiff-RL 的核心直觉非常巧妙： 不要直接评分，先找不同，再验证。
该方法不再让 Judge 直接给 Actor 生成的描述打分，而是引入一个参考描述（Reference Caption）作为对比锚点。流程如下：
- 发现差异：Judge 对比 Actor 描述和参考描述，找出具体的视觉声明差异（如：颜色是绿还是蓝？椅子是3把还是2把？）。
- 图像验证：针对每一个差异点，Judge 回到原图进行独立验证。注意，参考描述并非绝对真理，它只是提供对比维度。
- 类型化错误分配：为 Actor 和 Reference 分别分配带类型的错误（如 color_hallucination, count_mismatch）和严重程度。
- 奖励合成：基于这些细粒度的统计信息，合成最终的标量奖励。
这种设计将“幻觉”和“遗漏”解耦了。你可以清楚地看到模型是因为说错了扣分，还是因为没说对（但也没说错）而没加分。
### 两种奖励策略与实验结果论文设计了两种奖励组合方式，对应不同的优化目标：
- 相对奖励（Relative Reward）：对比 Actor 和 Reference 的错误数量。鼓励覆盖更多细节，适合提升信息密度。
- 仅 Actor 奖励（Actor-only Reward）：只惩罚 Actor 自身的错误。更保守，专注于减少幻觉。

### 工程启示- 奖励粒度决定行为边界：如果你发现模型在 RLHF 后变得“话少”、“保守”，检查你的 Reward Model 是否过于整体化。引入细粒度的错误分类（Type-specific Errors）是破局关键。
- 参考文本的正确用法：Reference Caption 不应被视为 Ground Truth，而应作为“差异探测器”。利用它来引导模型关注那些容易被忽略的视觉维度，但最终裁决权必须交给图像本身。
- 可诊断性优于黑盒评分：将奖励拆解为 color_hallucination、detail_omission 等具体类型，不仅有助于训练，更便于开发者定位模型的具体短板。
### 局限与展望目前该方法依赖于强大的多模态 Judge（如 Gemini-3-Pro）来进行差异发现和验证，计算成本较高。此外，对于完全新颖且参考文本中未提及的视觉元素，模型的发现能力仍受限于对比锚点。未来若能结合自监督的差异挖掘，或许能进一步摆脱对高质量 Reference 的依赖。
