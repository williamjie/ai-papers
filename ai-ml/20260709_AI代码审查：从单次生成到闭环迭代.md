# ⭐⭐½ AI代码审查：从单次生成到闭环迭代

**日期**: 2026-07-09

---

论文 : SWE-Review: Closing the Loop on Issue Resolution with Agentic Code Review链接 : https://arxiv.org/abs/2607.06065现在的 AI 编程 Agent 越来越强，能直接生成 Pull Request (PR)。但大多数系统还是“单次射击”模式：Agent 写完代码就结束，缺乏系统性的审查和修改机制。这就导致很多 PR 虽然语法正确，但逻辑漏洞百出，或者只修复了表面症状。
这篇论文提出了 SWE-Review ，核心思路是把代码审查变成一个主动的 Agent 任务，而不是简单的文本分类。它通过“生成-审查-修改”的闭环，显著提升了最终问题的解决率。这对工程落地意义重大：我们不再需要追求单次生成的完美，而是可以通过迭代审查来逼近正确解。
### 痛点：为什么现有方案不够用？
现有的自动化代码审查大多基于“单轮固定上下文”（Single-turn fixed-context）。模型只看 Diff 和少量检索到的文件，然后给出通过或拒绝的建议。
这种做法在简单场景下还行，但在复杂的仓库级 Bug 面前非常脆弱。
反直觉发现 ：一个看似正确的 Diff 可能掩盖了根本原因，或者修改了错误的位置。单轮审查往往只能看到“症状”，而看不到“病因”。
例如，某个 PR 增加了一个 NaN 检查来防止崩溃，但这只是治标不治本。单轮审查模型通常会批准这个修复，因为它看起来安全且针对性强。但真正的 Bug 可能在上游模块，导致函数返回了错误的值。
### 方法拆解：主动探索的 Agent 审查者SWE-Review 的核心 Insight 是： 代码审查需要证据，而证据往往不在 Diff 里。
它设计了一个主动审查 Agent（Reviewer Agent），工作流程如下：
- 环境探索：Agent 可以浏览文件、搜索代码、检查依赖关系。
- 动态决策：基于收集到的证据，决定 Accept 还是 Request Changes。
- 结构化诊断：如果拒绝，必须提供具体的缺陷描述、位置和建议修复方案，以便下游 Agent 进行修改。
这种设计的关键在于“适应性”。审查者不知道需要看哪里，所以它必须先理解 Issue，再追踪调用链，最后才评估 PR。这就像人类资深工程师做 Code Review 一样，先复现问题，再审视代码。
### 关键结果：数据说话作者在 SWE-Review-Bench（1,384 个 AI 生成的 PR）上进行了测试，对比了单轮审查和 Agent 审查的效果。
1. 决策准确率与修复率提升使用 Claude Opus 4.6 作为审查者，Agent 审查在两个指标上都优于单轮审查：
指标 单轮审查 (Diff+Context) Agent 审查 提升幅度 决策准确率 (DA) ~70-80% ~89% 显著更高 修改后解决率 (RRR) ~50-60% ~52-75% 尤其对低质量 PR 提升巨大⚠️ 注意 ：对于低质量的 PR（如 Qwen3-30B-A3B 生成的），Agent 审查将最终解决率从 44.1% 提升至 52.6% ，几乎翻倍。这说明当候选代码较差时，主动探索的价值最大。
2. 难度越高，优势越明显随着 Bug 难度增加（从 Easy 到 Hard），单轮审查的性能下降更快，而 Agent 审查能保持较高的准确率。这是因为复杂 Bug 需要非局部的仓库推理，固定上下文无法覆盖所有必要信息。
3. 审查轨迹可用于训练小模型作者构建了 SWE-Review-Traj 数据集（8,914 条轨迹），用于监督微调（SFT）小模型。
- Qwen3-8B 经过微调后，完成审查报告的比例从 4% 飙升至 71-84%。
- 决策准确率从随机水平提升到 67-72%。
这意味着我们不需要昂贵的闭源大模型来做日常审查，训练一个小模型即可胜任。
### 工程启示：如何落地？
- 构建闭环管道：不要指望 Agent 一次写出完美代码。引入“生成-审查-修改”循环，哪怕只迭代 2-3 次，也能显著提升最终质量。
- 审查即数据：收集高质量的审查轨迹（包括探索过程和诊断信息），这些数据不仅能训练审查模型，还能反哺代码生成模型。论文显示，混合训练审查数据能让代码生成模型的解决率提升 5.6%。
- 测试时扩展（Test-time Scaling）：利用审查 Agent 作为“门控”机制。如果审查通过则停止，否则返回修改。这种方法比传统的 Best-of-N 采样更高效，平均只需 2.44 次采样即可达到 38.4% 的解决率，而传统方法需要更多样本且无法利用诊断信息。
### 局限与展望目前 SWE-Review 主要关注功能性 Bug 修复，尚未涵盖代码风格、安全性、性能等非功能性指标。此外，审查 Agent 本身也可能出错，特别是面对极其复杂的架构变更时。
未来方向包括扩展审查维度，以及探索更高效的探索策略，以减少 Token 消耗和延迟。但对于当前的工程实践来说，引入主动审查 Agent 是一个性价比极高的升级路径。
