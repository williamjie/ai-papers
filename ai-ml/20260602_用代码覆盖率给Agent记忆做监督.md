# ⭐⭐⭐ 用代码覆盖率给 Agent 记忆做监督

**日期**: 2026-06-02

---

论文 : Joint Agent Memory and Exploration Learning via Novelty Signals链接 : https://arxiv.org/abs/2606.01528在开放环境里，Agent 的“探索”能力一直是个老大难。没有明确奖励，它要么原地打转，要么重复无效操作。这篇来自清华和百度的论文 JAMEL，给出了一个很聪明的解法：别硬凑记忆，用“代码覆盖率”这种确定性信号，把记忆模块和探索策略绑在一起训练。
### 痛点：长程交互的记忆陷阱做 GUI Agent 的都知道，长对话（Long Context）是性能杀手。保留完整的历史截图和文本，Token 消耗呈指数级增长；如果粗暴截断历史，Agent 就会失忆，导致重复点击已经试过的按钮。
现有的潜层记忆（Latent Memory）方案虽然能压缩历史，但面临一个死循环： 没有监督信号 。你很难告诉模型“这一步的记忆应该长什么样”，因为标准的数据集只给了最终结果，没给每一步的中间状态反馈。结果就是，记忆模块学得稀里糊涂，Agent 依然会在死胡同里打转。
### 核心洞察：探索本身就是最好的老师JAMEL 的核心直觉非常漂亮： 记忆和探索是互为因果的 。
- 记忆服务于探索：只有记住了“哪些路走过”，才能发现“新路”。
- 探索监督记忆：如果 Agent 走了一条新路（产生了 Novelty），说明它成功利用了历史记忆避开了旧路。这个“新颖性”信号，反过来证明了当前记忆状态的有效性。
关键设计 ：论文利用 GUI 领域的特性，使用**代码覆盖率（Code Coverage）**作为新颖性指标。只要触发了新的代码路径，就给予奖励。这是一个确定性的、持久的信号——一旦走过，永远不再算新。这比基于预测误差的好奇心驱动更稳定，且无需人工标注。
### 架构拆解：极简的潜层记忆JAMEL 的实现并不复杂，但很有效：
- 历史压缩器：使用冻结的 VLM（如 Qwen3-VL-2B）将每一步的 (观察, 动作) 对压缩成一个向量 Token。
- 记忆对齐：通过一个线性层，将这些记忆 Token 投影到策略模型（Policy Model）的嵌入空间。
- 软前缀注入：将压缩后的记忆作为 Soft Prefix 拼接到当前输入前，让策略模型基于“压缩后的历史”做决策。
训练时，利用拒绝微调（Rejection Fine-Tuning）收集数据。只保留那些最终能带来覆盖率提升的轨迹片段，强迫模型学习“如何利用记忆去发现未知”。
### 实验结果：小模型吊打大基线在 ScaleWoB 基准测试上，JAMEL 的表现令人印象深刻。它在 10 个未见过的 Web App 上进行了评估，每个 App 限制 50 步交互。

### 工程启示与局限这对我们做 Agent 落地有两个重要启发：
- 不要盲目堆砌 Context：对于需要长期交互的任务，潜层记忆（Latent Memory）是必选项。但关键在于如何训练它，JAMEL 证明了“过程奖励”比“结果奖励”更能塑造有效的记忆。
- 寻找领域内的“硬指标”：在 GUI 里是代码覆盖率，在其他领域呢？如果能找到类似确定性的新颖性信号（比如机器人里的新物体发现），就能复现这种无监督的监督微调。
当然，局限也很明显。论文提到，在像拼多多这样界面极其密集、弹窗频繁的场景下，JAMEL 仍会出现停滞。这是因为潜层记忆压缩丢失了部分细粒度信息，导致 Agent 无法区分视觉上相似但功能不同的元素。
总结 ：JAMEL 不是单纯的性能提升，它提供了一套“用探索信号训练记忆”的范式。对于想降低 Agent Token 成本、提升长程交互能力的工程师来说，值得深入研究其数据收集管线。
