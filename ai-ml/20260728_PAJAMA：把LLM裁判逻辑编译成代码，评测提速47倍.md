# ⭐⭐⭐½ PAJAMA：把 LLM 裁判逻辑编译成代码，评测提速 47 倍

**日期**: 2026-07-28

---

论文 : Codifying the Judge: Scalable Evaluation via Program Distillation链接 : https://arxiv.org/abs/2607.22561LLM-as-a-Judge（大模型作为裁判）已成为自动化评估的标准配置，但每次调用都伴随着高昂的 API 费用和不可控的延迟。威斯康星大学麦迪逊分校团队提出的 PAJAMA 系统，试图通过“程序蒸馏”彻底解决这一痛点：让 LLM 不再直接打分，而是生成执行评分逻辑的 Python 代码。
### 为什么需要“裁判代码化”？
现有的 LLM 裁判方案存在四个致命伤，严重阻碍了工程落地：
- 推理成本高：使用 GPT-5 等闭源模型进行百万级样本评估，API 账单令人咋舌；即使使用开源模型，GPU 资源消耗依然巨大。
- 逻辑黑盒：LLM 给出的理由往往不可靠，难以区分是真实推理还是幻觉。
- 系统性偏见：裁判容易受格式、长度或情感色彩影响，导致评估结果失真。
- 重复计算税：修改评分标准意味着必须重新运行整个数据集的推理，浪费算力。
PAJAMA 的核心洞察非常巧妙： 将 LLM 的判断逻辑“蒸馏”为可执行代码 。LLM 仅在合成阶段被调用一次以生成程序，后续所有样本均由本地运行的 Python 函数直接评分。这不仅消除了每样本 API 成本，还实现了评估过程的完全透明和可编辑。
### PAJAMA 方法拆解：从黑盒到白盒PAJAMA 并非简单让 LLM 写代码，它包含三个关键组件来解决程序生成的多样性、噪声和不确定性问题：
- 多样化程序合成：通过预设的 10 种评估准则（如逻辑连贯性、事实一致性）引导 LLM 生成不同的 Python 评分函数。系统会过滤掉逻辑重复的程序，确保裁判委员会具备多样性。
- 弱监督聚合与校准：单个程序往往存在盲区或噪声。PAJAMA 采用弱监督学习中的标签模型（Label Model），基于验证集上各程序的投票一致性，自动学习每个程序的权重并聚合最终裁决。同时引入“弃权机制”，当程序置信度低时选择弃权，提高整体可靠性。
- 置信度感知的混合路由：对于程序委员会无法达成共识或置信度低的样本，系统将其标记为“不确定”，并回退到 LLM 裁判进行二次评估。这种混合策略在保持高速度的同时，弥补了纯代码裁判的能力边界。
### 实验结果：速度与精度的帕累托前沿论文在五个偏好数据集和四个模型家族上进行了验证，数据极具说服力：
- 性能对标：纯程序裁判的平均准确率达到 78.11%，与 OLMo-2-13B-Instruct 持平，仅比最强的 GPT-5 Thinking（85.72%）低不到 8 个百分点。
- 速度碾压：程序执行速度比最小的 Gemma-3-270M-Instruct 快 2.12 倍，比 Qwen2.5-14B-Instruct 等较大模型快约 50 倍。
- 混合路由优势：结合 OLMo-2-7B-Instruct，PAJAMA 在吞吐量提升 2.9 倍的同时，准确率反而提升了 +5.0%。这证明了基于程序内部信号（如投票方差）的路由策略优于传统的长度启发式或随机路由。
⚠️ 反直觉发现 ：在 RewardBench 上，使用 PAJAMA 生成的标签训练奖励模型，其泛化性能甚至 优于 使用 GPT-4 标签训练的模型。而在成本方面，PAJAMA 仅需一次性合成 80 个程序（约 $7.21），相比 GPT-4 线性增长的成本降低了 50 倍 。
### 工程启示：可修复的偏见PAJAMA 最大的工程价值在于其 可解释性和可修复性 。传统 LLM 裁判若存在偏见，只能通过微调或 Prompt 调整来缓解，过程不透明。而 PAJAMA 生成的代码允许工程师直接审查逻辑。
论文展示了通过 Coding Agent（如 Claude Code）自动校准程序以消除偏见的效果：
- 位置偏见：程序逻辑天然对输入顺序不变，Flip Rate 降至 0%。
- 丰富内容偏见：通过代码移除对列表、标题的加分逻辑，Rich Content 类别的 Flip Rate 降低了 9.39%。
这意味着评估偏差不再是模型的固有属性，而是一个可以通过“打补丁”修复的代码 Bug。
### 局限与展望尽管 PAJAMA 展现了巨大潜力，但其有效性依赖于 LLM 能够准确地将评分逻辑转化为代码。对于极度依赖主观审美或复杂语义理解的场景，程序可能难以捕捉细微差别。此外，合成高质量、多样化的程序本身仍需要较强的 LLM 能力作为支撑。未来，如何自动化生成更复杂的评分特征，以及扩大可覆盖的评估领域，将是进一步优化的方向。
