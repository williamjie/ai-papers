# 数据质量碾压算力堆砌：OpenSeeker-v2 SFT 制胜之道

**日期**: 2026-05-06

---

论文 : OpenSeeker-v2: Pushing the Limits of Search Agents with Informative and High-Difficulty Trajectories链接 : https://arxiv.org/abs/2605.04036在 Agent 领域，业界默认“深搜能力”是巨头的专利，背后是 CPT（持续预训练）、SFT（监督微调）和 RL（强化学习）的重型流水线。上海交大团队提出的 OpenSeeker-v2 直接掀了桌子：仅靠 10.6k 条精心构造的数据，通过纯 SFT 就击败了阿里通义 DeepResearch 等依赖复杂管线的模型。这篇论文的核心洞察在于： 对于搜索 Agent，数据难度与丰富度远比训练范式复杂更重要。
## 为什么 SFT 还能打？
现有工业级搜索 Agent 的训练往往陷入“算力军备竞赛”。然而，OpenSeeker-v2 证明了一个简单假设：如果训练数据足够“难”且信息足够“密”，单纯的 SFT 足以诱导模型学会长程推理和深度搜索。其关键不在于模型架构的变动，而在于 数据合成管线（Data Synthesis Pipeline）的三个关键改造 。
## 方法拆解：三个“简单”但致命的改动OpenSeeker-v2 没有引入新的算法模块，而是对合成数据进行了外科手术式的优化：
-扩大知识图谱规模（Scaling Graph Size）
直觉：简单的单跳查询无法训练出真正的搜索能力。
- 设计：在生成任务时，显著扩展拓扑图的搜索半径（从 kk 增加到 KK）。这使得生成的问题必须依赖多跳（Multi-hop）聚合多个节点的证据才能回答，强制模型学习复杂的路径探索。
-扩展工具集（Expanding Tool Set）
直觉：工具种类单一会导致策略僵化。
- 设计：增加可用工具的数量，让 Agent 在 ReAct 轨迹中学习更多样化的交互模式。这不仅提升了泛化能力，还迫使模型学会在不同工具间灵活切换，而非依赖单一关键词匹配。
-严格过滤低步数轨迹（Strict Low-Step Filtering）
直觉：能一步解决的答案对 Agent 训练毫无价值，甚至有害。
- 设计：设定最小工具调用阈值 TminT_{min}​，丢弃所有步骤数低于该阈值的轨迹。这一操作确保了训练集的“难度底线”，迫使模型适应长视距（Long-horizon）的信息寻求行为。
## 关键结果：小数据的大胜利OpenSeeker-v2 基于 Qwen3-30B 模型，仅使用 SFT 训练，在四个主流基准上取得了 SOTA 表现。请注意，对比基线大多采用了 CPT+SFT+RL 的重型管线。

- 轨迹长度：OpenSeeker-v2 的平均工具调用步数高达 64.67 步，远高于 OpenSeeker-v1 的 46.97 步和 RedSearcher 的 36.01 步。这直接验证了“长轨迹”对深度搜索能力的必要性。
## 工程启示- 拒绝“低质数据”：在 Agent 训练中，大量的简单查询（如直接 lookup）不仅浪费算力，还可能限制模型的上限。引入严格的难度过滤是提升性能的杠杆点。
- 合成数据即核心壁垒：当基础模型能力相近时，高质量、高难度的合成数据是拉开差距的关键。学术团队无需巨额算力，也可通过精细的数据工程实现突破。
- SFT 并非过时：在 Agent 领域，SFT 依然是构建基础推理能力的强力手段，关键在于数据是否“喂得够硬”。
## 局限与展望尽管 OpenSeeker-v2 展示了 SFT 的潜力，但其依赖高质量的合成数据生成管线，这对数据工程能力提出了较高要求。此外，当前工作主要聚焦于 ReAct 范式，未来可能需要探索更复杂的上下文管理或 RL 阶段以进一步突破极限。但对于大多数团队而言，优化数据质量无疑是一个高性价比的切入点。
