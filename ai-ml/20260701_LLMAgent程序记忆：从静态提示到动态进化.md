论文 : Managing Procedural Memory in LLM Agents: Control, Adaptation, and Evaluation链接 : https://arxiv.org/abs/2606.23127Agent 落地最大的痛点是什么？不是模型不够聪明，而是它记不住“怎么做”。
每次遇到新任务，Agent 都像失忆症患者一样重新推理。这篇论文提出了 AFTER 基准测试和 Evolution 框架，核心观点很直接： 程序记忆（Procedural Memory）不能是静态的 Prompt 模板，而必须是一个能从执行轨迹中自我进化的动态层。
## 为什么现有的“技能库”不够用？
目前很多 Agent 框架依赖预定义的技能文件（如 Cursor Rules 或 Agent Skills）。这些通常是专家手工编写的静态文档。
问题在于： 静态技能无法适应分布偏移。
当任务场景、用户角色或底层模型发生变化时，原本有效的步骤可能失效。现有基准测试（如 GAIA, SWE-bench）主要评估任务完成率，却忽略了 技能的迁移性 。这篇论文指出，真正的挑战不在于存储更多经验，而在于提取出能跨越上下文依然有效的程序结构。
## 核心方法：AFTER 基准与 Evolution 框架作者构建了 AFTER 基准，包含 382 个真实企业任务，覆盖 6 种职业角色（数据工程师、科学家等）和 22 种程序技能。
其设计直觉非常工程化： 将“检索质量”与“技能质量”解耦。
在实验中，任务所需的技能集合是固定的，不再让 Agent 去猜该用哪个技能。这样能纯粹评估技能内容本身的有效性。同时，引入 Evolution 框架作为评估接口，标准化了轨迹收集、版本控制和更新执行流程。
关键 Insight ：程序记忆的进化不是简单的“错误重试”，而是一个 Collect-Diagnose-Revise-Promote 的闭环。通过反思器（Reflector）分析失败轨迹，生成新的技能版本，并验证其泛化能力。
## 实验结果：多样性是泛化的唯一解论文揭示了几个对工程实践极具指导意义的结论：
### 1. 静态技能的价值有限，但进化收益显著在无进化的静态设置下，加入手工编写（H）或 LLM 生成（G）的技能，平均仅提升 +2.8% 的通过率。
然而，经过 单轮进化精炼 后，性能提升了 +3.7% 到 +6.7% 。对于小模型（如 Gemma 4 E4B），收益甚至高达 +14.2%。这说明：基础技能提供骨架，进化过程填充血肉。
### 2. “窄经验”导致过拟合，“宽经验”带来泛化这是最反直觉的发现。作者对比了从单一模型轨迹（Narrow）和多模型混合轨迹（Diverse）中进化出的技能。
- 窄经验：在训练集上表现极好，但在测试集上往往下降（过拟合到特定模型的 quirks）。
- 宽经验：虽然单源表现平平，但跨模型迁移时，测试准确率高达 73.1%，比最佳单模型源高出 +13.7%。
⚠️ 反直觉发现 ：较弱的源模型提供的轨迹，往往比强模型更具泛化价值。因为强模型的“完美”执行可能掩盖了通用的程序逻辑，而弱模型的挣扎过程蕴含了更鲁棒的步骤约束。
### 3. 角色迁移的陷阱技能在角色间迁移时表现糟糕。例如，为项目经理（PM）优化的 PDF 提取技能，直接用于数据科学家（DS）会导致性能下降 -4.8% 到 -7.5% 。
原因在于：同一技能在不同角色的上下文中有不同的语义侧重（PM 关注摘要，DS 关注数据结构）。 程序记忆具有强烈的领域特异性。
### 4. 推理成本大幅降低进化后的技能通过前置知识，减少了运行时探索。在 Kafka 异常检测任务中，进化技能使 Claude 的 Token 消耗减少 326k (62%) 。这在高频调用的工业场景中意味着真金白银的成本节省。
## 工程启示：如何构建生产级 Agent？
- 不要迷信静态 Prompt：手工编写的最佳实践很快会过时。建立自动化的技能进化管道，利用失败轨迹持续优化 SKILL.md。
- 混合数据源训练记忆：在进化技能时，务必混合不同模型、不同角色的执行轨迹。避免使用单一强模型的完美轨迹，那会导致严重的上下文过拟合。
- 角色隔离技能库：不要试图用一套通用技能覆盖所有岗位。为 Data Engineer 和 Project Manager 维护独立的技能演化路径，或在迁移前进行显式的领域适配。
- 关注 Token 效率：将程序知识前置到 Prompt 中，不仅提升准确率，更是降低推理延迟和成本的有效手段。
## 局限与展望AFTER 基准目前主要聚焦科技行业角色，未涵盖医疗、法律等垂直领域。此外，实验固定了轨迹预算，真实场景中海量轨迹如何影响迁移质量仍是开放问题。
这篇论文为 Agent 从“玩具”走向“工具”提供了关键的路径： 让记忆像代码一样版本化、进化化和工程化。
