论文 : Sol-Attn: Accelerating Video Generation Inference via On-the-Fly Attention Sparsification链接 : https://arxiv.org/abs/2607.24027视频生成的算力瓶颈，核心就在注意力机制（Attention）。随着序列长度爆炸式增长，传统的密集计算不仅慢，还极其吃显存。NVIDIA 最新提出的 Sol-Attn，通过“在线稀疏化”这一巧妙设计，在不损失画质前提下，将视频生成速度提升了 2.1× ，结合引擎优化甚至可达 5× 。
### 现有方案的死胡同目前的训练免费（Training-free）动态稀疏注意力主要依赖两种路由策略： Top-k 和 Top-p 。
- Top-k：强制每个 Query 块选择固定数量的 Key-Value 块。这导致预算僵化，无法适应注意力分布的动态变化。
- Top-p：保留累积概率达到阈值 pp 的块。虽然动态，但在注意力分散时可能导致预算严重失衡。
更致命的是，这两种方法都需要先计算完整的代理分数（Proxy Score）矩阵，并显式地生成路由索引。在长序列场景下，这种“先算全、再筛选”的模式带来了巨大的 HBM 内存流量开销，甚至抵消了稀疏化带来的计算收益。此外，未被选中的块直接被丢弃（Keep-or-drop），在激进稀疏率下会导致明显的精度下降。
### Sol-Attn 的核心洞察Sol-Attn 的核心直觉非常优雅： 既然分数是流式计算的，为什么不能边算边筛？
作者发现，预训练视频模型中的注意力分数分布近似高斯分布。基于此，他们设计了三个关键步骤：
-查询依赖的阈值（Query-Dependent Thresholding）：
不再使用固定的 Top-k/p，而是根据当前 Query 块的代理分数均值 μ\mu 和标准差 σ\sigma，动态计算阈值 τ=μ+βσ\tau = \mu + \beta\sigmaμ+βσ。参数 β\beta 控制全局稀疏度，而每个 Query 根据自身分布自适应筛选。
-在线流式稀疏化（On-the-Fly Sparsification）：
这是工程上的神来之笔。在 Online Softmax 的外层循环中，Query 块逐 Tile 扫描 Key 序列产生代理分数。分数一旦生成，立即与阈值比较：
高于阈值：进入内层循环进行精确稀疏注意力计算。
- 低于阈值：不丢弃，而是留在寄存器中用于后续近似修正。
⚠️ 关键点 ：整个过程无需将完整的代理分数矩阵或路由索引写入 HBM，彻底消除了路由阶段的内存瓶颈。
-代理分数复用作为近似修正（Proxy-Score Reuse）：
对于被筛选掉的块，Sol-Attn 利用泰勒展开的一阶近似，复用已计算的代理分数来估算其对 Softmax 分子和分母的贡献。这使得“路由”、“稀疏计算”和“误差修正”融合在同一个内核中，实现了真正的零额外开销路由。

### 工程启示与局限对工程师的价值：
- 内存友好：对于显存受限的部署环境（如消费级 GPU），Sol-Attn 避免了路由索引的大规模 IO，是长视频生成的理想选择。
- 即插即用：作为训练免费方法，无需重新微调模型权重，可直接集成到现有 DiT 推理管线中。
- 内核融合潜力：其流式设计天然适合与现代 GPU 架构（如 Hopper/Blackwell）的 Tensor Core 流水线结合。
局限与展望：
目前 Sol-Attn 主要验证于视频生成模型。对于文本序列极长的 LLM 场景，注意力分布可能偏离高斯假设，阈值策略的有效性需进一步验证。此外，近似修正引入了额外的 GEMV 计算，在稀疏率较低时（<70%）收益不明显，甚至可能有微小开销。
Sol-Attn 证明了“路由即计算”的可行性，为未来稀疏注意力算子的设计提供了新的范式参考。
