论文 : From Controlled to the Wild: Evaluation of Pentesting Agents for the Real-World链接 : https://arxiv.org/abs/2605.10834现在的 AI 渗透测试 Agent 越来越像回事了，但评估它们的方式还停留在“夺旗游戏”（CTF）时代。这篇来自 Ethiack 和 Notre Dame 大学的论文直接指出了痛点： 现有的基准测试过于简化，无法反映真实世界的安全评估需求 。作者提出了一套从“任务完成”转向“验证漏洞发现”的评估协议，旨在让评估结果真正具备工程落地价值。
### 为什么现有评估方案失效了？
目前的 AI 渗透测试评估主要依赖三种模式：
- CTF 风格：目标是拿到 Flag，环境封闭且目标单一。
- 远程代码执行（RCE）：虽然更真实，但仍局限于单点突破。
- 轨迹相似度：判断 Agent 的操作路径是否与专家一致。
这些方法的共同缺陷是 忽略了开放性探索 。真实渗透测试不是解谜游戏，而是需要在噪声中识别线索、规划攻击链、并处理不确定性的过程。如果一个 Agent 能通过非常规路径发现漏洞，但没拿到预设的 Flag，传统评估就会给它零分。这导致我们选出的“最强 Agent”可能在实际业务中毫无用处。
### 核心 Insight：以“漏洞发现”为单位的评估论文提出的核心方法论是将评估单元从 任务（Task） 下沉到 发现（Finding） 。其设计直觉非常工程化：
-结构化 Ground Truth + LLM 语义匹配不再要求精确匹配字符串，而是构建包含名称、类别、描述的结构化 Ground Truth（JSONL 格式）。使用 LLM-as-a-judge 进行语义比对，允许“一对多”的候选匹配。这种宽松的设计是为了保留合理的对应关系，避免因为描述措辞不同而误杀有效发现。
-二分图最大匹配解决歧义这是论文最精彩的技术细节。由于 Agent 可能重复报告同一漏洞，或一个发现对应多个 Ground Truth 条目，直接计数会导致分数虚高。作者引入**匈牙利算法（Hungarian Algorithm）**求解最大二分匹配，确保每个 Ground Truth 只被计一次，且重复报告不会增加得分。这解决了评估中的“刷分”问题。
-动态维护的 Ground Truth真实目标中可能存在未知的漏洞。协议要求定期由专家审核未匹配的发现，如果确认是新漏洞，则更新 Ground Truth。这意味着 Ground Truth 不是静态答案库，而是一个随认知深化而演进的活资源。
### 关键实验结果：随机性既是噪音也是资产作者在三个开源目标（vuln-bank, paygoat, xben-090）上测试了 Strix、PentAGI 和 Claude Code，共涉及 108 个专家标注的漏洞 。
反直觉发现：
⚠️ 单次运行具有严重误导性。 没有任何配置在单次运行中覆盖所有已知漏洞。高随机性的 Agent 在单次评估中可能表现平平，但在多次运行后，其累积覆盖率远超其他模型。
累积评估的价值：
通过聚合 3 次独立运行的结果，作者观察到显著的行为差异：
- Strix-Sonnet：虽然单次精度一般，但通过随机性探索了不同路径。在累积 3 次运行后，Recall（召回率）几乎翻倍，最终获得了最高的累积 F0.5 分数。
- PentaAGI-Sonnet：在累积过程中 Precision（精确率）大幅下降，导致其累积 F0.5 分数反而低于单次平均分数。这表明该模型倾向于产生大量重复或错误的正样本，多次运行反而增加了噪声成本。
评估维度 传统 CTF 评估 本文提出的协议 成功定义 获取 Flag / RCE 发现并验证漏洞 目标复杂度 单点、封闭 多表面、开放式探索 随机性处理 通常忽略或视为噪声 通过累积评估转化为覆盖率优势 评分机制 二元（成功/失败） 基于二分匹配的 Precision/Recall/F1### 工程启示：如何落地这套协议？
对于正在构建或选型渗透测试 Agent 的团队，这篇论文提供了三个具体建议：
-不要迷信单次跑分由于 LLM 的随机性，单次运行的指标波动极大。作者建议使用 Welch’s t-test（不假设方差相等）结合 Cohen’s d（效应量）来进行统计显著性检验。在小样本下，P 值可能失效，效应量能告诉你差异是否具有实际意义。
-引入“累积覆盖率”指标在资源允许的情况下，评估 Agent 在 kk 次运行后的去重漏洞总数。这能衡量 Agent 的探索多样性。一个能在多次尝试中发现新路径的 Agent，比每次走相同路径但偶尔成功的 Agent 更具实战价值。
-效率是第一性原理除了发现漏洞的数量，必须追踪运行时（Runtime）和货币成本（Cost）。作者建议绘制“漏洞发现随时间变化”曲线，以识别边际收益递减点。如果在短时间内发现了大部分高危漏洞，后续的低效探索就是浪费预算。
### 局限与展望目前该协议主要关注漏洞发现的准确性和效率，尚未涵盖 安全性行为 （如 Agent 是否执行了破坏性操作）。此外，Ground Truth 的维护依赖专家审核，这在大规模自动化测试中仍是瓶颈。未来工作将集中在跨运行记忆（Cross-run Memory）和动态补丁环境下的评估。
总的来说，这是一篇极具工程指导意义的论文。它告诉我们：评估 AI 安全 Agent，不能只看它能不能“通关”，更要看它在混乱的真实环境中，能持续、高效地发现多少真正的威胁。
