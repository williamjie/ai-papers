论文 : When Classic Cache Policies Fail: Learning-Augmented Replacement for Semantic Retrieval Buffers链接 : https://arxiv.org/abs/2607.00394在构建长周期运行的 LLM Agent 时，我们习惯性地沿用数据库时代的缓存策略（如 LRU、LFU）来管理“长期记忆”。但这篇论文揭示了一个令人不安的事实： 在语义检索场景下，经典缓存策略不仅无效，甚至表现不如最朴素的 FIFO。 对于正在落地 Agent 系统的工程师来说，这是一个必须警惕的工程陷阱。
### 为什么经典策略会翻车？
传统缓存理论建立在三个假设之上：命中是二元的（要么有要么无）、通过精确 ID 匹配、效用由访问频率决定。然而，LLM Agent 的记忆管理完全颠覆了这些前提：
- 软命中（Soft Hits）：检索质量是连续的 [0,1][0, 1] 值，而非布尔值。即使没有完全匹配的项，语义相近的项也能提供部分价值。
- 非平稳效用：随着对话主题漂移，曾经高价值的记忆可能迅速贬值。LRU 依赖的“最近使用”信号在话题跳跃的对话中毫无预测力。
- 检索噪声限制容量：缓存瓶颈不再是物理内存，而是嵌入空间的拥挤导致的检索精度下降。
⚠️ 反直觉发现 ：在 MemoryBench-Full 数据集上，LRU 和 LFU 的表现持续低于 FIFO。特别是 LFU，在话题多样且非重复的场景中，频率累积反而成为了误导性的噪音。
### SOLAR：从后悔值到贝叶斯更新作者提出了 SOLAR 框架，其核心 Insight 是将缓存管理分解为两个耦合决策： 何时修改 与 修改什么 。
1. 基于后悔积累的准入控制（When to Modify）
经典策略总是接纳新项，导致切换成本浪费在噪音上。SOLAR 引入了动态阈值 τ\tau ：只有当累积的检索质量损失（后悔值）超过阈值时，才触发缓存更新。
- 设计直觉：这类似于库存理论中的经济订货批量。通过指数移动平均（EMA）自适应调整阈值，SOLAR 将修改率控制在约 17%，确保缓存中保留的是真正高价值的信息，而非频繁震荡的噪音。
2. 贝叶斯在线驱逐策略（What to Evict）
当需要驱逐时，面对效用不确定的项，SOLAR 使用 Beta 分布后验进行 Thompson Sampling：
- 正反馈：若项被检索到，α\alpha 增加。
- 时间衰减：若长期未被检索，β\beta 增加，模拟“遗忘”机制以应对非平稳性。
- 新颖性奖励：防止新加入的项在未充分观察前被误杀。
这种设计实现了探索与利用的平衡，且无需外部模型调用，仅依靠隐式反馈即可运行。

- 倒 U 型关系：在合成实验中，当池子大小超过 ~1000 项后，检索质量反而下降。这证实了容量约束本质上是检索噪声问题，而非存储限制。
### 工程启示与局限对实际落地的指导意义：
- 放弃 LRU/LFU：在语义记忆模块中，不要盲目使用传统缓存算法。FIFO 虽然是 baseline，但比 LRU 更可靠。
- 引入准入控制：并非所有新产生的经验都值得存入缓存。通过监控检索质量损失来动态决定写入时机，能大幅降低无效更新带来的计算开销（SOLAR 开销 <1ms/步）。
- 关注工作集大小：如果 Agent 的任务领域固定，适当增大缓存 KK 直至覆盖工作集是有效的；但如果话题极度发散，单纯增加 KK 会引入噪声，此时 SOLAR 的筛选机制更具价值。
局限与展望：
- SOLAR 依赖于隐式反馈（是否被检索），对于未被检索但极具价值的“潜在”项，可能存在误判。
- 当前实现假设嵌入空间是静态的，若结合动态微调或重排序模型，其阈值策略可能需要重新校准。
