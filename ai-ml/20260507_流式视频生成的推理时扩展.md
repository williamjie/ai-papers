# 流式视频生成的推理时扩展

**日期**: 2026-05-07

---

论文 : Stream-T1: Test-Time Scaling for Streaming Video Generation链接 : https://arxiv.org/abs/2605.04461在视频生成领域，我们一直面临一个两难选择：要么花巨资训练更大的模型，要么在推理时接受质量瓶颈。 Test-Time Scaling (TTS) 提供了一种新思路——通过在推理阶段增加计算预算来提升质量，而不需要重新训练。然而，现有的 TTS 方法在视频上往往因为搜索空间过大、计算成本高昂而难以落地。
中科大等机构提出的 Stream-T1 抓住了一个关键痛点： 流式视频生成（Streaming Video Generation） 天然的“分块生成”和“少步去噪”特性，其实是 TTS 的最佳载体。这篇论文不仅提出了一个框架，更展示了如何通过精细的噪声引导和记忆管理，让长视频生成既稳定又连贯。
## 为什么现有 TTS 在视频上“水土不服”？
目前的视频 TTS 方法（如 ImagerySearch 或 Video-T1）通常采用全局并行去噪或逐帧自回归的方式。这带来了两个致命问题：
- 计算成本爆炸：在全局高维空间中搜索最优解，每一轮候选生成都需要大量的去噪步骤，效率极低。
- 缺乏细粒度时间控制：一次性生成所有帧，导致局部时间上的瑕疵无法修正，必须整体丢弃，无法实现动态的时间修正。
Stream-T1 的核心洞察是： 流式生成（Chunk-level synthesis） 将视频切分成小块，每块仅需少量去噪步骤（如 4 步）。这形成了一个“浅层但宽分支”的搜索树，极大地降低了 TTS 的计算开销，同时保留了时间轴上的细粒度控制能力。
## 方法拆解：三个关键模块Stream-T1 基于 LongLive 框架，通过 Beam Search 扩展候选空间，并在三个环节进行主动干预：
### 1. Stream-Scaled Noise Propagation：噪声的“历史传承”
传统自回归生成中，当前块的初始噪声是随机采样的，这导致相邻块之间缺乏隐式的连贯性。Stream-T1 提出利用 历史高质量块的噪声轨迹 来初始化当前块的噪声。
具体做法是使用球面插值（Spherical Interpolation）：
xnT=βxn−1T+1−β2ϵx_n^T = \beta x_{n-1}^T + \sqrt{1 - \beta^2} \epsilon T ​ = β x n − 1 T ​ + 1 − β 2 ​ ϵ其中 β\beta 控制时间相关性。这种设计保证了噪声分布仍为标准高斯分布，但引入了“历史先验”，使当前块的生成起点更贴近之前的成功轨迹，从而平滑过渡。
### 2. Stream-Scaled Reward Pruning：长短结合的评价体系TTS 的核心在于“选优”。Stream-T1 设计了复合奖励函数，平衡局部美学和全局连贯性：
- 短期得分 (SshortS_{short}​)：使用图像奖励模型评估当前块内每一帧的空间质量。
- 长期得分 (SlongS_{long}​)：使用视频奖励模型在滑动窗口内评估时间连贯性和文本对齐。
最终得分采用动态加权策略：随着视频进度增加，短期权重的影响逐渐降低并达到阈值，防止模型陷入局部重复或停滞。
### 3. Stream-Scaled Memory Sinking：智能记忆管理长视频生成的最大挑战是 KV-cache 的溢出。传统的滑动窗口会丢失早期信息，而静态锚点（如 LongLive）无法适应场景变化。Stream-T1 引入了 语义边界检测 ，动态决定被挤出窗口的记忆如何处理：
- Discard（丢弃）：如果当前块质量差（低于平均短分阈值），直接丢弃，防止错误累积。
- EMA-Sink（指数移动平均）：如果当前块质量好且无场景切换，将其与最新 Sink 进行 EMA 融合，压缩冗余信息，保持短期连贯。
- Append-Sink（追加）：如果检测到场景切换（长分显著下降），将当前块作为新的离散锚点追加到全局 Sink 中，确保长期语义不丢失。

## 工程启示- TTS 不等于暴力搜索：对于视频生成，盲目增加候选数量并不划算。Stream-T1 证明了**“主动引导”**（如噪声传播）比“被动筛选”更有效。
- 记忆管理需要语义感知：简单的滑动窗口或固定锚点无法应对长视频的复杂场景。根据奖励信号动态调整记忆策略（Discard/EMA/Append）是延长视频有效长度的关键。
- 流式架构的潜力：如果你正在部署长视频生成服务，考虑采用流式分块策略，并结合推理时缩放，可能比单纯扩大模型参数更具性价比。
## 局限与展望尽管 Stream-T1 表现优异，但它依赖于高质量的奖励模型（Reward Models）进行评分，这些模型本身可能存在偏差。此外，Beam Search 带来的计算开销虽然比全局搜索低，但在极端长视频下仍可能成为瓶颈。未来方向可能包括更高效的奖励模型蒸馏，或更精细的计算预算自适应分配。
