# 长记忆评测：让Agent成为资深同事

**日期**: 2026-05-13

---

论文 : LongMemEval-V2: Evaluating Long-Term Agent Memory Toward Experienced Colleagues链接 : https://arxiv.org/abs/2605.12493在构建企业级 Agent 时，我们常面临一个尴尬局面：模型参数里塞满了通用知识，却记不住昨天在内部系统里踩过的坑。现有的长上下文评测大多关注“文档检索”或“用户历史对话”，但这离真正的“Agent 长期记忆”还有距离。UCLA 团队发布的 LongMemEval-V2 (LME-V2) 提出了一个更务实的视角：记忆系统的终极目标，是让 Agent 从新手变成能独当一面的“资深同事”。
### 痛点：现有评测太“轻”了为什么需要 LME-V2？因为现有的基准测试（Benchmarks）要么太短，要么太简单。比如 MemoryArena 或 AgentLongBench，它们要么只涉及单个轨迹的短期记忆，要么是在简化的游戏环境中测试。但在真实的 Web 自动化场景中，Agent 需要处理的是复杂的界面交互、状态流转和隐性规则。
LME-V2 的核心洞察在于： 记忆不仅是“记住”，更是“内化环境经验” 。它不再问“用户说了什么”，而是问“在这个特定系统中，下一步该怎么做？”。评测集包含 451 个手工标注的问题，覆盖五个核心能力：
- 静态状态回忆（Static State Recall）：记得界面布局、按钮位置。
- 动态状态追踪（Dynamic State Tracking）：理解操作后系统状态如何变化。
- 工作流知识（Workflow Knowledge）：知道完成常见任务的标准步骤。
- 环境陷阱（Environment Gotchas）：知道哪里容易出错，哪些是系统特有的 Bug 或逻辑。
- 前提意识（Premise Awareness）：识别哪些在其他系统通用的假设，在当前系统中是错的。
数据规模上，LME-V2 达到了前所未有的深度：Small 版包含 100 个轨迹（25M tokens），Medium 版每个问题对应约 500 个轨迹（115M tokens）。这意味着模型必须在海量噪声中，精准定位到决定成败的那几条关键轨迹。
### 方法拆解：两种记忆架构的博弈为了在 LME-V2 上取得好成绩，作者设计了 AgentRunbook，分为两个版本，代表了两种不同的工程思路：
1. AgentRunbook-R (RAG 派)
这是传统的检索增强生成思路的升级版。它不只是简单地把轨迹切片存入向量库，而是引入了 三层知识池 ：
- 原始状态切片池：保留 UI 观察和局部动作，用于回答静态细节。
- 状态转换事件池：提取连续状态间的变化，构建环境的“世界模型”。
- 策略笔记池：将轨迹经验提炼为可复用的工作流和避坑指南。
查询时，LLM 控制器会根据问题类型，动态向不同池子发起检索。这种设计的直觉是：不同粒度信息应该被结构化存储，以提高检索精度。
2. AgentRunbook-C (编码 Agent 派)
这是本文最大的亮点。作者观察到，通用的 Coding Agent（如 Codex）在文件操作和工具使用上极强。于是，AgentRunbook-C 将记忆管理转化为文件管理问题 。
- 写入：轨迹直接存为文件。
- 读取：不依赖向量检索，而是给 Coding Agent 一个沙盒，里面包含工作流文档、内存 Manifest（索引摘要）和辅助脚本。
- 核心 Insight：让 Coding Agent 像程序员读代码一样，通过多步工具调用（搜索、查看、分析）来组装证据。这避免了向量检索在复杂逻辑推理上的不足。
### 关键结果：精度与速度的权衡实验结果非常有趣，揭示了不同架构的优劣。读者模型固定为 Qwen3.5-9B，上下文截断至 200K tokens。

- AgentRunbook-C 的平衡：通过添加工作流指导和 Manifest 索引，AgentRunbook-C 将准确率推高至 74.9%，同时将延迟从原生 Codex 的 177s 降低到 108s。它成功优化了精度-延迟的帕累托前沿。
### 工程启示- 向量检索不够用：在处理 Agent 轨迹时，单纯的语义相似度检索（Dense Retrieval）很难捕捉状态流转和隐性逻辑。如果需要高精度，必须结合结构化信息或推理型 Agent。
- Coding Agent 作为记忆控制器：利用 Coding Agent 的工具调用能力进行证据搜集，是一种极具潜力的架构。关键在于如何设计“引导机制”（如 Manifest 和 Helper Scripts），防止 Agent 在海量文件中盲目探索。
- 记忆需要“提炼”：Raw Data 直接存进去效果并不好（见消融实验，去掉 Note Pool 性能下降）。将轨迹提炼为“事件”和“策略笔记”是提升泛化能力的关键。
### 局限与展望尽管 AgentRunbook-C 表现优异，但 100s+ 的查询延迟对于实时交互场景仍然偏高。此外，LME-V2 的问题虽然难以被大模型直接回答，但未来随着模型对特定领域数据的预训练，区分“参数记忆”和“检索记忆”的界限可能会模糊。
总的来说，LME-V2 为 Agent 记忆研究树立了一个新标杆：不要只测“能不能找到”，要测“能不能像专家一样思考”。对于正在构建企业级 Agent 的工程师来说，AgentRunbook-C 的设计思路值得深入借鉴。
