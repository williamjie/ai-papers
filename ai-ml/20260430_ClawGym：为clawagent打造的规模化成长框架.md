# ClawGym：为 claw agent 打造的规模化成长框架

**日期**: 2026-04-30

---

论文 : ClawGym: A Scalable Framework for Building Effective Claw Agents链接 : https://arxiv.org/abs/2604.26904## 为什么值得关注Claw agent（夹爪智能体）与前些天讨论的Computer Agent不是一回事。它不是在GUI界面上点点划划的”虚拟用户”，而是真刀真枪地在你的本地文件系统、工具链和持久化工作区里干活的工程师。这类 agent 要处理的不是一轮对话，而是跨会话、跨状态的多步骤工作流——整理文档、批量处理数据、配置环境、生成报告，都是实打实的”脏活累活”。
但问题来了： 没有大规模、高质量、可验证的任务数据，再强的基座模型也训练不出靠谱的 claw agent 。现有的数据集要么是静态推理题，要么是结构化的软件工程任务（SWE-Bench），都无法还原真实工作区中模糊的指令、意外的文件状态、工具执行失败、长时程依赖这些 claw 场景的典型痛点。
ClawGym 的核心价值，就是补上了这块基础设施： 用一套系统化的方法论，把 13.5K 个可执行、可验证的 claw 任务”生”出来，然后把 agent 训练和评测的 pipeline 全部串起来 。这不是一个模型，而是一个让 claw agent 能规模化成长的”育婴室”。
## 问题根源：claw agent 的数据困境作者开篇就点出关键区别：
- 静态推理任务（如 AIME）：纯符号推理，给定即求解- 结构化 agent 任务（如 SWE-Bench）：有明确的代码库、测试用例、观测循环- Claw-style 任务：在本地工作区里”摸黑”操作——文件状态不透明、工具接口不友好、错误恢复靠自己这样的环境特性决定了：
- 数据难以规模化采集：真实用户数据涉及隐私，且任务边界模糊- 自动验证困难：成果是修改后的文件、生成的报告、配置变更，不是简单的对/错- 工作区状态复杂：需要逼真的 mock 文件和上下文才能让任务有意义所以缺的不是想法，而是 能批量生产、质量可控、与真实环境对齐的任务库 。ClawGym 就是要解决这个”有没有”的问题。
## 核心洞察：双通路任务合成ClawGym 的数据合成 pipeline 最大亮点是 “自上而下” + “自下而上” 双通路设计 。
### 通路1：Persona-Driven 自上而下用”用户画像 + 场景分类 + 原子操作”构成任务种子，再由 LLM 扩展成完整任务。
设计直觉 ：
- 从用户角色（学生、数据科学家、项目经理…）出发，保证任务场景的真实性和多样性- 9大类43子类的场景分类，覆盖常见工作流（数据处理、文档编辑、Web检索…）
- 7大类26种原子操作约束，确保生成的任务是 claw 环境里真能执行的为什么有效 ：
这种方式确保了任务的”用户视角”合理性——不是工程师臆想的”用 agent 写个爬虫”，而是”帮我整理上周会议的所有 CSV 并生成销售报告”这类真实需求。论文图2显示，场景分布相对均衡，没有明显的头部聚集。
### 通路2：Skill-Grounded 自下而上OpenClaw 生态中已有大量 skill（可复用的能力单元）。这里的关键是： 把 skill 当作积木，而不是完整任务 。
流程 ：
- 从 ClawHub 收集约 30K 个 raw skill- 用 MiniMax-M2.5 结构化标注，过滤掉依赖密钥、信息不足的 skill，保留 16K 个可合成 skill- 每个任务 = 1个主 skill + 最多3个辅助 skill，由 GPT-5 组合成完整用户指令设计直觉 ：
skill 本身是”怎么做”（how），加上场景和 persona 才构成”做什么”（what）。这种组合自然引入任务多样性，同时保证每一步操作都是 claw 环境里验证过的能力， 避免了生成无法执行的”空中楼阁”任务 。
两个通路互补：一个保场景真实性，一个保操作可执行性。最终产出 13.5K 个过滤后的训练任务。
## 资源与验证：让任务能跑起来、能判对错光有指令不够，还要 workspace 初始状态和验证机制。
### 资源生成（Stage 2）
针对每个任务，LLM 生成对应的 mock 文件：CSV、Markdown、配置文件等。关键是 任务自包含 ——所有输入文件由框架生成，不依赖外部数据，保证可复现性。
### 混合验证协议（Stage 3）
这是 claw 任务验证的核心难点。论文采用 code-based + rubric-based 双轨验证 ：
验证类型 覆盖范围 实现方式 Code-based 客观条件：文件存在、字段正确、数值匹配、数据一致性 生成可执行 Python 检查器，返回 [0,1] 分数 Rubric-based 主观质量：语气、清晰度、完整性、忠实度 LLM 生成评分规则，按 0/0.25/0.5/0.75/1.0 五档打分权重设置 ：λ = 0.7 给 code-checker，0.3 给 rubric。理由很实在：claw 任务的最终成果是 可观测的 workspace 改变 ，客观证据比主观判断更可靠。
### 质量过滤（Stage 4）
- Novelty：用 embedding 余弦相似度去重，避免模式雷同- Plausibility：GPT-5.4 judge 检查任务是否清晰、合理、不依赖虚构工具- Difficulty：LLM judge 评估复杂度，保持任务难度分布均衡- Verification sanity：
在初始 workspace（无 agent 输出）运行 checker，防止”还没做事就给分”的松散检查- LLM 审查 checker 是否覆盖核心要求、是否过严这套质量控制让最终数据集的信噪比得到保障。
## 训练与评测：从数据到 agent### ClawGym-Agents：两条训练路径-监督微调（SFT）：
用 GPT-5 在合成任务上做 black-box rollout，收集高保真交互轨迹- 过滤轨迹后，对小模型（如 Qwen 系列）做监督微调- 关键设计：用更强模型产生的轨迹作为”教师信号”，弥补小模型自身探索能力不足-强化学习（RL）探索：
实现轻量级 pipeline，每个任务独立沙盒并行 rollout- 解决 claw 任务长时程、高成本的样本效率问题- 但论文未深入展开 RL 实验结果，仅提到”consistent gains”，应该是探索性工作### ClawGym-Bench：校准过的评测基准从合成池中抽取 200 个实例，经过：
- 自动难度校准：rollout 预估各任务基线完成率，选难度适中的- 人工 + LLM 联合审查：确保任务清晰、无歧义、验证可靠为什么需要自建基准 ？PinchBench 是现有公开 benchmark，但 claw 场景的特殊性要求更贴近真实工作区的评测。ClawGym-Bench 覆盖 6 大类任务，与训练数据互补，避免数据泄漏。
## 关键结果：提升有多大？
论文在两个 benchmark 上对比了训练前后的效果：
模型 PinchBench 提升 ClawGym-Bench 提升 Qwen3-8B +38.90% +43.46% Qwen3-30B-A3B +54.68% +25.96%观察 ：
- 小模型收益显著：8B 模型在两个基准上都有 40%+ 提升，说明合成数据有效弥补了能力短板- 大模型收益分化：30B 模型在 PinchBench 上提升更大（54.68%），但在自建 benchmark 上收窄到 26%，可能说明：
PinchBench 与训练数据分布更接近，存在一定过拟合风险- ClawGym-Bench 难度更高或更贴近真实 claw 场景的复杂性绝对值 ：论文未给出 baseline 绝对分数，无法判断 50%+ 提升是从 20% 到 70% 还是 70% 到 105%（溢出）。但相对提升在小模型上依然可观。
## 工程启示：这对实际应用意味着什么-数据合成是 agent 能力的关键瓶颈与其无脑堆模型参数，不如先解决”高质量任务数据从哪来”的问题。ClawGym 的双通路设计（persona + skill composition）提供了一个可复用的方法论。
-验证协议决定评测可信度claw 任务不能只看最终答案字符串。混合验证中，code-checker 必须在初始状态运行时不应通过——这是一个实用技巧，能筛掉大量松散检查器。
-小模型 + 高质量数据 = 实用 agent8B 模型经此训练就能在 claw 任务上达到可用水平，对本地部署、端侧 agent 是大利好。不必迷信”越大越好”，领域数据比通用能力更重要。
-任务多样性需系统化控制单纯随机生成任务会导致模式坍塌。论文用 persona taxonomy 和 skill 组合作为”锚点”，在开放生成和可控分布间取得平衡——这对任何 agent 数据工程项目都有参考价值。
## 局限与未竟之事论文在讨论部分也坦诚了几个局限：
- 任务 novelty 可能仍有不足：即使经过去重，15K 任务相对于 claw 场景的无限可能性仍只是沧海一粟。
- 验证协议仍有盲区：rubric-based 验证依赖 LLM judge，本身存在主观性和漂移风险；更细粒度的轨迹级评估（安全性、效率、错误恢复）尚未覆盖。
- 泛化到真实用户环境存疑：mock 文件虽保证可复现，但与真实用户数据（混乱命名、意外编码、复杂关联）仍有 gap。
- RL 探索不充分：论文仅轻描淡写提到 RL pipeline，未展示详细结果，可能因为样本成本过高或收敛不稳定。
## 个人判断ClawGym 不是”突破性算法”，而是一套 扎实的基础设施工程 。它没有提出惊世骇俗的新模型，却解决了 claw agent 领域最实际的痛点： 没数据、没评测、难验证 。
优点 ：
- 双通路合成设计聪明，兼顾场景真实性与操作可执行性- 混合验证协议贴合 claw 任务的 workspace-grounded 特性- 量产 13.5K 任务 + 200 基准，为社区提供宝贵资源- 实验设计充分，消融对比到位（虽然细节未在摘录中完全展示）
不足 ：
- RL 部分浅尝辄止，未发挥 reinforcement 在长时程任务中的优势- 对任务难度与模型能力的关系分析可更深入（为何 30B 模型在自建基准上提升收窄？）
- 未公开代码/数据， reproducibility 依赖后续 release一句话总结 ：如果你在做 claw-style、workspace-grounded 或 file-system tool-use 方向的 agent，这篇论文的 数据合成方法论 + 验证设计思路 值得细读。它不告诉你”怎么调参”，而是告诉你”怎么造出一个能持续成长的数据工厂”。
