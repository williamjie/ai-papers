论文 : SG-OPD: Sign-Gated On-Policy Distillation via Sign-Consistency Gating and Phased Teacher Sampling链接 : https://arxiv.org/abs/2606.09304On-policy distillation (OPD) 让模型在自我生成的轨迹上学习，效果虽好但极难调参。这篇论文指出其核心痛点在于“学生”和“老师”的分布错位，并给出了一套工程上极其稳健的解决方案：用验证器信号做门控，解决冷启动崩溃和梯度冲突。
### 为什么 OPD 经常翻车？
OPD 的优势在于消除推理时的暴露偏差（Exposure Bias），但它隐含了两个极易破裂的假设：
- 轨迹级对齐脆弱：在强到弱（Strong-to-Weak）蒸馏中，学生初期的采样质量极差。此时老师给出的反向 KL 散度信号充满噪声，强行蒸馏只会让学生偏离正确方向。
- Token 级可靠性不均：即使整条轨迹被验证器判定为正确，老师在某些 Token 上的偏好可能与最终正确答案背道而驰。盲目放大这些梯度会破坏原本正确的推理路径。
### SG-OPD 的核心设计直觉论文提出的 Sign-Gated On-Policy Distillation (SG-OPD) 核心在于引入一个二元验证器（Binary Verifier）作为“信任信号”，在两个粒度上干预训练：
1. 样本级：分阶段教师采样 (Phased Teacher Sampling, PTS)
- 设计逻辑：解决冷启动问题。训练初期，混合一部分经验证器确认正确的老师轨迹作为辅助损失（Anchor）。
- 动态退火：随着训练进行，通过余弦调度逐渐降低该权重，直至完全回归 On-policy 学生采样。这避免了后期过度依赖老师导致的分布偏移。
2. Token 级：符号一致性门控 (Sign-Consistency Gate)
- 核心 Insight：对比 GRPO 优势（a1a_1​，基于验证结果）和 OPD 反向 KL 优势（a2a_2​，基于老师偏好）。
- 路由机制：
共识 Token (a1⋅a2>0a_1 \cdot a_2 > 0​⋅a2​>0)：老师和验证器方向一致 →\rightarrow 外推 (Extrapolation)，放大梯度，加速学习。
- 冲突 Token (a1⋅a2≤0a_1 \cdot a_2 \le 0​⋅a2​≤0)：老师偏好与正确答案方向相反 →\rightarrow 内插/软化 (Interpolation)，降低权重，防止破坏正确路径。
⚠️ 反直觉发现 ：在统一外推（Uniform Extrapolation）中， λ=1.8\lambda=1.8 1.8 会导致训练彻底崩溃（AVG 降至 24.71%）。但引入符号一致性门控后，同样的 λhigh=1.8\lambda_{high}=1.8 ​ = 1.8 却达到了最佳性能（28.78%），因为它精准过滤了有害梯度。

### 工程启示- 验证器不仅是奖励源：在 RLHF 或蒸馏中，不要只把验证器当作最终的标量奖励。将其转化为 Token 级的信任信号，可以大幅降低策略更新的方差。
- 混合策略优于纯 On-policy：完全依赖学生早期采样是危险的。引入少量高置信度的 Off-policy 数据作为“锚点”，并在后期退火，是解决冷启动的标准范式。
- 梯度路由的价值：当模型能力不足时，老师的指导往往是矛盾的。通过简单的符号判断来路由梯度（放大共识、抑制冲突），比复杂的超参数调优更有效。
### 局限与展望目前该方法主要验证于数学推理（二元奖励）。对于代码生成等具有中间步骤验证的任务，若能将轨迹级信号细化为步骤级证书，效果可能更佳。此外，不同模型规模下的超参数迁移性仍需进一步探索。
