## 为什么显存总是不够用？
3DGS 的核心瓶颈在于“参数表膨胀”。每个高斯原子携带 59 个浮点参数（位置、协方差、球谐函数等），加上训练时的梯度和 Adam 优化器状态，显存占用呈线性爆炸。
目前的单卡方案已经触及天花板：
- 原生 3DGS：受限于全量状态驻留显存，极限约 11.5M 个原子。
- 朴素卸载 (Naive Offload)：将优化器状态移至 CPU，但每轮仍需将全量参数搬入 GPU，极限约 50M。
- CLM (SOTA 基线)：卸载高维外观属性，保留几何参数，极限约 105M。再往上，光栅化辅助缓冲区就会直接 OOM。
对于城市级大场景，百万级精度远远不够，但多机分布式训练成本高昂。TideGS 的核心洞察在于： 3DGS 训练本质上是稀疏且轨迹相关的 。每一帧渲染只激活视野内的一小部分原子，且相邻帧的激活集合高度重叠。因此，GPU 显存不应作为“永久存储”，而应视为“工作集缓存”。
## TideGS 的设计直觉：SSD-CPU-GPU 三级缓存TideGS 构建了一个离核（Out-of-Core）训练框架，通过 SSD、CPU 内存和 GPU 显存的协同，解决了带宽和延迟问题。其核心由三大支柱组成：
### 1. 空间局部性：Block 虚拟化离核存储无法高效读取单个原子。TideGS 将高斯原子按 Morton 码（Z-order curve）排序，打包成固定大小（4096 原子/块）的 Block。
- 为什么这么做？ Morton 排序保证了空间邻近的原子在存储上也邻近。这使得基于包围球（Bounding Sphere）的 CPU 侧粗略剔除（Frustum Culling）极其高效，大幅减少无效 I/O。
- 对齐优化：每个 Block 大小约为 944 KiB，恰好对齐 SSD 的页面粒度，提升吞吐。
### 2. 异步流水线：掩盖延迟传统的离核循环会在 SSD 读取时阻塞 GPU。TideGS 设计了四级重叠流水线：
- SSD 预取至 CPU 缓存。
- CPU 到 GPU 的 H2D 传输。
- GPU 渲染与反向传播。
- GPU 到 CPU 的 D2H 写回。
通过双缓冲区和独立 CUDA Stream，TideGS 确保 GPU 计算时，下一帧的数据正在后台传输，最大化硬件利用率。
### 3. 轨迹自适应差分流：只传增量这是最巧妙的部分。由于相机轨迹平滑，相邻帧的可见 Block 集合 KtK_t ​ 和 Kt+1K_{t+1} ​ 高度重叠。
- 驻留策略：TideGS 维护一个容量受限的驻留集合 RtR_t​。
- 差分传输：它只传输 St+=Rt+1∖RtS_t^+ = R_{t+1} \setminus R_t+​=Rt+1​∖Rt​（新增块），保留 Rt∩Rt+1R_t \cap R_{t+1}​∩Rt+1​（重叠块），驱逐 St−=Rt∖Rt+1S_t^- = R_t \setminus R_{t+1}−​=Rt​∖Rt+1​（旧块）。
- 效果：PCIe 流量不再与模型总大小 NN 成正比，而是与“工作集变化量”成正比。

## 工程启示- 缓存思维重构显存管理：不要试图把所有参数塞进显存。对于稀疏访问的大模型，将显存视为 L1 Cache，利用 SSD 作为 L3 Cache，通过预测访问模式（如轨迹相关性）来预取数据，是突破硬件限制的有效路径。
- I/O 与计算的重叠是王道：TideGS 的高效率不仅来自算法，更来自系统层面的异步流水线设计。在工程落地中，务必分离 I/O 线程与计算线程，避免阻塞。
- 空间索引的重要性：Morton 排序带来的空间局部性，使得粗粒度的剔除成为可能。在处理大规模几何数据时，始终要考虑数据布局对缓存命中率和 I/O 模式的影响。
## 局限与展望TideGS 目前依赖于平滑的相机轨迹来最大化工作集重叠。对于剧烈跳变视角的场景，差分流的收益会下降，可能需要更复杂的预取策略。此外，优化器状态在块被驱逐后会被丢弃（冷启动），这可能影响收敛速度，需要在存储开销与收敛稳定性之间做权衡。
总体而言，TideGS 为单卡大规模 3DGS 训练提供了一套完整的工程范式，值得在本地化 3D 内容生成和大规模场景重建中深入借鉴。
