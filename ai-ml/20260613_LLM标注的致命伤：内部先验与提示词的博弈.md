# ⭐⭐⭐⭐ LLM标注的致命伤：内部先验与提示词的博弈

论文 : On the Limits of LLM Adaptability: Impact of Model-Internalized Priors on Annotation Task Performance链接 : https://arxiv.org/abs/2606.00467我们在用 LLM 做数据标注或作为 Judge 时，总默认只要 Prompt 写得够清楚，模型就会乖乖听话。但这篇论文泼了一盆冷水： LLM 不是白板，它们脑子里早就有了“固有认知” 。
当你的任务定义与模型预训练时的内部概念（Internalized Priors）不一致时，再好的 Prompt 也救不了场。这对依赖 LLM 进行大规模标注的工程实践来说，是一个必须正视的底层限制。
### 为什么我们总被 LLM “带偏”？
LLM 在预训练和 RLHF 阶段已经接触了海量数据，形成了对某些概念（如“毒性”、“仇恨言论”）的隐性理解。
当你要求模型检测“游戏内的干扰行为”时，它可能已经在心里把它归类为更严重的“身份攻击”。这种 定义错位 导致了一个核心问题：
- 用户提供的 Prompt 是显性指令。
- 模型的内部先验是隐性锚点。
当两者冲突时，隐性锚点往往占据上风。论文通过三个研究问题拆解了这一现象：熟悉度如何影响性能？错误能否被纠正？错误定义会引发什么后果？
### 核心洞察：概念对齐胜过文本记忆作者提出了一个关键指标： 定义特定熟悉度（Definition-Specific Familiarity, DSF） 。它衡量的是模型对任务概念的内在理解与数据集官方定义的语义相似度，而不是模型是否“背诵”过数据集中的文本。
实验结果非常反直觉：
- 文本记忆无效：控制数据集难度后，三种文本记忆指标（ROUGE-L、BERTScore 等）与准确率均无正相关（偏相关系数均为负值）。
- 概念对齐有效：DSF 与模型性能呈显著正相关（偏相关系数 r=+0.41r = +0.41+0.41）。
这意味着， 让 LLM 表现好的关键，不是让它见过这些句子，而是让它的“世界观”和你的任务定义一致。
### 令人绝望的“决策粘性”
这是工程上最痛的一点。我们常以为 Zero-Shot 错了，加个 Few-Shot 或详细解释就能救回来。但数据显示：
- 整体救援率仅 34.8%：近三分之二的初始错误，无论怎么改 Prompt 都纠正不了。
- 高置信度更难救：当模型对错误答案非常自信（Confidence > 0.9）时，救援概率骤降至 20.8%。
⚠️ 警示 ：LLM 存在强烈的“决策粘性”（Decision Stickiness）。一旦它基于内部先验做出了高置信度的判断，外部指令很难扭转它的决定。这不是 Prompt 技巧的问题，而是模型行为的可控性边界。
### 错误的定义，极高的自信更可怕的是，当给 LLM 一个 错误或不匹配的任务定义 时：
- 它真的会照做：模型会根据错误定义的宽窄调整预测阈值（例如，狭窄的定义导致漏报，宽泛的定义导致误报）。
- 它依然很自信：即使应用了错误定义，模型的自报置信度（Self-reported Confidence）依然维持在 84%-91% 的高位。

### 工程启示：别迷信 Prompt，先选对模型基于这些发现，给工程师的建议很直接：
- 诊断先行：在大规模标注前，先用 DSF 方法评估模型与任务定义的语义对齐度。如果对齐度低，换模型比优化 Prompt 更有效。
- 放弃“万能救场”幻想：不要指望通过复杂的 Prompt 工程来修正所有 Zero-Shot 错误。对于高置信度的错误，微调（Fine-tuning）可能是唯一解。
- 警惕虚假自信：在 LLM-as-a-judge 场景中，不要依赖模型的 Confidence Score 来过滤低质量结果。需要引入外部验证机制或人工抽检。
- 定义设计比模型选型更重要：实验显示，不同定义带来的准确率波动（17%）远大于不同模型间的差异（5%）。花时间在打磨任务定义上，回报率最高。
这篇论文提醒我们，LLM 是有“性格”的工具。理解并尊重它的内部先验，比试图强行扭转它要明智得多。
