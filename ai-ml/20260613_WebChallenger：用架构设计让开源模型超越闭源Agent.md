论文 : WebChallenger: A Reliable and Efficient Generalist Web Agent链接 : https://arxiv.org/abs/2606.10423Web 自动化领域长期存在一个尴尬的现实：最强的通用型 Agent 依赖昂贵的闭源推理模型，而开源模型即便参数量不小，在真实网页导航任务中往往表现拉胯。
这篇论文给出了一个反直觉的答案： 瓶颈不在模型能力，而在 Agent 架构。
作者认为，现有框架未能复现人类浏览网页时的三大认知优势：选择性注意力、持久记忆以及对常见交互模式的操作熟练度。WebChallenger 通过纯架构设计（而非模型微调），让开源模型在多个基准测试中追平甚至超越了闭源 SOTA。
## 痛点：为什么 LLM 刷网页这么笨？
人类浏览网页时，大脑会自动忽略页脚广告，记住常用网站布局，并熟练处理下拉菜单等交互。但当前的 LLM Agent 通常把整个页面的 DOM 或截图作为扁平的 Token 序列喂给模型。
这导致三个致命问题：
- 注意力稀释：关键信息淹没在无关的 HTML 标签中。
- 无状态失忆：每次访问新页面都像第一次，缺乏对网站结构的先验知识。
- 交互碎片化：填写表单、选择下拉项等本应连贯的操作，被拆解为多次独立的“观察-决策”循环，极易出错且效率低下。
## 核心架构拆解：PageMem 与三大机制WebChallenger 的核心创新在于构建了一个名为 PageMem 的结构化页面表示层，并在此基础上实现了三个关键机制。
### 1. PageMem：确定性的结构化抽象不同于直接解析 DOM，PageMem 从 DOM 中确定性构建出语义层级。它将页面拆解为多个 PageSection （如导航栏、产品列表），每个 Section 附带简短摘要。
- 设计直觉：这就像给网页生成了一个“目录”。Agent 不需要阅读整页内容，只需扫描摘要即可定位相关区域。
### 2. 分治式观察管道（Divide-and-Conquer Observation）
这是提升性能的关键。Agent 首先浏览 PageMem 的 Section 摘要，筛选出与任务相关的几个 Section，仅对这些区域进行详细的信息提取。
- 为什么有效：它将长上下文任务分解为多个聚焦的子 Prompt。实验显示，移除该模块导致准确率暴跌 17.6%，是三个组件中影响最大的。
### 3. 离线探索与持久记忆（Exploration and Memory）
在执行具体任务前，系统会进行一次确定性的离线遍历，构建 WebsiteMem 。这记录了页面结构、导航路径及元素行为。
- 工程价值：这种记忆是一次性构建、多次复用的。在推理阶段，Agent 仅加载极少量的额外 Token 作为书签或上下文，极大降低了计算开销。
### 4. 复合动作工作流（Compound Action Workflows）
系统将常见的多步交互（如下拉选择、表单提交）封装为单一的 Compound Action 。
- 核心 Insight：中间状态的变化（如点击下拉框后展开列表）不应由顶层 Agent 感知，而应由底层工作流自动处理。这不仅减少了决策步骤，还避免了因页面局部刷新导致的上下文丢失。
## 实验结果：开源模型的逆袭WebChallenger 使用未经微调的 GLM-4-32B 和 Qwen2.5-VL-7B ，在四个主流基准上取得了惊人的成绩。

⚠️ 反直觉发现 ：在 WorkArena 上，WebChallenger 以 70.9% 的成绩超越了 Claude 3.5 Sonnet (56.4%) 和 GPT-4o (45.5%) 的基线表现。
消融实验进一步验证了架构的价值：
- 移除观察管道：准确率下降 17.6%，且平均 Prompt 长度从 1850 Token 激增至 8793 Token，步骤数增加 56%。
- 移除复合动作：总 Token 消耗从 47.0M 上升至 64.9M，因为原本一次完成的交互现在需要多次观察和决策。
## 工程启示与局限### 对工程实践的启示- 架构优于模型规模：在 Web Agent 领域，精心设计的上下文工程和状态管理比盲目堆砌参数量更有效。
- 本地部署可行性：该系统完全基于开源模型且无需微调，使得在企业内网或低成本环境中部署高性能 Web Agent 成为可能。
- 结构化表示的重要性：PageMem 的设计表明，将非结构化的网页内容转化为机器可读的语义层级，是提升 LLM 理解能力的关键一步。
### 局限与展望- 离线探索成本：虽然是一次性投入，但对于动态变化极快的网站（如新闻首页），预构建的记忆可能迅速过时。
- 视觉依赖：目前严重依赖 VLM 进行图像描述，在纯文本界面或简单 DOM 结构下，VLM 的引入可能带来不必要的延迟。
WebChallenger 证明了，通过模仿人类的认知习惯来重构 Agent 架构，我们可以用更小的模型、更低的成本，实现接近前沿闭源系统的性能。对于正在探索 Web 自动化落地的团队来说，这是一个极具参考价值的开源方案。
