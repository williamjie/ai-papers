# ⭐⭐½ 用对比反思让模型快速学会推理

**日期**: 2026-06-09

---

论文 : CORE: Contrastive Reflection Enables Rapid Improvements in Reasoning链接 : https://arxiv.org/abs/2605.28742大模型学不会举一反三？斯坦福这篇新工作给出了一个极具工程价值的解法：不更新权重，只通过“对比成败”提炼自然语言洞察（Insights），让冻结的模型在极少样本下快速进化。
### 为什么现有的自我提升方案这么慢？
目前的强化学习从验证器奖励（RLVR）或提示优化（如 GEPA）方法有个致命痛点：太贵且太慢。
参数量更新方法（如 GRPO）通常需要数十万次 rollout 才能看到明显进步；非参数方法虽然轻量，但往往依赖数百个训练样本和数千次尝试。人类只需几个例子就能悟出规律，而模型还在海量数据里“暴力搜索”。
核心矛盾在于：现有方法要么存储原始轨迹（冗余且难复用），要么更新黑盒权重（不可解释）。我们需要一种既能抽象经验、又能高效检索的中间态。
### CORE 的核心直觉：成败对比才是金矿CORE（Contrastive Reflection）的设计哲学非常清晰： 不要总结成功，要对比失败与成功的差异。
它的核心流程包含三个关键设计：
-对比反思生成洞察当模型解题失败时，CORE 不会让它独自反思。它会从记忆库中检索一个语义相似且成功的轨迹（τ+\tau^+），与当前的失败轨迹（τ−\tau^-）进行对比。
⚠️ 关键 Insight：孤立的成功往往包含偶然因素，而“为什么这次对、上次错”的对比能迫使模型提炼出通用的策略约束（如搜索空间结构、中间状态追踪）。
-基于效用的门控记忆生成的洞察不是直接入库，而是经过“准入测试”。只有当该洞察能让模型在当前问题上首次尝试即成功时，才会被存入“洞察记忆”。
每个洞察都绑定一个经验效用分数（Utility Score），记录它在哪些问题上有效。
-双重检索机制推理时，CORE 根据当前问题的语义相似度，召回相关洞察。但排序不仅看相似度，更看重历史效用。这解决了传统 RAG “相似但不适用”的问题。
### 实验结果：少样本下的降维打击作者在火柴棍算术、数学 GAP、汉诺塔和斑马逻辑四个任务上进行了测试。使用冻结的 gpt-oss-120b 模型，结果令人印象深刻。
1. 极低的 Rollout 效率成本在仅 10 个训练样本的情况下，CORE 仅需 350 次 rollout 就超过了所有基线方法在整个训练过程中的最佳表现。
- Matchstick Arithmetic: 准确率从 0.472 提升至 0.873（+85%）
- MathGAP: 准确率从 0.472 提升至 0.830（+76%）
相比之下，GRPO 和 GEPA 即使运行 4000 次 rollout，最终表现仍落后于 CORE。
2. 极致的上下文效率这是工程落地最关心的指标。CORE 每次推理只增加约 0.92k tokens 的额外上下文。
- Episodic RAG: 增加 33.6k tokens（是 CORE 的 36.6 倍）
- MemRL: 增加 32.7k tokens（是 CORE 的 35.6 倍）
这意味着 CORE 可以在长上下文窗口受限的场景下，依然保持强大的自我进化能力。
3. 洞察的可解释性CORE 学到的不是模糊的权重变化，而是清晰的自然语言规则。例如在火柴棍任务中，它学会了：“使用链式等式：将减号转换为第二个等号，可以创建三部分等式…”（效用值：0.14）。
### 工程启示与局限对于正在构建 Agent 或推理系统的工程师，CORE 提供了两条重要路径：
- 低成本微调替代方案：如果无法承担 RLVR 的海量算力成本，可以尝试用 CORE 的逻辑构建“反思-提炼”循环。特别是对于有明确验证器（Verifier）的任务，这种方法能以极低的 Token 成本实现性能跃升。
- 知识图谱的自然语言化：CORE 的记忆库本质上是一个动态更新的、带权重的自然语言知识图谱。这为后续的多任务迁移学习提供了结构化基础。
当然，局限也很明显。CORE 强依赖于 可验证的奖励信号 。在开放域写作或没有标准答案的任务中，这种方法难以直接应用。此外，虽然它比 RAG 轻量，但每次推理仍需调用嵌入模型和检索逻辑，增加了少量延迟。
总体而言，CORE 证明了： 让模型学会“如何学习”，比单纯喂给它更多数据更有效。
