# 小米多语言翻译：无参考RL微调实战

**日期**: 2026-08-13

---

论文 : Reference-Free Post-Training of Open Large Language Models for Multilingual Machine Translation链接 : https://arxiv.org/abs/2608.10812开源大模型做机器翻译，最大的痛点不是模型不够强，而是高质量平行语料太贵、太少。小米这篇论文提供了一个极具工程价值的解法：利用无参考质量评估（Reference-Free Quality Estimation, QE）作为奖励信号，结合强化学习（RL）和检查点插值技术，在 46 种语言上实现了翻译质量的显著提升。
### 为什么现有方案不够用？
传统的监督微调（SFT）严重依赖人工标注的平行数据。对于低资源语言或非英语中心方向，这种数据极度匮乏。虽然强化学习可以利用海量源端文本进行训练，但直接使用 QE 模型打分容易引发“奖励黑客”（Reward Hacking）现象——模型学会生成流利但完全错误的译文来骗取高分。
小米团队的核心洞察是： 单纯依靠 RL 优化会导致模型偏离 SFT 阶段学到的稳健行为，产生奖励诱导的漂移。 因此，他们设计了一套组合拳：语言识别门控 + GRPO 强化学习 + SFT-RL 检查点线性插值。
### 方法拆解：三个关键设计直觉-防作弊的语言门控奖励函数由 XCOMET2 和 COMETKiwi 两个 QE 模型的分数平均值得出，但加了一个硬约束：使用 OpenLID-v3 识别译文语言。如果识别出的目标语言与预期不符，奖励直接置零。这有效抑制了模型生成“流利废话”的倾向。
-数据筛选策略RL 训练需要样本间有足够的奖励方差才能提供梯度信号。他们从 SFT 数据中保留源句，丢弃参考译文，通过 rollout 采样后，仅保留组内平均奖励在 0.30<μx<0.950.30 < \mu_x < 0.95μx​<0.95 且标准差 σx≥0.05\sigma_x \ge 0.05​≥0.05 的样本。最终筛选出 31,572 个实例用于训练，去除了那些模型已经做得很好或完全做不好的“无效”样本。
-检查点线性插值（Checkpoint Interpolation）
这是本文最实用的工程技巧。纯 RL 训练后的模型虽然 QE 分数高，但 spBLEU（基于词重叠的指标）往往下降。作者提出直接对 SFT 模型参数 θSFT\theta_{SFT}​ 和 RL 模型参数 θRL\theta_{RL}​ 进行线性插值：
θα=αθSFT+(1−α)θRL\theta_\alpha = \alpha\theta_{SFT} + (1 - \alpha)\theta_{RL}​=αθSFT​+(1−α)θRL​通过调整 α\alpha，可以在“神经质量指标”和“传统 BLEU 分数”之间找到最佳平衡点，且无需额外训练。
### 关键结果：小模型也能打在 WMT24++ 和 FLORES+ 基准上，MiLMMT-46-v1.0 系列模型表现强劲：
- 整体提升：相比 SFT 基线 v0.1，v1.0 在 WMT24++ 上的无参考 XCOMET 分数平均提升 2.75 分，COMETKiwi 提升 2.44 分。
- 越级打击：1B 参数的 MiLMMT-46-1B-v1.0 在几乎所有指标上都超过了参数量四倍的 TranslateGemma-4B。
- 头部竞争：12B 模型在 46 种语言的无参考评估中，超越了 Google Translate、Gemini 3 Pro 甚至 GPT-5。
⚠️ 反直觉发现 ：纯 RL 训练会导致 spBLEU 下降约 1.21 分。但这并非坏事，因为 spBLEU 惩罚合理的同义替换。通过设置 α=0.5\alpha=0.5 0.5 的插值，模型在仅损失 0.54 分 XCOMET 的情况下，找回了绝大部分 spBLEU 分数。
### 工程启示- 插值是免费的午餐：对于任何使用 RLHF/RLVR 的场景，直接混合 SFT 和 RL 检查点是一个低成本、高收益的尝试方向，能有效缓解奖励模型偏差带来的性能波动。
- 小模型潜力巨大：通过正确的后训练策略，1B-4B 级别的小模型在多语言翻译任务上可以媲美甚至超越更大的开源模型，适合边缘部署或低延迟场景。
- 数据质量重于数量：RL 阶段仅使用了 3 万多条精心筛选的数据，而非海量噪声数据，证明了“高方差、适中奖励”样本对策略优化的重要性。
### 局限与展望论文指出，在线策略蒸馏（On-Policy Distillation, OPD）虽然能将大模型能力迁移至小模型，但并未超越直接 RL+插值的效果边界。未来工作将探索更鲁棒的人类对齐奖励模型，并扩展到多模态翻译场景。
