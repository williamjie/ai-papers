**日期**: 2026-05-28

论文 : ScientistOne: Towards Human-Level Autonomous Research via Chain-of-Evidence链接 : https://arxiv.org/abs/2605.26340现在的 AI 科研 Agent 已经能写出像模像样的论文，甚至通过某些会议初审。但如果你仔细审查这些“全自动”产出的成果，会发现一个尴尬的事实：它们经常一本正经地胡说八道。引用不存在的文献、报告无法复现的分数、代码实现与文中描述完全脱节。
Google 团队这篇 ScientistOne 直击痛点：它不再单纯追求 Agent 能跑多快的实验，而是引入了类似数据库 ACID 原则的 证据链（Chain-of-Evidence, CoE） 机制。简单说，就是强制要求论文里的每一个论断，都必须能追溯到具体的代码行、日志文件或真实文献。
### 为什么现有方案不可信？
目前的自动科研系统（如 AI Scientist v2, DeepScientist 等）大多是流水线式的：文献综述 -> 假设生成 -> 实验执行 -> 论文写作。问题在于，错误会在流水线中放大且难以察觉。
作者对 5 个主流系统在 5 个前沿任务上生成的 75 篇论文进行了审计，结果触目惊心：
- 幻觉引用率高达 21%：很多参考文献根本不存在，是模型凭记忆“编”出来的。
- 分数复现率低至 42%：论文里写的 SOTA 分数，重新跑代码根本对不上。
- 方法-代码对齐率仅 20%-80%：文中描述的算法逻辑，在提交的代码里根本找不到对应实现。
这些失败的根本原因只有一个： 缺乏可验证性（Verifiability） 。现有的评估只看“写得漂不漂亮”，不看“证据链是否完整”。
### 核心设计：像 ACID 一样管理科研证据ScientistOne 的核心 Insight 是借鉴数据库事务的 ACID 特性，定义了科研产出的 CoE 标准 。它不仅仅是一个后验检查工具，而是内嵌在生成流程中的架构约束。
系统分为三个阶段，每个阶段都强制保留元数据：
- 文献 grounding（Problem Investigator）：不靠模型记忆瞎编引用。通过学术 API 检索，读取最多 100 篇全文 PDF，构建带来源标记的引文图。这从源头上切断了幻觉引用的可能。
- 探索与执行（Discovery Engine）：并行探索多个分支，保留完整的实验日志、评分器和代码版本。
- 写作与验证（Paper Writer & Claim Verifier）：这是最关键的创新。写作时，每个事实性声明（数字、方法、引用）都绑定一个内联证据标签（如 {source: "log.md:42"}）。在最终输出前，Claim Verifier 会逐条核对：
数字是否匹配实验日志？
- 引用是否在引文图中存在且内容一致？
- 方法描述是否与代码逻辑对齐？
如果验证失败，系统会自动重写或删除该声明，直到所有证据链闭合才生成最终 LaTeX。

### 工程启示与局限对于正在构建 Agent 应用的工程师来说，这篇论文提供了一个重要的范式转移： 不要只关注 Agent 能做什么，要关注如何验证它做了什么。
- 结构化元数据是关键：ScientistOne 的成功依赖于在生成过程中保留细粒度的证据标签（Provenance Metadata）。如果你的 Agent 只是输出最终文本，后期几乎无法追溯错误根源。
- 分离“生成”与“验证”：引入独立的 Claim Verifier 模块，利用确定性规则（如比对日志数字）和 LLM 判断（如方法对齐），可以大幅降低幻觉率。
- 引用必须 Grounding：对于知识密集型任务，强制通过 API 检索并缓存引用来源，比依赖模型参数记忆更可靠。
当然，ScientistOne 也有局限。它的核心瓶颈在于 研究合理性（Soundness） 而非写作能力。虽然它保证了“说的都是真的”，但有时因为无法复现 SOTA 方法的深度对比，导致评审认为缺乏新颖性比较。此外，这种强验证机制增加了计算开销和延迟，不适合需要秒级响应的场景。
总之，ScientistOne 告诉我们：未来的 AI 科研助手，核心竞争力不在于写得有多快，而在于 每一句话都能找到出处 。
