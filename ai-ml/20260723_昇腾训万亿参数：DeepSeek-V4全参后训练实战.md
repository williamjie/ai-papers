论文 : SLAI T-Rex: Full-Parameter Post-training of the DeepSeek-V4 Family on Ascend SuperPOD链接 : https://arxiv.org/abs/2607.20145在 GPU 垄断大模型训练的叙事下，这篇来自深圳 Loop Area Institute 的技术报告堪称“硬核突围”。它详细拆解了如何在昇腾（Ascend）NPU SuperPOD 上完成 DeepSeek-V4 家族万亿参数 MoE 模型的全参数后训练。这不仅是硬件适配的胜利，更是一次从底层算子到上层业务流的系统性工程重构。对于关注非英伟达生态、特别是国产算力落地的工程师而言，这份报告提供了极具参考价值的避坑指南和性能调优思路。
### 痛点：MoE 在 SIMD 架构上的水土不服DeepSeek-V4-Pro 拥有 1.6T 参数，结合了大规模 MoE 层与混合稀疏注意力机制。这种架构在 GPU 上尚且棘手，在基于 SIMD（单指令多数据）的昇腾 910C NPU 上则面临更严峻的挑战。
核心瓶颈并非算力不足，而是 内存压力、通信重叠失效以及算子执行效率低下 。
论文通过 Profiling 发现，训练步骤延迟由四部分组成：有用计算、未隐藏通信、流水线气泡和设备空闲等待。其中，通信占据了总设备内核时间的 52.2% 。更令人意外的是，MoE 特有的 All-to-All 通信仅占通信时间的 14.5% ，真正的拖油瓶是张量/数据并行（TP+DP）的 AllReduce 和流水线并行（PP）的点ToPoint 传输。
⚠️ 反直觉发现 ：稀疏注意力算子并非计算密集型，而是内存和控制密集型。
数据显示， SparseAttnSharedkvGrad 算子的向量计算流水线利用率仅为 9.5% 。它之所以慢，不是因为矩阵乘法重，而是因为不规则的数据访问模式导致硬件矩阵引擎“饿死”，大部分时间花在搬运 Key-Value Tile 和执行标量索引逻辑上。
### 方法拆解：分层优化与 Agent 驱动SLAI T-Rex 框架采用三层优化策略，从并行策略、通信编排到底层算子重写，层层递进。
1. 并行策略重构：ETP 与 VPP 的组合拳面对昇腾 NPU 64GB 的显存限制，传统的 TP=4 会导致通信爆炸。团队采用了 Expert-Tensor Parallelism (ETP) 策略：
- Attention 层：使用 TP=2，减少通信开销并提升 GEMM 效率。
- MoE 层：使用 ETP=1，保持专家宽度完整，避免计算碎片化。
在流水线并行上，团队放弃了双向重叠的 DualPipeV，转而采用 Virtual Pipeline Parallelism (VPP) 。原因在于 DualPipeV 需要保留两份模型块，会导致显存峰值飙升至 54.6 GB ，逼近硬件极限且得不偿失。VPP 通过细粒度的虚拟阶段交错，有效抑制了流水线气泡，同时保持了训练稳定性。
2. 通信隐藏：把等待变成计算MoE 的 Token Dispatch 存在一个同步瓶颈 before_ep_alltoall 。由于动态分割大小在路由完成后才能确定，设备端会出现可见的空闲停滞。团队利用 共享专家（Shared Expert） 不依赖路由信息的特性，将其前向计算提前至同步间隔执行。这一调度策略巧妙地将屏障延迟转化为有效的 Cube 计算，实现了计算与通信的深度重叠。
3. AuraKernel：OR 驱动的算子优化 Agent针对稀疏注意力等内存绑定型算子，团队提出了 AuraKernel 。不同于传统的启发式搜索，AuraKernel 引入了运筹学（Operations Research, OR）求解器来指导 Tiling 优化。它能在巨大的搜索空间中自动重构 AscendC 内核，解决长尾、碎片化的内存绑定算子问题。此外，通过双缓冲 Swap Optimizer，将优化器状态卸载到主机内存并与计算重叠，进一步缓解了 HBM 压力。
### 关键结果：性能与能力的双重飞跃这套全栈优化带来了显著的性能提升和业务价值：

### 工程启示- 算力适配需深入底层：在异构硬件上训练万亿参数模型，不能仅靠上层框架调优。必须深入到 Kernel 级别，识别内存绑定型算子并进行针对性重写或融合。
- 通信优化重于计算优化：在大规模分布式训练中，通信往往是主要瓶颈。通过并行策略调整（如 ETP）和调度技巧（如提前计算共享专家），可以显著降低暴露的通信延迟。
- CPT-SFT 协同效应：对于专业领域（如运筹学），单纯的 SFT 可能不足以建立深层的结构化推理能力。先进行领域主导的 CPT，再进行 SFT，能带来更稳定的性能增益和更好的泛化能力。
### 局限与展望尽管取得了显著进展，该工作仍局限于昇腾 SuperPOD 环境，其他 NPU 或混合集群的适配仍需探索。此外，AuraKernel 的自动化优化流程虽然高效，但其通用性和对其他架构模型的迁移能力仍有待验证。未来，随着模型规模的进一步扩大，如何在保持高 MFU 的同时降低能耗和硬件成本，将是持续优化的重点。
