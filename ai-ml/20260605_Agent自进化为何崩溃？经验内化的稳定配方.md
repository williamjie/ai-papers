# ⭐⭐⭐ Agent自进化为何崩溃？经验内化的稳定配方

**日期**: 2026-06-05

---

论文 : Rethinking Continual Experience Internalization for Self-Evolving LLM Agents链接 : https://arxiv.org/abs/2606.04703做自主 Agent 的同学都知道，让模型从历史交互中“长记性”是终极目标。
大多数现有工作都在玩单轮迭代：收集数据、蒸馏微调、性能提升，完事。
但当我们试图把这个过程循环起来，构建真正的“自进化（Self-Evolving）”闭环时，灾难发生了。
这篇来自人大和美团的论文揭示了一个残酷真相： 现有的经验内化方法在多轮迭代下会发生能力崩塌，而非复利增长。
为什么？因为我们在经验表示、注入方式和训练机制上，都踩了坑。
### 痛点：越进化，越愚蠢作者发现，如果使用主流的在线上下文蒸馏（On-policy Context Distillation），随着迭代次数增加，模型在 WebWalkerQA 等基准上的成功率会断崖式下跌。
这不仅仅是过拟合，而是 能力崩溃（Capability Collapse） 。
为了解决这个问题，作者没有搞复杂的架构创新，而是从三个维度重新审视了经验内化：
- 经验粒度（Granularity）：记具体案例还是抽象原则？
- 注入模式（Injection Pattern）：全局塞入还是按需调用？
- 内化机制（Regime）：在线纠错还是离线模仿？
### 核心洞察一：原则级经验 > 实例级经验直觉上，我们喜欢让模型记住具体的成功轨迹。
但数据显示，74.4% 的实例级经验包含特定 URL，93.9% 包含具体实体字符串。这些是“局部特征”，换一批数据就废了。
相反， 原则级经验（Principle-level Experience） 抽象出了可复用的策略和失败模式。
在样本中，84.0% 的原则级条目包含可复用的策略陈述，而实例级只有 3.7%。
实验结果很诚实：实例级经验在第一轮能涨点分，但第二轮就开始掉队，甚至低于基线。原则级经验则提供了更持久的信号。
### 核心洞察二：步进注入 > 全局注入这是本文最反直觉的发现之一。
传统做法是把所有相关经验作为上下文（Context）一次性塞给 Teacher 模型。这叫 全局注入（Global Injection） 。
作者提出 步进注入（Step-wise Injection） ：根据当前的交互历史，动态选择相关的经验片段。
为什么全局注入会翻车？
因为在长程任务中，早期的搜索规划经验和后期的证据验证经验完全不同。全局注入会导致信息错位，甚至让模型产生 过早回答（Premature Answer） 的幻觉。
数据说话：
- WebWalkerQA 提升：步进注入比全局注入高出 +8.0%。
- GAIA 提升：+5.9%。
- 过早回答率：全局注入高达 63.82%，而步进注入为 0%。
⚠️ 关键发现 ：全局注入不仅当前效果差，还会破坏模型在多轮迭代中利用新经验的能力，导致自进化循环断裂。
### 核心洞察三：离线蒸馏 > 在线蒸馏目前业界流行在线上下文蒸馏（On-policy Distillation），即让学生生成轨迹，老师进行修正。
作者指出，这种机制本质上是**反应式（Reactive）**的。学生一旦跑偏，老师只能在错误的状态上做局部修正，无法展示完整的正确路径。
相比之下， 离线上下文蒸馏（Off-policy Context Distillation） 让拥有经验的 Teacher 直接生成高质量轨迹，学生进行模仿。
这提供了更连贯的监督信号。更重要的是，它避免了在线训练导致的 轨迹膨胀（Trajectory Inflation） 。
数据显示，经过一轮在线更新后，学生模型的平均 Assistant Turn 从基线的 2.5 暴涨到 21.9 ，而 Teacher 只有 4.5 。这不仅浪费算力，还引入了噪声。
### 最终配方与工程启示将三者结合： 原则级经验 + 步进注入 + 离线蒸馏 。
结果令人振奋：模型在多轮迭代中保持了稳定的性能增益，并且保留了在推理时利用显式经验的能力（In-context Responsiveness）。
这对我们的工程实践有什么指导意义？
- 别只存 Log：建立经验池时，必须通过 LLM 进行抽象提炼，提取“原则”而非“案例”。
- 动态检索是关键：不要简单地把 RAG 结果拼在 Prompt 开头。需要根据当前步骤的状态，精准匹配相关经验。
- 慎用在线微调：对于 Agent 的持续学习，基于高质量 Teacher 轨迹的离线 SFT/DPO 可能比在线 RLHF 更稳定、更高效。
### 局限与展望论文目前主要聚焦于 Web 推理任务。
虽然原理通用，但在代码生成、多模态等复杂场景下，经验抽象的难度会指数级上升。
此外，自进化系统存在“错误累积”的风险。如果初始经验包含偏见或错误，离线蒸馏可能会将其固化并放大。
因此， 经验池的审计（Auditing）和过滤机制 将是下一个工程重点。
这篇论文没有提出新模型，但它给混乱的 Agent 持续学习领域带来了一剂清醒药： 稳定比单点突破更重要。
