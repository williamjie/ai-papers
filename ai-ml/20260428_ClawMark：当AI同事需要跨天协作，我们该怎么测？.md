# ClawMark：当 AI 同事需要跨天协作，我们该怎么测？

**日期**: 2026-04-28

---

论文 : ClawMark: A Living-World Benchmark for Multi-Turn, Multi-Day, Multimodal Coworker Agents链接 : https://arxiv.org/abs/2604.23781现在的 AI Agent 评价体系，有点自娱自乐了。
大部分基准测试（WebArena、OSWorld、Terminal-Bench）都存在同一个致命假设： 环境是静态的，任务在单次会话中完成 。但真实办公场景中，你的 AI 同事要陪你工作好几天——邮件在来，日历在变，文件在被更新，监控视频在录制。今天读的合同，明天可能就被法务部悄悄加了一条备注。
ClawMark 的核心洞见很简单： 评测 coworker agent 必须用「活世界」 。它设计了三个一体的机制：
- 多天时间线：每个任务 2-6 个回合，每个回合 = 一个工作日。Agent 必须跨天维持状态，而不是一次性输出轨迹。
- 动态环境注入：回合之间，外部状态独立变化。分为两种：
Loud events（大声事件）：明确通知（如 “新邮件已到”）
- Silent mutations（静默变异）：默默发生的变化（如温度传感器 CSV 被写入、费率表被覆盖、CRM 备注被追加）
- 全多模态证据：原始 PDF、照片、音频、视频、表格直接喂入，不预转录。
- 基于规则的确定性评分：1537 个 Python 检查器直接查询服务后状态，全程无 LLM-as-judge。
这意味着，如果一个 agent 在第一天读取了文件，第二天同一文件可能已被篡改——它必须主动刷新状态，而不是靠记忆。

- Kimi K2.6：75.4 → 65.8（-9.6 分）
- GPT-5.4：76.6 → 68.9（-7.7 分）
唯一幸免的是 Qwen 3.6 Plus，Day 2 反而微升 1.2 分。Day 3 虽有轻微回弹，但六款模型仍低于 Day 1 基线。 首次环境突变是广域压力测试，适应能力直接拉开差距 。
更关键是 Sonnet 4.6 与 GPT-5.4 的差距变化：Day 1 领先 6.5 分，Day 2 缩窄到 3.7 分，Day 3 进一步缩到 4.0 分。这暗示：环境变化可能压缩了模型间的相对差距，但绝对能力鸿沟依然存在。
## 失败归因：两大致命短板将 10,759 次 checkers 评估按失败模式分类（表 5），发现失败集中在两个结构应力点：
- 静默变化检测失败率 56.5%：接近两倍基准均值。模型经常忽略未被通知的外部更新。
- 后端写回失败率 53.6%：同样接近两倍均值。写回失败也是绝对值最大的失败桶，占总失败的 16.7%。
这两个失败率几乎翻倍于整体 31.6% 的失败率。 模型更常「漏看」外部变化或「写不回去」，而不是普通的提取或交付物错误 。
红线检查器（55 个，占 3.6%）表现尚可，仅 7.1% 失败率（26/364 次评估），但一旦触发就是高权重硬约束，直接拉低 Task Success。
## 工程启示：构建真实 coworker 的关键设计如果你在开发持久性办公 Agent，ClawMark 的设计原则值得直接移植：
-任务驱动证据生成优于先收集再设计：Pipeline Phase 1 先写 task.py（定义回合、钩子、注入、评分规则），再精确收集所需 1072 个多模态 artifact。反向操作会导致信息密集但目的模糊的数据集。
-确定性评分必须「bit-identical」：发布门禁要求两次独立重跑产生完全相同的 checker 输出和诊断信息。这是无 LLM-as-judge 承诺的工程保障——通过重复性测试消除随机性依赖。
-红线检查器必须是普通 rubric 条目，而非特殊路径：在实现上，红线就是带固定高权重的普通 checker。这样既保证复制性，又避免评分流程分支复杂化。
-每回合需明确区分 loud/silent 事件注入：代码层面通过 inject/stage{N}/ 目录投放文件，服务端 Python 在回合入口追加邮件、重写表格、编辑知识库条目。Agent 必须Refresh 外部状态，不能依赖缓存。
-跨模态一致性检查：要求至少两个模态之间存在有意义的关联或矛盾（如视频显示 CEO 进入区域，同时 CRM 记录收入骤降）。这点对多模态理解是硬指标。
## 局限与未来方向论文自身指出了两个待解难题：
- Run-to-run 方差未报告：表 3 注明每个模型仅单次完整扫描，窄分差内的排名应谨慎解读。
- 效率与准确率的 trade-off 不明显：虽然 Sonnet 4.6 在「每千次工具调用得分」上领先（13.2），但整体来看，工具调用量、token 消耗与得分无单调关系。GPT-5.4 工具调用多 23% 反而降 3.8 分，Gemini 输入 token 多 31% 降 7.6 分，Qwen 输出 token 多 1.8 倍降 18.6 分。cost 与能力不成正比。
ClawMark 本质是在说： 评测 coworker agent 需要模拟「世界在变」这一根本现实 。当前模型在静态会话中表现尚可，一旦引入外部扰动，系统性问题立刻暴露。这对于要落地办公场景的 Agent 开发者来说，是个明确的预警信号——别被单轮测试的分数蒙蔽，跨天适应和多模态证据融合才是真正的硬仗。
