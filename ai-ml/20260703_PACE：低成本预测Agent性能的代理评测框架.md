论文 : PACE: A Proxy for Agentic Capability Evaluation链接 : https://arxiv.org/abs/2607.02032跑一次 SWE-Bench 或 GAIA 动辄花费数千美元和数天时间，这对大多数开发者来说简直是天文数字。
我们真的需要每次都全量运行这些昂贵的 Agent 基准测试吗？
CMU 的这篇论文给出了一个令人信服的否定答案：通过精心挑选少量非 Agent 任务（如指令遵循、代码生成）作为“代理”，就能以极低成本精准预测模型在复杂 Agent 任务上的表现。
这就是 PACE（Proxy for Agentic Capability Evaluation）。
### 为什么我们需要代理评测？
现有的 LLM 评估分为两类：一类是快速、廉价的原子能力测试（如 MMLU、HumanEval），另一类是耗时、昂贵的 Agent 环境交互测试（如 SWE-Bench、GAIA）。
痛点很明显：
- 成本极高：单次 Agent 评测可能花费数千美元，且需要复杂的沙箱或浏览器环境配置。
- 频率受限：高昂的成本导致研究人员无法频繁评估模型，难以在开发迭代中获得及时反馈。
- 能力重叠：Agent 任务的成功往往依赖于指令遵循、规划、工具调用等基础能力，这些能力已有廉价基准覆盖。
PACE 的核心直觉是：如果 Agent 性能由这些基础能力决定，那么是否存在一个小的非 Agent 实例子集，其得分能高度预测目标 Agent 基准的表现？
### 方法拆解：如何选出“预言家”实例？
PACE 并没有发明新的评测任务，而是从现有的 19 个非 Agent 基准（涵盖 11 种能力）中筛选出最具预测力的实例子集。
其核心设计包含两个互补的筛选策略和一个噪声感知的回归模型：
1. 双路实例选择（Instance Selection）
PACE 将候选池分为两部分进行筛选，平衡“全局信息量”与“目标相关性”：
- 全局选择（Global Selection）：利用 SVD（奇异值分解）计算每个实例的杠杆率（Leverage Score），衡量其在整个源数据分布中的几何重要性。再乘以该实例得分与目标 Agent 基准得分的斯皮尔曼相关系数（Target Relevance）。这确保了选出的实例既具有代表性，又与目标任务强相关。
- 局部选择（Local Selection）：仅基于目标相关性（斯皮尔曼相关系数的绝对值）进行筛选。这捕捉了特定于当前 Agent 基准的独特信号。
2. 噪声感知回归（Noise-Aware Regression）
Agent 基准的实例数量通常较少，导致模型平均分存在较大的采样噪声。PACE 采用 Bootstrap 重采样技术，对目标得分进行多次重采样以生成多个副本，然后在这些副本上拟合线性回归模型。这使得预测权重对采样噪声更具鲁棒性。
⚠️ 关键 Insight ：直接在整个候选池上拟合 Lasso/Ridge 回归会因样本量远小于特征数（ ∣Mtrain∣≪∣I∣|M_{train}| \ll |I| ​ ∣ ≪ ∣ I ∣ ）而过拟合。PACE 通过先筛选再回归的解耦策略，有效避免了这一问题。
### 实验结果：低成本下的精准预测作者在 4 个 Agent 基准（GAIA, SWE-Bench Verified, SWE-Bench Multimodal , SWT-Bench）和 14 个模型上进行了严格的留一法交叉验证（LOOCV）。

- 泛化能力：即使在训练时未见过的模型上，PACE 也能保持稳定的预测性能，证明了其选出的实例具有普遍的代表性。
### 工程启示与可解释性PACE 不仅是一个黑盒预测器，它还揭示了不同 Agent 任务对基础能力的独特需求：
- GAIA：高度依赖“指令遵循”和“验证测试”。这符合其基于浏览器的问答特性，需要严格遵循格式并自我检查。
- SWE-Bench Verified：核心在于“规划”、“代码生成”和“错误恢复”。模型需要规划补丁、编写代码并在测试失败后恢复。
- SWE-Bench Multimodal：显著依赖“长上下文聚合”。尽管涉及多模态，但许多任务主要通过文本问题和代码解决，视觉内容仅起辅助作用。
- SWT-Bench：集中在“验证测试”和“规划”。生成能触发 Bug 的测试用例需要精细的多步骤规划。
对于工程师而言，这意味着：
- 快速筛选：在模型开发或选型阶段，可以先运行 PACE-Bench（仅需几分钟），快速排除表现不佳的候选模型，再对头部模型进行全量 Agent 评测。
- 能力诊断：通过分析代理实例的能力分布，可以直观地了解某个 Agent 基准主要考察哪些底层技能，从而针对性地优化模型。
### 局限与展望PACE 的有效性依赖于校准模型集（Calibration Set）的代表性。如果新模型的架构或训练范式发生巨大变化，超出校准分布，预测误差可能会增加。因此，随着模型技术的演进，需要定期更新校准集以保持预测精度。
尽管如此，PACE 为 Agent 评估提供了一种实用、低成本且可解释的替代方案，极大地降低了高质量评估的门槛。
