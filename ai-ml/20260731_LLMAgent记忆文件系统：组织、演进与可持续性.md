论文 : Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability链接 : https://arxiv.org/abs/2607.26637现在的 AI Agent 越来越像程序员，它们把长期记忆存在 Markdown 文件里。这成了行业默认做法（如 Anthropic 的记忆工具），但没人系统研究过： Agent 真的能随着数据增长保持文件系统整洁吗？这种整理值得投入成本吗？
这篇论文首次对“基于文件系统的 Agent 记忆”进行了系统性拆解。它不造新轮子，而是把现有的文件系统实践形式化，通过控制变量实验，揭示了 Agent 在管理记忆时的真实行为模式和代价。
### 为什么现有方案不够用？
传统的长期记忆方案五花八门：向量数据库、知识图谱、摘要库等。但它们往往需要定制接口，且难以与 Agent 已有的文件操作能力融合。
文件系统（Filesystem）天然具备层级结构、可解释性强，且 Agent 已经精通 read/write 等基础工具。然而，随着对话轮次增加，记忆会面临 重复、冲突、过时 等问题。如果 Agent 只是盲目追加内容，文件系统会迅速变成垃圾堆；如果频繁重构，又可能引入幻觉或丢失细节。论文的核心洞察在于： 将记忆管理拆解为三个独立角色——管理 Agent（写入/组织）、搜索 Agent（读取/回答）、执行 Agent（任务/技能），并研究它们之间的博弈。
### 方法拆解：三个角色的协同论文定义了一个极简但通用的框架：
- 管理 Agent (Management Agent)：负责整合新信息，决定文件结构、命名和合并策略。它的目标是保持“组织性”。
- 搜索 Agent (Search Agent)：只读模式，根据查询在文件系统中导航并返回带引用的答案。
- 执行 Agent (Execution Agent)：在技能场景下，利用检索到的记忆完成任务。
关键在于**工具链（Harness）**的设计。管理 Agent 使用标准的文件操作（创建、替换、重命名等），而搜索 Agent 则依赖文件系统原生工具（查看目录、正则搜索等）。这种不对称性迫使搜索 Agent 真正理解文件结构，而不是单纯依赖向量相似度。
### 关键结果：组织真的有用吗？
论文在 LoCoMo、PersonaMem 和 REALTALK 等长对话基准上进行了测试。以下是核心发现：

更强的管理 Agent 能更好地维持文件系统的层级结构（Taxonomy adherence），但搜索 Agent 的能力才是决定最终答案质量的关键。如果搜索 Agent 很弱，再好的文件系统也救不了它。
### 工程启示：如何落地？
- 不要过度设计记忆结构：对于大多数场景，简单的“按会话/主题文件夹”分类（Foldered sessions）已经足够好，且成本极低。复杂的动态重组（Reorganization）往往带来边际收益递减，甚至因为压缩导致信息丢失（Condense 版本正确率降至 79.1%）。
- 搜索效率是整理的最大红利：虽然正确率提升有限，但有序的文件系统能显著降低检索时的 Token 消耗。在大规模记忆场景下，“搜索经济性”（Search Economy） 才是整理的主要价值所在。
- 工具链决定行为：改变 Agent 使用的工具集（如从文件 API 切换到 Shell），会强烈影响文件系统的形状。工程师可以通过调整工具权限来引导 Agent 的记忆组织方式，而无需修改 Prompt。
### 局限与展望目前的研究显示，随着记忆规模增长，除了最强的管理 Agent，其他模型的文件组织结构会逐渐退化（Degradation）。此外，现有的评估基准对“结构质量”不敏感，导致我们难以量化“好结构”的具体收益。未来需要更长期的观察，看看在数月甚至数年的交互中，文件系统是否能真正自我进化。
总之，这篇论文告诉我们： 文件系统是 Agent 记忆的合理默认选择，但不要指望 Agent 能像人类图书管理员一样完美整理。保持简单、注重检索效率，比追求完美的层级结构更重要。
