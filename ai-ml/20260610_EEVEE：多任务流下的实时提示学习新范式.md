# ⭐⭐⭐½ EEVEE：多任务流下的实时提示学习新范式

**日期**: 2026-06-10

---

论文 : EEVEE: Towards Test-time Prompt Learning in the Real World for Self-Improving Agents链接 : https://arxiv.org/abs/2606.11182现有的测试时提示学习（Test-time Prompt Learning）大多假设数据来自单一分布，这在实验室里跑分还行，但在真实世界的 Agent 应用中完全行不通。现实中的用户请求是异构的、混杂的，如果只用一个通用的 Prompt 去适应所有任务，结果往往是“顾此失彼”，新任务的优化会破坏旧任务的能力。
EEVEE 这篇论文直击这个痛点，提出了首个面向多数据集流的测试时提示学习框架。它的核心思路非常工程化：与其让一个 Prompt 硬扛所有领域，不如引入一个路由器（Router），把不同领域的请求分发到专门优化的 Prompt 槽位中。
### 为什么单 Prompt 方案在混合流中会失效？
论文通过 Figure 1 展示了一个残酷的事实：随着任务数量的增加，现有的 SOTA 方法如 GEPA 和 ACE 会出现严重的“灾难性遗忘”。
当同时处理 GPQA、Formula、TheoremQA 和 HumanEval 四个基准时，GEPA 和 ACE 的累积保留收益（Retention Improvement）分别为 -15.36 和 -18.58。这意味着，为了适应新加入的任务，模型在旧任务上的表现反而下降了。这是因为单一 Prompt 空间无法容纳异构任务的反馈信号，导致相互干扰。
### 核心设计：路由与提示的协同进化EEVEE 的解决方案不是简单的分类器+Prompt，而是引入了**路由-提示协同进化（Router-Prompt Co-evolution）**机制。
- 路由器的作用：它将输入流划分为不同的任务簇，并为每个簇分配专用的 Prompt 配置。这保留了基于 Prompt 的轻量级适配优势，同时减少了跨领域的破坏性干扰。
- 协同进化的必要性：路由器和 Prompt 是相互依赖的。路由决定了每个 Prompt 看到哪些数据，而 Prompt 的质量又决定了路由决策是否合理。如果先固定路由器再学 Prompt，或者反过来，都会陷入次优解。
- 三阶段训练策略：
初始化：先在混合数据上学习一组多样化的 Prompt，利用帕累托前沿（Pareto-front）选择互补的候选者，为路由器提供有意义的分区依据。
- 探索：在轻量级预算下交替更新路由器和 Prompt。早期侧重一致性和平衡性，后期侧重下游准确率，避免过早收敛到不稳定的分区。
- 收敛：一旦路由器稳定，固定路由策略，投入更大预算对每个槽位的 Prompt 进行深度优化。
这种设计确保了路由决策和 Prompt 专业化能力共同提升，而不是孤立优化。
### 关键实验结果在四个基准（GPQA Diamond, Formula, TheoremQA, HumanEval）的混合测试中，EEVEE 展现了显著的优势：

- HumanEval 的爆发：在代码生成任务 HumanEval 上，EEVEE 达到了 72.63 分，相比基线的 49.46 分提升了 23.17 分。这说明 Prompt 学习在处理有明确反馈规则的任务（如代码执行）时效果极佳。
- 保留收益：在增量多基准设置中，EEVEE 的最终累积保留收益为 +41.53，而 GEPA 和 ACE 均为负值。
### 工程启示与局限性⚠️ 反直觉发现 ：Prompt 学习擅长捕捉“可复用的程序”，但可能削弱“领域知识”。
在 GPQA Diamond（封闭书问答）任务中，EEVEE 的表现甚至略低于基线（-1.45 分）。案例研究表明，学习到的 Prompt 倾向于加强通用的推理步骤，但在需要特定领域事实（如天体物理中的行星密度压缩）时，可能会低估这些知识的重要性。
对于工程落地，EEVEE 提供了几个重要指导：
- 异构场景必须解耦：如果你的 Agent 面临多种类型的任务（代码、数学、常识），不要试图用一个全局 Prompt 解决所有问题。引入路由机制是必要的。
- 成本可控：EEVEE 的平均 Token 消耗为 4.32k/样本，远低于 ACE 的 21.30k。这意味着这种复杂的协同进化机制在生产环境中是可负担的。
- 跨模型迁移可行：在 Qwen3-4B 上学到的 Prompt 直接应用到 DeepSeek-V3.2 上，平均分从 39.75 提升到了 54.10。这表明学习到的“解题策略”具有一定的模型无关性。
EEVEE 证明了在真实世界的异构数据流中，通过路由隔离任务空间并协同优化 Prompt，是实现自我改进 Agent 的一条高效路径。对于需要处理多领域请求的生产级 Agent 系统，这是一个值得借鉴的架构范式。
