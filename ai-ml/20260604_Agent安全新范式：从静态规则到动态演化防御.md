# ⭐⭐⭐⭐ Agent安全新范式：从静态规则到动态演化防御

**日期**: 2026-06-04

---

论文 : BraveGuard: From Open-World Threats to Safer Computer-Use Agents链接 : https://arxiv.org/abs/2606.01166当大模型开始操作终端、浏览网页和修改文件时，传统的“提示词过滤”彻底失效了。这篇来自复旦与蚂蚁集团等机构的论文提出了 BraveGuard，一种针对计算机使用代理（Computer-Use Agents）的自演化防御框架。它不再依赖静态的风险分类，而是通过挖掘开源威胁情报，生成真实的执行轨迹来训练守卫模型。
### 为什么现有的 Guard 模型不管用？
传统的安全守卫模型（如 Llama-Guard）主要处理单轮对话中的恶意提示或有害回复。但在 Agent 场景中，危害往往隐藏在多步执行的轨迹中。
单个动作看起来完全无害：读取配置文件、安装依赖、执行调试命令。然而，这些步骤组合起来可能导致数据泄露、权限提升或策略绕过。现有方案通常基于固定的风险分类法（Taxonomy）或合成攻击数据训练，无法覆盖不断演变的真实威胁空间。一旦遇到新的工具链或未记录的攻击模式，模型就会失效。
### 核心洞察：让防御系统“活”起来BraveGuard 的核心设计直觉是： 威胁空间是非平稳的，防御数据必须随现实世界同步演化。
它构建了一个闭环管道，包含三个关键阶段：
-开放世界威胁发现：
系统主动扫描 arXiv、OpenReview 等开源研究源，提取最新的安全漏洞、攻击模式和失效案例。这些情报被结构化为风险类别（如数据泄露）、攻击模式（如间接提示注入）和失效模式。这一步确保了训练数据始终包含最新的攻击手段。
-攻击合成与轨迹采集：
基于提取的情报，系统生成可执行的计算机使用任务，并让 Agent（如 OpenClaw）在沙箱中运行。这产生了真实的执行轨迹（Rollouts），包括工具调用、文件修改和命令输出。关键在于，它同时收集“成功攻击”和“失败/拒绝”的轨迹，为模型提供对比学习素材。
-轨迹级监督与自演化：
守卫模型不再判断单个提示词，而是对整个执行轨迹进行安全标注。更重要的是，系统利用验证集上的错误案例（Hard Cases）反向更新威胁分类和关键词集合，触发下一轮的数据生成。这种“发现-合成-训练-反馈”的循环，使防御能力随新威胁的出现而自动增强。
### 实验结果：性能提升显著论文在 AgentHazard-Strongest 和 ATBench-500 两个基准上进行了评估。结果令人印象深刻，尤其是在召回率（Recall）这一关键指标上。

消融实验进一步证实了“自演化”机制的价值：
- 仅使用静态分类法训练，F1 分数为 62.18%。
- 加入动态威胁发现后，F1 提升至 78.94%。
- 完整的自演化闭环最终达到 89.22% 的 F1 分数。
### 工程启示：如何落地 Agent 安全？
对于正在构建 Agent 系统的工程师，BraveGuard 提供了几个重要参考：
- 放弃静态黑名单：基于关键词或固定规则的过滤在多步推理面前不堪一击。必须转向基于上下文的轨迹分析。
- 重视“负样本”生成：防御模型需要看到真实的攻击路径才能学会识别异常。利用自动化红队工具（Red Teaming）生成多样化攻击轨迹是必要的投入。
- 闭环反馈机制：不要指望一次性训练就能解决所有问题。建立从生产环境或验证集中挖掘难例（Hard Cases）、反哺训练数据的管道，是实现长期安全的关键。
### 局限与展望论文也指出了当前方法的边界：
- 数据依赖：防御效果取决于开源威胁情报的质量和任务合成的保真度。未公开的黑客技术可能无法被覆盖。
- 格式泛化：目前模型主要基于 OpenClaw 的轨迹格式训练，在跨平台（如不同工具接口或序列化格式）时性能可能下降。ATBench 上的表现虽好，但仍略低于针对该格式专门训练的 AgentDoG。
BraveGuard 展示了一条清晰的路径：Agent 安全不是一次性的产品，而是一个持续演化的过程。只有让防御系统像攻击者一样不断学习和适应，才能在开放世界中守住底线。
