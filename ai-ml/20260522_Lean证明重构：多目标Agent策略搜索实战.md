论文 : Lean Refactor: Multi-Objective Controllable Proof Optimization via Agentic Strategy Search链接 : https://arxiv.org/abs/2605.20244LLM 生成的形式化证明（如 Lean）通常又长又脆弱，不仅难读，编译还慢。这篇论文提出了一套无需微调、基于 Agent 策略检索的重构框架，能在压缩代码长度的同时兼顾编译速度和版本兼容性，对工程落地极具参考价值。
### 为什么现有的重构方案不够用？
目前的 LLM 证明优化（如 ProofOptimizer）主要依赖强化学习或监督微调，但面临三个工程痛点：
- 多目标冲突：证明长度越短，往往意味着调用更重的自动化战术（tactics），导致编译时间飙升。单一目标优化无法平衡这种张力。
- 版本碎片化：Lean/Mathlib 更新极快，而 LLM 知识截止滞后。LLM 经常幻觉出不存在的 API，导致代码在不同版本间无法迁移。
- 微调成本高：每次模型或库版本更新都需要重新微调，扩展性差。
### 核心 Insight：把“重构经验”外置为元数据策略库Lean Refactor 的核心设计直觉是： 将重构知识从模型权重中解耦，外挂到一个带有丰富元数据的策略库（Strategy Bank）中。
其关键设计包括：
- 密集标注的策略：从 20 万+ 长-短证明对中蒸馏出 9,237 条策略。每条策略不仅包含“何时应用”、“如何应用”，还附带两个关键元数据：预期编译时间缩减率和兼容的 Lean/Mathlib 版本集合。
- 多目标可控检索：在推理时，根据用户需求动态调整检索规则：
追求最短证明：按语义相似度 Top-K。
- 追求编译速度：先语义检索，再按“编译成本缩减”元数据重排序（Rerank）。
- 指定版本兼容：过滤掉不包含目标版本的策略。
- 插件式 Agent 循环：由 Planner、Refactorer 和 Debugger 组成，使用冻结的前沿 LLM（如 Gemini, Claude），无需任何微调即可适配新模型。
### 关键结果：显著优于基线实验表明，该方法在竞赛和研究级基准上均取得显著压缩效果：
指标/数据集 miniF2F (竞赛) PutnamBench (竞赛) Analysis (研究) 证明长度压缩率 88.40% 70.38% 33.54% 对比 ProofOptimizer +10.5% (vs 87.9%) +13.2% (vs 57.2%) N/A多目标控制的威力：
在 miniF2F 上，如果只按语义相似度检索（追求长度），编译时间反而增加了 103.98% （相对值）。而启用“编译成本重排序”后，不仅恢复了正向收益，还在 PutnamBench 上实现了 42.62% 的编译时间缩减。这证明了元数据引导的必要性。
版本鲁棒性：
在跨版本测试中，经过重构的证明在 Lean v4.29.0 上的类型检查通过率显著高于原始证明和 ProofOptimizer 的结果（例如在 v4.29.0 上，Lean Refactor 保持 168/194 通过，而原始证明仅 141/194 ）。
### 工程启示- 检索即控制：对于多目标优化问题，与其训练复杂的奖励模型，不如在推理阶段通过元数据过滤和重排序来实现精准控制。
- 知识外置优于权重内嵌：将版本兼容性等易变信息存储在外部数据库，比微调模型更可持续。新模型发布后，直接挂载策略库即可继承所有优化经验。
- Agent 架构的通用性：该框架在 Claude Haiku 4.5 上同样有效，甚至能提升通用编程 Agent（如 Claude Code）的表现，证明了其“即插即用”的特性。
### 局限与展望目前跨版本评估主要限于自包含的竞赛题目，研究级项目因强依赖特定工具链而难以全面测试。此外，策略元数据基于聚类聚合，可能存在边际归因不精确的问题。未来可探索更细粒度的编译成本预测机制。
