论文 : K-BrowseComp: A Web Browsing Agent Benchmark Grounded in Korean Contexts链接 : https://arxiv.org/abs/2606.02404当通用大模型在英语基准上趋于饱和，工程师如何验证其跨语言、跨文化的真实 Agent 能力？这篇论文提供了一个极具参考价值的“非英语语境”测试场。它揭示了：即便是在韩国这样拥有成熟互联网生态的地区，顶级 LLM 在复杂网页浏览任务中的表现依然惨烈。
### 为什么需要这个基准？
现有的 Agent 评估多集中在英文环境（如 BrowseComp），这导致两个盲区：
- 语言偏见：模型可能在英语上表现优异，但在特定文化语境下失效。
- 饱和效应：主流模型已在现有基准上刷出高分，难以区分真实能力与数据泄露。
K-BrowseComp 填补了韩语 Agent 评估的空白。它包含 400 个问题，其中 300 个由人工构建并验证（Verified Subset），另外 100 个通过对抗性方法生成（Synthetic Split）。这些问题要求模型进行多跳推理或多约束并行搜索，且答案必须基于公开网页证据。
### 核心设计：利用“信息不对称”生成难题论文最精彩的部分在于其 合成数据生成策略 。作者发现，解决浏览问题很难，但一旦知道证据路径，验证答案相对容易。这种“解题难、验证易”的不对称性被用于反向构造题目。
具体流程如下：
- 失败模式分类：人工分析模型在 Verified 子集上的错误，归纳出 9 种失败模式（如 F4 半结构化解析失败、F7 约束跟踪失败）。
- 逆向生成：让 Agent 扮演出题人，针对特定失败模式（如 F1-F8）从种子页面反向构造问题。
- 三重过滤：
可搜索性：确保答案不能直接通过简单搜索获得。
- 良构性：参考求解器必须能从源页面提取唯一答案。
- 对抗难度：目标模型（如 GPT-5.4-mini）必须失败，且失败原因需符合预设模式。
这种方法生成的 100 个合成问题，成为了极具针对性的压力测试集。
### 实验结果：巨头也翻车在 300 题的 Verified 子集上，最强模型 GPT-5.5 仅取得 45.67% 的准确率。相比之下，这些模型在原始英文 BrowseComp 上的得分高达 84%+。韩国本土大模型表现更差，最高仅为 10.33%。

### 关键洞察：搜索次数不是瓶颈一个反直觉的发现是： 错误的尝试往往比正确的尝试消耗更多搜索调用。
⚠️ 数据说话 ：GPT-5.5 在正确任务中平均使用 9.30 次搜索，而在错误任务中仅使用 7.08 次。DeepSeek-V4-Pro 的正确/错误搜索次数分别为 9.80 和 7.47。
这意味着模型并非因为“搜得不够”而失败，而是 在检索到证据后，无法有效维护候选集、约束条件和实体角色 。例如：
- 候选捕获（Candidate Capture）：模型过早锁定一个看似合理的实体，后续搜索变成确认偏误，忽略了其他约束。
- 约束跟踪失败：模型分别搜索了多个线索，但从未将它们合并到同一个候选表中进行过滤。
### 工程启示- 状态管理是 Agent 的核心：提升 Agent 性能的关键不在于增加搜索预算，而在于增强中间状态的维护能力（如候选集、约束列表）。
- 本地化评估的必要性：通用模型在非英语语境下的表现断崖式下跌，企业落地时需针对本地数据构建专属基准。
- 合成数据的价值：利用失败模式反向生成测试题，是低成本构建高质量压力测试集的有效手段。
### 局限与展望目前基准仅覆盖韩语，且主要依赖 Perplexity Search API。未来可扩展至其他语言，并探索不同搜索后端的影响。此外，韩国本土模型的落后表明，针对本地网页结构的微调（SFT）和推理增强仍有巨大空间。
