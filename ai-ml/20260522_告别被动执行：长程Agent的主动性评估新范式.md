# ⭐⭐⭐ 告别被动执行：长程 Agent 的主动性评估新范式

**日期**: 2026-05-22

---

论文 : π-Bench: Evaluating Proactive Personal Assistant Agents in Long-Horizon Workflows链接 : https://arxiv.org/abs/2605.14678现在的个人助理 Agent（如 OpenClaw、Claude Code）正从“单轮问答”向“长期陪伴”演进。但工程师们常发现一个痛点：Agent 往往像个听话的实习生，用户不说细节它就不动，导致大量认知负担转移回用户身上。这篇论文提出了 π-Bench ，专门评估 Agent 在长周期工作流中“主动挖掘隐藏意图”的能力，这对构建真正实用的生产级 Agent 极具参考价值。
### 为什么现有的 Benchmark 不够用？
现有的 Agent 评测大多假设目标是明确的（Explicit Goals），或者只关注记忆检索（Memory Benchmarks）。但在真实场景中，用户的需求往往是**欠规范（Underspecified）**的。
比如用户说“帮我规划下周旅行”，Agent 如果只回复“好的，请提供预算和目的地”，这就是被动执行。优秀的 Agent 应该能结合历史会话中提到的“偏好海边”、“预算有限”等隐藏意图（Hidden Intents），主动给出方案或精准追问。π-Bench 的核心洞察在于： 主动性（Proactivity）与任务完成度（Completeness）是两回事 。Agent 可以靠用户反复补全信息来完成任务，但这并不代表它聪明或高效。
### 方法拆解：如何量化“主动性”？
π-Bench 的设计非常贴近工程现实，主要包含三个关键机制：
-持久化工作空间（Persistent Workspace）：
Agent 不是在真空里对话，而是在一个共享的文件系统中操作。任务涉及代码、文档等具体工件（Artifacts）的创建和修改。这种设计模拟了真实的 IDE 或办公环境，要求 Agent 具备跨会话的状态管理能力。
-隐藏意图追踪（Hidden Intent Tracking）：
每个任务都标注了一组未在初始请求中说明的“隐藏意图”。Agent 有三种处理方式：
Completed：Agent 直接通过推理或行动解决了该意图（最高级）。
- Inferred：Agent 提出了精准的澄清问题，用户随后提供信息（次高级，体现了 Agent 知道缺什么）。
- Provided：Agent 没动静，直到用户被迫主动补充信息才算解决（最低级，即被动）。
-双指标评估体系：
Proactivity Score (PROCPROC)：衡量 Agent 主动解决或澄清意图的比例。公式为 (∣Icom∣+∣Iinf∣)/∣I∣(|I_{com}| + |I_{inf}|) / |I|​∣+∣Iinf​∣)/∣I∣。这直接反映了 Agent 减轻用户认知负担的能力。
- Completeness Score (COMPCOMP)：衡量最终产出是否满足检查清单（Checklist）。这是传统的任务完成度指标。
### 关键结果：顶尖模型也“不够主动”
论文在 9 个前沿模型上进行了测试，数据揭示了令人惊讶的差距：
模型 Proactivity ( PROCPROC ) Completeness ( COMPCOMP ) GPT-5.4 67.0% 65.6% Claude Opus 4.6 65.5% 67.6% Qwen3.6 Plus 64.0% 64.1% Kimi K2.5 43.1% 61.6%几个关键发现：
- 主动性与完成度解耦：Kimi K2.5 的 COMPCOMP 高达 61.6%，但 PROCPROC 仅为 43.1%。这意味着它能在用户不断补全信息后完成任务，但缺乏主动挖掘需求的能力。相反，Seed2.0 Pro 的 PROCPROC (58.4%) 高于 COMPCOMP (52.1%)，说明它能发现问题，但最终执行落地能力较弱。
- 领域差异巨大：药师（Pharmacist）任务最容易，平均 PROCPROC 和 COMPCOMP 最高，因为约束条件具体且基于本地文件。而法律实习生（Law Trainee）和金融师（Financier）任务最难，COMPCOMP 最低，因为这些领域需要复杂的风险判断和非标准化推理。
- 历史会话的价值：消融实验显示，如果移除前置会话的历史信息，GPT-5.4 的 PROCPROC 从 78.5% 暴跌至 64.9%，而 COMPCOMP 仅下降 2.5%。这证明了长期记忆对于“主动性”至关重要——Agent 需要利用过去的交互来推断当前任务的隐藏约束，否则只能退化为被动响应。
### 工程启示对于正在构建 Agent 系统的工程师，这篇论文提供了明确的优化方向：
- 不要只盯着最终输出：在评估 Agent 时，必须引入“过程指标”。如果一个 Agent 需要用户问 5 遍才能开始干活，即使最后做对了，它的体验也是极差的。
- 强化“澄清”能力：训练 Agent 不仅要学会执行，更要学会识别“信息缺口”。在设计 Prompt 或微调数据时，应增加针对“欠规范请求”的正样本，奖励那些能提出精准问题的行为。
- 利用工作空间上下文：Agent 的主动性往往来源于对历史文件、代码库和过往决策的记忆。确保你的 Agent 架构能有效地检索和利用持久化工作空间中的隐性知识，是提升 PROCPROC 的关键。
### 局限与展望π-Bench 目前仍使用模拟用户（Simulated User），虽然保证了可复现性，但可能无法完全捕捉真实人类用户的非理性或模糊表达。此外，评测基于单一的 Agent 框架（Nanobot），不同架构下的表现差异仍有待探索。
总的来说，π-Bench 提醒我们： 真正的智能助手不是“指令执行器”，而是“意图管理者” 。在长程交互中，谁能更早地消除不确定性，谁才能赢得用户信任。
