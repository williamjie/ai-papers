# 扔掉真值标签：用 LLM 先验在 POMDP 中构建世界模型

**日期**: 2026-05-19

---

论文 : Learning POMDP World Models from Observations with Language-Model Priors链接 : https://arxiv.org/abs/2605.13740在构建机器人或游戏 Agent 时，我们常面临一个尴尬的困境：为了训练世界模型，我们不得不依赖“上帝视角”的地面真值（Ground-Truth States）。但在真实物理世界中，这种特权信号根本不存在。这篇论文提出了 Pinductor ，一个仅凭观测、动作和奖励数据，利用大语言模型（LLM）先验就能诱导出生成可执行部分可观测马尔可夫决策过程（POMDP）世界模型的方法。
### 痛点：没有“作弊码”的世界模型怎么学？
传统的 POMDP 学习方法（如表格估计器、深度循环潜在模型）通常需要海量的环境交互数据，或者对模型结构有极强的先验假设。
近期利用 LLM 生成代码世界模型的工作（如 WorldCoder, POMDP Coder）虽然提升了效率，但它们大多依赖一个关键假设： 在训练时拥有隐藏状态的特权访问权限 。例如，POMDP Coder 需要事后提供真实的中间状态作为监督信号。然而，在机器人探索杂乱房间或玩非完美信息游戏时，这种“事后诸葛亮”的数据是不可获得的。
这就引出了核心问题： LLM 的先验知识是否足够强大，能在完全没有隐藏状态标签的情况下，仅凭观测轨迹构建出可用的世界模型？
### 核心设计：基于信念的软似然评分Pinductor 的核心 Insight 在于： 既然看不到真实状态，那就看模型预测的观测是否与真实观测“长得像” 。
传统方法直接比较预测状态 s′s' 与真实状态 ss 。Pinductor 则不同，它完全在观测空间工作：
- 代码生成与提议：LLM 根据少量离线轨迹和环境 API，生成包含状态转移、观测、奖励和初始状态分布的可执行代码。
- 软观测模型（Softened Observation Model）：这是关键设计。LLM 生成的观测模型通常是确定性的（硬匹配）。Pinductor 引入一个距离核函数，将确定性预测转化为概率分布。
对于 MiniGrid 环境，距离 dobsd_{obs}​ 由网格视野差异、方向差异和携带物体差异组成。
- 观测似然被定义为：Om(o∣s,a)∝exp⁡(−dobs/κ)O^m(o | s, a) \propto \exp(-d_{obs}/\kappa)(o∣s,a)∝exp(−dobs​/κ)。
- 这种“软化”处理允许模型在预测不完全精确时仍保留一定的权重，避免了硬匹配导致的粒子过滤崩溃。
- 基于信念的评分（Belief-based Scoring）：系统使用粒子滤波（Particle Filter）在生成的模型中传播信念。评分依据是：模型诱导出的信念分布，能否解释观测到的轨迹？
公式本质是计算观测轨迹在模型诱导信念下的对数似然。
- 结构化调试反馈：LLM 不仅收到一个标量分数，还收到具体的“失败案例”：哪些时间步的观测距离大？哪些状态转移存在模型间的分歧（通过投票熵衡量）？这引导 LLM 进行针对性的代码修复，而非盲目重试。

### 工程启示- 代码即模型（Code-as-Model）的泛化：Pinductor 证明了在部分可观测场景下，生成可执行代码比直接输出概率分布更具鲁棒性和可解释性。
- 软匹配的重要性：在利用 LLM 生成确定性逻辑时，引入距离核函数进行“软化”处理，是连接离散代码逻辑与连续观测噪声的关键桥梁。
- 调试即学习：将执行错误和信念分歧转化为结构化反馈给 LLM，比单纯的强化学习奖励信号更高效。这对于调试复杂的 Agent 逻辑极具参考价值。
### 局限与展望目前方法主要局限于 MiniGrid 等结构化环境，且高度依赖 LLM 的能力（实验显示性能随 LLM 能力增强而提升）。此外，频繁的 LLM API 调用带来了较高的计算成本和方差。未来方向包括将其扩展至更复杂的连续控制任务，以及优化 LLM 的调用策略以降低延迟。
对于工程师而言，Pinductor 提供了一个清晰的范式： 当缺乏真值标签时，利用 LLM 的常识构建先验，并通过观测一致性进行闭环修正，是构建高效世界模型的可行路径。
