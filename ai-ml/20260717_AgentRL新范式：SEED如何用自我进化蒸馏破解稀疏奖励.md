# ⭐⭐ Agent RL 新范式：SEED 如何用自我进化蒸馏破解稀疏奖励

**日期**: 2026-07-17

---

论文 : SEED: Self-Evolving On-Policy Distillation for Agentic Reinforcement Learning链接 : https://arxiv.org/abs/2607.14777做长程 Agent 强化学习（Reinforcement Learning, RL）的朋友都知道，最头疼的就是奖励稀疏。
模型跑了一百步才拿到一个成功信号，中间哪一步踩坑了、哪一步操作神了，梯度根本没法精准归因。
清华团队这篇 SEED 论文提供了一个很巧妙的解法：让 Agent 自己复盘，把“事后诸葛亮”的经验提炼成技能，再实时蒸馏回策略网络。
这不仅仅是加个提示词（Prompt），而是通过 自演化在线策略蒸馏（Self-Evolving On-Policy Distillation） ，把静态的经验变成了动态进化的监督信号。
## 痛点：稀疏奖励下的信用分配难题在 WebShop 或 ALFWorld 这类长程任务中，基于结果的 RL（如 GRPO）只能告诉模型“这次成功了”或“失败了”。
这种粗粒度的反馈存在巨大的 监督鸿沟（Supervision Gap） ：
- 失败轨迹中有价值行为被忽略：可能前 90% 的操作都很完美，最后一步失误导致全盘皆输。
- 成功轨迹中的策略未被显式提取：模型虽然做对了，但不知道具体是哪种思维模式起了作用。
现有的解决方案要么依赖外部静态记忆库，要么在推理时插入冗长的技能提示词。
SEED 的核心洞察在于： 完成的轨迹本身就包含了决策时不可见的“后见之明”（Hindsight） 。
如果能把这些事后才能看清的规律，转化为训练时的密集监督信号，就能解决细粒度信用分配问题。
## 方法拆解：从“复盘”到“内化”的两阶段闭环SEED 的设计非常精妙，它没有引入额外的教师模型，而是让同一个模型身兼二职： 演员（Actor） 和 分析师（Analyzer） 。
### 第一阶段：后见之明技能微调（Hindsight Skill SFT）
首先，收集一批离线轨迹，用外部大模型分析这些轨迹，生成自然语言形式的“技能描述”。
这些技能包括可复用的工作流、关键观察点或避坑指南。
然后，对这些数据进行监督微调（Supervised Fine-Tuning, SFT），让基座模型学会如何从轨迹中提取这些技能。
这一步赋予了模型“自我复盘”的能力，为后续的自演化打下基础。
### 第二阶段：自演化在线策略蒸馏（Self-Evolving OPD）
这是 SEED 的灵魂所在。在 RL 训练循环中：
- 同步快照：冻结当前策略 πθold\pi_{\theta_{old}}​​，它既负责与环境交互收集轨迹，也负责分析这些轨迹生成技能 ss。
- 上下文增强重打分：对于同一条采样轨迹中的动作，模型分别在“普通上下文”和“技能增强上下文”下计算对数概率。
- 构建蒸馏信号：利用两者之间的概率差值 Δ\Delta，通过 Sigmoid 函数生成一个置信度门控 gg。
如果技能支持该动作，Δ>0\Delta > 00，门控开启，强化该动作；- 如果技能反对该动作，Δ<0\Delta < 00，门控关闭，抑制该动作。
- 联合优化：将这种 Token 级别的蒸馏损失与传统的 RL 奖励损失结合，共同更新策略参数。
核心直觉 ：随着策略参数的更新，模型收集轨迹的能力和分析技能的能力同步提升。这种“自我进化”机制确保了监督信号始终与当前策略分布对齐，避免了传统蒸馏中常见的分布偏移问题。
## 关键结果：全面超越基线SEED 在 ALFWorld、WebShop 和 Search-based QA 三个基准测试中表现强劲。

## 工程启示与局限对于正在构建 Agent 系统的工程师，SEED 提供了几个重要参考：
- 不要迷信推理时提示：如果技能是通用的，通过微调内化到模型中，不仅能减少 Token 消耗，还能获得更好的性能表现。
- 利用轨迹后处理：现有的 RL 流程往往只关注奖励值。尝试引入轻量级的轨迹分析模块，生成中间步骤的监督信号，能显著提升收敛速度。
- 小模型也能玩大 Agent：SEED 在 Qwen2.5-3B 上取得了优异结果，说明通过正确的训练范式，中小参数模型也能胜任复杂的长程交互任务。
当然，该方法也有局限。SFT 阶段依赖外部大模型生成高质量技能标注，这在一定程度上增加了前期成本。此外，自演化机制虽然避免了分布偏移，但也可能导致模型陷入局部最优的技能循环中。
总体而言，SEED 为 Agent RL 提供了一个兼顾样本效率和性能上限的新范式，值得深入研究和落地尝试。
