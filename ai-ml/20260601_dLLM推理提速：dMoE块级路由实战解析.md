论文 : dMoE: dLLMs with Learnable Block Experts链接 : https://arxiv.org/abs/2605.30876扩散大语言模型（Diffusion LLMs, dLLMs）正在成为自回归模型的强力竞争者，其天然支持并行解码的特性极具吸引力。然而，当 dLLM 结合混合专家（Mixture-of-Experts, MoE）架构时，现有的 Token 级路由机制会导致严重的内存瓶颈。这篇论文提出的 dMoE 方案，通过简单的“块级”聚合策略，在几乎不损失性能的前提下，将推理延迟降低了最高 1.66 倍。
## 痛点：并行解码引发的 MoE 灾难传统自回归模型一次只生成一个 Token，每个 Token 独立选择专家，激活的专家数量相对可控。但 dLLM 采用块扩散（Block Diffusion）机制，在一个去噪步骤中同时处理多个 Token。
这就导致了一个致命问题： 同一个前向传播中，不同 Token 可能激活完全不同的专家 。
论文在 LLaDA2.0-mini 上的实测数据显示，这种“各自为政”的路由方式使得单次推理激活的唯一专家数量高达 69.5 个。由于 MoE 模块的延迟与唯一激活专家数量呈线性正相关（如图 2c 所示），这直接导致内存访问成为主要瓶颈，MoE 延迟甚至超过了 Attention 计算。
⚠️ 关键洞察 ：在 dLLM 中，优化重点不再是单个 Token 的计算效率，而是如何压缩整个 Block 内被激活的专家总数（Unique Expert Count）。
## 方法拆解：从 Token 到 Block 的“粗粒度”路由dMoE 的核心直觉非常朴素但有效： 既然一个 Block 内的 Token 是并行处理的，为什么不让它们共享一部分专家池？
具体设计分为两步走：
-分数聚合（Aggregation）：
首先，保留原有的 Token 级路由逻辑，计算每个 Token 对所有专家的打分。然后，将这些打分在 Block 维度上进行累加，得到一个“块级专家得分”（Block-Level Expert Scores）。这一步利用了论文发现的规律：Token 级的专家得分与模型重构损失呈正相关（皮尔逊系数 0.46），说明高分专家确实更重要。
-动态核心集选择（Dynamic Coreset Selection）：
基于块级得分，使用 Top-p 策略筛选出一个“候选专家池”（Coreset）。这里的关键在于自适应：不同去噪步骤的专家分布集中度不同（变异系数 CV 高达 15%-17%），固定大小的裁剪会损害性能。Top-p 允许在分布集中时大幅压缩专家数，在分布分散时保留更多候选，从而灵活适应推理状态。
最后，原始的 Token 级路由被限制在这个 Coreset 内进行二次选择。训练阶段采用自蒸馏（Self-Distillation）范式，确保模型学会在这种受限路由下依然能准确预测。
## 关键结果：极致压缩下的性能保留dMoE 的效果可以用“暴力且优雅”来形容。在 LLaDA2.0-mini 上，它实现了惊人的专家压缩率：

## 工程启示与局限对于正在落地 dLLM 的工程团队，这篇论文提供了明确的优化方向：
- 路由层级上移：在并行解码场景下，Token 级的细粒度路由是内存杀手。将路由决策提升到 Block 或 Sequence 级别，是解决 MoE 推理瓶颈的必由之路。
- 动态阈值优于静态裁剪：直接固定 Top-K 专家会导致性能剧烈波动。利用 Top-p 这种基于概率密度的自适应方法，能更好地平衡不同推理阶段的复杂度。
- 自蒸馏的重要性：改变路由逻辑相当于改变了模型的归纳偏置。通过自蒸馏让模型“适应”新的稀疏模式，比直接微调或剪枝更有效且稳定。
局限性 ：目前实验主要集中在 LLaDA2.0-mini 这一特定架构上。虽然方法具有通用性，但在更大参数规模（如 10B+）或其他 dLLM 变体（如 SDAR）上的表现仍需验证。此外，Top-p 的阈值 pp 需要根据具体硬件和延迟需求进行调优，缺乏完全自动化的配置机制。
总体而言，dMoE 是一个低成本、高回报的工程改进，值得所有关注 dLLM 推理效率的团队参考。
