# 字节级大模型：用草稿纸打破效率瓶颈

**日期**: 2026-05-12

---

论文 : Scratchpad Patching: Decoupling Compute from Patch Size in Byte-Level Language Models链接 : https://arxiv.org/abs/2605.09630如果你还在为 Tokenizer 的边界问题头疼，或者觉得无 Tokenizer 的字节级模型太慢，这篇来自 Google DeepMind 的论文可能给你第三条路。它提出了一种叫 Scratchpad Patching (SP) 的机制，核心就一句话： 在“补丁”内部塞进临时的“草稿纸”，让模型在不需要增加 KV Cache 负担的前提下，动态增加关键位置的计算量。
### 痛点：补丁越大，信息越“滞后”
现在的无 Tokenizer 字节级模型（Byte-level Language Models）为了提速，通常会把连续的字节聚合成一个“补丁”（Patch），一次性扔进主干网络（Main Trunk）处理。
这里有个死结： 补丁大小（Patch Size） 。
- 补丁越小，序列越短，KV Cache 越小，速度越快。
- 但补丁越小，模型更新上下文越频繁，计算量爆炸。
- 补丁越大，效率越高，但引入了补丁滞后（Patch Lag）。
什么是补丁滞后？在自回归生成中，为了保证因果性，补丁内除了最后一个字节，前面的所有字节在预测时，只能依赖 上一个补丁 的表示。补丁越大，这个“旧信息”就越陈旧，模型就像戴着厚手套绣花，精度大幅下降。
传统的做法是优化补丁分割算法（如基于熵、基于空白符），但这只是切分得更聪明，没能解决“计算资源分配不均”的问题——简单的固定大小补丁在信息密集区显得算力不足，在稀疏区又浪费算力。
### 核心 Insight：瞬态草稿，不占缓存SP 的巧妙之处在于它没有改变补丁的边界，而是在补丁 内部 插入了瞬态的“草稿状态”（Scratchpad）。
- 按需刷新：在补丁内部，如果某个字节的预测不确定性（熵）高，就触发一次“草稿更新”。这个草稿会聚合当前补丁内已看到的字节，并重新通过主干网络，为后续字节提供更新鲜的上下文。
- KV Cache 隐身：这是工程上最性感的地方。这些草稿状态仅用于内部计算，不参与持久化的 KV Cache。推理时，KV Cache 里只保留每个补丁最终确定的那个状态。
- 解耦计算与大小：这意味着你可以在保持大补丁（低 KV Cache 占用）的同时，通过增加草稿数量来补偿精度损失。计算量不再被补丁大小死死绑定。
### 关键实验数据：16倍压缩，性能不打折论文在 2B 参数量的模型上进行了大量实验，结果非常直观。
1. 自然语言理解（NLU）：小补丁也能打大补丁看 Table 1 的数据，固定大小补丁（Fixed-size patching）在 p=16 时，平均准确率只有 48.0%。但加上 SP 后， Fixed (p=16) + SP 达到了 54.2% ，直接追平甚至略微超过了原始的字节级基线（54.1%）。
更厉害的是，它在保持 16 倍序列压缩比的同时，KV Cache 占用仅为字节级的 1/16。
2. 代码生成：效率与质量的兼得在 MBPP 和 HumanEval 上（Table 2），SP 同样显著提升了效果。
- Fixed (p=16) + SP 在 HumanEval 上 Pass@1 达到 14.8%，而普通 p=16 只有 10.5%。
- 相比 Tokenizer 基线，SP 模型在保持更短序列长度的同时，推理 FLOPs/byte 减少了 4.5 倍。
3. 计算效率验证Figure 7 显示，在 FLOPs 匹配的情况下，SP 模型在大多数补丁策略下都能达到或超越非 SP 基线。这说明 SP 带来的提升主要来自 计算分配的优化 ，而不是单纯堆砌算力。
### 工程启示：可插拔的“精度-速度”旋钮对于工程师来说，SP 最大的价值在于 推理时的灵活性 。
由于草稿状态的触发阈值（熵阈值 τSP\tau_{SP} ​ ）是在训练后固定的，你可以在推理时通过调整这个阈值，动态改变草稿的密度。
- 想快？调高阈值，减少草稿触发，牺牲少量精度换取速度。
- 想准？调低阈值，让模型在复杂代码或生僻词处多算几层。
Figure 10 展示了这种平滑的权衡曲线。这意味着你可以部署一个模型，根据用户请求的复杂度或服务器负载，实时调整计算预算，而不需要重新训练。
### 局限与展望当然，SP 不是银弹。
- 训练开销：虽然推理时 KV Cache 没变，但训练时需要并行处理这些瞬态状态，训练 FLOPs 会有所增加。
- 复杂补丁器的交互：在 H-Net 这种已经非常复杂的动态补丁策略中，SP 的效果提升有限，甚至在严格 FLOPs 匹配下略有下降（Section 5.1）。这说明如果边界切分本身已经非常智能，额外的内部刷新可能带来冗余计算。
总的来说，Scratchpad Patching 为无 Tokenizer 模型提供了一条实用的优化路径：不必在“大补丁的低精度”和“小补丁的高计算”之间二选一，而是让模型学会在关键地方“多写几笔草稿”。
