论文 : Domain-Specific Data Synthesis for LLMs via Minimal Sufficient Representation Learning链接 : https://arxiv.org/abs/2605.30039大多数数据合成工作都卡在第一步：你得先能把“领域”说清楚。
如果是写代码，你能写出“LeetCode 风格”的 Prompt 吗？如果是内部黑话或新兴梗，根本没法用自然语言定义。
这篇 KDD 2026 论文 DOMINO 提出了一种**归纳式（Inductive）**范式：别写 Prompt，只给几个参考样本，让模型自己悟出“领域规律”。
### 痛点：显式定义的局限现有的数据合成方法（如 Self-Instruct, MAGPIE）本质上是 演绎法 。
它们依赖人工编写的 System Prompt 或关键词提取。这要求领域特征必须能被自然语言明确描述。
但在实际工程中，很多高价值场景（如专有业务逻辑、快速变化的文化趋势）根本无法用文字精准定义。
更糟糕的是，如果直接拿少量参考样本做监督微调（SFT），模型会死记硬背样本细节，导致泛化能力极差，甚至性能下降。
### 核心 Insight：最小充分表示DOMINO 的核心直觉是模仿人类的归纳学习：通过观察少数典型例子，提取本质规律，忽略无关噪声。
技术上，它追求学习一个 最小充分表示（Minimal Sufficient Representation） D∗\mathbf{D}^* 。
- 充分性（Sufficiency）：表示必须包含领域的所有关键信息，能重构样本。
- 最小性（Minimality）：表示必须剔除样本特有的噪声（如具体数字、特定措辞），只保留通用模式。
为了实现这一点，DOMINO 引入了 对比解耦机制 。
它同时优化两类 Soft Token：
- 领域级 Token D∗\mathbf{D}^*：捕捉所有样本共享的“第一性原理”。
- 样本级 Token S(i)\mathbf{S}^{(i)}：捕捉每个样本独有的细节。
通过对比损失函数，强制模型将“区分不同样本”的任务交给 S(i)\mathbf{S}^{(i)} ，从而防止 D∗\mathbf{D}^* 过拟合到具体样本上。
关键设计 ：训练时联合优化 D∗\mathbf{D}^* 和 S(i)\mathbf{S}^{(i)} ，但推理生成数据时， 只使用 D∗\mathbf{D}^* 。
这种“分离”确保了生成的多样性——因为 D∗\mathbf{D}^* 不包含具体样本的锚点，LLM 必须在符合领域规律的广阔空间中自由探索。
### 实验结果：隐式领域下的降维打击论文在 LiveCodeBench 上进行了严格测试，这是一个动态变化的编程基准，完美模拟了“难以用 Prompt 定义”的隐式领域。
以下是基于 Qwen2.5-Coder-14B-Instruct 的结果对比（Pass@1）：

- 直接微调（SFT）是毒药：在 Live Code Execution 任务中，直接用参考数据 SFT 导致性能从 59.26% 暴跌至 38.88%。这证实了小样本下模型极易过拟合。
- LLM 比人类更懂“总结”：MAGPIE-Few Shot（让 LLM 自己看样本总结规律）略优于 MAGPIE-Human（人工写 Prompt）。说明在隐式领域，人类的语言描述反而丢失了细微的模式。
- 合成数据能超越原模型：使用 DOMINO 合成的数据微调 Base 版本，其性能（24.75%）甚至超过了原本经过指令对齐的 Instruct 版本（23.35%）。
### 工程启示对于需要快速适配新领域的工程师，DOMINO 提供了一条无需 Prompt 工程的捷径。
- 适用场景：内部私有数据、风格独特的代码库、新兴网络用语等“只可意会”的领域。
- 操作流程：收集几十到上百个高质量参考样本 -> 运行 DOMINO 训练 Soft Token -> 生成大规模合成数据 -> 微调目标模型。
- 成本控制：只需要优化少量的 Soft Token，无需全量微调 LLM，计算成本极低。
### 局限与展望DOMINO 目前主要在代码和指令跟随任务上验证，对图像或多模态领域的适用性尚待探索。
此外，参考样本的质量直接决定上限。如果初始样本存在严重偏差，归纳出的“领域规律”也会偏离正轨。
但不可否认，它标志着数据合成从“人工指导”向“数据驱动归纳”的重要一步。当领域无法被言说时，让模型自己去“看”，或许是更优解。
