# ⭐⭐⭐½ 扔掉地图引擎：大模型如何学会公交导航

**日期**: 2026-05-22

---

论文 : TransitLM: A Large-Scale Dataset and Benchmark for Map-Free Transit Route Generation链接 : https://arxiv.org/abs/2605.22355传统的路径规划系统是个“重工程”产物：你需要维护庞大的路网拓扑图，编写复杂的 Dijkstra 或 RAPTOR 算法，还要处理实时路况。阿里高德团队这篇论文抛出了一个大胆的想法： 能不能完全抛弃地图引擎和拓扑图，让大模型直接从数据里“学会”坐公交？
他们给出的答案是肯定的。通过构建一个包含 1300 万条真实导航日志的专用数据集 TransitLM，他们证明了经过持续预训练（Continual Pre-Training, CPT）的大模型，不仅能生成结构合法的路线，甚至能仅凭 GPS 坐标隐式地完成“地点到站点”的空间对齐。
### 为什么通用大模型搞不定公交规划？
你可能会说，GPT-4 或 Qwen 这种通才模型什么不会？但在公交导航这个垂直领域，它们表现糟糕透顶。
核心痛点在于 结构幻觉 。通用模型缺乏对城市交通拓扑的深层理解。当你问它“从 A 到 B 怎么坐车”，它可能会编造出一个不存在的站点，或者给出两条根本不相连的线路。现有数据集要么只有车辆轨迹（如 T-Drive，缺少站点结构），要么只有静态路网（如 GTFS，缺少用户行为偏好）。没有结合“完整路线结构”和“真实用户选择”的数据，模型就无法学习端到端的规划逻辑。
### 核心 Insight：用数据代替算法TransitLM 的设计直觉非常清晰： 如果导航引擎生成的候选路线本身是合法的，那么这些日志就是完美的“教科书”。
- 数据即知识：他们从北京、上海、深圳、成都四个城市提取了 1300 万条规划记录。每条记录不仅包含起点终点，还包含了完整的站点 ID 序列、换乘点、耗时和票价。
- 隐式空间对齐：这是最精彩的部分。模型输入是原始 GPS 坐标，输出是站点序列。模型不需要显式的“坐标转站点”映射表，它通过海量数据学习到了“这个坐标附近通常对应哪个站点”。这种能力被称为隐式空间接地（Implicit Spatial Grounding）。
- 词汇表扩展：为了防止模型把站点 ID 拆解成字符从而产生幻觉，他们将 120,845 个站点 ID 注册为独立 Token。这让模型能像处理单词一样处理站点，直接学习站点间的拓扑关系。
### 关键结果：小模型打败大通用实验结果非常有说服力。他们在三个任务上进行了测试：最优路线生成、偏好感知规划（如“优先地铁”）、多路线生成。
1. 通用大模型的溃败在最优路线生成任务中，即使简化输出要求（只预测首末站），SOTA 的通用模型表现依然惨淡（见表 1）：

2. 领域模型的碾压经过 TransitLM 持续预训练和微调的 Qwen3-4B 模型，性能实现了质的飞跃（见表 2）：

3. GPS 只有实验：真正的空间理解为了验证模型是否真的理解了空间，还是只是在“背地名”，作者做了一个消融实验：只输入 GPS 坐标，去掉所有文本提示。
- 通用大模型：REM 直接跌至 <1%，因为失去了地名线索，它们无法将坐标映射到具体站点。
- TransitLM 模型：Qwen3-4B 的 REM 仅从 71.0% 微降至 70.4%。这证明了模型确实内化了空间拓扑，而非简单的文本联想。
### 工程启示- 垂直场景无需依赖复杂后端：对于公交、地铁等相对静态的交通网络，端到端的大模型方案是可行的。你可以用一个小参数量的领域模型替换掉复杂的图搜索引擎，降低系统耦合度。
- 多任务联合训练无负迁移：论文发现，将最优路线、偏好规划、多路线生成三个任务混合微调（Joint SFT），模型在所有指标上均优于单任务训练。这意味着你可以部署一个统一模型处理所有导航需求，无需维护多个服务实例。
- 数据规模存在边际效应：实验显示，CPT 数据量从 6.25% 增加到 100%，性能单调提升。但在仅使用 6.25% 数据时，连通性已达 94%，说明基础拓扑学习较快，而精确匹配和数值预测需要更密集的数据覆盖。
### 局限与展望目前 TransitLM 主要覆盖中国四个城市，且基于静态路网。现实世界中，实时拥堵、临时封路等动态因素尚未纳入。此外，模型生成的路线虽然结构合法，但是否具备“人类直觉”（如避开恶劣天气路段）仍需进一步探索。不过，这已经为“无地图导航”打开了大门。
