# 早退不崩盘：KV共享让大模型推理提速2倍

**日期**: 2026-04-22

---

论文 : River-LLM: Large Language Model Seamless Exit Based on KV Share链接 : https://arxiv.org/abs/2604.18396大模型推理慢，大家都懂。Early Exit（提前退出）听起来是个完美的方案：简单的 token 在浅层就退出来，复杂的 token 走深层。但现实很骨感——在 Decoder-only 架构里，Early Exit 有一个致命缺陷，叫 KV Cache Absence （KV缓存缺失），导致理论提速 3.3 倍，实际几乎跑不出来。
上海交大这篇 River-LLM 干了一件漂亮的事：零训练（Training-free），通过一个”KV共享出口河”机制，把这个问题彻底修了，实测提速 1.71× 到 2.16×，且精度几乎不降。
## 痛点：为什么Early Exit在LLM里这么难？
在 CNN 里，Early Exit 早就玩烂了。但在 LLM 里，情况完全不同。
Decoder-only 模型做自回归推理时，每个新 token 都要依赖前面所有 token 的 KV Cache。如果一个前面的 token 提前退出了，它跳过的那些层就没有生成 KV 对。后面的 token 要计算 Self-Attention 时，发现缺数据——这就叫 KV Cache Absence 。
论文评估了现有四种补救方案，结果都不理想：
方案 原理 代价 KV Mask 把缺失KV的token屏蔽掉 精度暴跌，需要更深层补偿，延迟反而更高 Batching Recompute 缺了KV就重算 长序列下计算开销巨大，破坏内存访问效率 State Propagation 把当前层隐藏状态复制给后续层 精度和速度的折中，但实际提速仍不如预期 Mono-Decreasing Exit 强制token退出位置单调递减 牺牲了Token-level Exit的灵活性，KV问题避开了，但潜力没了图3的数据显示，在 GSM8K 基准上，这些方法要么延迟比基线还高（Mask），要么提速微乎其微（Recompute）。 没有一种方案能真正桥接理论层数减少和实际墙钟加速之间的鸿沟。
## 核心Insight：KV-Shared Exit RiverRiver-LLM 的设计直觉很简单： 既然跳过backbone层会导致KV缺失，那我不跳过KV了，我用一个轻量级的”出口层”来自然生成这些KV。
具体怎么做？
- 权重直接复制：把backbone对应层的Attention和FFN权重直接拷贝到Exit Layer，不做任何微调。
- 4-bit量化：对Exit Layer做PTQ（Post-Training Quantization），W4A16量化方案，但KV Cache保持FP16。这样做有两个好处：一是让Exit River的吞吐比全精度backbone块快2.4×；二是量化带来的KV误差极小——论文Fig.5显示，无论在哪层退出，Exit KV和Backbone原生KV的余弦相似度始终高于0.97。
- 串行拓扑：Exit Layer从预设入口层Ls开始串联，token一旦决定退出，就沿着这条”Exit River”快速走完剩余层，自然生成完整的KV Cache，无需任何后处理恢复操作。
这就是论文定义的 “Seamless Exit” （无缝退出）：
- Granular Freedom（粒度自由）：每个token可以独立在任意层退出。
- Intrinsic KV Integrity（内建KV完整性）：跳过层的KV是执行Exit Path的副产品，不需要额外的恢复或重计算。
## 怎么决定什么时候退？
光有Exit River不够，还得知道 什么时候该退 。River-LLM 用了一个巧妙的启发式策略： State Transition Similarity （状态转移相似度）。
核心观察是：backbone层输入和输出的隐藏状态之间的余弦相似度，可以预测累积KV误差。Fig.6a显示，第一层的状态转移相似度和最终层的Backbone-Exit Value相似度存在中等正相关（r = 0.5536, p < 0.001）。
退出决策公式很简单：
D(l) = I[ min(st,b) > τ ]其中 st,b 是第l层第b个样本的状态转移相似度，τ 是阈值。Fig.6b显示，这个相似度随层数大致单调递增——意味着浅层对隐藏状态影响更大，深层更多是冗余计算，符合Early Exit的物理直觉。
这个设计最聪明的地方在于： 它不需要训练任何Exit Predictor ，直接利用backbone自身的前向传播结果就能做决策。
## 关键结果：数字不会骗人论文在 Llama3.2 1B、Llama3.1 8B、Phi4-mini、Ministral3 8B 四个模型上做了全面评估。
精度保持（Table 2）：
在默认阈值 τ=0.5 下，Llama3.2 1B 平均只执行3-4层backbone，大部分基准精度与基线几乎持平。比如 GSM8K 从 33.2→29.3（MATH 17.8→14.6），HumanEval 25.8→23.2。提升到 τ=0.7 时，精度几乎无损。

## 工程启示- 零训练部署：不需要微调Exit Layer，权重直接拷贝+量化，一分钟搞定。这对生产环境非常友好，不需要重新训练或收集数据。
- Prefill和Generation阶段不同策略：Prefill阶段用Sequence-level Exit（所有token统一深度，保持并行Attention kernel效率），Generation阶段切换到Token-level Exit（最大化加速）。这个设计很务实。
- 适合长序列场景：GSM8K、MATH、HumanEval 这种生成长度的任务，Token-level Exit 的潜力远大于 Sequence-level Exit。如果你的应用场景是代码生成或数学推理，这个方案值得重点关注。
- 精度-速度可调：通过调整 τ 阈值，可以在精度和加速比之间灵活trade-off，不像全量化那样一刀切。
## 局限与展望论文没有明确讨论的边界：
- Exit Layer 的入口层 Ls 怎么选？论文提到是”predefined”，但没有给出自动化搜索方法。
- 状态转移相似度作为退出判据，在极端case下是否稳定？比如某些token的隐藏状态本身就波动较大。
- 论文只评估了 Decoder-only Transformer，Encoder-Decoder 架构（如T5）是否适用还需要验证。
但总的来说，River-LLM 提供了一个优雅的思路： 与其花大力气修复KV缺失，不如让缺失的KV在一条轻量级的”河流”中自然生成。 这个设计直觉值得所有做推理加速的工程师参考。
