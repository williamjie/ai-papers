# Agent创意新基准：Affordance-Based工具复用

**日期**: 2026-05-08

---

论文 : CreativityBench: Evaluating Agent Creative Reasoning via Affordance-Based Tool Repurposing链接 : https://arxiv.org/abs/2605.02910大模型在逻辑推理和常规工具调用上已经很强，但在面对“没有现成工具”的突发状况时，往往显得笨拙。这篇来自UIUC和亚马逊的研究提出了 CreativityBench ，它不测模型背了多少知识，而是测模型能不能像人一样，通过理解物体的物理属性（Affordance，可供性），把一把钥匙当成撬棍，把破瓶子当成玻璃刀。这对构建真正具备**创造性问题解决（Creative Problem Solving）**能力的Agent至关重要。
## 为什么现有评测不够用？
目前的Agent评测主要停留在两个维度：
- 分析智能（Analytical Intelligence）：数学推理、代码生成，这类任务有标准答案。
- 实践智能（Practical Intelligence）：调用API、浏览网页，这类任务路径相对固定。
但在现实世界中，真正的挑战是 创造性智能 ：在资源受限、非标准环境下，重新组合现有物品来解决问题。现有的基准（如MacGyver）虽然涉及工具复用，但往往只要求模型选出“大致合理”的物体，缺乏对**部件级（Part-level） 物理属性和 可供性（Affordance）**的严格 grounding。
作者发现，简单的思维链（Chain-of-Thought, CoT）并不能显著提升模型的创意能力。在100个任务的预实验中，结构化CoT虽然让“物理接地”得分从3.44微涨到3.54，但在“创意推理”维度反而表现更差。这说明： 缺的不是推理步骤，而是对物体底层物理机制的深刻理解。
## CreativityBench 的核心设计为了解决这个问题，论文构建了一个基于**可供性（Affordance）**的知识库和评测基准。
### 1. 可供性知识库（Affordance KB）
这是整个基准的基石。传统的知识图谱关注“物体是什么”，而这个KB关注“物体能做什么以及为什么能做”。
- 层级结构：Entity（实体）→ Parts（部件）→ Attributes（属性）→ Affordances（可供性）。
- 细粒度拆解：例如，钥匙的“尖端”（Part）具有“刚性、尖锐”（Physical Attributes），从而提供了“撬动、切割”（Affordances）。
- 状态感知：不仅包含固有属性，还包含状态属性（如真空袋是空的还是满的），因为状态不同，可供性完全不同。
- 规模：包含4K实体，26K部件，157K条可供性标注。
### 2. 逆向工程任务生成传统的任务生成是先有场景再找工具，容易导致多个解或模糊性。CreativityBench采用 逆向工程 ：
- 采样黄金可供性：从KB中选择一个特定的部件属性组合。
- 合成场景：围绕这个可供性构建一个物理上必须依赖它才能解决的问题。
- 干扰项采样：精心选择具有相似语义但物理属性不同的物体作为干扰项（Distractors），迫使模型不能靠语义匹配，必须靠物理推理。
- 双重验证：确保在当前场景下，黄金解是唯一最优解。
最终生成了14K个 grounded 任务。
## 关键实验结果作者评估了10个主流大模型（包括GPT-5, GPT-4.1, Qwen3, Llama等），结果揭示了当前模型的几个致命短板：
模型/维度 Entity Correct Rate Gold Correct Rate 洞察 整体表现 中等 < 40% 模型能猜对物体，但找不到对的地方用 GPT-5 系列 高 低 逻辑推理强，但创意复用弱 Qwen3-32B 中 高 在小参数模型中，创意工具发现能力意外较强核心发现：
- 部件级接地是瓶颈：模型经常选对物体（Entity Correct），但无法定位到正确的部件（Gold Correct）。性能在从实体级到部件级的过程中下降了 60%以上。
- 推理≠创意：在逻辑推理上最强的模型（如GPT-5家族），在创造性工具发现上并不占优，甚至被Qwen3-32B超越。这说明分析能力与创造性复用是解耦的。
- Scaling Law失效：模型大小增加带来的收益迅速饱和。面对长尾、罕见的工具复用场景，大模型表现依然很差。
- CoT无效：包括提高采样温度、使用结构化CoT等推理时策略，几乎无效，甚至因为过度自信而加剧幻觉。
## 工程启示对于正在构建Agent的工程师来说，这篇论文提供了几个明确的改进方向：
- 引入物理常识层：不要只依赖LLM的隐式知识。在Agent的工具调用模块前，增加一个基于物理属性（硬度、弹性、形状）的过滤或重排序层。
- 细化工具表示：在工具库（Tool Registry）中，不要只存“物体名称”，要存“部件-属性-功能”三元组。例如，Key: [tip, rigid, sharp] -> [pry, cut]。
- 微调数据构造：未来的SFT数据不应只关注“调用什么API”，而应关注“如何解释物体属性以解决非标准问题”。
- 警惕CoT陷阱：在处理创造性、开放性问题时，简单的分步推理可能限制模型的发散思维，甚至导致过早收敛到错误假设。可能需要探索基于世界模型的模拟或强化学习策略。
## 局限与展望CreativityBench目前主要聚焦于静态场景下的工具复用，且依赖LLM作为Judge进行部分验证，可能存在评估偏差。未来需要结合具身智能（Embodied AI）环境，验证这些推理在真实物理交互中的可行性。
总之，CreativityBench 指出了大模型从“执行者”向“创造者”进化过程中缺失的那块拼图： 对物理世界底层机制的深刻理解与重组能力。
