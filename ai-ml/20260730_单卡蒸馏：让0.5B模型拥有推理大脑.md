# ⭐⭐⭐½ 单卡蒸馏：让0.5B模型拥有推理大脑

**日期**: 2026-07-30

---

论文 : CADENCE: Closing the Reasoning Gap via Coverage-Adaptive On-Policy Distillation链接 : https://arxiv.org/abs/2607.16955大多数工程师对“知识蒸馏”的印象还停留在用大模型生成数据做监督微调（Supervised Fine-Tuning, SFT）。但这种方式有个致命缺陷：学生模型在训练时看老师的答案，推理时却只能靠自己瞎猜，这种分布错位（Distribution Shift）导致小模型很难真正学会“思考”。
这篇论文提出了 CADENCE 框架，核心在于解决 On-Policy Distillation（在线策略蒸馏）中的三个顽疾。最让人兴奋的是，作者仅用一台 Apple Mac Studio（40核GPU），就成功将 1.5B 教师模型的推理能力迁移到了 0.5B 学生模型上。
### 为什么现有的蒸馏方法会失效？
作者精准地指出了当前 On-Policy 蒸馏的三个“崩溃模式”：
- 冷启动崩溃（Cold-start collapse）：小模型一开始根本猜不到老师喜欢的那个词，导致反向 KL 散度下的梯度消失，学生无法 bootstrap。
- 无状态的调度：现有的方法通常按固定时间比例混合前向/后向 KL，忽略了不同问题的难度差异。简单题可能早就学好了，还在被强行“覆盖模式”训练；难题还没入门就被迫“锐化”。
- 奖励稀疏（Binary reward sparsity）：传统的 Pass/Fail 信号太粗糙。一道数学题思路全对但最后算错，和完全胡言乱语得到的奖励是一样的（都是0）。这浪费了大量中间过程的有价值信息。
### CADENCE 的核心设计直觉CADENCE 不是简单的模块堆砌，而是一套针对上述痛点的组合拳。其核心机制 DRIFT 并没有追求序列级的 KL 梯度估计，而是务实地在 Token 级别进行前向 KL（覆盖模式）和反向 KL（锐化模式）的凸组合优化。
为了控制这个混合过程，作者引入了几个极具工程洞察力的组件：
- COVA（覆盖率自适应调度）：这是解决“无状态调度”的关键。它不再看训练步数，而是实时监测学生模型对教师 Top-k 词汇的覆盖程度。只有当覆盖率超过阈值 γ\gamma，才加速从“广泛探索”向“精准模仿”过渡。
- FTB（分叉 Token 增强）：利用全局归一化的熵作为参考，专门在教师模型高熵（即推理关键分歧点）的位置放大梯度信号。这比盲目加权所有 Token 更有效。
- CCD（密集奖励机制）：针对数学题，如果学生答案错误但数值接近正确答案，给予部分分数。这一改动将非零奖励的比例从 ~49% 提升到了 ~55%，显著缓解了稀疏奖励问题。
⚠️ 反直觉发现 ：作者明确指出，DRIFT 优化的是 Per-token surrogate objectives（Token级代理目标），而非严格的序列级 KL 梯度。这种“不完美”的近似反而带来了更稳定的方差和计算效率，是工程落地的务实选择。
### 实验结果：单卡也能跑推理蒸馏在 GSM8K 数据集上，使用 Qwen2.5-Math-1.5B 作为教师，0.5B 学生模型的初始准确率为 48.7%。经过 CADENCE 蒸馏后，准确率飙升至 69.8% ，填补了与教师模型之间 63.2% 的性能差距。

### 工程启示与局限对于想要部署边缘侧推理模型的团队，CADENCE 提供了清晰的路线图：
- 不要只做 SFT：On-Policy 采样能显著缩小训练-推理分布差距。
- 奖励信号要密集：在数学或代码生成中，引入数值接近度等部分奖励（Partial Credit）比单纯的 Pass/Fail 更有效。
- 关注覆盖率而非步数：自适应调度能让模型在不同难度的样本上获得更合适的训练节奏。
当然，方法也有边界。作者承认 CCD 的部分奖励提升幅度有限（仅 ~6%），未来可能需要步骤级的过程奖励（Step-level process rewards）来进一步突破。此外，该方法目前主要针对数学推理，在代码或逻辑领域的泛化性仍需验证。
总之，CADENCE 是一篇极具工程落地价值的论文，它用巧妙的机制设计弥补了小模型的先天不足，且对硬件极其友好。
