论文 : ParaVT: Taming the Tool Prior Paradox for Parallel Tool Use in Agentic Video Reinforcement Learning链接 : https://arxiv.org/abs/2605.20342用强化学习（Reinforcement Learning, RL）给多模态大模型（Large Multimodal Models, LMMs）注入“调用工具”的能力，是长视频理解领域的热点。但很多工程师在落地时会发现一个尴尬现象：模型要么格式崩了乱写代码，要么为了省事直接跳过工具瞎猜。这篇来自 MiroMind 和 NTU 等机构的论文 ParaVT，不仅提出了并行的工具调用架构，更精准地拆解了导致 RL 训练失败的“工具先验悖论”，给出了极具实操价值的解法。
### 痛点：串行调用的脆弱与 RL 的“双刃剑”
现有的长视频理解方案（如 LongVT）通常采用串行工具调用：模型看一段、切一刀、再看下一段。这种模式有三个致命伤：
- 错误累积：如果第一步切片切错了，后续推理全废，且没有同伴纠错。
- 上下文污染：多轮对话中不断堆叠视频帧 Token，导致上下文窗口迅速饱和。
- 推理延迟线性增长：调用次数越多，等待时间越长。
ParaVT 提出在单轮内并行分发多个时间窗切片给子 Agent，最后汇总证据。这听起来很美好，但直接上 RL 训练（如 GRPO）时，模型会陷入作者定义的**“工具先验悖论”（Tool Prior Paradox）**：
- 格式脆弱（Format Fragility）：预训练阶段留下的工具调用先验很强，但在 RL 的温度采样下，模型会退化回旧的 <tool_code> 标签或丢掉闭合标签，导致 Reward 无法解析。
- 工具必要性缺失（Tool Necessity Gap）：如果给模型的概览帧足够多，它直接能答对，那“调用工具”和“不调用”的奖励没区别。RL 的梯度消失，模型学会偷懒（Reward Hacking），直接跳过工具。
### 方法拆解：PARA-GRPO 的两步走策略为了解决上述悖论，作者提出了 PARA-GRPO ，核心直觉是“先保格式，再给压力”。
-探索锚定（Exploration Anchoring）——解决格式崩溃针对性奖励：不在所有 Token 上施加格式惩罚，只在最容易崩的结构边界（如 </think> 闭合标签）施加奖励。这避免了与内容准确性梯度的冲突。
- 约束生成：强制模型以 <think> 开头，并奖励包含 <answer> 结尾的 rollout。
- Insight：RL 引起的策略漂移集中在少数高发散 Token 上，通过锚定这些结构边界，能以最小代价恢复 Rollout 的可解析性。
-帧预算门控（nFrames Gating）——解决偷懒问题随机化概览帧数量：在训练时，随机给模型提供 4 到 64 个不等数量的概览帧。
- 制造奖励差距：当概览帧很少时，不调用工具必错，调用工具能得分，从而产生显著的 Advantage 信号。这强制模型在困难样本上学会使用工具，而在简单样本上保持灵活。
### 关键结果：显著的性能提升ParaVT 基于 Qwen3-VL-8B-Instruct 进行训练，在 6 个长视频基准测试中全面超越基线。

### 工程启示- RL 训练需要“对症下药”：不要盲目套用通用的 GRPO/DPO 框架。对于 Agent 场景，必须单独处理“格式稳定性”和“动作必要性”。
- 并行优于串行：在视频理解中，并行切片+文本摘要聚合，不仅提高了容错率（多数投票），还控制了 Token 膨胀，这是未来 Video Agent 的主流方向。
- 数据构造很关键：作者将串行的工具调用轨迹合并为并行的独立切片，这种数据清洗思路对构建高质量 SFT 数据很有参考价值。
### 局限与展望虽然 ParaVT 效果显著，但其并行架构依赖于子 Agent 返回文本摘要而非原始帧，这在一定程度上损失了细粒度视觉信息。此外，随机化帧预算的训练策略增加了工程实现的复杂度，需要在实际部署中权衡训练成本与推理收益。随着模型内部工具能力的增强，如何更优雅地平衡“预训练先验”与“RL 对齐”，仍是下一个研究重点。
