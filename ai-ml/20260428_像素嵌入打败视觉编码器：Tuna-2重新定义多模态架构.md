# 像素嵌入打败视觉编码器：Tuna-2 重新定义多模态架构

**日期**: 2026-04-28

---

论文 : Tuna-2: Pixel Embeddings Beat Vision Encoders for Multimodal Understanding and Generation链接 : https://arxiv.org/abs/2604.24763这篇论文干了一件挺疯狂的事——直接把 vision encoder 扔了，用最简单的 patch embedding 处理原始像素，结果发现在理解和生成任务上双双打爆那些带着预训练编码器的老架构。Tuna-2 不是 incremental 改进，而是一条技术路线的胜利： 端到端像素空间建模 。
## 问题在哪？为什么需要新方法？
现在的多模态模型（尤其是 unified multimodal models, UMMs）普遍面临一个结构缺陷： 编码器不匹配 。
早期方案（如 BAGEL、Ming-UniVision）采用 解耦表示 ——理解用 CLIP 这类 representation encoder，生成用 VQ-VAE/VAE。两套视觉表示，两个训练范式，天然存在对齐问题。
后来方案（如 Tuna、Show-o2）改用 统一表示 ——共享一个 vision encoder，一张图片编码一次，同时喂给语言头和生成头。听起来完美了？不，问题还在：
- pretrained vision encoder 的先天限制：固定输入分辨率、固定的归纳偏置（比如只关注语义忽略纹理细节）
- 无法端到端：编码器是预训练的，和下游任务存在 gap，不能从像素开始一起优化- 信息损失：VAE 压缩到 latent space 必然丢失细节，这对 fine-grained 理解是致命的最新的趋势已经露出端倪：vision-language 领域开始走向 encoder-free（Mono-InternVL、NEO），生成领域也在拥抱 pixel-space diffusion/flow matching（JiT）。那问题就来了—— 能不能把两者结合，彻底抛弃 vision encoder？
Tuna-2 的回答是：能，而且效果更好。
## 方法拆解：三层架构的逐步简化Tuna-2 的设计思路很清晰： 渐进式移除视觉编码器 ，直到只剩一个 transformer。
### 三层架构演进版本 VAE Representation Encoder Patch Embedding 核心能力 Tuna ✅ ✅ ❌ latent-space UMM Tuna-R ❌ ✅ (SigLIP-2) ❌ pixel-space + 编码器先验 Tuna-2 ❌ ❌ ✅ 纯 pixel-space end-to-endTuna-R 是关键中间态——去掉 VAE 后，视觉表示直接是 pixel-space feature maps（SigLIP-2 的视觉 token），然后用 flow matching 做生成。但 Tuna-R 仍依赖 SigLIP-2 的语义先验。
Tuna-2 更进一步： 完全移除表示编码器 ，只用 patchify layer 把 256×256×3 的图片变成 1024 个 patch tokens（每个 256-dim），直接和 text tokens 一起进 LLM（Qwen2.5-7B-Instruct）。 结构上回归本质 。
### Pixel-space 生成怎么搞？
没了 VAE latent，怎么训练 flow matching？他们用了 JiT 的 x-prediction + v-loss 范式：
xt = t×x1 + (1-t)×x0 // 线性插值构造 noisy samplexθ = πθ(xt, c, t) // 模型直接预测 clean imagevθ = (xθ - xt) / (1-t) // 转成 velocityLflow = ||vθ - (x1-x0)||²推理时用欧拉求解器：xt’ = xt + (t’-t)×vθ。 直接在像素空间做 rectified flow ——这个设计在工程上很干净，没有 latent decode 的额外步骤和损失。
### 掩码特征学习：应对像素空间的高维度Pixel-space 学习最大的问题是 冗余太多 。原始像素有 256×256×3=196,608 维，而 latent space 可能只有 256×16×16=65,536 或者更少。模型太容易作弊——通过插值平滑就能降低 loss，而不是真正理解语义。
解决方案是掩码 （类似 MAE）：
- 生成任务：随机 mask 一部分图像块，模型从部分观测的 noisy image 预测完整 clean image。逼模型学习用上下文推理被遮盖区域。
- 理解任务：在部分遮蔽的视觉输入下预测文本响应。这相当于给视觉理解加了 dropout，防止语言先验主导。
论文在表 6 验证了这个策略：对 Tuna-R 和 Tuna-2，加入 masking 后 OCRBench、MMVP、CountBench、GenEval 全面提升。 有趣的是，Tuna-2 收益更大 ——因为没有预训练编码器的先验缓冲，更依赖训练时的鲁棒表示学习。

## 工程启示：这方法到底能不能用？
### 1. 本地部署的潜力Tuna-2 架构极简：patch embedding + transformer decoder + flow matching head。没有独立编码器， 内存占用更低，加载更快 ——适合本地/边缘部署。
7B 模型加 patch embedding 层（约 10M 参数），总参数量可控。如果量化到 4-bit， 单卡 24GB 显存可能跑得动 ——比那些带着 400M+ ViT 的模型友好。
### 2. 微调和 SFT 更干净传统 UMM 微调痛苦在哪？ vision encoder 和 LLM 要对齐，需要 connector layer 训练、分阶段微调、小心别破坏 encoder 特征。
Tuna-2 完全端到端 ：输入 patch → 输出 text/image token，一个 loss 搞定。SFT 流程简单：50k steps 覆盖编辑、instruction 遵循、高质量生成即可。论文表 3 显示 SFT 后 Tuna-2 和 Tuna-R 生成差距几乎消失——说明 少量高质量微调就能补足 encoder-free 的生成短板 。
### 3. 数据工程的权重更高既然架构更简单， 数据质量和多样性就更加关键 。
论文用 550M image-text pairs（70% captioning + 30% generation）+ 20% text-only data。7:3 的 generation:understanding ratio 是 ablations 找到的最佳平衡点（图 5）。这对工程实践有直接指导： 多模态数据混合比例需要精细 tuning ，且生成任务对数据比例更敏感（MSE loss 波动更大）。
### 4. Masking 策略值得借鉴论文的 masking-based feature learning 并非必须，但能稳定提升性能。关键在于时机—— 不是从头 mask，而是在 pretraining 中后期（后 40%）加入 。这个 timing 很务实：先让模型学基础视觉-语言对齐，再用 masking 强化鲁棒性。
代码层面的实现也简单：随机选 15-30% 的 patches 替换成可学习的 mask token，然后正常计算 loss。相当于给视觉表征加了 dropout。
### 5. 分辨率与计算 trade-offTuna-2 在 256×256 下训练，表 5 的 rFID 0.93 比不过 512×512 的专用 VAE。这意味着： 像素空间学习对分辨率更敏感 ——更高分辨率需要更多计算来建模高维像素分布。
工程落地上，如果追求 SOTA 生成质量，可能仍需要 latent-space + VAE；但如果任务是 视觉推理为主、生成为辅 （如 agent 的视觉分析+简单编辑），Tuna-2 的架构更实用。
## 局限与后续方向论文没提太多局限，但从结果能看出几点：
-生成质量仍有差距：与 FLUX.1、SD3-M 等专用生成模型比，GenEval 的 object、color、position 等子项差 0.1-0.2。pixel-space flow matching 在高分辨率下挑战仍大。
-数据饥渴：图 6 显示 Tuna-2 需要更多数据才能追上 Tuna-R 的早期性能——encoder-free 的收敛速度慢于 encoder-based。这意味着预训练成本更高。
-任务特异性：在需要 world knowledge 的生成任务上，encoder-based 可能仍有优势；但在细粒度视觉推理上，encoder-free 已然领先。
后续方向论文提到了两点：
- 更大规模、更多样化的数据- 更高分辨率的像素空间训练更深层的可能性 ：把 Tuna-2 的架构和最新的 Mamba/SSM-based LLM 结合？或者用更强的 patch-level tokenizer（如 token 数更少的）来降低计算负担？这些都是工程上可以探索的。
## 总结：为什么说 Tuna-2 重要？
Tuna-2 不是「又一个 UMM」，而是 对统一多模态模型架构的一次根本性追问 ：我们真的需要 vision encoder 吗？
答案是： 对于理解任务，尤其需要细粒度视觉推理的场景，不需要。像素嵌入 + 端到端训练 + 掩码正则化，直接学出的视觉表征更强 。
这带来的工程启示很直接： 如果你的应用场景是视觉推理（agent 环境理解、文档分析、视觉 QA），优先考虑 encoder-free 架构；如果更看重生成保真度（艺术创作、广告设计），可能 latent-space 仍是更稳的选择 。
架构越简单，可解释性越强，可部署性越好。Tuna-2 证明——有时候，把复杂的模块扔掉，反而能走得更远。
