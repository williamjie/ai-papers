# SkillFlow：让Agent真正学会‘积累经验’

**日期**: 2026-04-21

---

论文 : SkillFlow: Benchmarking Lifelong Skill Discovery and Evolution for Autonomous Agents链接 : https://arxiv.org/abs/2604.17308我们常说 Agent 需要”举一反三”，但现实是：大多数 benchmark 都在考”开卷考试”。
给定技能，Agent 会用吗？这太简单了。真正的挑战是：Agent 能不能自己从踩过的坑里提炼出可复用的套路，并在下一个任务中用上？
中国科学技术大学团队最近发布的 SkillFlow benchmark，就是专门测这个的。166 个任务，20 个家族，要求 Agent 从零开始，边做边学，边学边修。
## 为什么现有 Benchmark 不够看？
目前的 Agent benchmark 有个共同毛病： 静态技能评估 。
你给 Agent 一个技能包，它能不能完成任务？能，说明模型强。但不能完成任务，你就不知道是模型笨，还是技能给得不对。
SkillFlow 的核心观点很简单：
真正的能力不是”使用现成技能”，而是”从经验中自我进化”。
为了测这个，作者设计了一个 Agentic Lifelong Learning 协议：
- Agent 从空技能库开始- 按难度递增顺序做任务- 每个任务做完后，根据执行轨迹（Trajectory）和评估反馈（Rubric），生成一个 Skill Patch（技能补丁）
- 补丁会增删改技能库里的东西- 下一个任务带着更新后的技能库继续做这不是简单的”把历史经验喂回去”，而是要求 Agent 自己决定： 什么经验值得存？怎么存？旧经验错了怎么办？
## 核心设计：DAEF——把业务逻辑抽成”工作流骨架”
SkillFlow 最聪明的设计是 Domain-Agnostic Execution Flow（领域无关执行流，DAEF） 。
什么意思？假设你有 20 个任务，看起来领域不同（金融、医疗、法律），但它们背后的 Agent 工作流是一样的：读取 → 检索 → 计算 → 验证 → 输出。DAEF 就是把具体业务细节（文件名、实体、业务语义）剥掉，只留下操作类型和依赖关系，形成一个 抽象工作流骨架 。
这样做的妙处在于：
- 跨领域可迁移：同一个 DAEF 可以实例化为不同领域的任务，技能可以在这些任务间复用- 难度可控：同一个 DAEF 下，可以通过改变数据复杂度、约束条件来制造难度梯度- 避免”伪智能”：Agent 不能靠 memorize 答案，必须理解工作流本身的模式任务构造流程也很讲究：
- 从 SkillsBench 和 GDPval 精选 64 个种子任务- 从 8000+ 开源技能中匹配 2318 个高质量技能- 用 双 Agent 协作：Architect Agent（基于 GPT-5.3-Codex）负责生成任务，Critic Agent（基于 Claude Opus 4.6）负责审查- 人类审核四个维度：指令泄露、逻辑合理性、难度梯度、环境正确性最终产出 20 个任务家族，每个家族 8-9 个任务，共 166 个可运行任务。
## 实验结果：强者愈强，弱者越乱作者测试了 11 个模型变体，结果非常有意思，也让人有点扎心。

但其他模型呢？

-Opus 4.6 是唯一稳定进化的模型。即使把完整历史对话直接当上下文喂给它，完成率也只有 51.04%，远低于技能进化协议的 71.08%。说明进步确实来自”技能结构化”，而不是”上下文变长”。
-错误技能会带来系统性漂移。一旦 Agent 写入了错误的技能，后续任务会继承同样的 flawed abstraction，局部错误变成序列级模式。这解释了为什么 GPT 5.3 Codex 和 Qwen 系列反而退化了——技能库里有毒。
-技能膨胀是弱模型的典型死法。Qwen 和部分 MiniMax 模型的问题不是”不会写技能”，而是”写了太多碎片化技能”。每个任务都总结一个新技能，技能库越来越大，但没有任何一个技能被反复打磨。论文称之为 fragmentation through skill inflation（通过技能膨胀导致的碎片化）。
-关键差距不在”写技能”，而在”修技能”。大多数模型都能完成任务后生成一个技能，但真正拉开差距的是：能否识别错误技能、能否修正它、能否在后续任务中验证修正效果。
## 工程启示这篇论文对 Agent 工程有几个实实在在的启示：
1. 技能库要”小而精”，不要”大而全” 。Opus 4.6 最终技能库只有 1.05 个技能（均值），但效果最好。Codex 也很擅长把变体合并到一个核心技能里，虽然它整体完成率低，但技能管理策略是对的。 合并优于扩张 。
2. 技能修复比技能生成更重要 。不要只关注”如何让 Agent 生成好技能”，更要关注”如何让它发现并修复坏技能”。这可能是当前 Agent 系统最大的短板。
3. 结构化经验 > 原始历史 。直接把对话历史当上下文喂给模型，效果远不如把经验提取为结构化技能。这是因为结构化技能消除了无关信息，提供了可复用、可修改的程序化知识。
4. 难度梯度很重要 。SkillFlow 的任务按难度排序，这让 Agent 的能力可以渐进式积累。如果任务顺序随机或跳跃，技能复用几乎不可能。
## 局限与展望论文也坦诚了一些局限：
- 家族内重置：每个任务家族结束时技能库会重置，没有评估跨家族的泛化能力。这避免了技能检索的混淆，但也让评估相对保守。
- 单一评估顺序：任务按固定顺序执行，没有评估 Agent 在不同顺序下的适应性。
- 技能检索机制缺失：当前协议中技能使用由 Agent 原生 harness 决定，没有独立的检索模块。扩展到开放环境时，如何高效检索相关技能是一个待解决的问题。
## 结语SkillFlow 揭示了一个残酷的事实： 大多数 Agent 还不会”真正学习” 。它们能完成任务，能生成技能，但不能稳定地通过迭代更新实现自我进化。
真正强大的 Agent，不是那个一开始就什么都会的，而是那个犯过错、修过 bug、积累了经验，并且能把经验变成可复用知识的。
这才是 Agent 走向通用的关键一步。
