# 别用AdamW了，优化器也要看层说话

**日期**: 2026-05-20

---

论文 : Symmetry-Compatible Principle for Optimizer Design: Embeddings, LM Heads, SwiGLU MLPs, and MoE Routers链接 : https://arxiv.org/abs/2605.18106还在给整个模型统一喂 AdamW？这篇论文直接掀了桌子： 优化器不应该是一刀切的，而应该像建筑工地的不同工具一样，针对不同层的几何结构“量体裁衣”。
这篇来自 UPenn 的工作提出了一套“对称性兼容”的优化器设计原则。核心观点很硬核：神经网络的不同层（Embedding、MLP、MoE Router）拥有不同的数学对称性，而传统的逐元素自适应优化器（Coordinate-wise Adaptive Optimizers）完全无视了这些结构，导致几何上的错位。
### 痛点：几何盲视的代价Adam、RMSprop 这些经典优化器，本质上是把权重矩阵拉平成一个大向量，然后对每个坐标独立更新。这带来一个致命问题： 它假设矩阵里的每个元素都是独立的。
但在现代 LLM 中，权重矩阵往往具有强烈的结构特征：
- 普通线性层：具有双正交对称性（Bi-orthogonal symmetry）。
- Embedding/LM Head：词表维度是离散的排列对称，隐藏层维度是连续的旋转对称。
- SwiGLU MLP：中间神经元具有排列不变性。
- MoE Router：专家之间可互换，且 Softmax 对整体偏移量不敏感。
用无视结构的 AdamW 去更新这些具有强结构的矩阵，就像用一把万能钥匙去开所有锁——能开，但效率极低，且容易破坏原有的几何特性。
### 方法拆解：让优化器“懂”对称性论文的核心 Insight 是： 优化器的更新规则 U\mathcal{U} 必须与参数块的对称群 GG 保持等变（Equivariant）。 即 U(g⋅D)=g⋅U(D)\mathcal{U}(g \cdot D) = g \cdot \mathcal{U}(D) D ) = g ⋅ U ( D ) 。
基于此，作者为不同类型的层推导了专属优化器：
-普通线性层/Attention：
对称性：双正交对称。
- 方案：谱优化器（Spectral Optimizers）。如 Muon、Scion、PolarGrad。它们通过极分解提取正交因子，保持奇异值结构。
-Embedding & LM Head：
对称性：左排列（词表）+ 右正交（特征）。
- 方案：
Right-Spectral：只计算较小的右 Gram 矩阵 DTDD^T DD 的谱更新，避免大词表带来的计算灾难。
- Row-Norm：基于行范数的自适应更新。
- Hybrid：混合上述两者。
- 直觉：词表维度巨大但稀疏，特征维度较小且稠密。混合更新既照顾了词表的离散性，又利用了特征空间的几何结构。
-SwiGLU MLP：
对称性：中间神经元的排列对称。
- 方案：Gate/Up 投影使用行感知（Row-aware）更新，Down 投影使用列感知（Column-aware）更新。
- 直觉：MLP 的中间维度只是特征变换的通道，神经元顺序无关紧要，因此更新规则应允许行/列的排列不变性。
-MoE Routers：
对称性：专家排列 + 共享 Logit 偏移不变性。
- 方案：Centered Row-Norm 或 Left-Spectral。
- 直觉：去除所有专家共同的偏移分量，只更新专家间的相对差异，这符合 Softmax 的数学本质。
### 关键结果：稳定且有效作者在 Qwen3-0.6B、Gemma 3 1B、OLMoE-1B-7B 以及 downsized gpt-oss 上进行了预训练实验。结论非常清晰： 对称性兼容的优化器堆栈（Optimizer Stack）在验证集损失和训练稳定性上均优于纯 AdamW。
- Dense 模型：在 Qwen3-0.6B 风格模型上，混合更新（Hybrid）带来了可见的验证损失降低；在更大的 Gemma 3 1B 上，增益更加显著。
- MoE 模型：这是重头戏。在 downsized gpt-oss 的预训练中（见图 2），使用 RowNormM + LeftPolarGradM（针对 Router 的对称性兼容更新）的配置，不仅最终验证损失最低，而且显著减少了训练过程中的 Loss Spike（损失尖峰）。
- 对比基线：
纯 AdamW：基准线，收敛慢，波动大。
- RowNormM + AdamW（仅 Router 用对称优化）：有改善，但不如全栈兼容。
- RowNormM + LeftPolarGradM：最佳表现，验证损失曲线平滑且更低。
### 工程启示这篇论文对工程师最大的价值在于 打破了“一个优化器走天下”的惯性思维 。
- 分层配置优化器：不要再用一个 AdamW 实例管理所有参数。在代码中，可以根据参数名称（如 embed_tokens, lm_head, gate_proj, router）注册不同的优化器步骤。
- MoE 训练稳定性：如果你正在训练 MoE 模型，Router 层的优化器选择至关重要。使用中心化行范数（Centered Row-Norm）或左谱更新，能有效抑制训练不稳定。
- 计算效率：对于超大词表的 Embedding/LM Head，使用右谱更新（Right-Spectral）比全矩阵谱分解更高效，因为它只涉及隐藏维度的 Gram 矩阵。
### 局限与展望作者也坦诚，这并非在所有 regime 下都绝对优于坐标式优化器。目前的实验主要集中在预训练阶段，且模型规模尚在 1B-7B 级别。此外，实现这些等变优化器需要更复杂的代码逻辑（如极分解、行范数计算），对工程实现有一定门槛。
但方向是明确的： 未来的优化器将是“结构化”的，而非“扁平化”的。 随着模型架构日益复杂，理解每一层的几何对称性，将成为提升训练效率的关键钥匙。
