# 打破天花板：CoPD如何让多能力模型超越领域专家

**日期**: 2026-05-01

---

论文 : Co-Evolving Policy Distillation链接 : https://arxiv.org/abs/2604.27083如果你还在纠结多模态模型训练该用Mixed RLVR还是两阶段蒸馏，这篇论文可能会颠覆你的认知。作者指出， 现有的两种主流范式本质上都在”浪费信号” ：一个被能力冲突拖累，一个因行为漂移失效。而他们提出的CoPD，直接把这个问题升维成”协同进化”。
## 问题与动机：为什么两阶段蒸馏也翻车？
后训练领域有个共识：想整合多种能力？先各自用RLVR训专家，再用OPD蒸馏合并。听起来合理，但作者做了个实验，发现事情没那么简单。
他们在论文里定义了一个关键指标： top-k token overlap （公式6），用来量化教师和学生在策略轨迹上的行为相似度。结果发现（图2）： OPD带来的性能增益和这个overlap高度正相关 （线性相关系数r=0.89，R²=0.79）。也就是说，教师和学生行为越像，蒸馏越有效。
问题来了：按两阶段流程，专家训到收敛后，再拿初始模型当学生做蒸馏，这时两者行为差异已经很大了。图2(c)(d)显示，随着RLVR训练进行，专家与初始模型的top-k overlap单调下降，对称KL divergence上升一个数量级。 到蒸馏开始时，教师已经”漂”得太远，学生根本吸收不了 。这就是为什么表1里V→T蒸馏后，文本推理从Text-Expert的57.89掉到56.09，损失了近2个点。
与此同时，Mixed RLVR也好不到哪去。表1显示，Mixed RLVR的文本推理只有55.76，图像推理54.88，两者都低于各自专家（57.89和55.76）。作者归结为 能力冲突代价Φ(D1,D2) ：不同能力需要不同的优化方向，混合训练时梯度互相打架， Eq.(2)的 Umix = X - Φ 里，Φ就是那个负数项。
所以困境很清晰：
- Mixed RLVR：满信号但冲突代价高- Static OPD：无冲突但吸收效率η(Olow)太低- 两者都离理论最优解 η(Omod) · X 差得远## 方法拆解：为什么不间断地互训？
CoPD的核心思想简单得惊人： 别等专家练完再教，让他们边练边互相教。 更关键的是，这种”教”是双向的、周期性的。
具体来说，训练流程在每周期内交替两个阶段：
Phase I：Branch-specific RLVR像常规RLVR一样，每个分支在自己的数据上训练SRL步。这时分支间差异会拉大，为后续蒸馏提供”新知识”。
Phase II：Mutual OPD每个分支在另一个分支的数据上生成rollout，并从那里获得token级别的监督信号。注意这里不是冻结的教师，而是 活生生的、正在进化的另一个分支 。公式(8)定义了跨分支的token advantage：δ = log π_teacher - log π_student。
关键的insight是： RLVR和Mutual OPD形成互补闭环 。RLVR拉开差距（让蒸馏有东西可传），互训拉近行为（让东西可吸收）。因为交替足够频繁（SRL:SOPD=1.5:1最佳，图4(c)），gap永远不会大到无法吸收，也不会小到无信息量。
一个很重要的设计细节： 所有分支始于同一基座π0，互训时保持双向监督 。这保证了参数不会大幅发散，最终可以直接通过简单参数平均合并（Merge）得到统一模型——而不需要一个额外的蒸馏阶段。

1. 别一次性训到底再蒸馏如果你正在训练多模态或multi-task模型，传统的”先训后蒸”可能浪费了至少10%-20%的潜力。考虑把蒸馏信号穿插在训练过程中，特别是当不同任务差异较大时。
2. 行为距离是比loss更直接的监控指标top-k token overlap计算很简单（公式6），在rollout时就能算。当branch间overlap低于0.90时，可能需要增加互训频率。
3. 协同进化能突破单领域天花板最震撼的结论是：CoPD不仅整合了能力，还 让整合后的模型超越了原始专家 。表1里，CoPD文本58.76 > Text-Expert 57.89，图像56.97 > Image-Expert 55.76。这意味着 跨能力学习产生了1+1>2的协同效应 。
4. 训练拓扑可以更灵活两分支用双向互训，三分支用hub-and-spoke（文本作hub），N分支理论上也可扩展。关键是要保持”活教师”状态。
对于本地部署或agent场景，这条路径也值得参考：与其训练一个”全能但平庸”的模型，不如并行训练多个专业化分支，再用CoPD风格的机制融合——既能保持各自优势，又能获得跨域泛化。
## 局限与展望论文没提但值得思考的几点：
计算成本 ：CoPD需要并行训练多个分支，虽然总步数与Static OPD相当（保证数据吞吐量一致），但内存占用和实际训练时间肯定更高。对于资源受限的场景，可能需要权衡。
分支数量扩展性 ：三分支时他们用了hub-and-spoke拓扑（文本作central hub）。如果分支数进一步增加，如何设计互训拓扑而不爆炸？可能需要分层或稀疏互训。
任务相关性要求 ：CoPD有效的一个前提是分支间有潜在的协同效应（文本和图像推理确实相关）。如果强行把两个完全无关的任务放一起，互训可能产生负迁移。
离线场景适配 ：论文假设有各能力的可验证 reward 函数（verifiable reward）。如果某些能力只有人工标注的偏好数据，如何适配CoPD的RLVR-OPD交替流程？这需要额外设计。
## 结语核心评价：这是一篇 把范式问题讲透 的论文。它没有堆砌复杂loss函数，而是从行为距离这一根本矛盾出发，用”边练边教”的朴素思路解决了”教不动”的难题。
实践建议：如果你在折腾多模态/多任务后训练，值得复现一下CoPD。特别是当你发现Mixed RLVR效果平平时，别急着调数据比例，先检查branch间行为一致性——也许你的专家们已经”鸡同鸭讲”了。
