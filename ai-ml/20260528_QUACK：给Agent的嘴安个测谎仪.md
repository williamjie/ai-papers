# ⭐⭐⭐⭐ QUACK：给 Agent 的嘴安个测谎仪

**日期**: 2026-05-28

---

论文 : QUACK: Questioning, Understanding, and Auditing Communicated Knowledge in Multimodal Social Deduction Agents链接 : https://arxiv.org/abs/2605.27068做多智能体（Multi-Agent）系统的同学都知道，现在的 Agent 赢比赛靠的是运气还是实力，光看胜率根本看不出来。QUACK 这篇论文干了一件很硬核的事：它不只让 VLM 玩社交推理游戏，还给它们装了个“测谎仪”，逐句审计 Agent 说的话是不是瞎编的。这对我们排查 Agent 幻觉、优化长程记忆有直接的工程参考价值。
### 痛点：胜率掩盖了推理崩塌现有的社交推理基准（如狼人杀、Among Us）大多只关心结果：谁赢了？谁被投出去了？但这有个巨大的盲区。一个 Agent 可能因为队友失误而惨败，尽管它的逻辑完全自洽；反之，它也可能靠胡言乱语误导对手从而获胜。更致命的是，现有环境大多是纯文本的，缺乏“可回溯的真实世界状态”。没有 Ground Truth（地面真值），我们就无法区分 Agent 是在进行严密的逻辑推理，还是在基于概率生成看似合理的废话。
QUACK 的核心 Insight 在于： 社交推理游戏天然具备可恢复的 Ground Truth 。引擎日志记录了每一 tick 每个 Agent 的位置、动作和视野。这意味着，Agent 说的每一句话（“我在仓库”、“我看见他杀人了”），理论上都可以被精确验证。
### 方法拆解：三层审计框架QUACK 没有停留在环境搭建上，而是提出了一套三层评估框架（Three-tier Evaluation Framework）：
- Tier 1：游戏结果。传统的胜率、存活率。
- Tier 2：行为轨迹。从日志重构 Agent 的实际移动路径、任务效率等。
- Tier 3：语句级一致性验证（核心贡献）。这是本文的杀手锏——Statement Verification Pipeline。
这个 Pipeline 的工作流非常工程化：
- Claim Extraction（主张提取）：利用 LLM 将 Agent 的自由对话拆解为结构化主张，分为五类：位置（LOCATION）、目击（SIGHTING）、活动（ACTIVITY）、指控（ACCUSATION）和辩护（DEFENSE）。
- Claim Verification（主张验证）：将提取的主张与引擎日志中的真实轨迹进行比对。系统会自动标记出四种典型的“接地失败”（Grounding Failures）：
空间幻觉：声称自己在某处，但日志显示不在。
- 无依据指控：指控某人，但没有任何观察证据支持。
- 欺骗崩塌：冒充者（Duck）说了极易被证伪的假话，而非精心设计的谎言。
- 言行不一：声称的任务或路径与实际执行的动作冲突。
### 关键结果：最强模型也在“胡扯”
QUACK 在 270 场游戏中评估了 GPT-5.5、Gemini-3.1-Pro 和 Claude-OpuS-4.7 三款前沿 VLM。数据揭示了令人不安的事实： 即使是最强的模型，其语言也严重脱离感知现实。
指标 全局平均值 含义解读 空间幻觉率 15.1% 约 7 句位置/目击陈述中就有 1 句是假的。Agent 记错了自己或他人的位置。 无依据指控率 53.5% 超过一半的指控没有任何观察证据支撑。Agent 在“盲猜”而非推理。 欺骗崩塌率 22.1% 冒充者说了近 1/4 的可验证假话，且多为低级谎言（如声称看见了已死之人）。 谎言检测率 75.2% 当冒充者撒谎时，好人阵营有 75.2% 的概率将其投出。说明谎言虽多，但往往很拙劣。
特别值得注意的是 GPT-5.5，作为好人阵营胜率最高（81.1%）的模型，它的空间幻觉率依然高达 16.4% ，无依据指控率达 54.5% 。这说明 高胜率并不等同于高可靠性 ，Agent 可能在错误的推理基础上碰巧赢了。
### 工程启示：如何落地？
- 日志即真理（Log as Truth）：在构建多智能体系统时，务必保留细粒度的执行日志。不仅是动作结果，还要包括感知快照。这是后续进行自动化审计（Automated Auditing）的基础设施。
- 从结果评估转向过程评估：不要只盯着 Win Rate。引入类似 QUACK 的“主张验证”模块，可以帮你定位 Agent 是“没看见”、“看见了但忘了”还是“看见了但在瞎编”。这对于调试长程记忆（Long-horizon Memory）和 RAG 检索质量至关重要。
- 警惕“无依据指控”：53.5% 的无依据指控率表明，当前 VLM 在缺乏证据时倾向于强行输出结论。在工程上，可以通过 Prompt 约束或后处理过滤，要求 Agent 在做出判断时必须引用具体的日志片段（Evidence），否则视为无效输出。
### 局限与展望QUACK 目前仅在一个 10 房间、6 人局的地图上进行测试，且主要依赖 LLM 进行主张提取（虽然人工验证准确率高达 99.5%，但仍存在保守漏检的可能）。此外，它尚未剥离视觉模态的影响，未来可以进一步探究是“看不懂图”还是“记不住事”导致了幻觉。
总之，QUACK 提供了一套标准化的“测谎”工具链。对于任何希望提升 Agent 推理透明度和可靠性的团队来说，这套验证 Pipeline 的思路值得直接复用。
