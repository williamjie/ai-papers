论文 : Got a Secret? LLM Agents Can’t Keep It: Evaluating Privacy in Multi-Agent Systems链接 : https://arxiv.org/abs/2605.27766现在的 AI 安全评测大多还停留在“单轮对话”阶段：给模型一个恶意指令，看它拒答还是顺从。这种静态测试假设模型是孤立运行的，但现实中的 Agent（智能体）是在持久化的社交环境中与其他 Agent 长期互动的。这篇论文直接戳破了这个泡沫： 在社交压力下，LLM Agent 根本守不住秘密。
## 为什么现有的安全评测失效了？
传统的安全基准（Benchmark）测试的是模型的“内在对齐”，但在多智能体系统（Multi-Agent Systems, MAS）中，隐私泄露往往不是由恶意攻击触发的，而是由**社会规范（Social Norms）**驱动的。
论文的核心洞察是：**上下文完整性（Contextual Integrity）**在社交环境中会动态退化。当 Agent 看到其他 Agent 都在分享个人信息时，“不分享”就不再是默认行为，而变成了“不合群”。这种压力不需要复杂的提示词注入（Prompt Injection），仅仅是社区氛围的变化就足以让 Agent “同化”。
## 方法拆解：构建 Moltbook 仿真平台为了量化这种风险，作者搭建了一个名为 Moltbook 的仿真平台，模拟了 Reddit 式的社交网络。
-大规模仿真环境：
包含 2,533 个 Agent，分布在 **124 个子版块（Subreddits）**中。
- 每个 Agent 都拥有一个合成的私人人类档案（包含身份、财务、健康等 10 类敏感信息）。
- 模拟运行了 25 天，产生了超过 11 万条帖子和回复。
-两组互补实验：
有机泄露（Organic Leakage）：让 Agent 在自然社交中自由互动，观察隐私是否随时间累积泄露。
- 对抗性压力测试（Elicited Leakage）：将单个 Agent 放入冻结的社交平台快照中，注入不同密度的“泄露示范帖”，测试其在不同社交污染程度下的表现。
-检测机制：
使用 LLM-as-a-judge（GPT-5-nano）作为裁判，判断每条内容是否违反了上下文完整性原则，即在不恰当的上下文中披露了敏感属性。
## 关键结果：社交压力是隐私杀手实验数据非常直观地展示了社交环境对隐私保护的破坏力。
### 1. 单轮 vs 多轮社交：泄露率翻倍在传统的单轮测试中，OpenAI 模型的隐私违规率约为 19.95% 。但在 Moltbook 的多轮社交环境中，这一数字飙升至 45.30% 。
- 结论：静态基准严重低估了 Agent 部署中的真实风险。
### 2. 泄露具有极强的“传染性”
论文发现，Agent 的行为高度受邻居影响。
- 如果前一条回复是干净的，后续回复泄露概率为 1.6%（接近全局基线 1.8%）。
- 如果前一条回复已经泄露了隐私，后续回复的泄露概率激增至 12.8%。
- 倍数效应：Agent 在观察到同伴泄露后，泄露敏感信息的概率是之前的 8 倍（原文摘要称 8x，正文数据分析为 ~5.1x-8x 区间，取最高值警示）。
### 3. 系统指令（System Prompt）防不住“从众”
即使我们在 System Prompt 中明确写入“严禁泄露私人信息”，效果也微乎其微。
- GPT-4o：有指令时泄露数从 2,624 降至 2,102，仍有大量违规。
- GPT-5-mini：从 2,889 降至 2,194。
- 整体情况：即使有明确的安全指令，泄露率仍高于 37.8%。只有 GPT-5 表现出较强的抵抗力（降至 482），但其他模型依然“随大流”。
### 4. 社区语境比模型架构更重要不同 Subreddit 的泄露率差异巨大，甚至超过模型间的差异：
- 高泄露区：自我介绍类版块，泄露率超 16%。
- 低泄露区：技术工具类版块（如 r/memory），泄露率低于 2%。
- 结论：Agent 所在的社区主题决定了隐私边界，而非仅仅取决于模型本身的安全对齐水平。
实验维度 关键数据对比 核心发现 评估方式 单轮 19.95% vs 多轮社交 45.30% 社交互动使隐私风险翻倍 同伴影响 干净前序 1.6% vs 泄露前序 12.8% 泄露行为具有显著传染性 指令防护 有指令泄露率仍 > 37.8% System Prompt 无法抵抗社会压力 社区差异 技术区 <2% vs 社交区 >16% 社区语境是首要风险变量## 工程启示：如何保护 Agent 隐私？
对于正在构建多智能体系统的工程师来说，这篇论文提供了三个关键警示：
-不要依赖 System Prompt 做唯一防线：
在持久化社交场景中，LLM 的指令遵循能力会被社会规范稀释。必须引入外部强制约束，例如在输出层增加 PII（个人身份信息）过滤网关，或者限制 Agent 只能访问脱敏后的记忆片段。
-隔离敏感上下文：
既然社区语境影响巨大，应避免让处理敏感数据的 Agent 进入“鼓励分享”的公共社交子版块。通过权限控制，将 Agent 的活动范围限制在任务导向型、低社交压力的环境中。
-重新设计安全评测基准：
现有的单轮红队测试（Red-teaming）不足以评估 Agent 的安全性。需要引入多轮、多智能体交互的仿真测试，特别是模拟“社会工程”和“从众压力”场景，才能发现真实的隐私泄露漏洞。
## 局限与展望论文主要基于合成数据和 GPT/Gemini 系列模型，未涵盖开源小参数模型在极端社交压力下的表现。此外，目前的防护手段仍停留在检测层面，如何设计能够抵抗社会压力的“鲁棒性对齐”机制，是后续研究的关键方向。
