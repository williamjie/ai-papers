# ⭐⭐ RLVR 新思路：成败分治的自蒸馏 H²SD

**日期**: 2026-07-22

---

论文 : H^2SD: Hybrid Hindsight Self-Distillation链接 : https://arxiv.org/abs/2607.18955在强化学习（Reinforcement Learning, RL）优化大模型推理能力的当下，我们常面临一个尴尬局面：要么奖励太稀疏导致训练震荡，要么强行蒸馏导致信息泄露。这篇来自上海人工智能实验室等机构的论文 H²SD 提供了一个极其优雅的解法： 根据轨迹成败，动态切换“微调力度”与“方向修正” 。
### 现有方案的痛点：尺度的失衡目前的 RLVR（可验证奖励强化学习）主要依赖 GRPO 等算法，它们给整个回答序列打一个标量分数。这导致严重的信用分配问题——模型不知道具体是哪个 Token 导致了成功或失败。
为了解决稀疏监督，On-Policy Self-Distillation (OPSD) 引入了“特权信息”（如正确答案），让模型自己教自己。但这有个致命缺陷：直接匹配分布容易导致 信息泄露 ，且训练极不稳定。随后的 RLSD 方法试图通过仅调整更新幅度来稳定训练，但它放弃了对错误路径的显式方向修正，导致纠错能力不足。
简而言之，OPSD 太激进容易崩，RLSD 太保守纠不动错。H²SD 的核心 Insight 就是： 成功的路径不需要改方向，只需要强化关键 Token；失败的路径必须给明确的方向指引。
### H²SD 方法拆解：成败分治策略H²SD 框架将学生模型生成的轨迹分为两类，分别采用不同的蒸馏策略：
-成功轨迹（Success Path）：幅度调制（Magnitude Modulation）
逻辑：既然答案对了，说明推理方向没问题。此时引入 Teacher 的目的不是让它“重写”答案，而是识别出哪些 Token 对正确性贡献最大。
- 操作：Teacher 接收正确的学生回答并附带“重述（Rephrase）”指令。利用 Teacher 对原 Token 的概率分布，仅调整 RLSD 中的更新权重，不改变梯度方向。这保留了奖励信号的方向性，同时细化了 Token 级的信用分配。
-失败轨迹（Failure Path）：反向 KL 散度修正（Reverse KL Correction）
逻辑：答案错了，说明推理路径偏离。此时仅靠惩罚（Negative Reward）不够，必须告诉模型“正确的路在哪”。
- 操作：Teacher 接收包含关键步骤的 Hint（由更强模型生成），计算学生分布到 Teacher 分布的反向 KL 散度。这为错误轨迹提供了明确的分布级修正方向。
⚠️ 关键细节 ：为什么成功路径要用“重述”指令？
实验发现，如果直接用外部 Hint 去匹配成功路径，可能会因为推理风格不同导致过度约束（Over-constraint）。让学生“重述”自己的正确答案，既能去除冗余，又能保持原有推理逻辑的一致性。
### 实验数据：全面碾压基线作者在 Sudoku、Calcudoku 和 Arrow Maze 等复杂逻辑推理基准上进行了测试。结果非常具有说服力：

消融实验进一步验证了“分治”的必要性：如果反过来（成功用 KL，失败用幅度），性能会暴跌至低于基线模型，且策略熵迅速坍塌，导致探索能力丧失。
### 工程启示与落地建议- Hint 的质量决定上限：H²SD 依赖外部强模型生成包含中间步骤的 Hint。在本地部署时，如果无法接入更强模型，可以使用“兄弟解法（Sibling Solution）”，即利用同批次中验证正确的其他采样作为 Teacher 信号。实验显示，Sibling Solution 也能带来显著提升（Sudoku-6x6 达 61.75%），虽略低于外部 Hint，但工程成本更低。
- 避免过度蒸馏：对于已经成功的样本，不要盲目追求分布对齐。H²SD 的成功证明，“少即是多”——在方向正确时，仅做幅度加权比强行对齐分布更稳定、更高效。
- 效率优势：Figure 3 显示，H²SD 在达到最高准确率的同时，生成的 Token 数量最少。这意味着它不仅更准，而且推理成本更低，非常适合对延迟敏感的生产环境。
### 局限与展望尽管 H²SD 表现优异，但它仍依赖“可验证奖励”（Verifiable Rewards）。对于数学、代码等客观题效果显著，但在开放域对话或主观创作任务中，缺乏明确的对错判断，其“成败分治”机制将难以直接应用。未来如何结合过程奖励模型（Process Reward Model, PRM）来扩展其适用范围，是值得探索的方向。
