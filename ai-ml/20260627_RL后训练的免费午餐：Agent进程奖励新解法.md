论文 : Neglected Free Lunch from Post-training: Progress Advantage for LLM Agents链接 : https://arxiv.org/abs/2606.26080做 Agent 最头疼的是什么？不是模型不会用工具，而是你不知道它每一步做得对不对。现有的进程奖励模型（Process Reward Models, PRMs）在数学推理上表现不错，但在多轮交互、状态复杂的 Agent 场景下，标注成本高到离谱，且泛化性极差。
这篇论文给出了一个极具工程价值的洞察： 你不需要专门训练 PRM 。强化学习（RL）后训练过程中产生的策略变化，本身就蕴含了完美的进程级评分信号。作者称之为“进度优势”（Progress Advantage），它完全免费、无需标注，且效果吊打许多专用奖励模型。
### 痛点：为什么 Agent 的 PRM 这么难搞？
传统的 PRM 依赖蒙特卡洛估计或人工标注来获取步骤级反馈。但在 Agent 场景下，这两个路都走不通：
- 不可逆性：发邮件、删文件等操作无法回溯，导致无法进行多次 Rollout 来估算价值。
- 随机环境：外部工具返回的结果是随机的，破坏了确定性 MDP 的假设，使得基于概率比的隐式奖励推导失效。
结果就是，最需要细粒度反馈的 Agent，恰恰是最难获得这种反馈的系统。
### 核心 Insight：从 Reward 转向 Advantage论文的核心突破在于理论视角的转换。
在确定性环境中，策略与参考策略的对数概率比可以直接恢复出精确的奖励（Reward）。但在随机 MDP 中，由于环境转移的不确定性，这个等式不再成立，会残留无法消除的价值函数项。
关键直觉 ：既然无法恢复绝对奖励，那就去恢复 优势函数（Advantage Function） 。
优势函数衡量的是“某个动作比当前状态下的平均动作好多少”。论文证明了，在 KL 正则化的 RL 目标下，最优策略与参考策略的对数概率比，恰好等于最优优势函数：

### 实验结果：免费午餐真香吗？
作者在四个基准测试（BFCLv4-MT, WebShop, AgentDojo, τ2\tau^2 -bench）上验证了该方法，对比了多种基线。
1. 推理时扩展（Test-time Scaling）
在 Best-of-8 采样中，利用进度优势选择最佳轨迹：
- Qwen3.5-9B：平均成功率达到 62.1%。
- 对比基线：显著优于 Self-Certainty (51.5%) 和 DeepConf (55.8%)。
- 甚至超越专用模型：在部分任务上超过了经过专门训练的 WildReward-8B 和 ThinkPRM。
2. 不确定性量化（Uncertainty Quantification）
预测轨迹最终是否成功（AUROC 指标）：
- 在 τ2\tau^2-Airline 任务中，Gemma4-4B 使用进度优势达到了 0.865 的 AUROC。
- 相比之下，Self-Certainty 仅为 0.840，而专用的 ThinkPRM-7B 低至 0.478。
3. 失败归因（Failure Attribution）
定位多智能体系统中的关键错误步骤：
- 进度优势的表现接近专门为此任务训练的 AgenTracer，远优于预训练奖励模型。
### 工程启示：如何落地？
- 零成本集成：你不需要收集数据、不需要微调新模型。只要你有 RL 后的 checkpoint 和对应的 base/sft checkpoint，就能立即计算进度优势。
- 聚合策略至关重要：Token 级别的优势需要聚合到 Step 或 Trajectory 级别。论文发现，不同任务适合不同的聚合方式（如 Best-of-N 用 Mean-Min，UQ 用 Max-Mean），需要根据场景调优。
- 参考模型的选择：πref\pi_{ref}​ 不能太近也不能太远。太近信号弱，太远则被分布差异主导。论文建议可以尝试策略合并（Policy Merging）来构造更优的参考策略。
### 局限与思考虽然效果惊艳，但该方法依赖于 RL 训练的质量。如果 RL 过程本身没有学到有效的策略区分度，进度优势也会失效。此外，对于非 KL 正则化或纯裁剪基线算法，其理论保证稍弱（尽管论文证明了局部近似成立）。
总的来说，这是一篇典型的“把基础理论吃透后反哺工程”的好文。它提醒我们，在追求复杂的新架构之前，先看看手头已有的 RL 产物里是否藏着被忽视的金矿。
