# ⭐⭐⭐½ 打通数学知识孤岛：TheoremGraph 架构解析

**日期**: 2026-07-01

论文 : TheoremGraph: Bridging Formal and Informal Mathematics链接 : https://arxiv.org/abs/2606.25363数学界长期存在一个尴尬的割裂：非正式论文（Informal）引用的是整篇文档，而形式化证明库（Formal，如 Lean）记录的则是细粒度的声明级依赖。这种颗粒度错位导致知识图谱无法互通。TheoremGraph 试图通过统一的语义空间，将这两座孤岛连接起来。
对于正在构建数学 Agent 或自动化形式化系统的工程师来说，这篇论文的价值在于它提供了一套现成的、可落地的“跨模态”对齐基础设施。
### 为什么需要这个？
现有的数学信息检索（Math IR）大多停留在关键词或公式层面。LeanSearch v2 虽然强大，但主要服务于 Lean 社区内部。当研究者试图从自然语言论文中找到对应的形式化定理时，往往面临“找不到”或“找不准”的困境。
TheoremGraph 的核心洞察是： 依赖关系（Dependency）不仅是数学逻辑的骨架，更是语义检索的最佳锚点。 它不满足于简单的文本相似度，而是构建了包含 1170 万条非正式声明和 38.8 万条形式化声明的统一图谱。
### 核心方法拆解论文的方法论可以概括为三个步骤：提取、嵌入、桥接。
1. 多源依赖提取（Extraction）
- 非正式侧：从 arXiv 解析出 1170 万条定理环境，利用确定性规则（如 \ref）和启发式方法提取了 1830 万条有向依赖边。
- 形式化侧：开发了 LeanGraph，直接基于 Lean 4 的内核 API 提取编译后的类型检查依赖。这比源码解析更准确，因为它能区分结构继承、签名依赖和证明项依赖等六种语义类型。
2. Slogan 生成与嵌入（Embedding）
这是桥接的关键。论文没有直接使用原始 LaTeX 或 Lean 代码，而是让 LLM（Qwen3-235B）为每个声明生成一句简洁的自然语言“标语”（Slogan）。
- 设计直觉：Slogan 剥离了具体的符号表示差异，保留了核心数学语义。
- 技术实现：所有 Slogan 被嵌入到 R4096 向量空间，并存储在 pgvector 中，使用 HNSW 索引加速检索。
3. 跨形式化桥接（Bridging）
通过计算非正式声明与形式化声明在共享向量空间中的余弦相似度，系统自动发现潜在的对齐关系。
- 验证机制：引入 GPT-5.4 作为裁判（Judge），对相似度超过 0.8 的候选对进行人工级别的判定。
### 关键实验结果论文提供了扎实的数据支撑其有效性：

论文通过引入“名称-签名”表示法（Name-and-Signature Representation）和图扩展（Graph Expansion），成功将 R@10 提升至 0.775。这说明： 纯语义检索在数学领域不够用，必须结合结构信息（名称、签名）和拓扑关系（依赖图）。
### 工程启示- RAG 的新范式：传统的 RAG 检索文本块，而 TheoremGraph 证明检索“声明级依赖”能显著提升 Agent 的推理能力。在自动形式化任务中，检索相关的前提定理比检索整篇论文更有效。
- 混合检索策略：不要迷信纯向量检索。对于数学库，必须将“语义相似度”与“名称匹配”、“签名匹配”结合。论文中的消融实验显示，加入名称和签名信息是提升召回率的关键杠杆。
- 低成本对齐：通过 LLM 生成 Slogan 并计算余弦相似度，可以低成本地构建大规模跨模态知识图谱。这是一种可复制的工程模式，适用于其他需要连接不同表示形式的领域（如代码与文档）。
### 局限与展望TheoremGraph 目前主要覆盖 arXiv 数学类和 Lean 社区项目，尚未涵盖所有数学文献。此外，非正式依赖提取存在噪声，论文通过保留“提取器标签”让用户自行权衡精度与覆盖率，这是一种务实的工程妥协。
对于开发者而言，TheoremGraph 不仅是一个数据集，更是一个 API 和 MCP 接口。它标志着数学 AI 从“单点检索”向“结构化知识推理”迈出了重要一步。如果你想构建更聪明的数学助手，关注这种基于依赖图的 RAG 架构是必经之路。
