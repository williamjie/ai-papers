# ⭐⭐½ 解决OPD前缀失效：轨迹级蒸馏新思路

**日期**: 2026-06-09

---

论文 : Trajectory-Refined Distillation链接 : https://arxiv.org/abs/2606.08432在线策略蒸馏（On-Policy Distillation, OPD）已成为大模型后训练的核心环节，通过让学生模型在自身采样轨迹上接收教师模型的密集监督，实现高效的能力迁移。然而，这篇来自 McGill 和 UT Austin 的新工作揭示了一个被长期忽视的结构性缺陷： 前缀失效（Prefix Failure） 。
现有方案大多试图通过调整 Token 级别的损失函数来缓解问题，但作者指出，当推理路径在早期就偏离正轨时，这种“打补丁”式的修复根本无效。他们提出的 轨迹级精炼蒸馏（Trajectory-Refined Distillation, TRD） ，通过在蒸馏前修正整个推理轨迹，从根本上解决了这一痛点。
### 核心痛点：为什么 Token 级干预会失效？
在标准的 OPD 中，学生模型采样一个轨迹 yoy_o ​ ，教师模型针对每个位置提供监督信号。问题在于，如果学生在某个时刻进入了错误的推理路径（即前缀失效），教师模型面临两难：
- 继续错误路径：为了保持序列一致性，顺着学生的错误逻辑走。
- 强行纠正：试图跳回正确路径。
这导致教师分布呈现 双峰混合（Bimodal Mixture） 。此时，无论使用正向 KL 还是反向 KL，梯度都会变得破碎且无意义：
- 反向 KL：学生概率质量集中在错误路径上，导致损失主要优化“如何更好地犯错”，纠正信号被淹没。
- 正向 KL：教师试图覆盖所有模式，包括那些分布外的纠正起点，容易引发训练不稳定甚至模式崩溃。
⚠️ 反直觉发现 ：即使拥有完美的教师模型，仅靠 Token 级损失也无法恢复正确的推理路径。因为标准 OPD 的监督上下文始终锚定在“已发生的错误轨迹”上，教师只能不断重复建议同一个纠正起始 Token，却无法引导后续的多步正确推导。
### 方法拆解：从 Token 到 Trajectory 的跃迁TRD 的核心 Insight 非常直接： 既然错误的轨迹无法通过微调损失来拯救，那就直接在蒸馏前把轨迹修好。
具体流程如下：
- 采样原始轨迹：学生模型 πθ\pi_\theta​ 生成初始 rollout yoy_o​。
- 教师精炼：教师模型以 yoy_o​ 为上下文（在 OPSD 设置下还结合参考答案），生成一个修正后的轨迹 yry_r​。
公式：yr∼πT(⋅∣x,yo)y_r \sim \pi_T(\cdot | x, y_o)​∼πT​(⋅∣x,yo​)
- 基于修正轨迹蒸馏：使用 yry_r​ 作为监督目标，计算 KL 散度更新学生模型。
这一设计巧妙之处在于：
- 保持 On-Policy 支持：修正后的轨迹 yry_r​ 仍然以学生生成的 yoy_o​ 为起点或上下文，确保其处于学生模型的策略支持范围内，避免了离线数据带来的分布偏移。
- 恢复理想梯度：监督上下文沿着修正后的正确路径增长，而非冻结的错误路径，从而恢复了能够引导多步推理的理想梯度信号。
### 实验表现：全面超越基线作者在数学（AIME, HMMT 等）和代码生成任务上进行了广泛测试，使用 Qwen3 系列模型。结果令人印象深刻：
1. OPD 设置（不同教师与学生）
在 Qwen3-1.7B 学生 + Qwen3-8B 教师的设置下，TRD 在 AIME24 上比基线提升了 +4.6% (Avg@16)。对于更难的任务 AMOBench，Pass@16 提升了 +5.1% 。
2. OPSD 设置（自蒸馏，共享参数）
这是更具工程价值的场景，无需额外的大模型教师。
- Qwen3-8B 自蒸馏：在极具挑战性的 AMOBench 上，TRD 带来了 ~50% 的相对提升，Pass@16 达到 61.5%，远超其他基线（最高仅 51.3%）。
- 稳定性：几乎所有基于 Token 损失的基线在某些基准上都会出现性能回退，而 TRD 在所有测试基准上均优于或持平于基线模型。

### 工程启示对于正在构建 Agent 或进行模型微调的工程师，TRD 提供了几个关键指导：
- 重视轨迹质量而非仅损失函数：当模型出现系统性推理错误时，调整 Loss 权重（如 Clipping, Top-K）往往是治标不治本。引入教师模型的“重思考”环节来修正数据，效果更显著。
- OPSD 的潜力被低估：TRD 证明了利用同一模型在不同上下文下的能力差异进行自蒸馏，可以在不增加额外算力成本（无需加载大教师模型）的情况下，显著提升推理能力。
- 探索与开发的平衡：即使学生原始回答正确，TRD 也能通过教师生成替代的正确推导路径，拓宽学生的解空间，提升模型的鲁棒性。
### 局限与展望尽管 TRD 效果显著，但其依赖教师模型进行轨迹精炼，这增加了推理延迟。在 OPD 设置下，需要加载更大的教师模型；在 OPSD 中，虽然共享参数，但仍需额外的生成步骤。未来如何降低这一计算开销，或将其集成到更高效的训练流水线中，是值得探索的方向。
