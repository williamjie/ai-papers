# ⭐⭐⭐½ 终端Agent新标杆：超越代码的通用操作评估

**日期**: 2026-06-30

---

论文 : TUA-Bench: A Benchmark for General-Purpose Terminal-Use Agents链接 : https://arxiv.org/abs/2606.28480现在的 AI Agent 大多被困在 GUI（图形用户界面）里，或者只会在终端里写代码。但真实世界中，大量专业工作流——从生物医学图像分析到建筑能耗模拟——其实都依赖命令行工具。Meta 发布的 TUA-Bench 正是为了填补这一空白：它不再测试 Agent 会不会“点点点”，而是考察它们能否像资深工程师一样，通过纯文本接口完成复杂的通用计算任务。
### 为什么现有基准不够用？
目前的评测体系存在明显的割裂：
- GUI 基准（如 OSWorld）：侧重视觉感知和坐标定位，评估的是 Agent 的“眼手协调”，而非核心逻辑规划能力。
- 传统终端基准（如 Terminal-Bench）：高度集中于 Shell 编程和系统运维，缺乏对日常办公、科学计算等广泛场景的覆盖。
TUA-Bench 的核心 Insight 在于： 命令行是 LLM 的天然主场 。CLI 暴露的是文本原生的交互逻辑，命令明确、反馈结构化，且易于通过脚本组合复杂工作流。因此，一个真正的通用 Agent，必须具备在终端中调用专业软件（如 OpenFOAM、EnergyPlus）并处理非代码类任务的能力。
### 方法拆解：从日常到专业的全谱系覆盖TUA-Bench 包含 120 个 真实世界任务，分为五大类，其设计极具工程针对性：
-GUI-to-CLI 转换：
作者并未凭空造题，而是从 OSWorld 的 369 个 GUI 任务中筛选。关键创新在于去工具化约束：不再指定使用 LibreOffice，而是要求 Agent 通过命令行完成文档编辑、表格处理等意图。这迫使 Agent 自主选择 pandoc、sed 或 Python 脚本等合适工具，而非依赖固定 UI 路径。
-专家级科学工作流：
与博士级领域专家合作，设计了生物学、医学物理等领域的专业任务。例如，使用 OpenFOAM 进行共轭传热分析，或使用 EnergyPlus 模拟建筑能耗。这些任务要求 Agent 理解领域特定的输入输出格式和验证逻辑，远超简单的代码修复。
-难度感知筛选：
为避免基准迅速饱和，作者使用 GPT-5.5、Claude Opus 4.7 等前沿模型对候选任务进行预跑，仅保留那些平均成功率最低的 100 个日常任务和 20 个专业任务。这确保了评测的长期区分度。
### 关键结果：65.8% 的天花板与成本陷阱实验结果揭示了当前 Agent 能力的真实水位：
- 最强表现：Claude Code（搭配 Claude Opus 4.8，最大推理努力）以 65.8% 的成功率位居榜首。紧随其后的是 Codex (GPT-5.5, 64.7%) 和 OpenHands (63.4%)。
- 可靠性差异：虽然 GPT-5.5 和 Claude Opus 4.8 的平均成功率相近（约 60%），但 Claude 的 All-5（5次尝试全部成功）指标高达 42.5%，显著高于 GPT-5.5 的 31.7%。这说明在长程任务中，Claude 的行为更稳定。
- 时间预算至关重要：将单任务超时从 150s 增加到 2400s，成功率从 33.0% 飙升至 60.1%。大量失败并非因为“不会做”，而是因为“没做完”。
⚠️ 反直觉发现：模型优劣取决于 Agent 框架在 Mini-SWE-Agent 上，GPT-5.5 比 Claude Opus 4.8 高出 5.0% ；但在 OpenHands 上，Claude 反而领先 2.0% 。这意味着： 不存在绝对最强的模型，只有最匹配的框架组合 。
### 工程启示：如何落地终端 Agent？
-不要吝啬推理时间：
实验显示，增加思考努力（Thinking Effort）能线性提升成功率，从 none 到 medium 即可恢复约 15 个百分点的性能。但在高努力级别下，边际收益递减，且 Token 成本翻倍。中等至高推理设置是性价比甜点区。
-框架选择大于模型微调：
相同的 Claude Opus 4.7 模型，在 Terminus-2 框架下的表现远优于在 Claude Code 原生环境中的某些配置。这表明 Agent 的**执行引擎（Scaffold）**对成本效益的影响巨大。对于预算敏感的场景，Terminus-2 搭配开源模型（如 GLM-5.1）能在 $23/次 的成本下达到 ~48% 的成功率，极具竞争力。
-重视错误恢复与状态验证：
当前 Agent 在“系统软件操作”类别表现较好，但在“办公生产力”和“多媒体”类别普遍低于 45%。这表明 Agent 在处理非结构化文件（如 PPT 格式、视频元数据）时缺乏鲁棒性。工程实践中，需强化 Agent 对中间产物的自动校验机制，而非盲目执行下一步。
### 局限与展望TUA-Bench 目前主要基于 Linux 环境，且部分任务依赖互联网访问，这限制了其在完全离线或 Windows 主导的企业环境中的直接适用性。此外，65.8% 的成功率表明，通用终端 Agent 距离“可靠助手”仍有显著差距，特别是在长程规划与错误自愈方面。
对于工程师而言，TUA-Bench 不仅是一个评测集，更是一份 能力清单 。它提醒我们：构建 Agent 时，应优先考虑其通过 CLI 调用专业工具的能力，而非仅仅优化 GUI 交互的像素级准确率。
