# 给模型叠加技能不串台：Task Arithmetic的正交密码

**日期**: 2026-04-22

---

最近有个很性感的想法：微调完一个模型，把它的参数差直接相加，就能得到一个会多项技能的”全能模型”——不需要联合训练、不需要所有数据。这就是 Task Arithmetic（任务算术）。但工程上有个老问题：加多了，任务之间会打架。CLIP 合并八个分类任务后，性能掉得亲妈都不认识。
南京大学的这篇论文干了两件事：第一，从理论上说清楚”为什么 Task Arithmetic 会成功”；第二，提了一个叫 OrthoReg 的正则化方法，把合并精度从 84% 推到 88%，归一化精度直接突破 100%。
# 问题在哪：任务向量在打架Task Arithmetic 的做法很简单：
- 预训练权重记作 θ₀，每个任务的微调权重记作 θₜ- 定义任务向量 τₜ = θₜ - θ₀，即参数变化量- 合并时直接相加：θ_MT = θ₀ + Σ αₜτₜ听起来很美，但实际合并多个任务时，不同任务的向量会互相干扰。之前的解释是”Weight Disentanglement（权重解耦）“——理想情况下每个任务只在自己的数据域上生效。但这个概念太现象学了，它描述了”应该是什么”，却没说”为什么能是什么”。
这篇论文的核心追问是：
- 什么样的预训练模型天生适合 Task Arithmetic？
- 什么样的任务向量 τₜ 合并时不容易打架？
# 核心洞察：任务-特征专精（TFS）
论文提出了一个关键概念： Task-Feature Specialization（TFS，任务-特征专精） 。
简单说：一个理想模型在面对不同任务时，会智能地分配不同的内部特征。比如分类汽车和分类 MNIST 数字，应该用同一层网络中完全不同的列向量。
论文证明了 TFS 是权重解耦的 充分条件 （Theorem 1）。但更重要的是，TFS 还有一个可测量的几何后果： 权重向量正交性（Weight Vector Orthogonality, WVO） 。
论文在 CLIP ViT-B/16 上做了一个漂亮的实证：随机采样该模型所有线性层的列向量对，它们之间的角度几乎全部集中在 90° 附近（论文 Figure 2）。这意味着预训练本身就推高了正交性——这是一个可观测的信号，暗示模型可能具备 TFS 特性。
直觉理解 ：如果不同任务用了不重叠的特征通道，那么它们的参数变化向量自然就是正交的。正交向量的内积为零，合并时互不干扰。TFS 是因，正交性和解耦是果——三者同源。
# 方法拆解：OrthoReg问题来了：TFS 是理想状态，实际预训练模型达不到。那怎么办？
论文的思路很 clever：既然直接强制 TFS 做不到，那就强制它的几何后果—— 正交性 。
具体来说，在微调时的损失函数里加一项正则化：
L = L_task + λ · L_ortho其中 L_ortho = Σₗ ||(ΔW⁽ˡ⁾)ᵀΔW⁽ˡ⁾ - I||_F²展开说：对每个被更新的线性层，计算其权重更新矩阵 ΔW 的 Gram 矩阵（ΔWᵀΔW），让它尽量接近单位矩阵 I。这意味着 ΔW 的每一列（即每个特征方向）都正交且归一化。
为什么有效？论文在 Theorem 2 中给出了理论证明：即使 TFS 不成立（任务间有特征重叠），约束更新矩阵内部正交也能最小化跨任务干扰。机制有两个：
- 范数控制：正则化天然限制了任务向量的大小- 角度控制：强制内部正交结构，让不同任务向量之间的夹角统计上趋向 90°论文还揭示了 OrthoReg 和 TTA（Tangent Task Arithmetic）的内在联系：两者殊途同归，都是通过实现任务向量间的正交性来减少干扰。但 TTA 需要计算 Jacobian，内存翻倍、训练时间增加 2-3 倍；OrthoReg 是纯参数层面的轻量约束，几乎零额外开销。

# 工程启示这篇论文给模型编辑/合并的工程师三个实用建议：
-微调时加一个正交正则项是免费午餐。L_ortho 的计算非常简单——就是 Gram 矩阵和单位矩阵的 Frobenius 距离，加在标准损失后面就行，几乎零额外开销。
-λ 的选择很宽裕。论文 Figure 6 显示，λ 在 [0.1, 100] 范围内 OrthoReg 都稳定有效，不需要精细调参。
-ATT-FT + OrthoReg 是目前最强的任务加法方案。在三个模型尺度上都取得了最高绝对精度，值得直接拿来用。
-正交性可以作为评估预训练模型是否适合 Task Arithmetic 的诊断指标。如果你关心的模型列向量夹角不集中在 90°，那 Task Arithmetic 的效果可能打折扣。
# 局限与展望论文也坦诚了几个边界：
- 分析聚焦在线性层（全连接和注意力投影），对模型其他部分的推广需要进一步验证- TFS 是理想假设，实际任务间必然有共享特征，OrthoReg 处理的是”部分重叠”而非”完全不重叠”的场景- 实验集中在 CLIP 的视觉 Transformer 上，对其他架构（如纯语言模型）的泛化性有待验证不过方向已经很清晰了：从几何视角理解模型合并，用正交性作为减少任务干扰的核心机制，这个思路值得持续跟进。
