# ⭐⭐⭐⭐ 视频世界模型的记忆难题：MemLearner 的破局之道

**日期**: 2026-07-01

---

论文 : MemLearner: Learning to Query Context memory for Video World Models链接 : https://arxiv.org/abs/2606.31734做长视频生成的工程师都知道，最头疼的不是画质，而是“失忆”。模型生成几十秒后，场景里的物体位置变了、颜色乱了，完全对不上之前的帧。这篇来自快手（Kuaishou）的 MemLearner 论文，直击视频世界模型（Video World Models）的核心痛点： 如何让模型在长序列中保持视觉一致性？
### 现有方案的死胡同目前解决“记忆”问题主要有三条路：
- 3D 重建：把历史帧转成 3D 场景再渲染。太慢，且容易引入几何误差。
- 特征压缩：用向量存历史。信息损失大，细节保不住。
- 上下文检索（Context Retrieval）：直接挑历史帧当条件。这是目前最有潜力的方向，但现有方法全是“规则派”。
比如基于视场角重叠（FOV overlap）或点云匹配的方法，在简单场景还行。一旦遇到 遮挡（Occlusion） 或 动态物体 ，规则就崩了。墙挡住了视线怎么办？人跑走了怎么追踪？硬编码的规则根本没法泛化。
### 核心 Insight：让模型自己“学”着查记忆MemLearner 的核心直觉非常漂亮： 别写规则，让神经网络通过端到端训练，自己去学会从历史帧里“查询”有用的信息。
它引入了可学习的 Query Tokens（Q tokens） 作为桥梁：
- Context Tokens (C)：历史帧的特征。
- Predicted Tokens (P)：当前要生成的帧。
- Query Tokens (Q)：中间人，负责从 C 里提取信息，喂给 P。
最关键的设计抉择： 作者尝试过加一个独立的“查询模块”，结果彻底失败（实验显示该模块没学到任何东西，模型退化成纯文本生成视频）。
⚠️ 反直觉发现 ：最好的办法不是加新模块，而是 直接复用预训练的视频生成模型本身 来做查询。
利用预训练 DiT 强大的视觉先验知识，把 C、Q、P 一起塞进同一个 Transformer 里交互。这样既省了从头训练的成本，又能自然学到复杂的上下文关联。
### 工程上的两个“减负”策略长视频意味着海量的历史 Token，全量计算会爆显存。作者做了两个非常实用的效率优化：
-浅层查询（Query Only in Early Layers）：
把 DiT 分成两部分。前几层（如 5 层）负责让 C、Q、P 交互，完成“信息查询”；后面的深层只处理 Q 和 P，专注“内容生成”。实验表明，查询任务不需要太深的网络，这样大幅降低了计算量。
-剔除冗余注意力：
在 Attention 计算中，砍掉不必要的组合。比如，历史帧（C）不需要作为 Query 去查别人，它只需要被 Q 查。只保留 Q->P、Q->C 和 P->{P,Q} 这三种核心交互模式。

### 工程启示与局限对开发者的意义：
- 数据策略很重要：作者发现纯真实视频（YouTube）因为缺乏精确相机位姿和足够的“回访”场景，很难练出记忆能力。他们构建了一个基于虚幻引擎的渲染数据集，并提出了多数据集训练策略：给不同质量的数据源分配独立的相机编码器，避免噪声干扰。
- 不要盲目加模块：在预训练大模型上微调时，直接利用现有架构的能力往往比外挂新模块更有效、更稳定。
局限性：
论文也诚实指出了边界：当前 1B 参数量的模型，如果场景里同时有超过 5 个互动的角色，依然会乱。这说明记忆容量还受限于模型规模。未来的方向是扩大模型和数据，以及探索更高效的上下文压缩方法。
MemLearner 提供了一个清晰的范式转移： 从“硬规则检索”走向“学习型查询” 。对于正在攻坚长视频一致性的团队来说，这套 Q-Token + 浅层交互的设计思路，值得深入借鉴。
