# ⭐⭐⭐½ MilliVid：用分层潜变量解决视频长程一致性难题

论文 : MilliVid: Hierarchical Latents for Long-Range Consistency in Video Generation链接 : https://arxiv.org/abs/2606.09056生成超过几十秒的连贯视频，一直是当前扩散模型最大的痛点。大多数现有方案在生成长视频时，要么因为 Transformer 序列长度限制而“失忆”，要么为了保持上下文而牺牲画质。这篇来自 MIT 和 Toyota Research Institute 的论文提出了一个非常工程化的解法：不再试图让模型记住所有细节，而是通过分层潜变量（Hierarchical Latents）和从粗到细（Coarse-to-Fine）的生成策略，用极少的 Token 预算换取极长的时间一致性。
### 为什么现有的长视频方案不够好？
目前主流的长视频生成通常采用自回归滚动（Autoregressive Rollout）。模型每次只生成一小段视频，并将最近的一段作为上下文输入下一步。这种做法有个致命缺陷： 遗忘 。当关键帧滑出 Transformer 的固定序列窗口时，模型就彻底忘记了场景的结构信息。
简单的增加上下文长度并不现实，因为计算成本随序列长度呈二次方增长。之前的 SOTA 方案 FramePack 尝试通过降低远处帧的分辨率来节省 Token，但它发现即使压缩了上下文，模型依然很难回忆起离开视野后再次出现的内容。这说明单纯的空间下采样并不能有效保留对长期一致性至关重要的语义结构。
### 核心 Insight：分层潜变量与从粗到细生成MilliVid 的核心直觉非常清晰： 不同视觉信息需要不同的时间持久度。 场景布局、物体位置等“粗粒度”结构必须长期保持一致，而纹理、高频细节等“细粒度”信息可以容忍短期遗忘。
为此，作者设计了两步走策略：
-分层自编码器（Hierarchical Autoencoder）：
不同于传统的单尺度压缩，他们训练了一个能输出多级 Token 的自编码器。最粗层级每帧仅需几个 Token，仅保留场景布局；最细层级则包含完整纹理。关键在于，这些层级是独立解码训练的，且粗层级并非简单的均值池化，而是通过 Transformer 学习到的语义压缩，这比直接下采样保留了更多结构信息。
-从粗到细的滚动生成（Coarse-to-Fine Rollout）：
在固定序列长度约束下，模型先生成大量低分辨率的长序列帧，确立全局一致性；然后逐步 upscale，生成高分辨率细节。
⚠️ 关键设计：为了避免“超分辨率”与“时间预测”产生冲突（例如远处招牌文字在粗粒度时模糊，细化时可能变成不同的字），MilliVid 的上下文始终包含最高分辨率的最近帧，以及仅生成到较粗层级的未来帧。这种混合精度的上下文策略，确保了细节生成不会破坏已建立的全局结构。
### 实验数据：一致性的大幅提升为了公平评估长程一致性，作者构建了一个名为 LoopCraft 的 Minecraft 数据集，包含 200,000 个 1024 帧的游戏视频，专门测试模型在角色转圈回到原点时能否识别之前的场景。

### 工程启示与局限这篇论文对视频生成工程的指导意义在于： 不要试图用单一精度的 Token 处理所有时间跨度。 通过显式地分配计算预算——将大部分 Token 用于近期的细节，少数 Token 用于远处的结构——可以在有限的硬件资源下最大化时间一致性。
然而，该方法也有明显的局限性：
- 训练成本高：需要从头训练分层自编码器和扩散模型，无法直接微调现有的大型预训练视频模型（如 WAN 或 Hunyuan Video）。
- 推理步数增加：相比 FramePack，MilliVid 需要约 33% 更多的滚动步骤，因为每个层级都需要独立的去噪过程。
尽管如此，对于需要高度几何一致性的应用（如机器人世界模型、游戏引擎内容生成），这种“牺牲细节保结构”的分层思路提供了极具价值的参考方向。未来若能结合知识蒸馏技术，将分层潜变量对齐到现有大模型的 Latent Space，其落地潜力将进一步释放。
