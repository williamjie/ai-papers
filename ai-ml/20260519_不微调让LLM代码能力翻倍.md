# 不微调让LLM代码能力翻倍

**日期**: 2026-05-19

---

论文 : Solvita: Enhancing Large Language Models for Competitive Programming via Agentic Evolution链接 : https://arxiv.org/abs/2605.15301让大模型（LLM）写代码，最头疼的不是“能跑”，而是“对且快”。在算法竞赛这种高压力场景下，传统方案要么是一次性生成（Single-shot），要么是多步流水线，但本质上都有一个致命缺陷： 无状态（Stateless） 。模型解完一题，经验就丢了；下一题哪怕类型一模一样，它依然从零开始“瞎猜”。
南京大学和清华大学联合发表的 Solvita 论文，提出了一种 不微调底层模型参数 ，却能通过“经验积累”让代码准确率近乎翻倍的方案。这给工程落地提供了一个极具价值的思路：与其死磕昂贵的模型微调，不如构建一个能自我进化的 Agent 记忆网络。
### 痛点：为什么现有的多 Agent 框架不够用？
目前的 Code Agent（如 AlphaCodium）虽然引入了规划、验证等步骤，但每次解题都是独立的。即便引入了检索增强生成（RAG），也只是静态地查找相似题目，无法根据“上次这种策略为什么失败”来动态调整。
人类程序员之所以强，是因为他们积累了 可迁移的经验 ：知道哪类题目适合用动态规划，哪种边界条件容易踩坑。Solvita 的核心洞察就是： 将这种“经验”显式地建模为一个可训练的知识网络，而不是依赖模型的隐式参数。
### 方法拆解：四个 Agent 与动态知识网络Solvita 构建了一个闭环系统，包含四个专职 Agent，每个 Agent 背后都有一个 可训练的图结构知识网络 ：
- Planner（规划者）：将自然语言题目转化为数学形式，预测算法标签。
- Solver（求解者）：生成代码。关键创新在于基于补丁的修复（Patch-based Repair）：不重新生成整个代码，而是针对报错位置生成 SEARCH/REPLACE 补丁。这不仅节省 Token，还能保留已验证正确的逻辑。
- Oracle（预言家）：生成认证测试用例，验证代码正确性。
- Hacker（黑客）：生成对抗性测试用例，专门寻找边界条件和性能瓶颈。
核心机制：强化学习更新路由权重这四个 Agent 并不直接修改 LLM 权重，而是通过**强化学习（Reinforcement Learning）**更新各自知识网络中的边权重。
- Solver 网络采用三层异构图（Q-问题, M-元认知, S-技能）。当某次解题成功，相关技能节点的路径权重增加；失败则减少。
- 训练信号来自 Oracle 的认证结果和 Hacker 的攻击结果。如果 Hacker 发现了漏洞，这个“失败信号”会反向传播到 Planner 和 Solver 的网络中，让它们在未来遇到类似结构时避开该策略。
这种设计让系统具备了 宏观记忆 ：它记住了“对于这类图论题，DFS 容易超时，应优先尝试 BFS”，并将这一经验固化在网络的权重中，供后续题目直接调用。
### 关键结果：准确率翻倍，成本可控在 CodeContests、APPS 和 AetherCode 等基准测试上，Solvita 的表现极具说服力。以下是基于 GPT-5.4 骨干模型在 CodeContests 上的对比数据：
方法 Pass@1 准确率 Single-pass (基线) 40.0% AlphaCodium 60.6% MapCoder 57.6% Solvita (Ours) 82.4%- 翻倍效果：相比一次性生成的 40.0%，Solvita 达到了 82.4%，几乎是两倍的性能提升。
- 成本优势：得益于补丁修复机制，Solvita 的平均 Token 消耗与开源 Agent 框架相当，远低于商业 CLI 工具。在 CodeContests 上，补丁修复比全量再生节省了 91.2% 的完成 Token。
- 实时竞赛表现：在 Codeforces 实战中，Solvita 的预估 Rating 迅速收敛到 Legendary Grandmaster（≥3000） 级别，而裸跑模型仅停留在 2700-2850 分。
### 工程启示- 经验外置优于模型内化：对于垂直领域（如代码、法律、医疗），微调模型成本高且易遗忘。Solvita 证明了通过外部知识网络积累“策略经验”，可以低成本地提升模型上限。
- 对抗性测试的价值：Hacker Agent 的存在提醒我们，仅靠正向验证是不够的。引入“找茬”机制，能让系统在部署前发现更多潜在 Bug，这在工业级代码生成中至关重要。
- 补丁式迭代更实用：全量重写代码不仅浪费资源，还容易引入新 Bug。采用 SEARCH/REPLACE 局部修复，更符合人类 Debug 的习惯，也更适合工程落地。
### 局限与展望Solvita 目前主要针对算法竞赛场景，其知识网络依赖于结构化的算法标签和测试用例。在开放域软件开发中，如何定义“技能节点”和“对抗攻击”仍需进一步探索。此外，知识网络的维护成本随着问题规模增长而增加，如何高效管理这个“宏观记忆”是下一步的关键。
