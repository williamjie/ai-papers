论文 : When Tools Fail: Benchmarking Dynamic Replanning and Anomaly Recovery in LLM Agents链接 : https://arxiv.org/abs/2606.05806现在的 Agent 评测大多活在“真空”里。
工具永远返回正确 JSON，API 永远不超时，网络永远畅通。这种“快乐路径（Happy Path）”假设让模型看起来无所不能，但一上生产环境就原形毕露。
这篇来自上海 AI 实验室、华东师大和百度的论文，直接掀了桌子： 当工具真的失效时，Agent 到底能不能自救？
作者提出了 ToolMaze 基准，专门测试 Agent 在动态重规划（Dynamic Replanning）和异常恢复上的真实能力。结论很扎心：模型规模越大，基础任务做得越好，但“抗揍”能力的提升速度慢得令人绝望。
### 痛点：从线性执行到迷宫探索现有评测有两个致命盲区。
第一， 缺乏结构化失败 。以前的噪声注入是随机的，没法区分 Agent 是靠运气蒙对，还是真的进行了系统性重规划。
第二， 忽视隐性失败（Implicit Failures） 。显性错误（如 HTTP 404）好办，模型知道重试或报错。但如果是工具返回了格式正确、语义却完全错误的“毒数据”（比如库存显示负数），Agent 往往会盲目信任并传播错误，导致级联崩溃。
ToolMaze 的核心 Insight 是将评测空间正交化：
- 拓扑复杂度（C-axis）：从 C1 线性单路径，到 C4 多分支复杂 DAG。这决定了 Agent 有多少条“退路”可选。
- 扰动模式（P-axis）：2×22 \times 22 矩阵，交叉组合显性/隐性错误与瞬时/永久故障。
这种设计强迫 Agent 从“执行者”转变为“探索者”，必须检测异常、回溯并寻找替代路径。
### 关键发现：规模换不来鲁棒性论文在多个主流模型上进行了测试，结果揭示了几个反直觉的现象。
⚠️ 核心数据：故障容忍度的提升速度，比基础任务执行慢 3.66 倍。
作者绘制了模型参数量与性能的对数线性拟合曲线（Figure 5）：
- 基础任务成功率（TSR）每增加一个数量级参数，提升 17.85 pp。
- 扰动恢复率（PRR）仅提升 4.88 pp。
这意味着，单纯堆算力无法解决 Agent 的“脆弱性”。动态重规划是一种独立于通用指令遵循之外的、需要专门训练信号的能力。
隐性失败的杀伤力极大。
在隐性语义失败场景下，由于模型对污染输出存在系统性过度信任（Systemic Over-trust），恢复率（PRR）暴跌约 37% 。
扰动模式 描述 平均 PRR (w/ hint) P1 显性 + 瞬时 81.44% P2 显性 + 永久 38.12% P3 隐性 + 瞬时 27.68% P4 隐性 + 永久 17.58%可以看到，一旦错误变得“隐蔽”（P3/P4），即使有提示词辅助，恢复率也断崖式下跌。特别是 P4 场景，模型不仅无法恢复，还会陷入无效的试错循环，导致恢复成本（RC）飙升。
提示词只能治标。
虽然使用“失败感知提示词（Failure-aware Prompt）”能带来 1.5%~20.8% 的性能提升，但即便在最佳配置下，扰动场景下的成功率仍远低于无扰动基线。这说明当前的 LLM 缺乏内在的异常检测直觉。
### 工程启示：如何构建更鲁棒的 Agent？
对于正在落地 Agent 应用的工程师，这篇论文给出了明确的避坑指南：
-不要依赖模型的“常识”来校验工具输出。
模型对结构化但语义错误的 JSON 毫无抵抗力。必须在代码层实现显式的数据完整性校验（Data Integrity Check），比如检查库存是否非负、价格是否在合理区间。
-重规划能力需要专门训练。
如果你的业务场景涉及多工具链式调用，仅靠 SFT 或 Prompt Engineering 不够。需要构建包含“错误-重试-切换路径”轨迹的数据集进行微调，让模型学会“走不通就换路”，而不是死磕报错的工具。
-拓扑设计决定容错上限。
ToolMaze 显示，C2（1-to-N 替代）场景下模型表现最好，因为路径清晰。但在 C4 复杂多分支中，模型容易陷入组合爆炸的试错陷阱。在设计 Agent 工作流时，尽量简化依赖图，提供明确的“降级策略（Fallback Strategy）”，而不是让模型自己瞎猜。
### 局限与展望ToolMaze 目前基于预定义的 DAG 拓扑，虽然保证了 Ground Truth 的精确性，但距离完全开放的 Web 环境仍有差距。
此外，它主要关注单一工具的失败，未涵盖多跳级联故障（Cascading Failures）或对抗性注入。未来的方向可能是引入更复杂的混沌工程（Chaos Engineering）手段，模拟真实世界中那种“牵一发而动全身”的系统性崩溃。
总之，如果你想让 Agent 真正上生产，别只盯着 Happy Path 的准确率。 学会处理失败，才是 Agent 成熟的标志。
