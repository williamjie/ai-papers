论文 : Harness Handbook: Making Evolving Agent Harnesses Readable,Navigable, and Editable链接 : https://arxiv.org/abs/2607.13285现在的 AI Agent 系统，核心难点往往不在模型本身，而在包裹模型的“脚手架”（Harness）。随着业务迭代，这些代码库变得庞大且耦合严重。这篇论文解决了一个极其工程化的痛点： 当需求描述的是“行为”，而代码组织的是“文件”时，如何让 Coding Agent 快速定位修改点？
### 痛点：行为与实现的错位在生产环境中，一个 Agent 的行为（如“重试失败的工具调用”）通常分散在多个文件、函数甚至状态机中。现有的代码搜索或 Repository Map 工具，本质上还是基于文件结构和关键字的。
这导致了一个严重的认知断层：
- 人类开发者需要花费大量时间构建心理模型，追踪跨文件的执行流。
- Coding Agent受限于上下文窗口，只能迭代探索，极易遗漏散落在边缘路径或罕见执行分支中的关键代码。
论文将这个问题定义为 行为定位（Behavior Localization） 。现有的检索方法能帮你找到“相关的代码片段”，但无法告诉你“这些片段如何协作产生目标行为”，更无法保证你找到了所有受影响的位置。
### 核心方案：Harness Handbook作者提出了 Harness Handbook ，一种以行为为中心的中间表示层。它的核心直觉是： 不要按文件组织知识，要按运行时行为组织。
#### 1. 三层渐进式披露结构Handbook 构建了一个 L1-L3 的文档树，模拟人类理解复杂系统的过程：
- L1 (系统概览)：架构、执行模型、全局数据流。
- L2 (组件概览)：特定阶段的责任、输入输出、依赖关系。
- L3 (单元深潜)：直接锚定到源码的具体实现片段。
#### 2. 自动化构建流水线这不是让人工写文档，而是通过静态程序分析（Static Program Analysis）和 LLM 辅助的结构化生成自动构建：
- 阶段 I：提取函数、调用图、状态读写等确定性事实。
- 阶段 II：将源码单元映射到执行阶段骨架（Execution Stage Skeleton）。这里引入了“提议-审查”循环，确保映射的准确性。
- 阶段 III：合成层级文档，并建立与源码的动态链接。
#### 3. 行为引导的渐进披露 (BGPD)
在修改时，Agent 不再盲目搜索，而是先通过 Handbook 定位相关行为阶段，再向下钻取到具体代码，最后验证源码是否匹配。如果代码库发生变更，Handbook 会自动重新同步，保持知识的新鲜度。
### 实验结果：更准、更快、更省 Token作者在两个开源 Agent Harness（Terminus-2 和 Codex）上进行了评估，对比了基线方案与 Handbook 辅助方案。结果令人印象深刻：
指标 Terminus-2 提升 Codex 提升 备注 整体胜率 (Win Rate) +18.9% +10.0% 相比基线，计划质量显著更高 定位准确率 (F1) +12.3% ~ +16.3% +5.0% ~ +18.8% 所有 24 项指标均提升 完全错误率 (Wrong) -10.3% ~ -13.3% -7.2% ~ -25.9% 彻底找错位置的情况大幅减少 Token 消耗 -8.6% -12.7% 效率反而更高，非单纯堆料⚠️ 反直觉发现 ：使用 Handbook 不仅提高了质量，还降低了 Token 消耗。这说明 Agent 不再需要盲目地读取大量无关代码来“猜”位置，而是精准导航，减少了无效上下文加载。
特别是在 Search-Hostile（搜索不友好） 的请求中，Terminus-2 的胜率提升了 33.3% 。这类请求通常涉及难以通过关键字检索到的逻辑，传统方法在此类场景下表现最差，而 Handbook 的优势最为明显。
### 工程启示- 显式知识优于隐式检索：对于复杂系统，让 Agent 先理解“行为-实现”的映射关系，比直接扔给它整个代码库或搜索结果有效得多。
- 中间表示层的重要性：在源码和自然语言需求之间，构建一个结构化的、可更新的中间层（如 Handbook），能显著降低 Agent 的认知负荷。
- 自动化维护是关键：Handbook 的价值在于它能随代码自动同步。如果维护成本过高，这种静态文档会迅速过时。论文中的自动重同步机制是落地的关键。
### 局限与展望目前该方法主要应用于两个开源 Harness，且依赖于静态分析提取的调用图。对于动态特性极强、依赖运行时反射或外部复杂状态的系统，静态分析的准确性可能面临挑战。此外，构建 Handbook 本身也有计算成本，需要在“一次性构建开销”和“长期维护收益”之间权衡。
这篇论文为 Agent 系统的自我进化提供了一条务实的路径： 先读懂行为，再动手修改。
