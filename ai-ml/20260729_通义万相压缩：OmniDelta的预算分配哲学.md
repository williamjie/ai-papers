论文 : OmniDelta: Skill-Driven Budget Allocation for Token Compression in OmniLLMs链接 : https://arxiv.org/abs/2607.25669OmniLLM（全模态大模型）虽然能统一处理文本、音频和视频，但长序列带来的显存和推理成本是工程落地的硬伤。这篇来自阿里通义实验室的论文没有纠结于“剪枝算法”本身，而是把目光投向了更上游的问题： 在剪枝之前，如何动态分配有限的 Token 预算？
### 现有方案的痛点：固定预算的盲目性现有的压缩方法（如 OmniZip、OmniSIFT）大多关注“保留哪些 Token”，但往往预设了固定的模态预算或时间窗口。
这种做法有两个致命缺陷：
- 跨模态分配僵化：音频和视频的重要程度随 Query 变化。问“背景音乐是什么”时，音频权重应远高于视频；问“主角穿了什么”时则相反。固定比例会导致关键证据丢失。
- 模态内分布均匀：视频中有大量静态过渡帧，音频中有静音段。对它们分配相同预算是巨大的浪费。
⚠️ 反直觉发现 ：论文通过诊断实验发现，直接用 Query 与音视频 Embedding 计算余弦相似度来路由预算，准确率仅约 50%（接近随机猜测）。因为 Query 表达的是“任务意图”，而模态 Token 编码的是“样本内容”，两者空间并不对齐。
### 核心 Insight：Skill-Driven 的层级预算分配OmniDelta 的核心设计直觉是： 预算分配应基于“技能需求”而非“表面相似性” 。它构建了一个无训练（Training-free）的两级分配框架：
1. 意图感知的跨模态分配（Inter-Modal）
作者离线构建了音频和视频的“技能池”（Skill Pools），包含各类任务的关键字（如音频侧的“节奏、音色”，视频侧的“OCR、动作”）。
- 机制：将 Query 映射到 Embedding 空间，计算其与技能池中各项的相似度。
- 效果：这种方法将路由准确率从直接相似度的 ~50% 提升至 84.3%（Post-Thinker 阶段）。
- 执行：根据得分差值，动态调整音频和视频的总 Token 配额。例如，视频导向问题会从音频预算中“抽血”补给视频。
2. 内容感知的模态内分配（Intra-Modal）
在确定了音视频各自的总预算后，进一步细化到帧或音频片段级别：
- 复杂度信号：计算局部 Token 的多样性，高复杂度区域获得更多预算。
- 冗余度信号：对比相邻时间单元的重叠程度，高冗余区域被压缩。
- 动态重分配：基于上述信号，打破固定窗口限制，将预算倾斜至信息密度高的关键帧或语音段。

### 工程启示- 解耦“分配”与“选择”：不要试图用一个复杂的剪枝网络解决所有问题。先做粗粒度的预算动态分配（Where to spend），再做细粒度的 Token 筛选（What to keep），这种分层策略更稳健且无需额外训练。
- 语义路由优于向量相似度：在多模态路由任务中，基于预定义技能/意图的语义匹配比直接的 Embedding 距离更可靠。这为 Agent 工具调用或模态选择提供了新思路。
- 无训练部署友好：OmniDelta 完全基于启发式规则（Skill Pool + 复杂度计算），无需微调模型即可直接集成到现有推理管线中，适合快速落地。
### 局限与展望虽然效果显著，但 OmniDelta 依赖预构建的技能池，对于极度垂直或新颖的任务类型，技能覆盖度可能不足。此外，其动态分配引入了额外的计算开销（尽管论文指出 TTFT 增加可忽略），在极端低延迟场景下需进一步评估。
总体而言，OmniDelta 证明了**“花对钱”比“省钱”更重要**。对于正在部署 OmniLLM 的工程团队，这是一种低成本、高收益的优化手段。
