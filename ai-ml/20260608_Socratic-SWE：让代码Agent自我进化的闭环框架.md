# ⭐⭐⭐⭐ Socratic-SWE：让代码 Agent 自我进化的闭环框架

**日期**: 2026-06-08

论文 : Socratic-SWE: Self-Evolving Coding Agents via Trace-Derived Agent Skills链接 : https://arxiv.org/abs/2606.07412现在的 LLM 代码 Agent 训练有个死结：高质量 SWE（软件工程）任务太稀缺，靠人工标注或固定规则生成数据，根本跟不上模型能力的迭代。这篇论文提出了一套闭环自我进化框架，让 Agent 从自己的“失败轨迹”中提炼技能，反向生成针对性难题，实现数据与能力的同步增长。
### 痛点：传统合成数据是“盲人摸象”
现有的合成数据方法（如 AST 变异或 Bug 注入）通常是静态的、模型无关的。它们生成的任务分布固定，无法感知 Agent 当前的弱点。
这就导致两个问题：
- 信号稀疏：随着模型变强，固定数据集中能提供有效训练信号的任务越来越少。
- 轨迹浪费：RL 训练中产生的大量交互轨迹（Trace）通常只用来计算奖励，随后就被丢弃。这些轨迹其实记录了 Agent 在哪里反复失败、哪种修复策略容易引发回归，是极具价值的“能力边界地图”。
### 核心洞察：把“失败”变成“技能”，再把“技能”变成“考题”
Socratic-SWE 的核心直觉非常精妙： 不要只把轨迹当作奖励信号，要把它提炼成结构化的 Agent 技能（Agent Skills）。
整个流程是一个三阶段的闭环：
-轨迹蒸馏（Trace Distillation）
Agent 在种子任务上运行，收集成功和失败的轨迹。系统从中提取出“失败模式”和“有效修复策略”，形成结构化的 Agent Skill Registry。
技能不是模糊的描述，而是包含名称、适用条件和操作序列的结构化文档。例如：“当 grep 搜索失败时，尝试遍历文件树”。
-技能引导的任务生成（Skill-Guided Generation）
Generator 角色利用这些技能作为约束，在真实代码仓库中构造新的修复任务。
针对性：任务专门针对 Agent 当前暴露出的能力缺口。
- 可验证性：生成的任务必须通过格式、接地性、执行稳定性和语义正确性四重检查。
-梯度对齐奖励（Gradient Alignment Reward）
这是防止“刷分”的关键。系统维护一个可信的验证集，计算其策略梯度方向 GvG_v​。对于 Generator 生成的每个候选任务，计算其诱导的 Solver 更新梯度 gτg_\tau​。
如果 cos⁡(gτ,Gv)\cos(g_\tau, G_v)​,Gv​) 为正且较大，说明这个新任务能让模型向“正确”的方向进化。
- 只有既可通过执行验证，又与目标梯度对齐的任务，才会进入训练集。
### 实验结果：显著超越基线在相同的计算预算下（3 次迭代，每次 12k 实例），Socratic-SWE 在所有基准测试中均取得最佳效果。
基准测试 Base Agent SSR (最强基线) Socratic-SWE 提升幅度 SWE-bench Verified 42.60% 47.00% 50.40% +7.80% SWE-bench Lite 29.67% 34.00% 36.67% +7.00% SWE-bench Pro 17.24% 20.66% 22.85% +5.61% Terminal-Bench 2.0 10.11% 12.36% 14.61% +4.50%关键发现 ：Socratic-SWE 在 SWE-bench Verified 上比最强的基线 SSR 高出 3.40 个百分点。更值得注意的是，SSR 在第 3 次迭代后趋于饱和，而 Socratic-SWE 在第 4、5 次迭代中仍能持续增长，直到第 5 次才达到 52.00% 的平台期。
消融实验显示：
- 移除技能注册表：性能大幅下降 4.20%，证明“针对性课程”是核心驱动力。
- 替换 GDPO 为 GRPO：性能下降 1.80%，说明在部分修复场景下，分解奖励的学习方式优于二元 Pass/Fail 信号。
### 工程启示：如何落地自我进化？
- 轨迹即资产：不要只保存最终的 Patch，要完整记录 Agent 的探索路径。这些“废数据”是下一轮训练的金矿。
- 结构化技能优于自由文本：将失败经验提炼为带条件触发的操作序列，能让 Generator 更精准地构造难题，避免生成无意义的随机 Bug。
- 梯度对齐防作弊：单纯的可执行验证不够，必须确保新任务带来的参数更新方向与全局优化目标一致，防止 Agent 学会“投机取巧”的特定技巧。
### 局限与展望目前方法依赖于固定的种子仓库池和可信验证集。当技能库覆盖完现有仓库空间后，进化会停滞（第 5 次迭代已见端倪）。未来需要引入动态仓库扩充或跨域技能迁移，才能实现真正的无限自我进化。此外，该方法强依赖可执行的测试环境，对于缺乏自动化测试的代码库，落地难度较大。
