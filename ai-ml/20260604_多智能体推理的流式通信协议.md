论文 : Streaming Communication in Multi-Agent Reasoning链接 : https://arxiv.org/abs/2606.05158在多智能体（Multi-Agent）系统中，我们习惯了“上游生成完毕再传给下游”的串行模式。这篇论文直接挑战了这个直觉：不仅流式传输能降低延迟，它还能显著提升推理准确率。
现有方案的痛点：被阻塞的流水线当前的多智能体框架普遍采用“生成后传输”（Generate-then-transfer）协议。这意味着上游 Agent 必须完整输出所有步骤，下游 Agent 才能开始工作。这种串行执行导致端到端延迟随管道深度线性增长。
更糟糕的是，这种全量传输往往引入了噪声。在多步推理中，早期步骤通常更可靠，而后期步骤容易出错或偏离主题。传统协议迫使下游 Agent 必须处理包含错误尾部的完整上下文，反而干扰了独立判断。
核心 Insight：早到的可靠信息优于晚到的全量信息论文提出的 STREAM MA 系统将通信粒度从“完整响应”细化为“推理步骤”。上游每生成一步，立即推送到下游队列。
⚠️ 反直觉发现 ：接收更少的上下文（仅早期步骤）反而能提高下游质量。因为多步推理的质量是非均匀的，早期步骤更可靠。流式协议让下游基于可靠前缀启动推理，当有噪声的后期步骤到达时，其影响已被稀释。
理论支撑：何时该用流式？
论文给出了首个封闭形式的联合分析（Theorem 1），定义了三种模式（Stream, Serial, Single）的有效性排序。关键在于步骤正确率 pjp_j ​ 与阈值 p∗p^* 的关系：
- Stream 优势区：早期步骤可靠 (phead>p∗p_{head} > p^*​>p∗)，后期步骤退化 (ptail<p∗p_{tail} < p^*​<p∗)。这是大多数复杂推理任务的常态。
- Serial 优势区：所有步骤均高于阈值，或者后期步骤通过自我修正变得极准。此时“信息越多越好”成立。

此外，论文发现了 步骤级缩放定律（Step-level Scaling Law） ：在固定 Agent 数量下，增加每个 Agent 的推理步数 SS ，能同时提升准确率和加速比。在 A=64, S=64 时，实现了 26.9 倍的墙钟时间加速。
工程启示：如何落地？
- Prompt 微调：只需在系统提示中添加 END_STEP 边界标记，无需重构整个 Agent 逻辑。
- KV-Cache 复用：流式传输天然形成共享前缀，结合现代推理引擎（如 vLLM）的 KV-Cache 机制，可进一步降低成本。论文指出，在高缓存命中率下，Stream 协议的成本优势更明显。
- 适用场景判断：并非所有任务都适合 Stream。对于需要强自我修正的任务（后期步骤极准），Serial 可能更好。但对于大多数数学、代码生成等“开头难、后面易出错”的任务，Stream 是首选。
局限与展望该方法依赖于任务可分解为独立步骤。对于开放式创意写作或单 token 分类等难以步骤化的任务，效果有限。此外，若上游 Agent 早期步骤完全错误（Head-perturbed），Stream 会放大错误，此时 Serial 或 Single 更稳健。
