论文 : Not only where, But when: Temporal Scheduling for RLVR链接 : https://arxiv.org/abs/2605.25381RLVR（Reinforcement Learning with Verifiable Rewards）已成为大模型后训练的核心范式，但大多数工程实践仍停留在“如何给 Token 分配奖励权重”这一静态维度。这篇论文抛出了一个被长期忽视的关键变量： 时间 。作者认为，学习信号在训练过程中“何时”被调度，其重要性不亚于它在序列中“何处”被分配。
### 现有方案的痛点：静态分配的僵化在标准的 GRPO（Group Relative Policy Optimization）中，全局标量奖励被广播到整个序列，所有 Token 平等参与优化。为了解决信用分配（Credit Assignment）问题，现有工作引入了基于策略代理（如 Token 熵、似然度）的 静态信用分配 。
⚠️ 核心痛点 ：一旦选定某种代理指标（例如高熵 Token），该标准在整个训练过程中保持不变。这导致模型在初期过度强调特定行为，而抑制了其他潜在有价值的策略演化，最终限制了性能天花板。
### 方法拆解：引入时间维度的动态调度论文的核心 Insight 是： 信用分配标准不应主导整个优化过程 。作者提出了 时序调度（Temporal Scheduling） ，即随着训练步数 τ\tau 的增加，逐渐衰减针对特定 Token 的强化力度，向通用优化回归。
具体实现上，作者发现简单的**轨迹百分位数（Trajectory Percentile）**是区分策略行为的天然视角：
- 早期阶段：优先优化轨迹后段（靠近最终答案）的 Token，确保推理结果的可靠性。
- 后期阶段：逐渐放宽标准，将优化范围扩展至轨迹前段（负责推理支架搭建）的 Token。
这种“由后向前”的渐进式优化，避免了初期因关注点分散导致的策略熵崩溃。公式上，它通过一个单调递减的调度函数 S(τ)S(\tau) 动态调整分配因子：

关键发现：
- 一致性提升：在 Qwen3-4B 上，TP-Schedule 相比 Vanilla GRPO，数学基准平均提升 2.2%，通用推理基准提升 2.7%。
- 熵的保留：标准 RLVR 在适应异质行为时会牺牲策略熵（Policy Entropy）。时序调度通过将优化焦点从后期 Token 逐渐前移，保持了更高的策略熵（训练全程保持 >33.9% 的相对熵水平），避免了早期过度拟合。
- 方向敏感性：若反向操作（从早期 Token 开始调度），由于依赖不可靠的后续生成，会导致优化不稳定。**“由后向前”**是有效的关键。
### 工程启示对于正在落地 RLVR 的工程团队，这篇论文提供了两个极具价值的实践指导：
- 不要迷信静态代理：单纯依靠熵或 KL 散度筛选 Token 并全程保持该标准，容易陷入局部最优。引入时间维度，让优化标准随训练进度动态松弛，能显著提升模型上限。
- 实现成本极低：时序调度是一个“即插即用”的模块。无论是连续的优势重加权，还是离散的稀疏 Token 选择，只需在训练循环中加入一个线性衰减函数 S(τ)S(\tau)，即可兼容现有框架（如 VERL）。建议将调度范围 ϵhigh\epsilon_{high}​ 设置在 0.6-0.8 之间，这是论文验证出的甜蜜点。
### 局限与展望目前该方法主要验证于数学和通用推理任务，且在 Qwen3 系列模型上表现最佳。对于更长上下文或更复杂的 Agent 轨迹，不同百分位数对应的策略行为分布可能需要重新校准。未来工作可探索如何自动编排多种信用分配标准，而非依赖单一的手动调度函数。
