# KV缓存压缩新范式：KVM架构解析

**日期**: 2026-05-12

---

论文 : Key-Value Means链接 : https://arxiv.org/abs/2605.09877在长上下文（Long Context）大模型落地的今天，我们面临着一个经典的“不可能三角”：标准 Transformer 拥有强大的上下文记忆能力，但 KV Cache 显存占用随序列长度呈二次方增长（ O(N2)O(N^2) ) ）；而线性 RNN（Linear RNN, LRNN）虽然显存恒定、推理极快，却往往在长距离依赖检索上表现乏力。
Recursal AI 和 Eleuther AI 联合发布的 Key-Value Means (KVM) 试图打破这个僵局。它不是简单的模型拼接，而是通过一种可扩张的块循环压缩记忆机制，在 Transformer 的精度和 RNN 的效率之间找到了一条平滑的插值路径。对于正在为本地部署长上下文模型头疼的工程师来说，KVM 提供了一种无需自定义内核、即可实现显存可控的方案。
## 为什么需要 KVM？
现有的长上下文优化方案主要分两派：
- 全注意力变体（如 Flash Attention）：通过工程优化加速计算，但无法改变 KV Cache 线性增长的硬件瓶颈。
- 固定状态架构（如 RWKV-7, Gated DeltaNet）：使用固定大小的矩阵状态（Fast Weights），显存恒定。但这类模型通常难以捕捉长距离细节，且往往依赖复杂的自定义算子（Custom Kernels）来保证训练效率。
KVM 的核心洞察在于： 注意力机制本身就是一种动态扩展的“快速权重” 。如果能将溢出的 Token 信息压缩并融入一个动态增长的状态中，同时保持 softmax 注意力的表达能力，就能兼顾两者。
## 方法拆解：三个关键设计KVM 并不是一种全新的基础结构，而是对 Block Sliding Window Attention (BSWA) 的精妙改造。其核心由以下三个组件构成：
### 1. 赢家通吃的状态压缩（Winner-Take-All Compression）
当滑动窗口（Sliding Window）向后移动，旧的 Token 块溢出时，KVM 不会直接丢弃它们，而是将其压缩到状态记忆中。
- 直觉：传统注意力使用 Softmax 对所有 Key 进行加权平均。KVM 发现，为了保持状态 Key 之间的可区分性（Separability），采用极端的稀疏更新更有效。
- 实现：对于溢出的每个 Key，找到与其余弦相似度最高的状态 Key（即“赢家”），将溢出 Key 的 Value 按权重加到该状态 Key 上。这类似于在线向量量化（Online Vector Quantization），但 KVM 将其整合在了单次 Softmax 注意力传递中，而非分离的层。
### 2. 即时归一化（Just-In-Time Renormalization）
这是 KVM 防止状态向量“萎缩”的关键数学技巧。
- 问题：当多个向量相加时，正交分量或反向分量会导致向量的范数（Norm）减小，长期积累后状态向量会变得极小，导致梯度消失或信息丢失。
- 解决：KVM 在读取状态进行注意力计算前，对状态 Key 和 Value 进行行级归一化。Key 使用 LayerNorm 归一化，Value 则保留其初始化时的范数（Radius）。这意味着，无论状态中合并了多少 Token，其 Value 向量的长度始终保持在合理范围内，仅方向反映信息的累积。
### 3. 可扩张的状态策略（Expandable State Strategy）
KVM 支持两种模式：
- 固定状态（Fixed-Size）：状态大小恒定（如 256 个 Token）。此时 KVM 退化为一个高效的 O(N) 块循环 RNN。
- 可扩张状态（Growable）：当溢出 Token 与当前状态“最不相似”（即信息量最大）时，将其直接追加到状态中。状态大小随序列长度呈次线性增长（如 O(N)O(\sqrt{N})​) 或饱和增长）。这允许模型在长文本中逐步“记住”关键信息，而不必像全注意力那样存储所有 Token。
此外，KVM 巧妙处理了位置编码（RoPE）：对状态区域使用无旋转或局部零化的 RoPE，对滑动窗口区域使用标准 RoPE，从而在避免位置信息混淆的同时保留了短上下文的位置感知能力。
## 关键实验结果作者在 Prolong 数据集上训练了 120M 和 350M 参数量的模型，上下文长度设为 8k，并在更长的测试集上评估。
表 1：长上下文检索能力对比 (NIAH-S1, 120M 模型)
模型 4K 8K 16K 32K BSWA (基线) 18.4 8.2 3.8 2.6 RWKV-7 97.2 95.4 71.6 9.8 GPTAlpha-2 (全注意力) 100.0 99.6 87.8 29.6 KVM 256 (固定状态) 99.4 97.8 98.4 98.4 KVM sqrt (可扩张) 100.0 99.8 99.8 99.6注：得分越高越好。
从表中可以看出：
- 固定状态 KVM 256 在 16K 和 32K 长度上远超 RWKV-7 和 BSWA，甚至接近全注意力模型 GPTAlpha-2 的表现，而显存占用仅为后者的几分之一。
- 可扩张 KVM 在所有长度上均达到或接近满分，证明了动态状态扩展对长距离依赖的显著增益。
- 在消融实验中，去掉“Value 长度归一化”会导致 32K 长度下的性能从 98.4 暴跌至 3.6，印证了 JIT 归一化的重要性。
## 工程启示- 无需定制算子：KVM 仅使用标准的矩阵乘法和 Softmax，这意味着它可以轻松集成到现有的 Transformer 框架（如 PyTorch, HuggingFace）中，无需编写复杂的 CUDA Kernel。
- 灵活的显存-精度权衡：通过调整状态大小策略（固定 vs. 可扩张），工程师可以根据硬件限制微调模型。对于显存受限的本地部署，固定状态 KVM 是极佳的替代方案；对于云端服务，可扩张模式能提供更强的长文本理解力。
- 混合架构潜力：KVM 可以与现有的线性 RNN 层混合使用，利用其改进的次线性显存增长特性，为 Agent 和长文档处理提供更高效的推理后端。
## 局限与展望尽管 KVM 表现优异，但它并非完美。首先，可扩张状态模式的训练和推理并行化比固定状态模式更复杂，需要仔细管理状态更新逻辑。其次，论文指出其状态区域完全摒弃了 RoPE（仅通过部分维度零化处理），这可能在某些需要精细位置感知的任务中造成信息损失。最后，目前尚未结合 GQA（Grouped Query Attention）或 MLA（Multi-Latent Attention）等主流优化技术，未来结合这些技术将进一步压缩显存占用。
总的来说，KVM 为长上下文模型提供了一条务实且高效的新路径，值得工程团队关注并尝试集成。
