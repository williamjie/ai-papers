# ⭐⭐⭐⭐ 剪枝模型崩坏？用动态蒸馏找回生成能力

**日期**: 2026-07-16

---

论文 : ShortOPD: Recovering Pruned LLMs with Short-to-Long On-Policy Distillation链接 : https://arxiv.org/abs/2607.13124结构化剪枝（Structured Pruning）是降低大模型部署成本的最优解之一，因为它能直接删减层或头，无需稀疏算子支持。但工程师们常遇到一个尴尬现实：剪枝后的模型在 MMLU 等选择题上表现尚可，一旦用于自由文本生成，质量直接崩盘。
这篇论文指出，这种“认知-生成鸿沟”并非能力消失，而是能力被“降级”了。正确的解题路径还在采样分布里，只是贪婪解码（Greedy Decoding）找不到它。
### 痛点：剪枝后的模型在“复读”
作者对 Qwen3-4B-Instruct 进行深度剪枝（移除 25% 参数）后发现，贪婪生成的准确率跌至谷底。但通过增加采样次数（pass@k），正确率显著回升。例如 GSM8K 在 k=64 时甚至超过了未剪枝教师模型。
这意味着： 能力未被擦除，只是被埋没。
传统的恢复手段如监督微调（SFT）或离线知识蒸馏（KD），往往使用固定的教师回答作为目标。这导致训练分布与推理时的学生分布严重错位（Off-Policy）。更糟糕的是，剪枝后的模型在早期极易陷入“后缀重复”陷阱。如果用长序列进行在线策略蒸馏（On-Policy Distillation, OPD），大量计算预算会浪费在低信息的重复尾部，导致收敛极慢。
### 核心 Insight：ShortOPD 动态预算控制论文提出的 ShortOPD 核心直觉非常工程化： 既然模型早期只会说废话，就别让它生成太长的废话。
ShortOPD 设计了一个“短到长”的动态采样预算控制器：
- 检测重复：实时监控生成的尾部是否进入周期性循环。
- 动态截断：当检测到高重复率时，自动缩小采样预算（Horizon），只保留有效前缀进行蒸馏。
- 逐步放开：随着模型恢复，重复率下降且出现正常截断时，再逐步增加采样长度。
这种设计避免了在“复读机”阶段浪费算力，让早期训练集中在高信息量的 Token 上。它不需要额外的标签或验证器，仅利用剪枝前的原始模型作为冻结教师，进行密集的对数概率匹配。

在效率上，ShortOPD 同样出色：
- 时间成本：仅需 8.5 小时训练，而固定长序列（8192 tokens）需 35.9 小时。
- Token 消耗：减少了 71% 的采样 Token 数。
- 性能持平：在平均得分上仅比固定长序列低不到 2 个点，但速度快了近 4 倍。
⚠️ 反直觉发现 ：稀疏奖励（如 RLVR/PPO）在剪枝模型恢复中几乎无效。因为剪枝后模型很难采样出正确答案，稀疏奖励无法提供梯度信号；而密集的教师分布能纠正每一个 Token 的错误。
### 工程启示- 别再用 SFT 救剪枝模型：离线蒸馏无法修复推理时的分布偏移。必须使用在线策略（On-Policy）让模型在“自己的错误”中学习修正。
- 动态预算是标配：在处理受损或低质量生成的模型时，固定长度的采样不仅浪费算力，还会引入噪声。根据生成质量动态调整上下文长度是提升训练效率的关键。
- 数据覆盖决定上限：消融实验显示，移除数学或代码领域的 Prompt 会导致对应能力恢复失败。On-Policy 蒸馏只修复学生访问过的状态，因此恢复语料必须覆盖所有需要保留的能力域。
### 局限与展望目前该方法主要验证于 Qwen3-4B 及中等比例剪枝（25%）。对于更激进的压缩或更大规模模型，其边界尚不明确。此外，如何自动确定“可恢复的压缩临界点”仍是未解之谜。但对于追求极致推理成本的工程团队而言，ShortOPD 提供了一条从“能用”到“好用”的低成本路径。
