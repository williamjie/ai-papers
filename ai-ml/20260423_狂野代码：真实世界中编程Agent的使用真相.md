# 狂野代码：真实世界中编程Agent的使用真相

**日期**: 2026-04-23

---

论文 : SWE-chat: Coding Agent Interactions From Real Users in the Wild链接 : https://arxiv.org/abs/2604.20779大家最近是不是都被”AI Agent能解决50%需要人类花12小时才能完成的任务”这类新闻刷屏了？METR和Kwa等人的报告看着挺美，但咱们搞工程的都清楚，benchmark里的完美表现和现实里的屎山代码之间，隔着一条巨大的鸿沟。斯坦福这篇论文直接扒开了这层窗户纸——他们收集了6000个真实用户的编程Agent交互会话，共63000条提示词和355000次工具调用。这才是我们该看的”野生”数据。
## 为什么这篇论文值得看现有的编程Agent评测基本都集中在SWE-bench这类精心挑选的GitHub Issue上，指令清晰、边界明确。但现实中开发者是怎么用Agent的？他们有多少代码真正合入了？Agent到底多不靠谱？这些问题，benchmark给不了答案。SWE-chat是第一个从真实开源开发者那里收集到的大规模交互数据集，而且它是持续更新的活数据（Living Dataset），这本身就很有价值。
## 核心发现：Vibe Coding正在成为主流论文最炸裂的发现是编程模式的双峰分布（Bimodal）：
- Vibe Coding（氛围编程）：Agent写了99%以上的提交代码，占41%的会话- 纯人工编码：人类写了全部代码，占23%- 协作编程：人和Agent共同贡献代码，占36%注意，Vibe Coding的占比在三个月内从20%翻倍到了41%。这意味着越来越多的开发者选择把活儿全丢给Agent，然后祈祷它别翻车。
更关键的是任务类型的分布。很多人以为Agent主要用来写代码，但事实是**“理解现有代码”（26.6%）才是最常见的意图**，创建新代码（13.4%）反而排第二。日常开发、git操作、debugging各占约13%。这说明Agent的实际用途远比”补丁生成器”丰富得多，现有benchmark严重低估了这种多样性。
## Agent效率有多低？
数据不会骗人。以下是论文中的关键数字，建议截图保存：
指标 协作编程 Vibe Coding 纯人工 代码存活率（Agent写的代码最终被提交的占比） 44.1% 59.0% N/A 每100行提交代码消耗的Token 中位数较低 204K（3倍于协作） 较低 每100行提交代码的美元成本 $0.05 $0.13（2.6倍于协作） $0.07 每100行提交代码耗时 4.8分钟 12.6分钟 8.6分钟这里有个反直觉的结论： 协作编程（人和Agent一起写）反而是成本最低、效率最高的模式 。Vibe Coding虽然存活率高一点（59% vs 44.1%），但它消耗的Token和金钱分别是协作模式的3倍和2.6倍。换句话说，你让Agent全权负责，看起来省事，实际烧钱又烧时间。
还有一个更扎眼的数据：Agent生成的代码中， 只有44.3%最终活了下来 ，其余要么被人类删了，要么被Agent自己覆盖了。也就是说，超过一半的Agent产出最终被扔进了垃圾桶。
## 安全问题：Vibe Coding是安全漏洞的温床论文用Semgrep跑了一遍静态分析，结果如下：
编程模式 每千行引入漏洞数 每千行修复漏洞数 纯人工 0.08 0.04 协作编程 0.14 0.08 Vibe Coding 0.76 0.52Vibe Coding引入安全漏洞的速度是纯人工的 9倍 ，是协作编程的 5倍 。虽然它也修复了更多漏洞（因为改的东西多），但净效果仍然是引入多于修复，而且差距最大。这解释了为什么越来越多的安全团队对AI生成代码持谨慎态度——你省了时间，但可能埋了雷。
## 用户行为：人类比Agent更”卷”
这里有个有趣的不对称现象：
- Agent主动停下来问用户澄清问题的比例：不到1.4%- 用户打断Agent的比例：约5%- 用户推回（Push Back）Agent输出的比例：约39%也就是说，Agent几乎从不主动说”我不确定，你能再解释一下吗？“，但用户几乎每两次交互就要纠正一次。大多数用户的行为画像属于”专家级吹毛求疵者”（Expert Nitpicker）——他们会仔细检查Agent的输出并逐一修正，即使是在Vibe Coding模式下，仍有47%的用户表现出这种行为。
这说明什么？说明现在的Agent还不够聪明，它不会主动求助，于是人类被迫承担了本该由Agent完成的监督工作。这本质上是一种 低效的权力倒置 。
## 工程启示-别盲目追求全自动化。协作模式（人和Agent各写一部分）在成本和效率上都优于Vibe Coding。让Agent做辅助，比让它当主角更划算。
-Agent的”沉默错误”是个大问题。Agent极少表达不确定性，错误通常只有在人类仔细审查时才会被发现。这意味着当前的Agent设计需要加强”主动求助”的能力。
-安全审计不能省。Vibe Coding引入漏洞的速度远超人工，安全审查的优先级应该更高，而不是更低。
-现有的benchmark严重失真。它们奖励一次性完美补丁生成，但现实中最常见的任务是理解代码和多轮迭代对话。我们需要基于真实交互轨迹构建新的评测体系。
## 局限论文自己也承认，数据来自主动选择加入Entire.io日志的早期采用者，可能不代表全体开发者。而且大部分数据（约85%）来自Claude Code，对其他Agent（如Cursor、OpenCode）的覆盖有限。但这已经是目前最接近真实场景的数据了，瑕不掩瑜。
这篇论文最核心的价值在于它证明了： Agent的能力在快速提升，但人机协作的范式还没有跟上 。我们还在用2024年的思维使用2026年的工具。
