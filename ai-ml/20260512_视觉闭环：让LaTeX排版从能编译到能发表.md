# 视觉闭环：让 LaTeX 排版从能编译到能发表

**日期**: 2026-05-12

---

论文 : PaperFit: Vision-in-the-Loop Typesetting Optimization for Scientific Documents链接 : https://arxiv.org/abs/2605.10341很多工程师可能有过这种痛苦经历：LaTeX 代码编译没报错，但导出的 PDF 里公式溢出、表格被截断、页面留白巨大，甚至因为多了一页半而违反会议页数限制。以前我们只能手动反复编译、检查、修改，这就是典型的“编译-检查-编辑”死循环。
这篇 PaperFit 论文直击这个痛点，提出了 Visual Typesetting Optimization (VTO) 任务。它的核心观点很明确：仅靠源码和日志是不够的，排版本质上是二维视觉判断，必须引入视觉闭环（Vision-in-the-Loop）来自动化这一过程。
## 为什么现有方案搞不定排版？
论文指出了现有三个根本性缺陷：
- 不可见性 (Incomplete Observability)：基于规则的工具和编译日志只能看到一维信号。比如 overfull hbox 警告，规则工具知道溢出了，但不知道溢出多少在视觉上是否严重，也无法判断图片位置对阅读流的影响。
- 修复空间无约束 (Unconstrained Repair Space)：当模型发现问题时，它面临巨大的动作空间。很多“伪修复”（如滥用 \vspace, \resizebox）虽然能编译通过，但破坏了排版规范，甚至把问题转移到其他地方。
- 未验证的级联效应 (Unverified Cascading Effects)：LaTeX 编辑是非局部的。修改一个图片宽度可能导致整篇文档的断页重排。纯文本 LLM 是开环操作，改完不渲染、不检查，无法确认全局布局后果。
## PaperFit 的核心设计拆解PaperFit 不是一个简单的“看图改代码”的 Agent，而是一个精心设计的 视觉闭环控制系统 。它的核心 Insight 在于： 视觉反馈是必要的，但不够充分；必须配合结构化诊断和受限修复策略。
### 1. 多源证据融合 (Sense)
单一信号无法捕捉所有缺陷。PaperFit 融合了四层证据：
- 源码层 (.tex)：结构、宏定义、受保护对象（图、表、引用）。
- 日志层 (.log)：编译错误、警告、模板兼容性。
- PDF 层 (.pdf)：总页数、浮动元素位置。
- 图像层 (Page Images)：二维视觉缺陷（如孤儿行、列不平衡、表格溢出）。
这些证据被转化为结构化缺陷记录 d=(c,o,r,e)d = (c, o, r, e) ( c , o , r , e ) ，包含类别、位置、严重等级和支持证据。
### 2. 受限修复策略 (Act)
这是论文最有工程价值的部分。它定义了一个 修复偏好配置文件 π\pi ，将 LaTeX 操作分为三类：
- 布局原生 (Layout-native, 首选)：调整浮动参数 [htbp]、拆分多行公式、使用 tabularx 替代 \resizebox。这些操作解决根本问题，副作用小。
- 间距操作 (Spacing-manipulative, 受限)：局部 \vspace 调整，需显式理由并通过验证。
- 伪修复 (Pseudo-fix, 禁止)：禁止使用 \resizebox 压缩表格、\newpage 强行分页、\scalebox 缩放图片。这些被视为“掩耳盗铃”，会破坏排版规范。
此外，还有 内容保护机制 ：修复前后快照对比受保护对象，防止误删或移动。只有在布局原生修复用尽后，才允许极小范围的语义润色（如精简句子）来调整页数。
### 3. 清单门控验证 (Verify)
每次修复后，系统重新编译、渲染、检查整个文档。Gatekeeper 基于 Checklist 输出三种状态：
- DONE：所有约束通过，无阻塞缺陷。
- CONTINUE：安全但仍有问题，继续迭代。
- BLOCKED：修复不安全或不可行，停止。
## 关键实验结果PaperFit 在自建的 PaperFit-Bench （200 篇论文，10 种模板，13 种缺陷类型）上进行了评估。对比基线包括规则工具、纯文本 LLM（单轮/多轮）和纯视觉 Agent（单轮/多轮）。

- 纯视觉不够用：VisualMR（多轮视觉 Agent）虽然编译渲染成功率高达 97.5%，但 VLM 得分仅 2.801，页数命中率仅 54.9%。这说明没有结构化诊断和受限修复，多轮视觉反馈容易引入新缺陷或忽视页数限制。
- PaperFit 的全面领先：PaperFit 实现了完美的编译和渲染成功率（1.000），VLM 得分 3.391，领先第二名 VisualMR 约 21%。页数命中率 80.5%，远超 VisualMR 的 54.9%。
- 内容完整性：所有方法的内容嵌入相似度均 >0.97，证明改进主要来自布局优化而非内容篡改。
## 工程启示- Agent 设计需要“护栏”：在代码生成或修改任务中，开放式的自我迭代容易发散。引入受限动作空间（如禁止某些 LaTeX 命令）和结构化缺陷分类，能显著提升稳定性和可解释性。
- 视觉反馈必须闭环：对于任何涉及布局、UI 生成的任务，仅靠文本推理或单次视觉检查是不够的。必须建立“修改-渲染-验证”的闭环，且验证必须覆盖全局（非局部）。
- 分层验证机制：将验证分为硬性约束（编译、页数、内容保留）和软性质量（视觉美观），并设置门控（Gatekeeper），可以有效防止错误级联。
## 局限与展望论文主要关注学术文档的排版优化，未来可能扩展到更复杂的文档类型（如商业报告、书籍）。此外，VLM 作为视觉评估器的成本和延迟仍是工程落地的挑战，未来可能需要更高效的轻量级视觉奖励模型。
