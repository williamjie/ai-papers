# ⭐⭐⭐½ 训练前清洗：用 RAG 重写对抗 LLM 投毒

**日期**: 2026-05-21

---

论文 : Be Kind, Rewrite: Benign Projections via Rewriting Defend Against LLM Data Poisoning Attacks链接 : https://arxiv.org/abs/2605.19147LLM 的安全防御通常集中在推理阶段（如对抗 Prompt Injection），但数据投毒（Data Poisoning）和后门攻击（Backdoor Attacks, BAs）是在微调（Fine-tuning）阶段埋雷的。这篇论文提出了一个反直觉但极其有效的思路： 与其在训练时或推理时修补，不如在训练前把脏数据洗干净。 作者提出了一种基于检索增强生成（RAG）的数据重写方法 OBBR，在保持模型性能的同时，大幅提升了后门攻击的防御能力。
### 现有防御的痛点目前的防御手段主要分为两类，但都有明显短板：
- 反应式（Reactive）：如 CLEANGEN，在推理时通过复杂的解码算法过滤恶意输出。虽然有效，但推理开销巨大，且一旦后门被模型学会，很难彻底根除。
- 交互式（Intraactive）：如 CROW，在微调过程中通过正则化干扰后门学习。这需要修改训练算法，且效果有限。
更糟糕的是，现有的防御在面对多种后门模式时往往失效。一旦模型在微调中习得了后门行为，后续的“安全训练”也难以将其移除。因此，**主动式（Proactive）**防御——在数据进入训练管道之前进行清洗——成为更优解。
### 核心 Insight：开卷考试比闭卷靠谱传统的主动防御是“闭卷重写”（Closed-Book Benign Rewriting, CBBR），即让一个 LLM 直接重写训练样本，依赖其参数化知识判断好坏。但这有个大问题：重写的 LLM 可能本身对某些细微的恶意模式识别不足，或者重写后丢失了原始语义。
本文的核心创新是 OBBR（Open-Book Benign Rewriting） 。其直觉很简单： 让重写模型在“开卷”状态下工作。
具体流程如下：
- 构建一个纯净的良性语料库 BrefB_{ref}​。
- 对于每一个待处理的训练样本 xx，通过向量检索（Retrieval）找到语义最相似的 kk 个良性样本。
- 将这些良性样本作为 Context，连同原始样本 xx 一起喂给重写 LLM。
- LLM 基于这些“正确示例”重写 xx，将其投影到良性提示空间。
为什么这样设计？
从理论上看，引入良性样本作为条件，严格提高了生成良性输出的后验概率（Theorem 1）。直观理解就是：给模型几个“标准答案”作为参考，它改错别字或去除恶意诱导时会更准确，既保留了原意，又剔除了毒性。
### 关键结果：安全与效率的平衡作者在 5 种后门攻击模式和 4 个主流模型（Llama-3.2-1B, Qwen-2.5-1.5B/7B, Llama-3.1-8B）上进行了测试。数据非常硬核：
1. 攻击成功率（ASR）大幅下降下表展示了平均攻击成功率（越低越好，数据来自 Table 1）：

2. 推理开销可控很多人担心重写数据会增加成本，但 OBBR 的开销远低于反应式防御。在 Llama-3.1-8B 上：
- 无防御：总耗时 4.68 分钟。
- OBBR：总耗时 6.48 分钟（增加约 38.5%）。
- CLEANGEN：总耗时 9.15 分钟（增加约 619% 的推理开销，因为需要复杂的解码过程）。
OBBR 将计算压力前置到了数据预处理阶段，且可以通过批量处理优化，推理阶段零额外开销。
3. 对非触发式投毒（PIA）同样有效对于没有特定触发词、直接导致模型安全护栏失效的投毒攻击（Poison Injection Attacks），OBBR 同样表现出色。在 StrongREJECT 基准测试中，OBBR 将模型对恶意请求的合规率从 72% 降至 33.4% 以下，平均提升了 47.1% 的安全性，而闭卷重写 CBBR 几乎无效。
4. 不损害模型能力使用 LIMA 数据集微调后，在 7 个标准 NLP 基准测试中，OBBR 处理后的数据微调的模型，平均性能差异为 -0.4 到 -1.5 分 （负值表示性能提升，见 Table 3）。这意味着重写不仅没丢语义，反而可能因为去除了噪声而提升了模型表现。
### 工程启示- 数据清洗是安全的第一道防线：不要指望模型训练完再打补丁。在 SFT 或 DPO 之前，引入一个基于 RAG 的重写 pipeline，性价比极高。
- RAG 不仅是检索，更是规范：OBBR 证明了检索到的良性样本可以作为“少样本提示”（Few-shot prompting）来引导 LLM 的行为。这在数据增强和去毒场景中通用。
- 权衡计算资源：如果推理延迟敏感，OBBR 是比 CLEANGEN 更好的选择。它用少量的预处理时间换取了推理阶段的零延迟和更高的安全性。
### 局限与展望- 依赖良性语料库质量：OBBR 的效果高度依赖于 BrefB_{ref}​ 的纯净度和覆盖面。如果良性语料库本身有偏差，重写结果也会受影响。
- 领域适应性：目前实验主要在通用指令数据上，未来需要探索针对特定垂直领域（如医疗、法律）的良性语料构建。
