# ⭐⭐½ TIDE：用模板与迭代挖掘隐藏问题

**日期**: 2026-06-05

---

论文 : TIDE: Proactive Multi-Problem Discovery via Template-Guided Iteration链接 : https://arxiv.org/abs/2606.04743现在的 Agent 大多还是“被动响应型”的。用户不问，它不动；用户问什么，它答什么。但真实工作场景中，真正致命的问题往往藏在文档、邮件或代码的缝隙里，用户自己都没意识到。这篇来自 KAIST 的论文提出了 TIDE 框架，试图让 Agent 从“执行者”变成“侦探”，主动发现并解决那些未被明确提出的多重隐藏问题。
### 痛点：单轮预测的盲区现有方案通常假设问题数量已知或只需处理单一意图。但在个人工作空间或软件仓库中，问题是共存的、数量未知的，且最显眼的问题往往会掩盖更细微但关键的隐患。
作者指出，传统的“单次生成”（Single-Shot）方法有两个致命缺陷：
- 覆盖不足：模型倾向于锚定最显著的特征，导致次要问题被忽略。
- 精度低下：缺乏可复用的推理先验，预测容易变得泛化甚至投机，无法提供具体证据和行动方案。
### 核心 Insight：迭代 + 模板TIDE 的设计直觉非常清晰：既然一次看不全，那就分多次看；既然容易瞎猜，那就按套路出牌。它结合了两个互补机制：
1. 迭代发现（Iterative Discovery）
不要试图在一次 LLM 调用中列出所有问题。TIDE 采用多轮迭代，每轮只生成少量候选项，并 显式地条件于上一轮的发现状态 。
- Why：通过累积已知信息，强迫模型在后续轮次中将注意力转向未被覆盖的区域，从而突破“显著性偏见”。
2. 思维模板（Thought Templates）
从已解决的案例中蒸馏出可复用的模式。每个模板包含问题名称、结构模式和证据流（Evidence Flow）。
- Why：将隐性的推理过程显性化为结构化 Schema。例如，“冲突的信源”模板会指导模型先定位交付物，再寻找跨渠道的矛盾版本，最后关联截止日期。这避免了每次从零开始推理导致的幻觉。
### 实验数据：碾压式领先作者在个人工作空间（Personal Workspace）和软件仓库（Software Repository）两个场景下，对比了 Single-Agent、Multi-Agent 并行基线以及 TIDE。结果令人印象深刻：

### 工程启示- 迭代优于并行：在处理复杂、多目标任务时，增加并发度不如增加“思考深度”。让模型看到之前的发现，能显著降低重复劳动并提升覆盖率。
- 模板即知识：Few-shot 示例只是展示结果，而 TIDE 的模板抽象出了“如何寻找证据”的过程。这种结构化的推理先验可以跨模型迁移（论文显示 GPT 生成的模板在 Gemini 上同样有效）。
- 主动式 Agent 的落地路径：不要指望一个 Prompt 就能让 Agent 成为全能管家。构建一个包含“问题模式库”的系统，并通过迭代机制不断刷新上下文，是提升 Agent 实用性的关键。
### 局限与展望目前模板是静态构建的，尚未实现在线更新。此外，迭代过程带来了额外的 LLM 调用成本，虽然效率优于并行基线，但在实时性要求极高的场景中仍需优化。未来方向包括自动从交互中扩充模板库，以及探索更高效的迭代终止策略。
