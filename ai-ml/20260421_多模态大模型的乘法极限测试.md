# 多模态大模型的乘法极限测试

**日期**: 2026-04-21

---

论文 : Multiplication in Multimodal LLMs: Computation with Text, Image, and Audio Inputs链接 : https://arxiv.org/abs/2604.18203现在的多模态大模型（Multimodal LLMs）看着挺全能，但你敢让它直接算个 47×3647 \times 36 36 吗？
这篇来自 ACL Findings 2026 的论文，直接撕开了“感知”与“计算”之间的遮羞布。作者发现：模型能完美识别图片里的数字，能听懂语音里的读数，但一旦涉及多位数乘法，准确率就会断崖式下跌。
这不是模型“听不懂”，而是它根本“算不对”。
## 痛点：GSM8K 掩盖了真正的算术短板我们常用 GSM8K 等基准测试来评估模型的推理能力，但这些测试把语言理解、逻辑规划和算术计算混在一起。一个模型能做对复杂的数学应用题，不代表它能可靠地执行中间步骤的乘法。
更关键的是，现实中的计算往往不是文本形式——它可能是一张截图、一张幻灯片，或者是语音输入。现有的基准缺乏跨模态的成对实例，导致我们根本没法公平地比较不同模型在纯算术任务上的真实能力。
## 核心方法：控制变量法测“算术负载”
作者设计了一个极其严谨的多模态乘法基准，核心思路就三个字： 控制变量 。
### 1. 算术负载（Arithmetic Load）
作者提出了一个简单粗暴但极其有效的难度指标 CC ：
C=dtotal×dnon−zeroC = d_{total} \times d_{non-zero} d t o t a l ​ × d n o n − z er o ​其中 dtotald_{total} ​ 是两个操作数的总位数， dnon−zerod_{non-zero} ​ 是非零数字的数量。
举个例子： 47×3647 \times 36 36 的负载是 4×4=164 \times 4 = 16 4 = 16 。
这个指标本质上是在估算“操作步数”，它比单纯看位数更能反映进位传播（carry propagation）带来的计算压力。
### 2. 跨模态成对基准同一个乘法问题，生成三种形式：
- 文本：数字或单词形式- 图像：渲染的数学公式图片- 音频：语音朗读总共 10,000 个配对实例，确保模型看到的“算式”完全一致，只有输入通道不同。
### 3. 启发式探针（Heuristic Fingerprinting）
这是论文最精彩的部分。人类做乘法有多种策略：
- 竖式乘法（OT）：逐位相乘，处理进位- 分配律分解（DD）：如 47×36=40×36+7×3647 \times 36 = 40 \times 36 + 7 \times 3636=40×36+7×36- 四舍五入补偿（RC）：如 49×51=502−149 \times 51 = 50^2 - 151=502−1作者通过“强制补全损失探针”（Forced-Completion Loss Probe），只通过前向传播（无需采样），测量模型对不同策略前缀的偏好。损失越低，说明模型越“顺”这个策略。

### 模态影响：文本最优，音频拖后腿- 文本通常是性能最强的模态。
- 图像和音频往往滞后，主要表现为截距（基线性能）更低，而非衰减斜率更陡。
- 在感知测试中，模型跨模态识别数字的准确率超过 99%，这直接证明：性能下降是计算能力不足，而非感知能力不足。
### 模型偏爱“分配律分解”（DD）

### LoRA 微调：越调越错？
作者训练了三个启发式特定的 LoRA 适配器（RC、DD、OT），试图引导模型使用特定策略。结果令人震惊：
- 114/121 次行为翻转是负面的（准确率下降）。
- 即使只训练“推理风格”而不涉及具体算术内容（STYLE 控制），准确率也普遍下降。
这说明： 基座模型内部的“启发式路由器”已经比任何单一启发式微调都更优化 。强行注入特定策略，反而会破坏模型原有的平衡。
参数空间的几何分析也证实了这一点：不同启发式对应的 LoRA 更新方向几乎正交（余弦相似度 ≈0\approx 0 0 ），说明它们对应不同的参数子空间，强行合并只会互相干扰。
## 工程启示- Agent 工作流要警惕“幻觉计算”：模型在 Agent 流程中执行中间步骤乘法时，极易出错，且错误随位数呈指数级增长。不要信任模型的内生算术能力。
- 提示工程可以“投其所好”：既然模型偏爱分配律分解（DD），在 Prompt 中显式引导这种分解方式（如“将其中一个数拆分为…”）可能比让模型自由发挥更可靠。
- 模态选择很重要：如果必须让模型做算术，优先使用纯文本数字形式，避免图像或音频带来的额外性能损耗。
- 微调不如工具调用：LoRA 微调的结果表明，试图通过轻量级适配来增强模型的内生计算能力是低效的。直接调用计算器或代码解释器是更靠谱的方案。
## 局限与展望论文仅聚焦于乘法，加法、除法或代数可能表现不同。此外，探针和 LoRA 实验仅针对 Qwen3-VL 系列，其他模型家族的启发式偏好是否一致，仍有待验证。
但无论如何，这篇论文提醒我们：多模态大模型的“智能”是脆弱的，它在感知上的完美掩盖了计算上的无能。作为工程师，我们必须认清这个边界。
