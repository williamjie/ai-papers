# ⭐⭐ 端侧 LVLM 视觉编码器新 SOTA：UltraViT

**日期**: 2026-07-29

---

论文 : UltraViT: Latency-Optimized On-device Vision Encoder for Large Vision-Language Models链接 : https://arxiv.org/abs/2607.23373当我们将大视觉语言模型（LVLM）部署到手机等边缘设备时，最大的瓶颈往往不是语言模型本身，而是那个臃肿的视觉编码器。
传统方案如 SigLIP-400M 在移动端处理高分辨率图像时，其计算开销巨大。在一个典型的端侧 LLaVA-OV 模型中，仅视觉特征提取阶段就占据了近 50% 的端到端推理时间。这简直是资源浪费。
大多数现有工作试图通过压缩 Token 数量或使用更小的语言模型来优化，却忽略了视觉编码器本身的架构效率。Samsung AI Cambridge 团队提出的 UltraViT，正是为了解决这一痛点，它专为端侧延迟优化，重新设计了视觉编码器的底层逻辑。
### 核心洞察：异构混合优于同质堆叠UltraViT 的核心设计哲学是： 网络的不同层级需要不同的空间混合器（Spatial Mixer） 。
传统的 Vision Transformer 通常在所有层使用相同的注意力机制或卷积模块，这是一种“一刀切”的低效做法。UltraViT 采用金字塔架构，并根据真实设备上的延迟测量结果，在不同阶段动态选择最优的操作原语：
- Stage 1（高分辨率）：使用卷积混合器。此时 Token 数量巨大，全局注意力计算成本极高，而卷积在移动端 NPU 上效率极高，且擅长捕捉局部特征。
- Stage 2：混合使用卷积和稀疏注意力。开始引入长距离依赖，但通过优化后的稀疏机制控制成本。
- Stage 3：使用通道分区注意力（CP Attn）。随着分辨率降低，Token 减少，可以承担更多注意力计算，但需避免多头注意力带来的内存碎片化。
- Stage 4（低分辨率）：使用单头全注意力。此时 Token 极少，全局感受野的收益最大，且单头设计避免了多头注意力的访存开销。
这种异构设计并非凭空想象，而是基于在三星 Galaxy S25 Ultra 上进行的详尽硬件延迟搜索得出的最优解。
### 训练策略：从对比学习到生成式对齐除了架构创新，UltraViT 还提出了一种两阶段预训练策略，以解决传统对比学习（如 CLIP）信号过于粗糙、难以支撑 LVLM 生成任务的问题。
- 第一阶段：密集蒸馏。利用高分辨率教师模型的知识，通过像素洗牌（Pixel Shuffle）对齐空间特征，强制学生模型学习丰富的局部和全局语义表示。
- 第二阶段：生成式预训练。直接将编码器与冻结的、已对齐视觉的大语言模型（LLM）连接，进行下一词预测任务。
⚠️ 反直觉发现 ：传统的对比学习目标对于 LVLM 来说信号太粗了。通过引入冻结 LLM 作为解码器进行生成式监督，能让视觉特征更贴合文本生成的需求，从而在后续微调中获得更好的语义 grounding 能力。
为了平衡训练效率，他们在第二阶段动态切换不同容量（0.5B 和 1.5B）的 LLM 作为教师，既保证了语义深度，又控制了计算成本。
### 关键结果：更快、更准、更省UltraViT 在保持甚至提升精度的同时，实现了显著的加速。以下是与当前最强的端侧视觉编码器 FastVLM 的对比（基于相同训练数据重训）：
指标 FastVLM (FastViTHD) UltraVLM (UltraViT) 优势 TextVQA 66.7% 71.8% +5.1% DocVQA 69.9% 72.2% +2.3% ChartQA 64.2% 70.0% +5.8% 端侧推理速度 基准 1.7× 更快 显著加速 Token 数量 较多 减少 16.0× 内在压缩此外，与主流的 SigLIP-400M 相比，UltraViT 的推理速度快了 19.1 倍 ，并且天然实现了 16 倍 的 Token 数量减少。这意味着它不仅视觉编码器快，还大幅减轻了后续 LLM 的计算负担。
在数据效率上，UltraViT 仅使用了约 4.1B 次样本更新（FastVLM 为 13B）和 235M 张唯一图像（FastVLM 为 2B），就达到了 SOTA 性能。
### 工程启示对于致力于端侧 AI 落地的工程师，UltraViT 提供了几个关键指导：
- 不要忽视视觉编码器：在端侧场景中，视觉编码器的优化空间远大于 Token 压缩。直接替换高效的编码器能带来立竿见影的延迟降低。
- 硬件感知的架构搜索：理论 FLOPs 不等于实际延迟。必须在目标硬件（如 NPU）上测量不同算子的耗时，进行异构模块的组合优化。
- 生成式预训练的价值：对于 LVLM，视觉编码器不仅是特征提取器，更是语义对齐的桥梁。使用冻结 LLM 进行生成式蒸馏，比单纯的对齐损失更能提升下游任务表现。
### 局限与展望尽管 UltraViT 表现出色，但其架构的复杂性（多种混合器的组合）可能增加工程实现的难度。此外，其性能高度依赖于特定的硬件延迟特性，迁移到其他异构平台可能需要重新进行架构搜索。未来，如何将这些硬件感知的优化策略自动化、通用化，将是进一步的研究方向。
