# 反思式规划：RL对齐的离散扩散自编辑

**日期**: 2026-05-08

---

论文 : ReflectDrive-2: Reinforcement-Learning-Aligned Self-Editing for Discrete Diffusion Driving链接 : https://arxiv.org/abs/2605.04647自动驾驶规划中，模仿学习（Imitation Learning）最大的痛点不是“学不会”，而是“改不了”。一旦生成轨迹出现纵向速度误判或横向航向漂移，传统端到端模型通常只能重新生成整条轨迹，或者依赖外挂的平滑模块。LiAuto 的 ReflectDrive-2 提出了一个更优雅的思路：既然离散扩散模型天生支持 Masked Token 的局部重写，为什么不直接让模型自己“反思”并修正自己的草稿？
### 痛点：草稿与编辑的割裂现有的离散扩散规划器（如 DriveFine）虽然引入了 Refiner（精炼器），但 Draft（草稿生成）和 Refine（修正）往往是解耦的。Supervised Fine-Tuning (SFT) 阶段，Draft 模型优化自己的 Token 预测损失，Edit 模型优化修正损失，两者互不相干。
这就导致了一个工程上的尴尬：在推理时，即使加入自编辑步骤，提升也微乎其微。论文数据显示，仅靠 SFT 训练，推理时的 AutoEdit 对 PDMS 的提升最多只有 0.3 。因为 Draft 模型不知道什么样的草稿容易被编辑，Edit 模型也不知道什么样的修正能带来更好的闭环驾驶表现。
### 核心 Insight：RL 耦合的全流程优化ReflectDrive-2 的核心创新在于 Reinforcement Learning (RL) 对齐的自编辑机制 。它不再将编辑视为后处理，而是将其视为策略 rollout 的一部分。
-结构化扰动训练：
在 SFT 阶段，作者没有随机 Mask，而是构造了针对驾驶常见错误的“结构感知扰动”（Structure-Aware Perturbations）。
纵向扰动：对轨迹弧长进行缩放（β\beta），模拟超速或制动不足。
- 横向扰动：对轨迹进行旋转（α\alpha），模拟车道偏离。
模型被训练去从这些结构化的错误中恢复出专家轨迹。这给了 Edit 模块明确的“纠错方向”。
-RL 耦合的 Credit Assignment：
这是最关键的一步。作者将 Draft 和 AutoEdit 视为一个完整的 Markov Decision Process (MDP)。
终端奖励（Terminal Reward）只分配给编辑后的最终轨迹。
- 策略梯度（Policy Gradient）通过整个 rollout 反向传播，同时更新 Draft 和 Edit 阶段的 Token 转换概率。
这意味着，Draft 模型学会了生成“可编辑”的草稿（即编辑后得分更高的轨迹），而 Edit 模型学会了进行“有效”的修正（即能提升闭环分数的修正，而不仅仅是降低 Token 级不确定性）。
### 关键结果：RL 带来的质变这种耦合设计带来了显著的性能提升。请看下表对比：

在 NAVSIM 基准测试上，ReflectDrive-2 实现了 91.0 PDMS （纯视觉输入），在 Best-of-6 的 Oracle 设置下高达 94.8 PDMS 。
### 工程启示：为反射式推理定制的推理栈为了让“决策-草稿-反射”这一复杂流程在车端落地，作者设计了一套高效的推理栈，在 NVIDIA Thor 上实现了 31.8 ms 的平均延迟：
- Shared-Prefix KV Reuse：决策、草稿、编辑都共享相同的视觉和指令前缀，复用 KV Cache，将注意力操作延迟从 0.28ms 降至 0.08ms。
- Action-Expert FFN：轨迹 Token 块较短且词汇受限，使用紧凑型 FFN（隐藏层 4096 -> 1024），延迟降低 2.6 倍，且对轨迹误差影响极小（MeanSADE 仅增加 0.056）。
- Alternating Step Decode (ASD)：在流式推理中，交替运行“全步长”和“轻步长”帧。轻步长帧直接对上一帧的轨迹进行 Token-to-Token 编辑，而非重新生成，进一步降低了平均延迟。
### 局限与展望ReflectDrive-2 展示了离散扩散模型在可编辑性上的巨大潜力。然而，RL 训练的稳定性和收敛速度依然是工程落地的挑战。此外，Best-of-6 的高分依赖于多采样和 Oracle 选择，实际部署中如何平衡采样开销与实时性，仍需更多探索。但无疑，这种将“反思”内化为策略一部分的思路，为 VLA 和自动驾驶规划提供了新的范式。
