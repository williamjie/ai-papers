现有的自动化工具要么只能处理纯文本输入，要么生成的只是无法修改的位图（Raster）。
Crafter 这篇论文提出了一套“多智能体挂架（Harness）”方案，不仅解决了跨类型图表生成的难题，还首次实现了从生成到可编辑矢量图（SVG）的全流程自动化。
这对工程实践的意义在于：它证明了在结构化视觉任务中， 编排层（Orchestration Layer）的价值远高于底层模型本身的堆砌 。
## 为什么现有方案不够用？
科研图表与自然图像不同，它是离散语义组件的结构化组合：标签、箭头、图标和注释必须精确对齐。
现有方案存在两个致命痛点：
- 输入单一且不可编辑：大多数系统仅支持 Text-to-Image，且输出为静态位图。当研究者需要调整某个标签或更换配色时，只能重新生成，效率极低。
- 迭代修正失效：简单的重试（Retry）策略在复杂布局上效果很差。因为每次生成的错误模式不同，累积的自然语言修正指令会产生矛盾，导致模型“越改越乱”。
Crafter 的核心 Insight 是： 不要试图训练一个更强的生成器，而是要构建一个围绕生成器的挂架（Harness） 。通过结构化的规范（Specification）作为记忆，实现闭环验证和局部纠错。
## 方法拆解：多智能体协作的奥秘Crafter 包含两个核心系统： CRAFTER （图表生成）和 CRAFT EDITOR （位图转矢量）。它们共享同一套挂架设计模式。
### 1. CRAFTER：生成端的结构化修正传统 Agent 流程往往将修正指令作为自由文本追加到 Prompt 中，这会导致上下文污染。Crafter 引入了三个关键机制：
- 多样性驱动的计划探索（Diversity-Driven Plan Exploration）：
模型首先提出 KK 个候选视觉计划（如不同的布局风格），并行渲染后由裁判选择最佳起点。这避免了因初始构图错误导致的后续所有修正无效。
- 结构化修正层（Structured Corrective Layer）：
这是最关键的设计。修正器（Reviser）不直接修改 Prompt，而是将批评意见转化为**类型化操作（Typed Edits）**写入共享规范 SS。例如，“添加布局约束”或“禁止某类伪影”。这保证了规范的内部一致性，避免了自由文本的矛盾积累。
- 指令性批评与验证-修正循环：
批评者（Critic）不再输出标量分数（如 5/10），而是提供维度得分、缺陷识别和具体修正建议。结合“最佳历史回退”机制，防止迭代过程中的质量倒退。
### 2. CRAFT EDITOR：位图转 SVG 的闭环为了生成可编辑图表，Crafter 设计了从位图到 SVG 的转换流程：
- 提取阶段：通过指令驱动的智能体清理画布，剥离文字和杂乱背景，提取纯净元素。
- 处理阶段：对每个元素进行描述、定位和分类（矢量或位图）。
- 组合阶段：生成 SVG 骨架并注入资产。这里使用了混合批评者（Hybrid Critic），结合 VLM 的全局布局评估和程序化检查器（审计箭头端点、重叠等），确保结构精确性。

- 解耦生成与编排：Crafter 证明了挂架是执行器无关的（Executor-Agnostic）。更换更强的图像生成模型无需修改架构，只需调整 Prompt。
- 混合评估策略：在矢量图形生成中，纯 VLM 评估不够，必须结合程序化检查（如检测 SVG 标签闭合、坐标重叠）才能捕捉细微的结构错误。
### 局限与展望- 计算成本：多轮迭代和并行探索增加了 Token 消耗和推理时间。
- 泛化边界：虽然涵盖了多种输入条件，但对于极度非标准或艺术性极强的图表，结构化规范可能难以覆盖所有创意需求。
Crafter 为科研辅助工具提供了一个清晰的范式： 用结构化的智能体协作，弥补生成模型在逻辑一致性上的不足。
