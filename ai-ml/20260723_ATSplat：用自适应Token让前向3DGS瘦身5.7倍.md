论文 : ATSplat: Compact Feed-forward 3D Gaussian Splatting with Adaptive Token Expansion链接 : https://arxiv.org/abs/2607.20417喂，还在为前向 3D 高斯泼溅（Feed-forward 3DGS）模型那庞大的显存占用头疼吗？
这篇来自延世大学和新国大的 ATSplat 给出了一个极优雅的解法。它不靠堆料，而是通过“自适应 Token 扩展”，在单次前向传播中实现了类似传统优化过程的 场景自适应容量分配 。
简单说：以前是“像素对齐”导致到处撒网，现在是“哪里难重建，就在哪多给点资源”。
## 痛点：像素对齐的“浪费美学”
现有的主流前向 3DGS（如 MVSplat, DepthSplat）大多采用**像素对齐（Pixel-aligned）**范式。
逻辑很直观：每个输入像素预测一个深度，沿相机射线提拉到 3D 空间生成高斯。
但这有个致命缺陷： 高斯的数量分布取决于图像分辨率和视角数，而不是场景复杂度。
⚠️ 反直觉事实 ：在纹理简单的白墙区域，像素对齐方法会生成大量冗余高斯；而在复杂的几何细节处，却可能因为分辨率限制而欠采样。
这直接导致两个工程灾难：
- 渲染效率低：无效高斯占用了大量光栅化带宽。
- 存储成本高：动辄数百万的高斯数量，对移动端部署极不友好。
## 核心 Insight：把“优化”变成“前向”
传统 3DGS 之所以强，是因为它在训练时能 自适应细化（Adaptive Densification） ——哪里误差大，就在哪分裂出新的高斯。
ATSplat 的核心洞察是： 能不能在前向推理中，模拟这种“基于难度的自适应分配”？
为此，作者设计了 ATSplat（Adaptive Token Splatting） 框架，包含三个关键步骤：
### 1. 稀疏骨架初始化不再逐像素生成高斯，而是先用冻结的 DINOv2 提取粗粒度 Patch 特征，结合预测的深度图，反投影生成一组 稀疏的 3D 锚点 Token（Sparse 3D Anchor Tokens） 。
这构成了场景的“骨架”，数量极少，但覆盖了整体结构。
### 2. 解耦位置预测每个锚点 Token 并不直接对应一个高斯，而是通过 MLP 解码为一组 局部高斯 。
关键点在于：这些高斯的位置是相对于锚点的 3D 偏移量（3D Offsets） 。
这意味着高斯可以“跳出”相机射线，自由分布在 3D 空间中，彻底解耦了输入图像网格对位置的束缚。
### 3. 自适应 Token 扩展（ATE）
这是最精彩的部分。在解码器的每一层，模型会预测每个锚点的 不确定性分数（Uncertainty Score） 。
- 监督信号：通过中间渲染结果计算误差图（D-SSIM），反向传播训练不确定性头。
- 动态扩展：高分数的锚点（即难重建区域）会被选出来，通过线性投影生成多个子 Token。
- 效果：复杂区域拥有更多的高斯预算，简单区域保持稀疏。

## 工程启示- 稀疏化是前向 3DGS 的必经之路：像素对齐范式已触及天花板，基于 Token 或 Voxel 的解耦设计才是未来。
- 不确定性引导分配极具价值：不需要显式的渲染误差反馈，仅通过监督不确定性分数，就能实现高效的容量分配。这对实时应用至关重要。
- 局部偏移量提升灵活性：允许高斯脱离相机射线分布，能更好地处理遮挡和细碎几何结构。
## 局限与展望论文也坦诚指出了不足：
- 缺乏剪枝机制：目前只有扩展，没有移除冗余 Token。引入类似传统 3DGS 的剪枝策略可能进一步提升效率。
- 大场景扩展性：当前设计主要针对中小规模场景，扩展到城市级大规模场景仍需架构改进。
ATSplat 证明了一件事： 高质量的前向 3D 重建，不在于你用了多少高斯，而在于你把高斯用在了哪里。
