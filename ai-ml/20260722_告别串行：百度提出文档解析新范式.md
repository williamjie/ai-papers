# ⭐⭐ 告别串行：百度提出文档解析新范式

**日期**: 2026-07-22

---

论文 : HPD-Parsing: Hierarchical Parallel Document Parsing链接 : https://arxiv.org/abs/2607.18839现在的 VLM 文档解析器有个致命伤：为了追求端到端的统一架构，它们把整页文档当成一个长序列，从头到尾串行生成。这种“贪吃蛇”式的自回归解码，随着文档变长，推理延迟呈线性甚至指数级爆炸。
百度 PaddleOCR 团队在最新论文 HPD-Parsing 中，直接动刀重构了解码范式。他们不再让模型一口气吐出整页内容，而是引入了 分层并行解码（Hierarchical Parallel Decoding） 。简单说，就是“全局统筹布局，局部并行填肉”。这一改动让推理吞吐量飙升至 4,752 TPS，比传统基线快了 3.06 倍，且精度不降反升。
### 痛点：统一架构下的串行瓶颈现有的文档解析方案主要分为两类：流水线式（Pipeline）和统一式（Unified）。
流水线方案虽然灵活，但模块间误差累积严重；统一方案（如 InternVL、DeepSeek-OCR）通过联合优化提升了精度，却继承了 LLM 最糟糕的解码习惯—— Token-by-Token 自回归 。
论文指出一个被忽视的事实：文档解析具有天然的 层级局部性 。
- 布局分析需要全局视野：确定阅读顺序、区域关系必须看全图。
- 内容识别是局部任务：某个文本块或表格的内容，主要依赖其对应的视觉区域，与其他遥远区块的文本内容几乎无依赖。
强行用单一线程串行生成所有内容，不仅浪费了计算资源，还让每个新生成的 Token 都要去 Attention 前面所有无关的历史 Token，导致 KV Cache 无限膨胀。
### 核心洞察：布局协调 + 局部并行HPD-Parsing 的核心 Insight 是将解码过程拆解为两个并行的维度： 分支间并行 与 分支内加速 。
#### 1. 布局协调的分支解码（Layout-Coordinated Parallel Decoding）
模型首先由一个主分支（Main Layout Branch）负责全局统筹。它按阅读顺序生成文档结构，当遇到特定路由标记 <FORK> 时，推理引擎会动态“分叉”出多个子分支（Content Branches）。
- 主分支：继续解析后续区域的布局。
- 子分支：并行处理各自区域的详细内容。
这种设计的关键在于 共享前缀 KV Cache 复用 。子分支无需重新编码图像或重复计算公共前缀，只需隔离出自己的局部上下文。这不仅大幅缩短了有效注意力窗口，还实现了真正的并发解码。
#### 2. 渐进式多 Token 预测（P-MTP）
即使并行了解码，单个分支内部仍是自回归的。为此，HPD-Parsing 集成了 P-MTP 技术。它通过轻量级 MLP 模块，从隐藏状态中逐步预测多个未来 Token。
关键数据 ：在推理阶段，每个解码步骤平均能接受 6.6 个 Token 。这意味着原本需要 N 步的生成过程，现在只需约 N/6.6 步即可完事。
### 训练策略：分阶段适应新范式从串行切换到并行并非易事，模型需要重新学习这种“分叉”逻辑。团队采用了三阶段训练策略：
- 初始化：使用传统全页序列生成进行 SFT，让模型掌握基础的文档解析能力。
- 范式迁移：将数据重构为布局分支和内容分支格式，引入特定监督信号。此时重点在于让模型适应 <FORK> 和 <CHILD> 标记，并强化对困难样本的处理。
- 奖励优化：通过轻量级强化学习，针对公式、表格等特定组件的质量进行精细化调整。
此外，他们构建了一个自动化的难度感知数据策展管道，利用多模型标注和 VLM 迭代修正，确保了训练数据的高质量和高覆盖率。
### 实验结果：速度与精度的双赢在 OmniDocBench v1.6 基准测试上，HPD-Parsing 的表现令人印象深刻：
指标 HPD-Parsing (1B) 传统自回归基线 最快现有模型 吞吐量 (TPS) 4,752 ~1,550 ~1,810 加速比 - 3.06x 2.62x Overall 得分 94.91 - -- 精度：以仅 1B 参数的体量，HPD-Parsing 达到了 94.91 的 Overall 分数，超越了 Qianfan-OCR、Logics-Parsing-v2 等更大规模的模型。
- 效率：相比最快的现有文档解析模型，吞吐量提升了 2.62 倍；相比原生自回归基线，提升高达 3.06 倍。
### 工程启示这篇论文对工程落地的指导意义巨大：
- 重新思考解码器设计：不要迷信端到端的单序列生成。对于具有明显结构化的任务（如代码生成、文档解析），引入层级并行机制是突破延迟瓶颈的关键。
- KV Cache 管理至关重要：通过共享前缀和局部隔离，可以有效控制显存占用并加速 Attention 计算。这在长上下文场景中尤为宝贵。
- 多 Token 预测的普适性：P-MTP 等技术不仅适用于文档解析，任何具有较强局部可预测性的生成任务都可借鉴此思路。
### 局限与展望尽管 HPD-Parsing 表现出色，但其实现复杂度较高。动态分支分叉和 KV Cache 管理对推理引擎（如 vLLM）的调度逻辑提出了更高要求。此外，该方法目前主要验证于 InternVL3.5-1B 架构，在其他基座模型上的泛化能力仍需进一步探索。
对于追求极致推理效率的工程团队来说，HPD-Parsing 提供了一条清晰的路径： 用结构化的并行，换取串行的延迟。
