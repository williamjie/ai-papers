# ⭐⭐⭐ Harness-1：用状态外挂让搜索Agent更聪明

**日期**: 2026-06-03

---

论文 : Harness-1: Reinforcement Learning for Search Agents with State-Externalizing Harnesses链接 : https://arxiv.org/abs/2606.02373现在的搜索 Agent 有个通病：模型既要负责“思考”（语义决策），又要负责“记账”（记忆已读文档、证据链）。这导致 RL 训练效率极低，因为模型把大量算力浪费在重复的上下文管理中。Harness-1 的核心洞察很直接： 把可恢复的“簿记”工作从策略中剥离，交给环境端的 Harness 维护。
### 痛点：RL 不该学“死记硬背”
传统搜索 Agent 将状态管理塞进 Policy 内部。随着对话轮次增加，模型必须从原始观察中重构搜索状态。这不仅低效，还导致学习条件恶劣：长文本中的结构信息过于分散，奖励信号无法区分是“搜错了”还是“忘了”。
Harness-1 提出 有状态认知卸载（Stateful Cognitive Offloading） 。策略只负责语义决策（搜什么、留什么、何时停），而环境端的 Harness 维护候选池、证据图、验证记录等持久化状态。这给了 RL 一个稳定的接口，让它专注于优化搜索行为，而不是重新发明记账方法。
### 方法拆解：三个关键设计直觉Harness-1 不是简单的工具调用，它通过三个机制重塑了 Agent 的训练界面：
- 自动种子（Auto-seeding）：解决冷启动奖励稀疏问题。第一次成功搜索后，Harness 自动将 Top-8 结果放入精选集并标记为“一般”。策略的任务从“从零构建”变为“精炼筛选”，这让早期轨迹的差异性更明显，RL 信号更强。
- 证据图（Evidence Graph）：轻量级正则提取实体、日期和文档关联。它将跨文档结构压缩成紧凑块，让模型能直接查找“哪些文档包含实体 X”，无需重读全文。这是将非结构化文本转化为结构化状态的关键。
- 多样性激励（Diversity-preserving Incentives）：防止策略坍缩。如果没有工具多样性奖励，Agent 会退化为无脑的连续搜索。Harness-1 通过奖励函数强制模型在搜索、策展、验证之间保持节奏，确保精选集的质量而非仅仅是发现量。
### 关键结果：小模型打败大模型Harness-1 基于 20B 参数模型（gpt-oss-20b），在 8 个基准测试中平均精选召回率达到 0.730 。这比最强的开源搜索子代理高出 +11.4 个百分点，甚至超过了 GPT-5.4、Sonnet-4.6 等更大规模的前沿模型。

### 工程启示：架构即算法这篇论文对工程实践的指导意义在于： 不要试图让 LLM 记住所有事。
- 状态外置：在构建 Agent 时，应将上下文管理、去重、摘要等“机械工作”交给环境层。LLM 只应处理高价值的语义判断。
- 奖励设计：RL 训练搜索 Agent 时，必须包含工具多样性奖励和策展质量奖励，否则策略会坍缩为低效的暴力搜索。
- 数据效率：Harness-1 仅使用 899 条 SFT 轨迹和有限的 RL 数据就取得了显著效果。这表明，良好的状态接口设计可以大幅降低对训练数据量的依赖。
### 局限与展望Harness-1 的证据图目前基于正则表达式提取，未来可替换为更智能的实体链接和关系抽取。此外，去重机制（MinHash-LSH）在某些情况下可能会合并近重复的黄金文档，导致召回率轻微下降，这是为了控制 Token 预算而做出的权衡。
总的来说，Harness-1 证明了 搜索 Agent 的性能瓶颈往往不在模型大小，而在状态管理的架构设计 。通过让环境承担“簿记”责任，我们能让 RL 训练更高效、更稳定，也让小模型在复杂搜索任务中具备与大模型竞争的能力。
