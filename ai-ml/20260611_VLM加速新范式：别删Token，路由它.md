# ⭐⭐⭐⭐ VLM加速新范式：别删Token，路由它

**日期**: 2026-06-11

---

论文 : Reroute, Don’t Remove: Recoverable Visual Token Routing for Vision-Language Models链接 : https://arxiv.org/abs/2606.12412VLM 推理加速的核心矛盾在于：为了省显存和算力，我们习惯性地“剪枝”掉不重要的视觉 Token，但这往往导致模型在后续层中“后悔”。这篇论文提供了一个极简且优雅的解法： 别删，先挂起，等它变重要再唤醒 。这是一个无需训练、即插即用的加速插件，能在保持理论算力不变的前提下，显著修复激进剪枝带来的 Grounding（定位）能力崩塌。
### 现有方案的致命痛点：不可逆的“误杀”
目前的视觉 Token 压缩方法（如 FastV, PDrop, Nüwa）大多遵循 Rank-and-Remove （排序并移除）范式：在浅层计算注意力得分，保留高分 Token，永久丢弃低分 Token。
这种设计的底层假设是： Token 的重要性在解码器深度上是稳定的 。
⚠️ 反直觉发现 ：作者通过追踪实验证明，这个假设是错误的。
以 RefCOCO 数据集为例，对于查询“穿绿衬衫的男人”，其对应的关键视觉 Token 在第 3 层（FastV 剪枝点）的注意力百分位仅为 0.11 ，在第 8 层（PDrop 剪枝点）为 0.25 。因此，这些方法会将其永久移除。然而，到了第 25 层，该 Token 的重要性飙升至 0.97 。
浅层注意力是弥散的，关键信息往往在中深层才浮现。 不可逆的删除，本质上是切断了模型在深层利用这些信息的后路。
### 方法拆解：Reroute 的核心直觉Reroute 的核心洞察在于将“剪枝”重构为 “可恢复的路由”（Recoverable Routing） 。
它不引入任何新参数，也不改变现有的评分机制（仍复用 Text-to-Vision Attention），仅改变了低分 Token 的 命运 ：
- 传统剪枝：低分 Token →\rightarrow 永久删除 →\rightarrow 候选池缩小。
- Reroute：低分 Token →\rightarrow 旁路挂起（Bypass） →\rightarrow 保留在序列中，进入下一阶段的候选池。
在每个路由阶段，只有被选中的 Token 进入 Attention + FFN 计算，未被选中的 Token 通过残差连接直接跳过当前层。关键在于， 挂起的 Token 会在下一个路由点重新参与竞争 。如果它在深层变得重要，它就能“复活”并进入计算流。
从架构视角看，这是一种无需训练的 Mixture-of-Depth (MoD) 实现：不同视觉 Token 在解码器中经历不同的计算深度，而非一刀切地全部经过所有层。
### 关键结果：用极小代价换回 Grounding 能力Reroute 作为插件，兼容 FastV、PDrop 和 Nüwa。实验表明，它在保持理论 TFLOPs 和 KV-Cache 预算不变的情况下，大幅提升了定位性能。
1. LLaVA-1.5-7B 上的表现（RefCOCO 系列）
在 HuggingFace 格式下，当平均 Token 数压缩至 64 （减少 88.9%）时：
- FastV: Avg Ratio 仅为 3.8%（基本失效）。
- PDrop: Avg Ratio 为 22.2%。
- PDrop + Reroute: Avg Ratio 提升至 34.0%。
即使是在更宽松的 192 Token 预算下，Reroute 也将 FastV 的平均表现从 45.5% 拉升至 59.2% 。
2. Qwen 系列模型的跨架构迁移在 Qwen2.5-VL-7B 上，当减少 88.9% Token 时：
- FastV: Avg Ratio 仅 2.4%。
- PDrop + Reroute: Avg Ratio 达到 18.6%。
在混合架构的 Qwen3.5-9B-Hybrid 上，收益更为惊人。由于该模型包含线性注意力块，保持序列布局至关重要。Reroute 在 77.8% 压缩率下，将 PDrop 的平均表现从 25.8% 提升至 59.7% 。
3. 效率与通用能力无损- 算力：Reroute 的理论 TFLOPs 和 KV-Cache 占用与基线剪枝方法完全一致（例如在 64 Token 预算下，KV Cache 减少 86%）。
- VQA 性能：在 GQA、TextVQA 等通用问答任务上，Reroute 的表现与基线持平甚至略优，证明其并未牺牲通用理解能力。
### 工程启示- Grounding 任务必须慎用激进剪枝：如果你的应用涉及目标检测、引用回答（Referring Expression），传统的 FastV/PDrop 在压缩率超过 70% 时会严重退化。Reroute 是一个低成本的补救方案。
- 即插即用，无需重训：Reroute 不需要微调模型权重，只需修改推理代码中的 Token 调度逻辑。对于已部署的 VLM 服务，升级成本极低。
- 路由频率需调优：实验显示，增加路由层数（N）通常能提升性能，但存在边际效应。在 RefCOCO testB 上，N=8 时达到峰值。工程落地时，建议根据模型深度调整路由间隔，而非全层路由。
### 局限与展望Reroute 并非银弹。其效率增益主要停留在理论层面，实际延迟取决于 Gather/Scatter Kernel 的优化程度以及 KV-Cache 的管理策略。此外，它依赖于注意力分数的准确性，如果评分器本身存在偏差，挂起机制可能无法有效唤醒正确 Token。对于混合架构（如 Qwen3.5），目前仅对 Softmax Attention 块进行路由，与线性注意力状态的交互仍需进一步研究。
总之，这篇论文提醒我们： 在 VLM 加速中，信息保留的灵活性比单纯的计算削减更重要。 下次再想删 Token 时，不妨先问��自己：它真的不重要吗？还是只是还没到时候？
