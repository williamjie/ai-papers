论文 : ClawGym II: Exploring Black-Box RL on Agent Harness链接 : https://arxiv.org/abs/2608.16798做 Agent 开发的朋友都知道，现在的 Claude Code 或 OpenClaw 这类“Agent 框架”（Harness）越来越强。它们内部集成了复杂的上下文管理、工具编排和重试机制。但问题在于：如果底层模型没经过针对性训练，再好的框架也带不动。这篇论文给出了一个硬核解法： 不改动框架内部代码 ，通过黑盒强化学习（Black-Box RL）直接优化底层模型。
### 痛点：透明性丧失与轨迹碎片化传统 RL 要求环境是透明的，模型每一步的动作和状态都要清晰可见。但现代 Harness 是个“黑盒子”：
- 逻辑不透明：框架内部有大量的隐式控制流（如自动重试、上下文压缩），模型看不到这些中间态。
- 轨迹碎片化：Harness 会把一次任务拆成多次模型调用，甚至分叉出子代理（Subagent）。直接拿这些碎片做训练，会丢失长程依赖，且包含大量无效噪声。
### 核心方法：前缀树重构与解耦优化论文的核心 Insight 是： 将策略优化与 Harness 执行彻底解耦 。
-沙箱隔离 + 代理拦截每个任务在临时沙箱中运行，保证环境独立。
- 在模型服务端部署一个 Serving Proxy。Harness 照常运行，但所有发给模型的请求和响应都被 Proxy 截获并记录。
- 设计意图：不需要逆向工程 Harness 的内部逻辑，只需关注“模型输入/输出”这一边界。
-前缀树（Prefix Tree）重构轨迹这是最关键的技术点。Harness 产生的调用是线性的、碎片化的，但逻辑上是有共享历史的。
- 论文将这些调用组织成一棵前缀树。根节点是初始 Prompt，子节点是后续调用。
- 去噪过滤：
Dead Leaves（死叶子）：因重试产生的无效分支直接丢弃。
- Over-Branching（过度分叉）：如果分叉过多，说明任务陷入死循环，整个 Rollout 废弃。
- Auxiliary Trajectories（辅助轨迹）：子代理或上下文压缩产生的轨迹不参与主奖励计算，避免信用分配混乱。
-树结构上的 PPO/GRPO传统的 RL 假设一条轨迹对应一个 Reward。但在前缀树中，多条分支共享同一最终状态（Reward）。
- 论文修改了优势函数（Advantage）计算：所有从根到叶的路径共享同一个 Rollout 级别的 Reward。
- 一致性保障：通过 Token-level Importance Sampling 修正推理引擎和训练引擎之间的概率差异，防止训练崩溃。
### 关键结果：稳定且显著的提升实验基于 Qwen3-30A3B 模型，在 ClawGym-Bench 上进行测试。结果非常扎实，且在 200-400 步优化中保持收敛稳定。

更有趣的是 Mix-Harness Training ：
- 混合使用 OpenClaw 和 Claude Code 的数据联合训练一个模型。
- 结果不仅没有冲突，反而匹配或超过了单一 Harness 训练的效果。这证明了该方法具有极强的泛化性。
### 工程启示- 黑盒 RL 是 Agent 进化的必经之路：不要试图去“读懂”商业 Agent 框架的内部逻辑，把模型当作黑盒中的可优化组件，通过边界拦截数据进行训练。
- 前缀树是处理复杂交互的关键数据结构：如果你的 Agent 涉及多轮、多工具、子代理，传统的线性轨迹记录会丢失信息。前缀树能高效复用共享历史，减少计算冗余。
- 基础设施决定上限：论文花了大量篇幅讲沙箱隔离、故障重试和流式解析缓冲。在大规模 RL 中，稳定性比算法细节更重要。
### 局限与展望- PPO 的简化：对于分叉轨迹，论文采用了简化的 PPO（γ=1,λ=1\gamma=1, \lambda=11,λ=1），未完全建模分支间的依赖关系，这可能导致优势估计方差较大。
- 辅助轨迹浪费：目前子代理的数据被丢弃，未来若能有效利用这些“中间过程”数据，可能有进一步的性能提升空间。
这篇论文不仅是一个算法贡献，更是一套完整的 Agent RL 工程基础设施 。对于想要微调自有模型以适配特定 Agent 框架的团队，这套“沙箱+Proxy+前缀树”的架构极具参考价值。
