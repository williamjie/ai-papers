# LLM工具调用失灵：知行鸿沟与表征正交性

**日期**: 2026-05-19

---

论文 : Model-Adaptive Tool Necessity Reveals the Knowing-Doing Gap in LLM Tool Use链接 : https://arxiv.org/abs/2605.14038如果你正在构建 Agent，一定遇到过这种尴尬场景：模型明明能直接回答简单算术题，却非要调一次计算器；或者面对超纲事实查询，它明明答不上来，却硬着头皮胡编乱造。这篇来自马里兰大学的新论文揭示了一个残酷真相： LLM 并不是不知道何时该用工具，而是“知道”却“做不到”。
这种“知行鸿沟”（Knowing-Doing Gap）不仅解释了 Agent 的不可靠性，更指出了现有优化思路的盲区。
### 痛点：谁定义了“需要工具”？
现有研究通常把“是否需要工具”视为一个静态属性，由人类或强模型标注。但这忽略了模型能力的差异性：Qwen-8B 能心算的题目，对 Qwen-4B 来说可能需要计算器。
作者提出了 模型自适应工具必要性（Model-Adaptive Tool Necessity） ：
- 对特定模型 ff，在无工具情况下进行 N=10N=1010 次采样（T=0.7T=0.70.7）。
- 若 10 次全对，标记为“不必要”；只要错一次，标记为“必要”。
这一定义将“必要性”锚定在模型的实际能力边界上，而非题目本身的难度。
### 核心发现：内部认知与执行动作“正交”
作者将工具调用拆解为两阶段：
- 认知阶段（Cognition）：模型内部是否意识到需要工具？
- 执行阶段（Execution）：模型是否输出了工具调用 Token？
通过线性探针（Linear Probing）分析隐藏层状态，作者发现：
- 认知可解码：在算数任务中，模型内部状态能线性区分“必要/不必要”（MCC > 0.4）。
- 动作可解码：模型是否调用工具的动作意图也可线性解码。
- 关键 Insight：在驱动最终输出的最后一层、最后一个 Token 处，代表“认知必要性”的向量 wc\mathbf{w_c}​ 与代表“执行动作”的向量 wa\mathbf{w_a}​ 几乎正交（Cosine Similarity ≈0\approx 00）。
这意味着，模型在内部“知道”该用工具，但在生成决策的瞬间，这个认知信号与执行信号发生了断裂。
### 数据说话：高达 54% 的行为错配在算数和 TruthfulQA 数据集上，四种主流模型（Qwen3-8B/4B, Llama-3.1-8B, Llama-3.2-3B）表现出巨大的行为错配：
模型 算数错配率 TruthfulQA 错配率 主要错误模式 Qwen3-8B 41.7% 31.1% 算数：过度调用 (UN-C 38.2%) Qwen3-4B 26.5% 41.8% 算数：调用不足 (N-NC 14.5%) Llama-3.1-8B 38.5% 30.8% 算数：严重调用不足 (N-NC 30.1%) Llama-3.2-3B 54.0% 32.8% 算数：极度调用不足 (N-NC 39.0%)
Sankey 图归因分析 显示，绝大多数错误（橙色流）发生在 认知正确但执行错误 的阶段。模型内部已经正确判断了必要性，但未能转化为正确的 Action。
### 工程启示：别只调 Prompt，要修“神经回路”
- 微调策略转变：传统的 SFT 只是让模型模仿“何时调用”，但并未解决内部认知与执行的正交断裂。未来的对齐训练可能需要显式约束隐藏层中认知向量与执行向量的对齐。
- 置信度误导：实验发现，即使模型内部对“必要性”的判断置信度极高（接近 0 或 1），依然会发生执行错误。因此，依赖模型自我评估置信度来路由工具是无效的。
- 后处理补救：既然认知信号在中间层是可解码的，工程上可以尝试在推理过程中提取中间层状态，通过外部探针判断模型是否“内心焦虑”，从而强制触发工具调用，弥补执行层的缺陷。
### 局限与展望该研究主要基于算数和事实 QA，复杂多步推理场景下的认知-执行耦合机制可能更复杂。此外，正交性是否源于训练数据中工具调用指令的分布偏差，仍需进一步探究。
