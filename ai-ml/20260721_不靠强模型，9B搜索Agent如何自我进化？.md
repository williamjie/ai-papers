# ⭐⭐⭐½ 不靠强模型，9B 搜索 Agent 如何自我进化？

**日期**: 2026-07-21

---

论文 : DeepSearch-World: Self-Distillation for Deep Search Agents in a Verifiable Environment链接 : https://arxiv.org/abs/2607.07820做 Agent 微调的工程师都知道一个死结：用 SFT 模仿强模型，性能很快触顶；用 RL 自我进化，奖励太稀疏导致训练像盲人摸象。
这篇来自腾讯和 HKUST 合作的论文，提供了一个极其实用的解法： 构建一个“可验证”的离线环境，让 Agent 在确定性世界里自己玩、自己纠错、自己蒸馏。
不需要更强的 Teacher 模型，9B 参数量的 Qwen3.5 经过这套流程，在 GAIA 上提升了 37.6%，HotpotQA 飙升了 48.1%。这不仅是 SOTA 的追逐，更是低成本训练长程搜索 Agent 的工程范本。
### 为什么现有方案搞不定“自我进化”？
目前的 Agent 训练主要有两条路，但都有硬伤：
- 模仿学习（SFT）：依赖固定轨迹。一旦 Backbone 能力有限，生成的轨迹多样性不足，模型很快过拟合，无法突破自身上限。
- 强化学习（RL/GRPO）：奖励通常是最终的“对/错”。对于需要多步搜索、查询改写、证据提取的长程任务，中间哪一步错了？是 Query 写错了，还是工具选错了？稀疏奖励给不出细粒度指导。
⚠️ 核心洞察 ：
传统的 On-policy Self-Distillation (OPSD) 试图用 Token 级分布来缓解奖励稀疏，但在 Agent 场景下，如果环境是不确定的（比如实时网页），Teacher 在每一步的工具调用分布可能是噪声。 只有在一个“确定性”且“可验证”的环境中，过程级的监督信号才是可信的。
### DeepSearch-World：给 Agent 一个“标准答案库”
论文的核心贡献之一是 DeepSearch-World ，一个基于 Wikipedia 的离线、确定性环境。
它的设计直觉非常工程化：
- 确定性工具：web_search_wiki 和 visit_wiki 不是调用真实 API，而是基于 BM25 索引和 SQLite 的本地检索。同样的 Query，永远返回同样的结果。这消除了随机性对训练稳定性的干扰。
- 实体级验证：每个问题都关联一组目标实体（Target Entities）。Agent 每调用一次工具，环境就能判断是否命中了未解决的实体。这种“进度条”式的反馈，比 LLM 主观判断要廉价且准确得多。
- 420K 多跳 QA：通过知识图谱上的随机游走生成任务，确保训练数据覆盖足够的推理深度和多样性。
### DeepSearch-Evolve：从“脚手架”到“独立行走”
有了环境，怎么让模型变强？论文提出了 DeepSearch-Evolve 框架，其精髓在于 “Scaffold-to-ReAct” 的转换策略。
-Teacher 阶段（带脚手架）：
Teacher Agent 在环境中执行任务时，拥有显式的“工作记忆”（Working Memory），包括 completed_list、todo_list 和 experience。它还能收到环境的“接地反射”（Grounded Reflection），比如搜索失败时，环境会提示下一个未解决实体。
-数据清洗与转换：
拒绝采样：只保留最终答案正确的轨迹。
- 质量过滤：剔除冗余证据或逻辑不一致的轨迹。
- 关键一步：将 Teacher 的“脚手架”行为（规划、记忆更新、错误恢复）重写为标准 ReAct 格式的 <think> 思考块。
💡 工程直觉 ：
我们训练的目标是一个能独立部署的 ReAct Agent，而不是一个依赖外部 Prompt 才能工作的模型。因此，Teacher 的“外挂大脑”（显式状态跟踪）必须被内化为学生模型的“隐式推理能力”。通过重写，学生学会了像 Teacher 一样思考，但无需外部结构支持。
- 迭代蒸馏：
用清洗后的 ReAct 轨迹对 Student 进行 SFT。Student 变成下一轮的 Teacher，循环往复。
### 实验结果：数据多样性比重复更重要实验数据非常有说服力。基于 Qwen3.5-9B-Instruct 基座，经过 11 轮自我进化后，DeepSearch-World-9B 的表现如下：
Benchmark Qwen3.5-9B (Base) DeepSearch-World-9B 提升幅度 BrowseComp 7.4% 31.2% +23.8% GAIA 23.9% 61.5% +37.6% HotpotQA 45.3% 93.4% +48.1%对比其他开源 Agent，它在不依赖更强模型蒸馏的情况下，达到了极具竞争力的水平。
⚠️ 反直觉发现 ：
论文对比了 100K 和 420K 数据池的效果。 更大的数据池（420K）带来了更高的性能天花板和更稳定的训练曲线。
原因在于：自我进化依赖数据的多样性。小池子很快耗尽，模型开始重复拟合旧轨迹；大池子能持续提供新的推理路径和失败恢复模式，防止过拟合。
此外，行为分析显示，基座模型平均只进行 4.7 轮交互就结束任务（往往过早回答），而进化后的模型能坚持 18.0 轮 ，并显著增加了 visit 工具的使用频率（从 0.9 次增至 5.4 次），说明它真正学会了“深入挖掘证据”。
### 工程启示与局限对工程师的价值：
- 离线环境先行：在训练复杂 Agent 前，先构建一个确定性、可验证的模拟环境（如基于本地知识库），能极大降低调试难度和训练成本。
- 内化而非外挂：不要指望 Prompt Engineering 解决所有问题。通过数据转换，将复杂的认知行为（规划、反思）编码进模型权重，是提升鲁棒性的关键。
- SFT 依然有效：在长程任务中，经过精心筛选和格式化的 SFT 数据，比不稳定的 RL 信号更易于收敛且效果显著。
局限：
- 环境局限于 Wikipedia，领域覆盖有限。
- 目前主要依赖 SFT，RL 如何注入高层策略（如规划、错误恢复）仍是未解之谜。
这篇论文证明， “可验证的环境” + “正确的数据转换” ，足以让中等规模模型在搜索任务上实现质的飞跃。对于资源有限的团队，这是一条极具性价比的进化路径。
