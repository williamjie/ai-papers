论文 : Beacon: Knowing When and How to Perform Agentic Visual Reasoning链接 : https://arxiv.org/abs/2607.28595现在的多模态大模型（MLLM）Agent 有个通病：不管题目难易，上来就疯狂写代码调用工具。这不仅拖慢推理速度，还容易引入额外的幻觉错误。Beacon 这篇论文直击痛点，提出了一套强化学习框架，让模型学会“看菜下碟”——简单题直接答，难题才动刀。
### 现有方案的痛点：工具滥用与收益抵消我们常认为给模型加上代码解释器（Code Interpreter）就能提升复杂视觉推理能力。但 Beacon 作者通过深入分析发现，现有的 Agentic MLLM（如 Thyme, DeepEyes-V2, Metis 等）存在严重的**模式适应性（Mode Adaptiveness）**缺失。
反直觉发现 ：在多数现有模型中，工具带来的性能增益（Tool-Gain）几乎被其引入的错误（Tool-Harm）完全抵消。
作者定义了“文本易解”和“文本难解”样本。理想情况下，模型应在“文本易解”时保持静默，在“文本难解”时积极调用工具。然而实验显示，现有模型的 MAmean（模式适应性得分）普遍在 50% 左右徘徊，甚至低于随机猜测。这意味着它们要么盲目信任工具，要么完全拒绝工具，缺乏基于任务难度的动态判断能力。
### 核心 Insight：按需奖励与提示引导Beacon 的核心贡献在于其强化学习（Reinforcement Learning, RL）阶段的两项关键设计，旨在解决“何时用”和“怎么用”的问题。
1. 必要性感知自适应奖励（Necessity-Aware Adaptive Reward, NAAR）
传统 RL 只关注最终答案对错，导致模型倾向于通过调用工具来“碰运气”。NAAR 引入了基于组内表现的动态奖惩机制：
- 简单题惩罚过度推理：如果一组 rollout 中已有纯文本回答正确，那么使用代码并答对的样本仅获得 0.25 的奖励，而纯文本答对获得 1.0。这迫使模型在不需要工具时保持简洁。
- 难题鼓励工具探索：如果组内所有纯文本回答均错误，使用代码并答对的样本将获得 1.0 的全额奖励。
这种设计巧妙地平衡了效率与能力扩展，避免了因过度抑制工具使用而损害模型解决复杂问题的能力。
2. 提示引导的能力扩展（Hint-Guided Capability Expansion, HCE）
对于 RL 中那些连最强策略都难以解决的“硬骨头”，传统方法往往直接丢弃或给予低奖励，造成数据浪费。Beacon 引入专家模型（Gemini-3.1-Pro）生成无答案的中间步骤提示（Hint）。
- 在训练时，将 Hint 注入 prompt 引导模型探索正确的工具使用轨迹。
- 关键点：在计算策略更新时，移除输入中的 Hint，仅保留生成的轨迹。这使得模型能将“被引导出的能力”内化为自身的泛化能力，而非依赖外部提示。
### 关键结果：真正的性能跃升Beacon 基于 Qwen3-VL-8B-Instruct 进行训练，在 13 个涵盖高分辨率搜索、空间推理、图表理解等基准测试中表现优异。

### 工程启示与局限对于正在构建多模态 Agent 的工程师来说，Beacon 提供了两个重要参考：
- 奖励函数设计：不要只奖励“做对”，要奖励“做对且高效”。在 RLHF 或 GRPO 训练中，引入基于任务难度的条件奖励，可以显著降低推理成本。
- 硬样本挖掘：利用强模型生成中间步骤提示来辅助弱模型探索，是一种低成本提升复杂推理能力的手段。
当然，该方法依赖强大的专家模型（如 Gemini）来生成 Hint 和筛选数据，这在私有化部署或算力受限场景下可能面临挑战。此外，目前的评估主要基于静态基准测试，在动态、长程交互的真实 Agent 场景中，其适应性仍需进一步验证。
