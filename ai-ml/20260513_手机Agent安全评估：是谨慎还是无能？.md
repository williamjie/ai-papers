# 手机Agent安全评估：是谨慎还是无能？

**日期**: 2026-05-13

---

论文 : Safe, or Simply Incapable? Rethinking Safety Evaluation for Phone-Use Agents链接 : https://arxiv.org/abs/2605.07630当手机 Agent 面对一个高风险操作（比如自动扣费）时，它没造成损失，我们就能放心地说它“安全”吗？腾讯混元团队最新发布的 PhoneSafety 基准给出了一个反直觉的答案： 不，没出事可能是因为它太弱，根本看不懂屏幕或点不到按钮。
这篇论文的核心贡献在于指出了当前手机 Agent 安全评估中最大的混淆项： “无害结果”并不等于“安全决策” 。
### 现有评估的盲区在传统的 GUI Agent 评估中，我们通常看任务是否完成，或者最终是否造成了损害。但在手机端，一个错误的点击可能导致隐私泄露或资金损失。
论文提出了一个关键洞察：在安全关键瞬间（Safety-Critical Moments），Agent 的行为可以分解为三种截然不同的结果：
- Safe Action（安全动作）：Agent 识别了风险，选择了拒绝、询问用户或取消操作。这是真正的安全。
- Unsafe Action（不安全动作）：Agent 理解了界面，但做出了错误的选择（如直接点击确认支付）。这是对齐或判断力的失败。
- Failing to do anything useful（无效操作）：Agent 点击了无关区域、页面未响应或动作错位。虽然最终也没扣费，但这只是因为 Agent “无能”，而非“谨慎”。
如果像传统评测那样，只统计“最终是否造成损害”，那么 Case 2 和 Case 3 都会被误判为“安全”。这会导致我们对弱模型的高估，以及对强模型误诊。
### PhoneSafety 基准设计为了解决这个问题，作者构建了 PhoneSafety 基准，包含 700 个从真实手机交互中提取的安全关键瞬间，覆盖 130+ 个应用。
核心方法论：
- 局部决策评估：不评估完整任务流程，而是聚焦于“下一步动作”。给定用户指令、历史交互和当前截图，让模型预测下一步操作。
- 三元分类：严格标注每个场景下的“安全动作”和“不安全动作”参考行为，将模型输出归入上述三类。
- 真实轨迹挖掘：基于 4,512 条真实设备操作轨迹（约 75K 步）挖掘风险点，而非合成数据，确保场景的复杂性。
### 关键实验结果作者评估了 8 款代表性手机 Agent（包括 Gemini 3.1 Pro, Claude Opus 4.6, Kimi 2.5 等），发现两个重要现象：
#### 1. 通用能力 ≠ 安全性通用任务执行能力强的 Agent，不一定在风险面前更谨慎。
- Claude Opus 4.6：通用能力排第 3（53.0%），但安全动作率排第 2（67.0%），优于通用能力更强的 Seed 2.0 Pro。
- MobileAgent 3.5：通用能力排第 4（52.8%），但安全动作率仅排第 6（26.7%）。
- 相关性分析显示，通用能力与安全动作率的 Spearman 相关系数仅为 0.515，存在显著错位。
#### 2. “无效操作”是能力信号，而非安全信号这是论文最精彩的发现。高比例的“无效操作”通常意味着模型在视觉 grounding 或操作执行上存在短板，而非出于安全考虑。

- Kimi 2.5 的问题在于“瞎指挥”：它有 77.6% 的概率能执行动作，但在风险面前，30.3% 的次数选择了不安全操作。它不是不能动，是动错了。
- AutoGLM 9B 看起来“很安全”（不安全率仅 13.9%），但这是因为它在 62.1% 的情况下完全无法执行有效动作。它的“无害”源于无能。
#### 3. 失败模式的场景差异- Safety（拒绝有害指令）：失败主要表现为 Unsafe Action。模型能看懂，但没守住底线。
- Confirm/OP/TR/PM（确认/防误触/陷阱/权限）：失败主要表现为 Failing to do anything useful。例如在复杂的陷阱界面中，AutoGLM 的安全动作率仅 1.3%，98.7% 为无效操作。
### 工程启示- 不要只看最终结果：在评估手机 Agent 时，必须拆解“下一步动作”。如果一个模型在高风险场景下频繁出现“点击空白处”或“动作错位”，它并不比直接点击确认的模型更安全，只是还没触发后果。
- 安全与能力解耦：提升通用视觉 grounding 能力（减少无效操作）并不直接提升安全性，甚至可能暴露出更多的 Unsafe Action（因为能执行了，但策略没对齐）。因此，SFT（监督微调）或 RLHF 需要针对“风险场景”单独优化策略，而不仅仅是增强感知能力。
- 评估协议的影响：论文通过协议消融实验发现，改变“严格/最小”安全协议会大幅改变 Safe/Unsafe 的分类，但 CFR（无效操作率）保持不变。这进一步证明 CFR 是一个独立于安全策略的纯能力指标。
### 局限与展望PhoneSafety 主要基于中文安卓生态的静态截图评估，尚未涵盖动态交互或对抗性攻击。但对于追求落地的工程师来说，它提供了一个清晰的诊断框架： 区分“不敢动”和“动不了” 。
只有当模型既能“看懂”又能“选对”，才配称为安全。
