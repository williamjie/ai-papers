论文 : OmniPro: A Comprehensive Benchmark for Omni-Proactive Streaming Video Understanding链接 : https://arxiv.org/abs/2605.18577做实时视频 Agent 的同学肯定头疼过一个问题：现在的模型到底能不能“主动”说话？大多数所谓“流式理解”基准，本质上还是离线切片 QA，或者依赖固定时间戳轮询。这种测试掩盖了模型在真实连续流中“何时开口、说什么”的核心能力缺失。OmniPro 的出现，填补了这个空白，它是第一个真正联合评估多模态感知、主动响应和多样化视频理解任务的基准。
### 现有方案的痛点：伪主动与单模态依赖现有的主动流式评测（如 StreamingBench-Pro, OVO-Bench-Pro）存在三个致命缺陷，导致它们无法区分真正的 Omni-proactive 模型和普通的视觉模型：
- 缺乏真正的主动性：多数基准采用每秒轮询或预设时间点查询，模型是被动的回答者，而非主动的观察者。
- 模态单一：主要依赖视觉信号，忽略了语音（Speech）和非语音声音（Non-speech sound，如环境音）。现实中，很多触发事件（如警报声、哨声）首先出现在音频中。
- 任务狭窄：仅覆盖简单的警报或计数，缺乏对监控、定位、叙述和预测推理等复杂认知能力的考察。
### 核心设计：双模协议与全模态数据OmniPro 的设计直觉非常清晰： 要测出模型的“主动”能力，必须给它完整的连续流，并允许它自由决定输出时机。
1. 数据构建：84% 的音频依赖基准包含 2,700 个人工验证样本，覆盖 9 个子任务（如即时事件警报、实时状态监控、去重计数等）。最关键的是， 84% 的样本需要音频信号 。每个样本都标注了模态隔离标签，这使得我们可以精确分析模型是“听到了”还是“看到了”。
2. 双模评估协议（Dual-Mode Protocol）
这是 OmniPro 最具工程价值的创新：
- Probe Mode（探测模式）：针对任何 VLM。在触发点前后各查询一次（前 -5s 到 -2s，后 0s 到 +3s）。这测试的是内容理解能力，即模型是否具备相应的知识。
- Online Mode（在线模式）：针对支持流式推理的模型。模型接收连续帧，自主决定何时输出。这测试的是真正的主动响应能力。
### 关键结果：差距巨大且长尾效应明显论文评估了 11 个代表性模型（包括 Gemini-3-Flash, Qwen2.5-Omni, MiniCPM-o 4.5 等），揭示了几个残酷的事实：
1. 闭源与开源的巨大鸿沟在 Probe 模式下，Gemini-3-Flash 的平均准确率达到 40.4% ，而最佳开源模型（video-SALMONN 2+）仅为 22.1% 。在推理级任务（如步骤指导 Step-Inst.）上，差距更是拉大到 76.3 vs 31.6 。
2. 音频有用，但利用效率参差不齐引入音频（A+V）相比纯视觉（V）有显著增益，范围为 +2.4% 到 +11.1% 。但不同模型对音频的依赖程度差异巨大：
- video-SALMONN 2+ 极度依赖音频（Audio-only 17.5 vs Video-only 11.0）。
- Qwen3-Omni 则更偏向视觉驱动（Video-only 20.2 vs Audio-only 9.8）。
3. 长时程性能崩塌随着视频时间推移，模型性能急剧下降。在长时程（>180s）触发点上，模型平均仅保留了短时程性能的 37% 。特别是 MiniCPM-o 4.5 在 Online 模式下，长时程 F1 从 29.1 暴跌至 0.3 ，几乎完全失效。
4. 非语音声音是最大短板所有模型在需要“视觉+非语音声音”（如环境音）的触发任务上表现最差（F1/Accuracy 仅在 15.3–22.3 之间）。这说明当前 Omni-LLM 对复杂环境音频的感知能力仍然薄弱。
### 工程启示对于正在构建实时视频 Agent 或监控系统的工程师，OmniPro 提供了明确的优化方向：
- 不要迷信“流式”标签：如果你的模型在 Online Mode 下长时程表现崩盘，说明其时序记忆机制（如 Memory Bank 或 KV Cache 管理）存在严重缺陷。
- 重视音频通道：84% 的触发依赖音频，但在实际部署中，很多团队仍只接入视频流。加入非语音声音识别模块可能带来 +10% 以上的性能提升。
- 区分“理解”与“主动”：使用 Probe Mode 快速筛选模型的理解能力，再使用 Online Mode 评估其交互逻辑。两者差距大的模型，说明其“何时说话”的决策头（Decision Head）训练不足。
### 局限与展望OmniPro 目前主要依赖人类验证的样本，虽然质量高但扩展成本高。此外，非语音声音的弱表现提示我们，未来的 Omni-LLM 需要更细粒度的音频编码器，而不仅仅是 ASR（自动语音识别）。对于长视频理解，如何平衡计算成本与记忆持久性，仍是下一个核心挑战。
