# ⭐⭐⭐ 别急着抽象：LLM Agent 的经验为何难成技能？

**日期**: 2026-05-26

---

论文 : SkillEvolBench: Benchmarking the Evolution from Episodic Experience to Procedural Skills链接 : https://arxiv.org/abs/2605.24117Agent 领域有个迷思：只要让模型多跑几次任务，把成功的轨迹存下来，它就能“学会”技能。这篇论文直接泼了一盆冷水： 当前的 LLM Agent 很难将一次性的经验（Episodic Experience）提炼为可复用的程序化技能（Procedural Skills）。
作者构建了 SkillEvolBench，专门测试从“跑通任务”到“形成技能”的进化过程。结论很扎心：现在的 Agent 大多只是在打补丁，一旦环境稍微变化，那些所谓的“技能”就失效了，甚至不如直接回放原始轨迹。
### 痛点：经验 ≠\neq= 技能现有的 Agent 基准测试（如 SWE-bench, WebArena）主要看任务能不能完成。但完成一次任务留下的轨迹（Trajectory）充满了噪声：特定的输入、偶然的成功、错误的假设。
如果直接把轨迹存进记忆库，那是“死记硬背”；如果试图从中提取通用步骤，那就是“技能形成”。SkillEvolBench 的核心洞察在于： 区分这两者需要冻结评估。 只有在禁止 Agent 在测试时实时修正（Test-time Repair）的情况下，才能看出它到底是不是真的学会了通用逻辑。
### 方法拆解：冻结部署与角色演进这个基准的设计非常硬核，分为三个阶段：
- 获取阶段（Acquisition）：Agent 尝试解决基础任务、增强任务和变体任务。每次尝试后，系统会记录轨迹并给出验证器反馈（Verifier Feedback）。
- 技能演化（Skill Evolution）：一个独立的“技能作者”模块根据轨迹和反馈，决定是否写入新技能或修改旧技能。这里对比了两种初始化：
Self-Generated：从零开始，完全靠 Agent 自己悟。
- Curated-Start：提供人工编写的、有缺陷的初始技能，看 Agent 能否通过经验修复它。
- 冻结部署（Frozen Deployment）：这是最关键的一步。库被冻结，Agent 只能用现有的技能去解决更难的测试题：
Context Shift：任务背景变了，但逻辑没变。
- Adversarial Shortcuts：存在捷径能骗过浅层检查，看 Agent 是否依赖捷径。
- Composition：需要组合多个技能才能解决。
### 关键结果：抽象是有损的论文在 10 种模型配置和 3 个 Agent Harness（Claude Code, Codex CLI, Gemini CLI）上做了实验。数据揭示了几个反直觉的现象：
#### 1. 原始轨迹往往优于提炼后的技能这是最打击人的发现。图 4 显示，在大多数情况下， Raw-Trajectory（直接复用原始轨迹） 的表现优于 Skill-Based Conditions。
- Claude Opus 4.6 在 Self-Generated 模式下，虽然 LSR（学习成功率）提升了 5.5%，RSR（重放成功率）提升了 10.0%，但在 ESR（冻结部署成功率）上反而下降。
- GPT-5.4 在 Curated-Start + Always 更新策略下，ESR、ARSR 和 CompSR 有提升，但 CSSR（上下文迁移能力）下降了。
这说明当前的抽象过程是 有损的（Lossy Abstraction） ：提炼技能时丢弃了原始轨迹中那些对后续任务至关重要的上下文线索。
#### 2. “一直更新”策略并不总是更好直觉上，每次尝试后都更新技能库应该能覆盖更多情况。但实验显示， + Always 策略引入了“过程杂乱（Procedural Clutter）”。
- Gemini 3.1 Pro 在 Experience 模式下 LSR/RSR 提升明显，但在 + Always 模式下增益大幅缩水。
- 更多的更新导致技能库充满了针对特定 episode 的补丁，反而干扰了通用逻辑的形成。
#### 3. 不同模型失效模式不同- GPT-5.4：擅长抵抗捷径（Adversarial），但不擅长隐式调用（Context Shift）。
- Gemini 3 Flash：上下文迁移能力强，但极易被捷径误导。
- Claude Sonnet 4.6：在某些维度提升明显，但在对抗性任务上跌了 10.0%。
### 工程启示：别迷信“自动进化”
对于正在构建 Agent 系统的工程师，这篇论文有几个直接建议：
- 不要盲目追求全自动技能生成：目前的 LLM 还做不到从噪声轨迹中稳定提取鲁棒技能。Self-Generated 模式下的增益极不稳定。
- 人工介入的“种子技能”更有价值：Curated-Start 设置表明，提供一个有缺陷但结构正确的人工技能，比让模型从零开始摸索要有效得多。人类负责定义骨架，Agent 负责通过经验填补血肉。
- 警惕“捷径依赖”：如果你的 Agent 在简单任务上表现完美，但在稍微复杂一点的任务上崩盘，很可能它只是学会了针对特定测试用例的 Hack，而不是真正的程序化逻辑。引入 Adversarial 测试是必要的。
- 原始轨迹是宝贵的参考：在技能抽象技术成熟之前，直接检索和复用历史成功轨迹（RAG-like approach）可能比强行提炼“最佳实践”文档更可靠。
### 局限与展望SkillEvolBench 目前仅覆盖 6 个环境、180 个任务，虽然设计精良，但覆盖面有限。此外，它主要评估的是文本形式的技能描述（SKILL.md），对于代码脚本或二进制工具的演化评估尚浅。
未来的方向可能在于： 如何设计更好的“技能作者”提示工程 ，或者引入更结构化的中间表示（如代码片段而非纯文本步骤），以减少抽象过程中的信息丢失。在那之前，请对你的 Agent 保持一点怀疑精神：它真的学会了，还是只是记住了？
