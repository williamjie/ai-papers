# 激活 Steering 在多轮对话中的崩溃与修复

**日期**: 2026-05-12

---

论文 : Prompt-Activation Duality: Improving Activation Steering via Attention-Level Interventions链接 : https://arxiv.org/abs/2605.10664在 LLM 应用开发中，我们常面临一个两难选择：微调（Fine-tuning）效果好但成本高、难迭代；提示工程（Prompting）灵活但效果不稳定。 激活导向（Activation Steering） 试图走中间路线——在推理时通过修改内部激活状态来引导模型行为，无需更新权重。
然而，这篇论文揭示了一个被严重忽视的工程陷阱： 在状态式多轮对话中，传统的残差流激活导向会导致连贯性灾难。 如果你正在构建需要长期保持人设的 Agent，这篇论文提供的 GCAD 方法可能是你目前最需要的“补丁”。
## 问题：为什么 Steering 在多轮对话中会崩？
现有的 Persona Vector 方法（如 Chen et al., 2025）通常的做法很简单：
- 提取正向和负向提示下的激活差异，得到一个“人格向量”。
- 在推理时，将向量加到每一层的残差流（Residual Stream）中。
在单轮生成中，这看起来很完美。但在多轮对话（Autoregressive Generation）中，问题出现了。
LLM 使用 KV Cache 来加速推理。这意味着之前生成的 token 的 Key 和 Value 会被缓存并重复使用。当你把一个人格向量强行注入到残差流时，这个扰动会被写入 KV Cache。随后的 token 在注意力机制中会不断“回忆”这些被污染的状态。
论文将这种现象称为 KV-cache Contamination（KV 缓存污染） 。原本局部的扰动，随着对话轮次增加，在缓存中累积，最终导致模型输出变得重复、离题甚至逻辑崩溃。图 1 显示，标准 Steering 在 Turn 10 时连贯性分数（Coherence Score）从 76.6 暴跌至 57.9，漂移量（Drift）高达 -18.6。
有趣的是，单纯依靠 System Prompt 控制人设时，连贯性却非常稳定。这说明问题不在于上下文长，而在于 残差流注入的方式破坏了模型原本的处理路径 。
## 方法拆解：GCAD 的三个关键设计为了解决这个问题，作者提出了 Gated Cropped Attention-Delta (GCAD) 。核心 Insight 是： 不要直接在最后的残差流里“撒胡椒面”，而要模仿 Prompt 的作用路径，在注意力层面进行更精细的干预。
GCAD 有三个核心组件：
### 1. 提取路径重构：从残差流到注意力输出论文通过数学分解证明，Persona Vector 中真正携带“人设信号”的主要是自注意力机制（Self-Attention）的路径，而 MLP 路径和 Embedding 差异往往携带的是上下文噪声或表面内容。
因此，GCAD 不再提取全层的残差差异，而是专门提取 Attention Output 的差异。
### 2. 裁剪（Cropping）：只保留 System Prompt 的贡献这是解决 KV Cache 污染的关键。在提取 Steering Signal 时，标准方法会平均所有 Response Token 的激活。GCAD 则只截取 System Prompt Token 对 Attention 的贡献（即 Equation 7）。
- Why? 这样提取出的向量只反映“系统指令如何重塑注意力”，而不包含“模型自己生成的内容”。
- Effect: 避免了将生成的、带有噪声的响应状态重新注入并污染后续的 KV Cache。
### 3. 门控（Gating）：Token 级别的动态调节标准 Steering 对所有 Token 使用相同的系数 α\alpha ，这导致几乎所有 Token 都被强行推向人设方向，造成过度饱和。
GCAD 引入了一个 Token-level Gate （Equation 10）。它计算当前 Token 的 Query 与 System Prompt 的 Key 之间的兼容性（Cosine Similarity）。
- 逻辑：如果当前 Token 已经很符合人设（高兼容性），就减少干预；如果不符合，就加强干预。
- 结果：恢复了类似自然 Prompting 的“稀疏对齐”模式，而不是均匀覆盖。
## 关键结果：稳住了吗？
在 Qwen2.5-7B 和 Llama-3.1-8B 上的 15 种人格特质实验中，GCAD 表现显著优于标准基线。

具体案例中，对于“Sycophantic”（奉承）特质，标准方法在 Turn 5 连贯性仅剩 18.3，而 GCAD 保持在 62.5。对于“Humorous”（幽默）特质，标准方法在 Turn 5 连贯性跌至 0.5（几乎不可读），GCAD 则稳定在 80.1。
消融实验（Table 2）进一步证实：
- 去掉裁剪 (w/o crop)：连贯性再次恶化，证明裁剪对防止 KV Cache 污染至关重要。
- 去掉门控 (w/o gate)：人设表达波动变大，证明门控有助于稳定控制强度。
## 工程启示- 多轮对话慎用标准 Steering：如果你正在构建角色扮演的 Agent，直接使用 h + alpha * vector 的方法在多轮后极大概率会失效。
- 干预位置很重要：在注意力输出层（Attention Head Output）进行干预，比在残差流（Post-MLP）更稳定，因为这更符合模型处理指令的自然路径。
- 动态权重优于静态权重：引入简单的 Query-Key 相似度作为门控，能以极低的计算成本（仅一次点积）显著提升长程稳定性。
## 局限与展望GCAD 目前主要验证在 Persona Steering 上，对于推理能力（Reasoning）或知识型任务的 Steering 效果如何，论文未做深入探讨。此外，裁剪操作依赖于准确识别 System Prompt Token 的位置，在复杂的多轮历史中（System Prompt 可能被截断或混合），如何高效实现“Cropping”仍需工程优化。
总的来说，GCAD 为激活导向工程提供了一个更鲁棒的多轮对话范式： 少即是多，精准干预优于暴力注入。
