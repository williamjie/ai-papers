论文 : From Prompt Injection to Persistent Control: Defending Agentic Harness Against Trojan Backdoors链接 : https://arxiv.org/abs/2605.31042当 LLM 代理（Agent）从聊天窗口走向本地工作区，安全边界发生了根本性位移。攻击者不再需要一次性说服模型，而是可以将恶意指令碎片化地写入文件、记忆或配置中，等待未来某个时刻被触发。这种“特洛伊木马”式的多步攻击，让现有的单轮防御体系形同虚设。
### 为什么现有防御失效了？
传统的提示注入（Prompt Injection）防御大多关注当前对话上下文。然而，在本地代理环境（如 OpenClaw 风格的 Harness）中，模型具备读写文件、调用工具和跨会话复用状态的能力。
⚠️ 关键洞察 ：攻击者可以将无害的规则分散在不同文件中。例如，一个项目笔记要求生成诊断报告，而另一个配置文件定义该报告需引用私有数据。单独看每个步骤都正常，但组合起来就构成了不可逆的数据泄露。
论文指出，现有的基准测试（如 AgentDojo、InjecAgent）在面对 GPT-5.4 等强基座模型时，攻击成功率（ASR）几乎为零。这是因为现代模型对单轮显式注入具有极强的识别能力。但一旦攻击转化为 持久化的工作区状态 ，防御难度呈指数级上升。
### ClawTrojan：首个多步特洛伊木马基准为了量化这一威胁，作者构建了 ClawTrojan 基准。它包含 362 个样本，覆盖编码、研究、办公等场景。与以往不同，ClawTrojan 评估的不是单次动作的安全性，而是整个攻击链的持久化能力。
实验结果显示，在 GPT-5.4 环境下，无防御状态的 ASR 高达 95.5% 。这意味着绝大多数强模型在面对精心设计的多步工作区污染时，都会中招。
### DASGuard：溯源与清洗的动态防御针对这一痛点，论文提出了 DASGuard （Detect, Attribute, Sanitize）。其核心直觉是： 不要只问“这个动作是否安全”，而要问“这个内容是否源自可信源头” 。
DASGuard 的工作流程分为三步：
- 检测（Detect）：扫描敏感文件中的控制类文本，结合规则匹配、嵌入相似度及历史发现进行判定。
- 归属（Attribute）：构建内容来源图，标记每个文本片段的来源（用户、系统、外部工具或工作区文件）。
- 清洗（Sanitize）：如果检测到未授权的控制内容写入敏感区域（如记忆、策略文件），则阻止操作或进行影子副本清洗。
这种设计的关键在于 跨步状态追踪 。DASGuard 会记录之前的发现，当后续步骤尝试复用这些被污染的内容时，能立即识别并阻断。
### 实验数据：降维打击在 ClawTrojan 基准上的对比实验极具说服力。以下是主要结果汇总：
方法 ASR (%) ↓ 全链 ASR (%) ↓ 渗透率 (%) ↓ GPT-5.4 (无防御) 95.5 89.1 92.2 ClawKeeper 94.3 86.1 90.3 MELON 92.6 83.8 87.5 PromptShield-8B 88.7 77.9 82.7 CaMeL 74.3 52.5 62.3 DASGuard 15.8 5.9 10.1可以看到，传统防御方法（如 ClawKeeper、MELON）虽然能拦截部分显式恶意动作，但对持久化攻击链的阻断效果有限。而 DASGuard 将 ASR 从 95.5% 骤降至 15.8%，全链成功率更是低至 5.9%。
消融实验进一步证实了**来源标签（Source Labels）**的重要性。移除来源标签后，DASGuard 的性能几乎退化到无防御水平（ASR 升至 92.7%），这证明了“内容溯源”是该方法的核心支柱。
### 工程启示与局限对于正在构建本地 Agent 的工程师来说，这篇论文给出了明确的安全建议：
- 隔离数据与指令：永远不要假设工作区文件是可信的指令源。
- 实施影子写保护：在文件提交前，对变更内容进行来源审计和清洗。
- 关注持久化风险：防御重点应从单次对话扩展到跨会话的状态一致性。
当然，DASGuard 也有局限。它依赖于代理运行时能提供内容来源钩子（Hooks），且对干净任务的误报率（FPR）略高（13%）。但在安全性优先的场景下，这种适度的保守策略是可接受的。
随着 Agent 越来越深入地介入实际工作流， “信任但验证” 必须升级为 “溯源并清洗” 。DASGuard 提供了一个可落地的范式，值得所有本地代理架构参考。
