# AI Agent 搞不定应急响应？阿里开源 SecRespond 基准测试

**日期**: 2026-07-30

---

论文 : SecRespond: Benchmarking AI Agents for Real-World Post-Compromise Incident Response链接 : https://arxiv.org/abs/2607.26791现在的 AI Agent 吹得天花乱坠，但在真正的网络安全实战中，它们真的能干活吗？阿里通义实验室最近抛出的 SecRespond 基准测试给出了一个略显尴尬的答案： 目前的顶级模型在“发现”问题上表现尚可，但在“彻底修复”上几乎全军覆没。
这篇论文填补了 AI 安全评估的一个巨大空白。以往的基准测试（如 CTF 挑战或漏洞挖掘）大多关注“攻前”阶段，即在一个干净的环境里找洞。但真实世界的应急响应（Incident Response, IR）发生在“攻后”，系统已经被入侵，磁盘里满是残留的恶意文件、被篡改的配置和噪音日志。SecRespond 是第一个针对这种 事后处置全流程 的基准测试。
### 为什么现有的评估不靠谱？
现有方案最大的痛点在于 环境过于理想化 。大多数测试要么是基于静态日志的推理，要么是 Docker 容器里的 CTF 题目。它们缺乏真实入侵留下的“法医证据”：比如攻击者为了持久化（Persistence）偷偷修改的系统服务、被擦除的部分痕迹，以及正常业务产生的并发噪音。
SecRespond 的设计直觉很硬核： 不给干净环境，只给烂摊子。
它构建了 10 个基于真实云主机快照的“网络靶场”（Cyber Ranges）。每个靶场都包含：
- 取证磁盘快照：只读，包含所有目录和入侵残留。
- 安全产品数据：实时告警、漏洞扫描结果、基线检查报告。
Agent 的任务不是简单的问答，而是要像真正的 SOC 分析师一样，调查主机、重构攻击链，并输出四份报告：入侵分析、漏洞验证、基线风险评估，以及最重要的—— 修复计划 。
### 核心设计：分层拆解与细粒度评估SecRespond 没有用简单的“对错”来评分，而是设计了一套 五维能力分类体系（Capability Taxonomy） ，包含 52 个具体能力和 280 个检查点。这种设计的目的是解决开放-ended 任务难以自动评估的问题。
这五个维度分别是：
- 入侵实体（Intrusion Entity）：能否找到恶意进程、文件和网络连接。
- 持久化机制（Persistence Mechanism）：能否发现定时任务、服务后门、注册表修改等隐蔽手段。
- 基线风险（Baseline Risk）：SSH 加固、权限审计等配置问题。
- 漏洞风险（Vulnerability Risk）：确认主机上存在的具体 CVE 弱点。
- 调查与响应质量（Investigation & Response Quality）：攻击链重构的完整性、修复方案的验证闭环。
评估采用 LLM-as-a-Judge 模式，由三个强模型独立打分，分为“检测”和“规划”两个轴。检测看是否发现了问题及证据充分性；规划看修复步骤的正确性和完整性。
### 实验结果：发现容易，修复难论文测试了 23 个前沿 LLM（包括 Claude Opus 4.7, GPT-5.5, Qwen3.7 Plus 等），结果揭示了几个反直觉的事实。
⚠️ 核心发现：检测与规划存在巨大鸿沟所有模型的“检测”得分都显著高于“规划”得分。以最强的 Claude Opus 4.7 为例，其平均检测得分为 79.0%，但规划得分仅为 65.7%。而 GPT-5.5 的差距更夸张：检测 70.7%，规划仅 36.0%， 差距高达 34.7% 。
这意味着什么？Agent 能顺着告警找到明显的恶意文件（如挖矿进程），但在后续步骤中往往“虎头蛇尾”。它们会建议杀掉进程、删除文件，却经常忽略 轮换泄露的凭证 、 封锁出站通道 或 验证业务服务健康状态 。没有模型能在任何一个靶场实现 100% 的检测和修复。

### 工程启示与局限对于正在落地 AI 安全运维的团队，这篇论文有三个关键指导意义：
- 不要指望 Agent “一键修复”：目前的 Agent 更适合做“辅助调查员”，提供线索和初步分析，而不是自动执行修复脚本。因为它们在长尾的修复步骤（如凭证轮换、服务重启验证）上极易遗漏。
- 模型选型需看“规划”而非仅看“检测”：如果只看能否发现漏洞，很多模型都能及格；但要看能否给出可执行的、完整的 remediation plan，差距就拉开了。建议优先测试 Claude Opus 系列或 GLM/DeepSeek 等强代码能力模型。
- 持久化机制是盲区：平均而言，Agent 对“入侵实体”的检测率达 75.4%，但对“持久化机制”（如 crontab、systemd timer、注册表）的检测率仅 58.8%。这是未来微调或 Prompt 优化的重点方向。
SecRespond 目前公开了数据集和评估框架，但它主要基于 Linux 和 Windows Server 的云主机场景。对于更复杂的混合云环境、容器逃逸后的横向移动追踪，以及实时交互式响应（而非离线快照分析），仍有巨大的探索空间。
