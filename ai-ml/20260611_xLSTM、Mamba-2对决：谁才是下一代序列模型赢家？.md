# ⭐⭐⭐½ xLSTM、Mamba-2 对决：谁才是下一代序列模型赢家？

**日期**: 2026-06-11

论文 : On Subquadratic Architectures: From Applications to Principles链接 : https://arxiv.org/abs/2606.12364Transformer 的二次方计算复杂度一直是工程落地的痛点。业界急需高效的子二次方（Subquadratic）架构来替代它，但 xLSTM、Mamba-2 和 Gated DeltaNet 到底谁更强？这篇来自 JKU 和 NXAI 的最新研究给出了硬核答案：在代码和时间序列等复杂任务上，xLSTM 全面胜出。
### 为什么标准基准测不出好坏？
以往大家喜欢用 HellaSwag 或 ARC 这种常识推理基准来刷榜。但在这些任务上，各种架构的差异微乎其微，根本看不出优劣。作者认为，只有把模型扔进 具有长程结构化依赖 的复杂场景，才能拉开差距。于是，他们选了两个硬核战场：代码预训练和时间序列预测。
### 核心 Insight：统一框架下的“记忆博弈”
论文最精彩的部分在于，它没有停留在调参层面，而是建立了一个统一的数学框架，把 xLSTM、Mamba-2 和 Gated DeltaNet 拆解为 线性注意力（Linear Attention）+ 门控机制 。
在这个视角下，架构的本质差异体现在两个原语能力上：
- 累加（Accumulation）：处理无界长度的计数任务。
- 状态追踪（State Tracking）：处理有限状态机的有序更新。
⚠️ 关键发现 ：Mamba-2 的输入门和遗忘门是耦合的，这导致它在“计数”任务上表现糟糕；Gated DeltaNet 虽然引入了正交投影来覆盖旧值，适合检索，但会干扰累加过程。只有 xLSTM 通过独立的指数输入门，实现了灵活的权重修正，完美兼顾了累加与追踪。
### 实验数据：xLSTM 的统治力作者进行了三项大规模对比实验，结果非常直观。
1. 代码预训练（400M 参数混合模型）
在 HumanEval pass@64 指标上，xLSTM [7:1] 在所有数据配置下均领先：
- 20B Code Tokens: 比第二名高出 1.43%- 100B Code Tokens: 领先优势缩小至 0.90%- 混合语料: 依然保持 1.81% 的显著优势2. 知识蒸馏（从 Qwen3-4B 蒸馏）
在代码生成任务中，xLSTM [1:0] 作为即插即用的线性注意力替换方案，平均表现最佳：
- HumanEval: xLSTM (0.831) > Gated DeltaNet [-1,1] (0.813) > Default GDN (0.802)
- MBPP+: 虽然 Gated DeltaNet 略胜一筹，但 xLSTM 综合平均分（0.768）高于其他两者（约 0.755）。
3. 时间序列预测（GIFT-Eval 基准）
在 1M 到 40M 参数规模下，xLSTM [3:1] 全面压制对手。以 10M 参数为例：
- MASE: xLSTM (0.733) vs Mamba-2 (0.767)
- CRPS: xLSTM (0.508) vs Mamba-2 (0.525)
4. 合成任务验证（长度泛化）
在 Majority 计数和 Parity 状态追踪任务中，只有混合架构 xLSTM [1:1] 能同时实现完美的长度泛化。Mamba-2 在长度扩展至 2048 时，准确率直接崩盘至 0.241。
### 工程启示：如何选型？
这篇论文给工程师提供了明确的选型指南：
- 如果你做代码大模型或 Agent：优先考虑 xLSTM 架构。它在处理语法树、变量绑定等结构化依赖时，比 Mamba-2 更稳健。
- 如果你做时间序列预测：xLSTM 在小中规模（1M-40M）下是首选。虽然在大参数下差距缩小，但其稳定性更好。
- 架构设计直觉：不要迷信纯线性注意力。混合架构（如 xLSTM [m:s]）通过少量循环层（sLSTM）提供状态追踪能力，大部分线性层（mLSTM）负责高效累加，是目前平衡效率与性能的最优解。
### 局限与展望论文也坦诚了局限性：代码实验仅在 400M 参数下进行，时间序列实验未覆盖超大模型。此外，xLSTM 的训练稳定性仍依赖于特定的归一化技巧。未来需要更多大规模预训练数据来验证这一结论是否能在万亿参数级别延续。
