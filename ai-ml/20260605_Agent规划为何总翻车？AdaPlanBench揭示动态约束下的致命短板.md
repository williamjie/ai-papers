# ⭐⭐ Agent 规划为何总翻车？AdaPlanBench 揭示动态约束下的致命短板

**日期**: 2026-06-05

---

论文 : AdaPlanBench: Evaluating Adaptive Planning in Large Language Model Agents under World and User Constraints链接 : https://arxiv.org/abs/2606.05622现在的 Agent 应用里，最让人头疼的不是“能不能做”，而是“能不能在限制条件下改着做”。
真实世界充满动态约束：工具可能突然不可用（环境约束），用户偏好也可能中途变更（用户约束）。现有 Benchmark 大多假设约束在任务开始前就全量给定，这完全脱离了实际交互场景。AdaPlanBench 的出现，正是为了填补这一空白，它模拟了“边做边发现限制”的真实痛点，对构建鲁棒的 Agent 系统具有极高的参考价值。
### 为什么现有的评估不够用？
传统评估往往把 Agent 当成静态规划器。但在真实交互中，约束是**渐进式披露（Progressive Disclosure）**的。
比如你要烘干一个湿排球，你先用毛巾擦，系统反馈“家里没毛巾”；你再改用风扇，用户又反馈“我讨厌风扇太慢”。Agent 必须在多轮交互中，从反馈里推断出隐藏的环境限制和用户偏好，并动态重构计划。这种**双重约束（Dual Constraints）**下的自适应规划，才是 Agent 落地的核心难点。
### 方法拆解：不仅是测试，更是压力测试AdaPlanBench 的核心设计直觉在于**“让错误暴露约束”**。它不直接告诉 Agent 所有限制，而是当 Agent 提出违反约束的计划时，才揭示该约束。这种机制迫使 Agent 必须具备两个能力：
- 主动探索与推断：从局部反馈中反推全局限制。
- 记忆与修正：在累积的约束集上重新规划，而不是简单重试。
数据集基于 MacGyver 构建，包含 307 个家庭任务。通过自动化流水线，每个任务被注入环境约束（如“没有毛巾”）和用户约束（如“不喜欢噪音”）。这种设计不仅保留了开放式的动作空间，还通过多轮交互协议，精准评估 Agent 在信息不全时的适应力。
### 关键结果：最强模型也仅及格线边缘实验结果相当扎心。即使是目前最强的闭源模型 GPT-5，准确率也仅为 67.75% 。开源模型表现更差，Qwen3 系列普遍在 14%-30% 之间徘徊。
⚠️ 反直觉发现：有效计划率（VPR）高 ≠ 任务成功率高Gemini-3-Flash 和 Gemini-3.1-Pro 的 VPR 超过 90%，意味着它们很少因违反约束而终止对话，但最终准确率却低于 45%。这说明模型能“记住”已披露的约束，但无法在受限空间内找到真正有效的解决方案。

### 工程启示：如何提升 Agent 的鲁棒性？
- 显式记忆模块效果有限：研究尝试将已披露约束显式附加到 Prompt 中，准确率仅提升不到 3%。这说明瓶颈不在“遗忘”，而在“推理”。单纯增加上下文窗口无法解决复杂约束下的规划难题。
- 反馈机制需重构：传统的 Rubric 反馈（如指出物理合理性不足）反而可能导致 VPR 下降约 40%。模型倾向于修复最新指出的问题，却破坏了之前已满足的约束。工程上应避免简单的“纠错式”反馈，转而采用全局一致性校验。
- 重视用户偏好建模：环境约束相对客观（有无工具），而用户约束主观且多变。在构建 Agent 时，应引入专门的偏好对齐模块，而非仅依赖通用的指令跟随能力。
### 局限与展望目前 AdaPlanBench 仍局限于家庭场景，且为纯文本交互。未来需扩展到具身智能和多模态环境，以测试感知-行动闭环下的规划能力。此外，用户偏好的模糊性在现有数据集中被简化了，真实场景中如何处理“软约束”仍是巨大挑战。
对于工程师而言，这篇论文是一个警钟：不要高估当前 LLM 的动态适应能力。在构建生产级 Agent 时，必须为“规划失败后的重规划”设计专门的容错和状态管理机制。
