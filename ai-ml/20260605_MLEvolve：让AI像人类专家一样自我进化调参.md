论文 : MLEvolve: A Self-Evolving Framework for Automated Machine Learning Algorithm Discovery链接 : https://arxiv.org/abs/2606.06473AutoML 领域长期存在一个尴尬现状：Agent 虽然能写代码，但往往陷入“无记忆搜索”和“分支隔离”的泥潭。MLEvolve 试图打破这一僵局，通过引入图搜索和回顾性记忆，让 AI 具备类似人类专家的“自我进化”能力。
### 现有方案的痛点：为什么你的 Agent 还在盲目试错？
目前的 MLE Agent（如 AIDE、ML-Master）主要面临三大工程瓶颈：
- 分支信息隔离：传统的树搜索中，不同探索路径互不干扰。A 分支发现的优秀特征工程技巧，无法直接复用给 B 分支。
- 无记忆搜索：每次决策都基于即时反馈，缺乏对历史经验的累积。Agent 容易在长周期任务中重复犯同样的错误。
- 缺乏层级控制：规划与代码生成耦合，导致 Agent 经常“推倒重来”，迭代效率极低且难以稳定收敛。
### 核心拆解：MLEvolve 的三大进化引擎MLEvolve 的核心 insight 在于将搜索过程从“线性试错”升级为“经验驱动的图演化”。
#### 1. 渐进式蒙特卡洛图搜索 (Progressive MCGS)
传统 MCTS 是树结构，MLEvolve 将其扩展为图结构 G=(V,E)G=(V, E) ( V , E ) 。
- 跨分支引用边 (ErefE_{ref}​)：允许节点从其他分支甚至非相邻层级获取信息。当某个分支停滞时，Agent 可以“借鉴”其他强分支的方案进行融合（Multi-branch Aggregation）。
- 熵驱动的策略切换：引入基于香农熵的渐进调度。早期高熵阶段广泛探索，后期低熵阶段通过 Elite-Guided 策略聚焦于 Top-K 精英节点。实验显示，有效活跃分支数从早期的 4.8 逐渐收敛至后期的 2.8，实现了资源的高效集中。
#### 2. 回顾性记忆 (Retrospective Memory)
这是解决“无记忆”问题的关键。系统包含两部分：
- 冷启动知识库：针对特定任务类型（如图像分类、表格回归）预置领域先验，降低初始错误率。
- 动态全局记忆：自动累积搜索过程中的计划、代码、指标和分析日志。检索采用混合策略（BM25 + FAISS），并通过 RRF 融合排序。在 Debug 阶段，Agent 可直接查询历史相似错误记录，避免重复踩坑。
#### 3. 分层规划与自适应代码生成将“改什么”（Planner）与“怎么改”（Coder）解耦。根据搜索状态动态选择三种模式：
- Base 模式：从零生成完整代码，适用于初始阶段。
- Stepwise 模式：按模块逐步生成，适用于复杂流水线。
- Diff 模式：对现有代码进行局部补丁编辑。这是稳定迭代的关键，避免了全量重写带来的不可控风险。

### 工程启示：如何构建更聪明的 Agent？
- 记忆是长期优化的核心：不要指望 LLM 的内部知识能覆盖所有长尾错误。建立结构化的“失败案例库”和“成功模式库”，并在检索时结合语义与关键词，能显著提升 Debug 效率。
- 搜索策略需要动态调整：固定的探索系数（Exploration Constant）是低效的。根据任务进度动态收缩搜索范围，从“广撒网”转向“精耕作”，是节省计算资源的关键。
- 代码修改要“微创”：在迭代优化中，优先使用 Diff 模式进行局部修改，而非全量重写。这不仅能保留已验证的正确逻辑，还能大幅降低生成错误率。
### 局限与展望尽管 MLEvolve 表现优异，但其依赖强大的基础模型（如 Gemini-3.1-Pro-preview）和较高的计算资源（H200 GPU）。对于中小规模团队，如何轻量化“回顾性记忆”的检索开销，以及如何在小参数模型上实现稳定的 Diff 编辑，仍是落地过程中的挑战。
