# ⭐⭐⭐ SimWAM：训练时看未来，推理时只看眼前

**日期**: 2026-08-10

---

论文 : SimWAM: A Simple World Action Model for End-to-End Autonomous Driving链接 : https://arxiv.org/abs/2608.07468端到端自动驾驶的“世界模型”路线最近很火，但工程落地有个死穴：推理时还得生成未来视频帧，延迟高得没法上车。SimWAM 提出了一个极简思路： 把视频生成纯粹当作训练信号 。训练时让规划器看未来，部署时直接扔掉视频分支，只保留轻量级的动作专家。
### 现有方案的痛点目前的 World-Action Models (WAMs) 如 DriveLaW、DriveWAM 大多遵循“先想象再行动”（imagine-then-act）范式。规划器必须依赖生成的未来帧作为条件输入。这导致两个问题：
- 推理延迟爆炸：实时规划环路里塞进了昂贵的视频合成步骤，如图 1 所示，现有 WAM 的延迟普遍在 800ms 以上。
- 架构耦合过紧：视频生成器和规划器深度绑定，想换更强的视频模型或缩放规划器大小都很困难。
### 核心 Insight：隔离注意力掩码SimWAM 的核心设计在于 隔离注意力掩码（Isolated Attention Mask） 。
在联合训练阶段，预训练的视频专家（Video Expert）和轻量级动作专家（Action Expert）共享一个注意力流。
- 视频分支负责预测未来帧，学习交通动力学先验。
- 动作分支负责预测轨迹。
- 关键点：通过掩码设计，动作 Token 只能关注当前观测，完全看不见未来的视频 Token。
这意味着，动作专家在训练时吸收了视频分支对场景动态的理解（通过共享的当前观测表示），但在推理时，它根本不需要未来帧作为输入。训练结束后，直接丢弃视频 DiT，只保留动作 DiT。这就实现了“训练时看未来，推理时只看眼前”。
⚠️ 反直觉发现 ：消融实验表明，如果让动作分支也能看到未来视频 Token（双向注意力），PDMS 反而从 90.3 降到了 90.1。隔离不仅带来了效率，还提升了性能，说明“看未来”对规划器本身可能是噪声干扰。
### 强化学习优化：从 ODE 到 SDE单纯的模仿学习（Imitation Learning）容易受限于专家数据的质量。SimWAM 进一步引入了基于策略梯度（GRPO）的强化学习。
- 难点：流匹配（Flow Matching）通常是确定性的常微分方程（ODE），缺乏探索所需的随机性。
- 解法：将 ODE 转化为保留边缘分布的随机微分方程（SDE）。这使得模型能采样一组候选轨迹，利用 NAVSIM 的组合奖励函数进行优化。
- 效果：RL 阶段仅更新动作专家的 LoRA 适配器，PDMS 从模仿学习的 90.3 提升至 91.5。
### 关键结果在 NAVSIM 基准测试中，SimWAM 的表现令人印象深刻，尤其是考虑到它只使用了单目前置摄像头。

- 视频骨干可替换：将视频专家从 Wan2.1-1.3B 换成更强大的 Cosmos2.5（在驾驶视频上预训练），PDMS 提升了 0.2 分至 90.4，且无需修改动作专家或推理管线。
- 零样本迁移：在 nuScenes 上直接测试，平均碰撞率低至 0.04%，优于许多经过微调的基线模型。
### 工程启示- 解耦即正义：将“感知/预测”与“规划”在推理时彻底解耦，是降低自动驾驶系统延迟的关键。SimWAM 证明了世界模型的先验可以通过训练时的联合优化隐式转移，无需显式的未来生成。
- RL 的落地路径：通过 SDE 改造流匹配模型，为端到端规划器引入强化学习提供了一条可行路径。针对困难场景（Hard subset）进行 RL 微调，比全量数据训练效率更高。
- 分辨率性价比：实验显示，输入分辨率从 192×352 提升到 384×672 带来了显著的性能提升（+1.4 PDMS），但继续提升到 768×1344 收益递减且计算成本大增。384×672 是目前单目输入的甜点区。
SimWAM 没有追求复杂的算法堆砌，而是通过极简的架构设计解决了 WAM 落地的核心矛盾。对于正在探索世界模型在自动驾驶中应用的工程师来说，这是一个非常扎实且高效的基线参考。
