论文 : Share More, Search Less: Collaborative Parallel Thinking for Efficient Test-Time Scaling链接 : https://arxiv.org/abs/2605.27030在推理增强（Reasoning Augmentation）的大潮下，我们习惯用“并行采样”来换取准确率：开 64 个分支跑一遍，谁对听谁的。但这有个巨大的隐形浪费——每个分支都在重复造轮子。这篇来自北理工与小红书团队的论文指出： 平行搜索中的信息隔离是效率杀手 ，并提出了一种无需训练、即插即用的“协作式并行思考”（Collaborative Parallel Thinking, CPT）框架，让分支间实时共享发现，显著降低了冗余计算。
### 痛点：你在重复别人的发现现有的并行测试时扩展（Test-Time Scaling, TTS）方法，如 DeepConf 或简单的 Self-Consistency，核心逻辑是“独立探索，最后投票”。这意味着，如果分支 A 在第 1024 token 处推导出了关键约束 I1I_1 ​ ，分支 B 并不知道，它可能在后续步骤中花费大量算力重新推导 I1I_1 ​ 。
论文通过统计 HMMT 数据集上的信息单元发现：随着搜索进行，独立并行采样产生的**重复信息单元（Duplicate Information Units）**急剧增加，而新发现的信息越来越少。这种“信息孤岛”导致模型为了收集完整的决策信息，不得不进行大量的冗余探索。
### CPT 核心设计：共享池 + 自适应广播CPT 的直觉很简单： 让分支从“各自为战”变成“情报共享” 。但它没有简单地把所有分支的上下文拼在一起（那会爆炸），而是设计了三个关键组件：
-紧凑信息提取与去重池：
在每个固定 token 步长（如 2048 tokens）结束时，CPT 调用同一个模型从各分支中提取“紧凑信息单元”（中间结论、约束、反例等）。
- 这些单元被放入一个查询级共享池，并通过文本嵌入相似度阈值（τdup=0.75\tau_{dup}=0.75​=0.75）进行去重。这确保了共享内容是高密度、无冗余的决策信息，而非冗长的推理过程。
-上下文广播：
去重后的池子条目被序列化并注入到所有分支的输入上下文中。这样，后续步骤中，每个分支都能“看到”其他分支已经发现的线索，直接复用而非重新推导。
-自适应广播调度（Adaptive Broadcast Scheduling）：
这是最精妙的设计。过早共享会导致分支过早收敛，丧失探索多样性；过晚共享则浪费了前期积累的信息。
- CPT 监控“新信息增益率”。当边际收益下降至阈值 τstart\tau_{start}​（默认 0.4）时，开始广播；当收益进一步降至 τstop\tau_{stop}​（默认 0.1）时，停止同步，让分支自由运行至结束。这种机制平衡了探索与利用。

在端到端评估中（Figure 3），CPT 在相同的墙钟延迟（Wall-clock Latency）下，实现了更高的准确率。例如在 HMMT25 上，CPT 相比基线方法，在保持相近延迟的情况下，Pass@1 提升了数个百分比点。更重要的是， 生成 Token 数大幅减少 ，因为模型不再重复推导已知信息。
### 工程启示与局限对工程师的价值：
- 零训练成本：CPT 是纯推理时方法，无需微调或额外奖励模型，可直接集成到现有推理管道中。
- 延迟敏感场景友好：通过减少冗余 Token 生成，显著降低端到端延迟。对于需要快速响应的 Agent 系统，这种“少搜索、多协作”的策略比盲目增加并行数更有效。
局限与思考：
- Prefill 开销：CPT 通过更新输入上下文实现共享，在标准解码实现中可能触发重新 Prefill，带来额外的 FLOPs 开销（Table 3 显示 Info Extract 和 Dedup 占用了约 10-20% 的延迟）。未来需要关注 KV Cache 感知的共享机制。
- 同步粒度：目前仅在固定 token 步长同步，步内发现无法实时共享。更细粒度的注意力级共享可能是下一步方向。
CPT 揭示了一个被忽视的事实： 并行推理的效率瓶颈不在于算力不足，而在于信息流通不畅 。让模型“分享更多，搜索更少”，是提升 TTS 性价比的一条务实路径。
