论文 : Generative Compilation: On-the-Fly Compiler Feedback as AI Generates Code链接 : https://arxiv.org/abs/2607.13921让 LLM 写 Rust 代码，最大的痛点不是“写不出来”，而是“写完跑不通”。Rust 的所有权系统虽然强大，但对生成式模型来说简直是噩梦。传统做法是等代码全写完再扔给编译器报错，这就像你写了一万字才发现第一段有个错别字，后面的努力全白费了。
ETH Zurich 和 UC Berkeley 的这篇新论文提出了一个极其实用的概念： 生成式编译（Generative Compilation） 。它让编译器在 LLM 生成代码的过程中实时介入，提供即时反馈。这不是简单的语法检查，而是真正的语义级“边写边查”。
### 现有方案的死胡同目前处理 LLM 代码错误主要有两派：
- 事后诸葛亮（Post-Generation Feedback）：等模型生成完整文件后，运行编译器。
痛点：反馈太晚。如果第 5 行借用了变量，第 10 行又尝试可变借用，错误在第 4 行就已经注定发生。但模型直到第 20 行写完才知道错了。这导致大量无效 token 生成，且报错信息堆积如山，模型很难定位根源。
- 强行约束（Constrained Decoding）：在采样阶段过滤掉会导致错误的 token。
痛点：实现成本极高。需要重新实现语言语义（Rust 编译器代码量超 60 万行），且只能支持黑盒模型中的白盒访问，无法用于 GPT-4/Claude 等主流闭源 API。此外，它只是“静默过滤”，不告诉模型为什么错，模型学不到东西。
### 核心 Insight：Sealor（密封器）
论文的核心创新是一个叫 Sealor 的轻量级变换工具。它的直觉非常巧妙： 既然编译器只能检查完整程序，那我们就把半成品“补全”成完整程序再给编译器看。
具体流程如下：
- LLM 生成一个代码前缀（Partial Program）。
- Sealor 介入，保留已生成的语法结构，插入类型安全的占位符（如 holeval()），并闭合未完成的括号和块。
- 将这个“密封后”的完整程序发送给标准编译器（如 rustc）。
- 如果编译器报错，Sealor 将错误映射回原始前缀的位置，反馈给 LLM。
关键设计哲学 ：Sealor 必须满足 全局完备性（Global Completeness） 。即：如果一个前缀 有可能 被补全为合法代码，Sealor 绝对不能报错。否则就是误杀，会干扰模型生成真正正确的代码。同时，它追求 选择性健全性（Selective Soundness） ，尽早捕捉那些注定无法修复的死胡同（Dead Ends）。
这种设计避免了重新实现 Rust 类型系统的巨大工程负担，直接复用了 rustc 的强大诊断能力，且完全兼容黑盒 API。
### 实验结果：早报错，少犯错论文在 C-to-Rust 翻译和新 API 代码生成任务上，测试了 7 个前沿模型（包括闭源和开源）。对比基线是传统的“生成后反馈”。
指标 传统事后反馈 生成式编译 (On-the-Fly) 提升效果 编译器错误率 高 显著降低 减少无效重试次数 功能正确性 基准 提升 代码更健壮 错误检测时机 文件末尾 接近错误源头 避免错误级联具体表现上，生成式编译能检测到广泛类型的错误，且这些错误通常出现在生成的早期阶段。例如，在一个借用冲突的例子中，传统方法要在函数结束后才报错；而生成式编译在生成到第 4.5 行时就发出了警告，比传统方法提前了近一半的代码量。
这意味着模型可以在错误蔓延之前修正方向，而不是在一堆累积的错误中挣扎。
### 工程启示：如何让 AI 写 Rust 更靠谱？
- 不要只依赖 Prompt：对于强类型语言，单纯的 Prompt Engineering 效果有限。引入编译器的实时反馈回路是提升代码质量的低成本高回报手段。
- 黑盒模型也能用：你不需要微调模型或访问内部 logits。只要你的 LLM API 支持流式输出（Streaming），就可以实现这种“边写边查”的架构。
- 错误定位更精准：传统的批量报错会让模型困惑。生成式编译提供的诊断信息是局部的、聚焦的，模型更容易理解“哪里错了”以及“为什么错”。
### 局限与展望目前该方法主要在 Rust 上验证，且 Sealor 的实现依赖于对语言语法的深入理解。对于 Python 等动态语言，这种基于静态分析的实时反馈价值可能不如 Rust 显著。此外，Sealor 的完备性证明是在核心演算（Featherweight Rust）上完成的，实际 Rust 语言的复杂性可能导致边缘情况下的误报，尽管论文声称通过机制化验证在 Lean 中保证了性质。
总的来说，这是一篇工程价值极高的论文。它没有追求复杂的算法创新，而是巧妙地连接了 LLM 生成过程与传统编译器基础设施，为 AI 辅助编程提供了一个可落地的最佳实践。
