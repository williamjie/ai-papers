# 从失败中学习：CIPO 让 LLM 推理训练不再浪费错误

**日期**: 2026-05-19

---

论文 : Learning from Failures: Correction-Oriented Policy Optimization with Verifiable Rewards链接 : https://arxiv.org/abs/2605.14539在 RLVR（可验证奖励强化学习）的训练实践中，我们往往面临一个尴尬的困境：模型生成的错误轨迹被当作“负样本”直接丢弃或惩罚，但这些错误背后其实蕴含着巨大的信息量。这篇来自中科院软件所和小红书团队的论文提出了一种名为 CIPO （Correction-OrIented Policy Optimization）的新方法，核心思路非常直接且工程友好—— 不要只惩罚错误，要让模型学会修正错误 。这种方法在不引入额外外部监督信号的前提下，显著提升了数学推理和代码生成的性能。
### 痛点：稀疏奖励下的“盲目惩罚”
现有的 RLVR 算法（如 GRPO）主要依赖二元奖励（正确/错误）。当模型生成一条错误轨迹时，算法通常只是降低该轨迹的概率。这种做法存在两个严重问题：
- 信号稀疏且模糊：无论错误是“最后一步计算失误”还是“逻辑根本错误”，模型收到的反馈都是同样的负梯度。这导致优化方向不明确。
- 信息浪费：许多错误轨迹包含部分正确的推理步骤。直接丢弃这些轨迹不仅浪费了宝贵的监督信号，还阻碍了模型在局部邻域内的有效探索。
之前的解决方案往往依赖过程奖励模型（PRM）或 LLM 评论家，但这带来了额外的标注成本和计算开销，且辅助模型的能力瓶颈可能引入噪声。CIPO 的目标是 完全基于模型自身的策略分布 ，挖掘失败轨迹的价值。
### 核心 Insight：从“抑制”到“方向性引导”
CIPO 的核心直觉在于： 错误是通往正确的路标 。
传统 RLVR 是“抑制-强化”范式，而 CIPO 引入了 修正导向的监督 。具体流程如下：
- 生成与验证：对原始 Prompt 生成 Rollout，验证其正确性。
- 构造修正对：对于失败的轨迹 yfaily_{fail}​，将其与原始 Prompt 拼接作为新条件（xrep=Concat(x,yfail)x_{rep} = \text{Concat}(x, y_{fail})​=Concat(x,yfail​)），让模型重新采样生成修正后的解 y′y'。
- 联合优化：将标准 RLVR 目标与修正目标联合优化。
为什么这样设计有效？
- 差异化失败模式：对于“近失”（Near-miss，如最后一步算错）的轨迹，模型在局部邻域内采样得到正确答案的概率较高，从而产生强烈的、方向明确的梯度信号。对于根本性错误，修正概率低，梯度贡献小。这种机制自然地实现了隐式的难度加权。
- 显式修正能力：模型不仅学会了生成正确解，还学会了“看到自己的错误并纠正它”，这对代码调试和迭代推理场景极具价值。
### 关键设计：防止“过修正”与“灾难性遗忘”
直接让模型修正所有错误会导致分布偏移和能力退化。CIPO 引入了两个关键机制来保证稳定性：
- 自适应回放比率（Adaptive Replay Ratio）：动态调整成功轨迹与失败修正轨迹的混合比例。当模型在已掌握的能力上出现退化时，增加成功轨迹的比重；当性能稳定时，增加失败轨迹的比重以探索新能力。
- 风险厌恶奖励塑形（Risk-Averse Reward Shaping）：引入非对称惩罚。如果模型在条件为正确轨迹时生成了错误响应（即“正确 -> 错误”的退化），施加额外惩罚。这确保了模型在探索修正能力的同时，不会丢失已有的正确知识。
- 难度感知偏好（Difficulty-Aware Preference）：优先回放通过率在中间区间（δlow≤P^(x)≤δhigh\delta_{low} \le \hat{P}(x) \le \delta_{high}​≤P^(x)≤δhigh​）的样本，避免在过于简单或过于困难的样本上浪费计算资源。
### 实验结果：全面超越 GRPO论文在 11 个基准测试上进行了评估，涵盖数学推理和代码生成。以下是关键数据对比：
数学推理（Qwen3-4B）

代码生成与调试（Seed-Coder-8B）
- 代码生成：CIPO 在 LiveCodeBench v6 上的 Avg@1 达到 30.33%，优于 GRPO 的 29.45%。
- 代码调试：在 DebugBench 上，CIPO 平均提升 4.20%，达到 65.33%，甚至超越了 Qwen2.5-72B-Instruct，并接近 Claude-Sonnet-4 的水平。
内在推理能力的扩展论文特别强调了 Pass@K 指标。CIPO 在数学任务上的 Pass@32 比 GRPO 高出 6.12% 。这表明 CIPO 不仅仅是将概率质量重新分配到已知正确答案上，而是真正扩展了模型的内在推理能力，探索到了更多样的正确解空间。
### 工程启示- 零额外标注成本：CIPO 不需要人工标注的修正数据，也不需要训练额外的奖励模型或评论家。所有修正样本均来自模型自身的 On-policy 失败轨迹。这对于资源有限的团队极具吸引力。
- 即插即用：CIPO 是 RLVR 的一种扩展，可以集成到现有的 GRPO 或其他 RL 训练框架中。
- 调试能力内生：对于需要 Agent 自我反思和调试的场景（如代码生成、复杂规划），CIPO 训练的模型具备更强的“自我纠错”能力，这可能减少在线推理时的重试次数，降低延迟。
- 稳定性至关重要：论文中的消融实验显示，移除“风险厌恶奖励塑形”会导致性能大幅下降（-6.97%）。这提醒我们在利用失败样本时，必须精心设计防止能力退化的机制。
### 局限与展望虽然 CIPO 表现出色，但其依赖“可验证奖励”这一前提，限制了其在开放域对话等难以自动验证场景的应用。此外，修正过程的采样增加了计算开销，尽管论文通过难度感知偏好进行了优化，但在大规模训练中仍需关注效率问题。未来，如何将这种“从失败中学习”的范式扩展到过程奖励更丰富的场景中，是一个值得探索的方向。
