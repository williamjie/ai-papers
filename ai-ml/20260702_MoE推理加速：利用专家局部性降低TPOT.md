# ⭐⭐⭐½ MoE推理加速：利用专家局部性降低TPOT

**日期**: 2026-07-02

---

论文 : ELDR: Expert-Locality-Aware Decode Routing for PD-Disaggregated MoE Serving链接 : https://arxiv.org/abs/2607.00466在 Prefill-Decode (PD) 分离的 LLM 服务架构中，现有的路由策略大多只关注负载均衡。
但对于混合专家（Mixture-of-Experts, MoE）模型，这完全不够。
因为等量的负载并不等于等量的延迟。
### 为什么现有方案失效？
MoE 模型的 Decode 阶段是内存带宽受限的。
在 Dense 模型中，Batch 内的所有 Token 共享同一组权重，权重加载成本被均摊。
但在 MoE 中，每个 Token 可能路由到不同的专家。
Decode 步骤的成本取决于 Batch 中激活的 不同专家集合的大小（Union of Experts） 。
⚠️ 反直觉发现 ：在 Qwen3-30B-A3B 上，当活跃专家数从 16 增加到 128 时，MoE 层延迟增加了 4.7倍 ，而 Batch Size 的变化对延迟影响微乎其微。
现有的路由策略将 Decode Worker 视为可互换的单元，忽略了“专家组成”这一关键变量。
如果两个请求激活相同的专家，它们共享权重加载；如果激活不同专家，则需分别加载。
### ELDR 的核心洞察：专家局部性论文发现，专家的激活具有强烈的 领域相关性 。
代码、数学、医疗等领域的请求，倾向于激活不同的专家子集。
更关键的是，Prefill 阶段的专家激活与 Decode 阶段高度相关（相关系数 0.70–0.92 ）。
这意味着，在 Prefill 结束时，我们就能预测该请求在 Decode 阶段会访问哪些专家。
ELDR 利用这一信号，构建了一个 专家签名（Expert Signature） ，用于指导路由决策。
### 方法拆解：如何设计签名与路由？
ELDR 的设计分为离线和在线两个阶段，核心在于平衡“局部性”与“负载”。
#### 1. 专家签名构建签名不是简单的激活计数，而是经过精心设计的向量：
- 离散计数：使用 Top-K 的离散计数而非连续 Logits，因为只有被选中的专家才会产生权重加载。
- IDF 加权：类似 TF-IDF，降低通用专家的权重，放大区分度高的稀缺专家信号。
- 层掩码选择：通过贪心算法选择信息量最大的层，剔除噪声层。
这种设计使得签名之间的距离能准确预测 Decode 阶段的专家重叠程度。
#### 2. 离线聚类：平衡 K-Means为了将请求分配到不同的 Decode Worker，ELDR 使用 平衡 K-Means 对签名空间进行划分。
普通 K-Means 会导致热门领域（如英语）的集群过大，造成负载不均。
平衡约束确保每个 Worker 负责大致相等数量的签名区域，避免单点过载。
#### 3. 在线路由：局部性带宽在线阶段，ELDR 计算请求签名与各 Worker 质心的相似度。
它不直接选择最相似的 Worker，而是选择一个**局部性带宽（Locality Band）**内的候选 Worker 集合。
最终，在这些候选中，选择当前负载最低的 Worker。
关键机制 ：带宽保证专家局部性，负载选择吸收实时波动。两者结合，既减少了权重加载，又避免了尾部延迟飙升。
#### 4. 前缀缓存一致性当请求命中 KV Cache 时，Prefill 被跳过，签名缺失。
ELDR 设计了与 KV Cache 块级索引一致的 签名缓存 。
通过累加缓存块的专家足迹和新生成部分的签名，恢复完整的专家签名，确保路由准确性。
### 实验结果ELDR 在 vLLM 上实现，并在最多 40 张 GPU 的集群上进行评估。
对比最强的负载均衡基线，ELDR 显著降低了中位 TPOT：
模型 任务负载 TPOT 降低 语言负载 TPOT 降低 Qwen3-30B-A3B 7.0% - 13.9% 5.9% - 10.0% GPT-OSS-120B 7.0% - 13.9% 5.9% - 10.0% Gemma-4-26B-A4B 7.0% - 13.9% 5.9% - 10.0%- 同域 Batch 优势：相同领域的请求组成的 Batch，每步激活的专家数量比混合领域 Batch 少 17–21%（任务）和 3–10%（语言）。
- 开销极低：签名缓存占用 KV Cache 空间不足 1%。
- 输出不变：由于不改变模型结构和门控决策，输出结果与标准 Top-K 路由完全一致。
### 工程启示对于部署 MoE 模型的团队，ELDR 提供了明确的优化方向：
- 路由维度升级：从单纯的“负载均衡”转向“专家局部性感知”。
- Prefill 信号利用：Prefill 阶段的激活信息不仅是计算结果，更是 Decode 阶段的路由特征。
- 缓存协同：KV Cache 与专家签名应联合设计，避免缓存命中导致路由信息丢失。
### 局限与展望ELDR 目前主要适用于 PD 分离架构。
在单实例部署中，由于所有请求共享同一内存池，专家局部性的收益可能受限。
此外，平衡 K-Means 需要离线校准，当工作负载发生剧烈漂移时，可能需要重新拟合聚类中心。
但总体而言，这是一篇极具工程落地价值的论文，揭示了 MoE 推理中常被忽视的内存带宽瓶颈及其解决方案。
