# 告别历史回放：MementoGUI 的长期记忆控制

**日期**: 2026-05-19

---

论文 : MementoGUI: Learning Agentic Multimodal Memory Control for Long-Horizon GUI Agents链接 : https://arxiv.org/abs/2605.18652长程 GUI Agent 最大的痛点不是“看不见”，而是“记不住”。当交互步骤超过一定阈值，现有的 Agent 往往因为上下文窗口爆炸或关键视觉线索丢失而陷入死循环。MementoGUI 这篇论文提供了一个极具工程价值的解法：不再把历史截图当垃圾堆，而是通过一个轻量级的“记忆控制器”，主动筛选、压缩并检索关键信息。
### 为什么“直接喂历史”行不通？
目前的 GUI Agent 在处理长任务时，通常采用两种笨办法：
- 原始历史回放 (Raw History Replay)：把过去几十张截图全塞进 Prompt。这不仅导致 Token 成本飙升，更让模型淹没在冗余信息中，找不到真正的决策依据。
- 纯文本记忆 (Text-only Memory)：只保留文字摘要。但这丢弃了 GUI 交互中最关键的“局部视觉证据”（比如某个按钮的状态变化、临时弹出的菜单），导致模型“失忆”。
作者的核心洞察是： 长程 GUI 控制本质上是一个多模态记忆控制问题，而非单纯的上下文长度问题。 有效的 Agent 应该像人类一样，决定何时更新记忆、保留什么细节、以及如何调用过去的经验。
### 方法拆解：MementoGUI 的“外挂大脑”
MementoGUI 的设计非常巧妙，它是一个 即插即用 (Plug-in) 的框架，不需要微调底层的 GUI 动作模型（如 UI-Venus 或 GUI-Owl），而是外挂了一个名为 MementoCore 的记忆控制器。
这个控制器基于 Qwen3-VL 构建，通过四个 LoRA 适配器实现四个核心操作：
- 步骤处理 (Step Processing)：判断当前界面变化是否重要。如果重要，提取事件摘要 (Summary) 和感兴趣区域 (ROI Box)。
- 工作记忆压缩 (WM Compression)：当短期记忆满了，自动将旧条目压缩为紧凑的文本摘要，并保留关键的视觉标识符。
- 情景记忆写入 (Episodic Writing)：任务结束后，将完整轨迹转化为可复用的“情景记忆”存入数据库。
- 情景记忆选择 (Episodic Selection)：在需要时，通过两阶段检索（向量粗筛 + 多模态精筛）从历史经验中找回相关片段。
关键设计直觉：
- ROI 级视觉证据：不同于纯文本摘要，MementoGUI 保留了关键步骤的截图裁剪 (Crop)。这解决了“文字描述不清视觉状态”的问题。
- 按需检索：情景记忆不是每步都查，而是由控制器判断是否需要 (γt)，平衡了精度与延迟。
- 解耦训练：记忆控制器通过自动从 PSAI 计算机使用轨迹中生成的数据进行 SFT 和 DPO 训练，与动作模型完全解耦。

### 工程启示- 不要微调动作模型，先优化上下文：对于现有的 GUI Agent，直接微调成本高且风险大。MementoGUI 证明，通过外挂一个专门的“记忆层”来净化输入 Prompt，能以极小的代价获得显著的性能提升。
- 视觉记忆不可丢弃：在 GUI 场景中，纯文本摘要损失了太多状态信息。保留关键步骤的 ROI 截图是提升长程任务稳定性的关键。
- 两阶段检索是性价比之选：先向量粗筛再模型精筛，既保证了检索的相关性，又控制了计算开销。
### 局限与展望虽然效果显著，但 MementoGUI 引入了额外的推理延迟。在 GUI-Odyssey 上，UI-Venus-1.5-8B 的端到端延迟从 41.98 秒增加到了 56.20 秒（8B 控制器）。对于实时性要求极高的场景，可能需要更轻量的控制器或异步记忆更新机制。此外，情景记忆的积累依赖于历史数据的质量，冷启动阶段的性能可能受限。
总体而言，MementoGUI 为构建可靠的长程 GUI Agent 提供了一条清晰的技术路径： 从被动接收历史，转向主动控制记忆。
