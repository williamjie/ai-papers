论文 : Kwai Keye-VL-2.0 Technical Report链接 : https://arxiv.org/abs/2606.10651快手最新开源的 Keye-VL-2.0 并非简单的参数堆砌，而是针对“超长视频”和“多任务冲突”这两个工程痛点给出的系统性解法。作为一枚 MoE 架构的多模态基座模型，它在保持 3B 激活参数的同时，实现了 256K 上下文的无损处理，这对本地部署长视频理解极具参考价值。
现有 MLLM 在处理小时级视频时面临两难：要么暴力降采样导致关键帧丢失，要么全量保留导致显存爆炸。更棘手的是，强行注入代码、工具调用等 Agent 能力，往往会引发“灾难性遗忘”，导致模型基础推理能力退化。Keye-VL-2.0 的核心价值在于它没有回避这些矛盾，而是通过架构创新和训练策略分别击破。
核心 Insight : 稀疏注意力（DSA）与 GQA 的结合，让长视频处理从“暴力计算”转向“精准检索”，解决了 KV Cache 线性增长的死结。
在架构设计上，Keye-VL-2.0 首次将 DeepSeek 的稀疏注意力（DSA）适配到基于 GQA 的多模态架构中。传统 DSA 多用于 MLA，而 GQA 是主流 MLLM 的标配。
- MQA 风格索引器: 它共享一个 Key Head 来计算全局索引分数，大幅降低计算量。通过 Top-k 机制选出最相关的 Token，将注意力复杂度从 O(L2)O(L^2)) 降至 O(Lk)O(Lk)（k=2048k=20482048）。
- GQA 稀疏聚合: 所有 GQA 组共享同一套稀疏索引集，既保留了 GQA 的结构优势，又避免了全量密集注意力的内存开销。
这种设计让模型能“无损”处理 256K 上下文，意味着它可以完整摄入长达数小时的视频特征，而不必依赖激进的帧抽取。配合原生分辨率视觉编码器（Native-Resolution ViT），模型在保持全局结构的同时，不丢失局部细节，这对 OCR 和图表理解至关重要。
训练策略上，论文提出了“跨模态多教师在线策略蒸馏”（MOPD）。为了解决多任务对齐中的遗忘问题，它不再依赖端到端的联合优化，而是利用专用教师模型提供 Token 级别的密集反馈。
- 动态路由: MOPD 将不同模态和任务的专家知识隔离，再蒸馏回统一的 MoE 骨干。
- RL 增强: 结合 Context-RL 和 Video-RL，稳定长序列决策树，减少视觉幻觉。
这种“分而治之”再“融合”的策略，让 Keye-VL-2.0 在获得强大 Agent 能力的同时，守住了 STEM 和数学推理的基本盘。
实验数据证明了这一路线的有效性。在 TimeLens 细粒度时间定位基准上，Keye-VL-2.0-30B-A3B 的表现令人瞩目：
- ActivityNet: mIoU 达到 74.1%，远超 Gemini-3-Flash 的 65.7% 和 Qwen3.5-35B-A3B 的 61.2%。
- QVHighlights: mIoU 为 42.4%，同样领先于主要竞品。
在长视频理解方面，其在 Video-MME-v2 上取得 58.5 分，LongVideoBench 上达到 57.0 分。虽然略低于 Gemini-3-Flash（70.1 和 64.6），但考虑到后者是闭源模型且参数量可能更大，Keye-VL-2.0 作为开源 MoE 模型，其性价比极高。
对工程师而言，Keye-VL-2.0 提供了两个关键启示：
- 长视频不需要暴力降采样: 通过 DSA 等稀疏注意力机制，可以在有限算力下保留完整时间线信息，这对视频摘要、高光提取等场景是质变。
- Agent 能力需隔离训练: 直接混合训练容易破坏基座能力，MOPD 这种基于在线策略的蒸馏方法，为构建多功能 Agent 提供了更稳定的微调范式。
当然，模型仍有局限。例如，在极端长上下文中，稀疏索引的准确性可能受限于 Top-k 的选择；且 MoE 架构对推理基础设施的要求较高，需要专门的负载均衡和并行策略支持。但总体而言，Keye-VL-2.0 为开源社区提供了一条兼顾效率与能力的可行路径，值得深入研读其工程实现细节。
