# ⭐⭐⭐ 告别暴力蒸馏：β-OPSD 让模型推理更稳更强

**日期**: 2026-07-31

论文 : β-OPSD: Deriving with Policy Optimization, Training with Self-Distillation链接 : https://arxiv.org/abs/2607.28582On-policy self-distillation (OPSD) 是提升大模型推理能力的热门路线，但工程落地极难。它太“脆”了：稍微调参不当，模型就崩盘或性能倒退。这篇论文不仅指出了 OPSD 的结构性缺陷，还给出了一个既优雅又好用的解法——β-OPSD。
### 为什么现有的 OPSD 这么难用？
传统的 OPSD 让模型直接模仿“拥有上帝视角”的老师（比如知道正确答案的同一架构模型）。这听起来很完美：学生生成轨迹，老师给出每一步的最优 token，学生去拟合。
但问题在于，这种“一步到位”的模仿太激进。
核心痛点 ：直接把学生拉到老师的分布上，忽略了学生当前的能力边界。就像让小学生直接背博士论文，不仅学不会，还会把原本的基础知识搞乱。
论文作者敏锐地发现，传统的 OPSD 其实是强化学习（RL）中 KL 正则化目标的一个特例——当惩罚系数 β=1\beta = 1 1 时。这意味着，我们之前一直在用一个隐式且固定的参数在训练，完全没有控制“保守程度”的自由度。
### β-OPSD：用 RL 推导，用蒸馏实现β-OPSD 的核心 Insight 非常漂亮： 不要把老师当成唯一目标，而要把它当成一个可调节的终点。
作者将 β\beta 显式化为一个可控参数。通过数学推导，他们证明了最优策略实际上是“参考策略”（通常是当前学生）和“特权老师”之间的几何插值。
- 当 β→∞\beta \to \infty∞，目标接近学生自己（保守）。
- 当 β=1\beta = 11，目标就是老师（激进，即传统 OPSD）。
工程上的神来之笔：
直接优化这个 RL 目标计算量巨大且方差高。作者选择“曲线救国”：既然最优策略是两者的插值，那我们就在 logit 层面做线性混合 。
Target=softmax((1−w)⋅StudentLogits+w⋅TeacherLogits)\text{Target} = \text{softmax}((1-w) \cdot \text{StudentLogits} + w \cdot \text{TeacherLogits}) = softmax (( 1 − w ) ⋅ StudentLogits + w ⋅ TeacherLogits )
其中 ww 随训练进度从低到高线性增加。这样，模型在初期主要学习自己的逻辑（保持稳定性），后期逐渐吸收老师的智慧（提升上限）。
此外，为了解决早期 token 错误导致后续全盘皆输的问题，作者引入了 Return-to-Go 信用分配机制。简单说，就是让前面的 token 也能“看到”后面生成的总误差，从而更合理地调整梯度。
### 实验数据：小模型收益巨大在数学推理基准测试（AIME, HMMT）上，β-OPSD 的表现令人印象深刻，尤其是在中小参数模型上。

消融实验进一步证实了两个组件的有效性：
- Logit 插值目标：相比直接蒸馏老师，插值目标在 AIME 2024 上提升了 6.03%。
- Return-to-Go 信用分配：相比局部 Token 梯度，全局信用分配在 AIME 2025 上提升了 5.55%。
### 工程启示：如何落地？
如果你正在尝试用自蒸馏提升模型的推理能力，这篇论文提供了两个直接的优化方向：
- 不要直接 Distill Teacher：实现一个 Logit 混合层。在训练初期，让学生权重占主导（例如 wstart=0.5w_{start}=0.5​=0.5），随着训练进行，逐渐增加老师权重（wend=0.8w_{end}=0.8​=0.8）。这能显著降低训练初期的 Loss 震荡。
- 重视序列级反馈：标准的 Cross-Entropy Loss 是逐 Token 计算的，缺乏全局视野。引入 Return-to-Go 机制，虽然实现稍复杂，但能让模型更好地理解“这一步走错对最终答案的影响”，尤其在长推理链条中效果显著。
### 局限与展望β-OPSD 目前主要在数学推理任务上验证。虽然其理论框架通用，但在代码生成、逻辑推理等其他领域是否同样有效，仍需社区进一步探索。此外，插值权重的调度策略（Linear Schedule）目前是手调的，未来能否自适应调整权重，也是一个值得关注的方向。
总的来说，β-OPSD 用极简的工程改动（Logit 混合 + 梯度加权），解决了 OPSD 长期存在的稳定性难题。对于追求高性价比推理模型优化的工程师来说，这是一个不容错过的技术点。
