论文 : DiffusionGemma Technical Report链接 : https://arxiv.org/abs/2608.00146如果现在的 LLM 推理速度让你觉得“慢”，那是因为你还在用自回归（Autoregressive, AR）那一套。DiffusionGemma 的出现，直接把这个瓶颈撕开了一个口子：在单张 NVIDIA H100 GPU 上，它实现了约 1,500 tokens/秒 的生成速度。这不仅仅是快一点，而是数量级的跨越。
### 为什么自回归模型越来越慢？
现在的 LLM 服务有一个死结： 内存带宽瓶颈 。
当并发量低时，GPU 算力闲置，大部分时间花在把权重和 KV Cache 从内存搬运到加速器上。虽然投机解码（Speculative Decoding）能缓解这个问题，但它依然受限于“草稿-验证”的串行逻辑，通常每次前向传递只能产出 3-6 个 token。
DiffusionGemma 的核心洞察非常大胆： 既然不能一个个猜，那就一次性猜一大块。
它放弃了逐 token 生成，转而采用**离散扩散（Discrete Diffusion）**机制，并行细化长度为 256 的 token 块。这种设计将推理从“内存受限”强行扭转为“计算受限”，完美契合了现代 GPU 擅长并行计算的硬件特性。
### 方法拆解：不是从零训练，而是“旧瓶装新酒”
DiffusionGemma 并没有从头预训练一个扩散模型，那太烧钱了。它的工程智慧在于 复用与微调 ：
- 基座选择：直接基于 Gemma 4 26B A4B MoE 模型初始化。这让它继承了原模型的长上下文、多模态理解和思维链（Thinking Mode）能力。
- 两阶段训练流水线：
阶段一：监督微调（SFT）。教会模型双向去噪。它不再只看左边，而是通过双向注意力机制，在一个 256 token 的画布上同时观察上下文。
- 阶段二：采样器蒸馏与强化学习（SD·RL）。这是关键。它不仅优化生成质量，还专门针对推理效率进行训练，大幅压缩去噪步数。
⚠️ 核心 Insight ：整个微调过程消耗的 token 预算不到原始 AR 模型总训练量的 10% 。这意味着扩散模型的落地门槛被极大地降低了。

### 工程启示：本地部署与 Agent 的新希望对于工程师来说，这篇论文有三个直接可用的信号：
- 低延迟场景的首选：如果你的应用对首字延迟（TTFT）和生成速度极其敏感（如实时对话、交互式代码补全），DiffusionGemma 的 1,500 TPS 意味着几乎“无感”的等待。
- 混合解码的可能性：论文指出，微调后的模型仍然保留自回归生成能力。这暗示了一种混合架构：简单任务用扩散模式极速输出，复杂推理任务切换回 AR 模式保证质量。动态路由将成为可能。
- 开源与许可：基于 Apache 2.0 协议开放权重。对于想要构建私有化、高吞吐 LLM 服务的企业，这是一个可以直接落地的基座。
### 局限与展望当然，天下没有免费的午餐。扩散模型在生成过程中引入了额外的计算复杂度（虽然被并行化抵消了大部分）。此外，论文提到在某些极端长上下文中，扩散去噪的一致性可能不如 AR 模型完美。但考虑到其开放权重和极高的推理效率，DiffusionGemma 无疑是当前文本生成领域最值得关注的工程突破之一。
