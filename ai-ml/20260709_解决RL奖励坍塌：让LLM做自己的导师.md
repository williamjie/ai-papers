# ⭐⭐⭐⭐ 解决RL奖励坍塌：让LLM做自己的导师

**日期**: 2026-07-09

论文 : LLM-as-a-Tutor: Policy-Aware Prompt Adaptation for Non-Verifiable RL链接 : https://arxiv.org/abs/2607.04412在非可验证任务（如复杂指令遵循）的强化学习（Reinforcement Learning, RL）中，我们常遇到一个尴尬局面：模型越强，奖励信号反而越“哑火”。这篇论文提出了一个巧妙的思路：让 LLM 不仅当裁判（Judge），更当导师（Tutor），通过动态调整题目难度来维持训练的有效性。
### 痛点：为什么模型变强后，RL 就失效了？
在数学或代码等可验证领域，对错是绝对的。但在指令遵循任务中，我们依赖 LLM Judge 打分。
现有方案通常使用静态提示词（Static Prompts）。当策略模型（Policy）能力提升时，原本有挑战的题目变得太简单，所有生成的回答都接近满分；或者题目太难，全部不及格。
⚠️ 核心洞察 ：奖励信号的判别力不仅取决于 Judge 的质量，更取决于“提示词-策略”这对组合的难度匹配度。当模型对某个提示词的输出质量方差趋近于零时，无论 Rubric（评分细则）多精细，梯度更新都会失效。
之前的工作要么只调整评分标准（Rubric Adaptation），要么盲目增加难度。前者无法解决“无差异可评”的问题，后者可能导致分布偏移。
### 方法拆解：Append-Only 的动态课程学习LLM-as-a-Tutor 的核心直觉非常工程化： 与其重写题目，不如追加约束。
该方法让一个更强的 LLM（Tutor）扮演两个角色：
- 考官（Examiner）：采样当前策略模型的两个输出，进行成对比较（Pairwise Comparison）。如果两者质量无显著差异，说明该提示词对当前策略“太简单”或“饱和”。
- 出题人（Generator）：针对被判定为“非挑战性”的提示词，追加一个原子级约束（Atomic Constraint），并同步更新评分细则。
为什么设计成“追加（Append）”而不是“重写（Rewrite）？”
- 单调递增难度：追加约束意味着新题目必须同时满足旧要求和新要求，难度必然上升或持平，绝不会倒退。
- 保持分布一致：重写提示词容易偏离原始任务分布，导致模型学到的是“解题技巧”而非“指令遵循能力”。
这种机制形成了一种自校准的课程学习（Curriculum Learning）：模型越强，Tutor 追加的约束越多，训练信号始终保持在模型的“最近发展区”。
### 关键结果：比盲目进化更有效作者在 FollowBench、AdvancedIF 和 InfoBench 三个基准上进行了测试。使用 Qwen3-1.7B 作为策略模型，Qwen3-8B 作为 Tutor/Judge。

- 优于纯 Rubric 调整：即使动态调整评分标准（Policy-adaptive rubrics），平均分也仅为 51.04，低于本文方法的 51.96。这证明了当提示词本身无法激发质量差异时，改评分规则是徒劳的。

- 追加优于重写：消融实验显示，“追加约束”在所有基准上均优于“重置”或“重写”提示词的策略。
### 工程启示- Pairwise > Pointwise：利用 LLM 进行成对比较来判断“是否需要加难”，比直接打分更可靠。LLM 在判断“A 和 B 是否一样好”上，比判断“A 得几分”更敏锐且更符合人类直觉。
- 动态难度是 RL 的必需品：对于非可验证任务，静态数据集很快会被模型“刷分”。引入基于策略表现的动态数据增强，能显著延长 RL 训练的有效窗口期。
- 小模型也能受益：即使是用 1.7B 的小模型做 Policy，配合 8B 的 Tutor，也能获得显著提升。这意味着该框架对算力敏感的场景（如端侧模型微调）具有落地价值。
### 局限与展望目前该方法主要应用于指令遵循任务，因为“追加约束”是增加此类任务难度的自然方式。对于数学推理或代码生成，如何定义“原子级约束”仍是一个开放问题。此外，Tutor 模型的判断误差可能会累积，需要进一步研究其对长程训练稳定性的影响。
