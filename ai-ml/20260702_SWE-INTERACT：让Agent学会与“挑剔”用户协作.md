# ⭐⭐⭐ SWE-INTERACT：让 Agent 学会与“挑剔”用户协作

**日期**: 2026-07-02

---

论文 : SWE-INTERACT: Reimagining SWE Benchmarks as User-Driven Long-Horizon Coding Sessions链接 : https://arxiv.org/abs/2606.30573现在的 SWE 基准测试大多假设需求是清晰且完整的，Agent 只需要埋头写代码。但现实开发中，需求往往是模糊、碎片化且不断变化的。这篇来自 Scale AI 的论文提出了 SWE-INTERACT ，一个模拟真实“用户-Agent”多轮协作流程的新基准。它不再考核 Agent 的单次实现能力，而是测试其在模糊指令下发现意图、应对反馈并迭代代码的能力。
### 为什么现有基准不够用？
传统 SWE 基准（如 SWE-bench Pro）将长周期任务简化为“一次性自主实现”。所有需求 upfront 给出，Agent 只需关注实现细节。
然而，大规模真实编码会话数据显示，绝大多数任务并非如此。开发者通常发送简短、模糊的指令，随后通过审查代码、提出批评和补充约束来逐步明确需求。这是一个 目标发现 → 计划 → 批准 → 实现 → 修订 → 提交 的循环。
现有基准忽略了这一核心环节：Agent 是否能在面对模糊初始请求时，主动挖掘用户意图？是否在收到反馈后能正确保留之前的工作并整合新约束？SWE-INTERACT 旨在填补这一空白。
### 方法拆解：拟人化的“挑剔”用户模拟器SWE-INTERACT 的核心创新在于其 用户模拟器（User Simulator） 的设计。它不是简单的 API 调用，而是一个具备人格、能操作 Agent 工作空间的动态实体。
-基于真实数据的人格建模：
作者分析了 SWE-chat 中的数千条真实用户消息，发现最常见的交互模式是 “Vibecoding”（Agent 写 >99% 代码），而最典型的用户人格是 “Expert Nitpicker”（专家型挑刺者）。这类用户消息简短、直接、迭代性强，且极度关注 API 细节。SWE-INTERACT 的模拟器完全复刻了这种“挑剔”风格：它不会一次性给出所有需求，而是随着 Agent 的代码进展，逐步揭示隐藏要求。
-工作空间感知与工具调用：
这是该基准最具工程价值的部分。用户模拟器拥有对 Agent 工作空间的 Shell 访问权限（如 git, grep, sed）。这意味着“用户”可以像真实开发者一样检查代码差异、搜索文件，并基于实际代码状态提供针对性反馈。这迫使 Agent 必须写出可被审查的代码，而不仅仅是通过单元测试的脚本。
-渐进式需求揭示：
任务开始时，Agent 只收到模糊的高层描述。随着交互进行，用户模拟器会根据 Agent 的当前实现，逐步抛出新的约束和修正意见，直到所有原始任务指令都被“ handed off ”。最终的成功判定依然依赖原始的自动验证器（Verifier），确保评估标准的客观性。
### 关键结果：单轮强手在多轮中折戟实验对比了 GPT 5.5、Opus 4.8 等前沿模型在单轮基准与 SWE-INTERACT 多轮设置下的表现。数据揭示了令人惊讶的性能断层：

- Token 消耗：增加 1.6-4.5 倍。
- 成本：每次尝试的成本增加 2-3.5 倍。
### 失败模式分析：Agent 到底卡在哪？
通过对 287 个失败轨迹的分析，作者识别出主要的失败原因：
- 技术实现错误 (34%)：即使理解了需求，最终代码仍存在 Bug。
- 遗忘需求 (34%)：在多轮交互中，Agent 容易忽略早期提出的要求，导致最终提交遗漏关键功能。
- 误解/错误假设 (14%)：未主动澄清模糊点，而是基于错误假设进行实现。
- 缺失用户要求 (12%)：这是基准本身的局限性，即模拟器未能揭示某些必要需求。
值得注意的是， 目标发现（Goal Discovery） 并不等同于 正确实现 。许多模型能在计划阶段覆盖 >80% 的潜在目标，但在具体实现中得分下降。虽然 GPT 5.5 和 Opus 4.8 最终能恢复大部分目标覆盖率，但仍有大量因技术错误导致的失败。
### 工程启示- 评估体系需升级：如果你的 Agent 在 SWE-bench 上表现优异，但在实际协作中频繁返工，SWE-INTERACT 能帮你定位问题。它揭示了当前模型在“状态保持”和“上下文整合”上的短板。
- Prompt 工程的重要性：模拟器的 “Expert Nitpicker” 人格证明，清晰的交互协议和反馈机制对 Agent 表现至关重要。在实际应用中，设计良好的用户界面和反馈循环可能比单纯提升模型参数更有效。
- 长程记忆的瓶颈：多轮交互中的“遗忘需求”问题，指向了当前 LLM 在长上下文下的信息检索与整合缺陷。未来的优化方向应聚焦于如何帮助 Agent 在多轮对话中维护一致的任务状态图。
SWE-INTERACT 不仅是一个基准，更是一个信号：Coding Agent 的下一阶段竞争，不在于谁写的代码更长，而在于谁能更好地与人协作。
