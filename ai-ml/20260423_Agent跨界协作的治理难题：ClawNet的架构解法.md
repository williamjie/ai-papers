# Agent 跨界协作的治理难题：ClawNet 的架构解法

**日期**: 2026-04-23

---

论文 : ClawNet: Human-Symbiotic Agent Network for Cross-User Autonomous Cooperation链接 : https://arxiv.org/abs/2604.19211AI Agent 已经能自己操作文件系统、调用 API、控制终端——单用户场景下，Agent 越来越像一个能干活的数字员工。但现实中的工作从来不是单打独斗。两个不同公司的 Agent 怎么协作？A 公司的 Agent 能看 B 公司的哪些数据？谁该对最终决策负责？这些问题，现有 Agent 框架基本没有回答。
ClawNet 的切入点很明确： Agent 的下一个 frontier 不是更强的单体能力，而是跨用户协作的基础设施 。

ClawNet 的核心判断是：真实世界协作离不开三个结构性要素—— 身份（Identity）、授权（Authorization）、问责（Accountability） 。现有 Agent 系统完成了”个人能力数字化”，但完全没碰这三个要素。
## 方法拆解：架构隔离优于策略约束ClawNet 最聪明的设计直觉，用论文原话说就是 “Cannot beats Should Not” 。
传统安全方案依赖 prompt 级别的约束：“不要泄露隐私信息""不要越权操作”。但论文指出，让 LLM 在每一步推理中都完美遵守指令，这在统计上是不可能的。ClawNet 的解法是： 把安全从行为可靠性（Should Not）升级为结构确定性（Cannot） 。
具体怎么做？分层身份架构。
每个用户拥有一个永久绑定的代理系统，分为两层：
Manager Agent ：持有用户全部认知（通过三层记忆系统逐步构建：事实记忆 → 模式记忆 → 价值记忆），但 架构层面被隔离于所有外部通信 。它不能直接对外发消息，只能作为内部顾问给 Identity Agent 出建议。
Identity Agent ：每个对应一个具体的协作上下文（比如”采购经理身份”、“学术研究身份”）。它只持有与其身份域相关的知识子集 Kᵢ ⊂ Kᤨ，对外代表用户参与协作。
这个设计的精妙之处在于：Manager Agent 虽然知道一切，但架构上无法越界；Identity Agent 虽然知识受限，但只能在其授权范围内行动。安全不再依赖”模型应该不乱说话”，而是依赖”系统结构上就不可能乱说话”。
## 跨用户协作怎么跑通？
论文通过一个”跨境企业采购”场景（Figure 2）演示了完整的协作流程：
- Mr. Li 发出采购意向 → 他的 Agent 读取本地需求文档 → 向供应商发送结构化请求- 供应商 CEO 的 Agent 接收后，在授权范围内拆解任务 → 委派 Tech Agent 做技术评估、Business Agent 做商业分析 → 各自只访问自己权限范围内的本地资源- 结果聚合为提案 → 返回给 Mr. Li 的 Agent → 上报人类审批- Mr. Li 批准后 → Agent 执行本地操作整个过程中， Agent 自动化的是信息交换和方案讨论，最终决策权始终在人手里 。每个操作都被记录为 ℓ = (操作, 用户, 身份ID, 结果, 时间戳) 的审计日志。
授权验证采用 双因子独立机制 ：
- L1 ACL（服务端）：验证操作是否在身份域配置的范围内- L2 白名单（客户端）：用户设备上的独立文件夹白名单两层独立运作，任一拒绝就全链路拒绝。论文称之为”纵深防御，而非串联防御”——即使云侧 L1 被绕过，客户端 L2 仍会兜底。
## 工程启示这个架构对实际工程有几个值得借鉴的点：
-“架构隔离 > prompt 约束”的原则可以推广。任何涉及 Agent 外部通信的场景，都应该优先考虑系统层面的隔离，而不是依赖模型指令遵循能力。
-分层身份的设计模式适用于任何需要”一个主体代表多个角色”的系统。Manager 做全局协调但不暴露，Worker 做对外交互但知识受限——这个模式在微服务、零信任架构中也很常见，只是 Agent 领域还没人这么系统化地做。
-三层记忆驱动的认知耦合（事实 → 模式 → 价值）是 Agent 从”工具”进化为”可靠代理人”的关键路径。价值记忆让 Agent 知道”什么绝对不能做”，这比知道”应该做什么”更重要。
-双因子独立授权的思路值得在 Agent 框架中推广。服务端 ACL + 客户端白名单的纵深防御，在跨网络边界的协作中特别有用。
## 局限与展望论文目前更像是一个架构提案，有几个明显短板：
- 缺乏量化验证。没有给出任何性能指标、安全事件降低率、或与其他方案的对比数据。概念演示（Figure 2）是叙事性的，不是实验性的。
- 规模问题未讨论。当用户拥有大量 Identity Agent、网络中有大量用户时，消息路由和授权验证的开销如何？论文没有给出复杂度分析。
- Manager Agent 的知识聚合机制值得进一步研究。Manager 通过聚合所有 Identity Agent 的记忆来获得全局视角，这本身就是一个复杂的知识融合问题。
总的来说，ClawNet 提出的是一个方向性问题： Agent 从单打独斗走向跨界协作时，基础设施应该怎么搭？ 它的回答——身份绑定 + 分层架构 + 纵深授权 + 全链路审计——在当前 Agent 框架普遍忽略治理层的大背景下，值得持续关注。
