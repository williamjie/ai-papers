论文 : LongAttnComp: Cross-Family Context Compression for Long-Context Reasoning链接 : https://arxiv.org/abs/2606.01336当上下文长度突破 10 万 Token，推理延迟和显存成本成为工程落地的最大瓶颈。现有的无训练注意力压缩方法（如 Speculative Prefill）在代码调试等复杂任务上表现疲软，而基于微调的方案往往缺乏通用性。LongAttnComp 提出了一种轻量级的跨家族上下文压缩器，通过两阶段微调策略，在保持极低计算开销的同时，实现了跨不同模型架构的高精度迁移。
### 为什么现有方案不够用？
长文本推理的核心痛点在于“检索”与“推理”的耦合。传统方法要么依赖固定的压缩预算，无法适应信息密度不均的输入；要么基于无训练的注意力权重，在需要深层语义理解的代码任务中丢失关键证据。AttnComp 虽然引入了可训练的交叉注意力层，但其设计局限于短文本问答和文档级评分，难以直接应用于缺乏自然边界的超长连续流数据。
### 核心设计直觉：从文档到 Token 块LongAttnComp 的核心 Insight 是将压缩视为一个自适应的检索问题，并对 AttnComp 进行了四项关键改造：
- Token 级分块（Token-level Chunking）：放弃文档边界，将输入切分为固定大小的 Token 块。这解决了现实场景中长代码或长对话缺乏清晰段落划分的问题，使压缩粒度更灵活。
- 基于预算的 Top-p 选择：原算法在分数低于阈值时停止，导致过度压缩。新方法引入硬性的 Token 预算（Budget），确保在证据分散的任务中保留足够多的上下文，避免“断崖式”性能下降。
- 位置重排序：选中块后恢复原始顺序，维持语义连贯性，这对代码逻辑至关重要。
- 两阶段微调策略：
Stage 1：使用 SQuAD 和 HotpotQA 构建通用检索基础，解决单点事实查找。
- Stage 2：引入 MuSiQue 等多跳推理数据，并混合 Stage 1 数据进行回放，防止灾难性遗忘，增强复杂逻辑下的证据聚合能力。
### 关键实验结果在 InfiniteBench Code-Debug 任务上，LongAttnComp 展现了惊人的跨模型泛化能力。即使压缩器仅在 Llama-3.1-8B 上训练，它也能无缝迁移到 DeepSeek、MiniMax 和 GPT-OSS 等完全不同架构的目标模型。
目标模型 Full Context Spec Prefill LongAttnComp (Stage 2) DeepSeek-R1 74.37% 62.44% 76.90% (+2.5%) MiniMax-M2.5 83.76% 57.10% 82.23% (-1.5%) GPT-OSS-120B 86.00% 52.28% 81.73% (-4.3%)
⚠️ 反直觉发现 ：在 DeepSeek-R1 上，经过压缩的 LongAttnComp 准确率反而超过了完整上下文（Full Context）。这表明通过剔除噪声，模型能更聚焦于关键代码逻辑，而非被海量无关 Token 干扰。
在 LongBench v2 的多文档推理任务中，Stage 1 表现不佳（41.7%），但经过 Stage 2 微调后，Subq 变体提升至 48.9%，Nosubq 变体达到 49.7%，大幅缩小了与全量上下文的差距。
### 工程启示- 压缩器即插件：LongAttnComp 证明了只需微调少量参数（约 0.5%），即可构建一个通用的预处理模块。无需针对每个目标模型重新训练，极大降低了部署成本。
- 数据决定上限：架构本身不是瓶颈，训练数据的分布才是。从 NIAH（大海捞针）到多跳推理的数据演进，直接决定了压缩器能否处理复杂逻辑。
- 超参数需动态调整：Chunk size 和选择模式（累计分数 vs 纯预算）高度依赖任务类型。代码任务适合大块（1024 Token），而多文档推理适合小块（32 Token）。
### 局限与展望目前该方法仍依赖启发式查询解析（取最后 N 个 Token），在查询嵌入位置不固定时会有约 1 点的精度损失。此外，针对不同任务手动调整 Chunk size 和预算模式增加了部署复杂度。未来方向包括开发自适应选择机制以及更鲁棒的无监督查询解析器，以实现真正的“开箱即用”。
