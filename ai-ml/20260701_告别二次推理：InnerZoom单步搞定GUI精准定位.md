论文 : One Forward Beats Two: InnerZoom for Accurate and Efficient GUI Grounding链接 : https://arxiv.org/abs/2606.30084做 GUI Agent 的工程师都懂那个痛点：模型能看懂界面，但点不准坐标。为了解决这个问题，主流方案是 ZoomIn——先猜个大概区域，裁剪放大后再跑一次推理。这招虽然有效，但代价惨重：延迟翻倍，算力加倍。
阿里通义实验室这篇新论文直接掀了桌子： 为什么一定要跑两遍？ 他们提出的 InnerZoom，通过“跨层证据桥接”，在单次前向传播中实现了比两次推理更准的定位。对于追求低延迟的本地 Agent 部署，这是一个极具工程价值的突破。
### 核心洞察：模型其实早就“看见”了目标InnerZoom 的设计源于一个反直觉的诊断发现。作者分析中间解码层的视觉响应图时发现： 目标区域的证据在中间层就已经涌现，但在最终坐标生成时消失了。
⚠️ 关键数据 ：在 Qwen3-VL-4B 中，第 19-23 层的 ROI Recall（目标区域召回率）峰值高达 69.0% ，但到了最后一层骤降至 14.0% 。
这意味着模型不是“找不到”目标，而是“记不住”。现有的 ZoomIn 方案是通过外部裁剪强行让模型重新看一遍，而 InnerZoom 的思路是： 既然中间层已经有了证据，为什么不把它提取出来，直接喂给后面的解码层？
### 方法拆解：把“视觉记忆”变成“持续引导”
InnerZoom 的核心机制可以概括为三个步骤，全程无需额外输入：
-证据提取（Target-Region Evidence Extraction）
在坐标生成前，利用指令 Token 和视觉 Token 的注意力映射，定位高响应区域。关键一步是：它不去看压缩后的视觉 Token，而是去抓取未合并的原始 Vision Encoder 特征。这些特征保留了更丰富的局部细节，为精准点击提供素材。
-跨层精炼（Cross-Layer Evidence Refinement）
这是最巧妙的设计。作者引入了一个共享的“迭代双槽证据适配器”（Iterative Dual-Slot Evidence Adapter）。
它在第 20、23、26、29 层插入，形成一个跨层工作空间。
- 这个空间像一个“记忆缓存”，随着解码层层推进，不断聚合和更新目标区域的视觉证据。
- 通过门控机制（Gated Update），它只保留与当前解码上下文最相关的证据，避免噪声干扰。
-引导解码（Evidence-Guided Decoding）
精炼后的证据不是简单相加，而是注入到目标区域位置的 Key/Value 投影中。
Query 保持不变，保证自回归解码流程不被破坏。
- KV 被替换为增强版特征，使得模型在生成坐标 Token 时，能“看到”经过多层精炼的高精度局部细节。
### 实验结果：又快又准，碾压 ZoomIn在相同的 4B 基座和训练配置下，InnerZoom 的表现令人印象深刻。它不仅比单步基线强，甚至在多数场景下超过了需要两次推理的 ZoomIn。

### 工程启示与局限为什么你应该关注 InnerZoom？
- 推理成本减半：对于需要高频交互的 GUI Agent（如自动化测试、RPA），减少一次前向传播意味着响应速度直接翻倍。
- 无需修改推理框架：InnerZoom 是模型内部的结构调整，不需要像 ZoomIn 那样在应用层做复杂的裁剪和重传逻辑。
- 小模型友好：实验显示 2B 版本同样有效，证明了该方法不依赖大模型的冗余容量，适合边缘设备部署。
局限与思考- 超参敏感：适配器插入的层数（20, 23, 26, 29）和槽位数量（2个）经过仔细调优。不同架构的模型可能需要重新搜索这些位置。
- 极端场景依赖裁剪：在 SS-Pro 等超宽屏双显示器测试中，InnerZoom 略逊于 ZoomIn。这说明当目标区域极小且背景极复杂时，物理裁剪带来的分辨率提升仍有不可替代的价值。
总的来说，InnerZoom 证明了“更聪明的单次推理”优于“笨拙的多次推理”。它不是简单的增量改进，而是对 MLLM 视觉-语言对齐机制的一次深刻重构。如果你正在构建低延迟的 GUI Agent，值得深入研读其代码实现。
