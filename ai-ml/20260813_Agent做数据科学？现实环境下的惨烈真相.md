论文 : DSAgentBench: Can Agents Automate End-to-End Data-Science Workflows in Real Computer Environments?
链接 : https://arxiv.org/abs/2608.10366现在的 AI Agent 吹得有多神？能写代码、能修 Bug，甚至号称能自动跑通整个数据科学流程。但 DSAgentBench 这篇论文直接泼了一盆冷水：在真实的操作系统里，让 Agent 从零开始完成端到端的数据分析任务，即使是当前最强的闭源模型，成功率也不到 60%。
这不仅仅是个 Benchmark，更是一次对“Agent 落地能力”的残酷压力测试。它揭示了一个被忽略的工程真相： 能生成正确的 Python 代码，绝不等于能在复杂的桌面环境中自主完成数据分析。
### 为什么现有评测都在“自嗨”？
过去的数据科学评测（如 DS-1000、MLAgentBench）大多停留在“静态代码执行”层面。你给模型一个数据集和一段指令，它吐出代码，跑通就算赢。
但这太脱离现实了。真实的数据科学家每天在做什么？
- 去 Kaggle 或 GitHub 下载数据；- 在终端安装依赖、处理环境报错；- 在 Jupyter Notebook 里探索数据，发现异常后切回 IDE 修代码；- 最后生成可视化图表并汇报。
这是一个**多工具协调（Multi-tool Coordination） 且 长周期（Long-horizon）**的过程。现有的评测缺乏“真实计算机交互”，无法评估 Agent 是否具备在操作系统中“落地”的能力。DSAgentBench 正是为了填补这一空白而生。
### 核心设计：把 Agent 扔进真实的 Ubuntu 桌面DSAgentBench 的核心 Insight 在于： 评估必须基于最终产出的语义正确性，而非代码的语法正确性。
- 真实环境构建：基于 OSWorld 框架，搭建了一个包含 VS Code、Jupyter Notebook、Chrome 和终端的真实 Ubuntu 环境。Agent 需要通过截图（Screenshot）或辅助功能树（A11y Tree）来感知界面，并通过鼠标点击、键盘输入来操作软件。
- 全生命周期任务：包含 275 个任务，覆盖数据获取、探索性分析（EDA）、特征工程、建模、评估和可视化六大阶段。其中近半数（47.6%）被标记为“困难”，需要 5 步以上的复杂推理。
- 确定性评估器：这是最硬核的部分。评测不看代码长什么样，而是检查最终生成的文件、图表或模型指标是否符合预期。例如，相关性分析任务会直接读取计算出的皮尔逊系数，误差容忍度仅为 ϵ=0.01\epsilon = 0.010.01。
### 实验结果：巨头们也没能“通关”
论文对 15 个主流 Agent 进行了测试，结果令人深思。
模型 Screenshot + A11y 成功率 主要失败原因 Claude-4.6-Sonnet 56.70% (最强) 终端操作、代码逻辑错误 GPT-5 29.81% 规划能力不足、早期失败多 Gemini-2.5-Pro 20.81% 接地（Grounding）问题 GPT-4o 24.54% UI 接地错误为主 开源模型 (如 UI-TARS) < 1% 几乎全部因接地失败⚠️ 反直觉发现 ：增加步数预算并不能显著提升成功率。将最大交互步数从 15 步增加到 50 步，GPT-4o 的成功率仅从 24.54% 微增至 25.81%。这说明瓶颈不在“时间不够”，而在“根本不知道下一步该干什么”或“操作完全错误”。
此外， 辅助功能树（A11y Tree） 的加入确实有帮助。Claude-4.6-Sonnet 在加上 A11y 信息后，整体成功率从 50.55% 提升至 56.70%。这证明结构化的 UI 元数据能显著改善 Agent 的界面接地能力。
### 工程启示：Agent 落地的三个深坑对于正在尝试构建数据科学 Agent 的工程师来说，这篇论文提供了宝贵的避坑指南：
- 接地（Grounding）是首要难题：开源模型几乎全军覆没（<1%），主要原因就是无法正确识别屏幕上的按钮和文本。如果你的 Agent 连“点击运行”都找不到，谈何数据分析？
- 多工具切换是性能杀手：实验显示，仅在 Jupyter Notebook 中执行的任务成功率远高于涉及 VS Code 和终端的多工具任务。Agent 在跨应用切换时容易丢失上下文状态。
- 错误恢复能力极弱：分析表明，许多失败发生在早期步骤（如无法打开终端或安装库）。一旦第一步出错，后续所有推理都建立在错误的系统状态上，导致“一步错，步步错”。
### 局限与展望DSAgentBench 目前主要聚焦于表格数据（95.3%），对图像和文本数据的处理涉及较少。此外，开源模型尚不支持 A11y Tree 输入，这在一定程度上限制了公平对比。
但这并不妨碍它成为该领域的基石。它告诉我们： 通往自主数据科学 Agent 的路，远比我们想象的漫长。 未来的突破点可能不在于更大的语言模型，而在于更鲁棒的 GUI 接地技术和更强的环境状态管理能力。
