# 企业Agent需要世界模型吗？

**日期**: 2026-05-13

---

论文 : Do Enterprise Systems Need Learned World Models? The Importance of Context to Infer Dynamics链接 : https://arxiv.org/abs/2605.12178在传统的强化学习和具身智能领域，“世界模型（World Models）“几乎成了标配：让智能体在内部构建一个模拟器，通过预测环境状态变化来规划行动。但在企业级 SaaS 场景（如 ServiceNow）中，这套逻辑可能跑不通。ServiceNow 的研究团队发表了一篇极具颠覆性的论文，直接质疑了在企业环境中训练固定权重世界模型的必要性。
核心结论很反直觉：当系统动态（Dynamics）由可读取的业务规则定义时， 运行时检索（Runtime Discovery） 比 离线微调（SFT） 更鲁棒，更能适应租户间的配置差异。
## 为什么传统世界模型在企业里会”水土不服”？
企业系统和封闭环境（如游戏、机器人仿真）最大的区别在于： 动态是非固定的，且是显式可读的。
在机器人领域，重力加速度是恒定的，物理规律内化到模型里即可。但在企业服务中，同一个动作（比如”创建工单”），在不同客户（Tenant）那里引发的后果完全不同。这取决于该租户部署的业务规则、工作流、SLA 策略等配置项（Configuration, cc ）。
论文将状态转移建模为：
st+1∼P(st+1∣st,at,c)st+1 \sim P(st+1 | st, at, c) 1 ∼ P ( s t + 1∣ s t , a t , c )
如果采用传统的世界模型思路，我们需要收集大量历史数据来微调模型（Fine-tuning），试图让模型”记住”这些动态。但问题是：
- 配置随时变：管理员会修改规则，模型训练出来的分布很快过时。
- 租户差异大：A 客户的规则在 B 客户那里可能完全失效。
- 规则是可见的：企业系统通常暴露了 API 和配置元数据，我们不需要”猜”，可以直接”读”。
因此，论文提出了一个简单却有力的假设： 既然规则在推理时就能读到，为什么还要让模型去死记硬背？
## 方法拆解：从”记忆”转向”发现”
作者对比了三种路径：
- Prompted Baseline：仅靠零样本提示，不提供额外上下文。
- Learned World Model：在转移数据上进行监督微调（Supervised Fine-Tuning, SFT），试图内化动态。
- Enterprise Discovery Agent：不更新权重，而是在推理时主动查询当前实例的配置（业务规则、Schema），然后基于检索到的上下文进行推理。
关键 Insight 在于 Discovery Agent 的设计。它不试图用一个固定的神经网络去近似整个环境，而是采用 “Retrieve-then-Reason” 策略。对于复杂的多步级联（Cascade），它会动态检索相关的业务规则，将其注入 LLM 上下文，从而获得针对当前实例的精准预测。
## 关键结果：微调在分布外（OOD）崩塌为了验证这一点，作者构建了 CascadeBench 基准测试，专门评估在配置漂移（Configuration Shift）下的表现。实验结果非常打脸：
1. 微调在训练分布内很强，但出了分布就废了如图 3 所示，Gemma-4-31B 微调后在分布内（In-distribution）的 IoU 达到了 91.6 ，远超基线的 ~23。但在面对未见过的租户配置（CascadeBench OOD）时，性能暴跌至 40.47 ，几乎回到了基线水平。这说明微调只是记住了特定分布的模式，并没有学会通用的推理逻辑。

## 工程启示- 不要盲目微调世界模型：如果你的应用场景中，环境动态是由外部配置驱动的（如 CRM、ERP、ITSM），训练一个固定的世界模型性价比极低。一旦客户配置变更，模型就需要重新训练或微调，维护成本高昂。
- RAG 是企业的”世界模型”：对于这类系统，构建一个强大的 Retrieval-Augmented Generation (RAG) 系统，让 Agent 在推理时实时获取当前的业务规则、工作流定义和 Schema，比训练一个庞大的预测模型更有效。
- 分层处理复杂度：论文将动态分为 Tier 1（Schema 决定）、Tier 2（规则级联）和 Tier 3（执行语义）。对于 Tier 1 和 Tier 2，通过检索规则即可解决；只有 Tier 3（涉及引擎内部执行顺序等黑盒行为）才需要更复杂的探索或学习。
## 局限与展望当然，Discovery Agent 不是银弹。它依赖于 业务规则的可读性 。如果访问控制限制了规则查看，Agent 就会退化为普通的 Prompted Baseline。此外，对于 27B-31B 规模的开放权重模型，检索循环的可靠性仍不如微调模型稳定，这意味着在小模型场景下，混合策略（结合微调先验和运行时检索）可能是未来的方向。
总之，这篇论文提醒我们： 在规则显式的企业系统中，“知道去哪找规则”比”记住规则”更重要。
