论文 : PIPE-Cypher: Automatic Enterprise Benchmark Generation for Text-to-Cypher Systems链接 : https://arxiv.org/abs/2606.08481企业图数据库（Property Graphs）的评估一直是个痛点。公开数据集如 SNB 或 FinBench 无法反映企业内部独特的 Schema、术语和业务逻辑。
如果直接让 LLM 生成合成数据，往往面临“幻觉”和“不可执行”的双重陷阱。这篇论文提出了 PIPE-Cypher ，一个完全本地化的基准生成流水线，旨在解决企业级 Text-to-Cypher 系统的评估难题。
它的核心价值不在于提出新的模型，而在于构建了一套 可重复、可审计、隐私安全 的数据工厂流程。对于需要私有化部署且对数据一致性要求极高的金融或合规场景，这套工程实践极具参考价值。
### 为什么现有方案不够用？
传统的 Text-to-SQL/Cypher 评估依赖静态公开数据集。但在企业中：
- Schema 独特性：每个公司的实体关系、属性命名和值域都不同。
- 动态变化：随着产品迭代，图结构频繁变更，静态基准迅速过时。
- 隐私边界：敏感业务数据不能上传至云端 API 进行生成或评估。
更关键的是，单纯依靠 Prompt 让 LLM 生成 Cypher 查询并不可靠。模型可能写出语法正确但语义错误（如关系方向反了）或无法执行的查询。PIPE-Cypher 的核心 Insight 是： 将“生成”与“验证”解耦，用确定性规则约束概率性生成。
### 方法拆解：六步走的确定性流水线PIPE-Cypher 不依赖单一的大模型黑盒，而是采用了一个混合架构：本地小模型负责语言生成，确定性代码负责逻辑校验。
-Schema 画像与逆向接地（Reverse Grounding）
这是最关键的创新点。在生成问题之前，系统先通过只读 Cypher 查询找到图中实际存在的“槽位值”（Slot Values）。
设计意图：避免生成“看起来合理但图中无答案”的问题。例如，如果图中没有名为 “John” 的用户，生成的问题就不应包含该实体。
-约束生成与修复使用本地模型（如 Qwen3.5-9B）基于模板和逆向接地的值生成 Cypher。
关键控制：引入“类型占位符”机制，防止模型记忆特定租户的敏感值，同时保持查询结构的一致性。
-确定性治理层（Deterministic Governance）
在 LLM 判断之前，先通过代码层进行硬性过滤：
只读安全：拦截任何写操作或管理员权限调用。
- 方向校验：检查关系箭头方向是否符合 Schema 定义。
- 字面量精确匹配：确保查询中的值与图中实际存储的值完全一致（包括大小写、标点）。
-执行验证与 LLM 裁判只有通过了上述硬性检查的候选项，才会被送入本地 LLM 裁判进行语义审查。
效率优化：裁判 Prompt 仅包含查询涉及的相关 Schema 片段，而非全量 Schema，降低了上下文长度和计算成本。
### 关键结果：数据不说谎作者在 FinBench、SNB 和 ICIJ 三个公开代理图上进行了验证，结果揭示了当前 Text-to-Cypher 模型的脆弱性。
1. 生成效率与质量- 产出规模：从 4,925 个候选生成了 3,000 个被接受的平衡样本（FinBench 2,000 + SNB 1,000）。
- 接受率：整体接受率为 60.9%。大部分拒绝源于重复性控制或执行结果为空，而非语法错误。
- 多样性治理：通过 MMR 风格的新颖性目标选择，结构化子结构覆盖从 97 提升至 134，属性覆盖率从 0.407 提升至 0.426（Table 3）。
2. 下游模型压力测试这是最让人警惕的数据。在 296 个保留样本上，11 个本地模型的零样本（Zero-shot）执行准确率极低：
- 均值准确率：仅 0.036。
- 最佳模型：最高仅达到 0.203。
- 解析有效性 vs 执行准确性：Qwen3.5-9B 基线模型的解析有效率达 0.963，Schema 有效性达 0.916，但执行准确率仅为 0.189。
⚠️ 反直觉发现 ：模型能写出语法完美、符合 Schema 的 Cypher，但往往问错了问题或遍历了错误的关系路径。这证明仅靠语法检查（Syntax Check）作为评估指标是严重失真的。
3. Few-shot 的效果边界- 无签名泄露控制：当排除与测试集具有相同查询签名的示例后，平均准确率提升至 0.200。
- 同类示例库：使用有序或随机的同类示例作为 Few-shot，准确率可达 ~0.27，但这被视为操作上限（Operational Upper Bound），因为存在签名泄露风险。
### 工程启示- 本地化是刚需：PIPE-Cypher 全程使用本地模型（Qwen3.5-9B）进行生成和裁判，无需调用付费 API。这对于处理敏感金融或合规数据的企业至关重要。
- 验证重于生成：不要指望 Prompt Engineering 能解决所有逻辑错误。引入确定性的 AST 解析、执行引擎校验和方向检查，是保证基准质量的下限。
- 基准即资产：生成的基准不仅是测试集，还可以作为 Schema 特定的检索增强（RAG）示例库。PIPE-Cypher 提供的“脱敏导出”功能，使得这些高质量对可以在内部安全地用于微调或 RAG。
### 局限与展望- 语义正确性不等于执行正确性：虽然执行验证能过滤掉语法错误，但 LLM 裁判的校准仍依赖少量人工标注（80 行样本，Kappa=0.60）。
- 模板集中化：尽管有多样性控制，查询签名（Query Signature）的多样性仍然较低，主要受限于种子模板。
- 构造限制：为了安全，管道故意跳过了 UNION、CALL 等复杂或高风险的 Cypher 结构，这意味着它覆盖的是“安全子集”，而非全量生产环境查询。
PIPE-Cypher 提供了一套成熟的工程范式： 用确定性规则约束概率模型，用执行结果验证语义逻辑 。对于任何试图在企业内部落地 Text-to-Graph 应用团队来说，这套流水线比单纯调优 Prompt 更具长期价值。
