论文 : Running the Gauntlet: Re-evaluating the Capabilities of Agents Beyond Familiar Environments链接 : https://arxiv.org/abs/2606.14397现在的 Web Agent 评测大多像是在“刷分”。在 Amazon、Booking 这些常见电商或 CRM 系统上，SOTA 模型早已接近满分。但这真的代表 Agent 能处理复杂工作流了吗？牛津大学与 SoftServe 联合发布的 GauntletBench 给了行业一记响亮的耳光： 当面对视频剪辑、3D建模等专业级应用时，最强 Agent 的成功率仅为 19.1%，而普通人类非专家用户能达到 80% 以上。
### 为什么现有评测“失效”了？
当前主流基准（如 WebArena, REAL）存在两个致命盲区：
- 场景同质化：任务多基于消费级应用，逻辑简单且重复。
- 能力维度单一：过度关注 UI 导航和表单填写，忽视了 时间感知（Temporal Perception）、图形理解（Graphical Understanding） 和 3D 推理（3D Reasoning）。
GauntletBench 的核心洞察是： Agent 需要被推向“不熟悉”且“视觉密集”的专业环境。 为此，作者构建了五个专业 Web 应用：视频编辑器、工作流构建器、3D 建模器、航班分析器和电路设计器。这些界面大量使用 Canvas 渲染，刻意屏蔽了 DOM 树等结构化信息，强迫 Agent 像人类一样依赖截图进行视觉感知。
### 方法拆解：不仅是难，而是“真”
GauntletBench 的设计精髓在于其 模块化管道（Modular Pipeline） 和 定制化评估器 ：
- 环境隔离：支持开源 MLLM 和闭源框架（如 GPT CU, Claude CU）的统一接口。
- 视觉强制：在 3D 建模等场景中，仅提供截图观察空间，禁止访问底层浏览器 API。这直接测试了模型对非结构化视觉信息的解析能力。
- 人性化评估：传统评测是“全有或全无”的字符串匹配。GauntletBench 引入了容忍度机制。例如，视频剪辑任务中，时间戳允许 ±100ms 误差；颜色匹配采用模糊算法。这更贴近真实业务场景中对“可用性”而非“绝对精确”的需求。
### 关键结果：SOTA 模型的尴尬现状实验数据揭示了令人震惊的能力断层。以下是核心对比（基于论文 Table 2）：

- 视觉模态至关重要：在仅暴露少量结构化信息的场景中，纯文本 LLM 几乎完全失效。引入视觉输入后，Qwen 和 GPT 系列的进度率分别提升了 43.5% 和 15.5%。
- 规模即正义：Table 3 显示，在同一架构下，更大规模的模型（如 Claude Opus vs Haiku）不仅成功率更高，且消耗 Token 更少。这说明对于复杂任务，单纯靠“多思考几步”无法弥补基础能力的不足。
- 推理的双刃剑：开启扩展推理（Extended Reasoning）能提升强基座模型的效果，但对弱模型效果甚微，反而增加了 Token 消耗和步骤数。
### 工程启示：从“刷榜”到“落地”
- 不要迷信 DOM 树：在专业软件（如 Figma, Premiere Web版）中，DOM 往往缺乏语义或完全由 Canvas 绘制。Agent 必须具备强大的 视觉 grounding 能力，不能仅依赖辅助功能树（Accessibility Tree）。
- 评估指标需重构：简单的 Success Rate 无法反映 Agent 的潜力。GauntletBench 引入的 Progress Rate（进度率） 更具参考价值——它表明 Agent 可能完成了 80% 的逻辑，只是最后一步出错。这对调试 Agent 轨迹至关重要。
- 分治策略优于盲目堆栈：Figure 5 显示，Claude Opus CU 虽然步骤较多，但通过更细粒度的增量操作（Divide-and-Conquer），实现了最高的成功率和较低的推理成本。这提示我们在设计 Agent 时，应鼓励其拆解复杂任务，而非一次性输出完整计划。
### 局限与展望GauntletBench 目前仅覆盖 100 个任务，且局限于 Web 环境。此外，错误分析显示， “任务完成误判” （Agent 以为做完了但其实没做完）和 “接地失败” （点错位置且不自知）是主要瓶颈。
未来，随着多模态模型视觉能力的提升，我们预计这些专业场景的成功率会逐步上升。但在达到人类水平之前，盲目将 Agent 部署到核心生产流程中，风险依然极高。 真正的智能，不在于在熟悉的环境中刷高分，而在于在不熟悉的领域中能走多远。
