论文 : OmniPack: Unified Token Compression for Efficient Omni-modal Large Language Models链接 : https://arxiv.org/abs/2608.03812Omni-LLM（全模态大语言模型）虽然强大，但音视频输入产生的海量 Token 让推理成本高得离谱。这篇论文提出的 OmniPack 是一个无需训练（Training-free）的框架，能在几乎不损失性能的前提下，把计算量砍掉九成以上。对于正在尝试部署本地多模态 Agent 或长视频理解应用的工程师来说，这不仅是加速方案，更是落地可行性的关键突破。
## 现有方案的痛点：为什么简单压缩行不通？
目前的 Token 压缩方法主要分为两类，但都有明显缺陷：
- Pre-LLM 压缩（进入 LLM 前）：通常基于局部重要性或相似度合并。问题在于，多模态证据往往分散在长序列中（如视频首尾的关键帧、音频中的短暂异响）。只看局部容易丢弃全局分布的关键信息，导致“瞎子摸象”。
- Inner-LLM 压缩（在 LLM 内部）：虽然利用了文本引导，但往往忽略了音频和视频之间的跨模态协作。在 LLM 深层，视听特征已经充分交互，如果只靠文本去剪枝，就浪费了这种复杂的语义关联。
核心洞察 ：不同阶段该用不同的压缩策略。进入 LLM 前，应利用模态特定的时空结构去除冗余；在 LLM 内部交互充分后，再利用任务相关的语义和跨模态协作进行精细化剪枝。
## 方法拆解：两阶段协同压缩OmniPack 的设计非常巧妙，它把压缩过程分成了两个互补的阶段：
### 1. Pre-LLM：基于结构的粗粒度压缩在进入 LLM 之前，模型还没有理解任务意图，因此 OmniPack 利用编码器自身的注意力机制和模态特性来筛选 Token。
- 重要性选择：不仅看注意力中心度，还结合视频的空间/时间变化率、音频的瞬态事件边界。这确保了关键动作和声音突变被保留。
- 覆盖性选择：为了防止只关注局部热点，使用 DPC-KNN 算法确保选出的 Token 在时空上具有代表性且分布均匀。
- 相似度合并：这是亮点之一。未被选中的 Token 不会被直接丢弃，而是根据亲和度“合并”到保留的代表性 Token 中。这相当于把冗余信息压缩进关键节点，减少了不可逆的信息丢失。
### 2. Inner-LLM：基于语义的细粒度精炼在 LLM 的第 ℓ\ell 层（实验发现第 18 层效果最佳），视听特征已经与文本充分交互。此时进行第二次压缩：
- 查询感知：计算 Token 与全局文本查询向量的相关性。
- 视听协作：引入跨模态原型，衡量视觉 Token 与音频原型的匹配度，反之亦然。这确保了“看图说话”或“听音辨位”所需的跨模态证据不被误删。
- 多样性保留：在筛选时平衡相关性和语义多样性，避免所有保留 Token 都指向同一类信息。

## 工程启示：如何落地？
- 即插即用：OmniPack 是 Training-free 的，这意味着你可以直接把它集成到现有的 Qwen2.5-Omni 或 MiniCPM-o 推理管线中，无需重新训练模型。
- 动态层选择：Inner-LLM 压缩的最佳层数因模型而异（Qwen2.5-Omni-7B 是第 18 层，3B 版本是第 26 层）。在实际部署时，建议针对特定 backbone 进行简单的网格搜索以确定最佳截断层。
- 长视频/音频首选：对于长序列输入，Pre-LLM 的结构化压缩能大幅减少初始 Token 数量，显著降低显存占用和首字延迟（TTFT）。
## 局限与展望尽管效果出色，但该方法仍依赖编码器输出的注意力图和模态特定的结构线索。如果输入数据的分布发生剧烈变化（如极端噪声或非常规视角），基于统计的覆盖性选择可能会失效。此外，目前主要验证了 Qwen 和 MiniCPM 系列，对其他架构（如 LLaVA-OneVision）的泛化性仍需进一步测试。
