# ⭐⭐⭐ RePoT：让 LLM 规划具备断点续传能力

**日期**: 2026-05-30

---

论文 : REPOT: Recoverable Program-of-Thought via Checkpoint Repair链接 : https://arxiv.org/abs/2605.30052在当前的 Agent 开发中，我们常面临一个尴尬的局面：LLM 生成的代码或计划在前 90% 都完美无缺，却在最后一步因为一个非法操作导致全盘崩溃。传统的补救手段要么是完全重跑（浪费算力），要么是昂贵的树搜索（延迟高）。这篇论文提出的 RePoT 方案，巧妙地将“断点续传”机制引入 LLM 规划，用极低的额外成本实现了错误的局部修复。
### 为什么现有的“一次性”规划不可靠？
Program-of-Thought (PoT) 让模型生成 Python 代码来输出行动序列，这比纯文本推理更稳健。但 PoT 有一个致命弱点： 全有或全无（All-or-Nothing） 。
一旦执行过程中出现一个非法动作，整个轨迹就废了。现有的改进方案主要有两类：
- 多采样投票（如 Self-Consistency）：不管第一次是否接近成功，都生成 kk 次，成本是 O(k)O(k)。
- 树搜索（如 ToT, LATS）：在生成过程中就进行分支探索，计算开销巨大。
这两种方法都忽略了一个事实： 大多数失败案例中，LLM 已经生成了很长的有效前缀 。如果能把这个“已验证的前缀”保存下来，只让模型修复剩余部分，效率会高得多。
### RePoT 的核心设计：确定性回放 + 后缀修复RePoT 的设计直觉非常工程化：把 LLM 当作一个不靠谱的草稿员，而把环境模拟器（Environment Simulator）当作严格的质检员。
整个流程分为三步：
- 生成：LLM 生成一次 PoT 计划。
- 确定性回放（Verified Replay）：这是核心创新。系统不直接运行整个计划，而是逐步在环境中模拟执行。每一步都检查合法性，直到遇到第一个非法动作为止。此时，我们得到了一个最大验证前缀（Maximal Verified Prefix）和当前的确切状态。
- 后缀修复：如果前缀未达目标，发起第二次 LLM 调用。关键区别在于，这次调用的输入不是“请重试”，而是：“当前状态是 SS，之前成功执行了动作序列 PP，请从 SS 开始继续规划”。
核心 Insight ：LLM 不需要重新思考前半部分，它只需要基于“可信的检查点（Checkpoint）”进行局部修复。这种设计将“全局重算”降级为“局部增量”，极大地降低了认知负荷和计算成本。
### 实验数据：性价比极高的提升作者在多个基准测试上验证了 RePoT 的效果，数据非常漂亮：

成本方面，由于只有约 14% 的问题需要第二次调用，RePoT 的平均 LLM 调用次数仅为 PoT 的 1.11-1.39 倍 。这意味着你用不到 20% 的额外成本，换来了显著的准确率提升。
### ⚠️ 反直觉发现：检查点比“错误反馈”更重要为了搞清楚 RePoT 为什么有效，作者构建了一个名为 DERAIL-550 的控制实验，专门注入错误并测试恢复能力。结果令人惊讶：
- 仅给错误信息（Error-only）：GPT-medium 的恢复成功率仅为 3.1%。
- 给出检查点状态（Checkpointed）：成功率飙升至 ≥30%（GPT）甚至 ≥70%（Gemini）。
这揭示了一个重要结论： LLM 很难通过文本形式的“错误批评”来自我修正，但它非常擅长基于确定的环境状态继续规划。 “可信的状态快照”是恢复能力的承载信号，而非具体的错误描述。
### 工程启示与局限对于正在构建 Agent 或代码生成系统的工程师，RePoT 提供了几个实用的建议：
- 引入确定性验证器：如果你的任务有明确的环境反馈（如 SQL 执行结果、单元测试、游戏模拟器），务必在每次 LLM 调用后进行逐步验证，而不是等到最后。
- 状态传递优于文本反思：当修复错误时，不要只把 Error Log 扔给模型。将当前的中间状态（State）序列化后作为 Context 传入，效果远好于让模型“回想”自己错在哪。
- 自适应策略：论文提到，如果验证前缀非常短（如 <15%<15\%15%），直接重试（Fresh Retry）可能比修复更有效。这提示我们可以实现一个简单的路由逻辑：前缀长则修复，前缀短则重跑。
局限性 ：RePoT 强依赖于存在一个确定性的环境验证器。对于开放式创作或没有明确对错标准的任务，这种方法难以直接应用。此外，如果 LLM 在第一步就完全迷失（空前缀），RePoT 会退化为简单的重试，此时其优势不再明显。
总之，RePoT 是一个轻量级但极具工程价值的改进。它证明了在不增加复杂树搜索结构的前提下，通过精细的状态管理，就能显著提升 LLM 规划的鲁棒性。
