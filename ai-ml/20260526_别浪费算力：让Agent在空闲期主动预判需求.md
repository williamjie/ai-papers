论文 : Anticipate and Learn: Unleashing Idle-Time Compute in Proactive Agents链接 : https://arxiv.org/abs/2605.25971现在的 AI Agent 大多像个“懒政”客服：你问一句，它答一句；任务一结束，立刻休眠。这种纯反应式（Reactive）的交互模式最大的浪费，就是忽略了用户提问之间的“空闲时间”。上海交大与腾讯联合提出的 ProAct 架构，核心直觉非常直接： 与其在用户提问时临时抱佛脚，不如在空闲期利用算力提前预判需求、搜集证据。
### 为什么需要“主动”？
传统 Agent 的痛点在于“被动响应”。当用户提出复杂需求（如“准备项目汇报 PPT”）时，Agent 往往需要从零开始检索信息、生成内容，导致交互轮次多、用户等待久。心理学中的“主动应对”（Proactive Coping）策略认为，个体应在压力出现前就积累资源。ProAct 将这一理念引入 Agent 设计：利用对话历史与持久化记忆，在空闲窗口期预测未来需求，并提前准备好知识工件。
### 方法拆解：预测 + 获取 + 门控ProAct 并非简单的后台搜索，而是一个结构化的闭环系统，核心由三个模块驱动：
-未来状态预测（Future-State Prediction）：
这是系统的“大脑”。它不只盯着最后一句对话，而是结合持久化记忆（用户画像、历史摘要、未解决的知识缺口）来推演未来。例如，当用户预约了会议，系统不仅记录动作，还会推断“可能需要进度汇报材料”，从而生成候选需求集 ZtZ_t​。
-空闲时间获取（Idle-Time Acquisition）：
这是系统的“手脚”。面对预测出的多个候选需求，系统不会盲目执行，而是通过一个价值评分函数进行筛选：
S(z)=wrrz+wggz+wvvz+wττzS(z) = w_r r_z + w_g g_z + w_v v_z + w_\tau \tau_zwr​rz​+wg​gz​+wv​vz​+wτ​τz​其中 rr 是相关性，gg 是知识缺口，vv 是增量价值，τ\tau 是时效性。只有得分高于阈值的需求，才会触发后台的证据检索或工件生成。这种设计避免了无意义的算力空转。
-价值感知推送门控（Value-Aware Push Gate）：
这是系统的“刹车”。提前准备的内容不一定非要立刻告诉用户。系统会根据预期效用与打扰成本的权衡，决定是主动推送、排队待用还是静默存储。这解决了“过度主动”导致的用户体验下降问题。
### 关键结果：预测指导比盲目搜索强得多为了验证效果，作者构建了 ProActEval（200 个场景，40 个领域）。实验设计非常严谨，对比了三种情况：
- Reactive：纯反应式基线。
- Undirected Idle：有空闲时间获取，但无预测指导（盲目搜索）。
- Directed Idle：完整的 ProAct（预测 + 获取）。
数据揭示了核心 Insight： 算力本身不是瓶颈，方向才是。

### 工程启示与局限对工程师的指导意义：
- 重构空闲时间：不要让用户等待时 Agent 处于休眠状态。利用这段时间进行轻量级的意图预测和证据预取。
- 记忆即资产：持久化记忆不仅是存储，更是预测的输入。需要建立结构化的用户画像和知识缺口追踪机制。
- 门控策略至关重要：主动推送是一把双刃剑。必须实现基于效用/成本权衡的门控逻辑，避免“帮倒忙”。
局限与展望：
目前 ProActEval 是基于合成数据的封闭世界测试，真实场景中的用户需求更不可预测。此外，过度依赖 LLM Judge 进行评估可能存在偏差。未来工作需关注开放域下的误判率控制以及用户自定义的干预阈值调节。
总之，ProAct 提供了一个清晰的范式： 从“响应式助手”向“预判型伙伴”演进，核心在于将计算重心从交互瞬间前移至空闲窗口。
