# ⭐⭐⭐½ 扩散语言模型的新解：为每个Token分配独立时间

**日期**: 2026-07-18

---

论文 : Token Time Continuous Diffusion for Language Modeling链接 : https://arxiv.org/abs/2607.14106在加速推理的竞赛中，离散扩散模型（Discrete Diffusion LMs）往往因为“并行采样”带来的分布失真而翻车。这篇来自 UT Austin 的工作提出了一种名为 TTCD（Token Time Continuous Diffusion）的新架构，核心直觉非常大胆：既然不同 Token 的确定性不同，为什么不让它们以不同的速度从噪声演变为数据？
### 痛点：全局时间的 tyranny现有的扩散语言模型通常使用一个全局时间步 tt 。这意味着在去噪过程中，所有 Token 都处于相同的“模糊程度”。
这在工程上带来两个严重问题：
- 因子分解问题（Factorization Problem）：在高加速比（少步数）下，并行采样多个 Token 会导致分布近似误差，生成的文本质量断崖式下跌。
- 无法区分已知与未知：在条件生成任务中，Prompt 是清晰的，而 Canvas 是噪声的。全局时间迫使模型用同一套逻辑处理两者，这显然不符合直觉。
### 核心 Insight：Per-Token TimesTTCD 的核心创新在于引入了 每个 Token 独立的时间（Per-token times） 。
关键设计 ：不再所有 Token 共享同一个 tt ，而是为每个位置分配一个局部时间 tlt_l ​ 。这个时间由全局时间 tgt_g ​ 和一个随机分配的“秩”（Rank）决定。
这种设计的精妙之处在于：
- 连续空间演化：Token 嵌入从高斯噪声确定性地流向干净数据，避免了离散空间的采样误差。
- 差异化去噪速率：通过 Beta 分布量化函数映射，某些 Token 会比其他 Token 更快完成“去噪”。
- 熵驱动排序：在推理时，模型根据输出分布的熵来分配 Rank。确定性高的 Token（低熵）获得高 Rank，从而更早被“确定”；不确定性高的则保留更多噪声，等待后续步骤细化。

在 160M 参数规模的蒸馏模型对比中：
- 无条件生成：TTCD 在 1-4 步生成中，其困惑度（Perplexity）和文本熵的平衡优于离散基线 Duo w/ DCD。
- 条件生成：这是 TTCD 的主场。由于 Prompt Token 的时间被固定为 1（完全干净），而 Canvas Token 从 0 开始演化，模型能自然地利用上下文信息。在 32 长度 Canvas 的 4 步生成中，TTCD 显著优于 FMLM 和 Duo。
### 工程启示：为什么你应该关注 TTCD？
- 推理加速的新范式：如果你正在尝试将扩散模型用于低延迟场景（如实时对话、Agent 思考过程），TTCD 提供的“确定性提前收敛”机制可能比传统的蒸馏更有效。
- 无需额外参数的架构修改：TTCD 对 DiT 架构的修改非常轻量，主要是将 AdaLN 中的全局时间替换为每个 Token 的局部时间嵌入。这意味着现有的扩散 Transformer 代码库可以很容易地适配这一特性。
- 解决“重复词”问题：连续空间模型常因熵崩溃导致生成重复文本。TTCD 通过让不同 Token 在不同时间点变“确定”，天然地缓解了这一问题，生成了更多样化的文本（见图 1 中 TTCD 更高的熵值）。
### 局限与展望论文诚实地指出，目前实验仅在 100M-160M 参数规模下进行。在千亿参数时代，TTCD 能否保持相对于自回归模型或多 Token 预测器的优势，仍需大规模验证。此外，如何将这种“Token 时间”概念迁移到纯离散的均匀噪声模型中，也是一个有趣的开放问题。
总之，TTCD 不仅仅是一个增量改进，它挑战了扩散模型中“全局同步”的固有假设。对于追求极致推理效率的工程团队来说，这种细粒度的时间控制思路值得深入探索。
