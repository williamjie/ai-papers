# LLM Agent 何时调用工具？无需推理，隐藏状态已给出答案

**日期**: 2026-05-14

---

论文 : LLM Agents Already Know When to Call Tools — Even Without Reasoning链接 : https://arxiv.org/abs/2605.09252在构建 LLM Agent 时，我们常面临一个尴尬的现实：模型过于“勤快”，哪怕问题简单到像“巴黎的首都是哪里”这种常识，它也要先调用一次搜索或知识库。这种不必要的 Tool Call 不仅浪费 API 费用，还显著增加延迟。
这篇论文《LLM Agents Already Know When to Call Tools — Even Without Reasoning》直接戳破了当前 Agent 开发的两个幻觉：
- 通过 Prompt 工程或让模型“思考后再行动”（Reason-then-Act），无法有效抑制无效调用。
- 模型其实已经知道何时需要工具，只是它在生成文本时“嘴瓢”了，没能把内部知识转化为正确的决策。
## 现有方案为何失效？
为了验证这一点，作者首先构建了一个名为 WHEN2TOOL 的基准测试。这个基准非常硬核，涵盖了 18 个环境（15 个单跳，3 个多跳），并明确划分了三种工具必要性场景：
- 计算规模：比如万亿级乘法，模型算不了，必须用计算器。
- 知识边界：比如虚构的历史事件，模型没学过，必须用检索。
- 执行可靠性：比如追踪 20 步递归，模型容易出错，必须用代码执行器。
每个场景都有 Easy/Medium/Hard 三个难度等级，完美模拟了真实场景中“何时该用工具，何时不该用”的决策边界。
基于这个基准，作者测试了两种主流的免训练（Training-free）基线：
- Prompt-only：试图通过改变 System Prompt（如“仅在必要时调用”、“节省调用”）来抑制工具使用。
- Reason-then-Act：要求模型先输出推理过程，判断是否需要工具，再执行。
结果让人大跌眼镜（见表 2）：
- Prompt-only 是“一刀切”：它虽然减少了工具调用，但也误杀了大量“Hard”任务中真正需要的工具调用。在 Qwen3-4B 上，Hard 任务每节省一次调用，准确率损失高达 -42.4%。
- Reason-then-Act 是“伪聪明”：虽然它在 Easy 任务上表现稍好，但在 Hard 任务上依然昂贵。更糟糕的是，对于 Llama 系列模型，Reason-then-Act 直接导致工具调用崩溃（调用率从 79.5% 跌至 31.2%），模型在推理过程中陷入了“想调用但写不出正确 JSON”的死循环。
## 核心 Insight：模型“心里有数，嘴上无门”
既然 Prompt 和显式推理都搞不定，作者深入挖掘了模型的 隐藏状态（Hidden States） 。
他们提取了模型在生成答案前最后一个 token 的隐藏层表示，训练了一个极简的线性分类器（L2-regularized logistic regression）来预测“是否需要工具”。
结果令人震惊（见表 3）：
- 该探针在所有 6 个测试模型上，AUROC 均达到 0.89 - 0.96。
- 即使是在 Reason-then-Act 完全失效的 Llama 模型上，隐藏状态中依然蕴含着极强的工具必要性信号。
这说明什么？ 说明模型在内部表征中已经清晰地编码了“我能不能做”的信息，但在自回归生成过程中，由于指令跟随能力或推理链路的偏差，它无法将这个内部知识转化为外部的正确决策。
## 解决方案：Probe & Prefill基于上述发现，作者提出了 PROBE & PREFILL 。这是一个零推理开销、仅增加 <1ms 延迟的轻量级干预方法：
- Probe（探针）：在推理时，提取输入 token 的隐藏状态，通过训练好的线性探针预测是否需要工具（输出概率 pp）。
- Prefill（预填充）：根据探针预测结果，直接在模型输出前预填充一句“引导语”：
若 p<τp < \tauτ（不需要工具）：预填充 “I can solve this directly without using a tool.”
- 若 p≥τp \ge \tauτ（需要工具）：预填充 “I need to use a tool for this question.”
这相当于给模型一个“心理暗示”，强行纠正其生成方向。对于 Llama 这种指令跟随较弱的模型，甚至可以使用“硬预填充”（Hard Prefill），强制格式化输出。

在真实的 Search-o1 Agent 基准测试中，该方法在不降低准确率的前提下，将 API 调用减少了 20% - 56% 。
### 对工程师的启示- 不要迷信“思考链”能解决所有决策问题：显式推理（CoT/ToT）会增加延迟和 Token 消耗，且不一定能提升决策准确性。对于“是否调用工具”这类二元决策，内部表征可能比外部推理更可靠。
- 利用内部状态进行轻量干预：如果任务允许，提取隐藏状态并进行简单的线性探测，是一种极低成本的优化手段。它不需要微调（SFT），不需要额外的推理步骤，只需在 KV Cache 生成前插入一句引导语。
- Agent 效率优化的新范式：从“教模型怎么思考”转向“读取模型已经知道什么”。这种 Representation Engineering（表示工程）的思路，在处理 Agent 的冗余行为时，比传统的 Prompt 优化更具潜力。
## 局限与展望当然，这种方法依赖于离线训练一个探针，虽然只需秒级 CPU 训练，但仍需少量标注数据。此外，不同模型对“软预填充”（Soft Prefill）的接受度不同（如 Llama 可能需要 Hard Prefill）。未来，探索无需训练的探针提取，或将其扩展到更复杂的 Multi-hop 规划场景，将是有趣的后续方向。
