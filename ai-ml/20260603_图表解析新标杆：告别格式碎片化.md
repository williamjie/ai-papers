论文 : ChartArena: Benchmarking Chart Parsing across Languages, Scenarios, and Formats链接 : https://arxiv.org/abs/2606.01348做文档智能（Document AI）的朋友都知道，表格解析有 TableBench，公式解析有 MathVerse，但图表解析（Chart Parsing）一直是个“烂摊子”。
直到腾讯联合南开大学等机构发布 ChartArena ，这个领域终于有了第一个真正覆盖全场景、多语言、且能公平比较不同输出格式的基准测试。
这篇文章不只是扔出一个数据集，它解决了一个长期困扰工程落地的核心痛点： 如何公平地评估那些吐出不同格式（Markdown、JSON、SVG、Code）的模型？
### 为什么现在的评测都不靠谱？
现有的图表解析评测存在三个致命缺陷，导致我们无法判断模型的真实能力：
- 输出格式孤岛：有的模型吐 Markdown 表格，有的吐 Python 代码，有的吐 SVG。直接比对字符串相似度毫无意义，因为语义相同但语法不同。
- 覆盖范围狭窄：大多数基准只关注柱状图、折线图、饼图这“老三样”。流程图（Flowchart）和思维导图（Mind Map）这种需要理解拓扑结构的图表被完全忽略。
- 脱离真实场景：数据集里全是干净的数字渲染图。现实中，我们更多遇到的是打印件拍照（有透视变形、光照不均）或手绘草图。
### ChartArena 的核心设计直觉ChartArena 的 Insight 非常清晰： 评测必须与格式解耦，且必须覆盖“非理想”视觉条件。
#### 1. 格式无关的评估协议（Format-Agnostic Protocol）
这是本文最大的工程贡献。作者设计了一个标准化管道，将所有模型的异构输出映射到两个规范化的语义空间：
- 数值图表 → 三元组视图（Triple View）：无论模型输出是 CSV、JSON 还是代码，最终都解析为 (header, entity, value) 的三元组集合。
- 结构图表 → 有向图视图（Directed Graph View）：流程图和思维导图被统一转换为带标签节点和有向边的图结构。
在此基础上，使用结构感知的指标进行打分：
- Exact Match (EM)：严格匹配。
- mean Average Precision (mAP)：在多个容差阈值下计算平均精度，容忍轻微的 OCR 误差或舍入差异，但严惩结构性错误。
这种设计确保了分数反映的是 语义理解能力 ，而不是模型是否擅长生成某种特定语法。
#### 2. 全覆盖的数据集构建ChartArena 包含了 8 种图表家族 （6 种数值 + 2 种结构），跨越 3 种视觉场景 （数字渲染、打印照片、手绘照片），支持 中英双语 。
- 数据规模：共 2,400 张图表，每种设置 50 个样本。
- 标注流程：采用“人机协作”模式。先用 MLLM 生成粗粒度标注，再由人工多轮校验，确保结构一致性。特别是手绘和打印场景，通过过采样（Over-sampling）防止评测被简单案例主导。
### 关键实验发现：谁在裸泳？
作者评估了 26 个主流模型，包括通用 MLLM、文档解析专用模型和专家级图表解析器。结果揭示了几个反直觉的事实：
#### 1. 闭源模型领先，但开源差距极小- Gemini 3.1 Pro 以英文 59.2 / 中文 73.2 的平均分位居榜首。
- 开源模型紧随其后：Qwen3.5-35B-A3B（英 56.0 / 中 67.1）和 Kimi K2.5（英 54.8 / 中 68.1）表现强劲，甚至超过了部分闭源竞品如 Seed-2.0 Pro。
- 结论：在图表解析任务上，顶级开源模型已经具备了与旗舰闭源模型竞争的实力。
#### 2. 文档解析模型的“偏科”严重专门优化的文档解析模型（如 HunyuanOCR、PaddleOCR-VL）在数值图表上表现尚可，但在结构图表上 断崖式下跌 。
- HunyuanOCR：流程图英文得分仅 39.9，比 Gemini 3.1 Pro（65.6）低 25.7 分。
- 思维导图：HunyuanOCR 得分 55.0，而 Gemini 达到 86.8，差距高达 31.8 分。
- 原因分析：结构图表需要更广泛的世界知识来推断隐含的节点和层级关系，小参数量的文档解析模型缺乏这种“常识推理”能力。
#### 3. 专家模型的局限性许多专门训练的图表解析器（如 ChartAst, TinyChart）甚至无法处理流程图或思维导图，因为它们从未在训练数据中见过这些类型。即使是表现最好的专家模型 RRVF，总分也落后于通用 MLLM 约 20 分。
⚠️ 反直觉发现 ：雷达图（Radar Chart）是所有模型中最难的类别。
即使是最强的 Gemini 3.1 Pro，英文得分也只有 31.8，大多数模型低于 25。这是因为从圆形轴估计角度值本身具有几何难度，且训练数据中雷达图样本稀缺。
#### 4. 手绘场景是真正的考验在打印和手绘照片场景中，所有模型的性能都显著下降。Gemini 3.1 Pro 倾向于保守策略（用“-”代替不确定值），而 HunyuanOCR 等模型则容易幻觉出看似合理但错误的数值。
### 对工程落地的启示- 不要迷信专用小模型：如果你的业务涉及流程图或思维导图，通用的大参数 MLLM（如 Qwen3.5, Gemini）远优于专门的文档解析小模型。结构理解需要强大的语义推理底座。
- 输出格式选择很重要：实验显示，SVG 格式在数值图表上得分最低（因为需要从几何图元重建数据），而 Markdown/JSON 最稳定。对于流程图，PlantUML 由于语法限制，在处理复杂拓扑时表现远不如 Mermaid 或 Graphviz。
- 后处理管道是关键：ChartArena 的评估协议证明了，建立一个统一的“归一化层”比直接比对原始输出更有价值。在实际工程中，建议将模型输出先解析为中间表示（如三元组或图），再进行下游业务逻辑处理。
### 局限与展望- 雷达图仍是盲区：目前没有任何模型能很好地处理雷达图，这可能需要引入专门的几何感知模块。
- 手绘鲁棒性不足：尽管覆盖了手绘场景，但整体得分依然很低。未来需要更多针对非结构化视觉噪声的增强数据。
ChartArena 不仅是一个基准，它提供了一套 可复用的评估基础设施 。对于正在构建文档智能 Agent 的团队来说，这套“格式无关”的评测思路值得直接借鉴到代码解析、公式提取等其他异构输出任务中。
