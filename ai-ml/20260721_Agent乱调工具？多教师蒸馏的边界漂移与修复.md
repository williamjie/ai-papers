# ⭐⭐⭐⭐ Agent 乱调工具？多教师蒸馏的边界漂移与修复

**日期**: 2026-07-21

---

论文 : Diagnosing and Calibrating Tool-Call Boundary Drift in Multi-Teacher On-Policy Distillation链接 : https://arxiv.org/abs/2607.07050做 Agent 开发的工程师都遇到过这种鬼畜现象：模型明明可以直接回答，却非要调个 API；或者陷入无限循环调用工具的死胡同。这篇论文揭示了一个反直觉的事实： 多教师在线策略蒸馏（Multi-Teacher On-Policy Distillation, MOPD）虽然能提升工具调用准确率，但会不可控地扭曲模型的“行为边界”，导致过度调用。
### 为什么常规蒸馏会“翻车”？
在 Agent 训练中，我们常采用“双师制”：一个老师教怎么调工具（Tool-Call Teacher），另一个教怎么直接回答（Response Teacher）。直觉上，学生模型应该兼收并蓄。
但论文发现， 聚合损失（Aggregate Loss）具有欺骗性 。即使整体训练日志看起来平衡，模型在“该直接回答”的场景下，调用工具的倾向依然显著上升。
⚠️ 核心洞察：行为杠杆失衡（Behavior Leverage Imbalance）
问题不在于总误差大小，而在于 信号落点 。工具调用的入口 Token（如 <tool call> ）具有极高的“行为杠杆”，改变它们就能重定向整个生成轨迹；而自然语言回答的信号分散在大量内容 Token 上。多教师蒸馏中，极少量的局部高分歧信号（High-Leverage Signals）就能压倒全局，把决策边界向“调工具”一侧强行弯曲。
### Soft Clamp：精准的手术刀为了修复这种漂移，作者对比了硬截断、全局重加权等方法，最终提出 Soft Clamp 。
它的核心直觉是： 只压缩极端异常，保留学习信号。
具体实现非常轻量：
- 计算当前 Batch 中 Token 级 Jensen-Shannon 散度（JSD）的均值。
- 设定一个动态阈值 CC。
- 对于低于阈值的普通 Token，损失不变；对于高于阈值的极端 Token，将其梯度缩放至 C/diC/d_i​。
这与“硬截断”不同，它不会直接丢弃困难样本的梯度；与“全局重加权”不同，它只针对局部极端值，不干扰正常分布。
### 实验数据：效果立竿见影在基于 APIGen-MT 构建的决策集上，使用 Qwen3.5-9B 模型进行对比（Table 3 & Table 4）：

在多轮对话测试中（BFCL Multi-turn），Soft Clamp 将平均每轮调用次数从 Vanilla GKD 的 1.515 降至 1.289 ，并将 Loop@3（3步内循环）的概率从 15.1% 降至 10.3% 。
更重要的是，Soft Clamp 在三个随机种子下的标准差显著更低，说明其训练稳定性优于全局重加权方法。
### 工程启示- 监控行为边界，而非仅看 Loss：在 Agent 微调中，必须单独监控“应回答却调工具”的比例（Response-side Tool-Call Probability）。聚合 Loss 下降不代表行为对齐。
- 警惕入口 Token 的杠杆效应：结构化标记（如 <tool call>）对模型行为的控制力远超普通文本。在设计蒸馏或 RLHF 策略时，需考虑这些高杠杆位置的特殊性。
- 轻量级校准优于复杂重构：Soft Clamp 不需要额外的验证集调参，也不改变教师路由逻辑，仅通过修改 Token 级损失计算即可生效，非常适合工程落地。
### 局限与展望论文指出，Soft Clamp 是以牺牲部分工具召回率（从 91.5% 降至 86.5%）为代价换取稳定性的。此外，该方法目前在 Qwen3.5-4B/9B 上验证有效，但在更复杂的异构教师或多技能场景下的泛化性仍需探索。
对于追求极致稳定性的生产环境 Agent，这是一种低成本、高回报的“防呆”机制。
