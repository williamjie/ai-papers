论文 : DeepVoyager-VL: Incentivizing Vision-in-the-Loop Search for Long-Horizon Multimodal Agents链接 : https://arxiv.org/abs/2608.01827现在的多模态 Agent 大多把“看图”当成一次性动作：要么在开头识别一下实体，要么在最后看一眼答案。
但这不符合真实世界的搜索逻辑。真正的长程推理中，中间搜到的一张图片往往是解开下一个谜题的关键钥匙。
DeepVoyager-VL 这篇论文的核心价值，就在于它强制 Agent 学会这种“视觉在环”（Vision-in-the-Loop）的搜索范式。对于正在构建多模态搜索产品的工程师来说，这是一套极具参考价值的工程与数据设计思路。
### 现有方案的痛点：视觉只是装饰品大多数现有的多模态搜索方法，本质上还是文本驱动的。
它们通常采用“实体替换”或“答案拼接”的策略：先构建好文本推理链，再把图片硬塞进去。
这导致了一个严重问题： 中间获得的视觉证据，极少能驱动后续的检索动作。 Agent 并不认为图片是必要的线索，因此缺乏主动获取和解析图片的动力。此外，长程交互中盲目加载所有候选图片会撑爆上下文窗口，而只保留文本摘要又会丢失关键细节。
### 核心 Insight：结构先于语言DeepVoyager-VL 的设计直觉非常清晰： 要训练 Agent 用视觉推理，数据里的视觉依赖必须是“结构性”的，而非“装饰性”的。
为此，作者提出了 EventVoyage-VL 数据合成管线。它不从文本出发，而是先构建一个包含时间、空间和参与者关联的多模态事件图。
关键设计 ：通过子图提取和组合，强制生成具有中间视觉依赖的问题。这意味着，如果不看某张特定的图片，Agent 就无法确定下一步该搜什么。
这种“结构先于语言”（Structure-before-language）的合成方式，确保了视觉证据在推理链中是 反事实必要 的——去掉这张图，答案就不唯一或无法得出。
### Agent 架构：按需加载，拒绝堆砌在 Agent 框架设计上，DeepVoyager-VL 引入了一个非常实用的机制： 分离“发现”与“观察” 。
搜索工具（如 Image Search）只返回轻量级的 URL 和标题引用，不占用大量 Token。只有当 Agent 显式调用 FETCH IMAGE 或 CROP IMAGE 时，视觉内容才会进入策略上下文。
这种设计解决了长程搜索中的两个矛盾：
- 证据管理：避免无关图片污染上下文。
- 主动感知：迫使 Agent 思考“这张图是否值得加载”，从而提升推理质量。
配合一个辅助的 VLM 对非视觉工具的输出进行目标导向摘要，整个系统能在保持长程记忆的同时，控制成本。
### 关键结果：SFT 胜过 RL？
论文在 10 个多模态搜索基准上进行了测试，结果令人印象深刻。

几个值得注意的数据点：
- 纯 SFT 的威力：没有使用强化学习（RL），仅通过监督微调（SFT），30B 模型在 VisBrowse-Bench 上比基线提升了 +30.7%。
- 数据增量价值：消融实验显示，加入 7K 条合成的“视觉在环”轨迹后，8B 模型平均分进一步提升 5.4%，30B 模型提升 6.5%。这证明了高质量合成数据的稀缺性和有效性。
- 长程优势：在需要多步视觉推理的基准（如 BrowseComp-VL, VisBrowse）上，增益远大于简单事实问答。
### 工程启示与局限对于工程师而言，这篇论文提供了两个直接可用的指导：
- 数据合成策略：不要盲目用 LLM 生成“图文混合”对话。尝试构建事件图或知识图谱，强制引入中间视觉依赖，这样训练出的 Agent 才具备真正的多模态推理能力。
- 工具接口设计：将“搜索列表”与“加载内容”解耦。这不仅节省 Token，更是一种隐式的思维链引导，让模型学会“先筛选，后深入”。
当然，方法也有边界。目前依赖的是合成数据，在完全未知的开放世界场景中，事件图的覆盖度可能有限。此外，虽然 SFT 效果显著，但在极端复杂的动态环境中，缺乏 RL 的反馈机制可能会限制 Agent 的自我纠错能力。
总体而言，DeepVoyager-VL 证明了： 让视觉成为推理的驱动力，而非输入的输出，是构建下一代多模态搜索 Agent 的关键一步。
