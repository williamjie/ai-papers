论文 : MemHarness: Memory Is Reconstructed, Not Replayed链接 : https://arxiv.org/abs/2607.28272现在的 LLM Agent 都在搞外部记忆，但大多数做法很粗暴：检索到过往经验，直接塞进 Context。
这种做法有个致命伤： “语义相关”不等于“当前可用” 。
过去成功的策略，在当下的环境状态里可能是毒药。这篇论文提出了一个反直觉的观点：人类回忆不是录像回放，而是基于当下情境的 重构（Reconstruction） 。MemHarness 框架让 Agent 学会在动作生成前，先对检索到的记忆进行批判和改写。
### 痛点：直接回放就是噪声现有方案（如 Mem0, SimpleMem）通常把检索到的经验当作静态 Prompt 片段注入。
这忽略了 状态偏差（State Mismatch） 。比如过去“开门”的经验是推门，但当前环境门是拉的。直接回放会导致负迁移（Negative Transfer），甚至让 Agent 表现比不用记忆还差。
### 核心 Insight：从 Replay 到 ReconstructMemHarness 的核心设计是将决策过程拆解为五步：观察、检索、 批判（Critique） 、 重构（Reconstruction） 、行动。
关键在于中间那两步：
- 批判：对比当前状态 hth_t​ 和记忆来源状态 oisrco^{src}_isrc​，判断是否适用。
- 重构：如果适用，改写为当前情境下的指导；如果不适用，直接丢弃或标记为空 <EMPTY>。
⚠️ 反直觉发现 ：这个重构能力不需要人工标注数据。通过 GRPO（Group Relative Policy Optimization）端到端训练，Agent 为了拿到任务奖励，会隐式地学会“哪些记忆该信，哪些该改”。
### 实验结果：重构才是硬道理论文在 ALFWorld 和 WebShop 两个长程交互基准上做了详细对比。数据非常有说服力：
1. 整体性能碾压MemHarness (基于 Qwen2.5-7B) 的表现不仅远超基线模型，甚至打败了闭源大模型。
方法 ALFWorld Avg. SR (%) WebShop Avg. SR (%) GPT-4o 49.2 31.8 Gemini-2.5-Pro 62.1 42.5 MemHarness (Ours) 85.2 75.62. 消融实验：重构模块的价值如果不做重构，直接回放原始记忆（Raw Memory），性能会大幅下滑。
- ALFWorld: MemHarness (85.2%) vs RL + Raw Memory (70.1%)。差距高达 15.1%。
- WebShop: MemHarness (75.6%) vs RL + Raw Memory (72.6%)。
这证明： 在复杂环境中，未经过滤的记忆就是噪声。
3. 内在推理能力的提升最有趣的是，即使测试时完全禁用记忆（w/o memory），MemHarness 的表现（ALFWorld 83.0%）依然显著高于纯 RL 基线（76.4%）。
💡 工程启示 ：重构过程本身作为一种潜层引导（Latent Guidance），在训练阶段就提升了模型的基础推理能力。哪怕最后不用记忆，模型也变强了。
### 为什么这么设计？
传统的 RAG 或记忆增强是“检索即使用”。MemHarness 引入了一个 显式的状态对齐机制 。
它不依赖外部工具做重写，而是将重构参数化到策略网络 πθ\pi_\theta ​ 中。这样，重构逻辑能随着 RL 训练不断优化，适应环境动态变化。
- 宏观过滤：实验显示，当提供错误的来源状态时，Agent 的拒绝率显著上升（ALFWorld 从 8.7% 升至 13.3%），证明它真的在比对状态。
- 微观适应：在 WebShop 中，面对网页内容的细微变化，Agent 能动态调整记忆的使用策略。
### 局限与展望目前方法依赖于 GRPO 进行端到端训练，计算成本较高。且重构过程是隐式的文本生成，可解释性仍有提升空间。
未来方向包括扩展到更大规模模型以及更开放的端到端环境。但对于工程实践者来说，**“记忆需要重构而非回放”**这一理念，足以重新审视现有的 Agent 架构设计。
