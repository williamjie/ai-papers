# 图像即词汇：用交错指令重构多图生成

**日期**: 2026-05-13

---

论文 : Images in Sentences: Scaling Interleaved Instructions for Unified Visual Generation链接 : https://arxiv.org/abs/2605.12305多模态生成的下一个瓶颈不在“画得像”，而在“指得准”。当提示词从单图扩展为多图交错指令（Interleaved Instructions）时，现有模型往往因为无法精准绑定对象而崩溃。字节跳动的 Inset 提出了一种看似简单却极具颠覆性的思路： 把图像当作词汇直接嵌入句子中 。
### 痛点：间接引用的陷阱目前主流的图文生成模型（如 Flux Kontext, DreamOmni2）大多采用“间接引用”范式。输入通常是 [Image1, Image2, ...] 加上文本 "Image 1中的狗拿着Image 2里的球" 。
这种设计的核心缺陷在于 长程依赖 。模型需要跨越长长的文本序列，去匹配最开头的视觉特征。随着参考图数量增加，这种“查找-匹配”机制极易失效，导致属性错位或忽略特定图像。此外，现有数据集多为短序列或简单组合，缺乏处理复杂逻辑推理的能力。
### 核心洞察：视觉即语言Inset 的核心 Insight 在于重新定义输入的 Token 结构。它不再将图像作为外部条件，而是通过语义 ViT（Visual Transformer）提取特征，直接插入到文本的语义槽位中。
例如，指令不再是分离的，而是变成：
"A [Image1] robot holds a [Image2] flower vase..."
这种 Native Interleaved Formulation（原生交错格式） 利用了 Transformer 的局部上下文感知能力。当图像 Token 紧邻其描述的名词时，模型无需进行复杂的远距离注意力计算，即可实现精确的对象绑定（Object Binding）。
工程细节值得注意：
- 丢弃 VAE Latents：Inset 仅使用语义 ViT 嵌入，抛弃了像素级的 VAE 潜在特征。实验表明，VAE 特征容易导致模型“硬复制”（Image-pasting），即生硬地粘贴像素而忽略编辑指令。ViT 特征迫使模型进行更深层次的语义推理。
- 两阶段引导策略：为平衡图文权重，Inference 时先通过 s1=4.0 增强文本影响力，再应用全局引导 s2=1.5，防止视觉信号主导生成过程。
### 数据引擎：从静态到动态的规模化仅有架构创新不够，高质量数据才是关键。Inset 团队构建了一个可扩展的数据引擎，合成了 1500万 高质量交错样本：
- 静态图像（10M样本）：利用 VLM 生成全局描述，SAM 提取实例掩码，DAM 生成细粒度对象描述，最后由 LLM 将这些视觉实例编织成自然的交错文本序列。
- 视频数据（5M样本）：为解决模型只会“复制”不会“变换”的问题，引入视频数据。通过 VLM 匹配不同帧中的同一对象，构建“源帧图像 Token + 目标帧文本描述”的训练对，教会模型根据指令改变对象姿态、光照等状态。
### 性能对比：复杂度越高优势越大在 InterleaveBench 基准测试中，Inset（7B+7B 参数）的表现令人瞩目。它不仅超越了所有开源模型，甚至在多项指标上比肩 GPT-4o 和 Seedream 4.0 等闭源巨头。
模型 参数规模 五图一致性 (Image Consistency) 五图文本一致性 (Text Consistency) GPT-4o - 0.89 0.81 Seedream 4.0 - 0.91 0.85 BAGEL 7B+7B 0.57 0.45 Inset (Ours) 7B+7B 0.94 0.78注：数据来源于论文 Table 1。
最关键的发现是 可扩展性 。随着输入图像数量从 2 个增加到 5 个，Inset 在图像一致性上领先开源基线 BAGEL 的差距从 +0.10 扩大到 +0.29 。这直接验证了“交错嵌入”架构在处理复杂多目标场景时的优越性。
### 工程启示与局限对开发者的意义：
- 提示工程范式转移：未来的多模态 Agent 不应再依赖“先传图后加索引”的笨拙方式，而应尝试构建结构化的交错指令序列。
- 编辑能力的自然涌现：由于训练数据中包含了视频变换样本，Inset 在无需额外微调的情况下，自然具备了高精度的多模态图像编辑能力，能忠实保留参考对象的视觉特征并进行状态修改。
局限：
尽管图像一致性极佳，但在文本一致性上（0.78），Inset 仍略逊于 Seedream 4.0（0.85）。作者指出，这主要受限于底层文本到图像生成模型的能力边界。
Inset 证明了将视觉视为“密集语言 Token”是一条可行且高效的路径。对于追求复杂场景可控生成的工程团队来说，这种原生交错架构值得深入研究。
