### 为什么固定 Block Size 是错的？
目前的 SOTA 方案（如 DFlash）通常采用固定的推理块大小（Block Size）。这种设计的逻辑很简单：训练时用什么大小，推理时就沿用。
但作者指出，这是一个根本性的次优假设。不同输入的语义约束和可预测性差异巨大：
- 强约束场景（如代码补全）：模型对后续 Token 非常确定，大 Block Size 能带来极高的并行效率。
- 弱约束场景（如开放式对话）：不确定性高，强行使用大 Block 会导致 Draft 错误累积，接受率暴跌。
⚠️ 反直觉发现 ：最优的 Block Size 并不是随机分布的。论文发现，对于绝大多数样本，其最优 Block Size 都集中在训练块大小附近的极小邻域内（例如 B±3B \pm 3 3 ）。这意味着我们不需要复杂的在线搜索，只需在一个离散的小集合中做分类预测即可。
### 方法拆解：BlockPilot 的核心直觉BlockPilot 的核心思路是将“选择 Block Size”转化为一个轻量级的策略学习问题。
- 特征提取：在 Prefilling 阶段结束后，提取目标模型最后一个 Token 的预测概率分布。
Why? 这个分布通过自回归注意力机制聚合了全局上下文信息，既反映了局部不确定性，也隐含了未来生成的稳定性信号。
- 轻量预测器：使用一个极小的 MLP（多层感知机）作为策略网络。
输入是上述概率分布，输出是候选 Block Size 集合 {B−k,…,B+k}\{B-k, \dots, B+k\}k,…,B+k} 的 Logits。
- 离线训练：通过离线枚举每个样本在不同 Block Size 下的接受长度（Acceptance Length），构建监督数据集进行训练。
这种设计极其巧妙： 预测只在 Prefilling 后执行一次，且完全独立于 Draft 和 Target 模型 。这意味着它可以即插即用，无需修改现有的推理框架。

- 开销极低：预测器参数量仅 0.32B，推理延迟增加约 7.34ms，相比主模型百毫秒级的延迟几乎可以忽略不计。
### 工程启示- 策略优于架构：在投机解码中，解码策略（Decoding Policy）本身是一个可学习的组件。不要迷信固定的超参数，自适应策略能挖掘出更多的并行潜力。
- 极简主义胜利：BlockPilot 证明了不需要复杂的在线优化或大型辅助模型，仅利用 Prefilling 阶段的静态特征就能实现显著的收益。这对于资源受限的边缘部署极具吸引力。
- 即插即用：由于不修改主模型和 Draft 模型，现有基于 DFlash 等扩散投机解码的系统可以直接集成此模块，获得免费的性能提升。
### 局限与展望虽然效果显著，但该方法依赖于离线枚举构建训练数据，这在超大模型或极长上下文场景下可能需要一定的预处理成本。此外，目前主要针对扩散型 Draft 模型，其在传统自回归 Draft（如 Medusa）上的泛化能力仍有待验证。
总体而言，BlockPilot 是一个典型的“小改动大收益”的工程优化案例，值得在追求极致推理延迟的场景中深入评估。
