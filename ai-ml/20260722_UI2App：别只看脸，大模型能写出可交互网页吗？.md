论文 : UI2App: Benchmarking Visual Interaction Inference in Executable Web Application Generation链接 : https://arxiv.org/abs/2607.06306现在的“截图转代码”工具大多在搞自嗨：生成的页面长得像那么回事，点一下按钮却毫无反应。
这篇 UI2App 论文直接撕开了这个遮羞布。它不关心你的 UI 还原度有多高，只问一个核心问题： 你能从静态截图中推断出正确的交互逻辑吗？
## 痛点：视觉保真度 ≠ 功能可用性现有的基准测试（如 WebGen-Bench）通常提供详细的文本指令或演示视频。这本质上是“规格遵循”（Specification Following），模型只是在执行已知任务。
但在真实开发中，设计师给的是截图，没有行为说明书。
UI2App 提出了 交互推断 （Interaction Inference）的概念：仅凭静态截图，恢复应用程序的行为。
作者构建了包含 327 张截图、45 个多路由 Web 应用的数据集。这些截图涵盖了从内容展示到后台管理的各种场景，且刻意去除了文本描述。模型必须自己“猜”出哪些元素是可点击的，状态如何流转。
## 方法拆解：为什么 IIS 才是硬指标？
论文设计了四个维度的评估协议，其中最具洞察力的是 IIS（Interaction Inference Score） 。
传统评测只看 DOM 结构和像素对齐（VFS）。UI2App 认为，一个“冻结的立面”（Frozen Façade）毫无价值。
IIS 的核心 Insight 在于分类与权重：
- 交互分类学：将交互分为 7 类，包括开关（Toggle）、展开/折叠、列表操作、数据 CRUD、表单验证、通知和跨路由状态（Cross-route state）。
- 作用域复杂度：
S1：UI 状态（如点击变色）
- S2：数据状态（如购物车计数更新）
- S3：跨路由持久化（如登录后跳转，状态保留）
评分公式不仅看是否实现，还根据状态管理的复杂度加权。S3 的权重最高，因为它代表了真正的应用逻辑能力。
## 关键结果：视觉冠军是交互倒数第一？
实验覆盖了 Claude Sonnet 4.6、Gemini 3.1 Pro Preview 等六大前沿模型。数据揭示了令人震惊的能力错配。
⚠️ 反直觉发现 ：视觉保真度（VFS）最高的模型，在交互推断（IIS）上排名垫底。

- Gemini 的困境：它在 VFS 上领先，但在 C04（CRUD）、C06（通知）和 C07（跨路由状态）上的得分均为 0.0。这意味着它生成了完美的静态页面，但所有交互都是无效的“空操作”。

- 开源模型的逆袭：Kimi K2.5 和 Qwen3.5 在 IIS 上分别以 20.7 和 13.2 超越了 Gemini 和 GPT-5.4。这打破了“闭源模型在所有维度均占优”的固有印象，至少在交互推断这一新赛道上，开源模型展现了更强的逻辑推理潜力。
## 工程启示：如何用好这些模型？
- 不要盲目信任视觉还原：如果你的业务依赖复杂的表单或状态流转，仅靠截图生成代码是不可靠的。Gemini 的高 VFS 分数具有极大的误导性。
- Prompt 必须包含行为约束：既然“纯图像推断”能力上限只有 39.3（Claude），那么在实际工程中，必须通过自然语言补充交互逻辑描述。UI2App 证明了“无文本指导”是当前的技术天花板。
- 关注 S3 级能力的缺失：对于需要跨页面状态同步的应用（如电商购物车、后台管理系统），当前模型几乎无法自动生成可靠代码。这部分仍需人工介入或采用更传统的开发模式。
## 局限与展望UI2App 目前主要基于 React + TypeScript 栈，且依赖人工标注进行交互验证（IIS）。虽然 Krippendorff α 系数达到了 0.72-0.84，但大规模自动化评估仍是挑战。
此外，Qwen2.5-VL 的缩放实验显示，模型能力在 32B 到 72B 之间存在“相变”（Phase Transition）。低于 32B 的模型几乎无法构建可运行的应用，而 72B 虽然 EXEC@3 提升至 62.2%，仍有近四成失败率。
结论很明确： 从截图到可交互应用，中间隔着巨大的“语义鸿沟”。视觉重建已接近成熟，但交互推断仍是下一个需要攻克的堡垒。对于工程师而言，现阶段最务实的策略是： 用 VLM 生成静态骨架，再用 Agent 或人工补全交互逻辑。
