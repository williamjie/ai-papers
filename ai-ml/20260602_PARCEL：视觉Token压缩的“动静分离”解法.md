论文 : PARCEL: Pool-Anchored Resampling with Conditioned Elastic Queries for Efficient Vision-Language Understanding链接 : https://arxiv.org/abs/2605.30126在部署大型视觉语言模型（LVLMs）时，我们常面临一个尴尬的权衡：为了速度压缩视觉 Token 会丢失细节，保留细节则算力成本高昂。现有的弹性推理方案往往顾此失彼，而 PARCEL 提出了一种“动静分离”的思路，试图在两者之间找到更优解。
问题与动机：现有方案的“左右互搏”
目前的弹性视觉 Token 压缩主要依赖两种范式，但它们都存在明显的频谱瓶颈。
第一种是刚性空间下采样（如 M3），通过嵌套平均池化减少 Token 数量。这本质上是一个低通滤波器，虽然保留了宏观布局，但引入了频谱混叠（Spectral Aliasing）。结果是高频细节模糊，导致图表推理或细粒度问答性能大幅下降。
第二种是非局部查询重采样（如 MQT），用可学习查询替代网格 Token。这种方法牺牲了显式的空间对齐关系，导致模型在密集定位任务中“找不到北”。
核心痛点 ：纯空间压缩丢失高频细节，纯查询压缩破坏空间结构。我们需要一种能同时保留两者优势的方法。
方法拆解：PARCEL 的“分工协作”直觉PARCEL 的核心 Insight 是动态划分特征提取的劳动（Division of Labor）。它不再让单一机制承担所有信息编码任务，而是引入了两个互补的角色：
- 空间锚点（Spatial Anchors）：通过平均池化生成低频率的几何布局 Token。它们负责稳住大局，提供明确的 2D 空间结构。
- 语义探索者（Semantic Explorers）：这是一组可学习的查询 Token，但它们不是盲目搜索，而是通过“池条件查询重采样”（Pool-Conditioned Query Resampling, PCQR）机制，先关注空间锚点，再交叉注意力到原始高分辨率特征。
这种设计的精妙之处在于 条件依赖 。查询 Token 在提取细节前，已经知道了哪些低频信息已被锚点覆盖。因此，它们被强制去捕捉那些池化操作丢弃的、互补的高频视觉信号。这就像是一个团队，有人负责画草图（锚点），有人负责填色和修饰细节（查询），且后者知道前者已经画了什么，避免重复劳动。
此外，PARCEL 采用了预算感知的分段路由策略：
- 低预算（16-63 Tokens）：使用 4×44 \times 44 网格作为锚点，剩余 Token 分配给查询。
- 中高预算（64-256 Tokens）：升级为 8×88 \times 88 网格锚点，提供 richer 的空间基础。
关键结果：帕累托前沿的全面超越在 PaliGemma-2 (3B) backbone 上，PARCEL 在 27 个基准测试中展现了显著的效率优势。以下是与基线 M3 和 MQT 的对比数据（保留率相对于未压缩模型）：

特别是在对分辨率敏感的任务（如 ChartQA）中，PARCEL 在 64 Token 预算下比 M3 高出 +4.7 分，证明了其频谱解耦的有效性。消融实验进一步证实，如果没有 PCQR 的条件机制，仅靠增加参数量无法弥补基线方法的结构性缺陷。
工程启示：如何落地？
- 动态适配部署：PARCEL 支持“一次训练，随处部署”。在端侧设备（如手机）上，你可以强制使用 16 Token 预算以换取极致速度；在云端服务器，则切换到 256 Token 以获得最佳精度。无需重新微调模型。
- KV Cache 优化：视觉 Token 数量的减少直接降低了 Transformer 解码阶段的 KV Cache 内存占用。对于长视频或高分辨率图像输入，这种节省是线性的，能显著降低 OOM 风险。
- 架构借鉴：如果你的自定义连接器（Connector）面临类似瓶颈，可以尝试引入“锚点+查询”的双路结构，并让查询路径显式地依赖于空间先验，而非独立学习。
局限与展望尽管 PARCEL 提升了帕累托效率，但其核心仍依赖于 PaliGemma-2 等特定 Backbone 的实验验证。在不同架构（如 Qwen-VL 或 LLaVA-OneVision）上的迁移成本尚需评估。此外，PCQR 模块引入了额外的自注意力计算，虽然论文声称开销可忽略，但在极端延迟敏感场景下仍需实测验证。
总体而言，PARCEL 为视觉 Token 压缩提供了一条清晰的路径：不要试图用一种机制解决所有问题，而是通过结构化的分工，让低频和高频信息各司其职。
