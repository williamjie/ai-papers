# ⭐⭐⭐½ 别只看成功率：安全 Agent 的成本效率真相

**日期**: 2026-07-21

---

论文 : Beyond Success Rate: Cost-Aware Evaluation of Offensive and Defensive Security Agents链接 : https://arxiv.org/abs/2607.15263大家平时看安全大模型评测，是不是总觉得“成功率”就是王道？能解出 CTF 题目、能查出漏洞，好像就赢了。但现实中的 SOC（Security Operations Center）分析师可不会给你无限的推理预算。每一步日志查询、每次外部情报 enrichment，都在烧钱。这篇论文的核心观点很直接： 脱离成本谈能力，都是耍流氓。
作者没有只盯着“最高成功率”，而是引入了 成本感知评估（Cost-Aware Evaluation） 。他们把进攻型任务（Cybench CTF）和防御型任务（Splunk BOTS v1 调查）放在同一个成本轴上对比。结果发现，红队（Red Team）和蓝队（Blue Team）的 Scaling Law 完全不一样。这不仅仅是学术好奇，更是工程落地的生死线。
### 为什么现有评测不够用？
目前的评测往往假设预算无限。比如 Claude Mythos Preview 的评测，动辄百万 Token 预算。但在生产环境中，Agent 需要决定：
- 这个 Splunk 查询值得发吗？
- 要不要调用 VirusTotal API？
- 什么时候该停止推理，给出结论？
如果只测峰值能力，你选出的模型可能在实战中因为“太烧钱”而被淘汰。作者提出用 固定预算下的成功率 作为核心指标，并拆解了 推理成本（Inference Spend） 和 工具成本（Tool Spend） 。
### 核心 Insight：红蓝队的 Scaling 规律截然不同论文最反直觉的发现是： 进攻靠算力堆，防御靠纪律控。
#### 1. 进攻型任务（Cybench）：钱能买到更多解在 CTF 挑战中，额外的测试时计算（Test-time Compute）能显著提升成功率。
- DeepSeek v4 Flash 在 0.80预算下成功率为76.10.80 预算下成功率为 76.1%，当预算提升到 2.10 时，成功率升至 86.4%。
- Claude Opus 4.8 更是如此，预算放宽后，其表现有显著提升（+18.8 个百分点）。
这意味着对于渗透测试、漏洞挖掘等任务，让模型多思考、多尝试执行命令，是有明确回报的。开源/开放权重模型通过增加推理步数，可以逼近甚至超越部分专有系统，且保持成本竞争力。
#### 2. 防御型任务（BOTS v1）：钱买不到更多分在 SOC 调查中，情况完全反转。 更多的预算并不等于更好的调查。
- DeepSeek v4 Flash 将预算从 2.10翻倍到2.10 翻倍到 4.20，得分仅从 73.0% 微增至 73.9%，但工具调用次数从 4,450 次暴涨到 4,938 次。
- Claude Opus 4.8 以最高的得分（93.9%）和最低的单千分成本（$2.98/1k pts）胜出，且仅使用了 603 次非提交工具调用。
⚠️ 关键结论 ：防御性成功不依赖于原始推理预算，而取决于 工具使用的纪律性（Disciplined Tool Use） 、遥测导航能力和选择性情报增强。盲目增加预算只会让 Agent 陷入无效查询的泥潭。

### 工程启示：如何选型与优化？
- 别只看 Leaderboard：如果用于 SOC 自动化调查，选模型要看“每千分成本”和“工具调用效率”，而不是绝对得分。Claude Opus 4.8 在此场景下性价比极高。
- 设置硬性预算上限：在 Agent 框架中（如 Inspect AI），务必设置 cost cap。对于防御任务，过高的预算会导致模型“过度探索”，反而降低准确率。
- 警惕数据污染：BOTS v1 是公开数据集，论文指出无工具探针下，部分模型（如 GPT-5.6 Sol）仍能答对 50% 以上的题目。这意味着绝对分数不可信，必须通过去污染测试（Decontamination Controls）来评估真实推理能力。
- 区分任务类型配置：
红队 Agent：允许较高的 Token 预算和重试次数，利用 Test-time Compute 提升突破率。
- 蓝队 Agent：限制昂贵的外部 API 调用（如 VirusTotal、WHOIS），强化 Prompt 中的“选择性查询”指令，避免无效搜索。
### 局限与展望论文承认 BOTS v1 数据较旧，且存在污染风险。未来的评估需要更干净的私有数据集，并扩展到 BOTS v2/v3 等更复杂的云原生场景。此外，当前的成本模型主要涵盖 Token 和外部 API，未包含基础设施运维成本，这也是实际落地中需要考虑的隐藏开销。
总之，这篇论文提醒我们： 在安全领域，效率即安全。 一个能花十块钱解决一个问题但耗时两小时的 Agent，和一个花一块钱十分钟解决的 Agent，在生产环境中的价值天差地别。工程师们在集成 AI Agent 时，请把“成本曲线”和“成功率曲线”一起画出来看。
