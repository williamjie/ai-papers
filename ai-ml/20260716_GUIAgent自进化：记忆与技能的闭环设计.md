论文 : KnowAct-GUIClaw: Know Deeply, Act Perfectly, Personal GUI Assistant with Self-Evolving Memory and Skill链接 : https://arxiv.org/abs/2607.12625GUI Agent 领域一直有个尴尬现状：模型越强，跑起来越慢，且每次任务都像“失忆”重来。这篇来自哈工大的论文提出了一个工程上极其实用的架构——KnowAct-GUIClaw，核心不在于堆砌更大的基座模型，而在于构建了一套**“记忆-技能”自进化闭环**。它让 Agent 不仅能执行操作，还能从历史轨迹中提炼出可复用的“肌肉记忆”，这在本地化部署和个人助手场景中极具落地价值。
### 痛点：为什么现有方案不够用？
现有的 GUI Agent（如 AppAgent, Mobile-Agent）通常采用单体架构或简单的 ReAct 循环。这种设计在长程任务中暴露出三个致命缺陷：
- 状态不可见与碎片化：GUI 操作本质上是部分可观测马尔可夫决策过程（POMDP）。截图、无障碍树、前台 App ID 只是设备状态的片段。单体 Agent 难以在长链路中保持上下文一致性，容易导致跨应用数据丢失或幻觉。
- 缺乏经验复用：每次任务结束，成功的导航路径和失败的避坑指南通常被丢弃。下次遇到类似场景，Agent 必须重新“探索”，导致效率低下且容易重复犯错。
- 执行效率低：所有子任务都强制通过视觉交互完成，忽略了 Deep Link、Intent 等快捷方式，造成大量 Token 浪费在无关的 UI 渲染上。
### 核心 Insight：Know-Route-Act-Reflect 架构论文的核心贡献是提出了一个四层循环架构，将“认知”与“执行”解耦，并引入自进化机制：
- Know（感知与上下文）：主机 Agent（Host）负责全局上下文管理。在执行前，它主动检索相关的历史记忆和技能，但仅作为建议而非强制指令。
- Route（路由与分解）：这是关键设计。Host 将复杂任务分解为子任务序列，并通过**黑板机制（Blackboard）**在子任务间传递结构化数据。如果某个子任务不需要视觉交互（如查询天气），Host 直接调用工具解决，避免启动沉重的 GUI 子 Agent。
- Act（混合执行）：GUI 子 Agent 拥有混合动作空间 A=Agui∪Askill∪Ashortcut∪AaskA = A_{gui} \cup A_{skill} \cup A_{shortcut} \cup A_{ask}Agui​∪Askill​∪Ashortcut​∪Aask​。它不仅支持点击、滑动等原始操作，还能调用经过验证的技能（Skills）和快捷方式（Shortcuts）。
技能（Skills）：从历史轨迹中蒸馏出的参数化动作序列。例如，“打开设置 -> 搜索 Wi-Fi”被封装为一个技能，执行前会进行状态校验，确保环境匹配。
- 快捷方式（Shortcuts）：如 Android Deep Link，仅在验证目标页面可用时调用，大幅缩短导航路径。
- Reflect（反思与进化）：任务结束后，系统对轨迹进行蒸馏。成功的模式被提炼为新技能或更新现有技能；失败的路径转化为经验记忆（Experience Memory），用于指导未来的路由决策。
⚠️ 反直觉发现 ：论文强调，记忆和技能是 可跨模型迁移 的。使用 Kimi-K2.6 生成的技能和记忆，可以直接赋能给 Qwen3.5-35B，使其性能提升 16.2%。这意味着“经验”本身成为了独立的资产，不再绑定于特定基座模型。
### 关键结果：效率与准确率的双赢在 MobileWorld GUI-Only 基准测试（117 个任务）中，KnowAct-GUIClaw 展现了显著优势：

### 工程启示- 解耦是王道：将长程规划（Host）与短期执行（GUI Sub-agent）分离，并通过结构化接口（黑板）通信，能有效缓解上下文窗口压力并提高鲁棒性。
- 经验即资产：不要只关注模型微调。构建一个可检索、可验证的技能库和经验记忆系统，能让中小参数模型获得接近大模型的长期任务能力。
- 混合动作空间：在 GUI 操作中强制引入 Deep Link/Intent 等快捷方式，并进行状态校验，是提升执行效率的关键工程手段。
### 局限与展望尽管效果显著，该架构仍依赖复杂的后处理流程（轨迹蒸馏、技能提取），这在实时性要求极高的场景中可能成为瓶颈。此外，跨平台迁移（如 Android 到 iOS）的技能通用性仍需更多验证。未来，如何自动化地优化技能库的检索效率，以及如何在边缘设备上轻量化部署这一闭环，将是重要的研究方向。
