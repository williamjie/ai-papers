论文 : ACC: Compiling Agent Trajectories for Long-Context Training链接 : https://arxiv.org/abs/2605.21850做 Agent 开发的工程师一定有个痛点：Agent 跑出来的多轮轨迹（Trajectory）数据量巨大，但直接拿来做监督微调（Supervised Fine-Tuning, SFT）效果往往不尽如人意。这篇来自中科大和上海 AI 实验室的论文《ACC: Compiling Agent Trajectories for Long-Context Training》给出了一个极其巧妙且低成本的解法： 别把 Agent 轨迹当对话练，把它当成“长上下文 QA”来练。
### 为什么现有的 Agent SFT 是“盲人摸象”？
通常我们训练 Agent 时，为了模拟推理过程，会 Mask 掉工具返回的观察结果（Observations），只让模型预测下一步动作。论文敏锐地指出，这造成了一个 监督盲区（Supervision Blind Spot） 。
想象一下：Agent 经过 5 轮搜索才找到答案。在标准 SFT 中，模型在第 1 轮看到的搜索结果，其梯度只能通过后续的动作间接传播。这种长链条的梯度衰减极快，导致模型根本学不会如何整合分散在多轮中的证据，它只学会了“根据当前上下文选下一个工具”，而不是“从全局证据推导最终答案”。
### ACC 的核心直觉：编译而非模拟ACC（Agent Context Compilation）的设计非常极简，核心 Insight 在于 重构监督信号的路径 。
- 打散重组：提取 Agent 轨迹中所有相关的工具响应、环境观察，拼接成一个完整的长上下文 CC。
- 引入干扰：不仅包含有用信息，还混入未访问的网页、无关代码文件作为 Distractor（干扰项），并随机打乱顺序。这强迫模型必须通过语义关联定位关键证据，而不是靠位置记忆。
- 直接监督：训练目标不再是预测中间的工具调用，而是直接基于 CC 生成推理链和最终答案。
这就好比把 Agent 的“探索过程”压缩成了最终的“解题笔记”。模型不再需要学习如何搜索，而是学习如何在海量碎片信息中建立长程依赖（Long-range Dependency）。
### 实验效果：小模型吊打大参数基线论文在 Qwen3-30B-A3B 上进行了验证，结果令人印象深刻。特别是在测试长程依赖能力的 MRCR 和 GraphWalks 基准上：
模型 MRCR (Overall) GraphWalks (Overall) Qwen3-30B-A3B (Base) 50.19 69.92 + ACC (Ours) 68.28 (+18.09) 77.51 (+7.59) Qwen3-235B-A22B (Strong Baseline) 67.51 76.63注意看这个对比：仅使用 ACC 数据微调的 30B 模型 ，在长上下文推理任务上已经追平甚至超过了参数量近 8 倍的 235B 基座模型 。更难得的是，它在 GPQA、MMLU-Pro 等通用能力基准上没有出现明显的灾难性遗忘（Negative Transfer），AIME’25 甚至提升了 +3.33 分。
消融实验进一步证实了“干扰项”的重要性：去掉 Search 和 SWE 任务中的 Distractor，MRCR 分数分别下降了 3.34 和 3.81 分。这说明， 学会在噪声中过滤无关信息，是长上下文能力的关键组成部分。
### 工程启示与落地建议这篇论文对实际工程有两个直接指导意义：
- 数据复用新范式：如果你手头有大量的 Agent 运行日志（无论是搜索、SWE 还是 SQL），不要只用来微调 Agent 框架本身。将其“编译”成长文本 QA 数据，是低成本提升模型长窗口理解能力的捷径。
- 机制层面的可解释性：论文通过注意力分布分析发现，ACC 训练后的模型出现了任务自适应的注意力重构。在 GraphWalks 任务中，模型学会了同时关注局部邻居和远距离节点；而在 MRCR 中，则强化了局部验证。这意味着 ACC 不仅仅是堆数据，它确实诱导了模型内部专家（Experts）的特化分工。
### 局限与展望当然，方法也有边界。ACC 依赖强教师模型（如 DeepSeek-V3.2-Thinking）来生成高质量的推理链，如果轨迹本身的答案错误，会导致误差传播。此外，目前仅在三种 Agent 类型上验证，对于更复杂的交互式环境，如何定义“编译后的上下文”仍需探索。
总之，如果你正在为长上下文模型的微调数据发愁，不妨试试把那些沉睡的 Agent 日志“编译”一下。
