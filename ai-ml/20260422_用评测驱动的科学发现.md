# 用评测驱动的科学发现

**日期**: 2026-04-22

---

论文 : Evaluation-driven Scaling for Scientific Discovery链接 : https://arxiv.org/abs/2604.19341LLM 做科研这件事，大家最近聊得很多了。但有个关键问题一直没被认真回答：评测反馈（evaluation feedback）这个核心机制，到底该怎么规模化？
斯坦福、北大、清华联合团队这篇论文给出了一个清晰的答案。他们发现，大多数现有方法都在卷 generation-side compute——推理 token 数、agent 轮次——却忽略了”评测驱动发现循环”本身的可扩展性。他们用 SIMPLETES 框架证明：系统性扩展评测循环，和扩展模型能力一样重要。
## 问题在哪科学发现本质上是 trial-and-error 循环：提出假设、实验验证、根据反馈修正。LLM 做科研时，这个循环的引擎就是 evaluator——一个能给出分数和反馈的 verifier/simulator/scoring function。
但现有的测试时扩展（Test-Time Scaling, TTS）方法要么只扩展生成侧计算，要么只做有限几轮探索循环。他们没回答一个核心问题：给定评测预算 N，怎么组织这些评测查询才能让发现效果最大化？
## SIMPLETES 的设计直觉SIMPLETES 的聪明之处在于，它把评测循环拆成了三个正交的缩放维度：
1. 全局宽度 C（Global Width）
这是最反直觉的设计。传统做法是单序列迭代——生成一个、评测一个、用历史反馈再生成一个，如此循环。问题在于：早期探索方向会锁定后续改进路径。论文里叫它”Matthew Effect”——一条路走通了，系统就死磕这条路，其他方向被饿死，最终困在局部最优。
SIMPLETES 的做法是并行跑 C 条独立轨迹。每条轨迹维护自己的历史，各自探索。论文在 Erdős 最小重叠问题和自相关不等式上的实验清楚展示了这一点：增加 L（单条轨迹深度）收益很快饱和，而增加 C（并行轨迹数）则持续带来提升。
2. 局部样本大小 K（Local Sample Size）
即使轨迹方向对了，LLM 单次生成仍可能产出弱候选。如果这个弱候选被 commit 到轨迹历史中，后续所有迭代都会被污染。
K 的解决思路很简单：在每个 refinement 步骤，生成 K 个候选，只把得分最高的那个加入历史。这是一个 trade-off——K 越大，每一步质量越高，但 refinement 深度 L 就越浅。论文实验显示，K 从 1 提升到中等值时收益明显，但 K 过大导致 L 不足时，收益会饱和甚至逆转。
3. 上下文压缩 Φ（Context Construction）
这是最容易被忽视但最实用的部分。轨迹历史会迅速膨胀，包含各种方案、分数、错误信息。LLM 的上下文窗口不是无限的，所以需要一个函数 Φ 把历史压缩成下一次生成的 prompt。
他们用了 RPUCG——一个基于图结构的 PUCT 扩展。每个历史节点有两个价值维度：自身得分，以及它启发过的后代节点的最高得分（带折扣）。RPUCG 在这两者间取平衡，既重用高质量经验，也给未充分探索的节点留出机会。

## 意外收获：自动训练SIMPLETES 在运行过程中会产生结构化的轨迹历史。作者把这些成功轨迹拿来做了 post-training——用每条轨迹中达到的最高得分来监督，而不是每个中间步骤的即时得分。
结果出人意料：微调后的模型不仅在训练过的问题上发现更高效，还能泛化到未见过的分布外问题。这说明评测驱动的历史能让模型学到通用的”发现行为”，不只是过拟合特定任务。
## 工程启示-别只卷推理长度。如果你的场景有可查询的 evaluator，评测循环的扩展策略可能比单纯增加推理 token 更有性价比。
-并行探索比深度迭代更抗过拟合。单序列 refinement 的 Matthew Effect 是个真实存在的路径依赖问题。加 C 比加 L 更有效。
-局部采样很重要。LLM 生成有噪声，K≥2 的局部贪心选择能防止坏样本污染轨迹历史。
-历史管理是门学问。RPUCG 的思路可以借鉴——不仅看节点自身得分，还要看它启发过多少好后代。
-轨迹数据值得保存。这些带反馈的发现轨迹本身就是高质量训练数据，能教模型”怎么根据反馈改进”。
## 局限论文也诚实提到了一些边界：
- 评测代理（evaluator surrogate）和真实目标（golden metric）之间的偏差可能导致 reward hacking。这在 Section 4.3 有专门分析。
- Best-solution restart 策略存在饱和现象——用之前最佳结果初始化新一轮探索，第二三轮通常就不会再提升了。
- 评测必须是可查询的。纯主观或当前无法评估的问题不适用这个框架。
## 一句话总结评测驱动的发现循环是科学进步的核心引擎，但过去没人系统地研究怎么扩展它。SIMPLETES 用 C×L×K 三个维度给出了一个简洁而有效的框架，用开源模型在 21 个科学问题上跑出 SOTA，还顺带产出了能自动训练模型的高质量轨迹数据。
对做 AI for Science 的人来说，这篇论文的价值不在于某个具体任务的突破，而在于提供了一种可扩展的范式。
