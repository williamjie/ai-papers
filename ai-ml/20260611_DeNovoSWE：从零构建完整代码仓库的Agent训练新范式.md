论文 : DeNovoSWE: Scaling Long-Horizon Environments for Generating Entire Repositories from Scratch链接 : https://arxiv.org/abs/2606.10728SWE-bench 已经卷不动了？当单点 Bug 修复不再是瓶颈，代码 Agent 的下一个战场是“从零开始构建整个软件仓库”。这篇论文提供了一个极具工程价值的答案：通过自动化流水线生成大规模、可验证的长程开发数据，让模型真正学会架构思维。
## 为什么现有的 SWE 数据不够用？
目前的代码 Agent 训练主要依赖单 Issue 修复数据（如 SWE-Gym, Scale-SWE）。这种数据有个致命缺陷： 它缺乏全局视野 。
修复 Bug 是“维护者”视角，而构建仓库是“架构师”视角。后者需要长程规划、模块解耦和复杂的依赖管理。现有的 NL2RepoBench 等基准测试只有几十条样本，根本不足以支撑大模型微调（SFT）。DeNovoSWE 的核心动机很直接： 我们需要一个足够大、足够难、且能自动验证的“文档到仓库”生成数据集。
## 核心方法：分治策略与防作弊沙箱DeNovoSWE 不是简单的爬虫，而是一套精心设计的自动化 Agent 流水线。其核心设计直觉在于 降低复杂度 和 确保真实性 。
### 1. Divide & Conquer（分而治之）
直接让 LLM 写一个完整仓库的文档几乎不可能，信息量太大且容易幻觉。作者采用了“分治”策略：
- 能力拆解：先由 Agent 识别仓库的高层功能模块。
- 代码画像：通过执行单元测试，追踪运行时调用链，区分“直接组件”、“核心间接组件”和“非核心间接组件”。
- 模块化文档生成：针对每个能力模块，独立生成文档。
这种设计的妙处在于： 它保留了实现的灵活性 。非核心组件被排除在文档之外，强制下游 Agent 自行实现细节，从而增加了任务的真实挑战性，避免了“填空题”式的简单生成。
### 2. Critic-Repair 迭代机制初版文档往往遗漏关键 API 或依赖。系统引入 Critic Agent 检查文档是否足以复现功能，并驱动 Repair Agent 进行多轮修正。这确保了训练数据的 可执行性 。
### 3. 极致的防泄漏沙箱 ⚠️这是工程落地中最容易被忽视的一环。为了防止 Agent “作弊”（比如偷偷 git clone 源码或读取缓存），DeNovoSWE 实施了严苛的隔离：
- 预清理：彻底清除源码、测试套件、Git 历史记录（包括 reflog）。
- 运行时限制：阻断网络访问、禁止安装目标包、模糊匹配可疑命令。
- LLM 审计：最后由 LLM 判断执行轨迹是否有绕过限制的嫌疑。
## 关键结果：从 5.8% 到 47.2% 的飞跃数据的质量直接决定了上限。DeNovoSWE 包含 4,818 个高质量实例，规模是 NL2RepoBench 的 46 倍。在 BeyondSWE-Doc2Repo 基准上，效果提升惊人：
模型基座 原始分数 (Doc2Repo) Scale-SWE 微调后 DeNovoSWE 微调后 Qwen3-30B-A3B 5.8% 29.2% 47.2% Qwen3.5-35B-A3B 43.8% - 50.0%反直觉发现 ：仅仅使用传统的 Issue 修复数据（Scale-SWE）微调，分数只能从 5.8% 提升到 29.2%。而加入长程仓库生成数据后，分数直接飙升至 47.2%。这证明了 任务类型的匹配度比数据量本身更重要 。
此外，DeNovoSWE-Agent-35A3B 达到了 50.0%，仅比 GPT-5.4 (CodeX) 的 61.7% 低约 11 个百分点，考虑到它是开源小模型，这一差距已经非常小了。
## 工程启示：如何构建高质量 Agent 数据？
这篇论文对一线工程师有三个重要指导意义：
-动态阈值过滤（Difficulty-Aware Filtering）
传统做法是只保留测试通过率 100% 的轨迹。但对于复杂仓库，完美轨迹极少。作者提出根据任务难度动态调整过滤阈值：简单任务要求高（>90%），困难任务允许低（>60%）。这有效保留了高价值但复杂的“部分成功”案例，平衡了质量与多样性。
-测试覆盖率即真理DeNovoSWE 筛选的仓库平均测试覆盖率达 85.5%。在缺乏人类标注的情况下，单元测试是唯一的客观验证标准。构建 Agent 数据时，务必优先选择测试完备的项目。
-长程能力需要专项训练通用代码模型擅长补全和修复，但不擅长架构。如果你的业务场景涉及从零生成模块或小型工具，必须引入此类“文档到代码”的长程数据进行 SFT。
## 局限与展望尽管效果显著，DeNovoSWE 目前主要聚焦于 Python 生态，且依赖 GPT-5.x 系列作为数据生成的底层引擎，成本较高。未来如何降低数据生成门槛、扩展至多语言混合仓库，将是下一步的关键。
对于正在构建代码 Agent 的团队来说，DeNovoSWE 不仅是一个数据集，更是一个 自动化数据工程（Data Engineering）的标杆模板 。它证明了：只要流水线设计得当，我们可以规模化地生产高质量、长程推理的训练数据。
