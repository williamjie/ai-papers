**日期**: 2026-06-02

论文 : Agent Skills Should Go Beyond Text: The Case for Visual Skills链接 : https://arxiv.org/abs/2606.01414现在的多模态 Agent 社区有个普遍误区：我们拼命把交互经验蒸馏成纯文本的 SOP（标准作业程序），以为这样就能实现“技能复用”。这篇论文直接泼了一盆冷水： 对于 GUI 操作、密集计数等视觉密集型任务，纯文本技能存在根本性的信息瓶颈。
作者提出的 Visual Skill 范式认为，Agent 的技能库不应只是 Markdown 文档，而应包含显式的视觉先验（Visual Priors）。这不仅仅是“给模型看张图”，而是将空间结构作为一等公民存入技能资产。
### 痛点：文本无法承载空间拓扑现有方案通常将 Agent 的轨迹总结为自然语言指令或推理链。这在 API 调用、SQL 生成等符号任务中很有效，但在视觉任务中会遭遇两个致命失败模式：
- 静态协议模糊（Static Protocol Ambiguity）：文本很难精确描述 UI 控件的边界曲率、嵌套层级或点击热区（Hit-region）的容忍度。一旦转化为语言，高维空间拓扑被压缩为一维序列，导致执行时“知道点哪里，但点不准”。
- 动态追踪崩溃（Dynamic Tracking Collapse）：在密集物体计数或迷宫求解中，Agent 需要记住“哪些区域已检查”。纯文本只能记录坐标列表，随着视觉密度增加，这种状态极易丢失，导致重复计数或遗漏。
⚠️ 核心 Insight ：问题不在于 MLLM 看不懂图，而在于我们积累的“可复用经验”被强制序列化成了文本，丢弃了原本的空间证据。
### 方法拆解：三种视觉技能形态论文将 Visual Skill 定义为三元组 Sv=(L,Pv,B)S_v = (L, P_v, B) ​ = ( L , P v ​ , B ) ，其中 LL 是文本逻辑， PvP_v ​ 是视觉先验， BB 是绑定协议。关键在于 PvP_v ​ 的三种形态设计：
- 静态先验（Static Priors）：针对稳定空间约定。例如 GUI 中的布局原型、错误模式示例。它解决的是“长什么样”的问题，提供可复用的空间参考系。
- 动态先验（Dynamic Priors）：针对持续感知追踪。不存储固定图片，而是规定如何在推理过程中实时生成视觉痕迹（如锚点、轨迹）。它解决的是“状态在哪”的问题，将空间记账外化为视觉工作记忆。
- 交错视觉技能（Interleaved Visual Skills）：将有序文本步骤与源帧截图绑定。适用于文档工作流等需要证据对齐的场景，防止推理与视觉证据脱节。
### 关键结果：量化“文本降级率”
为了证明价值，论文引入了**文本降级率（Textual Degradation Rate, TDR）**这一指标，衡量当知识被强制编码为纯文本时损失的绩效。实验在保持基础文本规则不变的前提下，对比了无技能、纯文本技能和视觉技能的表现。
GUI 定位任务（静态先验验证）：

- 技能库结构升级：不要只存 .md。未来的 Agent 技能包应包含 skill.md（逻辑）、assets/（视觉先验图）和 manifest.json（绑定协议）。
- 区分任务类型：并非所有任务都需要视觉技能。对于代数计算、代码生成等符号任务，纯文本更高效。视觉技能应仅用于依赖空间几何、边界敏感或持续追踪的任务。
- 自动化构建：论文开源了 AutoVisualSkill 流水线，能自动诊断是否需要视觉支持并生成对应资产。这提示我们，技能构建工具链需要增加“视觉瓶颈检测”模块。
### 局限与展望目前的方法仍依赖基础模型的感知能力，且静态先验的抽象程度（Abstract vs Instance-specific）需要精细控制，避免过拟合到特定样本。随着模型能力提升，静态图示可能演变为交互式注释或可执行视觉程序，但“空间知识应以视觉形式保存”这一原则不会改变。

亮点: 博文准确抓住了原文最核心的两个工程价值点：一是将“文本瓶颈”具象化为“静态协议模糊”和“动态追踪崩溃”两种可诊断的失败模式，便于工程人员理解问题；二是引入了“文本降级率（TDR）”这一量化指标，将原本定性的论点转化为可测量的评估目标。博文在“工程启示”部分对技能库结构（skill.md + assets/ + manifest.json）的提炼也很有实践指导意义。
挑刺:
- 遗漏关键实验数据范围：博文在GUI定位结果表格中仅展示了ScreenSpot-v2一个基准的数据，但原文Table 1同时报告了ScreenSpot、ScreenSpot-v2和GroundUI-18K三个基准的结果，且三个基准均呈现一致趋势。博文未说明这是选择性呈现，可能让读者低估实验覆盖的广度。原文：“As shown in Table 1, the no-skill baseline achieves reasonable Point-in-Box Accuracy… Across all three GUI grounding benchmarks.”
- TDR数值缺失：博文只提到了TDR的概念，但未给出原文中具体计算出的归一化TDR数值（如GUI grounding的Point-in-Box归一化TDR为17.1%，Counting的MAE归一化TDR为66.8%）。原文在5.4.1节明确给出了这些数值：“corresponding to normalized degradation rates of 17.1%, 8.1%, and 9.2%, respectively.” 博文省略了这些量化证据，削弱了“文本降级率”的说服力。
- 动态先验实现细节模糊：博文描述动态先验为“规定如何在推理过程中实时生成视觉痕迹（如锚点、轨迹）”，但原文明确其实现是“迭代渲染锚点”（见Appendix A.1：“the predicted points are rendered back onto the task image as numbered visual anchors… The loop stops when the model returns no new points”）。博文未说明这是循环迭代的过程，可能让读者误解为单次生成。
总评: ⭐⭐⭐½ 博文准确传达了原文的核心洞察和工程启示，但遗漏了部分关键量化数据和实验范围，整体是一篇忠实但不够全面的解读。
