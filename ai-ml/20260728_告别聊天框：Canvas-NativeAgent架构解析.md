论文 : JarvisHub: An Open Harness for Canvas-Native Multimodal Creative Agents链接 : https://arxiv.org/abs/2607.23588现在的 AI 创意工具大多还停留在“输入 Prompt，输出图片”的单步交互模式。这种模式在处理简单任务时很高效，但面对需要多轮迭代、版本管理和复杂依赖的长程创作任务时，往往显得力不从心。JarvisHub 这篇论文提出了一种全新的架构思路：把画布（Canvas）不仅作为用户界面，更作为 Agent 的外部记忆和操作空间。
### 现有方案的痛点：线性对话无法承载非线性创作目前的创意 AI 系统主要分为三类，但都有明显的局限性：
- Prompt-to-Output 工具：只保留最终资产，中间过程、失败尝试和参考图全部丢失。
- Chatbot Agent 平台：上下文被限制在线性聊天记录中，难以表达空间布局、版本分支和局部编辑目标。
- 节点工作流工具：虽然步骤可见，但通常是手动指定的固定管道，缺乏动态可编辑的项目状态。
⚠️ 核心洞察 ：创意工作的本质不是单次生成，而是不断演化的“项目状态”。Agent 需要知道哪些素材已存在、它们之间的关系、哪些候选项被接受或拒绝，以及下一步该更新哪里。这些信息很难存储在纯文本对话中。
### 方法拆解：Canvas 即状态，协议即约束JarvisHub 的核心创新在于将创意项目形式化为一个可编辑的 多模态工件图（Multimodal Artifact Graph） 。
1. 画布状态层（Canvas State Layer）
论文定义了一个包含节点、属性、布局、版本和依赖链接的状态结构 CtC_t ​ 。每个节点都有唯一的 ID、类型、位置、输入输出内容以及运行时状态。
- 可寻址性：Agent 可以精确引用特定的候选图片或视频片段，而不是模糊的“那个图”。
- 可重用性：参考图、草稿甚至被拒绝的候选项都可以作为后续步骤的输入。
- 可追溯性：用户可以清晰看到哪些材料影响了结果，哪个版本被选中。
2. 协议桥接层（Protocol Bridge）
为了防止 Agent 随意篡改画布，JarvisHub 引入了严格的协议约束。
- 能力清单（Capability Manifest）：列出当前项目可用的节点类型和操作。
- 执行授权（Execution Grant）：限制 Agent 在当前轮次允许执行的操作范围。
- 状态转移：只有经过验证的动作才会更新画布状态，确保所有变更都是显式、有效且可恢复的。
3. Agent 运行时（Agent Runtime）
运行时负责规划、调用工具并同步状态。它集成了五大工具族：
- Canvas Tools：读取、创建、更新节点。
- Generation Tools：图像、视频、音频生成。
- Native Tools：浏览器、文件、代码执行。
- Recovery Tools：检查、修复失败节点。
- MCP Tools：通过模型上下文协议扩展外部服务。
此外，运行时还利用**技能（Skills） 编码可复用的创意程序，利用 记忆（Memory） 保持跨轮次的一致性，并利用 子 Agent（Subagents）**处理并行子任务。
### 关键结果：长程创作的可解释性提升论文在三个高价值长程创意任务上进行了定性评估：叙事媒体生成、交互式 Web 开发和演示文稿生成。
任务类型 挑战点 JarvisHub 的表现 叙事媒体生成 角色一致性、镜头连贯性、风格统一 画布保留了故事规划、视觉参考和镜头候选项，使 Agent 能在后续镜头中复用前期设定的角色特征。 交互式 Web 开发 布局设计、前端代码、预览迭代 追踪了设计参考、实现进度和修订状态，确保了最终网站的视觉方向和界面一致性。 演示文稿生成 内容选择、叙事组织、跨页一致性 记录了讲座内容、生成的图表和幻灯片草稿，保持了主题结构和视觉风格的一致性。
虽然论文没有提供量化的基准测试数据，但其展示的**工作空间轨迹（Workspace Trace）**证明了该架构在处理复杂依赖和迭代修订时的优势。Agent 不再是一个黑盒，而是其每一步操作、使用的证据以及收到的反馈都被记录在案。
### 工程启示：从“调用模型”到“管理状态”
对于工程师而言，JarvisHub 提供了几个重要的实践指导：
- 外部记忆的重要性：不要试图将所有上下文塞进 LLM 的 Context Window。使用结构化的外部存储（如图数据库或 Canvas 状态）来管理长期项目状态。
- 动作空间的约束：通过协议桥接层限制 Agent 的操作范围，可以有效减少幻觉和错误操作，提高系统的稳定性。
- 轨迹记录的价值：完整的执行轨迹不仅是调试工具，更是未来训练更强大创意 Agent 的优质数据源。
### 局限与展望JarvisHub 目前仍有一些局限性：
- 缺乏量化基准：实验主要是定性展示，尚未建立标准化的长程创作评估指标。
- 依赖外部模型质量：最终产出的质量很大程度上取决于底层生成模型（如 GPT-5.5, Seedance 2.0）的能力。
- 语义正确性不保证：协议桥接层只确保操作的合法性，不保证 Agent 创意决策的语义正确性。
尽管如此，JarvisHub 为构建下一代创意 AI 系统提供了一个开放的、可研究的框架。它让我们看到，未来的创意 Agent 不应仅仅是工具的调用者，更应是项目状态的维护者和协作者。
