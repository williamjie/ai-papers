**日期**: 2026-07-29

论文 : Visual prompt engineering for video models链接 : https://arxiv.org/abs/2607.25537我们习惯给大语言模型精心打磨 Text Prompt，却往往忽略了视频生成模型同样拥有强大的“视觉输入”通道。这篇来自 Google DeepMind 的论文揭示了一个被长期忽视的工程杠杆： 通过修改输入图像的风格和细节（Visual Prompt Engineering, VIPE），可以显著提升视频模型的推理能力。
### 痛点：抽象场景下的推理失效目前的视频基础模型（如 Veo、Wan）常被用于解决视觉推理任务，比如物理模拟或逻辑谜题。然而，现有的基准测试多采用**抽象草图（Sketch）**作为输入。
实验发现，这种“贫瘠”的视觉上下文严重低估了模型的真实能力。以 VPCT 物理推理数据集为例，Wan2.2 在原始草图条件下的准确率接近随机猜测水平；即使是表现较好的 Veo 3.1，准确率也仅为 41.3%。
核心问题在于：视频模型在训练时主要接触的是 真实世界视频（Photorealistic Videos） 。当输入是抽象线条时，模型处于“分布外（Out-of-Distribution）”状态，导致生成的视频中物体随机消失、变形，场景一致性极差，进而破坏了推理链条。
### 方法拆解：VIPE 的核心直觉VIPE 的核心 Insight 非常直观： 将抽象任务图像转化为照片级真实感图像，以匹配模型的内部表征空间。
其工作流程分为三步：
- Ideator（构思）：由 VLM（如 Gemini）生成编辑指令。例如：“保持相机视角不变，将白色圆圈替换为红色台球，黑色线条替换为木质货架。”
- Editor（编辑）：使用图像编辑模型（如 Nano Banana）执行指令，生成多个候选变体。
- Filter（过滤）：由 VLM 评估候选图像的质量和对原任务的忠实度，选出最佳变体。
⚠️ 反直觉发现 ：消融实验表明，仅仅增加“3D 深度感”并不足以提升性能。只有当图像具备**真实纹理（Realism）**时，推理准确率才出现显著跃升。这说明模型依赖的是物理世界的材质先验，而非单纯的几何结构。
### 关键结果：超越文本提示与测试时缩放论文在多个任务上验证了 VIPE 的有效性，数据极具说服力：
模型/任务 Baseline (草图) VIPE (真实感) 提升幅度 Veo 3.1 (VPCT) 41.3% 59.3% +18 pts Omni Flash (VPCT) 56.3% 67.5% +11.2 pts Veo 3.1 (Sort 3 Numbers) ~4% 76%-86% >20x 提升更令人惊讶的是，VIPE 在**测试时缩放（Test-time Scaling）**上的性价比远超传统方法：
- 自一致性投票：Veo 3.1 通过生成 20 次视频并投票，准确率从 41.3% 提升至 50.0%。
- VIPE 单样本：仅使用一个经过 VIPE 处理的图像生成一次视频，准确率即达 59.3%。
- 组合策略：在 VIPE 基础上再进行 20 次投票，准确率可达 68.0%。
此外，在 Sort 3 Numbers 和 Conjunctive Search 任务中， 视觉提示工程的平均效果优于文本提示工程 。因为对于视频模型而言，图像提供了更多的 Token 和空间约束，是更主导的条件信号。
### 工程启示- 评估基准需重构：不要在抽象草图上评估视频模型的推理上限。VIPE 证明了当前许多“失败”案例其实是输入格式不匹配导致的。建议在评测前引入 VIPE 预处理步骤。
- 低成本推理增强：相比于增加视频生成次数（昂贵），生成几张高质量的控制图（便宜）是更高效的测试时计算分配策略。论文数据显示，VIPE 变体的成本仅为视频生成的 1/8。
- Agent 工作流集成：在构建视觉推理 Agent 时，可以引入一个“视觉预处理器”模块。如果初始输入是示意图或低质量截图，自动调用图像编辑模型将其转化为高保真场景，再送入视频模型进行模拟。
### 局限与展望VIPE 并非万能药。论文指出，对于原生图像生成模型（如 Nano Banana），VIPE 的收益并不显著，因为它们已经适应了多样化的风格分布。这暗示 VIPE 主要解决的是 模态间的表征错位 。
此外，自动化 VIPE 仍依赖强大的 VLM 进行构思和过滤，且存在“幻觉风险”——如果编辑过程意外改变了任务逻辑（如移动了障碍物位置），会导致错误答案。未来需要更严格的几何约束机制来确保任务保真度。

亮点: 博文准确提炼了“现实偏见”这一核心洞察，并用清晰的实验对比（如VIPE vs. 文本提示工程、VIPE vs. 测试时缩放）突出了VIPE的工程价值。对消融实验（3D深度 vs. 真实纹理）的解读到位，揭示了性能提升的关键来源。
挑刺:
- 结果混淆：Sort 3 Numbers 的 VIPE 提升幅度引用不当。 博文称“Veo 3.1 (Sort 3 Numbers) baseline ~4%, VIPE (真实感) 76%-86%”，但原文 Fig.6 中 86% 是 最佳文本变体（best text variant） 的准确率，而最佳图像变体（即 VIPE）为 76%。博文将两者合并为一个区间，可能误导读者认为 VIPE 本身可达 86%。
- 遗漏关键实验预处理细节。 原文 App.C 明确说明：为迫使视频模型模拟真实轨迹，在 VIPE 版的 VPCT 图像中移除了桶（buckets）并用背景色填充，而博文未提及这一约束，导致读者可能误以为 VIPE 直接对原图进行风格转换。
- 过度概括“自动化”流程。 博文仅描述 Ideator 由 VLM 生成编辑指令，但原文详细介绍了两种自动化方法（Freeform 与 ACE），其中 ACE 的树搜索和宪法学习是重要技术贡献，博文完全忽略，使“自动化”的工程深度被低估。
总评: ⭐⭐⭐½ 博文清晰传达了VIPE的核心思想与关键结果，但在Sort 3 Numbers结果中混淆了视觉与文本提示的最佳表现，且遗漏了VPCT实验的重要预处理细节，略损准确性。
