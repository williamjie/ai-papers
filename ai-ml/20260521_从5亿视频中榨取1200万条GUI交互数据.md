# ⭐⭐⭐⭐ 从5亿视频中榨取1200万条GUI交互数据

**日期**: 2026-05-21

---

论文 : Video2GUI: Synthesizing Large-Scale Interaction Trajectories for Generalized GUI Agent Pretraining链接 : https://arxiv.org/abs/2605.14747做 GUI Agent 的工程师都知道，数据是硬伤。现有的数据集要么靠人工标注，贵且慢；要么靠模拟环境，泛化性差。这篇来自小米和北大联合团队的工作，直接剑指痛点： 既然互联网上有海量的软件教程视频，为什么不把它们变成训练数据？
他们提出了 Video2GUI 框架，从 5 亿条 YouTube 元数据中筛选出 420 万高质量教程视频，最终合成包含 1270 万条交互轨迹的 WildGUI 数据集。这不仅是一个数据集，更是一套可复用的“视频转 Agent 数据”的工程范式。
### 为什么现有方案走不通？
目前的 GUI Agent 训练数据主要来源有两个：
- 人工标注：如 MIND2WEB，成本高，规模难以突破百万级。
- 合成数据：基于代码或模拟器生成，缺乏真实世界的视觉多样性和长尾场景。
互联网视频（尤其是 YouTube）天然具备“步骤清晰、视觉丰富、覆盖广泛”的特点。但直接利用视频有两个巨大障碍：
- 噪音极大：5 亿视频中，只有极少部分是真正的 GUI 操作教程，其余是 Vlog、新闻或无关内容。
- 无标注：视频只有像素，没有点击坐标、操作意图等结构化标签。
### Video2GUI 的核心设计直觉论文没有简单粗暴地让大模型看视频，而是设计了一套 粗到细（Coarse-to-Fine） 的过滤与提取流水线，核心 Insight 在于 分层降维 ：
-元数据粗筛（Meta Info Filtering）：
Why：直接处理 5 亿视频的视频流，存储和算力成本是天文数字。
- How：先利用 DeepSeek-V3 对 1 万条样本进行标注，微调一个轻量级的 Qwen2.5-7B 分类器。仅通过标题、描述、关键词，将 5 亿视频缩减至约 2000 万候选视频。这一步几乎零视频解码成本。
-视觉质量精筛（Video Quality Scoring）：
Why：元数据无法判断视频画质、是否包含实际操作演示、讲解是否清晰。
- How：提取前 1 分钟视频，使用全模态模型 Qwen2.5-Omni 从“主题相关性、指令清晰度、录制质量”三个维度打分。最终保留 416 万视频（约 30 万小时），确保了数据的高质量。
-轨迹提取与空间接地（Trajectory Extraction & Grounding）：
Why：视频压缩导致分辨率低，无法直接用于像素级定位；且长视频超出模型上下文窗口。
- How：
分段处理：将视频切分为 4 分钟片段，利用滑动窗口和历史上下文记忆，让 Gemini-3-Pro 提取任务指令、时间戳和操作细节。
- 高分辨率接地：针对每个操作时间戳，从原始视频中提取前后 0.5 秒的三帧高清截图。利用多帧信息解决快速界面变化带来的定位难题，将操作映射到精确的屏幕坐标。
### 实验结果：规模带来显著增益WildGUI 是目前最大的开源 GUI 预训练数据集，涵盖 1500+ 应用和网站，包含 1.245 亿张截图。在 Qwen2.5-VL 和 Mimo-VL 上进行持续预训练后，效果提升显著：
基准测试 模型 预训练前 +WildGUI 后 提升幅度 ScreenSpot-Pro (Avg) Qwen2.5-VL-7B 26.8 41.9 +15.1 ScreenSpot-Pro (Avg) Mimo-VL-7B 41.2 56.9 +15.7 OSWorld-G (Avg) Mimo-VL-7B 54.7 67.6 +12.9 AndroidControl (Step SR) Mimo-VL-7B 65.6 71.4 +5.8- 超越 SOTA：Mimo-VL-7B 在 OSWorld-G 上达到 67.6，超越了 Qwen3-VL-32B (60.6) 和 Seed1.5-VL (62.9)。
- Scaling Law 验证：预训练 token 从 0 增加到 2000 亿，性能持续上升，在 500 亿 token 时即超越仅做 SFT 的基线，且未见饱和迹象。
### 工程启示- 数据清洗比模型训练更重要：Video2GUI 展示了如何通过低成本分类器和大模型评分器，从海量噪音中提取高质量数据。对于任何依赖非结构化数据（如视频、日志）的 Agent 项目，这种“粗筛+精筛”策略值得借鉴。
- 多帧接地是关键：单帧截图往往丢失上下文，论文中采用“前后 0.5 秒三帧”进行空间定位，有效解决了动态界面的坐标映射问题，这是一个非常实用的工程 Trick。
- 两阶段训练范式：先在大规模合成数据上预训练（Continual Pre-training）以获取通用 GUI 知识，再用高质量开源数据进行 SFT 对齐。这种策略比直接 SFT 更能提升泛化能力，特别是在长尾应用和跨语言场景下。
### 局限与展望虽然 WildGUI 规模巨大，但数据来源于 YouTube 教程，可能存在“演示偏差”（Demo Bias），即操作过于规范，缺乏真实用户的错误操作和探索行为。此外，依赖 Gemini-3-Pro 进行标注带来了较高的 API 成本。未来，如何降低标注成本，并引入更多真实用户行为数据，将是下一步的关键。
