原文 : OTel and mesh-derived metrics: A 2026 reference来源 : https://www.cncf.io/blog/2026/06/29/otel-and-mesh-derived-metrics-a-2026-reference/如果你已经部署了 OpenTelemetry (OTel)，你可能以为自己对应用了如指掌。但真相是：你看到的只是“应用视角”，而非“网络视角”。这篇 2026 年的参考文章揭示了一个被广泛忽视的盲区——东西向流量的真实状态，以及如何用零代码侵入的方式补全它。
### 为什么 OTel 不够用？
OTel 的核心优势在于应用层可见性：追踪（Traces）、指标（Metrics）和日志（Logs）。通过自动插桩或手动埋点，你能看到 HTTP 请求数、数据库延迟甚至业务层的“购物车添加次数”。
但 OTel 有一个致命弱点： 它看不见网络层 。除非你在代码两端都显式插桩，否则应用内部的流量对 OTel 而言是黑盒。更糟糕的是，即使有插桩，应用报告的指标往往缺乏身份认证上下文（如 mTLS 身份），且容易因内部逻辑错误而失真。
### Mesh 指标的“上帝视角”
服务网格（Service Mesh）通过 Sidecar 代理拦截所有进出流量，提供了另一种维度的观测数据。以 Linkerd 为例，一旦 Pod 注入代理，无需修改任何应用代码，端口 4191 就会暴露出黄金指标：
- response_total：基于方向、状态码、gRPC 状态和客户端身份的分类计数。
- response_latency_ms：从请求头接收到响应流完成的真实网络延迟。
- TCP 级别指标：连接数、读写字节数等底层网络特征。
⚠️ 关键洞察 ：Mesh 指标提供了加密的身份证明（ client_id ），这是应用层指标无法提供的。它告诉你“谁”在访问“谁”，而不仅仅是“发生了什么”。
### 融合之道：重叠与互补文章通过对比展示了两者如何互补，而非互斥：
维度 OTel 应用指标 Mesh 代理指标 数据来源 应用代码内部逻辑 Sidecar 代理网络拦截 优势 业务语义（如“支付成功”）、自定义维度 mTLS 身份、真实网络延迟、东西向拓扑 盲区 无法感知网络层故障、缺乏加密身份 不懂业务逻辑、无法解释失败原因一个典型的反直觉案例 ：
在 gRPC 调用中，HTTP 状态码可能是 200 （成功），但 gRPC 状态却是 14 （UNAVAILABLE）。如果只监控 HTTP 状态，你会漏掉故障。Mesh 代理能识别 gRPC 状态并将其标记为失败，而 OTel Trace 则能展示具体的错误堆栈。 Mesh 发现异常，Trace 解释原因 ，这是最佳实践组合。
### 工程落地：Collector 配置陷阱将 Mesh 指标引入现有 OTel Collector 管道并非毫无风险。文章分享了一个真实的踩坑经验：
- 独立管道设计：在 OTel Collector 中建立独立的 metrics/mesh 管道，使用 Prometheus Receiver 抓取 linkerd-proxy 容器。
- 严格过滤：代理暴露的指标基数极高（单个直方图可能产生数千个系列）。必须使用 OTTL (OpenTelemetry Transformation Language) 或 Relabel Config 严格保留核心指标（如 response_total, response_latency_ms）。
- 配置陷阱：在较旧版本的 Collector 中，重命名规则中的 $1 可能被误解析为环境变量。务必固定 Collector 版本（如文中使用的 0.118.0），并注意转义问题。
### 基数警告：不要为看不见的指标买单这是本文最宝贵的工程建议之一。 保留一个直方图，就要为它的所有分桶付费。
未经过滤的 Mesh 指标包含大量标签（TLS、路由、客户端 ID 等）。在测试环境中，仅 response_latency_ms_bucket 就产生了 5,642 个时间序列。如果不加筛选直接写入后端存储（如 VictoriaMetrics），成本将呈指数级增长。
建议 ：在 Collector 端进行激进过滤。只保留你真正关心的 5-10 个核心指标族，丢弃其余所有噪声。
### 总结与行动指南对于云原生团队而言，OTel 和 Mesh 不是二选一，而是必选组合。
- 如果你只有 OTel：你缺失了服务拓扑的真实视图和加密身份上下文。
- 如果你只有 Mesh：你能看到失败，但不知道业务层面的原因。
行动很简单：通过 Namespace 注解注入 Mesh，配置一个独立的 Collector 管道抓取代理指标，并在 Grafana 中将两者混合展示。记住， 信任 Mesh 看网络和身份，信任 OTel 看业务和根因 。这种分层观测策略，才是 2026 年云原生可观测性的标准答案。
