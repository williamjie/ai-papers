# ⭐⭐⭐ FinRank：金融RAG的“硬负样本”基准测试

**日期**: 2026-08-10

---

论文 : FinRank: An Evidence-Grounded Benchmark for Financial Question Answering and Retrieval over SEC Filings链接 : https://arxiv.org/abs/2608.07400在构建基于 SEC 文件的金融 RAG（检索增强生成）系统时，最大的坑往往不是模型不会算数，而是它找错了证据。这篇论文直击痛点：如果模型引用了竞争对手的相似段落作为依据，即使数字正确，也是严重的合规灾难。FinRank 提供了一个专注于“证据归因”和“硬负样本区分”的新基准。
### 为什么现有基准不够用？
传统的金融 QA 基准（如 FinQA、TAT-QA）主要关注数值计算或端到端的答案正确性。但在真实的投研场景中，监管披露文件（如 10-K/10-Q）具有高度的模板化特征。
核心洞察 ：不同公司、不同时期的风险因素披露（Risk Factors）或会计政策说明往往措辞几乎一致。模型必须能区分“目标公司的当期披露”与“竞争对手的相似模板”或“历史时期的旧闻”。这种**证据鉴别（Evidence Discrimination）**能力，比单纯的答案生成更难，也更具实战价值。
### 方法拆解：人为制造的“混淆局”
FinRank 的核心创新在于其数据构建策略，特别是**硬负样本（Hard Negatives）**的设计：
- 数据来源：涵盖制药、油气、汽车三大行业的 22 家公司，共 1185 条手工标注的问答记录。
- 硬负样本构造：不同于随机采样，作者手动选取了最具迷惑性的段落作为干扰项。
79.9% 的硬负样本来自同行业竞争对手的同期文件（最容易混淆）。
- 13.2% 来自同公司不同年份。
- 6.9% 来自同公司同年份的其他部分。
- 多维元数据：每条记录包含难度、推理类型（定性/定量）、证据范围（单段/多段）等标签，支持细粒度分析。
### 关键结果：大模型也“眼瞎”？
实验结果显示，即便是强大的嵌入模型，在面对精心设计的硬负样本时表现依然堪忧。以下是基于全局混合语料库（5230 个片段）的检索性能对比：
模型 Recall@10 备注 BM25 32.1% 稀疏检索基线 all-mpnet-base-v2 31.8% 通用稠密检索，略低于 BM25 finance-adapted BGE 22.4% 金融适配模型，表现反而更差 bge-large-en-v1.5 35.6% 较大通用模型 e5-mistral-7b-instruct 44.8% 最强基线，但仍不足半数⚠️ 反直觉发现 ：当用人工精选的硬负样本替换随机负样本时，所有模型的成对准确率（Pairwise Accuracy）下降了 13.0–20.5 个百分点 。这证明了 FinRank 中的干扰项确实具有极高的迷惑性，现有模型难以区分“语义相似但实体错误”的内容。
此外，简单的 元数据过滤 （如限定股票代码、年份）能将 BM25 的 Recall@10 从 32.1% 提升至 55.0% 。这说明在工程实践中，先做结构化过滤再做语义检索是性价比极高的策略。
### 工程启示：如何落地？
对于量化金融工程师和风控系统开发者，FinRank 提供了三个明确的指导方向：
- 不要迷信端到端 RAG：在合规审查场景中，必须将“检索”与“生成”解耦。先评估检索到的片段是否属于正确的实体和时间周期，再考虑答案生成。
- 引入硬负样本训练：如果你的模型在通用语料上表现良好但在金融场景出错，很可能是因为缺乏对“模板化文本”的区分能力。使用类似 FinRank 的构造逻辑，收集同行业竞争对手的相似段落作为负样本进行对比学习（Contrastive Learning），能显著提升检索器的鲁棒性。
- 元数据是第一道防线：实验表明，利用 Ticker、Year、Doc Type 进行预过滤效果显著。在构建向量数据库时，务必保留并充分利用这些结构化字段，避免让语义模型去处理本应由规则引擎解决的实体匹配问题。
### 局限与展望FinRank 目前仅覆盖 22 家公司，且定性问题（68%）多于定量问题（32%）。这意味着它在评估复杂数值推理方面的代表性可能不足。此外，数据集主要基于 2024-2025 年的文件，对于长期趋势分析的泛化能力尚待验证。
尽管如此，FinRank 填补了金融检索领域“证据归因”评估的空白。它提醒我们：在金融 AI 中， 知道“为什么”引用这段文字，比仅仅给出一个正确的数字更重要。
