# 约束LLM代理在加密因子发现中的方法论突破

**日期**: 2026-04-30

---

论文 : From Hypotheses to Factors: Constrained LLM Agents in Cryptocurrency Markets链接 : https://arxiv.org/abs/2604.26747这篇论文干了一件很漂亮的事：把LLM agent关进笼子，让它做因子发现，但又不让它放飞自我。
## 为什么值得关注量化因子发现这个活儿，传统上靠人类研究员灵光一现，或者靠暴力网格搜索。LLM agent理论上能自主提出假设、写代码、迭代优化——听起来很爽，但问题来了： 如果agent可以自由修改数据分割、评价指标、代码逻辑，那它发现的到底是规律，还是过拟合的艺术？
本文的答案很明确： 把agent变成”假设生成器”，而把”裁判”交给确定性引擎 。这个分离设计在方法论上是一个重要澄清。
## 问题与动机：自由探索的代价因子发现不是简单的监督学习问题。研究员需要：
- 决定测试什么经济机制- 如何把这个机制编码为信号- 哪些失败是有信息的- 下一个候选应该和之前有何不同这是一个 序列假设搜索 问题，天然适合agentic reasoning。但如果agent可以随意改特征、改数据分割、改评价规则，那强结果很可能反映的是 uncontrolled search 而非真实发现。
加密货币市场尤其适合测试这个框架：上线历史不一、流动性差异大、投机情绪变化快，手动搜索困难。
## 方法拆解：笼子里的创造力### 核心设计原则：分离推理（agent） 与 评估（engine） 完全分离：
- Agent：读实验日志、提假设、写食谱、解释证据- Engine：计算信号、应用固定门控、记录失败、投资组合测试Agent能控制搜索方向，但 不能修改评估规则 。时间分割、门控阈值、交易成本、组合设置全部写在配置文件里，session内不可变。
### 约束因子DSL：可审计的_action space_这是整篇论文的技术核心。factor recipe 必须用受限的DSL写，不能生成任意代码。DSL支持：
- 横截面变换：分位秩（percentile rank）、z-score- 时间序列变换：lag、滚动均值、滚动标准差、差分、百分比变化- 非线性变换：log、绝对值、clipping- 组合：线性组合限制条件很严格 ：
- 只能用审定的时点变量列（open/high/low/close/volume/mcap等）
- 必须至少包含一个时间序列或非线性变换- 表达式树要浅到能手动审查目的有三个：防前视偏差、保持可解释性、让搜索空间可比较。
举个例子：假设”小市值、高波动范围、成交量 muted 的代币会跑赢”，DSL可以写成：
si,t = rank_t(-0.6*log(1+mcapi,t)) + 0.5*MA10(rangei,t) - 0.2*MA3(Δvolumei,t)
这个表达式 Audit 起来很容易，但足够表达一个多部分经济机制。
### 候选人生成：机械变体 + 假设驱动每轮混合两类候选：
- 机械变体：已成功因子的小变换（lag、平滑、横截面标准化）——提供受控的 exploitation- 假设候选：agent 自由生成，但必须包含五字段：名称、可证伪假设、经济理由、候选类型、可执行食谱这个混合设计很重要。纯机械会过度开采早期发现；纯假设会 drift 到无约束探索。
### 评估引擎与门控引擎计算每个资产-日的因子值，在训练窗口评估横截面预测能力。核心统计量：
- IC：日均 Pearson 信息系数- t-statistic of IC- 多空组合夏普比- coverage（非缺失分数占比）
门控只看训练窗口： IC ≥ τIC 且 tIC ≥ τt 。通过则进入 hold pool，失败则留在日志里作为反例。
关键点： 验证统计仅供诊断，不影响通过/失败决定 。纯样本外结果留到最后。
### 最终组合：岭回归 + 样本外检验搜索阶段结束后，从 hold pool curation 出 good factor pool（考虑强度、多样性、冗余度），然后 ridge regression 组合：
β̂ = arg min Σ(ri,t+1:t+2 - Si,t β)² + λ||β||²只在训练期拟合，然后独立评估训练、验证、纯样本外表现。支持等权与市值加权两种组合方式。

## 工程启示### 1. 约束即生产力DSL 不是限制，而是 质量控制阀 。它强制：
- 防前视偏差（只能用 point-in-time 变量）
- 保持可解释性（表达式树要浅）
- 可比性（搜索空间一致）
这对实盘系统有直接借鉴： 任何自动化的因子挖掘 pipeline，都必须有符号层约束 ，不能放任 LLM 生成任意 Python。
### 2. 可审计性靠追加日志实验日志是 append-only 的。每个候选记录：假设、理由、食谱、指标、解释、下一轮决策。这相当于 研究过程的区块链 ——成功和失败都不可篡改。
在风控和合规场景，这种不可否认性很重要。监管问”这个因子怎么来的”，你可以把整个推理链和实验记录扔出来。
### 3. 容量约束必须显式建模市值加权组合 vs 等权组合的巨大差异（等权夏普 1.55，市值加权”表现差”）说明： 发现的 alpha 只存在于小市值代币的流动性稀缺效应 。
这对实盘部署是红色警告：策略可能只适合小规模、高换手场景。论文提到换手率 0.368（等权多空），对应 5bps 成本下 44.55% 收益，算下来 毛摩擦区间大约在 15-20bps ——超过就悬。
### 4. 失败的候选也是资产失败候选留在日志里作为负例。agent 可以看到”range changes 和 volume recoveries 是有噪声的，而 level-based scarcity 和 attention measures 更稳定”。
这提示我们： 负样本挖掘在因子工程里同样有价值 。不是所有候选都要 pass，淘汰过程本身提供了关于信号结构的 meta-knowledge。
### 5. 时间分割纪律训练（2020-2022）→ 验证（2023）→ 纯样本外（2024-）。验证集只用于诊断，不参与门控决策。这是 严格的时间对齐 ，避免数据泄露。
很多实盘系统失败就是因为时间分割混乱。本文的protocol设计值得借鉴： selection gate 永远只看训练窗口 。
## 局限与展望### 局限（论文 Section 6 提及）
- 容量问题：市值加权表现差，alpha 集中在小代币- 数据范围：只测试加密货币，能否迁移到传统资产未知- DSL 表达力：受约束的 DSL 可能错过更复杂的非线性交互- Agent 依赖 GPT-5：模型能力边界即框架能力边界### 可拓展方向- 多资产迁移：把相同协议搬到美股、期货、外汇，看是否还能发现经济意义明确的因子- 更宽 DSL：加入交互项、分段函数，但保持可审计- 动态门控：目前门控固定，未来可考虑基于市场 regime 的自适应阈值- 人类-in-the-loop：把人类研究员的判断作为额外反馈信号## 一点批判性思考这篇论文的方法论价值大于 具体的因子发现 。它展示了一套 如何安全使用 LLM 做实证发现 的 protocol，而不是”我们用 LLM 找到了一个赚大钱的策略”。
核心贡献是 把 agentic AI 从”代码生成器”重新定义为”假设生成器” ，而把”实验员”角色交给确定性引擎。这个分离设计解决了金融研究中最大的痛点： 可重复性危机 。
但 honest 地说，44.55% 的年化收益听起来很美，但 这是 2024-2026 加密牛市的结果 。如果测试期包含 2022 大熊市，夏普还能剩多少？论文没提。这是一个信息 gap。
另外， 单一模型（GPT-5）的依赖性 是个隐患。如果换模型，搜索结果是否稳定？论文没做敏感性分析。这也是工程落地时需要考虑的。
## 小结这篇文章提供了一个 约束中的创造力 范本：LLM agent 可以在严格协议内进行科学发现，而不会变成 uncontrolled search。关键设计在于：
- DSL 约束行动空间- 确定性引擎固定评价规则- 追加日志保证可审计- 严格时间分割防泄露对金融工程团队的启示： 如果你打算用 LLM 做因子挖掘，先设计你的 DSL 和评估引擎，再放开 agent 的缰绳。否则，你得到的不是 alpha，是过拟合的幻觉。
